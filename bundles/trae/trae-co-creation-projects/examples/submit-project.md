# 提交共创项目示例

本示例演示两种场景下的共创项目提交流程：个人项目（AI 结对编程）和团队项目。

## 场景一：个人项目提交（AI 结对编程）

### 项目假设

你是一名独立开发者，使用 TRAE 作为 AI 结对编程伙伴，从零开发了一个命令行待办事项工具 `trae-todo`，现在想分享你的 TRAE 协作开发经验。

### 步骤 1：自检 Must Have

| 标准 | 自检 |
|------|------|
| TRAE 核心协作工具 | ✅ 全程使用 TRAE 开发，TRAE 是主要编程伙伴 |
| 展示有意义的协作 | ✅ 可描述具体的 AI 结对编程场景 |
| 可访问 | ✅ GitHub 仓库公开 |
| 基础文档 | ✅ 有 README |

### 步骤 2：填写中文 Issue 模板

**项目名称**：trae-todo - 命令行待办事项管理工具

**一句话描述**：与 TRAE 结对编程开发的命令行待办工具，支持优先级、标签和到期提醒。

**详细描述**：
> 这是我使用 TRAE 作为 AI 结对编程伙伴开发的一个命令行待办事项管理工具。开发过程中，TRAE 协助我完成了从项目初始化到功能实现的全过程。项目使用 Python 开发，支持任务的添加/删除/完成/列表展示，支持优先级（高/中/低）、标签分类和到期日提醒。

**GitHub 仓库**：https://github.com/yourname/trae-todo

**在线演示**：无（CLI 工具）

**项目类型**：🛠️ Tools & Utilities

**技术栈**：Python 3.12 + Click + SQLite

**核心功能**：
> - 添加/删除/完成/列出任务
> - 三级优先级设置
> - 标签分类和筛选
> - 到期日提醒
> - 数据持久化（SQLite）

**团队规模**：个人开发者（Solo with AI Pair Programming）

**协作类型**：AI 结对编程（Human-AI Pair Programming）

**TRAE 使用场景描述**（关键！Collaboration 评分核心）：
> 在开发 trae-todo 的过程中，TRAE 扮演了我的结对编程伙伴：
>
> 1. **项目初始化阶段**：我告诉 TRAE 我想做一个 CLI 待办工具，TRAE 帮我分析了技术选型（推荐 Click 而非 argparse），并生成了项目骨架代码。
>
> 2. **功能开发阶段**：我用自然语言描述每个功能需求（如"我需要一个优先级功能"），TRAE 生成初始代码，我审查并调整。遇到 bug 时，我把错误信息贴给 TRAE，它帮我定位问题并给出修复方案。
>
> 3. **代码审查场景**：每完成一个功能，我让 TRAE 审查我的代码，它指出了几个潜在问题：SQL 注入风险（建议使用参数化查询）、异常处理缺失、帮助文本不完整等。
>
> 4. **重构阶段**：项目完成后，TRAE 建议将数据操作层和 CLI 层分离，我采纳了这个建议进行了重构，代码质量显著提升。
>
> 5. **文档编写**：TRAE 帮我生成了 README 的初稿，我在此基础上修改完善。
>
> 整个开发过程是典型的"人机对话式编程"——我负责设计决策和方向把控，TRAE 负责代码生成、问题诊断和优化建议。

### 协作描述的写作要点

对于个人项目，Collaboration 字段需要特别注意：
- ❌ 不要只写"使用 TRAE 开发"——太空泛
- ✅ 要写具体的协作场景（谁做了什么决策、谁写了哪部分代码）
- ✅ 要体现 TRAE 在协作中的"角色"（伙伴/审查者/顾问）
- ✅ 最好有协作前后的对比（如 TRAE 发现了什么问题、效率提升多少）

## 场景二：团队项目提交

### 项目假设

你和 2 个朋友组成 3 人团队，使用 TRAE 协作开发了一个团队博客平台 `TeamBlog`，现在想提交。

### 填写要点差异

**团队规模**：3 人团队

**协作类型**：团队协作（Team Collaboration）+ AI 辅助

**TRAE 使用场景描述**：
> 我们 3 人团队在开发 TeamBlog 时使用 TRAE 作为协作辅助工具：
>
> 1. **代码审查辅助**：PR 提交后，我们使用 TRAE 辅助进行第一轮代码审查，它能自动发现常见问题，减少人工审查负担。
>
> 2. **新人上手**：团队中新加入的成员通过 TRAE 快速了解代码结构，TRAE 能解释代码逻辑和设计决策。
>
> 3. **冲突解决**：当我们对技术方案有分歧时，会让 TRAE 分析各方案的利弊，辅助团队决策。
>
> 4. **文档同步**：TRAE 帮我们在代码变更后自动更新相关文档，保持文档与代码同步。

## 提交后流程

1. 提交 Issue 后，等待维护者 24 小时内确认
2. 可能收到补充信息的请求（特别是 Collaboration 细节不够时）
3. 3-5 工作日内收到审核结果
4. 审核通过后，维护者将项目添加到展示列表
5. 你不需要创建 PR 或编写展示文件

## 常见问题

**Q: 个人项目和团队项目在审核时标准不同吗？**
A: 标准相同，但 Collaboration 维度的评估角度不同。个人项目看 AI 结对编程质量，团队项目看团队协作中 TRAE 的角色。

**Q: 项目还没完成可以提交吗？**
A: 可以。共创项目接受从想法到生产的所有阶段。早期项目重点展示协作计划和初步经验。

**Q: 没有在线演示可以提交吗？**
A: 可以。CLI 工具、库等项目不需要在线演示，只要仓库公开即可。
