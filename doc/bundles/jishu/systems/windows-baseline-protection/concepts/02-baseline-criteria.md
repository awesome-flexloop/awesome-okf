# 02 · 首版检查项与 7/8 口径

源文写「把 TPM、安全启动、内存完整性、只加载已签名驱动这些一共 8 项安全检查打包了起来」（F-025）。数字对，但只给了四个例子。微软 IT Pro Blog 给出了**首版完整清单**（F-026）。

## 八项逐条（官方 IT Pro Blog 口径）

| # | 检查项 | 白话：挡住什么 |
|---|---|---|
| 1 | 安全处理器（TPM 2.0） | 用独立硬件保管密钥并测量启动状态，密钥不落在普通内存里 |
| 2 | 安全启动（Secure Boot） | 开机时挡住未受信任的引导程序 |
| 3 | 基于虚拟化的安全性（VBS） | 用硬件虚拟化隔出受保护区，把关键系统进程放进去 |
| 4 | 内存完整性（HVCI） | 挡住往 Windows 受保护内存区域注入代码 |
| 5 | 仅加载已签名驱动 | 挡住没有有效签名的驱动 |
| 6 | Windows 认证驱动 | 再要求驱动满足微软的硬件签名与认证规则 |
| 7 | 内核调试保护 | 挡住调试工具绕过内核安全机制 |
| 8 | 易受攻击驱动保护 | 挡住已知存在漏洞的驱动 |

**判定规则**：全部满足才报告 `true`，缺一项就是 `false`（F-028）。这不是打分，没有「差不多通过」。

⚠️ **必须带「首版」限定词**：官方明确说这些是**现有能力**，新增的是把它们作为一个结果一起评估（F-027）；并且标准会随版本提高（F-031），今天通过首版不代表通过后续版本。详见[03 · 可验证安全状态](03-verifiable-security-state.md)。

## 为什么有的地方写 7 类

| 口径 | 来源 | 拆分方式 |
|---|---|---|
| **8 项** | Windows IT Pro Blog、多家媒体（T1/T2/T3） | 「仅已签名驱动」与「Windows 认证驱动」**分开列** |
| **7 类** | 微软支持页（经 T4 转引） | 把上面两条合并成一项「**测试签名保护**」 |

这是**分类粒度差异，不是任何一方写错**（F-029、核验报告 E2）。本包并列登记 8 项 / 7 类，不裁决单一对错——这也是[洞察 3](../references/insights-and-pattern.md) 的由来：越具体的数字，越要先问「谁拆的、谁合的」。

> 顺带一个同名陷阱：这里说的是 **Windows 基线保护**（设备状态），不是 2024 年前后经 Security Compliance Toolkit 分发的 **Windows Security Baseline**（配置策略包），同名不同物（F-032）。

## 哪两项最常被关掉

多家媒体与源文都指向**安全启动**与**内存完整性**（F-044）：前者常为 Linux 双系统关闭，后者曾被部分玩家为游戏帧数关闭。微软自己也曾建议部分玩家关闭内存完整性以换取性能——这类历史建议与今天的新基线之间存在张力，属于公开讨论中的兼容性问题，不是本包能够裁决的性能结论。

源文进一步推论「以后想要打开正版软件，就要先去 BIOS 里重启还原」（F-044）。这一步**尚未成为事实**：它取决于应用是否真的选择拒绝启动，而截至 2026-11-20 没有任何早期伙伴公开承诺拦截（核验报告 E4、缺口 G3）。可照做的自查步骤见[设备自查](../examples/01-check-your-device.md)。
