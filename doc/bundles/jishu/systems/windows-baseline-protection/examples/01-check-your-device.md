# 01 · 设备自查与三条修复路径

> **前置条件**：基线保护处于 Insider 预览，自 **Experimental 通道构建 26340.10013** 起**逐步推出**（F-019）。不是每台 Insider 机器都能立刻看到该页面；正式可用计划 2027（F-020）。若你的系统没有该页面，属预期情况，**不要据此推断设备是否安全**。

## 步骤 1 · 打开状态页

1. 打开 **设置**；
2. 进入 **安全**（2026-11-17 起新增的独立安全页，M3）；
3. 选择 **基线保护**（Baseline protection）。

官方给的路径即「设置 > 安全 > 基线保护」（F-043、M3）。防火墙控件移到「网络和 Internet」旁、应用与浏览器保护移到「应用」旁，是同一次安全页改版的一部分。

## 步骤 2 · 读懂三种显示

| 显示 | 含义 | 该做什么 |
|---|---|---|
| 全部通过（绿盾 / All protected） | 首版清单所有项已启用 | 无需操作；记住这是**首版**，后续基线版本可能提高门槛 |
| 需注意（黄盾 / Attention needed） | 页面列出**具体缺失项** | 进入步骤 3 |
| 待重启 | 某项已开启但尚未生效 | 重启后复查（官方说明存在 pending-restart 状态） |

> 绿盾/黄盾与按钮文案来自 B 类媒体对预览版界面的走查（T4），预览期 UI 措辞可能调整；**判定逻辑**以官方 M2 为准。

## 步骤 3 · 逐项核对

按[首版 8 项清单](../concepts/02-baseline-criteria.md)逐条对照页面列出的缺失项。最容易缺的两项：

- **安全启动**：常见于装过 Linux 双系统、曾手动关闭的机器；
- **内存完整性**：常见于为游戏性能或降压工具手动关闭过的机器。

另注意两条驱动规则（仅已签名驱动 / Windows 认证驱动）——自定义驱动、测试签名、开启内核调试的机器可能在这里不通过。

## 步骤 4 · 选一条修复路径

| 路径 | 适用 | 操作 |
|---|---|---|
| **A · Windows 内修复** | 系统能自行开启的项 | 用设置页的一键开启按钮，随后**重启**；部分改动重启后才计入状态 |
| **B · UEFI 固件修复** | 安全启动、TPM 等固件级开关 | 按页面引导进入 UEFI 固件设置开启；步骤**因厂商与机型而异**，按设备说明操作并重启 |
| **C · 联系 IT 管理员** | 组织管理的设备 | 策略可能由 Microsoft 365 管理中心 baseline security mode 控制，本地用户无权修改 |

**为什么一定要重启**：官方说明每项要求自启动起强制执行、关闭任一项都需重启（F-030）。反过来说，开启之后也要重启才生效——这一步漏了，页面状态不会变。

## 步骤 5 · 复核

重启后回到同一页面确认状态为「全部通过」。因为状态在一次开机周期内稳定，**查一次即可**，无需反复轮询。

## 边界与常见误读

- ✅ 自查能回答：**这台设备是否满足首版基线**。
- ❌ 自查**不能**回答：某款软件会不会因此拒绝启动。那是应用的策略，见[02 · 判断某应用策略](02-read-an-app-policy.md)。
- ❌ 通过 ≠ 不会中毒；`true` 只表示清单全部启用，不是安全评分（[03 · 可验证安全状态](../concepts/03-verifiable-security-state.md)）。
- ⚠️ 源文说「要成玩机必选项的是禁用 Windows 安全中心」——按官方口径，**关闭 SAC 是在安全中心内的单独开关**，与这里开启基线防护是两件事（核验报告 E3）。
