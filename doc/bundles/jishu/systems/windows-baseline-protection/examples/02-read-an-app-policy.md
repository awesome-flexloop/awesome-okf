# 02 · 判断某应用会不会拦你

[设备自查](01-check-your-device.md)回答「我的机器过不过」。但读者真正想问的是「**我常用的软件还打得开吗**」。这两个问题的答案不在同一层：前者由系统算，后者由每个应用自己定（F-036、F-037）。

用下面五问把二者拆开。五问来自模式[读出方优先](../references/insights-and-pattern.md)，任何一问答不上来就登记为缺口，**不要用推测填空**。

## 可复用核对表

| # | 问题 | 要找的证据 | 常见误答 |
|---|---|---|---|
| Q1 | **测什么** | 官方清单（首版 8 项 / 支持页 7 类） | 把「更严了」当答案 |
| Q2 | **谁读** | 用户、IT 管理员、应用三方；是否开放 API / 令牌 | 只想到「系统自己检查」 |
| Q3 | **谁裁决** | 平台还是应用；官方原话 `you own the policy` | 写成「微软决定拦不拦」 |
| Q4 | **读出后有几档动作** | `allow` / `warn` / `limit features` / `block` | 只记住 `block` 一档 |
| Q5 | **有无公开承诺** | 该应用厂商的官方公告、帮助文档、发行说明 | 把「参与测试」当成「已选 block」 |

## 示例 A · 套用到 Adobe（截至 2026-11-20）

| # | 答案 | 依据 |
|---|---|---|
| Q1 | 首版 8 项设备基线 | F-026（M2） |
| Q2 | 用户、IT、应用三方可读 | F-028、F-034 |
| Q3 | **应用裁决**，平台只报告状态 | F-036、F-037 |
| Q4 | 四档皆可选 | F-035、F-036 |
| Q5 | **无公开承诺采用 `block`**；Adobe 仅称可补充其反恶意与反盗版工作 | 核验报告 C11 / E4 |

→ **结论**：不能写「Adobe 检测不通过就拒绝启动」。正确写法是「Adobe 参与了测试，平台提供拒绝启动这一档，截至该时点未公开承诺采用」。这正是源文被勘误的一句（F-042）。

## 示例 B · 套用到一个已有先例

《战地风云 6》的 Javelin 反作弊要求开启安全启动（F-045）：

| # | 答案 |
|---|---|
| Q1 | 安全启动（单一项，**不是**完整基线） |
| Q2 | 游戏的反作弊组件自行检查 |
| Q3 | **游戏发行方裁决** |
| Q4 | 不通过则无法启动，属 `block` 一类 |
| Q5 | 有公开要求，属**已公开承诺** |

→ 对比可见：先例是**应用自建的单项检查**，基线保护是把这类检查标准化并开放给更多应用。两者都是应用裁决，但证据等级不同（先例有公开承诺，早期伙伴没有）。

## 三个反例（不要这样判断）

1. ❌ 「厂商在早期伙伴名单里」→ 所以会拦我。**参与测试 ≠ 已选档位**（缺口 G3）。
2. ❌ 「我的 Windows 版本够新」→ 所以不会拦。策略按应用逐个定（F-036），与系统版本无直接对应。
3. ❌ 「微软说平台不裁决」→ 所以绝对安全。预览期是否存在默认策略无公开证据（缺口 G1），正确表述是「**无公开证据**」，不是「确定没有」。

## 输出格式建议

把结论写成两栏，避免复述时再次混在一起：

| 能力（平台提供） | 策略（该应用已公开） |
|---|---|
| 四档：allow / warn / limit features / block | （查到的公开原文，或「未公开」） |

> 本表**不输出**「能不能打开」的保证或概率。预览期细则与各厂商档位均可变，复核触发见[bundle 根时效表](../index.md)。
