# 飞书深度集成

> **事实基础**：本文所有具体数据与声明均带 F 编号，完整事实清单见 [references/article-source.md](../references/article-source.md)，核验报告见 [references/verification.md](../references/verification.md)。

## 1. 前提：不依赖飞书，但飞书解锁全部潜力

博文首先澄清（F-018）：
- **不用飞书也完全能用**——文档、PPT、网页、多模态、电脑操作等全部能力都不依赖飞书
- **但用飞书企业账号登录才能"榨干全部潜力"**——自动与飞书信息、数据和工具打通（F-019）

## 2. "工作现场"问题

📝 博文提出核心观点（F-020）：任何Agent都需要一个"工作现场"。我们可以给Agent写一万字prompt描述背景，但它始终很难知道：
- 项目群是哪个
- 事情由谁审批
- 流程是什么样
- 上周会上到底定了什么

**而这些，在飞书里都可以找到。**

## 3. 飞书集成能力矩阵

### 3.1 文档与知识

| 能力 | 说明 | 事实 |
|------|------|------|
| 文档定位与总结 | 可总结最近稿件，定位到具体文章（如DeepSeek Harness上手指南）并总结内容 | F-021 |
| 作品集生成 | 将所有文章做成作品集网页，自动筛选值得放的文章、明确定位 | F-022 |
| 权限继承 | 文档链接同步继承原有飞书文档权限，不未经允许修改访问权限 | F-023 |

### 3.2 消息与组织

| 能力 | 说明 | 事实 |
|------|------|------|
| 组织信息读取 | 识别上级是谁、消息应发给谁 | F-025 |
| AI代发消息 | 自动编辑聊天文案，加"由豆包发送"标签区别真人消息 | F-024 |
| 群聊总结 | 读取群聊记录，还原完整脉络，包括"谁说了算" | F-026 |

**"由豆包发送"标签**（F-024）：豆包工作在飞书内替用户发送消息时，会明确标注「由豆包发送」，确保接收方知道消息来自AI而非真人。这是透明度设计，避免AI冒充人类。

### 3.3 群聊总结 vs 知识库检索

📝 博文特别指出飞书集成与普通知识库检索的本质区别（F-027）：

| 维度 | 普通知识库检索 | 豆包工作+飞书 |
|------|--------------|--------------|
| 数据范围 | 几份可搜索的文件 | 人、消息、文档、权限的关系网络 |
| 上下文保持 | 每次新任务需重新介绍"谁是谁、事情做到哪了" | 理解关系，无需重复介绍 |
| 信息状态 | 静态文档 | 动态的组织关系和工作状态 |

博文举例：没打通群聊的Agent，用户只能不断复制粘贴"王总今天说了什么"，信息永远是散的、滞后的。

### 3.4 多维表格（Bitable）

| 能力 | 说明 | 事实 |
|------|------|------|
| 实时看板 | 多维表格变为实时网页看板，数据刷新看板跟着刷新 | F-028 |
| 素材库 | 批量读取表中内容，批量生成宣传图和视频 | F-028 |
| 从零搭建 | 可让豆包工作从零搭建多维表格数据库 | F-028 |
| 高级视图 | 将单一表格变为有多种视图的高级多维表格 | F-028 |

博文实测场景：用多维表格智能体搭建每日热点追踪 → 飞书自动推送AI热点追加到表格 → 豆包工作基于表格搭建实时更新的AI热点追踪网页。

### 3.5 会议纪要与任务流

这是博文认为"最特别"的体验（F-029、F-030）：

| 阶段 | 多数Agent | 豆包工作+飞书 |
|------|----------|--------------|
| 会议后 | 争取给一份尽可能完善的总结 | 基于结论**继续推进** |
| 任务创建 | — | 给对应负责人创建任务 |
| 状态跟踪 | — | 完成后更新状态 |
| 异常处理 | — | 卡住时告知审批走到哪了 |
| 主动提醒 | — | 替用户给负责人发私信提醒进度 |

## 4. 从"交付产物"到"交付进展"

📝 博文的核心判断（F-031）：

> 大多数Agent交付的单位还是单纯的"产物"——一篇文档、一张图。豆包工作交付的是**进展**，做到了真正地从"帮我们记录"到"帮我们工作"，这中间隔着的，正是飞书里团队沉淀下来的那些真实任务流和审批流。

关键逻辑链：
1. Agent能生成文档/图片 → 交付"产物"
2. Agent能创建任务、跟踪状态、提醒负责人 → 交付"进展"
3. "进展"需要理解组织关系、审批流程、当前状态 → 这些都在飞书里
4. 因此飞书集成是从"工具"到"同事"的关键跃迁

## 5. 跨对象组合

博文总结：豆包工作和飞书深度打通后，把很多真实办公场景串起来了——文档、消息、任务、审批、多维表格、会议纪要不再是孤立功能，而是跨对象的组合工作流。博文认为"这种跨对象的组合或许才是Agent常说的'打通'二字真正的分量"（F-031）。
