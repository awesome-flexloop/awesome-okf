# QBS 方法本体：Question → Book → Skill

> 本篇文章的主线是**方法**，不是某个工具或产品。《Make Time》只是该方法的一次应用产物，其内容在 [01-make-time-framework.md](01-make-time-framework.md) 与 [02-attention-tactics.md](02-attention-tactics.md) 展开。

## 一、方法身份

| 属性 | 值 | F 编号 |
|------|-----|--------|
| 名称 | QBS | F-006 |
| 三步 | Question（问题）→ Book（书籍）→ Skill（技能） | F-006 |
| 作者定位 | 方法实践者（非原创者） | F-007 |
| 来源叙述 | 作者称"最近在 X 上刷到" | F-007 |
| 首个应用场景 | 时间管理 | F-010 |
| 开源落地 | `github.com/LearnPrompt/qbs` | F-033 / F-049 |

**核心主张**：不要直接让 AI 凭已有参数"编"一套 skill，而是让它**先定位一本真书、真读该书相关章节，再把书里的方法提炼成规则**（F-008）。

## 二、三步流程

文章给出的完整流程为（F-008）：

```text
有个卡住的问题
  → 让 gpt6 去找能解决这个问题的书
  → 自己完整读相关章节
  → 把方法提炼成一套能直接用的规则 skill
  → 再拿一个新任务测试
```

| 阶段 | 动作 | 承担者 | 关键点 |
|------|------|--------|--------|
| Q（Question） | 明确一个**具体卡住的问题** | 人 | 问题越具体，找书越收敛（对照作者观点 F-043） |
| B（Book） | 让模型推荐书；**人自己读相关章节** | 模型 + 人 | 阅读环节不由模型代劳，是方法的地基 |
| S（Skill） | 把章节内容提炼为可执行规则，并用新任务验证 | 模型 + 人 | 交付物是"规则"，不是"理论摘要" |

> ⚠️ 注意：**"自己完整读相关章节"是 QBS 不可省略的一环**。文章把阅读放在提示词要求中显式约束（见下节第 ② 条），而非交给模型摘要替代。

## 三、提示词模板（可直接复制）

文章提供了一段可直接使用的提示词（F-009）：

```text
我现在有一个问题：[把具体问题写在这里]。
帮我找一本能解决这个问题的书，完整读相关章节，
然后把书里的方法提炼成直接用的 skill。
```

### 模板内置的五条交付要求（F-009）

| # | 要求 | 作用 |
|---|------|------|
| ① | 说明找到了**哪本书**及**选择理由** | 防止推荐不可溯源、防止凭印象报书名 |
| ② | 说清**实际读了哪些章节** | 强制暴露阅读范围，可被人复核 |
| ③ | 把方法变成**具体操作步骤**，而非只给理论 | 交付物必须是规则，不是读后感 |
| ④ | 用**一个新的实际场景试跑**，证明规则能用 | 内建验证环节，避免"纸上可用" |
| ⑤ | 没找到书或读不到正文就**直接说明**，不要硬编 | 显式给出失败路径，抑制幻觉 |

> **这条 ⑤ 值得单独记住**：它是模板中唯一的"反幻觉"约束——把"找不到"设为合法输出，模型才不会为了完成任务而虚构书目与内容。该约束与作者开源仓库 README 中的"不承诺耗时"口径（F-052）方向一致：**两者都在拒绝给出无依据的确定性**。

## 四、方法为什么成立（分析）

| 观察 | 支撑事实 |
|------|---------|
| 书籍是**经过编辑与验证**的长文本知识源，比模型即时生成更稳定 | F-008 的流程把"找书 + 读书"置于生成之前 |
| 阅读范围可被 ② 条要求**显式化**，交付可被人审计 | F-009 |
| 试跑环节（④）让 skill 带**验证记录**，而非空口声明 | F-009 |
| 失败可声明（⑤），避免模型编造书目 | F-009 |

需要说明的是：**以上为对文章所述流程的机制解释，不是文章原文的论证**。文章本身侧重于流程叙述与个人体验。

## 五、作者的实践背景（自述，不可外推）

作者提出该方法的动因来自自身的注意力困境（F-035 ~ F-038）：

| 事实 | 内容 | F 编号 |
|------|------|--------|
| 并行任务数 | Codex 后台挂着七八个任务，另有团队协作消息要看，一天产出十几二十个结果 | F-035（作者自述） |
| 注意力状态 | 注意力被多个执行结果切割，一天下来没记住几个完成的信息 | F-036（作者自述） |
| 行为模式 | 一天刷了很多次 Codex 面板，每次都觉得"就看一眼点个继续完了" | F-038（作者自述） |
| 认知转折 | 初看觉得"就这？这不就是先做最重要的事吗"，随后修正为"没那么简单" | F-037（作者观点） |

> ⚠️ 上述均为**作者个人经验数据**，不构成对普遍人群的结论。作者据此推算的时间损耗（20 次 × 15 分钟 = 5 小时，F-039）依赖已勘误的切换成本数字，详见 [verification.md](../references/verification.md) 勘误 1 的影响评估。
