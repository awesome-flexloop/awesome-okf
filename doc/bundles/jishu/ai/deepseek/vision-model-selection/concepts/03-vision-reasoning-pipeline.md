# 视觉-推理双模型协作架构

选定视觉模型只是第一步，怎么把它接进以 DeepSeek 为核心的系统才是落地的关键。博文给出的落地模式是：**让视觉模型做感知，让 DeepSeek 做判断**（F-028）。

## 分工原则

落地时最好让视觉模型只返回五类感知结果，再交给 DeepSeek 判断（F-028）：

| 视觉模型只返回 | 说明 |
|---------------|------|
| OCR 文本 | 图中文字的转写（F-028） |
| 物体 | 图中识别到的对象清单（F-028） |
| 位置关系 | 物体间的相对位置（F-028） |
| 表格 | 图中表格的结构化转写（F-028） |
| 不确定项 | 视觉模型自身拿不准的内容，交由下游裁决（F-028） |

判断、推理、决策统一收敛到 DeepSeek 一侧。本地隐私场景展示了同一模式的本地化版本：MiniCPM-V 负责提取图片信息，DeepSeek 负责后续分析（F-024）。

> 事实溯源：F-024、F-028

## 三大收益

### 收益一：输出 tokens 更少

视觉模型只返回结构化感知结果而非长篇自由文本，使输出 tokens 更少（F-029）。在博文覆盖的价格表中，输出单价普遍高于输入单价（FlashX 输入 $0.04、输出 $0.40，F-013；豆包输入 ¥0.2、输出 ¥2，F-015；Gemini 2.5 Flash-Lite 输入 $0.10、输出 $0.40，F-019），压缩输出侧 tokens 直接影响成本。

### 收益二：识别结果可缓存

图片的感知结果不随下游问题变化，识别结果还能缓存（F-030）。同一张截图被多个任务复用时，视觉调用只需一次，缓存命中后的边际成本趋近于零。

### 收益三：避免两个模型重复推理

判断集中在 DeepSeek 一侧，能避免两个模型重复推理（F-031）。如果视觉模型既感知又下结论、DeepSeek 再判断一遍，等于同一推理花两份钱。

> 事实溯源：F-013、F-015、F-019、F-029 ~ F-031

## 成本意识：任务档位匹配模型档位

架构之外是成本意识：**识别报错弹窗也上顶配旗舰模型属于成本浪费**（F-032，作者观点）。

报错弹窗是视觉任务里最轻的档位——只需要 OCR 出文字与按钮这类感知结果（F-028），判断交给 DeepSeek。这类简单任务用免费或低价模型即可：GLM-4.6V-Flash 官方价格免费、适用中文截图与 UI 页面（F-010、F-011）；GPT-5 nano 便宜、适合图片分类与简单截图识别（F-021）。

完整的成本演练见 [成本-场景选型演练](../examples/cost-scenario-walkthrough.md)。

> 事实溯源：F-010、F-011、F-021、F-028、F-032

## 小结

双模型协作架构 = **感知收敛 + 判断收敛**：视觉侧按场景选够用的模型（[按场景选型矩阵](02-scenario-matrix.md)），感知输出结构化（[视觉模型输出结构设计示例](../examples/pipeline-output-structure.md)），判断收敛给 DeepSeek。三大收益（F-029 ~ F-031）让这条管线在成本上可解释、在工程上可缓存。
