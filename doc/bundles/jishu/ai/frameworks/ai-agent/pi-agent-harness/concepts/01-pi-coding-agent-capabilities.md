## 默认工具集

Pi 进入项目目录启动后，默认只给模型四个工具（F-011）：

| 工具 | 功能 |
|------|------|
| `read` | 读取文件内容 |
| `write` | 写入/创建文件 |
| `edit` | 修改已有文件 |
| `bash` | 执行终端命令 |

> 作者强调（F-011延伸）：一个能读写文件、修改代码、运行命令的模型，已经可以完成绝大多数本地编程任务——理解项目、修 Bug、重构、跑测试、写脚本、生成文档，甚至调用电脑里已有的 CLI 去操作别的系统。

## 多模型支持

Pi 支持多家模型服务商和自定义接口（F-012~F-013）：

| 服务商 | 备注 |
|--------|------|
| Anthropic | Claude 系列 |
| OpenAI | GPT 系列 |
| Gemini | Google |
| DeepSeek | 国产模型 |
| Kimi | 月之暗面 |
| MiniMax | 国产模型 |
| OpenRouter | 聚合路由 |
| 自定义兼容接口 | 本地模型或其他兼容 OpenAI 格式的接口 |

> 典型用法：需要速度时用快模型，需要攻坚时再切强模型，不必换一套 Agent 外壳。

## 扩展机制

Pi 真正有意思的地方，不是它默认做了多少，而是它允许你自己决定要加什么（F-014）：

| 扩展方式 | 适用场景 |
|---------|---------|
| **Skill** | 经常重复的一套做事方法 |
| **Prompt Template** | 经常重复的一段提示词 |
| **TypeScript Extension** | 需要增加新工具、命令、快捷键、权限检查、界面组件或事件钩子 |
| **Pi Package** | 把整套能力打包发给别人 |

可改造方向示例：代码审查 Agent、文档 Agent、运维 Agent、研究 Agent、公司内部流程专用助手。

## SDK 接入方式

通过 `pi --mode rpc` 可通过标准输入输出交换 JSONL 消息，让非 Node.js 程序也能调用 Pi（F-015）：

```
非Node.js程序
    │
    ▼ JSONL over stdin/stdout
pi --mode rpc  ──→  pi-agent-core
```

这意味着使用者不必从零开始处理模型流式输出、工具循环、会话保存、上下文压缩和事件订阅——Pi 已经把最麻烦的那层骨架搭好了。
