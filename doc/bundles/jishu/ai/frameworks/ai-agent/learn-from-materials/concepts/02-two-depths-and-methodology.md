# 02 两种学习深度与方法论库

> 对应事实：F-014~F-016、F-039、F-041
> 核验状态：✅ 以官方 README（EN/CN 双份）为准

## 为什么要有"深度"开关

同一份材料，读者诉求差别很大：有人只想**快速知道它讲了什么**，有人要**逐章吃透并记住**。learn-from-materials 用两种深度覆盖这两类场景（F-014）。

| 维度 | 快速了解（Quick Overview） | 系统学习（Systematic Study） |
|------|---------------------------|------------------------------|
| 目标 | 快速掌握材料全貌与核心观点 | 逐块读透、建立可回顾的完整学习资产 |
| 覆盖 | 概览式组织 | **逐块读到材料末尾** |
| 方法论 | 绑定候选方法论（`prepare_quick.py`） | 逐块审计方法论候选项去向 |
| 完成判据 | 六板块页面生成完毕 | **"卡片数量不作为完成证明"**（F-015） |

> 官方明确否决"堆卡片"式伪完成：**系统学习必须逐块覆盖到材料末尾**，并审计每个方法论候选项最终去哪了（绑定/丢弃/合并）。这是质量约束，而非可选建议。

## 方法论库：methods.json / methodology.json

材料里往往隐含了作者的**方法**（做事步骤）与**方法论**（方法的组织方式）。Skill 把两者拆成可绑定的结构化数据：

```mermaid
flowchart LR
    M[材料] --> C[提取方法候选]
    C --> MJ[methods.json<br/>方法清单]
    C --> MY[methodology.json<br/>方法论清单]
    MJ -->|methods.py bind| B[绑定到材料结构]
    MY -->|methodology.py bind| B
    B --> P[页面"行动规则"板块]
```

- **方法候选**：从材料中识别出的可执行步骤/规则
- **绑定（bind）**：把候选项关联到材料的具体章节与来源位置
- **去向审计**：系统学习模式要求说明每个候选最终如何处置

## 三类同源产出（F-016）

同一次转换会生成三类**同源**产物——都来自同一个 `.learnkb/`，因此内容一致：

| 产出 | 形态 | 用途 |
|------|------|------|
| `.learnkb/` | 结构化知识库（目录） | 机器可读的中间事实源，可复用、可增量 |
| **交互式单文件 HTML** | 单文件网页 | 直接打开阅读：六板块 + 主题 + 自检 + 本地笔记 |
| **同源 Markdown** | 文本 | 便于二次编辑、版本管理、导入其他工具 |

> "同源"是关键：不是分别生成两套内容，而是从同一知识库派生，**避免 HTML 与 Markdown 说法不一致**。

## 命令行链（F-039）

全部在 **Skill 根目录**运行：

```bash
python extract.py                 # 提取 + 能力检查
python methods.py bind            # 绑定方法候选
python methodology.py bind        # 绑定方法论候选
python prepare_quick.py           # 快速了解路径预备
python pipeline.py assemble       # 组装页面数据
python render_page.py             # 渲染单文件 HTML
python finalize.py                # 绑定 + 核验 + 打包交付
```

在宿主中通常**不必手敲这些命令**——Agent 会根据 `SKILL.md` 自动编排。手动运行的价值在于：排查、复现、对中间产物做定制。

## 什么材料适合哪种深度

官方给出的适配建议（F-038）：**长书、多材料交叉分析、专业论文和复杂开放题**更适合**长上下文、高推理能力**的模型。

参考选择：

| 材料 | 建议深度 |
|------|----------|
| 一份几十页报告、想快速掌握 | 快速了解 |
| 一本电子书、要逐章学 | 系统学习 |
| 多份材料要交叉分析 | 系统学习（且需更强模型） |
| 只想看看讲了啥的短文 | 快速了解 |
