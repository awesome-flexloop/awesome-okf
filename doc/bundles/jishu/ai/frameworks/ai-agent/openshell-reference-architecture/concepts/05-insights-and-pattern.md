# 洞察与迁移

以下结论是基于[事实台账](../references/article-source.md)的作者分析，不是 NVIDIA 的逐字表态。证据来自单一厂商设计，跨领域迁移尚无实践验证。

## I-001 访问路径决定控制覆盖

| 四元组 | 内容 |
|---|---|
| 陈述 | 可信授权组件的覆盖范围取决于访问是否必经它 |
| 证据 | Supervisor 中介与外围 fence（F-018、F-020）；Sentry 唯一路径前提（F-058） |
| 反常识 | 增加安全组件数量不自动增加控制覆盖；一条旁路即可使部分访问脱离治理 |
| 行动 | 以每个目标服务为单位枚举直连、DNS、内部地址和替代接口，验证未授权访问确实被阻断 |

现象是软件与硬件方案都强调受控路径；机制依据是授权只有在被调用时才能生效。影响是采购或架构图不能独自证明覆盖率。建议把“组件存在”与“路径不可绕行”分别验收。

## I-002 配置状态与生效状态需要分开

| 四元组 | 内容 |
|---|---|
| 陈述 | 发布策略、运行时接受策略、实际请求被新策略约束，是三个证据环节 |
| 证据 | 创建时锁定与热更新分工（F-030）；意图发布不等于应用（F-039）；audit 与 enforce 区别（F-042） |
| 反常识 | YAML 已更新、证明器已运行或审计日志已出现，都不足以单独证明阻断已生效 |
| 行动 | 对同一工作区保留发布、应用、拒绝结果的关联证据，并用新旧规则相反的请求验证变化 |

现象是声明式部署容易把配置文件当终态；机制依据是配置传播与执行存在不同生命周期。影响是错误的成功状态可能长期保留。建议对锁定策略使用重建验收，对热策略使用生效回读和请求验证。

## I-003 撤销能力需要包含业务终点

| 四元组 | 内容 |
|---|---|
| 陈述 | 撤销必须沿工作区进程、网络和目标业务授权分别核对 |
| 证据 | 网络、进程、授权是不同结果（F-044）；凭证 generation（F-027）；带外检测后响应（F-056）；在途授权与传播上界（F-064） |
| 反常识 | “已隔离”不等于权限已失效，更不等于已写入的数据或订单已撤回 |
| 行动 | 标出最后一次被目标接受的动作，对后续访问测试拒绝，对已接受副作用设计业务补偿 |

现象是新闻稿强调响应速度；机制依据是不同系统分别接受权限与动作。影响是安全响应成功仍可能留下业务损失。建议把技术撤销和业务补偿交给各自责任方，并分别记录完成证据。

## E 边界先行治理

**成熟度：L1，单案例待验证。** 模式是本教程归纳，不是官方产品名。下面的反模式来自本次新闻稿与技术文档核对暴露的误读风险，不虚构生产事故。

适用于：不可信自动执行主体需访问高价值服务，且可以把授权放在必经路径的系统。不限于 AI。

不适用于：无法控制访问路径、目标系统不支持撤权，或已经不能建立独立信任域的场景。此时不能承诺完整治理，应缩小能力或改变部署形态。

1. 列出执行主体、访问对象与可能的失陷域。
2. 将身份、授权、证据和撤销职责分配到明确组件。
3. 建立必经路径，拒绝其他出口。
4. 分别核对策略发布、应用、请求结果。
5. 按进程、网络、下游权限和业务副作用分别演练响应。
6. 用故障与绕行测试收集证据，保留尚未覆盖的条件。

| 反模式 | 本案例中的风险 | 检验标准 |
|---|---|---|
| 硬件存在即治理完成 | 把 DPU 名称视为 Phase II 证据 | 必经路径、独立管理和失败行为均有验证 |
| 文件更新即策略生效 | 把挂载 YAML 更新视为阻断成功 | 应用反馈和实际拒绝结果一致 |
| 隔离成功即业务撤回 | 把毫秒响应与业务安全等同 | 后续授权被拒绝，已接受副作用另行处理 |
| 厂商数字直接算收益 | 省掉最高值和工作负载限定 | 固定环境、任务和基线后获得本地测量 |

### 迁移思想实验

在非 AI 的自动支付批处理系统中，可将批处理进程视为执行主体，支付 API 为目标，凭证代理为授权必经路径。网络断开后仍要撤销目标凭证，并对已经接受的付款走业务退款或冲正。这是结构类比，不是经过银行生产验证的推荐架构，也不意味着支付符合监管要求。

### 可证伪条件

如果发现未受控出口、执行域能修改可信授权方、旧凭证仍有效，或目标业务无撤销与补偿机制，则模式的完整覆盖假设不成立。迁移应报告这些反例，不应通过增加组件或改写成功状态掩盖它们。

### 成熟度维护

本包的计数单位是具有独立部署、责任人和实测证据的实际案例。同厂商多篇文档、重复审查和迁移思想实验均不计入 `validation_count`。L2 晋级至少需要两个独立实际案例，记录必经路径、策略生效、撤销及适用边界证据，并再次审查；不能只修改等级字段。反例出现时保留原记录，收缩适用域并重新验证；核心前提无法成立时标记弃用，不继续累计成功次数。
