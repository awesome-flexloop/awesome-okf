# 一个月三件事：时间线与官方口径

> **性质声明**：本文是行业评论的知识化重组，非官方文档、非操作教程。所有具体日期与范围均带 F 编号，完整清单见 [references/article-source.md](../references/article-source.md)，核验与勘误见 [references/verification.md](../references/verification.md)。

## 0. 术语表（先看这个）

| 名称 | 是什么 | 本文中的角色 |
|---|---|---|
| 扣子 / Coze | 字节的 AI Agent 开发平台，含低代码工作流、Bot、知识库、扣子编程 | 企业版套餐退场（F-003~F-008） |
| TraeWork | 合并前的办公向产品，偏任务、内容生成 | 被合并方（F-010） |
| TraeCode | 合并前的编程向产品 | 被合并方（F-011） |
| TRAE | 合并后的统一产品，一个客户端内含 Agent 与 IDE 两种模式 | 承接方（F-012~F-014） |
| 豆包 | 字节的 AI 助手主品牌 | 能力与账号的汇点 |
| 豆包工作 / Doubao Work | 面向生产力场景的 Agent 产品，可与飞书打通 | 工作场景承接方（F-024~F-026） |
| 豆包飞书账号 | 打通豆包、飞书、PICO、火山引擎等产品的统一账号体系 | 身份层整合（F-017、F-020） |

> 一句话关系：**扣子做工作流，TraeWork 做办公，TraeCode 做编程；合并后 TRAE 收工程，豆包工作收办公，账号统一到豆包飞书。**

## 1. 先厘清标题

原题用"扣子和 TRAE 陨落"（F-037）。**这是媒体修辞，不是产品事实**：扣子收缩的是企业版套餐，个人版继续运营；TRAE 做的是入口合并与账号统一，不是停运（F-008、F-012、F-017）。阅读时把"陨落"替换为"收口"，后续判断才不会跑偏。

## 1. 三件事的并列表述

| 事件 | 对外日期 | 动作 | 范围 | 终局时间 |
|---|---|---|---|---|
| 扣子企业版下线 | 2026-10-29 公告（F-003） | 停止新售 → 全面下线 | 企业标准版/旗舰版 + 火山引擎旧版套餐（F-004~F-006） | 旧版 2026-12-31；新版 2027-12-31 |
| TraeWork 与 TraeCode 合并 | 2026-10-09 发布（F-009） | 两个产品变一个入口，Agent + IDE 双模式（F-012） | 原 Work 的办公/内容能力并入原 Code 的工程能力 | 旧版 TraeWork 客户端 2026-10-23 结束服务（F-015，媒体转述） |
| TRAE 账号升级 | 2026-11-06 公告（F-016） | 个人账号并入豆包飞书账号体系 | TRAE CN 版个人用户，企业客户除外（F-017、F-018） | 2026-11-18 起自动升级 |

三件事横跨 10-09 到 11-06，作者的"短短一个月"（F-040）在日期上成立；但三者的性质并不相同：一件是**套餐退场**，一件是**入口合并**，一件是**身份统一**。

## 2. 扣子：两阶段，不是一刀切

官方公告的措辞是"暂停新售"与"全面下线"两阶段，未使用"分阶段下线"四字（见 E-3）。按官方表格拆开看：

| 阶段 | 时间 | 对象 | 客户安排 |
|---|---|---|---|
| 暂停新售 | 2026-11-30 | 企业标准版、企业旗舰版 | 已签合同未下单的，联系商务确认开通 |
| 旧版退场 | 2026-12-31 | 火山引擎购买的旧个人进阶版、旧企业版、旧团队版 | 未使用部分自动退款至火山引擎账户 |
| 新版退场 | 2027-12-31 | 企业标准版、企业旗舰版 | 新购/续费/增购的服务到期日均不得晚于该日 |

三个容易读错的细节：

1. **到期后仍可续费 14 天**，超过 14 天按新购处理（F-046）。
2. **个人版不在本次下线范围**（F-008）。官网公告列表另有《扣子个人版套餐价格调整公告》（F-049），说明个人版仍在运营、只是调价（E-1 的证据）。
3. **资源导出安排尚未公布**。官方写明对话、记忆、文件、编程项目、低代码工作流的导出与备份"将在后续公告中明确"（F-048）——这是企业客户真正需要盯的待办，而不是下线日期本身。

## 3. TRAE：从两个产品到一个入口

合并前的分工很清楚：TraeWork 偏办公、任务与内容生成（F-010），TraeCode 专注专业编程（F-011）。合并后的 TRAE 不是简单二选一，而是把两种使用姿势放进同一个客户端（F-012）：

| 模式 | 面向 | 主要动作 |
|---|---|---|
| Agent | 统筹项目、多任务并行 | 任务拆解、工具调用、多项目协作、多 Agent 分头推进（F-013） |
| IDE | 进入具体工程细改 | 代码编辑、调试、开发（F-014） |

这个设计的实质是**让"办公任务"可以平滑升级为"工程项目"**：先用 Agent 把需求变成文档与任务，需要改代码时再切 IDE，产物留在同一项目里。硅星人的实测还补了两个端侧事实：网页端与移动端同步覆盖，移动端不再区分 Work 与 Code（V-07）。

## 4. 账号：比客户端合并更强的信号

11-06 的公告要求个人账号在 11-18 自动升级为豆包飞书账号（F-016、F-017），企业客户不参与（F-018），原有代码、项目、历史、会员权益与积分保留（F-019）。升级后同一账号可登录豆包 App、飞书、PICO、火山引擎、豆包输入法等（F-020）。

为什么把账号单列一节？因为**客户端可以并存，账号体系只能有一个**。合并客户端是产品层动作，统一账号是身份层动作；后者一旦完成，用户在产品之间的迁移成本被抹平，入口收拢才真正不可逆。

## 5. 组织层：先并团队，再并产品

时间顺序是倒过来的：2026 年 8 月先做团队整合，TRAE、扣子团队整体并入豆包体系（F-021）；同月明确 TRAE Work、扣子与豆包的工作场景能力整合，TRAE IDE 与 CLI 作为豆包品牌下的编程产品线继续发展（F-022、F-023）；8 月下旬豆包工作亮相（F-024）。

也就是说，10 月与 11 月的三次对外动作，是 8 月组织调整的**落地排期**，不是临时起意。这条因果链在原文中是隐含的，本节按事实顺序还原，不替作者补因果结论。

## 7. 企业读者清单（若你在用扣子企业版）

按官方公告，需要按顺序处理四件事：

1. **对合同**：确认套餐类型（火山引擎旧版 / 新版企业标准版或旗舰版）与合同到期日（F-004~F-006）。
2. **定续费**：未到期可续费或增购，但服务到期日不得晚于 2027-12-31；已到期只有 14 天续费窗口（F-046）。
3. **盯导出**：对话、记忆、文件、编程项目、低代码工作流的导出安排“将在后续公告中明确”（F-048）——这是当前唯一没有时间表的待办。
4. **算退款**：旧版套餐超出 2026-12-31 的未使用部分自动退回火山引擎账户（F-047）。

> 以上均可在官方公告原文核对；本包不复述合同条款，也不提供采购建议。

## 8. 本包不采信的三类说法

1. "扣子停了"——停的是企业版套餐，个人版在运营（E-1）。
2. "TRAE 没了"——TRAE 在扩端、在统一账号，是形态变化（F-012、F-017）。
3. "字节官方宣布"——合并的对外形态是 TRAE 产品更新与媒体实测，非集团新闻稿（E-4）。
