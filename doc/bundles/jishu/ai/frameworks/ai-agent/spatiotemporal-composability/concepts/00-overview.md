# 00 · 总览：一篇论文在解决什么

> 一句话：论文把「插件装上去以后能不能干净地拆下来」和「依赖变了以后谁该跟着动」这两件事，从每个组件作者凭记忆维护的纪律，变成运行时可以结构性保证的机制。

## 1. 先用 6 行看懂核心动作

下面这段是**示意伪代码**，不是任何框架的真实 API，论文里也没有它。它只用来建立直觉：

```
function timerPlugin(ctx) {
  const id = setInterval(tick, 1000)   // ① 修改了共享环境
  return () => clearInterval(id)       // ② 同一处交出「怎么撤回」
}
// 卸载时：运行时把 ① 交出的逆按后进先出顺序全部执行
```

关键在于 **① 和 ② 写在同一个表达式里**。传统做法是把清理放进另一个 `deactivate` 钩子里，于是「有没有漏清一个定时器」只能靠人去核对两处代码。论文把这个约定 reify 成类型：一次上下文变换不返回新状态，而是返回「新状态 **＋** 一个就地生成的逆函数」。逆在看到具体状态的那一刻产生，而不是事先猜一个全局逆（F-024、F-030）。

由此得到两件事：卸载任意组件时，其余组件看到的世界与「它从未被加载」在观测上无法区分；依赖的提供方被换掉时，依赖方会按声明自动停用、重解析、再启用，而不需要写迁移脚本。

## 2. 论文的两个维度

| 维度 | 要求 | 静态世界里的对应物 |
|---|---|---|
| 时间可组合性 | 组件移除时，它对共享环境的修改须完整且安全地回退 | 词法作用域、RAII、bracket pattern（F-009、F-011） |
| 空间可组合性 | 组件须能声明、发现、解析彼此依赖，并随依赖变化协调生命周期 | 模块导入解析（F-010、F-011） |

静态语言里这两件事由编译器和作用域规则兜住；一旦把装配推迟到运行期、并且允许热插拔，编译器就退场了，而多数插件框架没有等价物。详见 [01 · 两个可组合性](01-two-composabilities.md)。

## 3. 三层抽象地图

本包其余各篇按「自底向上」排列，读之前先记住这张地图：

```
第 3 层  动态组合演算 + 元理论   → 07、08 篇：九条规则与七个定理
第 2 层  响应式协同效应          → 05 篇：依赖是带类型的键，变化会通知
第 1 层  可逆效应                → 04 篇：每次修改自带逆
            ↑ 三者共用同一个上下文（06 篇），由 Cordis 落地（09 篇）
```

- **第 1 层**回答「怎么撤回」。
- **第 2 层**回答「谁依赖谁、变了通知谁」。
- **第 3 层**回答「多个组件同时装卸时，什么顺序是合法的、最终会不会收敛」。

论文的第 3 层是形式化最重的部分，也是唯一给出了可证结论的部分；前提和「不保证什么」会在 [08 · 元理论](08-metatheory.md) 逐条列出。

## 4. 本包是什么、不是什么

| | 本包 | 兄弟包 `cordis/` | 兄弟包 `deepseek-harness/` |
|---|---|---|---|
| 视角 | 论文精读教程 | 框架源码机制 | Agent 框架应用 |
| 口径 | arXiv:2608.25512v1（2026-08-26，92 页） | 早期草稿概念引子 + 4.0.0-rc 源码 | 产品落地 |
| 形式化 | 定义、定理、演算规则逐条讲 | 概念性引用 | 不涉及 |

三者互为入口而非重复。既有 `cordis/references/background-paper.md` 记录的是**更早的草稿**口径（2026-08-13、约 88 页），与 arXiv v1 属版本差异（勘误 E-04），本包不改写它、也不复制它的内容，只做互链：[背景理论章节](../../cordis/references/background-paper.md)、[源码级效应机制](../../cordis/concepts/effects-coeffects.md)。

**本包不含**可运行示例、部署实测与性能基准：论文给的是伪代码与形式模型，没有可复现的安装 / 配置 / 调用流程，故不设空的 `examples/` 目录。理论符号到 API 的对照见 [理论符号 ↔ Cordis API 映射全表](../references/theory-api-mapping.md)。

## 5. 阅读前须知

- 全部事实以 `F-xxx` 编号标注，可在 [论文事实台账](../references/facts.md) 回查原文页码；形式符号集中在第 04 篇之后才引入，前四篇不要求数学基础。
- 论文是**活跃修订中的预印本**（F-003、F-004）。本包依据 v1，到期复核日 2027-02-28。
- 论文把「自我演化 Agent Harness」列为**未来验证方向**（F-072），不是已完成的实证；Koishi 案例是单生态、单宿主语言、观察性证据，作者自己在 Threats to validity 中说明其非对照实验（F-065）。
- **结构性保证 ≠ 自动验证**：运行时并不校验组件交出的逆是否真能回退，也不校验键上操作是否可交换，这两项是组件作者的义务（F-059）。这是本教程最容易被误读的一点。
