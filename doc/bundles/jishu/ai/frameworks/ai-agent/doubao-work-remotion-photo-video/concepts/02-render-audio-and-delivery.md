# 渲染声音与可维护交付

作者称确认静帧后得到 1080p、30 秒视频，初版没有配乐，后来追加需求才补入音乐（F-019/F-020）。本次没有播放成片，不能确认它的声音、分辨率或实际时长。这个过程提醒我们在开始制作时写明声音要求，并把“渲染生成”和“交付通过”分开。[事实登记](../references/article-source.md)

## 先冻结已批准的设计

建议在渲染前记录分镜版本、素材清单、字幕文本、声音来源和输出规格。若 Agent 想改变照片顺序或换音乐，应先说明变动；批准静帧不等于批准任何后续改稿。

动态预览用于查镜头衔接和字幕时序，完整渲染用于产生目标文件。官方文档给出的 `npm run dev` 是项目预览入口（F-027），`remotion-render` 技能负责视频或静帧渲染（F-025）。预览能打开，不代表最终格式可播放。

## 读懂渲染命令

以下是官方 CLI 的结构参考，**占位符不可原样执行，本次未运行渲染**：

```text
npx remotion still <entry-point或serve-url> <composition-id> <output-location>
npx remotion render <entry-point或serve-url> <composition-id> <output-location>
```

静帧对应 F-028，视频或音频对应 F-030。执行时先从项目确认入口、composition 标识和输出位置，不根据文章猜 `src/index.ts` 或某个视频 ID。

| 术语 | 含义及取得方式 |
| --- | --- |
| entry-point | 注册视频定义的项目入口文件；由 Agent 从实际项目确认 |
| serve-url | 可供渲染器加载项目的服务地址；由实际运行配置提供，不是任意网页地址 |
| props | 项目接收的输入参数，例如照片清单或标题；须符合该项目定义 |
| fps | 每秒帧数，是输出规格的一部分；不确定时先请 Agent 建议，待用户确认 |

官方 render 提供 `--width`、`--height`、`--fps` 和 `--duration`，其中 duration 单位为帧（F-031）。如果你自行要求 30 秒、30 fps，计算结果是 900 帧，这是教学算例，不是作者的帧率记录。不要把 `--duration 30` 误当 30 秒；同时核对项目的 duration、fps 与 CLI 覆盖值是否一致。

旧项目还应按依赖锁文件中的 Remotion 版本核对参数支持范围；当前官方文档列出的选项不能直接当作旧版本保证。原案例依赖版本仍未知。

Windows 上把 props 写进 JSON 文件通常比内联 JSON 引号更稳妥，这是 still/render 文档给出的建议（F-032）。没有 props 的项目不用为了模仿教程添加参数。依赖、浏览器、字体或素材加载失败时，先保存实际报错再定位，不能把自然语言“已完成”视为成功证据。

## 配乐与字幕都要定义来源

官方技能目录中 captions 提供字幕指导，markup 涵盖音频与时序知识（F-025）；没有证据说明它们会自动提供可商用音乐库。作者说补上音乐（F-020），也未给本次可核验的授权文件。

建议使用有明确许可的音乐，并保留作者、来源、许可范围与署名要求。个人收藏或可在线试听不等于允许发布和商业使用。没有合适授权时，可以交付清楚标记的无声版，而不是自行下载一首歌。

成片发布、商业使用和源素材转交是不同权限。音乐或照片获准嵌入成片，不自动允许随可编辑项目再分发；不能转交的文件用映射说明或占位替代，由接收方自行取得许可。交付包内容需要单独确认。

声音审核至少听完整片，检查开头与结尾是否突兀、音量是否掩盖旁白、切点是否影响叙事。字幕只写已确认的事实；旁白转录也需要回听，不能把自动字幕当成无误原文。这些都是交付建议，不是豆包自动质检能力的官方保证。

## 全片检查

| 层次 | 建议看什么 | 可以记录的通过证据 |
| --- | --- | --- |
| 文件 | 输出确实存在，可用目标播放器打开 | 文件名、格式、播放器、打开结果 |
| 规格 | 时长、画面尺寸、帧率与批准需求一致 | 媒体信息与需求逐项对照 |
| 动态画面 | 全片字幕、裁切、转场、黑帧、闪烁 | 问题所在时间点及修订结果 |
| 声音 | 是否应有音乐/旁白，音量与收尾 | 完整试听结果，授权记录 |
| 内容 | 人名、地名、照片顺序、隐私 | 用户确认文本和素材范围 |
| 可维护性 | 项目、素材映射与依赖记录可找到 | 交付目录与说明 |

文章中的自动画面质检仅为作者叙述 F-017。不要把 Agent 自评“画面很好”代替这张对照表，更不要只看一张截图就声称视频质量通过。

## 返工时保留可比版本

建议将反馈写到具体时间点，保留上一个输出，给新版本使用不同文件名。例如“12 秒标题出现太晚，提前到该镜头开始；配乐与其他镜头不变”。这能帮助核对改动，也避免修一个镜头时整体重写。

下面仍是**原创模板，非原文补配乐提示词，未在豆包实测**：

```text
以已确认的分镜与静帧版本为基准。
请先报告待渲染规格、声音来源、输出路径及预计资源消耗，等待确认。
按已批准的总费用上限与重试次数执行；超出上限、购买、订阅或开通许可前另行确认。
默认不向第三方上传照片、缩略图或隐私日志；需外传时按需求阶段的独立审批条件停止等待。
不要覆盖原版。完成后报告实际文件与媒体信息，不用计划值冒充实测值。
我会完整播放并按时间点反馈；未确认前不要发布。
若缺音乐授权，先保持无声并标注，不自行下载替代。
交付视频、可编辑项目、素材映射、字幕文本、依赖记录和运行说明；只打包获准转交的源素材。
```

程序化视频的可维护价值在于后续修改可回到项目。只给一个视频文件适合一次性观看；需要换照片或批量出片时，项目与授权记录同样重要。跨场景如何使用审核顺序，见[先预览后出片](03-preview-before-render-pattern.md)。

需要长期维护时，另保存依赖锁文件、运行环境和技能版本、素材及字体清单。只有在新环境实际重建并记录结果后，才标为“已验证可重建”；文件和说明存在本身不证明日后仍能渲染。
