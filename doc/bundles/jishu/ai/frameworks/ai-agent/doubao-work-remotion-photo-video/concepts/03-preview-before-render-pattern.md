# 先预览后出片

作者在照片视频案例中先看镜头静帧，再确认渲染（F-015/F-018）。Remotion 官方有静帧输出能力（F-028），但本次没有运行原项目。由此提出一个单案例候选模式：在较昂贵或难撤回的产出前，先检查能低成本观察的部分，再对剩余风险安排后续验收。[事实登记](../references/article-source.md)

## 使用边界

适用于能分阶段产生可审核中间物的任务，例如照片视频的分镜和代表帧。前提是中间物与最终产出关联清楚，审核者知道它遗漏什么。

不适用于中间物无法代表关键风险的场景，也不能替代安全关键系统的完整测试。若最主要问题是声音、时序或运行行为，一张静态图的价值有限。快速低成本一次性输出也未必值得增加多轮审批。

## 五步做法

1. 写明最终要求和不可接受的问题，包括素材权限、规格、文字与声音。
2. 选择便宜的中间物，并说明它能检验什么、不能检验什么。
3. 逐项审核，记录具体位置、问题和修改要求，不用“不错”代替通过条件。
4. 冻结已批准版本，授权下一阶段；发现输入或规格变化时重新确认。
5. 检查完整结果与剩余风险，保存版本及交付记录，不能把预览通过转写为全片通过。

## 风险反模式

下表三项均为风险推演。作者补音乐的过程只能证明需求发生过追加，不能证明初始需求要求配乐或作者漏审声音；其他两项同样不是已发生的作者失败经历。

| 反模式 | 案例或证据边界 | 建议防护 |
| --- | --- | --- |
| 用画面验收代替声音需求确认 | F-020 记录初版无配乐、后补音乐；也可能是正常新增需求 | 开始时明确声音要求，新增需求单独确认，交付时完整试听 |
| 只看代表帧便判全片合格 | 作者静帧与成片为不同阶段 F-015/F-019；本次未播放视频 | 动态预览和完整输出单独验收 |
| 把 Agent 自述当运行证明 | 安装和自动质检只有作者叙述 F-011/F-017 | 查看实际项目、产物与失败记录，不从回复推定成功 |

## 如何检验模式是否有用

先记录预览阶段发现的实际问题、返工次数和耗时，再与相近复杂度任务比较。没有对照数据，不能宣称节省百分比。

任务完成的最低证据是：中间物与最终版本对应、审核意见有处理结果、完整文件满足已批准规格、动态与声音风险另有检查。候选模式的效果验证还需要独立案例；本次 `validation_count: 0`，未完成运行效果验证。

后续计数只在独立实际案例有预先判据、审核成本与遗漏记录、完整结果及效果判断时增加。单次渲染成功只证明运行完成；文档复核、补看原作视频和跨域类比均不增加模式验证数。失败案例也保留记录，不只选择成功案例。

## 跨域迁移推演

印刷宣传册可以先看低分辨率校样，核对文字、图片和版式，再制作正式印刷文件。但校样不能验证纸张、色彩或装订，仍需打样和成品检查。

这与视频静帧的关系是方法类比，未在本次实际印刷或测量成本。迁移成立的检验问题是：中间物能否暴露关键错误；其余风险是否有后续检查；批准对象是否与最终输入同版本。任一无法回答，就不应沿用该模式。
