# 工程评估与可迁移方法

官方建议把复杂判断分成小问题，再由代码组合答案；同一请求中的问题共享状态、独立计算。[F-029、F-038](../references/article-source.md) 把这种能力接入业务前，需要同时定义模型要回答什么、程序允许做什么、何时不应继续。本章的方法是基于已读机制的**工程推导，未在Jev API上实测**。

## 先选一个有边界的判断

| 任务形态 | 优先考虑 | 原因 |
| --- | --- | --- |
| 明确且稳定的规则 | 确定性代码 | 不必为已知判断增加模型调用 |
| 基于当前文本的有限类别、真假或等级判断 | 评估Jev是否适用 | 答案形状可由Noul/Choice/Score表达 |
| 需要自由撰写长文或生成代码 | 文本生成系统 | Jev放弃自由字符串输出 |
| 直接理解图片、音频或视频 | 先用适当感知系统，或另选模型 | 当前Jev仅文本 |
| 高风险、不可逆的现实动作 | 独立授权和安全机制 | 模型置信度不能替代权限或安全证明 |

能力依据：[F-004、F-025～F-027、F-035](../references/article-source.md)。这不是宣称哪类模型普遍更强，而是先检验问题与接口是否匹配。

## 方法一 有界决策组合

**适用于**可观察状态、有限答案、可以拒绝或转人工的判断。**不适用于**要求模型凭空补足事实、无反馈执行或直接控制安全关键设备。跑酷的候选动作、航班的页面动作、客服的路由选择可作概念对照；前三者并没有形成生产级实测证据。

1. 确定一次判断的输入边界，记录状态来源、更新时间和缺失字段。
2. 区分真假、类别、等级，选择对应原语，明确criteria的每一项含义。
3. 将独立因素放在同请求中；依赖新数据的后续判断等真实数据到达再发起。
4. 在代码中组合结果，先检查状态有效性和权限，再决定自动、复核或拒绝。
5. 执行后记录结果与反馈，保留重新处理和回滚的路径。

官方支持问题分解与other/none选项，但上述完整执行治理是本教程的推导。[F-024～F-029、F-038](../references/article-source.md)

| 从材料识别的反模式 | 为什么不充分 | 对应修正 |
| --- | --- | --- |
| 从视频画面推导模型原生看图 | 官方当前只接受文本 | 显式标出感知/文本化组件 |
| 把0%类型错误理解为不会选错 | 原声明限定schema/type | 分别检查类型和业务结果 |
| 用语义丰富的question ID代替instructions | key不进入模型推断 | 在instructions写完整判断 |
| 强迫从不完备的选项中选答案 | 合法候选未必适合当前输入 | 加other/none或由策略拒绝 |

这些是材料对照识别的风险，不声称演示作者实际犯过这些错误。

**迁移练习：图书馆来信分流。** 把读者来信分为借阅、活动、其他，用另一题判断是否有明确日期要求。代码组合部门与时间信号，缺信息则请读者补充；不因分数高就替读者取消借阅。此例仅检验方法结构能否跨出游戏/广告领域，不是已部署系统。

检验标准：每个结果能定位原始材料、问法、模型版本与执行决定；缺字段、无合适类别、过期状态均有预定义出口。

## 方法二 可逆筛选评估

**适用于**广告候选、知识检索片段等可保留原始材料的筛选；**不适用于**删除唯一证据、权限规则或不可恢复记录。原文的上下文筛选只有描述，没有误删与任务质量数据。[F-020～F-021](../references/article-source.md)

1. 给原始记录和片段稳定标识，保留来源与未裁剪副本。
2. 用清晰问题评价相关性或质量，不把业务重要性藏进模糊的总分。
3. 在带标签样本上试验保留规则，将不确定样本单列。
4. 比较筛选前后终端任务是否仍能完成，检查关键证据遗漏。
5. 保存筛选决定和恢复入口，允许用户查看被排除材料。

反模式包括只报减少的token数、把低相关视为永久无用、用某批样本阈值覆盖新领域。它们对应当前材料缺少的质量分母，不是原演示已验证的缺陷。跨领域可用“会议资料候选阅读顺序”做纸面迁移：先排序而非删原件，再检查决策依据是否仍能找回；本教程没有处理私人会议材料。

检验标准：保留率降低时，任务成功率与关键证据召回仍在事先约定范围；无法满足就撤销筛选或转人工。不存在本文可预先给出的通用阈值。

## 如何验证概率与回退

先准备领域内的带标签样本，留出不参与调参的数据；样本应包括常见输入、信息不足、歧义、多语言和不适用情况。比较确定性规则、当前系统和候选模型，在同一输入与执行条件下记录：

| 指标 | 回答的问题 |
| --- | --- |
| 分类准确率、各类别误判 | 哪些类别容易混淆，错误后果是否对称 |
| 概率校准 | 相近预测概率的样本，真实发生比例是否接近 |
| 自动处理覆盖率 | 在既定错误容忍条件下有多少任务不用人工 |
| 人工复核负担 | 拒绝与回退是否把工作全部移给人 |
| 终端任务成功率 | 小判断变好后，整件事是否完成得更可靠 |
| 关键证据保留 | 筛选是否丢掉最终答案必需的依据 |

Choice/Score的confidence来自分布形状，不能直接当准确率；Noul没有同名字段。不同动作后果不同，应分别确定接受标准。英文效果不能直接套给中文，版本别名移动后也应复测。[F-025、F-028、F-031、F-036](../references/article-source.md)

## 时间与成本怎样计量

官方单价为每百万输入token 0.042美元、输出不计费；这只说明模型输入计费口径。[F-006](../references/article-source.md) 端到端任务仍包含材料获取、预处理、所有模型、重试、执行和人工回退。可用“总模型费用 + 外围处理费用 + 人工费用”组织成本台账，但没有真实用量就不代入虚构数据。

延迟应从用户或任务请求开始，量到所需结果完成，分别记录成功与失败任务、常见水平与尾部等待。官方70–500 ms和193.6/444.6倍有厂商评测与地域条件，原文各演示又缺统计分母，不能混合绘成一张性能排行榜。[F-007～F-009、F-012～F-020](../references/article-source.md)

同state的独立问题可以减少重复传输和串行请求；真正依赖前一结果的任务不能假并行。还要同时遵守请求容量、限流与有界重试。模型页64k总预算与原语页32k共享预算存在未解决差异，接近上限前应先确认当前官方规则，而不是以本文为容量保证。[F-029～F-034](../references/article-source.md)

## 上线边界

建议日志记录请求标识、脱敏状态摘要、问法版本、响应model、概率/置信度、策略分支与实际结果。只记录业务必需内容，访问权限与保留时间另行限定；官方“不用于训练”不等于“所有账户零留存”，企业ZDR详情仍须核对适用政策。[F-037](../references/article-source.md)

确认页面变化、API超时、返回错误、状态缺失时都有出口。401/422应修正鉴权或请求；429/529按官方建议退避，同时设最大等待和次数，不做无限重试。[F-030](../references/article-source.md) 高风险动作即使置信度高，也应有独立授权及确认。

## 自测与参考答案

1. **Noul为0.5能表示中等质量吗？** 不能，它表达yes/no不确定；质量程度应定义Score等级。
2. **两题出现在一个请求中，后一题会看到前一题答案吗？** 不会；需要前一结果构造新材料时再发请求。
3. **类型合法能免掉业务验证吗？** 不能；合法类别仍可能选错，权限也不由模型授予。
4. **广告评分便宜能说明营销回报高吗？** 不能；缺素材获取、准确率、真实转化和人工成本。
5. **怎样复用上下文筛选思想？** 保留原文和稳定引用，测试任务质量与关键证据保留，再调整规则。
6. **明天模型别名变了怎么办？** 记录实际版本，以留出数据复测后再迁移，不把旧阈值视为永恒有效。

问题依据与缺口可沿[事实表](../references/article-source.md)和[核验报告](../references/verification.md)继续核对。关于成本降低扩大用途，原文与厂商给出的是预期，不能作为本任务已证明的市场结论。[F-040](../references/article-source.md)
