# 四类自动化应用模式

文章提供四类应用叙述。为了避免把演示误当作产品能力，统一用三层模型阅读：

```text
状态提供者 -> Jev 的窄问题判断 -> 外围执行器/人工回退
```

## 1. 客服与工单分流

- **状态**：用户消息、订单记录、失败日志和服务等级规则。
- **判断**：是否紧急、是否退款、派给哪个队列。[F-008](../references/article-source.md)
- **执行**：升级工单、触发退款流程或转人工。

文章给出约100毫秒的说法，但没有请求数、区域、重试和人工回退数据，不能直接写成 SLA。[F-009](../references/article-source.md)

## 2. 实时游戏和 Agent 操作

- **状态**：游戏引擎输出的结构化状态，而不是自动推断的视觉画面。
- **判断**：左转/右闪、开火/走位或移动/跳跃。
- **执行**：游戏控制器把选择转换成动作，下一帧再提供新状态。

文章提到《毁灭战士》每秒约10次、单小时数美元以及超级马里奥控制，但没有独立运行日志，不能外推到所有游戏或机器人。[F-010～F-012](../references/article-source.md)

## 3. 浏览器 RPA

- **状态**：页面可交互元素、当前任务、已填字段和错误提示。
- **判断**：选择哪个框、是否点击确认、是否需要停止。
- **执行**：浏览器自动化框架实际点击、输入和等待。

Jev 的结构化答案不能替代浏览器权限、反 CSRF 防护、页面变化检测和人工确认。[F-013](../references/article-source.md)

## 4. 安全熔断与流水线调度

- **状态**：告警、服务健康、变更窗口和响应剧本。
- **判断**：严重程度、是否触发熔断、是否通知值班人员。
- **执行**：调用已有剧本、冻结发布或升级人工。

文章称官方流水线准确率接近顶尖模型，但没有提供可复现实验表；因此该场景只能作为架构方向，不能作为安全关键系统授权依据。[F-014、F-023](../references/article-source.md)

## 横向比较

| 场景 | Jev 负责 | Jev 不负责 |
| --- | --- | --- |
| 工单 | 窄问题分类和评分 | 退款授权、队列写入 |
| 游戏 | 下一动作选择 | 感知、物理模拟、动作执行 |
| 浏览器 | 页面动作判断 | 点击权限、等待和回退 |
| 安全调度 | 风险标签和剧本选择 | 安全策略最终批准 |

**本节洞察（I-2）**：迁移 Jev 时最容易遗漏的不是 Prompt，而是状态编码和外围执行契约。只有三层边界都可观测，速度优势才有机会转化为端到端收益。
