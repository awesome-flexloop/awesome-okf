# 直播迭代：把一次开播拆成三轮可验收动作

原文里这段是全文最像「工程」的部分：Agent 自行安装并登录直播伴侣，先彩排、准备文字与画面素材，测过之后再来问要不要正式开播。[F-046](../references/facts.md) 首播暴露四个问题，第二轮明显改善。[F-048、F-049](../references/facts.md)

本练习把那两轮拆成三轮可独立验收的动作。**不做**任何平台规则的规避设计，也不涉及刷量；只处理「怎么让一次对外直播可控」。

## 第 0 轮：彩排（不可见）

| 动作 | 产出 | 验收 |
|---|---|---|
| 装并登录直播软件 | 可推流的会话 | 预览窗口有画面 |
| 写口播脚本 | 一段能念完的文字 | 念一遍不需要临场补词 |
| 准备画面素材 | 头像、字幕样式、若干动画 | 每个素材都知道「什么时候出现」 |
| 空跑 5 分钟 | 一次无观众的完整流程 | 无中断、无黑屏、无静音 |

彩排的判定标准只有一条：**此时失败不花任何代价**。如果彩排需要真实开播才能完成，那它就不是彩排。

## 第 1 轮：首次开播

原文报告的四类问题，按可归因性排序：[F-048](../references/facts.md)

| 问题 | 更像哪一层 | 归因依据 |
|---|---|---|
| 画面单调，只有头像加字幕 | 素材与编排 | 与模型无关，换素材即可验证 |
| 甩尾巴这类动作词被念出来 | 文案与 TTS 文本未分离 | 舞台指令混进了口播文本 |
| 对弹幕反应慢 | 链路延迟 | 抓取间隔 + 生成耗时 + 推流叠加 |
| 画面下方有黑边 | 分辨率与画布比例 | 采集与推流分辨率不一致 |

四个问题里只有第二个是「Agent 写得不好」，其余三个都是配置与工程问题。这个分布本身值得记住：**对外表现的粗糙，多数不来自模型能力**。

## 第 2 轮：逐项修正

| 改法 | 具体动作 | 验收信号 | 别踩的坑 |
|---|---|---|---|
| 丰富画面 | 建立「台词 → 画面」映射，规定讲到哪句切什么 | 连续 3 分钟画面有变化且与内容相关 | 一次性换掉整套素材，无法归因 |
| 分离动作词 | 动作写成括号指令，TTS 只读正文 | 回放中不再出现动作描述被念出 | 只删动作词，画面又变回静止头像 |
| 提升响应 | 限定回复长度、预设高频回复、缩短抓取间隔 | 常见问题在可接受延迟内出现 | 为了快而放开长度限制，反而更慢 |
| 修画布 | 采集与推流统一分辨率，锁定比例 | 全屏无黑边，切换场景不跳 | 只在某一场景修，切换后又出现 |

原文对第二轮的描述是「画面更丰富、会按台词使用合适的动画」。[F-049](../references/facts.md) 这是结果描述，不是方法描述——它没有说改了几处。所以复现时要自己保证**一次只改一类**。

## 记分卡

每轮填一次，三轮之后能看出哪一类问题在收敛：

```text
轮次：第 __ 轮    时长：__ 分钟    观众峰值：__（可选）
画面变化次数：__     黑边：有/无     静音或卡顿：__ 次
动作词被念出：__ 次   弹幕平均响应：__ 秒
事故：__（内容事故 / 被提示违规 / 中途断流 / 无）
本轮只改了一处？是/否   改的是：__
```

最后两行是这张卡的关键。如果「否」，本轮结果不可用于归因。

## 边界

- 原文提到首播收到两个礼物。[F-051](../references/facts.md) 这是单次个例，不构成本包对变现能力的任何判断。
- 直播中诱导提问被婉拒（问主人是谁、支付密码）。[F-050](../references/facts.md) 这是单点测试，不等于抗注入达标；更严的测试设计见[安全边界](../concepts/safety-boundaries.md)。
- 平台对自动化直播、无人值守直播的规则随平台与时期变化，本包未取到任何官方条款，不给操作建议。
- 原文用 Claude Code 或 Codex 优化视频效果，[F-044](../references/facts.md) 属手段建议，本练习不展开。

流程为什么值得这样拆，见[社媒运营闭环](../concepts/social-ops-loop.md)里的「彩排—请示—正式」。
