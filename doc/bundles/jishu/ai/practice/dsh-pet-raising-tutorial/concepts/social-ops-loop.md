# 社媒运营闭环：消费型与生产型

鱼养熟之后，原文把它放出笼子做了两类事：在 B 站看别人的内容，在抖音生产自己的内容。[F-040、F-043](../references/facts.md) 这两件事的风险与验收方式完全不同，混在一起谈就会失焦。

## 两类活动

| | 消费型（B 站） | 生产型（抖音） |
|---|---|---|
| 动作 | 刷视频、点赞、发弹幕、留评论、把有趣的私信给主人[F-040](../references/facts.md) | 自发视频、回复评论、开直播[F-043、F-046](../references/facts.md) |
| 主要能力 | 浏览与判别：判断什么值得看、什么值得转述 | 生成与执行：写脚本、组装素材、按流程操作软件 |
| 失败代价 | 说错话、暴露偏好、被套信息 | 内容事故、账号受限、直播失控 |
| 验收方式 | 抽查它转述的内容是否属实、有没有夹带隐私 | 复盘回放：画面、口播、互动是否达标 |
| 原文的证据 | 作者自述日常操作，未给量[F-040](../references/facts.md) | 作者自述首播一个多小时、收到两个礼物[F-051](../references/facts.md) |

一个容易被忽略的差别：消费型的价值在**筛选**（它替你看完大量内容），生产型的价值在**执行**（它替你把事做完）。前者出错只是信息噪音，后者出错是公开可见的事故。所以生产型必须带人工闸门。

## 可迁移的模式：彩排—请示—正式

原文写直播时有一个细节值得单独拎出来：它先自行安装并登录直播伴侣，**先彩排**，准备好文字与画面素材，测试之后再跟作者确认要不要正式开播。[F-046](../references/facts.md)

这是一个通用的外部动作前置模式，适用于任何"一旦发出就收不回"的操作：

| 阶段 | 做什么 | 谁能看到 |
|---|---|---|
| 彩排 | 在不可见环境跑完整流程，产出素材与脚本 | 只有主人 |
| 请示 | 汇总彩排结果，明确问「要不要正式执行」 | 主人 |
| 正式 | 执行真实动作 | 所有人 |

它的价值不在技术，而在**把不可逆动作降级为可预览动作**。同样的形状可以套到群发消息、发布视频、提交表单、发起支付上。反过来说，凡是跳过彩排直接正式执行的配置，都是把不可逆风险交给了模型的判断力。

## 迭代闭环

原文的改进方式全程是自然语言：看到不对，直接说；说完再看一遍。[F-049](../references/facts.md) 两轮之间发生了什么，可以从问题清单反推：

| 首播问题 | 属于哪一层 | 可验收的改法 |
|---|---|---|
| 画面单调，只有头像加字幕[F-048](../references/facts.md) | 素材与画面编排 | 增加画面元素与分镜，明确「讲到哪句时切什么画面」 |
| 甩尾巴这类动作词被念出来[F-048](../references/facts.md) | 文案与口播分离 | 动作描述写成舞台指令，不进 TTS 文本 |
| 对弹幕反应慢[F-048](../references/facts.md) | 链路延迟 | 缩短抓取间隔、限定回复长度、预设高频回复 |
| 画面下方有黑边[F-048](../references/facts.md) | 分辨率与画布比例 | 统一采集与推流分辨率，锁定画布比例 |
| 第二次画面更丰富、按台词使用动画[F-049](../references/facts.md) | 前三项的合并结果 | 逐项回归，确认不是「整体换了套素材」的错觉 |

改完要能回答一个问题：**这次变好，是因为改了哪一处？** 如果一次改十处，下次坏了也不知道回滚什么。

## 反模式

| 反模式 | 后果 |
|---|---|
| 把「能跑通」当成「能对外」 | 彩排没做就正式，事故直接公开 |
| 只测成功路径 | 弹幕骂人、礼物诱导、连麦请求这类场景没预案 |
| 用「它自己会处理」代替规则 | 没有黑名单与止损条件，出事只能手工关 |
| 每轮都重写全部配置 | 无法归因，也无法回滚 |
| 追求「无人值守」 | 越接近无人值守，越需要前置闸门与熔断，而不是相反 |

## 与安全章的关系

本章只讲**怎么组织活动**，不讲**平台允不允许**。原文里的自动点赞、批量弹幕、自动发视频、自动开播，在多数平台属于自动化互动范畴，规则随平台与时期变化；本包未取到任何官方条款，因此不给频率、话术或规避建议。[F-041](../references/facts.md) 放养前的判定标准与测试方法见[安全边界](safety-boundaries.md)。
