# 单人窄赛道现金流模式

> 本篇为 E（萃取）阶段产出：从 Verbi 个案抽象出的模式。配套质量门 G3 要求：触发场景 + 核心步骤 + 反模式 + 迁移验证。

## 模式一句话

在巨头用「大而全 + 留存游戏」覆盖的市场里，选择一个**被牺牲掉的具体用户任务**（如「敢开口说外语」），用最小组合的订阅基础设施做成由一人经营的现金流生意。

## 触发场景（什么时候适用）

- 存在成熟大市场，但头部产品为规模而做标准化取舍，某些「非高频但高价值」的任务体验差；
- 创始人具备产品全栈能力 + 至少一种自有触达能力（内容、社群或受众）；
- 目标是现金流而非融资扩张，可以接受窄天花板。

## 核心步骤

| 步骤 | Verbi 对应事实 |
|------|---------------|
| 1. 识别巨头取舍中的「被牺牲任务」 | Duolingo 式刷词留存在「口语开口」上体验弱（F-018） |
| 2. 反向定义产品：只做该任务的闭环 | AI 真实对话 + 口语反馈 + 进度数据，不做闪卡（F-002/F-004） |
| 3. 用托管基础设施替代团队 | React Native + Node.js + RevenueCat，订阅/收据/看板外包给基础设施（F-008） |
| 4. 设计「免费试用 → 年付订阅」漏斗 | Active Trials 6,167 → 年订阅转化，单日 $16,889（F-022/F-023/F-024） |
| 5. 创始人亲自掌握分发并长期经营 | ASO 自理 + TikTok/YouTube 内容 + UGC 创作者（F-019/F-024/F-025） |
| 6. 经营指标聚焦转化与净利率 | MRR $16,752、自述净利率 55%（F-011/F-014） |

## 反模式（本案例反向暴露的错误做法）

| 反模式 | 为什么错 |
|--------|---------|
| 正面对标巨头做「更全的语言应用」 | 单人在内容广度、留存游戏化、投放预算上均无优势 |
| 把成功归因为「上架即自然量」 | 与事实不符——案例依赖创始人内容能力与 UGC（勘误 E-1）；忽视分发前提会得到零下载应用 |
| 追求一次性买断或只做周订阅 | 年付订阅提供现金流前置与营收弹性，是该模式营收结构的关键 |
| 自建订阅/支付后端 | 与「单人」不相容；RevenueCat 类服务已将该成本趋近于零 |
| 只讲技术差异化 | AI 对话能力非独家，真正壁垒是产品取舍 + 创始人分发禀赋 |
| 把单源自述数字（净利率/环比）当审计事实 | 应保持口径标注与核验意识 |

## 迁移验证

- **可迁移方向**：同类「巨头市场里的具体任务」型应用——垂直写作任务、垂直考试的口语/面试演练、特定职业的话术演练等；也适用于非应用形态的微型订阅产品。
- **迁移的必要条件**：创始人侧必须补齐「分发」一环（内容或受众），这是模式中唯一无法靠基础设施买断的要素。
- **不适用场景**：需要网络效应/供给侧规模的市场、强合规高客单 B2B、以及创始人无任何触达能力却只能付费投放的情形。

## 边界声明

- 该模式萃取自单一案例，账本数字为截图时点口径，其中净利率、环比为单源自述（F-012/F-014）；
- 模式描述的是「可解释的成功结构」，不构成因果保证——案例同时受益于 AI 应用需求窗口、应用商店流量时点等不可控因素；
- 本知识包未做产品实测，迁移前应自行小成本验证试用转化。
