# GPT-6 Astra 五大行为模式

> 本篇为**机制原理层（Why）**：解释 Astra 相比 GPT-5.6 Sol 等早期模型的五类行为基线变化，以及为什么官方要专门给出 Prompt 配方。可直接使用的 Prompt 原文见 [02 官方 Prompt 配方](02-prompt-recipes.md)。

官方在"Prompting best practices"中明确（F-023）：GPT-6 Astra 比 GPT-5.6 Sol 等早期模型更智能、能力更强，**同时存在可通过 Prompt 针对用例优化的行为模式**。这意味着换模型后旧 Prompt 可能出现"模型反而不顺手"的现象——不是能力退化，而是行为基线变了。

## 行为模式总览

| # | 模式 | 默认倾向 | 可能的意外 | 调优方向 |
|---|------|---------|-----------|---------|
| 1 | 主动性与贯彻执行力 | 额外输入会实质改变结果时倾向提问确认 | 你期望它合理假设直接做，它却停下来问 | 用授权 Prompt 调整自主程度（F-024/F-028） |
| 2 | 指令遵循 | 长指令遵循更强，对 skills/AGENTS.md 等上下文指令更敏感 | skill 里不清晰/冲突的指令导致停顿、提前中断 | 明确用户指令与 skill 的优先级、要求溯源（F-029） |
| 3 | 个性与写作风格 | 详细、格式化回复，跨会话复用某些短语 | 列表/表格/Markdown 堆砌，AI 味重 | 在系统 Prompt 中显式指定文体（F-033） |
| 4 | 子代理委托 | 具备拆分并行委托能力 | 实际委托频率低于工作流预期 | 显式指定何时、多大程度委托（F-038） |
| 5 | 测试与验证 | 完成前倾向详尽测试 | 小任务测试范围过度 | 让测试量与变更规模匹配（F-040） |

## 1. 主动性与贯彻执行力（Initiative and follow-through）

Astra 在长任务中通常比 GPT-5.6 Sol 及更早模型更能保持前后一致；区别在于遇到歧义时的默认动作变了（F-024）：

- **早期模型**：倾向自行作出假设并继续
- **Astra**：更可能主动提问、要求澄清——因为它被设计为"更有效的协作者"，当额外输入可能**实质改变结果**时会停下来

官方把这种倾向称为"行动闸门前置"。调优手段不是简单一句"主动一点"，而是三段式：① 指示模型推断真实意图并偏向行动；② 声明"can you / I want / help me"类措辞即隐含授权；③ 要求先做出具体可审查结果再请求批准。三段官方 Prompt 原文与解读见 [02 官方 Prompt 配方](02-prompt-recipes.md) 第 1 节。

另有一个默认行为细节（F-028）：模型喜欢在工作过程中提出**非阻塞式问题**。可以按应用需要的自主程度，用上述 Prompt 调节这些问题的密度。

## 2. 指令遵循（Instruction following）与 skills 敏感性

Astra 更能遵循长指令，但对上下文中的信息**更敏感**（F-029）。直接后果：skill 文件中不清晰或相互冲突的指引，可能导致模型停顿并过早阻塞工作。

官方原文给出的行动建议有两条（F-029）：

1. **显式声明优先级**：明确用户指令与 skill 指令谁优先；
2. **审计指令资产**：官方"**strongly recommend** auditing skills and other files accessible to your model for instructions that could influence its behavior"，点名的文件类型就是 `AGENTS.md`。

### 标题命题辨析："Skill 又要被干掉了？"（F-042，作者观点）

博文标题是引流式反问，**该命题不成立**，且与官方立场方向相反：

| 标题暗示 | 官方文档实际表述 |
|---------|-----------------|
| Skills 的作用被新模型取代/淘汰 | 模型对 skills 和 AGENTS.md 中的指令"可能更敏感"（more sensitive） |
| —— | 官方强烈建议**审计**这些文件中可能影响模型行为的指令 |
| —— | 模型页工具特性表中 Skills 仍为明确支持项 |

博文正文实际内容（用户指令优先于 skill、要求模型点名是哪个 SKILL.md 的哪条指令让它停下）同样是在**强化** skill 治理而非唱衰。合理的推论方向是：模型越敏感，低质量/互相冲突的指令资产代价越高——skills 进入"需要治理"而非"被干掉"的阶段。该辨析仅针对标题修辞，不影响正文技术内容的可信度（正文经核验忠实于官方指南）。

## 3. 个性与写作风格（Personality and writing style）

默认输出倾向"可扫读"形态（F-033）：小标题、项目符号、编号列表、表格、粗体、引用块、Markdown 代码块，并可能在不同会话中重复某些短语。

- **适用**：技术答复、仪表盘说明、清单类内容
- **不适用**：公众号文章、评论、邮件、故事——过多列表和表格让内容臃肿死板（博文语）

关键点是**不能假设模型会自行选择散文风格**：需要在系统 Prompt 中明确指定风格与结构。官方给了三段递进配方：散文风格、技术沟通平衡、去 AI Slop 词表（详见 [02 官方 Prompt 配方](02-prompt-recipes.md) 第 3 节）。博文作者对"官方去味儿配方效果"的期待属作者观点（F-037），未经实测验证。

## 4. 子代理委托（Subagent delegation）

Astra 受过把任务拆分并委托给并行 subagent 的训练，但**委托频率可能低于你的工作流预期**（F-038）。多 Agent 系统的搭建者需要用 Prompt 明确两件事：

1. **何时委托**：只要并行化能节省时间或提升质量就应委托（根代理与 subagent 都适用该原则）；
2. **委托程度**：配合 harness 的多代理实现调节。

附带一个工程细节：Agent 之间的消息可能含语法/空格错误，官方专门提供一段"代理间消息可读性"Prompt，要求单词/数字间保留恰当空格（F-039）——因为这些消息和最终答复都可能被人阅读。

## 5. 测试与验证（Testing and verification）

编程任务中，Astra 倾向在认定任务完成前做**详尽测试**；小任务上可能测试范围超出实际所需（F-040）。官方 Prompt 的平衡原则：

- 可逆、低影响的变更，不编写照搬实现逻辑的测试；
- 若用测试验证，测试必须有实际意义且为验证实现所必需；
- 运行与变更规模匹配的测试、完成规定检查；通过后仅在出现新改动、测试失败或未决问题时才扩大或重跑测试，否则继续推进。

## 机制层小结：aligned 模型的三个基线位移

综合五维模式（本 bundle 基于 F-023～F-040 的归纳）：

1. **从"假设后行动"到"提问后行动"**——歧义默认走澄清，自主性需用 Prompt 显式授予并分层（可逆放行、不可逆末位确认）；
2. **从"上下文只是参考"到"上下文都是指令"**——skills/AGENTS.md 等文件从软约束变为可触发真实阻塞的硬输入，指令资产需要审计与冲突管理；
3. **从"一次回答"到"可编排协作者"**——格式倾向、委托倾向、测试倾向都暴露为可调参数，应用方要为自己的场景定义行为契约，而不能依赖模型的默认品味。

这也解释了博文作者的核心感受（F-043，作者观点）：相比笼统地说"主动一点""去掉 AI 味儿"，官方配方的价值在于把每个行为倾向拆成了可直接粘贴、边界清楚的具体指令。
