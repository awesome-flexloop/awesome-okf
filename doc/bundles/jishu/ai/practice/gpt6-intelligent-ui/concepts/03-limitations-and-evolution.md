# 局限与演进：能力边界、交互范式转变与"软件适应人"

> 对应 F 编号：F-024（局限）、F-025（不支持 Pro effort）、F-026（推演）、F-027（多模态融合）、F-028（iPhone 类比）、F-029（Agent 演示）、F-030（"软件适应人"）。

## 两大局限

### 1. 与高质量 UX 的差距（F-024）

- 动态图表、交互组件**更像一次性体验**。
- 缺少**稳定可靠的代码沙盒**与**独立资产入口**。
- 结果：轻量级任务流畅，但对需要高精准度与专业性的场景"显得有些小儿科"。

### 2. 暂不支持 Pro effort / Astra（F-025, F-026）

- Intelligent UI 目前**不支持 Pro effort**；Pro effort 用的是 **GPT-6 Astra**。
- 推论：新式交互界面与最强推理模式**不能同时出现**；真正复杂、需长时间思考的任务可能回到传统文字形式。
- 何时结合仍是 OpenAI 待解问题。

## 交互范式的转变

### 多模态融合（F-027）

底层逻辑是**多模态融合改变了人机交互方式**：

- 自然语言：适合表达复杂目标，但不一定适合精细操作。
- 图形界面：适合观察状态、比较选项、调整参数。
- 两种方式互相补充。

### iPhone 类比（F-028）

作者类比 2007 年第一代 iPhone：点按、滑动、双指缩放重新定义了手机操作，从"依赖物理按键的间接操作"走向"直接触碰屏幕"。Intelligent UI 把交互从"只回答问题"变成"用户参与问题解决"，答案不再是对话终点，而成为可触摸、修改、继续使用的对象。

### 走出对话场景的 Agent 化（F-029）

- 豆包手机助手技术预览版：对话连接系统操作层。
- 荣耀 MagicOS 9.0 YOYO：用户说"帮我点一杯热拿铁"，YOYO 调用外卖应用、找到常去咖啡店、完成点单并在结算前向用户确认。
- 关键价值：用户从"阅读答案的人"变成"参与任务的人"。

### "软件适应人"（F-030）

OpenAI："过去的几十年里，人们一直在学习用为某个具体任务而设计好的固定的程序，未来软件要能够去适应人的各种各样的工作。"

## 结论与边界

- 作者以安妮·卡森《红的自传》引文收束（F-031）："How does distance look? ... It depends on light"——「距离看起来是什么样？它取决于光」「现在，Intelligent UI 把这束光放进了对话框」。
- **口径**：局限（一次性体验、缺沙盒）为作者观点；豆包/YOYO 为厂商演示转述；"软件适应人"为厂商自述（详见 [references/verification.md](../references/verification.md)）。
- 是否"确实是未来软件的开端"是开放性推测，本束不作断言。
