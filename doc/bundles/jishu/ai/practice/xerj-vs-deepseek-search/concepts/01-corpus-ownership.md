# 语料归属

## 第一决策轴

检索选型的常见问法是「哪个检索质量更好、哪个更便宜、哪个更快」。这些问题**都问早了**——它们假定了「要检索的东西在同一个地方」，而这个假定通常不成立。

正确的问题是：**要检索的东西归谁？**

- 归**你**（你的代码库、你的日志、你的邮件、你的会议记录、你的历史决策）→ 只能自建；
- 归**别人且在公网**（上游项目的最新实现、今天的新闻、某个 API 的当前文档）→ 托管搜索才有意义。

这不是偏好问题，是**结构问题**（F-034）：

| 问题 | XERJ | DeepSeek |
|---|---|---|
| 「我们内部昨晚那次 CI 失败日志里写了什么」 | ✅ 能（F-001：日志是支持的格式之一） | ❌ **结构上做不到**——它不索引你的私有日志（F-032） |
| 「我们三个月前那次架构决策的理由是什么」 | ✅ 能——命名空间记忆 + 第二大脑（F-003） | ❌ 结构上做不到（无状态） |
| 「今天 Rust 发布了什么新特性」 | ❌ **结构上做不到**——它只索引本地文件（F-001） | ✅ 能（F-016：公网实时） |
| 「这个库的当前版本 API 长什么样」 | ⚠️ 只有你自己有一份快照时才可能 | ✅ 能，且是实时 |

## 为什么这个问题决定了其余一切

一旦语料归属确定，其余八个对照轴的权重就确定了：

**归你 → 隐私与可控性权重最高。** 数据不出机器是硬需求（F-011）。DeepSeek 侧的检索词与目标 URL **必然出网**（F-041）——对于「检索词里包含了未发布的业务名」这种场景，这本身就是否决项。

**归别人 → 时效与覆盖面权重最高。** XERJ 只能给出你本地快照的答案；要公网最新内容只有托管搜索（F-001、F-016）。

**两者都要 → 串联。** 见 [04 成本曲线与选型](04-cost-model-and-selection.md) 的决策树与 F-040。

## 归属判定的三个问题

落地时按顺序问：

### 问题 1：这个东西在公网上有权威副本吗？

| 情况 | 结论 |
|---|---|
| 有（上游项目源码、公开文档、发布公告） | 托管搜索可以起步；**但如果它同时是你的依赖，自建一份固定的 commit 快照通常更好**——版本漂移会让 Agent 的答案不可复现 |
| 没有（内部日志、私有代码、内部 Wiki） | 只能自建 |
| 部分（自家产品的用户文档在公网，但内部实现不在） | 分开处理 |

> 参考编码这条线上，XERJ 上游自己的做法是**两边都要**：Hub 语料用公网项目的固定 commit 快照（`tools/xerj-code/hub/*.json`），本地私有代码用 `autoindex` 索引自己的目录。见 [XERJ 参考编码与语料库](../../../frameworks/xerj/concepts/08-reference-coding.md)。

### 问题 2：答案需要「可复现」还是「要最新」？

这是一个硬取舍，不能两全：

| 需要 | 选择 | 理由 |
|---|---|---|
| **可复现** | 自建 + 固定快照 | 托管搜索的结果随时间与排序变化；同一问题今天与下周答案不同，Agent 的行为不可回归测试 |
| **要最新** | 托管搜索 | 自建快照在信息更新后就是错的 |

> 参考编码的实测支持这个取舍：在**模型没记住**的代码上检索赢 2.7 倍输出 token（比 grep 少），比纯记忆少 26 倍；在**模型已记住**的公共库代码上，检索是净开销。详见 [XERJ 参考编码与语料库](../../../frameworks/xerj/concepts/08-reference-coding.md)。

### 问题 3：检索词本身敏感吗？

DeepSeek 侧会把你的**检索词**发往公网（连同目标 URL）（F-041）。如果检索词里会出现未公开的业务名、客户名、密钥片段、内部人名——那就不是「可以后补的细节」，而是**否决项**。

XERJ 侧的例外要说清楚：默认不出机器，但有三个特性会把文本发出去——`rerank`（搜索期把命中正文发给第三方评判服务）、代理嵌入（`--embed-mode proxy`）、WAL tap（F-011）。三者**默认关闭**，且 `rerank` 明确「不在用户同意前不要用在必须留在本地的数据上」。

## 一个反直觉的推论

**「自建 vs 托管」不是二选一，而是同一检索动作的两个阶段。**

真实 Agent 的典型回路是：

```
① 不知道该看什么       → 问公网：Search 找候选 URL
② 需要具体内容         → Fetch 抓正文
③ 这个内容以后还要用   → 写入本地索引
④ 下次问同类问题       → 直接查本地，不重复付费
```

第 ③ 步是分界线：**一旦某份外部内容被判定为「会重复用到」，把它固化到本地索引就开始省钱**（F-040、F-036）。

这也解释了为什么 DeepSeek 的计费结构会改变架构决策：¥0.005/次在低频场景可忽略，在 50 轮 × 4 次/轮的深研型任务里就是 ¥1.00，**与同仓 1017 max 档单任务约 ¥1.3 的模型费同量级**（F-037）。
