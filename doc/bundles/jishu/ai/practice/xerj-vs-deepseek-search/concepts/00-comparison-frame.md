# 对比框架与结论

## 先给结论

**XERJ 与 DeepSeek Search/Fetch 不是竞品，而是语料两端。**

它们看起来都在回答「让智能体拿到外部知识」，但**检索面几乎不重叠**：

| | XERJ | DeepSeek Search / Fetch |
|---|---|---|
| 语料 | **你的**：本地文件、代码库、日志、邮件、PDF、长期记忆（F-001、F-003） | **公网的**：实时网页（F-016） |
| 形态 | 自建、本地、一个静态二进制（F-014） | 托管 API，按次计费（F-028） |
| 时间性 | 你的数据当时的快照 | 实时 |
| 记忆 | 有，且是一等公民（F-003） | 无状态（F-032） |

所以「选 XERJ 还是选 DeepSeek 搜索」这个问题本身**提错了**。正确的问题是：**「要检索的东西归谁」**（见 [01 语料归属](01-corpus-ownership.md)）。

## 九个对照轴

### 1. 语料归属（决定性）

XERJ 索引本地任意文件夹（F-001）；DeepSeek 索引公网实时网页（F-016）。**这一条决定了其余八条。**

### 2. 检索能力

| 维度 | XERJ | DeepSeek |
|---|---|---|
| 全文 | BM25 + 4 个以上内置分析器（源码实为 11 个） | 托管搜索，排序分 `rerank_score` 0～3（F-021） |
| 向量 | kNN（HNSW 未过滤 + 精确重打分）+ `hybrid` 融合 | 未在官方文档中出现向量检索 |
| 结构化 | 62 种聚合，桶路径精确（F-002） | 未在官方文档中出现聚合 |
| 过滤语法 | 50 种查询类型 | `site:` `-site:` `lang:` `after:` 等 8 个操作符（F-020） |
| 权威度信号 | 无内置站点权威度概念 | `authority` 0～4，≥3 为极权威（F-021） |

> 注意 DeepSeek 侧的 `rerank_score` 与 `authority` 是**两个独立的排序/质量信号**，而 XERJ 侧的对应物是**用户自建的数据**——没有第三方权威度可言。

### 3. 上下文成本控制

**同一思想，两种实现**（F-035）：

| | XERJ | DeepSeek |
|---|---|---|
| 机制 | `_passage` 服务端切片 + `_source` 投影（F-004） | `snippet` / `summary` / `content` 三档分层 + `need_content` 默认 false（F-024） |
| 典型量级 | 源码语料 5 命中：416,630 → **12,122 字节**（34×） | `snippet` 100～200 字符 / `summary` 600～800 字符 / `content` 全文（F-021） |
| 默认行为 | 默认返回**完整文档**（容易踩坑） | 默认**不返回**正文（默认更安全） |

> **反常识**：DeepSeek 的默认值更保守（不返回全文），XERJ 的默认值更激进（返回全文）。同一个「先摘要后全文」的思想，落在两个相反的默认值上——**用 XERJ 检索源码时不加 `_passage`，上下文会立刻爆掉**。

### 4. 记忆与连续性

XERJ 有完整的跨会话设施：命名空间记忆（物理隔离的索引）+ 关系层第二大脑（9 个确定性检测器、最多两跳）（F-003）。DeepSeek 侧**完全无状态**（F-032）。

这一条决定了「智能体记住上次学到的什么」这类问题**只有一边能答**。

### 5. 失败语义

XERJ 把边界编码进响应体：追加式 `_xerj.hints` 提示、结构化 `not_supported_yet`、带替代方案的 400、语义明确的 429（F-006～F-009）。DeepSeek 侧是 OpenAI 兼容错误格式 + 10 个状态码（F-025），其中 **404 把五种成因合并成一个码**（F-026、F-038）。

### 6. 成本形态

XERJ 是**固定成本**（一次索引 + 一台机器，边际近零，F-010）；DeepSeek 是**线性成本**（¥0.005/次成功请求，F-028）。DeepSeek 的结构**惩罚重复查询**（F-036）。

### 7. 隐私

XERJ 默认数据不出机器，三个会外发文本的特性（`rerank`、代理嵌入、WAL tap）默认关闭（F-011）。DeepSeek 侧的检索词与目标 URL **必然出网**（F-041）。

### 8. 规模上限

XERJ 受本机磁盘与内存约束，服务端堆随已索引文档数增长（F-013、F-042）；DeepSeek 受其自有索引覆盖与账号级 QPS 约束（F-016、F-029、F-042）。

### 9. 可验证性

XERJ 的质量自宣附测量条件、失败案例与一键复现脚本（F-012、F-015）；DeepSeek 只给索引规模与机制描述，**未提供召回率、时延或与主流搜索引擎的对比数据**（F-031、F-039）。

## 一张总表

| 对照轴 | XERJ | DeepSeek Search / Fetch | 事实 |
|---|---|---|---|
| 语料 | 本地文件 + 长期记忆 | 公网实时网页 | F-001、F-016 |
| 部署 | 一个静态二进制 61.6 MB，无 JVM | 托管 API，`api.deepseek.com` | F-014、F-018 |
| 全文检索 | BM25 + 11 个内置分析器 | 托管搜索 | F-002、F-016 |
| 向量检索 | kNN + hybrid | 官方文档未提供 | F-002 |
| 聚合 | 62 种，桶路径精确 | 官方文档未提供 | F-002 |
| 记忆 | 命名空间 + 第二大脑 | 无状态 | F-003、F-032 |
| 上下文控制 | `_passage` + 投影（34×） | 三档摘要分层 | F-004、F-024 |
| 失败语义 | 边界编码进响应体 | 状态码，404 合并五因 | F-006～F-009、F-026 |
| 计费 | 固定成本 | ¥0.005/次成功请求 | F-010、F-028 |
| 限速 | 无（本地进程） | Search 100 QPS / Fetch 25 QPS（账号级） | F-029 |
| 隐私 | 默认不出机器 | 检索词与 URL 出网 | F-011、F-041 |
| 质量可验证性 | 附测量与复现脚本 | 未提供对比数据 | F-012、F-031 |
| 计费切换风险 | 无 | 2026-11-01 起对已有 Harness/Claude Code/Codex 用户生效 | F-030 |

## 三条使用建议

**① 按语料归属选，而不是按检索能力选。** 见 [01 语料归属](01-corpus-ownership.md)。

**② 高频重复的查询走自建，低频时效性的查询走托管。** DeepSeek 的按次计费会惩罚重复（F-036）；XERJ 的边际成本近乎零（F-010）。

**③ 两者可以串联。** Search 定位 → Fetch 取正文 → 写入 XERJ → 之后本地查（F-040）。
