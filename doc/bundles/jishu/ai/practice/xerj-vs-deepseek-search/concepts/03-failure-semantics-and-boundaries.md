# 失败语义与可诊断性

评估一个检索接口时，**成功路径的信息量远低于失败路径**。Agent 会在失败时做出动作，而动作的正确性取决于接口能否告诉它「为什么失败、接下来该干什么」。

## 两套错误契约

### XERJ：边界编码进响应体

| 场景 | 行为 | 对 Agent 的含义 |
|---|---|---|
| 查了未映射字段（`ax-*` 索引） | **400**，报出字段名与可检索字段（F-006） | 改字段名重试 |
| `_source` 未投影且没要 `_passage` | HTTP 200，但 `_xerj.hints` 附一条**开箱即用的修正请求**（F-006） | 直接用提示里的请求重试 |
| 用了不支持的 ES 调用 | 结构化 `not_supported_yet` 错误，**不是 500**（F-007） | 走替代路径，不是重试 |
| scroll 超过 10,000 快照窗口 | **400**，错误信息说明「不会返回被静默截断的结果集」并给出 `search_after` 替代方案（F-008） | 改用 `search_after`，不要重试 |
| 节点内存断路器 | **429**，语义是「卸荷」而非失败：降并发、只重发被拒条目（F-009） | 退避重发被拒项，继续 |
| 分词/抽取失败 | 降级为 junk 记录并计数，**从不死 Fatal** | 不必处理 |
| 集群集群未加载语料 | 退出码 3 = 「不是没匹配，是语料没加载在这台服务器上」 | 重新索引或改指节点 |

> **设计意图**：这些不是「错误处理」，是**契约**。每一个错误码或提示都对应一种明确的 Agent 动作。

### DeepSeek：OpenAI 兼容状态码

错误格式统一为 OpenAI 兼容结构，`param` 字段**恒为 `null`**（F-025）：

```json
{ "error": { "message": "'count' must be between 1 and 50",
             "type": "invalid_request_error", "param": null,
             "code": "invalid_request_error" } }
```

| 码 | 含义 | 官方建议动作 |
|---|---|---|
| 400 | 请求头/体不合法 | 不修改请求不重试 |
| 401 | API Key 缺失或无效 | 不重试 |
| 402 | 账号余额不足 | **先充值再重试** |
| 403 | Fetch 被安全策略拒绝 | 不重试 |
| 404 | 未获取到可用网页内容 | 不重试 |
| 408 | 读请求体超时 | 等待后重试 |
| 413 | 请求体过大 | 不重试 |
| 429 | 超 QPS 限制 | 等待后重试 |
| 500 | 服务端内部错误 | 等待后重试 |
| 504 | 下游请求超时 | 等待后重试 |

官方给出的重试纪律很明确（F-027）：**408 / 429 / 5xx 等待后重试；402 先充值；其它 4xx 不修改请求不重试。Search 与 Fetch 都是只读请求。**

## 关键差距：404 合并了五种成因

DeepSeek 的 404 对应五种完全不同的现实（F-026）：

1. URL 不可用
2. 被站点策略拦截（反爬）
3. 目标站点返回错误
4. 内容类型不受支持
5. 页面没有可提取的 Markdown 正文

**对 Agent 来说，这五种需要完全不同的反应**：

| 成因 | 正确反应 | 错误反应 |
|---|---|---|
| URL 不可用 | 换一个候选 URL | 重试同一 URL（浪费） |
| 被站点策略拦截 | 换来源（缓存、镜像、快照） | 重试（必然再失败） |
| 站点返回错误 | 等待后重试 | 立刻放弃 |
| 内容类型不支持 | 换 URL 或改用 Search 的摘要 | 重试 |
| 无可提取正文 | 用 Search 的 `summary` 代替 | 重试 |

而 API 把它们压成同一个 404，只在 `message` 里用「例如」列举。**Agent 无法从状态码区分它们**——除非去解析 `message` 文本，那本来就是脆弱契约。

对照之下，XERJ 侧的 scroll 超限错误**在错误信息里直接写明替代方案**（`search_after`），并且明确声明「不会返回被静默截断的结果集」——这不是状态码能表达的，是**面向动作的信息**。

## 一个容易被忽略的语义：429 不是失败

DeepSeek 的 429 意思是「超了 QPS 限额，等一下」；XERJ 的 429 意思是「内存断路器卸荷，节点还活着，降并发继续」（F-009）。

两者都该重试，但**重试策略不同**：

| | 建议动作 |
|---|---|
| DeepSeek 429 | 指数退避，等 QPS 窗口过去；注意 Fetch 还有未公布的域名级限制，429 可能先于账号级出现 |
| XERJ 429 | 降并发（不是纯退避），只重发被拒条目，**继续跑**——终行会带 `bulk_retries=N` |

## 评测建议：把失败路径当测试用例

评估任一检索接口时，不要只跑成功路径。去撞边界：

| 探测 | XERJ | DeepSeek |
|---|---|---|
| 查一个不存在的字段 | 400 + 可检索字段列表 | 无对应面（公有网语料，字段由服务方定） |
| 请求一个未实现的能力 | `not_supported_yet` | 404（Fetch）/ 200 空数组（Search 无结果） |
| 超出上限 | 400 + 替代方案 | 413（请求体过大）/ `count` 越界 400 |
| 制造背压 | 429（卸荷语义） | 429（限流语义） |
| 不存在的页面 | 404（索引不存在） | 404（五因合一） |

> **可迁移的方法论**：**一个检索接口的「失败可诊断性」比它的「召回率」更能决定 Agent 能不能自主工作**。召回率差是质量问题（可以换语料、换模型）；失败不可诊断是契约问题（Agent 只能瞎试，而瞎试的成本直接落在你的账单上）。
