# Windows 从应用录音到带引用的分析

用一段自有或已明确获准处理的短视频验证声音路径，再处理真实直播。输入包含一小段说话、一个数字和一处停顿即可；这是一项供读者重复的实验，本包没有在 Windows 上实际录屏或识别音频。

## 录制应用声音

在满足版本条件的 Windows 与 OBS 中，新建独立场景，添加“应用程序音频捕获”，选择播放视频的应用。若使用 OBS 30.1+ 的窗口/游戏捕获音频选项，不要再为同一声音重复添加另一来源。关闭不需要的麦克风和 Desktop Audio，观察目标音量表随播放变化。浏览器通知、其他标签页声音也可能进入同一进程的音轨，先关闭无关内容。

在录制设置中显式选择 MKV，并检查目标源分配到了要录制的音轨；不要靠默认值推定。需要保留幻灯片或演示时增加窗口画面源；仅有音频源不包含这些视觉信息。若录入多个音轨，记录哪个轨道是目标内容，后面的默认第一音轨不一定正确。

录制短样后点击停止，等软件完成写入。重新打开本地文件，核对开头、数字附近和结尾：有无静音、重复回音、通知声、削波或遗漏。只看音量表变化不足以证明写入文件正确。问题未解决前不开始长时录制。

## 选择转录路径

不写代码时，可把文件导入 Buzz，并选择本地引擎与适合语言的模型，不选择云 API。下载完成不等于已证明离线；断开网络后重新打开文件转录，记录结果或错误。系统声音实时转录需要正确的回环设备，不能把 Buzz 麦克风选项当作自动捕获浏览器声音。

希望得到稳定片段 ID 时，转到[离线 JSONL 示例](offline-transcription.md)。该示例只处理已关闭的 16 kHz、16-bit、单声道 PCM WAV，不需要把直播 URL 交给模型。先按[采集页](../concepts/02-capture.md)试听确认目标音轨并提取为 WAV；即使原视频只有一条音轨也要完成这一步。示例不提供选轨参数，时间戳相对此 WAV 首采样，不自动对齐视频。

TXT 适合初读；SRT/VTT 保留播放器时间；JSONL 为 Agent 保留 ID、修订与文本。GUI 导出字幕不会自动满足本包 JSONL 契约，需另做转换并核对时间单位。没有转换器时，可以人工抽取少量带 ID 的记录验证分析流程，不宣称已完成自动化系统。

## 交给只读 Agent

先确认 Agent 的推理位置：桌面窗口不代表本地模型。涉及私人内容时，只使用已核实的本机后端和固定文件读取范围；不清楚是否外发就停止上传。使用[分析任务模板](../concepts/05-agent-analysis.md)，只交给它已经检查过的片段，不授权执行命令或操作账号。

要求结果包含主题、主张、逐字引文与片段 ID。运行[引用检查示例](agent-evidence-check.md)只能检查引用匹配；仍需回听核对数字、否定词、责任人和上下文。把“主播声称某效果”写成“该效果已被验证”应退回修正。

## 判断是否可以扩大样本

| 可观察结果 | 继续条件 |
|---|---|
| 本地媒体可播放 | 目标音轨有声，开头与结尾存在，没有重复收声 |
| 转录可回听 | 数字、术语和否定词有人工对照，时间戳能回到相邻语句 |
| 文件不外发 | 所选后端和网络活动符合授权；断网运行结果有记录 |
| 分析可回查 | 每项主张有存在的 ID、修订和逐字引文；人工判断引文支持结论 |
| 长时处理可解释 | 存储空间够用，断线缺口记录独立，不承诺全场无损覆盖 |

扩大到长直播前，补上模型版本、参数、设备、媒体时长、处理耗时和失败情况。若要边播边分析，再引入关闭短块与定稿队列；不要让转录进程读取仍在写的文件。
