# 知识地图

## 事实层

- **页面与文章**：页面标题、账号显示、原创标记、发布时间、作者 framing（F-001–F-006）。
- **官方机制**：Warmup/Holdout、Base/Loaded 配对、状态隔离、任务结构与 Judge 流程（F-013–F-017）。
- **指标与证据边界**：指标、delta 公式、重复次数、置信区间、排行榜快照和论文限制（F-008–F-012、F-018–F-023）。
- **领域语境**：先前的相关评测工作，以及采集时未确认许可证的仓库状态（F-024–F-026）。

## 机制层：四元组洞察

### 洞察一：Loaded Impact 衡量加载产物的增量，不是 Agent 的绝对能力

- **现象/结论**：LIFT 比较同一 Holdout 任务上的 Base 与 Loaded 差异。
- **证据**：F-013、F-014、F-019、F-020。
- **反常识点**：delta 更优不等同于 runtime 的绝对任务能力更强。
- **影响**：忽略配对基线会把变化幅度误读成跨 Agent 能力排名。
- **建议**：同时报告 Base、Loaded、delta、任务集和 runtime，不单独用 delta 代表总体能力。

### 洞察二：Holdout 隔离决定结果是否能支持泛化判断

- **现象/结论**：评测把演化阶段和最终 Holdout 阶段分开，并管理运行状态。
- **证据**：F-013–F-015。
- **反常识点**：熟悉任务上的状态复用不单独证明对未见任务的泛化。
- **影响**：数据泄漏、环境残留或任务重复会抬高 Loaded 的表观效果。
- **建议**：冻结任务划分，记录状态快照与容器边界，并验证两种条件执行的是同一 Holdout 输入。

### 洞察三：统计格式完整不代表数据足够新或实验已完成

- **现象/结论**：榜单声明 10 次重复和 95% CI，但数据快照早于文章；论文称当前结果为部分跨 runtime 扫描。
- **证据**：F-008–F-012、F-021。
- **反常识点**：有重复次数与置信区间不等于覆盖了项目当前状态或全部计划实验。
- **影响**：静态旧快照可能被误读为发布时最新成绩，部分结果可能被误读为最终结论。
- **建议**：引用榜单时同时写明生成时间、重复次数、区间定义、样本范围和论文版本状态。

### 洞察四：Judge 和执行环境也是测量系统的一部分

- **现象/结论**：论文列出 Judge 偏差与环境保真度等局限。
- **证据**：F-015、F-017、F-022。
- **反常识点**：观测结果不仅取决于 Agent，也受裁判规则和环境塑造。
- **影响**：容器任务与真实浏览器/桌面工作的差异限制了结论的外推范围。
- **建议**：报告 Judge 一致性、环境覆盖与失败样例，并将结论限定在实际测试条件内。

## 迁移层：同题配对评测

**模式名：同题配对评测。成熟度 L1-draft**，目前依据单一框架的公开材料整理，尚无独立复现实证。

- **适用于**：评估加载记忆、技能、策略或其他演化产物是否改善最终任务表现。
- **不适用于**：目标是直接比较系统绝对能力，或无法建立可比任务与判分条件。
- **步骤**：冻结 Holdout 任务；用同一输入和约束运行 Base/Loaded；隔离并记录演化状态；按预定次数重复；一起报告原始值、差异、不确定性和失败样例。
- **检验标准**：任务一致、状态可追踪、重复次数与指标定义明确、区间与限制可复核。
- **反模式**：只报 Loaded；两条件使用不同任务；训练题充当 Holdout；只挑单次最好结果；把容器基准推广到所有真实环境。
- **跨领域迁移**：比较检索知识加载前后的问答系统、策略文件加载前后的流程 Agent，或规则配置加载前后的自动化系统；必须保证配对条件可比。

## 可复现性判定

1. **输入、过程和输出是否明确？** 是。官方材料定义任务字段、Base/Loaded 流程和效率指标（F-016–F-020）。
2. **读者能否只凭文章独立复现？** 否。文章没有提供固定版本、完整环境准备、运行步骤和输入输出剧本。官方仓库可供后续研究，但本包不把文章改写成未经验证的操作教程。

因此本包不创建 `examples/`。
