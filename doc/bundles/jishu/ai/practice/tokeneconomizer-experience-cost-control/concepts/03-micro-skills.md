# 微技能：用证据门控把仓库事实注入上下文

## 它解决什么

仓库专属的操作事实会被一轮轮重新发现：这个仓库要用 `python -m pytest`、`npx tsc`，某条命令要先设环境变量，生成文件落在哪个目录（F-018、F-021）。micro-skill 就是**一行这样的仓库事实**，附一组可执行的 detectors（F-051、F-052）。

关键不在于「记住」，而在于**什么时候才允许写进起始上下文**。博客的表述是：只有多次会话确认了该模式才加入，后续证据反驳时把它撤下。论文把这套门控写成了可复现的规则。

## 四步循环

| 步骤 | 动作 | 是否调用模型 | 事实编号 |
|---|---|---|---|
| 1. 提议 | 每 5 个任务，LLM proposer 从近期轨迹摘要生成一行事实 + 可执行 detectors | 是 | F-051 |
| 2. 逐轨迹检验 | 每个任务结束后，detectors 判断该轨迹是确认、反驳，还是根本不需要这条事实 | 否 | F-052 |
| 3. 选择性注入 | 满足确认条件且 need rate 达标时，才在任务起始注入 | 否 | F-053、F-054 |
| 4. 退休 | 支持度转负或出现高风险矛盾时永久移除 | 否 | F-057 |

第 2 步「不调用模型」是成本设计的关键：证据收集是纯规则执行的，只有第 1 步周期性调用一次 proposer。这也解释了插件为什么把 micro-skills 默认关闭——提议器本身要花钱，收益取决于仓库与工作内容（F-096）。

## 三道门

**门 1 · 确认**：3 次确认，且这 3 个任务**编辑的文件互不重叠**（F-053）。「互不重叠」是为了避免同一个改动被反复计成三次独立证据。

**门 2 · 需要率**：need gate 要求该事实在 ≥4 次被触发的任务里，need rate ≥ 0.4（F-054）。一条虽然被确认、但极少用得上的事实不值得每轮都塞进上下文。

**门 3 · 支持度**：式 (2)（F-055）

```
q_i(f) = Σ_{j<i} γ^(i−j) · ( 1[ξ_j confirms f] − λ · 1[ξ_j contradicts f] )
```

- γ = 0.8：每过一个任务，旧证据按 0.8 衰减（F-056）；
- λ = 5：一次反驳按 5 次确认计（F-056）；
- qᵢ(f) < 0 → 永久退休（F-057）。

这套设计的取向很明确：**新证据比旧证据重，反证比正证重**。一条事实要长期留在上下文里，需要持续被轨迹确认；一次明确的反驳就足以把它撤掉。

## 三态状态机（论文表 11）

| 状态 | 是否注入 ΔPᵢ | 离开条件 |
|---|---|---|
| Candidate | 从不 | 在 3 个编辑文件互不重叠的任务上确认 → Confirmed |
| Confirmed | 每个任务按需注入；need rate 未达标则暂不注入、下个任务前重查 | qᵢ(f) < 0，或高风险技能出现任一矛盾 → Retired |
| Retired | 从不 | 永不离开；proposer 可用**新标识符**提出替代事实 |

「Retired 不可复活」看起来严苛，但配合「可用新 id 重提」，效果是把一条被证伪的经验彻底清出账本，同时不阻止重新学习。附录 H 记录：**约五分之一被提议的技能在流内被退休**（F-059）——账本确实在改主意，而不是只增不减。

事实编号 F-065、F-072。读这张表要注意单位不统一（表 7 明确说明）：`Needed` 的单位是「任务」，会比 `Confirmed` 大 33–37 倍；`Masked` 是流末仍被屏蔽的 schema 数，`Re-audits` 是以完整目录运行的任务数，两者不可比较。

另一个值得注意的结论：组合变体的各列计数与对应单策略变体接近，说明**三条元策略很少互相干扰对方的决策**（附录 H）。这为「叠加」提供了机制层面的解释，而不只是结果层面的数字。

## 论文配置 vs 插件行为

| 维度 | 论文实验 | 开源插件 |
|---|---|---|
| 提议周期 | 每 5 个任务（F-051） | `microskills_propose_every` 默认 3 个 session（F-097） |
| 默认开关 | 开 | **关**（F-096） |
| 无模型调用的模式 | — | `microskills=envfacts`：只从重复失败中学事实（F-097 之外的 README 说明） |
| 复用历史 | 每个仓库从零开始（F-086） | Claude Code 可 `history_import=on` 导入更早会话，且无需模型调用 |

逐项差异见 [参数分账台账](../references/parameter-ledger.md)。**别把 README 的 `k=3` 读成论文的确认阈值 3**——前者是提议周期，后者是确认次数，只是碰巧都是 3。

> **可迁移的一点**：证据门控的价值不在「记得准」，而在「错了能自动退」。任何把历史经验写进生产路径的系统，都应该同时写下「什么证据会推翻它」和「推翻后怎么回滚」。
