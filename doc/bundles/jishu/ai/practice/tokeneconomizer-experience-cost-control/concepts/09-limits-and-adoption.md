# 局限与落地判据：什么时候不该上

## 论文自述的三类误判（F-106）

| 误判 | 后果 | 恢复路径 |
|---|---|---|
| micro-skill 过期 | 注入过时仓库事实 | 后续轨迹反驳即退休（F-057） |
| 被剪的工具重新需要 | 任务缺工具 | 下一次全目录复审归还（F-063）；插件侧 `toolprune restore`（F-101） |
| 困难但有效的任务被误判为失败循环 | 打断本可成功的工作 | 先 redirect 再 stop、放过不确定情形（F-106）；插件侧只提示、不自行停止（F-100） |

论文的态度值得注意：**不追求零误判，而是限制每次误判的损害**。这既是 [可迁移模式](08-transferable-pattern.md) 的第 4 步，也是评估任何类似系统时该问的第一个问题。

## 三类覆盖边界

1. **harness 覆盖**：实验只覆盖三种广泛使用的编码 agent，未覆盖 Pi 等更精简 harness（F-107）。插件虽列了稳定 / 实验性支持矩阵（F-092、F-093），但实验性适配器的能力并不齐整。
2. **任务流真实性**：SWE-Bench 流是「相关但彼此独立的修复」，不是真实用户连续会话（F-108）。论文推测连续会话会提供更多可复用经验，并把交互式工作流列为下一步测试对象。
3. **证据独立性**：四个采集信源均由作者团队发布，本次采集未取得独立第三方复现（F-109、F-014）。`experiments/` 提供复现材料（F-104），但本束未运行。

## 投入产出判据（V 阶段采纳 V-3）

省的是 **token 账单**，不是人力、交付周期或代码质量。下面这些情形，先别上：

| 情形 | 判据 | 依据 |
|---|---|---|
| 项目只有三五个任务 | 前几个任务成本可能更高，第 6 个任务起才全部低于默认 | F-086 |
| 每个任务都在新仓库 | 经验不可复用；安全基准上 micro-skills 被关闭、ReposVul 降幅仅 6.4–9.3% | F-071、F-091 |
| 轨迹本来就短 | 可回收成本少，干预的收益上限低 | F-091 论文解释 |
| 无人值守 headless 且无外层超时 | 插件只提示不刹车，被标记的 turn 会跑到 agent 自身上限 | F-100 |
| 无法按缓存口径计量成本 | 账面「省了 token」不等于「省了钱」 | F-049 |
| 质量指标缺失或允许用质量换成本 | 整套方法的目标函数把质量写成约束 | F-050、F-082 |

**值得上**的画像：长期维护的同一代码库、任务以时间序列持续到达、agent 版本在受测区间内（见 [术语表版本快照](../references/glossary.md)）、能同时观测成本与 Pass@1 类质量指标、且有人或外层机制处理「仍卡住」的提示。

## 落地检查表

- [ ] 先按仓库分组记录**基线成本与质量**，再启用任何策略；
- [ ] `config` 打印本仓全部生效设置并存档，确认 micro-skills 的实际开关（F-096、F-101）；
- [ ] 明确「插件不会自行停止 turn」，headless 场景配外层超时；
- [ ] 至少观察 6 个任务再判断成本是否回落，别用前两个任务下结论（F-086）；
- [ ] `status` / `microskills` / `toolprune` 定期检查被注入的事实与被剪的工具；
- [ ] 出现「事实过时 / 工具缺失」时走退休与 restore 通道，不手工删配置硬扛；
- [ ] 报告里同时写成本降幅与质量变化，且注明成本口径是否含控制器开销（F-048、F-049）；
- [ ] 不把论文数字当作对本仓库的承诺（F-109）。

## 复核触发条件

1. arXiv 出现 v2，或仓库 Settings 表默认值、支持矩阵变化；
2. 出现独立第三方复现报告（当前 F-109 为「未取得」）；
3. `stale_after: 2027-02-28` 到期；
4. 常用 agent 版本超出 [术语表](../references/glossary.md) 登记的受测区间。
