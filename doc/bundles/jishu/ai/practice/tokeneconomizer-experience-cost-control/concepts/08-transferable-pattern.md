# 可迁移模式：可逆节流

> 本页是七概念 **E（萃取）** 阶段产物：把 TokenEconomizer 的具体做法去掉场景细节，只留下「下次遇到类似问题怎么做」。模式基于 1 个主案例 + 论文内 3 条元策略的独立变体对照，成熟度标为 **L1（单案例待跨项目验证）**，不宣称已通用验证。

## 模式名片

| 项 | 内容 |
|---|---|
| 名称 | **可逆节流**（4 字） |
| 一句话 | 用历史轨迹驱动的资源削减，必须同时具备证据门控、反证通道与恢复路径；削减量不是目标，质量约束下的净收益才是 |
| 触发信号 | ① 同一环境反复执行相似任务；② 成本按轮重复计费；③ 固定策略在不同环境效果相反 |

## 适用于 / 不适用于

| 适用于 | 不适用于 |
|---|---|
| 任务按时间序列到达、环境稳定可复用 | 一次性任务、每次都是全新环境 |
| 被削减的对象是可枚举、可恢复的配置（工具、上下文片段、轮次预算） | 削减会不可逆地破坏数据或外部副作用 |
| 成本可被计量且能归因到具体任务 | 只有总成本、无法拆到环境或任务 |
| 有明确的「质量不低于基线」约束可写 | 质量无法度量，或允许用质量换成本 |

论文里的反例很直接：安全审计基准每个任务都是新仓库，micro-skills 因此被整体关闭，只剩两条元策略；ReposVul 轨迹更短，可回收成本少，降幅只有 6.4–9.3%（F-071、F-091）。**经验不可复用时，节流模式就该自动退场。**

## 五个步骤

1. **先量，再削**：在动任何配置之前，对一个代表性任务流做剖析，把成本拆成可归因的几类（对应 F-018~F-029 的 30%/7%、23/16、17%/32%）。
2. **按环境分账**：为每个环境单独维护状态，不把 A 环境的经验搬到 B 环境（F-019 的 7% 跨仓匹配率就是判据）。
3. **给每个削减动作配证据门控**：重复证据才生效；证据要能自动采集、且采集本身尽量不花被优化的资源（detectors 不调用模型，F-052）。
4. **同步写反证与恢复**：什么证据会推翻这条决策、推翻后怎么回滚、多久强制复审一次（F-057 的 λ=5、F-063 的每 5 任务全目录复审）。
5. **把质量写成约束，把控制器开销计入账本**：优化目标形如「最小化期望成本 s.t. 期望质量 ≥ 基线 − ε」（F-050），且控制器自身的调用成本必须计入（F-048、F-049）。

## 五个反模式（G3 要求 ≥3）

| # | 反模式 | 案例依据 |
|---|---|---|
| 1 | **全局固定裁剪**：一套精简配置套所有环境 | F-031~F-038：三种固定策略在 Django 全降、SymPy 全升 |
| 2 | **削完不给恢复通道**：错剪后无法自愈 | F-063 复审、F-101 `restore` 存在的理由 |
| 3 | **把重复当失败**：见到重复错误就停 | F-029：50 条成功轨迹中 36 条也重复失败签名 |
| 4 | **省钱不计控制器开销**：judge 每轮都调也报「节省」 | F-048、F-049：成本含控制器自身调用、按缓存计价 |
| 5 | **把经验库当只增不减的资产**：事实越攒越多、从不退休 | F-059：约 1/5 提议技能在流内被退休 |

## 检验标准

做完怎么知道做对了：

- [ ] 每个环境都有独立状态，且能打印出「本环境当前生效的全部策略」；
- [ ] 任意一条生效策略都能回答：由哪几条证据确认、什么证据会推翻它、怎么回滚；
- [ ] 质量指标与成本指标**成对**报告，且质量不劣于基线约束；
- [ ] 控制器自身开销已计入成本，不是从分母里偷偷拿掉；
- [ ] 在「全新环境」对照组上， savings 自动收敛到接近 0 或策略自动关闭，而不是硬套出负收益；
- [ ] 存在一个「前几个任务更贵、之后才回本」的可观测拐点（对应 F-086 的第 6 个任务）。

## 跨领域迁移示例（非 AI 编码场景）

**示例 A · 数据库索引治理（数据基础设施）**：把「慢查询历史」当轨迹。索引不是越多越好——每个索引都按写入次数重复计费。可逆节流对应：仅在多个不重叠时间窗的查询里反复出现同一过滤条件才建索引（证据门控，类似 F-053 的「编辑文件互不重叠」）；一旦写入放大或查询模式变化就自动 drop（反证，类似 λ=5）；每隔固定周期全量复审一次索引目录（类似 F-063）。检验标准同样成对：P99 延迟不得劣于基线，且要把「维护索引的写入开销」计入账本。

**示例 B · CI 测试选择（研发流程）**：把「历史变更→失败用例」当轨迹，按仓库剪掉长期未触发的测试套件。反模式 3 在这里同样成立：某次重复失败不等于该套件无用；必须定期跑一次全量套件复审，并保留一键恢复。

两个迁移共同点：**削减对象是可枚举的配置，成本按轮重复计费，质量有基线约束**。缺任一条，这个模式就不适用。

## 与既有模式的关系

- 与「上下文压缩」互补：压缩作用于单任务内的上下文，可逆节流作用于跨任务的配置；论文表 1 显示 TE 可与 RTK / RepoMap 叠加（F-083）。
- 与「程序记忆 / 技能库」的区别：技能库以「提升成功率」为目标，可逆节流以「质量约束下降成本」为目标，且强制配套退休机制（F-050、F-057）。
