# Graphic-Eval：把“设计好不好”拆成三根轴

## 本章要点

1. Graphic-Eval 同时扮演两个角色：演化时的 reward，和报告时的指标（F-060）。
2. 三根轴：completeness 评“要求做全没有”，aesthetics 评“视觉质量”，critique 定位“哪里不好”（F-061）。
3. completeness 先抽 3–10 条可判定要求，再逐条判 met / partial / not_met，权重 1 / 0.5 / 0（F-062、F-063）。
4. 标量分是 0.7×完整度 + 0.3×美学；τ=0.6 只用于挑失败对象，不用于发布决策（F-066）。
5. 成功率与质量分是两个口径：质量只在成功样本上计算，不能混成一个准确率（F-078）。

## 三轴分工

| 轴 | 回答的问题 | 输出 | 在系统中的作用 |
|---|---|---|---|
| completeness | brief 的要求做到了多少 | 0–1 的比例 | 主信号，权重 0.7 |
| aesthetics | 纯视觉质量如何 | 1–10 分，归一化到 0–1 | 次信号，权重 0.3 |
| critique | 具体哪里有问题 | 八维 major/minor 计数 | 诊断，不进标量 |

三轴分开的意义：一张漂亮但完全跑题的图，不应因为“好看”而通过；一张满足所有要求但排版粗糙的图，也不应被当成“没完成任务”。

## completeness：先分解，再检查

### 第一步：分解

一个被提示为“资深平面设计师”的 LLM 调用从 brief 抽出 **3–10 条可评分要求**（F-062）。抽取规则包括：

1. 每条要求必须能被判为 met / partial / not_met。
2. 对“复古感”这类软要求，要把灵活性写进判据；对具体指令则保持精确。
3. 相关属性合并为一条，避免同一件事被重复计分。
4. **排除“用哪个工具/软件、如何实现”的要求**。

第四条最关键：completeness 评的是**结果**，不是路径。Agent 可以自由选择工具，只要最终产物满足 brief。

### 第二步：检查

一个多模态调用收到 brief、要求列表与渲染图，逐条标注 met / partial / not_met；任何低于 met 的项都必须给出理由（F-062）。计分（F-063）：

| 判定 | 得分 |
|---|---|
| met | 1.0 |
| partial | 0.5 |
| not_met | 0.0 |

completeness 是这些得分的平均。那些“为什么没做到”的理由，正是 Reflector 后来消费的 why-bad 信号。

## aesthetics：只评视觉，不看跑题

aesthetics 由另一个多模态调用完成，明确**忽略是否遵循 brief**，只评构图、平衡、负空间、层级、排版、色彩和谐、形式语言与工艺（F-064）。

| 分数 | 锚点 |
|---|---|
| ≤3 | 弱 |
| 6 | 过得去但平庸 |
| 8 | 专业、精致 |
| 9–10 | 卓越 |

最后存为 `aesthetic = score / 10`，落在 0–1。

为什么要把“是否遵循 brief”从美学里剥掉？因为如果美学分也奖励“贴题”，它就会和 completeness 高度相关，0.7/0.3 的加权就失去意义。剥掉之后，0.3 的权重才合理：一张漂亮但跑题的图，不应获得高通过率（F-064、F-066）。

## critique：定位问题，而不是打分

第三个多模态调用扮演“资深设计总监”，在八个维度上逐项列出可见问题，并标注 major / minor（F-065）：

1. 层级 / 排版
2. 对比 / 可读性
3. 间距 / 对齐
4. 色彩
5. 构图 / 平衡
6. 工艺 / 执行
7. 一致性
8. 原创性

critique 不进入 0.7/0.3 标量，只作为诊断轴：它能说明美学分的变化是不是“因为对的理由”。

## 标量分与失败阈值

单条轨迹的标量分为：

$$s_j = 0.7 \times \text{completeness}_j + 0.3 \times \text{aesthetic}_j$$

用途只有一个：**把轨迹分成成功与失败，供修订选择**（F-066）。

| 用途 | 是否使用绝对分 |
|---|---|
| 选择要修订的技能 | 是，s < 0.6 记失败 |
| 决定候选是否发布 | 否，只用成对回放 |

这是理解全文的关键分工：绝对分负责“找问题”，相对比较负责“决定改不改”。

## 同一个 judge 的双重角色

论文有意让同一个冻结 judge 既驱动演化，又报告内部改进（F-060）。好处是：技能是**按它将被衡量的标准**被修订的，不会出现“优化 A 指标、报告 B 指标”的错位。

代价是：

1. **自评偏差**：同一模型家族的 judge 可能偏爱自家输出；论文用成对比较与随机换序缓解，并可切换到跨家族后端（F-067）。
2. **指标不独立**：内部改进不能当作外部验证；论文明确说不能替代真实用户研究（F-099）。
3. **感知上限**：VLM 会放过它看不见的像素级错位（F-101）。

## 四个指标必须分开读

| 指标 | 定义 | 能回答 | 不能回答 |
|---|---|---|---|
| 成功率 | 900 秒内产出有效设计的比例 | 工具链是否跑通 | 跑通的结果好不好 |
| 生成质量 | 成功样本上的 benchmark 分数 | 成功时质量多高 | 失败率有多高 |
| 完整度 | 要求满足率（0–1） | brief 做得全不全 | 视觉是否好看 |
| 配对胜率 | 盲测下 Evolve 相对 Base 的胜出比例 | 相对偏好 | 绝对水平 |

论文特别提醒：质量分只在成功生成上计算，成功率与质量不能混成一个准确率（F-078）。Qwen 就是例子：质量分很高，但成功率低，说明它只在容易的 prompt 上成功（F-085）。

## 成本信号

每次 rollout 还记录工具调用数、wall-clock 与输入/输出 token（F-068）。这不是事后补充，而是与质量并列的一等结果：技能库的第二重作用就是缩小工具面、减少迭代。

## 局限

| 局限 | 说明 |
|---|---|
| judge 漂移 | 同一图跨运行评分会变；靠成对比较抵消 |
| 同族偏好 | 可切换跨家族后端，但不能完全消除 |
| 感知上限 | Droste 案例中 VLM 会放过明显错位（F-101） |
| 无人类验证 | 论文未招募用户，内部指标不等于人类偏好（F-099） |

## 常见误读

| 误读 | 纠正 |
|---|---|
| “美学分高就是设计好” | 美学明确忽略 brief 遵循度（F-064） |
| “completeness 是准确率” | 它是加权满足率，partial 计 0.5（F-063） |
| “0.6 是上线门槛” | 0.6 只用于分成功/失败；上线由回放门控决定（F-066） |
| “内部指标提升等于用户更满意” | 论文明确否认（F-099） |

3. 同一个 judge 既演化又报告，带来什么好处与什么风险？
