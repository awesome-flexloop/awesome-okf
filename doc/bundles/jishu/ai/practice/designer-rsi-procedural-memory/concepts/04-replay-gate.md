# 匹配回放门控：不接受“平均分变高”，只接受“没有变坏”

## 本章要点

1. 绝对分数不可靠：同一张图在同一 judge 上会漂移，solver 本身也随机，输入资产还会变（F-052）。
2. 门控用**相对比较**消除共同漂移：同一批、同一 context、双臂重放、成对判定（F-053、F-055）。
3. 一个 prompt 有多个 context；候选必须赢多数 context 才算赢这个 prompt（F-056）。
4. 接受条件是**无任何记录退化，且至少一条记录改进**；全部打平也拒绝（F-058）。
5. 这是“宁可错过改进，也不接受已见退化”的保守策略；它只保证回放集内不退化，不保证全流量安全（F-059）。

## 为什么“平均分上升”是个坏规则

VLM judge 对同一张图的评分会跨运行漂移；solver 的采样也有随机性；不同回放还会检索到不同资产。若用“平均分上升就接受”：

| 混杂来源 | 会发生什么 | 后果 |
|---|---|---|
| judge 漂移 | 这一批评分整体偏高 | 把噪声当改进 |
| solver 随机 | 候选恰好采样到更好的输出 | 把运气当能力 |
| 输入差异 | 候选拿到更好的资产/上游状态 | 把输入优势当技能优势 |

门控通过设计消除前两类：两臂在同一批、同一 context 下重跑，共同漂移在差值中抵消；判定只问“哪张图更好地满足 brief”，不问绝对分（F-052、F-053）。

## 门控的五个要素

| 要素 | 具体做法 | 解决什么 |
|---|---|---|
| 匹配上游 | 同一 prompt、同一资产、同一上下文，冻结后双臂重放 | 排除输入差异 |
| 选择回放集 | 重写：2 条高分 + 2 条低分；mint：触发簇内按分数无关采样 | 同时检验“修失败”与“不破坏成功” |
| 成对判定 | 每个 prompt 的每次 context 都成对比较，随机交换展示顺序 | 降低位置偏差与绝对分漂移 |
| 逐 prompt 多数 | 候选须赢该 prompt 的多数 context，才算赢这个 prompt | 防止一个 context 的大胜掩盖其他 context 的失败 |
| 保守接受 | 无任何记录退化，且至少一条记录改进 | 不接受“用一处退化换另一处提升” |

（F-053、F-054、F-055、F-056、F-058）

## 判定逻辑

对每条回放记录，候选与基线多次成对比较，汇总为该记录上候选的胜率 r（0 到 1）。设平局带半宽为 δ：

1. r 大于 0.5+δ：该记录为**改进**。
2. r 小于 0.5−δ：该记录为**退化**。
3. 其余为**平局**。

候选被接受，当且仅当：

- 不存在任何一条退化记录；
- 至少存在一条改进记录。

两个条件缺一不可。全部打平的候选会被拒绝：它不值得一次版本升级，而且上线会重置技能统计却没有可测收益（F-057、F-058）。

> 这比“最大化期望质量”更保守。论文明确说：在部署产品里，一次可见退化比一次错过的改进代价更高（F-058）。

## 重写与新增的回放集不同

| 场景 | 对照臂 | 回放 prompt 来源 | 检验目标 |
|---|---|---|---|
| 重写（Deepening） | 旧版技能（incumbent） | 该技能历史轨迹中 2 条高分 + 2 条低分 | 既修失败，又不破坏原有成功用法（F-054） |
| 新增（Widening） | 无技能 Agent | 触发缺口簇内的轨迹，不看分数 | 新技能是否比“没有它”更好（F-053、F-054） |

重写的“2 高 + 2 低”是关键设计。只回放失败案例，会把技能改成“专治这一种失败”，却悄悄破坏原本能处理的情形；只回放成功案例，又无法验证它是否真的修好了问题。

## 拒绝之后发生什么

| 候选类型 | 处理 | 证据是否保留 |
|---|---|---|
| 重写被拒 | 丢弃候选；连续失败计数 +1，推动定向→整体重写升级；可能触发一次性探索环 | 提案与 before/after 快照留档（F-050、F-058） |
| 新增被拒 | 丢弃候选；occurrences 保留在缺口池 | 等更多证据后可再试（F-044） |

“拒绝也留档”让技能库的历史不只记录“什么上线了”，也记录“什么被尝试过、为什么被拒”。这对审计很重要。

## 一个 illustrative 判定表（非论文数据）

假设某候选重写回放了 4 条记录，每条有 3 个 context：

| 记录 | 类型 | 候选胜率 r | δ=0.1 时判定 |
|---|---|---|---|
| P1 | 低分轨迹 | 0.83 | 改进 |
| P2 | 低分轨迹 | 0.67 | 改进 |
| P3 | 高分轨迹 | 0.50 | 平局 |
| P4 | 高分轨迹 | 0.33 | 退化 |

结论：拒绝。虽然两条失败被修好，但一条原本成功的记录退化了。门控不做“净收益”交易。

这个例子只说明规则，不代表论文的实际回放结果。

## 它能保证什么，不能保证什么

| 能保证 | 不能保证 |
|---|---|
| 在选定的回放案例上，候选没有变差 | 未回放的任务组合不会误触发（F-059、F-098） |
| 改进是成对比较出来的，不是平均分噪声 | 人类用户会更喜欢结果（F-099） |
| 每次拒绝都有记录，可审计 | 技能在超长流程中仍被完整遵守（F-102） |

论文自己用 R4 的回退说明第二列：R4 的低端完整度降到 90%，低于基线 94%，尽管它在 ≥0.9 的高端仍高 7 个百分点（F-079）。回放集通过，不等于全流量安全。

## 与工程实践的类比

| 类比 | 相同点 | 不同点 |
|---|---|---|
| 回归测试 | 上线前必须“不破坏已通过案例” | 回归测试是确定性的；这里是 VLM 成对判定，需要平局带 |
| A/B 测试 | 相对比较、控制混杂 | A/B 看总体指标；这里要求**逐条不退化**，更严格 |
| 金丝雀发布 | 先小范围验证 | 这里验证的是历史回放，不是真实流量分流 |

## 设计取舍

| 选择 | 收益 | 代价 |
|---|---|---|
| 不看绝对分 | 免疫 judge 漂移 | 无法利用“整体质量上升”这种信号 |
| 逐条不退化 | 保护已有成功用法 | 可能拒绝掉净收益为正的候选 |
| 全部打平也拒绝 | 避免无意义版本升级 | 微小但真实的改进可能被漏掉 |
| 每条 2 高 + 2 低 | 成本可控 | 回放集小，覆盖有限 |

## 常见误读

| 误读 | 纠正 |
|---|---|
| “门控是在选分数最高的候选” | 它只做接受/拒绝，不做排序（F-058） |
| “平均分提高就能上线” | 明确禁止；只看成对比较（F-052） |
| “全部打平可以保守上线” | 全部打平会被拒绝（F-058） |
| “通过门控就说明全流量安全” | 只保证回放集内不退化（F-059） |

## 自检问题

1. 门控为什么要求“同一批、同一 context”，而不是分别跑两次再比平均分？
2. 重写回放为什么必须同时包含高分与低分轨迹？
3. 一个候选修好了两条失败、但让一条成功退化，应该接受吗？为什么？
4. 如果业务更怕错过改进而不是怕退化，这套门控应该怎么改？代价是什么？
