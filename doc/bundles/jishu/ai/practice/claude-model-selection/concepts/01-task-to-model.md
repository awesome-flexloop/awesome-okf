# 按任务选型与 effort 调档

## 默认答案：Opus 5.5，`medium`

博文的中心建议很直接：多数工作从 Opus 5.5 的默认 effort `medium` 开始（F-005）。理由是它在能力与成本之间取得平衡，且单位 token 价只有 Fable 5.2 的一半（F-006）。这也是 Claude Code 的默认档位，所以“不知道该选谁”时的正确答案就是不动。

选型不是一次性的，而是随任务形态上下移动：

1. 范围明确、可快速验证的日常工作 → 下移 Sonnet 5.5（F-007）。
2. 最简单的高频工作（分类、路由、抽取）→ 再下移 Haiku 5.5（F-009）。
3. 最难的技术项目，或 Opus 5.5 在 `high` 仍不足 → 上移 Fable 5.2（F-010）。

一个容易踩的坑：**规格清晰不等于应该用 Sonnet**。迁移与性能优化往往规格写得很清楚，但难度足以需要 Opus 5.5；重大项目甚至需要 Fable 5.2（F-008）。判断依据是“执行难度与失败代价”，不是“需求文档是否完整”。

## 任务—模型矩阵

| 任务 | 起始模型 | 起始 effort | 判断依据 |
|---|---|---|---|
| 日常工程、调试、多 PR 功能 | Opus 5.5 | `medium`，再 `high` | 成本与能力平衡（F-013） |
| 分类、路由、打标、高频抽取 | Haiku 5.5 | `medium` | 家族内最低成本与延迟（F-014） |
| 搜索文件、读日志、摘要子代理 | Haiku 5.5 或 Sonnet 5.5 | 模型默认 | 错误易发现，判断留给主模型（F-015） |
| 聊天与交互式会话 | Sonnet 5.5 | `low` 或 `medium` | 等待时间优先（F-016） |
| 范围明确的编码（修 bug、功能迭代） | Sonnet 5.5 | `medium`，更难时 `high` | 半价处理范围明确任务（F-017） |
| 日常文档、幻灯片、表格 | Sonnet 5.5 | `high`（Claude Code 为 `medium`） | 迭代快、设计感强（F-018） |
| 重复运行的 Agent 任务 | Sonnet 5.5 | `medium` | 定义明确、重复执行（F-019） |
| 计算机使用、重视觉工作流 | Opus 5.5 | `medium` | 长时间 agentic 循环（F-020） |
| 大型重构、迁移、架构规划 | Fable 5.2 | `medium`，再 `high` | 开放式技术工作（F-021） |
| 深度研究、科学或定量分析 | Fable 5.2 | `medium`，再 `high` | 最难技术项目（F-022） |
| 不确定 | Opus 5.5 | `medium` | 默认档位（F-023） |

## effort 优先于换模型

换模型是粗调，effort 是细调。博文明确要求：在换模型之前先调 effort（F-011）。原因是超过 `high` 之后，再升一档的成本可能已经等于换更大的模型，而收益未必更好。

effort 能买到的是“想得更久、调更多工具、更多自检”，买不到的是模型不具备的知识与技能（F-012）。所以两类问题的解法不同：

1. 任务需要更长的推理链、更多验证 → 升 effort。
2. 任务需要模型压根没有的领域能力 → 换更大的模型。

另一个被低估的变量是延迟。effort 与延迟大致正相关，交互式场景里把 effort 拉到 `max` 往往得不偿失；博文建议人正在等待的回复从 Sonnet 5.5 的 `low`/`medium` 起步（F-016）。

## 能力不足时的三步升级

博文给出固定顺序（F-042）：

1. 先检查模型能否自验：有没有测试、构建或调用端点的脚本。
2. 自验补上后仍不够，再把 effort 升一档。
3. 仍不够，换上一级模型，并从比原模型更低的 effort 起步。

这个顺序的价值在于：**自验通常比升 effort 更便宜，也更少增加延迟**。可自动校验时，博文甚至建议全部用低 effort 跑，只对失败项用高 effort 重跑——同子集通过率约 97%、`$0.17`/题，优于全 `high` 的 95.3%、`$0.29`/题（F-043）。

## 用代码路由，不要让模型路由

当路由规则简单（例如按步骤类型固定模型），让代码选模型，而不是再问一次模型“你该用谁”（F-074）。模型路由会引入额外 token、额外延迟和额外不确定性；规则明确时它没有收益。

## 适用边界

矩阵是起点，不是结论。博文自己在最后要求读者在自己的任务上实测（F-075），因为厂商基准的最难任务分布与你的业务不一定一致。价格、effort 档位与模型版本都会变，本文数值以 2026-11-10 为准。
