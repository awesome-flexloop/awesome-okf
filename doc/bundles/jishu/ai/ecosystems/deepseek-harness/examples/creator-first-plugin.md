# 从一个倒计时插件开始

**这是待复现的练习方案，本次未安装或运行插件。** 适用前提是已有可用 Harness、模型配置和可选择的测试工作区。新环境安装按当前官方指南完成，本文不提供猜测的下载包、API 签名或自动安装脚本。

## 确认环境

官方入门顺序为打开设置中的模型配置、选择工作区，再创建会话并发送任务；审批由当前权限策略决定。[F-058](../references/creator-mode-facts.md) 记录实际 Harness 版本、模型名称、profile 和权限策略，费用按自己的模型服务确认。本次不引用旧知识包的历史定价。

界面入口以[官方 Web UI 指南](https://deepseek-harness.github.io/deepseek-harness/en/guide/quickstart)为准；profile 的确认方式见[官方安装文档](https://deepseek-harness.github.io/deepseek-harness/en/develop/basic/publish)。先由当前环境的设置或启动配置确认这些值，不猜不存在的菜单。不能确认会话对应的 profile 时只做预览，不批准安装。首次请求前还需确认模型费用预算、尝试轮次及数据外发范围，详见[安全条件](../concepts/creator-safety-and-lifecycle.md)。

选不含凭证和业务数据的测试工作区，保留当前配置。原文明确的入口是新建空白会话后，在模式选择中切到创造模式；若当前界面不存在此入口，先确认版本与功能，不继续按旧界面盲点。[F-022](../references/creator-mode-facts.md)

## 先请求预览

以下提示词由本教程原创，借用原文的小组件任务思路，不复制作者长提示词，也不声称经过本次运行验证。

```text
我想在当前工作台做一个可停用的下班倒计时插件。
先检查运行时提供的 UI 扩展能力和安装目标，只给出设计与变更预览。
期望位置是聊天输入区附近，不覆盖输入框、不改变现有会话内容。
让我输入本地目标时间，显示剩余时分秒；到时显示“已到目标时间”，不出现负数。
目标绑定创建时的本地日期，过去的目标视为已完成；跨午夜不自动重设为下一天。
本轮先不做百分比进度，也不自动推断明天的下班时间。
说明状态保存在何处、计时器如何在卸载时清理，以及如何恢复原界面。
不要自动安装依赖、读取凭证、切换权限或执行代码。等待我确认。
```

简化百分比是本教程的设计取舍：源文提出百分比，却未完整定义工作开始时间与跨日口径。[F-029、F-030](../references/creator-mode-facts.md) 先测试时间显示，之后再补齐工作区间与跨日规则。

上述日期规则也是本教程的取舍，不是产品契约。首轮仅测试本地时区固定、系统时间正常的情形；手工调时、时区切换、休眠恢复和夏令时变化列为未支持边界，未测试前不得声称覆盖。

## 检查方案再批准

方案至少应回答插件实际名称、目标 profile、挂载位置、依赖与待修改配置、数据存储、卸载路径。工具名称可由当前运行时返回，但不要自行假设 `cordis_inspect_query` 的参数。[F-025、F-026](../references/creator-mode-facts.md)

若 Agent 输出独立 HTML，而没有说明如何成为当前宿主的插件，回到方案阶段。若请求完全权限，先核对具体操作；无法限定范围就停止。权限取舍见[安全与生命周期](../concepts/creator-safety-and-lifecycle.md)。

确认后可以单独允许本次安装与运行，授权中写清“只允许上述插件、指定 profile 和已展示的变更”。这不是永久授权，也不自动允许额外软件包或外部服务。

## 用已知结果测试

| 测试输入或动作 | 期望观察 | 记录 |
|---|---|---|
| 设置稍晚于当前时间的目标 | 显示正剩余时间并按秒更新 | 实测后填写 |
| 设置一分钟后的目标并等待经过该时刻 | 自然切换完成文字，之后保持非负且不自动跳到明天 | 实测后填写 |
| 设置已过去的目标时间 | 显示完成状态，不出现负数 | 实测后填写 |
| 修改目标时间 | 显示立即变化，不产生第二个计时器 | 实测后填写 |
| 正常输入消息 | 输入框、发送与会话历史仍可用 | 实测后填写 |
| 切走后回到聊天 | 状态行为与方案一致 | 实测后填写 |
| 停用并重新启用插件 | 界面恢复，未出现重复组件 | 实测后填写 |
| 卸载插件 | 插件界面与计时活动停止，原任务可用 | 实测后填写 |
| 比对停用前后的配置 | 本次配置变更已按基线恢复，其他插件及用户补丁不被覆盖 | 实测后填写 |

这组标准是建议，不是作者已有测试结果。作者明确报告的只是归零状态出现。[F-032](../references/creator-mode-facts.md)

“没有重复计时器”和“计时活动停止”不能只靠截图判断。要求方案提供可观察的活动实例计数、计时回调计数及卸载清理日志，或当前运行时支持的等效证据；修改、停用、重启后分别核对。没有这样的证据时，仅记“界面通过、后台清理未验收”，不编造检查 API。配置基线与恢复顺序见[恢复流程](../concepts/creator-safety-and-lifecycle.md)。

## 保存复现证据

记录环境版本、原始任务、批准的变更、安装日志、失败提示、测试观察及恢复结果。截图只在不含敏感会话和凭证时保留；不要把 API Key 或用户数据贴入公开知识包。

成功后可进一步定义进度百分比；失败时先判断处于安装、配置、运行时、UI 还是交互层，再把最小错误信息交给 Agent。不要用“多给权限”替代根因判断。
