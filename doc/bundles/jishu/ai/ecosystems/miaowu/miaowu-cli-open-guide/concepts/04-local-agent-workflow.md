# 本地 Agent 协作工作流：意图话术、本地预览、同步与冲突规避

## 1. 协作模型：你说意图，Agent 选命令

这条工作流里人不直接敲 CLI，而是对本地 Agent 讲意图，由 Agent 调用 meoo cli 完成云端动作（F-001、F-013）。标准节奏是四拍：

```text
描述需求 → Agent 本地开发 + 云端开资源 → 本地预览自测 → 部署出链接
```

## 2. 第一拍：一句话创建项目

对 Agent 发送完整意图（F-012，逐字）：

```text
帮我用meoo做一个好看的个人主页，数据接入云服务数据库，然后一键发布到线上
```

Agent 随后自动完成：写个人主页 → 调用 meoo cli 在云端创建数据库 → 补齐缺失的后端代码 → 部署到线上 → 生成可分享链接（F-013）。人只需看终端输出等它跑完。

若项目包含服务端进程，另补一句明确部署形态（F-017）：

```text
这个项目需要服务端进程，请使用全栈应用部署。
```

## 3. 第二拍：本地预览，完整自测

AI 干完活后让它先起本地预览（话术逐字）：

```text
起个本地预览看看效果
```

浏览器自动打开 `localhost:3015`，可以在本地完整跑一遍真实业务：注册账号、提交表单、查看数据库（F-014）。

两条预览规则（F-018）：

- **静态应用通常是 `localhost:3015`；全栈应用按项目自己的方式启动**（例如框架自带端口）；
- **本地预览和部署上线是两件独立的事**——可以反复本地修改、反复预览，确认后再部署。

## 4. 第三拍：部署上线，拿分享链接

确认无误后发送（话术逐字）：

```text
部署上线
```

Agent 自动执行 `meoo deploy`，构建打包并发布到 CDN，终端输出一个可直接分享的访问链接；把链接发给朋友或发到社交平台即可使用（F-015）。静态/全栈两种形态的命令差异见 [03](03-deploy-static-vs-fullstack.md)。

## 5. 第四拍（按需）：同步回 Meoo 云端

以下云端能力**建议在代码同步到 meoo 云端后使用**（F-016）：

- 扩充数据库容量；
- 调用大模型服务（AI 问答、文生图、识图等）；
- 自定义域名；
- 自定义网页发布范围：全网可见 / 指定人员可见 / 仅自己可见。

同步话术（逐字）：

```text
帮我把代码同步到meoo云端
```

同步后可以在 meoo 官网看到该应用，并直接在秒悟里二次修改（F-016）。团队/CLI 视角的等价命令是 `meoo sandbox push`（F-055，见 [06](06-team-skill-cli-integration.md)）。

> 洞察（流程型）：默认路径是「本地为主，云端为发布目标」；同步操作则把主副本交回云端。它不是普通的代码推送，而是**编辑权切换**——同步之后云端副本才被视为可在网页端继续编辑的可信版本（见下条冲突规则）。

## 6. 坑点清单（来自官方 FAQ）

| # | 坑 | 源页口径与处置 |
|---|---|---|
| 1 | 云服务「开通成功」却连不上数据库 | **正常延迟**：命令返回成功只代表开通申请已发出，数据库实例还需时间就绪；等 2-3 分钟后让 Agent 重试（F-020） |
| 2 | 本地在改代码，网页后台也在编辑 | **有覆盖冲突风险**：本地开发期间不建议直接在网页后台发布覆盖；确需网页侧协作，先同步代码到 Meoo 云端再操作网页（F-019） |
| 3 | 纯静态页也去开通云服务 | 不必：不需要注册登录、不存数据的项目直接发布，不消耗云服务额度（F-023） |
| 4 | 余额不足中断部署 | 查 `https://docs.meoo.com/pricing`，或到 `https://meoo.com` 删除不用的项目/实例释放资源（F-027） |
| 5 | 老项目直接开迁 | 先备份代码，再让 Agent 检查项目类型、列出改造点后部署（F-028） |

> 洞察（运维型·可迁移模式）：「命令成功 ≠ 资源就绪」是异步开通类云服务的普遍模式——开通接口只承诺受理，就绪要轮询/等待。可迁移做法：开通类指令后固定等待窗口 + 重试循环，不要立刻在业务代码里发起连接并把失败误判为配置错误。
