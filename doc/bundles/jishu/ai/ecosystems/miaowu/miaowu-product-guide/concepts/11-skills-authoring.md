# 技能创建与使用：把 Prompt 沉淀为可复用 Skill

> 侧边栏归属「功能特性 → 扩展能力」。当你的提示词从「一次性」走向「流程化、要复用」，就到了 Skill 的适用域。

## 1. Skill 是什么：和 Prompt 的边界

源页定义（F-124，核心句逐字）：

> Skill（技能）是一种**模块化的能力封装机制**，它将特定领域的专业知识、操作流程与最佳实践打包为可复用的功能单元。**如果说 Prompt 是临时性、一次性的指令，Skill 则是对专业且流程化的需求说明进行结构化封装，形成可在对话或 AI 编程中复用的插件化工具包。**

机制效果：通过 Skill，系统能够像人类专家一样，针对不同任务场景动态调用相应的专业能力。源页举例：构建「视觉设计优化」Skill 后，当用户请求任何可视化输出（演示文稿、仪表盘、HTML 页面、报告、电子表格、PDF、数据可视化）时，系统自动启用该技能做专业化视觉提升（F-124）。

平台定位（逐字，F-125）：

> 秒悟 Skills 是一组可重复被利用的工具包，利用 **Meoo Skills + AI Coding** 你可以快速构建一个具备业务领域知识、使用内部 API 调用的 Meoo 原生应用。

| | Prompt | Skill |
|---|---|---|
| 生命周期 | 临时、一次性 | 可复用、可发布、可迭代 |
| 内容形态 | 一句指令 | 知识 + 流程 + 约束的结构化封装 |
| 触发方式 | 每次手写 | 系统按任务场景动态调用 / 手动@ |
| 能力边界 | 单次对话 | 可含内部 API 调用、业务知识库（F-125/F-126） |

## 2. 什么时候用：四类场景 + 一条总则

总则（逐字）：**任何时候你想扩展秒悟的能力边界，都可以用 Skill 强化**（F-126）。官方列举：

1. 使用沉淀的业务知识库、组件库、模版、脚本等，快速创建符合团队规范的 Meoo 应用；
2. 需要在**多个项目中共用**的功能片段；
3. 做测试、做报表、调用 API、调用 hsf/http 接口；
4. 自定义 SubAgent（F-126）。

判据：同一套要求第三次写进对话框（参照 [03 提示词五要素](03-web-app-build.md)），就值得沉淀成 Skill。

## 3. 构建技能三步

### 3.1 输入提示词

选中**「技能构建」**，在对话框描述想构建的技能，点按钮，秒悟即刻自动计划和执行，完成技能构建（F-127）。

**自然语言构建四原则**（F-128，逐字）：

| 原则 | 要点 |
|---|---|
| 目标清晰 | 精准定义最终效果，明确功能边界与使用场景 |
| 步骤明确 | 拆解执行流程，按顺序描述操作逻辑与规则 |
| 约束具体 | 写明异常处理、参数限制、输出格式等规则 |
| 场景完整 | 覆盖主流使用场景，明确触发条件与交互逻辑 |

**完整示例：天气查询 Skill（源页逐字，F-128）**：

> 为用户提供全国城市实时天气查询，仅支持国内地级市，不提供预报外数据；执行步骤为接收城市名称→校验城市合法性→请求天气接口→整理数据并回复；仅支持中文城市名，无结果提示重新输入，接口异常返回统一提示；支持直接问城市天气、切换城市查询，自动识别提问意图响应。

这 88 个字恰好覆盖四原则：目标（实时天气查询）+ 边界（仅国内地级市/仅中文城市名/不提供预报外数据）+ 步骤（接收→校验→请求→整理回复）+ 异常约束（无结果/接口异常）+ 触发场景（直接问/切换城市）。写技能提示词时可直接套这个密度。

**对话增强三能力**（F-129）：

- 上传图片和视频；
- **选择模型**：支持多种底层模型；源页推荐原话——「**Kimi 2.5 效果稳定，GLM-5/MiniMax-M2.5 解决复杂问题效果较好**」；
- 上传技能：支持上传本地技能包（zip 上传的市场侧入口见 [12](12-skill-marketplace.md) F-139）。

> 模型口径提示：这里的三个命名（Kimi 2.5、GLM-5、MiniMax-M2.5）与 [07 AI 服务](07-ai-service.md) 运行时 API 传参值（`kimi-k2.5`/`glm-5`/`MiniMax-M2.5`，F-074）一致，与 [02 构建器 13 模型](02-model-selection.md) 的代次命名不同——写技能选模型按本页推荐，写运行时 API 按 07 页传参值。

### 3.2 优化技能：两条路

1. **对话窗口**输入修改指令，秒悟自动修改优化；指令本身还可以点**「润色」**让 Meoo 帮你润色修改；
2. 点**「编辑」**进入编辑模式，直接对生成的技能手工编辑（F-130）。

### 3.3 生成（发布）技能

点**「发布技能」**，按需填写技能名称、简要描述、技能标签、**是否上架到技能市场**，点**「立即发布」**，即生成可用技能（F-131）。之后可以：

- 在秒悟技能商店查看和管理自己的技能；
- 在创建应用时使用该技能。

## 4. 应用技能：两种方式

口号是「**单个应用一次集成，永久使用**」（F-132）：

**方式一：从技能市场添加**
技能市场（`https://meoo.com/skills`）找到心仪技能 → 点**「添加」** → 点**「使用技能」**，即可在创建应用对话框中使用（F-132）。市场的分类与权限见 [12 技能市场](12-skill-marketplace.md)。

**方式二：对话页内集成**
对话页面点**「技能」**按钮，选择对应技能即可集成；还支持技能搜索、技能管理、去技能市场发现更多技能（F-133）。这与 [03 阶段二](03-web-app-build.md) 的「左下方点击技能添加 AI 服务」（F-040）是同一入口。

## 5. 上线后怎么迭代：五步 FAQ

源页唯一 FAQ 给出已上线技能的迭代 SOP（F-134）：

1. **数据驱动定位问题**：通过技能日志、失败案例、用户反馈，精准找到意图识别错误、答非所问、调用异常等问题，不凭感觉修改；
2. **精准修复确保稳定**：只针对问题点小范围优化，不动核心流程；明确适用范围，增加拒识规则，减少误触发；
3. **结构化与体验双重提升**：规范输入输出格式，提前校验必填信息；优化多轮对话记忆，减少重复提问，统一异常回复话术；
4. **闭环案例 + 回归验证**：所有问题案例整理成库，每次优化后跑全量测试，确保新升级不影响原有功能、不引入新问题；
5. **灰度发布安全上线**：先小范围放量，指标稳定后再全量；保留历史版本，出现问题快速回退。

> 洞察（工程型）：这五步是一套完整的生产级 ML/Agent 运维闭环——问题定位（observability）→ 最小修复（blast radius 控制）→ 结构化契约（IO 校验）→ 回归基线（case 库）→ 灰度+回滚（progressive delivery）。值得注意的是第 2 步的**拒识规则**：Skill 的质量不只取决于「该做时做对」，也取决于「不该做时别误触发」，这与天气示例里「仅支持国内地级市」的边界声明（F-128）首尾呼应——边界写在构建期，守在迭代期。

## 6. 坑点与边界

- **别用 Skill 装一次性需求**：Skill 的价值在复用与跨项目共享（F-126）；单次任务写好 [03 五要素提示词](03-web-app-build.md) 即可。
- **提示词必须写异常分支**：四原则中「约束具体」要求写明异常处理（F-128）；天气示例里「无结果提示重新输入，接口异常返回统一提示」就是范本，漏掉异常分支会把错误处理甩给运行时自由发挥。
- **模型推荐不等于 API 传参**：F-129 的命名只用于技能构建对话框；详见第 3.1 节口径提示。
- **上架是可选项**：发布时可选是否上架技能市场（F-131），私有技能不影响自己使用。
- **迭代必须有 case 库**：第 4 步要求全量回归（F-134）；上线后不收集失败案例就无法执行官方迭代法。
- **源页截图边界**：技能构建入口、润色按钮、编辑模式、发布表单、市场添加按钮均在截图中，本束只转写文字层。
