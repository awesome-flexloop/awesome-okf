# 四种 Agent 模式选型：Agent、Swarms、Plan、Design

> 秒悟构建器提供四种 Agent 模式（F-011）。模式选错不会让任务失败，但会直接影响等待时间、Token 花费与返工率。本篇给一张选型表和每种模式的适用判据。

## 1. 选型速查表

| 模式 | 一句话定位 | 什么时候选 | 你愿意付出什么 |
|---|---|---|---|
| **Agent**（复杂任务） | 深度推理，复杂需求、长任务处理（F-012） | 多文件、多技术栈；要完整可运行的系统原型；对代码质量要求极高 | 等更长时间换更好结果 |
| **Swarms**（蜂群模式） | 蜂群并发，极致速度、更快交付（F-013） | 任务简单、明确、单一；探索期快速看代码样例（Drafting）；只需解释代码或简单重构 | 速度优先，接受轻量推理 |
| **Plan**（规划模式） | 提前规划、步骤拆解、确认再执行（F-014） | 完整应用构建；编码前要审查功能、架构与实施步骤；怕黑盒跑偏返工 | 多一次方案确认环节 |
| **Design**（设计模式） | 设计探索，多方案选择，择优后实现（F-015） | 视觉导向页面；最终风格未定；不想对着一个初稿反复改 | 先花时间在多个方向间取舍 |

## 2. Agent：复杂任务的默认档

Agent 模式面向「深而长」的任务（F-012），官方给出四个适用信号：

1. 任务非常复杂，涉及多个文件和技术栈；
2. 对代码质量要求极高，不能容忍低级逻辑错误；
3. 需要构建一个完整的、可运行的系统原型；
4. 不介意等待更长的时间以换取更好的结果。

**怎么用**：从零搭一个带前后端与数据库的完整应用（如 [03](03-web-app-build.md) 所述全栈主线）时，Agent 是稳妥起点。

## 3. Swarms：蜂群并发的速度档

Swarms 蜂群模式用并发换交付速度（F-013），四个适用信号：

1. 任务简单、明确、单一；
2. 正在探索思路，需要快速看到代码样例——官方称之为 **Drafting**；
3. 只是需要解释代码或进行简单的重构；
4. 在赶时间，或者 Token 预算有限。

**怎么用**：早期思路发散、小片段试错、「这段代码什么意思」式问答用它；任务一旦长成多文件系统工程，应回到 Agent。

## 4. Plan：先方案后执行的可控档

Plan 模式把「想」和「写」显式拆成两个阶段（F-014）：

- 适用任务：涉及完整应用构建，需要明确功能、架构及实施步骤；
- 核心机制：编码前先审查整体计划，确认技术选型与逻辑无误；**确认后系统自动连续执行，无需中途干预**，兼顾效率与可控；
- 适合的人：追求过程透明，希望避免黑盒操作导致方向偏差或返工风险。

> 洞察（流程型）：Plan 模式本质上是给「对话式开发」补了一个**人工确认闸门**。纯对话模式的主要风险不是 AI 做错，而是它闷头做了 30 步后方向全错；Plan 用一次前置确认把返工成本从「整条执行链」压缩到「一页方案」。这与开放平台「全链路接入」前先定身份和流程的思路同构（见姊妹束 [开放平台总览](../../miaowu-cli-open-guide/concepts/00-open-platform-overview.md)）。

## 5. Design：先选方向再制作的审美档

Design 模式解决「初稿不满意、来回改」的问题（F-015），四个信号：

1. 还没有确定最终风格，希望先看到不同设计方向再做判断；
2. 在做视觉导向的页面，要求结果不只是「能用」，而有明确的审美、层次和完成度；
3. 不想围绕一个不满意的初稿反复修改，希望一开始就拥有可对比、可取舍的选择空间；
4. 希望先确认设计方向，再进入正式制作，减少后续返工和沟通成本。

**怎么用**：作品集、品牌官网、营销活动页等视觉权重高的任务先用 Design 出多方案，定方向后再进入制作；制作期的局部微调则交给 [05 可视化修改](05-visual-editing.md)。

## 6. 组合用法：一条任务线中的模式切换

源页没有限制一个项目只能用一种模式。结合各模式定位，官方描述的机制支持这样的自然组合（模式语义均逐字来自 F-012–F-015，组合顺序为教程性引导）：

1. **Swarms 探索**：快速 Drafting，验证点子能不能跑；
2. **Design 定调**：视觉类任务出多方案择优；
3. **Plan 定架构**：把选中的方向拆成功能、架构、步骤，确认后连续执行；
4. **Agent 攻坚**：复杂多文件实现与长任务收尾。

## 7. 坑点与边界

- **不要用 Swarms 跑系统级任务**：官方把「任务非常复杂、涉及多个文件和技术栈」明确划给 Agent（F-012），蜂群的快是为简单单一任务设计的。
- **Plan 的价值依赖你认真审方案**：确认后系统自动连续执行、无需中途干预（F-014），意味着确认动作本身是唯一闸门，方案没看清就确认等于放弃该模式的主要收益。
- **Design 不替代设计规范沟通**：它给「可对比、可取舍的选择空间」（F-015），但色板、主色调、圆角、移动端适配等具体约束仍应像 [03 提示词五要素](03-web-app-build.md) 那样显式写清。
- **模式与模型是两个维度**：本页只讲执行模式；构建器用哪个底层模型是另一项选择，见 [02 模型选择](02-model-selection.md)。
- **源页信息边界**：官方页未给模式切换的界面位置、是否支持模式间上下文继承、各模式 Token 倍率等细节，本束不脑补。
