# 网页应用构建主线：四阶段从需求到发布

> 网页应用是秒悟的主交付通道，支持 web 和 H5 页面双端适配（F-033）。官方把流程分为四阶段（F-032）：**描述功能需求 → AI 编程开发 → 预览与测试 → 应用发布**。本篇按阶段展开每一步的具体机制与官方话术。

## 阶段一：描述功能需求

### 1. 建项与发起

1. 进入秒悟首页，选择应用类型「网页应用」（支持 web 和 H5 双端适配，F-033）；
2. 在文本框用自然语言描述需求提示词；
3. 选择模型（怎么选见 [02 模型选择](02-model-selection.md)，源页也直接指向《支持模型介绍》）；
4. 点击回车键或右方箭头开始开发——秒悟会根据提示词设计应用，并**自动为项目设置名称**（F-033）。

### 2. 提示词五要素

源页给出的结构化方法（F-034，逐字）：

> **角色设定　背景上下文　核心功能　技术约束　输出规范**

官方明示：提示词的质量直接决定代码的质量和可用性（F-034）。

### 3. 三组官方正反例（逐字）

| # | ❌ 差的写法 | ✅ 好的写法 |
|---|---|---|
| 1 | 做一个减脂规划助手。 | 请帮我生成一个减脂期间每日每餐的餐普规划助手，支持用户输入身高、体重、年龄、性别后生成一份详细的减脂规划。 |
| 2 | 做一个计算出用户每日热量的功能。 | 首先计算出用户每天最低需要多少热量，减脂期间推荐摄入多少热量，其次自动规划每日餐食的热量分配、荤素搭配、菜的热量计算，最后自动计算每日的热量缺口有多少，预计减重多少斤。 |
| 3 | 界面风格要好看的。 | 界面风格应简洁现代），主色调为深蓝色，按钮要有圆角和轻微的悬停阴影效果。移动端必须完全适配。 |

三组例子（F-035）分别示范了**角色+输入输出**、**计算步骤拆解**、**视觉技术约束**三类要素的补法。注意源页原文即写作「餐普规划」、且第三组「现代」后带一个多余右括号——引用时保留原样，不代为校改。

### 4. 澄清机制

AI 收到提示词后，如果判断提示词不明确、缺失关键信息，不足以生成合适的 PRD 和产品原型，会主动发提示要求补充（F-036）。这是可选且可多轮的环节——对应 [01 Plan 模式](01-agent-modes.md) 的「先确认再执行」取向。

## 阶段二：AI 编程开发应用

收到需求后，AI 立即启动需求分析，规划开发流程和步骤，逐步生成前后端代码；代码生成完毕后自动构建并启动服务，提供可视化预览界面（F-037）。

开发期有四项配置：

| 配置 | 怎么做（源页口径） |
|---|---|
| **一键链接数据库** | 数据需要长久记录、反复使用时，在对话框逐字输入「**开启数据库，并且把前端与数据库链接**」，秒悟自动创建数据库链接（F-038）。数据库能力本体见 [06 云服务](06-cloud-services.md) |
| **基础信息修改** | 点击**左上方标题**修改项目基础信息；应用标题即显示名称，便于识别管理（F-039） |
| **上传附件（可选）** | 支持上传图片/视频/文件（F-040）；格式与 5MB/10 个限额见 [09 文件存储](09-file-storage.md) |
| **配置技能（可选）** | 左下方点击「技能」添加 AI 服务或大模型，可选择已有 AI 技能或发现更多技能（F-040）；详见 [11](11-skills-authoring.md)、[12](12-skill-marketplace.md) |

> 洞察（交互型）：网页应用阶段的所有「配置动作」都收敛到同一个对话框——建库不是点控制台按钮而是说一句话（F-038），加能力不是填表单而是@技能（F-040）。这就是主页「你说，它做」（F-005）在功能层的具体形态：**对话即控制台**。同构现象在云服务按需启用（F-068）、存储桶创建（F-115）、小程序登录配置（F-054，入口在云服务面板）上反复出现。

## 阶段三：预览与测试

1. **预览**：点击「预览」进行开发预览和效果测试；
2. **自动测试**：初步生成后端代码后会**自动生成测试用例并完成一轮单元测试**，测试通过后才可在右侧预览页面查看后端功能的实际运行效果（F-041）；
3. **调整需求**（可选）：之前某次描述有误导致不满足需求时，在左下方对话框于**当前版本基础上**调整（F-042）；
4. **版本回滚**（可选）：左侧栏目「版本历史」→点击需要恢复的版本（F-043）；
5. **版本对比**（可选）：点击「代码-对比」，在左侧版本栏选版本，点击「查看改动」，对比多个版本之间的代码差异（F-044）。

> 洞察（工程型）：「自动单测 + 版本历史 + 代码对比」把专业软件工程里的 CI 与 diff 能力压进了无代码对话流——调整需求（F-042）相当于一次新的提交，回滚（F-043）相当于 revert，对比（F-044）相当于 code review。非开发者不需要知道这些术语，但他实际在操作一套最小版本控制系统。

## 阶段四：应用发布

- 发布动作：右上角点击「**发布-立即发布**」，发布成功后会生成网址链接，可通过链接直接访问（F-045）；
- 自定义域名（**付费解锁** ⚠️ 时效以 pricing 页为准），两档：
  1. 自定义 Meoo 三级子域名；
  2. 自定义完全独立域名服务（F-045）。

域名还牵出两个进阶能力：根目录验证文件与 SEO/GEO 文件的开放规则依赖「是否绑定独立自定义域名」（见 [10 根目录文件](10-root-file-seo-geo.md)）；需要自有服务器/命令行部署时走 CLI（见姊妹束 [部署指南](../../miaowu-cli-open-guide/index.md)）。

## 全流程速查

```text
首页选「网页应用」
  → 五要素写提示词（角色/背景/功能/约束/输出规范）
  → 选模型 → 回车/箭头发起（自动命名）
  → （可选）多轮澄清
  → AI 生成前后端 + 自动构建启动
      → 对话框：「开启数据库，并且把前端与数据库链接」
      → 左上标题改信息；附件；技能
  → 自动测试用例 + 一轮单元测试 → 预览
  → 调整需求 / 版本历史回滚 / 代码-对比
  → 发布-立即发布 → 网址链接
  → （付费）三级子域名 / 完全独立域名
```

## 坑点与边界

- **提示词不要只写功能名**：三个 ❌ 例的共同问题是缺输入输出、缺步骤、缺约束（F-035）；「界面好看」这类零约束描述无法验收。
- **数据库不是默认就有**：数据要长久保存才需要开库（F-038）；不开云服务的应用本质是展示页（F-066）。
- **回滚与对比都在左侧栏**，调整需求在左下方对话框（F-042–F-044）——三个入口源页文字明确，具体界面以截图承载，本束不脑补按钮外观。
- **自动测试只承诺「一轮」**：源页口径是初步生成后自动跑一轮单元测试（F-041），不等于持续集成或完整回归；业务上线前的验收仍需自己做（小程序场景的真机清单见 [04](04-wechat-miniprogram.md) F-057）。
- **演示视频不可转写**：源页内嵌一段约两分钟的演示视频，本束只登记其存在与时间轴，不引用视频内容。
- **H5 入口已合并**：不要去找旧的独立 H5 构建入口，原首页 H5 构建能力已合并到网页应用（F-047）。
