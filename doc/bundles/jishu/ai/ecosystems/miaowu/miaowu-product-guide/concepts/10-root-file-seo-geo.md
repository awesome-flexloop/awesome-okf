# 根目录文件配置：验证文件与 SEO/GEO 文件的双轨规则

> 根目录文件配置功能可以让你在用秒悟发布的网站根路径下放置 `.txt` / `.xml` 等文件，用来完成**站点所有权验证**、**SEO 收录**、**AI 搜索（GEO）** 等配置（F-116）。
>
> 本页一句话总结：**验证文件谁都能放；SEO/GEO 文件要先有独立域名（静态部署还要去水印）。**

## 1. 三类用途与两类人群

### 1.1 适用场景（F-116）

| 场景 | 要放什么 | 干什么 |
|---|---|---|
| 站点所有权验证 | 搜索引擎/广告平台/第三方服务要求的 `xxx.txt` | 证明网站归你所有 |
| SEO 配置 | `robots.txt`、`sitemap.xml` | 让百度/谷歌等搜索引擎更好收录 |
| GEO / AI 搜索配置 | `llms.txt` | 让 AI 搜索识别站点内容 |

### 1.2 谁能用（门槛双轨，F-117）

- **所有**用秒悟发布网站的用户，都能上传普通验证文件，**无门槛**；
- 想让 SEO/GEO 文件生效的用户，**必须已绑定独立自定义域名**；静态部署还需已**开启去秒悟水印**；
- 只用平台默认域名或平台子域名（如 `myapp.meoo-app.xxx`）的用户，SEO/GEO 文件**不会对外开放**。

## 2. 场景一：上传站点验证文件（默认支持）

适用：搜索引擎、广告平台、第三方服务要求上传验证文件，如 `google-site-verification.txt`、`verify_xxx.txt`（F-118）。

三步（F-119）：

1. 从对方平台拿到要求上传的验证文件（如 `xxx.txt`）；
2. 让 Agent 把该文件放到应用根路径下；
3. 发布网站后，通过 `你的域名/xxx.txt` 即可访问，回到对方平台点验证。

> 验证文件属于普通根路径文件，**默认支持访问，不要求绑定自定义域名，也不要求去水印**（F-119 说明逐字）。

## 3. 场景二：配置 SEO / GEO 文件

### 3.1 哪些文件名属于 SEO/GEO 文件（清单逐字）

```text
/robots.txt  /sitemap.xml  /sitemap-*.xml  /llms.txt  /llms-*.txt
```

通配形态 `sitemap-*.xml`、`llms-*.txt` 也在管控范围内（F-120）。

### 3.2 开放的两个条件 + 四步操作

条件（F-121）：

1. 已绑定**独立自定义域名**（如 `www.example.com`、`app.example.com`）——注意不是平台子域名前缀；
2. 若为**静态部署**，先开启「**去秒悟水印**」。

步骤（F-121）：

1. 先绑定独立自定义域名；
2. 静态部署先开启去秒悟水印；
3. 让 Agent 把 `robots.txt` / `sitemap.xml` / `llms.txt` 放到应用根路径下；
4. 发布后通过 `你的自定义域名/robots.txt` 验证是否可访问。

> ⚠️ 如果只用平台分配的默认访问域名，**即使上传了 robots.txt、sitemap.xml、llms.txt，也不会对外开放**（F-121 注意逐字）。

## 4. 什么是「完全自定义域名」

| 算 ✅ | 不算 ❌ |
|---|---|
| 绑定自己的独立域名，如 `www.example.com`、`app.example.com` | 平台域名下的自定义子域名，如 `myapp.meoo-app.xxx` |

判定准则（F-122 逐字）：**应以「是否绑定独立自定义域名」为准，而不是只看用户是否改过平台子域名前缀。**

这与 [03 发布环节](03-web-app-build.md) 的两档域名服务对应：三级子域名（付费）只解决「名字好记」，完全独立域名（付费）才解锁 SEO/GEO 文件开放。

> 洞察（平台治理型）：为什么平台要拦默认域名上的 robots.txt？源页 Q1 给出了动机原文——「**为避免平台默认域名被用于搜索分发**」（F-123）。共享后缀的默认域名若允许任意用户声明收录/AI 抓取，会产生子域信誉污染（一个用户的内容影响整个后缀的搜索表现）。这条规则本质是 SaaS 共享域名的信誉隔离：验证权属可以（不涉及分发），开放抓取不行（涉及共享域信誉）。

## 5. FAQ 四条速查（源页原文）

**Q1：为什么验证文件能访问，但 robots.txt 不能访问？**
站点验证文件属于普通根路径文件，默认支持；`robots.txt`、`sitemap.xml`、`llms.txt` 属于 SEO/GEO 文件，为避免平台默认域名被用于搜索分发，需要绑定独立自定义域名后才支持。静态部署还需要开启去水印（F-123）。

**Q2：我已经改了应用访问域名，为什么还不行？**
确认改的是哪一种（F-123）：

- 只是改了平台子域名前缀 → 不满足条件；
- 绑定了自己的独立域名 → 满足自定义域名条件；
- 静态部署还需确认是否已去水印。

**Q3：上传验证文件需要开启自定义域名或去水印吗？**
不需要。普通站点验证文件（如 `google-site-verification.txt`）默认支持访问，不要求绑定自定义域名，也不要求去水印（F-123）。

**Q4：哪些文件被当作 SEO/GEO 文件处理？**
`robots.txt`、`sitemap.xml`、`sitemap-*.xml`、`llms.txt`、`llms-*.txt` 都属于 SEO/GEO 文件，需满足自定义域名（静态部署还需去水印）后才对外开放（F-123）。

## 6. 决策树

```text
要往站点根路径放文件
├─ 文件名是 robots.txt / sitemap(-*).xml / llms(-*).txt？
│    ├─ 是 → SEO/GEO 轨道
│    │       ├─ 已绑定独立自定义域名？─ 否 → 先去绑域名
│    │       ├─ 静态部署？─ 是 → 先开启去秒悟水印
│    │       └─ 让 Agent 放文件 → 发布 → 自定义域名/文件名 验证
│    └─ 否（普通验证文件 xxx.txt）→ 默认支持，直接放、直接发、直接验
```

## 7. 坑点与边界

- **「改过域名前缀」是最高频误判**：`myapp.meoo-app.xxx` 改什么前缀都还是平台子域名（F-122/F-123 Q2），解锁不了 SEO/GEO。
- **静态部署多一道水印条件**（F-121）：动态/静态部署形态以产品实际为准，源页未给部署形态判定方法；发现文件不开放时先查这两个条件而不是查文件内容。
- **通配文件名别想绕过**：`sitemap-*.xml`、`llms-*.txt` 明确同属管控（F-120/F-123 Q4），改名叫 `sitemap-news.xml` 不会让它变成普通文件。
- **放文件仍然是「让 Agent 放」**：源页操作路径是对话指令而非文件管理器上传（F-119/F-121）；对话即控制台主线（见 [03](03-web-app-build.md)）在根目录配置上同样成立。
- **域名付费与时效**：自定义域名服务为付费解锁（F-045），价格与档位以 pricing 页为准。
