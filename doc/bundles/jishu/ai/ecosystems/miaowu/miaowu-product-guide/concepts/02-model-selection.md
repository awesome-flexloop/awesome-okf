# 构建器 13 个支持模型选型图谱

>
> ⚠️ **先读第 5 节**：本页的 13 个模型名，与应用运行时调用 AI 服务 API 时用的 9 个传参值是**两套清单**，不能混用。

## 2. 按任务类型选（基于官方适用场景归纳）

- **复杂全栈/长周期自主开发**：Qwen3.7-Max（F-019）、DeepSeek-V4-Pro（F-022）、GLM-5.2（F-028）。
- **大规模代码库重构、读旧代码**：Qwen3.8-Flash（F-017）、Kimi K3/K2.5（F-024/F-025）、GLM-5.2（F-028）。
- **视觉驱动开发（截图转页面、界面还原）**：Qwen3.7-Plus（F-020）、Qwen3.8 系原生多模态（F-017/F-018）、GLM-5.3-Flash（F-026）。
- **高并发、低延迟、成本敏感**：Qwen3.8-Flash（1/9 训练成本，F-017）、DeepSeek-V4.1-Flash（F-021）、DeepSeek-V4-Flash（F-023）、GLM-5.3-Flash（十分之一成本，F-026）、GLM-5.2-Fast-Preview（80~100 TPS，F-029）。
- **超长文档/整库上下文**：Kimi K3（100 万，F-024）、GLM-5.3-Flash/GLM-5.2（100 万，F-026/F-028）、DeepSeek V4 双款（1M，F-022/F-023）、Kimi K2.5（200K+，F-025）。
- **流式实时交互**：GLM-5.2-Fast-Preview 的排队机制明确面向该场景（F-029）。

## 3. 三个选型判据（从官方表述反推）

1. **看上下文长度能否装下任务**：整库重构选 1M/2.8 万亿参数档；单页开发不必追求长窗口。
2. **看是否需要视觉输入**：截图改码、PDF 直读优先选「原生多模态/视觉编码器」型号（F-017/F-018/F-020/F-021/F-027）。
3. **看延迟与预算权重**：赶时间/省 Token 的高频任务选 Flash/Fast-Preview 档；这也正是 [01 Swarms 模式](01-agent-modes.md) 的配套取向（F-013）。

## 4. 技能构建场景的官方推荐

技能（Skill）构建页另有一个更小口径的模型推荐（F-129，源页原话）：

> 「Kimi 2.5效果稳定，GLM-5/MiniMax-M2.5解决复杂问题效果较好。」

这处推荐来自技能构建对话框的模型选择，命名与下节 API 传参值口径一致，可作为「写技能提示词」这一特定场景的官方建议。

## 5. 关键辨析：构建器 13 模型 ≠ AI 服务 9 传参值 ⚠️

官方文档里同时存在两张「模型清单」，名称对不齐（核验结论为 **conflicting 双源并存**，详见 [verification.md](../references/verification.md) 核验项四）：

| 维度 | 构建器模型页（本页，S3） | AI 服务页（[07](07-ai-service.md)，S8） |
|---|---|---|
| 用途 | 创建应用时选择**谁来写代码** | 应用上线后运行时**调用 AI 能力**的 API 入参 |
| 数量 | 13 个 | 9 个传参值（文本 6 + 视觉 1 + 图片 2） |
| 命名代次（例） | Qwen3.8-Flash/Qwen3.8-Max、Qwen3.7 系 | `qwen3.6-plus`、`qwen3-max` |
| DeepSeek | V4.1-Flash/V4-Pro/V4-Flash | `deepseek-v3.2` |
| GLM | 5.3/5.3-Flash/5.2/5.2-Fast-Preview | `glm-5` |
| 直接同名 | Kimi K2.5 ↔ `kimi-k2.5`（仅此一处直接对应） | 同左 |
| 独有项 | 4 厂商 13 型号 | `MiniMax-M2.5`、`qwen3-vl-plus`、`qwen-image-2.0`、`wan2.7-image` |

处置规则：

1. **在构建器里选写代码的模型** → 只看本页 13 个；
2. **在 Edge Functions 里写 API 调用** → 只能用 [07](07-ai-service.md) 表格里的 9 个传参值，把 `qwen3.6-plus` 之类写进代码不代表「选中了 Qwen3.8」；
3. 两套清单随发布节奏各自更新，官方模型页采集备注也自述「两处模型命名存在版本差异……引用时需注意时效」（F-016）。本束成文时点为 2026-10-18，`stale_after` 2027-01-18。

## 6. 坑点与边界

- **参数数字是营销材料**：2.4T、552B、896 专家、TPS、基准排名全部为厂商自述（F-017–F-029），源页未给评测方法、数据集与日期，选型时不要当作可复现实验结论。
- **短板也要看**：Kimi K2.5 页官方明确写出代码手感与精细度略逊、偶有幻觉（F-025）——这是 13 个型号中少有的自陈短板，选型权重应计入。
- **「支持 MCP」是 GLM-5.2 的模型能力**（F-028），与连接器「后续将支持接入 MCP」（F-143）是两个层面的 MCP，不要互相引证为同一功能。
- **Preview/预览版字样**：DeepSeek V4 两款标明「预览版」（F-022/F-023）、GLM-5.2-Fast-Preview 本身是预览版（F-029），生产关键路径使用前应有效果回归意识。
- **源页未给的信息**：各模型上下文窗口的完整对照表（仅部分型号明示）、价格/倍率、限流阈值（仅 GLM-5.2-Fast-Preview 提及 TPM 排队）均不在源页，不予推断。
