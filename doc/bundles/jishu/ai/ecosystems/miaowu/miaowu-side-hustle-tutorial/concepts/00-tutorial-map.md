# 教程地图与适用边界

## 1. 六步是怎么来的

源文是一篇叙事报道，不是方法论文。它给出的是一条**已经发生过的因果链**：

```text
坐进一家店 → 看见店员来回跑 → 想到"能不能合到一个应用里"
→ 做出能跑的一版 → 一家一家去问 → 一家愿意试
→ 免费用一个月 + 驻店一周 → 补齐琐碎需求 → 8 月底成交 1 万元
```

本教程把这条件链**倒过来读**，就成了可以照着走的六步。每一步都对应源文中的一个转折点，也都对应一个「如果跳过，会怎样」：

| 步 | 源文转折点 | 跳过这一步的典型后果 | 性质 |
|:---:|---|---|---|
| 0 选题 | 走进拼豆店，看见三四十张桌子和两个来回跑的店员（F-010–F-013） | 凭想象选题，做出来的东西没人用 | 源文事实 + 推断归位 |
| 1 假设 | 想到「把桌位、计时、订单放到一起」（F-018） | 有观察没切口，功能越加越散 | 推断（源文只给了一句想法） |
| 2 首版 | 2026-07 中旬开始开发；黑客松接触 Meoo 后重做（F-020、F-022） | 只做 PPT 或原型，进不了真实营业流程 | 源文事实 + 推断（范围判据） |
| 3 试用 | 跑 5 家、做话术导图、终于有一家愿试（F-028–F-034） | 做完了没人试，等于闭门造车 | 源文事实 + 推断（话术结构） |
| 4 成交 | 免费一个月，条件是反馈问题；驻店一周补需求（F-036–F-041） | 免费变成无限期义务，收不到钱也收不到需求 | 源文事实 + 推断（条款化） |
| 5 验收 | 8 月底成交 1 万元，约定一年免费维护（F-043、F-046） | 交付无边界，维护吞掉全部利润 | 源文事实 + 推断（清单与台账） |

## 2. 适用与不适用

| | 适用 | 不适用 |
|---|---|---|
| 场景 | 单店、单角色、动作重复且有明确交接的线下小微经营 | 需要多部门审批、采购流程长的组织客户 |
| 交付 | 一个能打开链接就用的小应用（F-025） | 需要私有化部署、等保、系统集成的项目 |
| 你的角色 | 一个人完成观察、构建、跑店、维护 | 需要团队分工、需要长期运维值班 |
| 目标 | 拿到**第一笔**付费，验证「有人愿意为你的东西付钱」 | 把它当可复制的规模化生意（源文自述第二、三家尚无答案，F-047） |
| 收入预期 | 一笔一次性交付 + 有限维护 | 稳定月收入（标题「月入过万」不是正文事实，正文可核为一笔 1 万元，F-045） |

## 3. 五项前置条件

| # | 条件 | 判断方法 | 不满足时 |
|:-:|---|---|---|
| 1 | **可达**：一家你能反复去的店 | 一周内能去两次，连续四周不断 | 换店；远程沟通替代不了现场观察（F-055） |
| 2 | **可观察**：店里有对外可见的重复动作 | 坐 90 分钟能记满一页动作 | 换店；没有重复动作就没有软件的立足点 |
| 3 | **有余量**：你能连续投入四周 | 每天 1–3 小时可稳定留出 | 缩小范围到「只做核心闭环」（见 03） |
| 4 | **能表达**：会用自然语言把需求说清 | 能让陌生人看懂你要做什么 | 先写一页假设卡再动手（见 02） |
| 5 | **能承受拒绝**：接受大部分店会说不 | 心理预期 ≥4 家失败换 1 家试用（F-028–F-034） | 别开始跑店，先把话术导图做出来（F-033） |

> 案例主角的实际投入：辞职后自学 AI 两个月（F-009）、7 月中旬开始开发（F-020）、跑 5 家店（F-028）、驻店一周（F-038）。这些是**她的**投入，不是准入门槛。

## 5. 与「先卖后做」的关系

库里另有一类做法叫「先卖后做」：先收定金，再动手。本案例走的是**相反顺序**——先做出能跑的版本，再去找愿意试的人（F-020 → F-043）。原因有二：

1. 她的目标是**练手**，不是最小化风险：辞职后两个月自学 AI，需要真实项目（F-009、F-049）；
2. 工具有代劳能力：服务器、数据库、部署不必自己折腾，做出第一版的成本被压低（F-024）。

因此本教程**不把顺序写成教条**。给两种起点各一句判据：

- **先做后卖**（本案例）：只有当「做出核心闭环的成本 ≤ 两个周末」时才成立；否则先用假设卡去换一次面谈。
- **先卖后做**：当你已有可展示的同类作品，或对方愿意为明确需求付定金时更稳。本教程第 02 章的假设卡即是「卖」的最小物料。
