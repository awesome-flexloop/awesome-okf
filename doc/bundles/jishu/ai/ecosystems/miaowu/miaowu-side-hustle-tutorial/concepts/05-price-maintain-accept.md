# 第 4 步：报价、维护边界与验收

> **目标**：把「免费试用」收束成「一次性交付 + 有限维护 + 变更另议」的一笔生意。
> **通过判据**：报价单、维护边界、验收单三份文件都在对方手里有一份，且维护工时开始记账。
> **性质**：报价结构、维护边界、验收清单、30 天路线为编者推断（T-037–T-043）；成交金额、维护约定、作者建议为源文事实（F-043–F-046、F-057）。

## 1. 成交信号

出现下面任意两条，就可以谈钱了（推断）：

| 信号 | 具体表现 |
|---|---|
| 使用惯性 | 店员在你不来时也照常打开；纸笔流程已经停了 |
| 归属语言 | 老板开始说「我们的系统」「你那个后台」 |
| 追加深需求 | 问你「能不能再加个 XX」，且是经营相关而非审美 |
| 主动问价 | 「这个怎么收费」「以后还能一直用吗」 |

反过来说，**如果试用一个月后店员又回到纸笔，不要谈价**——那说明它还没进入流程，谈价只会把关系变成尴尬。

## 2. 「1 万元」的正确读法

源文可核的成交事实是：2026 年 8 月底，这家店老板决定购买，金额 1 万元（F-043、F-045），双方约定一年内免费维护及需求修改（F-046）。同一篇文章还写了此前的投入：先免费用一个月（F-036）、驻店整整一周（F-038）、累计迭代数百次（F-042）。

| 读法 | 是否正确 | 说明 |
|---|:---:|---|
| 「一个月赚了 1 万」 | ❌ | 标题表述；正文是一笔一次性成交（F-045） |
| 「1 万 = 软件市场价」 | ❌ | 单案例、单店、单功能集，无功能清单与工时 |
| 「1 万 = 交付 + 一年维护」 | ✅ | 维护与需求修改包含在内（F-046） |
| 「照这个价去报价」 | ⚠️ | 只能作**结构参照**，不能作价格参照 |

把 1 万元拆成可见工作量，会得到一个更诚实的判断：它覆盖的不只是「写代码」，还包括一个月的现场试用、一周驻店、数百次小改动和一年的响应义务。**报价必须把这些算进去**，否则越接越亏。

## 3. 报价三明治

作者的建议是：报价包含什么、哪些修改需要另外沟通、后续维护要花多少时间，都该在接单时谈清楚（F-057）。把它落成三层结构：

| 层 | 内容 | 写法示例（结构示例，非价格建议） |
|---|---|---|
| **上层面包：一次性交付** | 已验收的功能集 + 数据初始化 + 一页操作卡 + 培训 30 分钟 | 「交付范围见附件清单，验收后 X 个工作日内付清」 |
| **夹心：维护期** | 明确时长、响应方式、每月工时上限 | 「交付后 12 个月内，每月不超过 N 小时的问题修复与小幅调整」 |
| **下层面包：变更另议** | 新增功能、跨店复制、硬件对接、数据迁移 | 「超出上述范围的需求，单独评估报价与排期」 |

> 关键不是数字，而是**三层都存在**。只剩第一层，维护会吞掉利润；只剩第三层，对方不敢买。

## 4. 报价单七项

```text
1. 交付范围：功能清单（逐条可勾选）
2. 交付物：访问链接、账号清单、一页操作卡、数据初始内容
3. 时间：验收日期（不写「尽快」）
4. 价格：一次性费用（含税否要写）
5. 付款节点：验收后 N 个工作日内一次性 / 或 3:7 两段
6. 维护：时长、响应方式、每月工时上限、超出如何计
7. 变更：哪些算新增、如何评估、是否影响排期
```

## 5. 维护边界

| 属于维护（含在维护期内） | 不属于维护（变更另议） |
|---|---|
| 已交付功能报错、数据错乱 | 新增功能模块 |
| 界面文案、字段顺序的小调整 | 重做界面风格 |
| 平台规则变化导致核销字段变化（如渠道改名） | 接入新的第三方平台 |
| 账号找回、密码重置 | 多店复制、多角色权限 |
| 每月固定时长内的小幅优化 | 硬件/打印机/门禁等设备对接 |
| 数据导出与备份指导 | 代运营、代录数据 |

维护台账（每次 ≥15 分钟就记一行）：

| 日期 | 事项 | 类型（修复/调整/咨询） | 耗时 | 是否在维护范围内 | 备注 |
|---|---|---|---|:---:|---|
| 09-05 | 核销渠道名称变更 | 修复 | 40 分钟 | 是 | 平台改版 |
| 09-12 | 增加「加钟」按钮 | 变更 | 90 分钟 | 否 | 已单独确认 |

台账的作用不是记账，而是**在争执发生前有据可依**，也是下一次报价的依据。

## 6. 验收清单

| 类 | 检查项 | 通过标准 |
|---|---|---|
| 功能 | 主流程 | 找桌→核销→结账 全流程一次通过 |
| 功能 | 异常路径 | 误核销可撤销；重复核销有提示 |
| 数据 | 完整性 | 40 桌真实规模数据无丢失、无串行 |
| 数据 | 导出与备份 | 能导出订单与核销记录；备份方式已交代 |
| 权限 | 角色 | 店员/老板可见范围符合约定 |
| 交付 | 链接与账号 | 店主手机可打开；账号已移交并改密 |
| 交付 | 操作卡 | 三步以内，贴在收银台 |
| 交接 | 兜底流程 | 系统不可用时回到纸笔的步骤已说明 |
| 承诺 | 维护范围 | 与报价单第 6 项一致，双方各留一份 |

## 7. 30 天路线（可按自己节奏缩放）

| 阶段 | 天 | 主要动作 | 产出 |
|---|:---:|---|---|
| 观察 | D1–D7 | 两次现场观察（含高峰）；填观察表 | 一页观察记录 |
| 假设 | D8–D10 | 写假设卡；问五个开放问题 | 假设卡 + 通过/放弃判定 |
| 首版 | D11–D16 | 定三层范围；建四张表；发布 | 可访问链接 + 操作卡 |
| 跑店 | D17–D21 | 3–5 家店；四段话术；记录拒绝理由 | 拒绝理由归类表 |
| 试用 | D22–D26 | 签试用四要素；驻店 3–5 个高峰时段 | 试用约定 + 驻店记录 |
| 成交 | D27–D30 | 出报价单；确认维护边界；验收 | 报价单 + 验收单 + 维护台账 |

## 8. 五条反模式

| 反模式 | 后果 | 纠正 |
|---|---|---|
| 无限期免费 | 对方习惯免费，价格永远开不了口 | 试用四要素写清时长与退出（见 04） |
| 只报一个总价 | 增加需求时无法拒绝 | 用三明治结构，把变更单独定价 |
| 维护不设工时上限 | 一年后被琐事拖死 | 每月固定小时数，超出另计 |
| 验收靠口头 | 各说各话，尾款难收 | 清单逐项打勾，双方签字或微信确认 |
| 把首单当模板 | 拿 1 万元套所有客户 | 只复用**结构**，价格按范围与工时重算 |

## 9. 何时停止、何时加价

| 情形 | 判断 | 动作 |
|---|---|---|
| 试用后店员回到纸笔 | 没进入流程 | 停止投入，记录原因，换店 |
| 需求超出维护上限且对方不愿付费 | 边界被侵蚀 | 按变更单报价；不接受则冻结范围 |
| 同一套功能第二家店要 | 复用价值出现 | 按「复制部署 + 培训」单独定价（源文尚无第二家，属推断，F-047） |
| 维护工时连续两月超上限 | 定价过低 | 下次续约时重算 |
