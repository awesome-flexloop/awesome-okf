# 这篇文章在讲什么：秒悟 Meoo 产品增长 Skill 包

> **一句话**：这不是一份「增长方法论」，而是一份**按产品阶段选技能**的导航 + 六个技能的使用示例（F-001、F-007、F-041）。
>
> **数据时点**：文章发布于 2026-10-15，本束采集于 2026-10-24；技能清单与平台入口会变，引用前请回技能详情页核对（F-013）。

## 1. 文章的起点：四个具体困境

文章没有从「增长理论」讲起，而是先列了四类卡点（F-006）：

| 卡点 | 读者处境 | 文章对应的技能方向 |
|---|---|---|
| 需求不确定 | 有个想法，不确定有没有人需要 | 需求先验 / 真需求诊断 / 产品评审 |
| 发布缺素材 | 应用准备上线，介绍素材还没做 | 应用首发素材包 / 官网 / 商店物料 |
| 获客无入口 | 链接发出去了，找不到试用用户 | 首批用户获取 / 冷启动方案 |
| 迭代无优先级 | 收了一堆反馈，下一版不知道先改什么 | 增长负责人 / 反馈转增长实验 |

这四类困境对应的是产品的四个不同阶段，而不是同一种「增长问题」。**文章的隐含判断是：先判断你在哪一段，再选工具**（F-009、F-010）。

## 2. 技能包的基本结构

- **共创主体**：秒悟 Meoo 联合 22 位博主共创（F-007、F-067）。
- **覆盖任务**：需求验证、产品构建、官网与商店物料、首发内容、视频与封面、用户获取、增长诊断、成本定价、反馈迭代（F-008）。
- **组织方式**：清单图按五个方向分组（F-014–F-018）：

| 分组 | 条目数 | 解决的问题 |
|---|---|---|
| 01 需求与产品构思 | 6 | 值不值得做、先做哪一版 |
| 02 产品构建与展示 | 3 | 把调研结论变成第一版、官网与商店物料 |
| 03 发布与内容传播 | 6 | 首发图文、视频、封面、热点选题 |
| 04 获客与增长诊断 | 4 | 找首批用户、定位增长瓶颈 |
| 05 商业化与反馈迭代 | 3 | 定价与付费流程、反馈转实验 |

**合计 22 条**（6 + 3 + 6 + 4 + 3）。每条只有「创作者 + 一句技能标签」，没有输入输出契约；真正的规格在平台技能详情页（F-013、F-061）。

> **两层名字**：文章用「共创博主显示名」（如阿东玩AI、职场懒人、海明Dev），平台用「技能作者 handle」（如 @张振东、@懒人哥、@黄明远）。15/22 已匹配，7 行仅文章口径；完整映射见 [01-skill-catalog.md](01-skill-catalog.md) §4（F-079–F-095）。

## 3. 三个数字的归一模型：22 → 24 → 25

文章与同库广场束里出现了 24、22、25 三个「技能数量」。它们不是三套互斥集合，而是**同一供给在不同聚合层级上的计数**：

| 层级 | 数字 | 构成 | 出处 |
|---|---|---|---|
| 文章精选清单 | **22** | 22 位共创者 × 1 行（系列族折叠为 1） | F-012、F-014–F-040 |
| 加速器集合卡片 | **24** | 22 + 空格的键盘 2 个额外平台变体（网页 / 手机 APP） | F-066、F-083、F-084、F-096 |
| 赏金广场条目 | **25** | 24 + 一起Vibe 1 条重复投稿条目 | F-073、F-075 |

**算术自检**：22 + 2 = 24；24 + 1 = 25；反向 25 − 1 − 2 = 22。

**证据强度**：`24` 的集合卡片是登录后页面，本次未直接采集；该模型与已知系列族完全自洽，标 `modeled`（核验项 23）。**本教程正文统一按 22 条精选行叙事**；引用 24/25 时注明层级。

## 4. 平台背景：Meoo 与它的技能市场

- **平台**：秒悟 Meoo 是 AI 应用创作平台，技能市场地址为 `https://meoo.com/skills`（F-063、F-078）。
- **技能市场机制**（官方文档，F-077）：支持 AI 语义搜索、全部技能/我创建的两视图、七类标签筛选、点「添加」后「使用技能」、详情页按官方/他人与自有分权限、本地 zip 上传发布。
- **使用路径**：打开对应技能页 → 安装技能 → 提供材料、说明任务（F-061）。
- **入口限制**：文章称暂仅支持电脑访问（F-063），本次未做移动端实测（核验项 22）。

这意味着：**本文是「选型层」，平台是「执行层」**。选完技能后，真正的输入格式、权限和产出仍以技能详情页为准。

## 5. 六个示例的共同形状

文章从 22 条里挑出 6 个重点技能，各配一个模拟示例（F-041）。它们的共同结构不是「聊天」，而是「交付物」：

| 技能（平台口径 / 文章别名） | 示例输入 | 交付物 |
|---|---|---|
| 需求先验｜模拟用户调研（文章：阿东玩AI） | 一句产品想法 | 需求判断 + 功能取舍 + 7 天验证计划（F-042–F-044） |
| 菜头应用首发素材包（文章：菜头Prompt.AI） | 模拟产品资料 | 6 张图文卡片 + 首发文案包（F-045–F-047） |
| 首批用户获取（文章：陈乔维Justin） | 模拟产品说明/调研/运营数据 | 用户画像 + 试用任务 + 观察指标（F-048–F-050） |
| 产品增长负责人（文章：花叔） | 模拟产品数据 | 增长诊断报告（三件优先事项 + 暂缓事项 + 复检条件）(F-051–F-053) |
| 菜菜的冲浪Skill（文章：蔡不菜（AI版）） | 产品与推广方向 | 冲浪简报 + 两套图文稿 + 工作简报（F-054–F-057） |
| 海明 App 商业化（文章：海明Dev） | 7 份模拟产品文档 + 竞品定价 | 商业化策略报告（优先问题 + 定价 + 付费墙 + 验证）（F-058–F-060） |

**六例全部是模拟数据**（F-069、F-071）。它们的价值在于示范「产出长什么样、验证看什么」，而不是提供可引用的业务结论（F-070）。

## 6. 阅读路径

1. **先选型**：[技能清单与选型表](01-skill-catalog.md)——按当前情况找到对应技能，并用「共创者 + 技能名 + @作者」三元组完成检索。
2. **看示例**：[六个重点技能实战](02-six-skills-in-practice.md)——每个技能的输入、交付物、验证信号与可复用动作。
3. **再串流程**：[从想法到第一批用户的增长闭环](03-growth-loop.md)——五阶段推进顺序、最小起步与反模式。
4. **最后看边界**：[洞察、模式与边界](04-insights-and-boundaries.md)——可迁移模式、单源限制、平台依赖与合规提醒。

> **不设 `examples/` 的原因**：技能运行依赖 Meoo 平台账号、技能安装与逐技能详情页，文章只给演示级输入输出，独立执行者无法仅凭本文复现同一结果；按可复现性两问判定为「否」（详见 [04-insights-and-boundaries.md](04-insights-and-boundaries.md) §4）。
