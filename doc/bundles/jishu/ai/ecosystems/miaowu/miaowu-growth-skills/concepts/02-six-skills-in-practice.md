# 六个重点技能实战：输入、交付物与验证信号

> **阅读前提**：以下六例全部来自文章的**模拟产品/模拟数据**（F-069）。示例中的数字只用于演示「怎么判断」，不可当作真实业务数据引用（F-070、核验项 19）。
>
> **命名约定**：标题用「平台技能名（@作者；文章别名）」。文章用共创博主显示名，平台用作者 handle，两层名字的完整映射见 [01-skill-catalog.md](01-skill-catalog.md) §4。
>
> **共同结构**：每个技能都不是「聊几句给建议」，而是收束到一个可下载/可复制的交付物；判断是否用对，看交付物是否回答了「下一步做什么、还缺什么」。

## 1. 需求先验｜模拟用户调研（@张振东；文章：阿东玩AI）

| 项 | 内容 |
|---|---|
| 触发场景 | 只有一个想法，不确定有没有人需要（F-006） |
| 输入 | 一句产品想法（F-043） |
| 主要产出 | 需求判断、功能取舍、7 天验证计划（F-042） |
| 示例输入 | 「我要做 agent 团队，用来解决办公问题。」（F-043） |
| 示例判断 | 「暂不够判」——赛道付费意愿有媒体级证据，但缺少目标用户的一手原话（F-044） |
| 功能取舍 | Must：单链路文档生成；Don't build：对外宣传 Agent 概念、一键多渠道直发（F-044） |
| 验证安排 | 7 天计划，访谈 20 位真实办公用户，拿到一手原话后再决定是否加功能（F-044） |
| 可复用动作 | 先要「判决 + 依据缺口 + 最小验证计划」，而不是要一份功能清单 |
| 边界 | 「暂不够判」是演示输出，不是对真实需求的结论（F-070） |

**为什么值得学**：它把「我觉得有人需要」拆成三件事——**当前能不能判、缺什么证据、下一步找谁验证**。这比直接生成 PRD 更能防止「凭想象做功能」。

## 2. 菜头应用首发素材包（@菜头Prompt；文章：菜头Prompt.AI）

| 项 | 内容 |
|---|---|
| 触发场景 | 准备上线，需要介绍素材（F-010） |
| 输入 | 产品链接、截图或说明（F-045） |
| 主要产出 | 内部产品价值卡 + 简短证据表、首发图文、社群和朋友圈短介绍（F-045） |
| 示例 | 模拟产品 FlowPilot AI：6 张图文卡片 + 推荐标题 + 小红书正文 + 短介绍 + 演示脚本（F-046） |
| 发布前核对 | 打开图片预览、核对文案、补上真实产品截图和体验链接（F-047） |
| 可复用动作 | 把「素材」拆成三层：内部价值卡（给自己看）、首发图文（给用户看）、短介绍（给社群看） |
| 合规提醒 | 配图标注「模拟产品素材示例 \| 图片内容发布前需核对」（F-071） |

**为什么值得学**：它不是一次性生成「一篇推广文」，而是同时产出**内部证据表**与**对外素材**。前者防止自嗨，后者才是发布物。

## 3. 首批用户获取（@anyu1888888；文章：陈乔维Justin）

| 项 | 内容 |
|---|---|
| 触发场景 | 产品能用了，缺少试用用户（F-010） |
| 输入 | 已能演示或试用的产品、用户调研与运营数据（F-048） |
| 主要产出 | 首批用户画像、沟通话术、反馈问题、七天冷启动计划（F-048） |
| 示例人群 | 有固定日报任务、手上已有 Excel 数据的电商运营负责人（F-049） |
| 示例试用任务 | 上传自己的 Excel，成功导出或复制第一份日报（F-049） |
| 验证信号 | 3 分钟内得到结果；第二天主动回来；愿意为稳定性和权限付费（F-050） |
| 可复用动作 | 把「找用户」改写成「定义一个可观察的试用任务 + 三个验收信号」 |
| 边界 | 示例人群与指标来自模拟测试，不可直接当市场结论（F-069） |

**为什么值得学**：它把「冷启动」从「去哪发链接」变成「谁来做、做什么动作、怎么判断成了」。这三个信号都可以在真实用户身上复测。

## 4. 产品增长负责人（@花叔；文章：花叔）

| 项 | 内容 |
|---|---|
| 触发场景 | 不知道下一步先做什么（F-010） |
| 输入 | 产品情况、现有数据、已做动作（F-051） |
| 主要产出 | 三件优先事项、暂缓事项、复检条件（F-051） |
| 示例定位 | 问题在「注册之后」：32,450 注册、18,760 完成首次应用创建、13,690 未完成（F-052） |
| 示例优先级 | 「帮助用户做出第一个能用的应用」列为优先关注环节（F-052） |
| 数据纪律 | 缺留存数据时明确写「留存率填不出来，不估」（F-053） |
| 可复用动作 | 先定位漏斗的**具体一级**，再排三件事；同时列出「哪些判断还做不了」 |
| 边界 | 数字为模拟数据；42.2% 等比例只验证了内部算术自洽（核验项 10–12） |

**为什么值得学**：它示范了「增长诊断」的两个硬要求——**定位到具体环节**（不是「增长不行」），以及**承认数据缺口**（不是硬估一个留存率）。

## 5. 菜菜的冲浪Skill（@caibucai；文章：蔡不菜（AI版））

| 项 | 内容 |
|---|---|
| 触发场景 | 想在小红书推广，缺少选题（F-010） |
| 输入 | 产品、已选推广方向、可用素材（F-054） |
| 主要产出 | 传播机会、选题比较、推广内容（F-054） |
| 示例稿件 A | 备选标题、封面文案、620 字正文、6 页画面安排，注明哪些可设计、哪些需实拍（F-055） |
| 示例稿件 B | 围绕「后续修改需求」5 页，第 4 页保留一次失误重试画面（F-056） |
| 对照与排期 | 两篇稿件的对照说明、效果观察方法、反馈修改建议；A 先发、B 隔 3–7 天（F-056） |
| 工作简报 | 保存目标受众、期望行动、发布账号身份、可用素材（F-057） |
| 可复用动作 | 用「工作简报」冻结背景，用「A/B 对照」而非单篇赌爆款 |
| 边界 | 不保证爆款、需手动发布；示例为模拟产品（F-054、F-069） |

**为什么值得学**：它把「内容推广」做成可复用资产：**简报**减少重复交代，**两套稿件**提供对照，**效果观察方法**让下一轮能改。

## 6. 海明 App 商业化（@黄明远；文章：海明Dev）

| 项 | 内容 |
|---|---|
| 触发场景 | 移动 App 有人用，付费少（F-010） |
| 输入 | 开发中或已上线 App 的项目材料、可核实竞品信息（F-058） |
| 主要产出 | 商业化评估、付费转化优化建议（F-058） |
| 示例优先问题 | 注册后未完成关键操作就离开、缺少免费体验、企业版功能与价格不匹配（F-059） |
| 示例方案 | 免费版 + 分档定价；个人/企业两条上手路径；付费提示时机（F-060） |
| 验证配套 | 实施清单、测试场景、观察指标（F-060） |
| 可复用动作 | 按「先改哪里 → 怎么收费 → 怎么验证」三段推进，不先谈定价数字 |
| 边界 | 示例中的 29/199/9999 元为模拟产品设定（核验项 14） |

**为什么值得学**：它没有直接给「定价表」，而是先判断**付费卡在哪**（价值未体验、权益不匹配），再设计付费墙与验证指标。

## 7. 六例对照总表

| 技能（平台口径） | 阶段 | 关键输入 | 核心交付物 | 验证信号 | 可复用点 |
|---|---|---|---|---|---|
| 需求先验｜模拟用户调研 | 需求 | 一句想法 | 判断 + 取舍 + 7 天计划 | 是否拿到一手原话 | 先判「能不能判」 |
| 菜头应用首发素材包 | 发布 | 链接/截图/说明 | 6 图 + 文案包 + 证据表 | 发布前核对项是否补齐 | 内外两套素材 |
| 首批用户获取 | 获客 | 产品说明/调研/运营数据 | 画像 + 话术 + 7 天计划 | 3 分钟结果、次日回访、付费意愿 | 试用任务可观察 |
| 产品增长负责人 | 诊断 | 产品数据 | 三件优先 + 暂缓 + 复检 | 漏斗卡点是否定位到一级 | 缺数据不硬估 |
| 菜菜的冲浪Skill | 传播 | 产品 + 方向 + 素材 | 简报 + 两套图文稿 | 对照后的反馈改法 | 简报 + A/B |
| 海明 App 商业化 | 商业化 | 产品文档 + 竞品 | 评估 + 定价 + 付费墙 + 验证 | 实施清单与指标 | 先卡点后定价 |

> **共性结论**：六个技能的价值都不在「生成一段话」，而在**把不确定性转成下一步可执行、可验证的动作**。这也是判断一个 Skill 是否值得安装的最快标准（见 [04-insights-and-boundaries.md](04-insights-and-boundaries.md)）。
