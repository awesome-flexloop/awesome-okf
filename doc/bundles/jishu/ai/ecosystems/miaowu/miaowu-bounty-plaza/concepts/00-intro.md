# 秒悟应用赏金广场定位：平台、页面与共创计划

本束解读一份公开网页「应用赏金广场」。要读懂它，先要回答三个问题：它属于哪个平台、这个页面本身在讲什么、以及它属于哪一类知识。

## 1. 平台是什么：秒悟 Meoo

- 秒悟 Meoo 是**阿里云推出的云端 AI 应用创作平台**（F-001）。
- 该平台归属由 5 个独立来源一致确认——官方文档站、阿里云官方页、高校机构通知、媒体与第三方产品目录，**非单源**（F-001）。
- 官方文档站 `docs.meoo.com` 的表述是：秒悟 Meoo「就像一个『会编程、懂设计、自部署的全能 AI 伙伴』」，用户**无需搭建环境、无需单独采购服务器资源、无需编写代码**（F-003）。
- 秒悟 Meoo 的官方平台入口为 `https://meoo.com/`（F-002）。

> 归属性说明：官方文档站正文并未直接出现「阿里云」字样，平台归属依靠上述多源交叉确认（F-001）。

## 2. 页面是什么：应用赏金广场

- **页面主标题**：应用赏金广场（F-011）。
- **副标题**：`AI Builder Growth 共创计划：从 Vibe Coding 作品到真实收益`（F-013）。
- **一句话主张**：`Meoo + Skill 帮你把想法变成有人用的“产品”。`（F-014）。
- **三个入口**（F-016、F-017）：
  - `使用 Meoo` → `https://meoo.com/`（F-016；官方平台入口亦见 F-002）；
  - `提交 Skill，参与共创计划` → **无独立链接目标**（仅有 CTA 文本，源页未明示目标页）（F-016）；
  - `查看更多技能` → `https://meoo.com/skills`（F-017）。

随后即是以**七个增长阶段**编排的 25 条技能条目（详见 [01-growth-stages.md](01-growth-stages.md) 与 [02-skills-catalog.md](02-skills-catalog.md)）。

### 关于「查看更多技能」指向的技能市场

- `查看更多技能` 指向 `https://meoo.com/skills`，是一个**技能市场列表页**，与本节的事件页属于**不同口径**（F-005、F-009）。
- 技能市场页按**区块分类**（通用 / 开发 / 测试 / 文档 / 数据 / 效率）展示技能，每条带**累计使用量计数**（如 25,399 / 37,066）（F-006、F-007）。
- 与之相对，主源事件页按**七阶段增长链路**分类，每条**无**使用量计数（F-009）——两页同主题条目并存但署名不同，本束**不作同一性断定**（F-010）。

## 3. 页面形态特征

- **状态指示**：`LIVE · 00:00:00`（F-012）。其计时语义（累计 / 倒计时 / 占位）**源页未明示**，列入缺口（见 [source-ledger.md](../references/source-ledger.md)「放弃核验清单」）。
- **条目版式**：固定为 `编号` / `阶段标签` / `技能名@创作者` / `一句话说明` 四要素（F-018）。
- **编号样式**：三位补零（`01`、`010`、`025`），编号从 `01` 连续到 `025`（F-019）。
- **阶段标签**：七个阶段名称及其页面顺序为**源页原始口径**（F-015），本束不作改名或重排。

## 5. 本页属于索引型知识，而非教程型知识

- 25 条条目**每条只给一句说明**（F-021–F-045），页面**无输入输出契约、无使用步骤、无案例**；唯一操作指引就是三个 CTA（F-016、F-017）。
- 因此本束的合理定位是**导航与结构解读**，不设 `examples/`：读者读完本页**不能直接使用任何技能**，**一跳后仍需平台侧详情**（见 [source-ledger.md](../references/source-ledger.md)）。
- 源页**未明示**、本束一律标注为缺口、不做推断补全的项目（见 [source-ledger.md](../references/source-ledger.md)「放弃核验清单」）：
  1. 赏金金额 / 奖励规则 / 分成比例；
  2. 结算与分成规则；
  3. 投稿（提交 Skill）的审核流程、门槛与周期；
  4. 各 Skill 的内部实现、输入输出契约与使用方式；
  5. 各 Skill 的累计使用量 / 安装量（广场层无计数）；
  6. `LIVE · 00:00:00` 计时语义。
