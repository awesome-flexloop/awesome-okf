# 成交条款、洞察与可迁移模式

> **一句话**：成交不是终点——这笔交易里**含一年内免费维护及需求修改**（F-046），而「能不能卖给第二家、第三家」源文**没有给出答案**（F-047）。本节把条款边界、五条洞察与两个可迁移模式说清。

| 项 | 内容 | 出处 |

> **⚠️ 两个易被忽略的口径**：

## 3. 五条四元组洞察（现象 / 根因 / 影响 / 建议）

> 洞察为**执行者解读**，非源文原话；每条均标注支撑事实。

### 洞察 1：需求可以来自「观察他人工作的困难」，而不必先有一个生意假设

- **现象**：她起初没有客户，也没规划做拼豆店生意，只是留意到店员的困难（F-018、F-019）。
- **根因**：现场的高频重复动作（反复确认、跨系统切换）是需求的可见信号，先于任何商业假设出现（F-014–F-017）。
- **影响**：这种起点降低了「想不出做什么」的启动成本，但**不保证需求成立**——文章明确承认有的店已有合适系统（F-053）。
- **建议**：把观察与验证分开——先观察、再找人核对（F-054–F-056）。

### 洞察 2：工具层降摩擦 ≠ 业务闭环

- **现象**：Meoo 解决了界面、服务器、数据库、部署与交付链接（F-023–F-025），但跑店、被拒、谈价、维护仍由她本人完成（F-028–F-034、F-046、F-057）。
- **根因**：工具降低的是**实现与交付层**摩擦，业务层（找客户、定价、长期责任）无对应替代（F-024、F-025、F-057）。
- **影响**：把「会做应用」误当成「能接单」会系统性低估投入（F-050）。
- **建议**：以「有没有人愿意试、愿不愿意付费」为业务层验证口径，而非以「应用能不能跑」为完成标准（F-056）。

### 洞察 3：免费试用的关键不在「免费」，而在**交换条件**

- **现象**：她提供免费一个月，但要求老板反馈哪里不好用、还缺什么（F-036、F-037）。
- **根因**：免费时长给了老板判断价值的时间，而反馈条件把「试用」变成**双边的信息交换**（F-036、F-037 的意图）。
- **影响**：没有交换条件的免费试用只消耗资源；有条件的试用同时产出需求清单（F-039–F-041）。
- **建议**：免费试用前先约定可执行、可回传的反馈方式（F-037）。

### 洞察 4：成交条款含隐性成本，报价口径要在接单时谈清

- **现象**：交易含一年内免费维护及需求修改（F-046）。
- **根因**：门店类应用的功能会随经营场景持续变化（在线预约、仪表盘、套餐设置均来自使用后反馈，F-039–F-041），维护不是可选项。
- **影响**：若报价只算开发、不算维护工时与修改范围，成交反而可能变成亏损（F-057）。
- **建议**：接单时明确「报价含什么 / 哪些修改另议 / 维护工时如何计量」三件事（F-057）。

### 洞察 5：单源案例证明「存在」，不证明「可复制」

- **现象**：文章发布账号即 Meoo 官方公众号（F-002）；能否卖给第二、三家无答案（F-047）；主角已转向 AI 硬件（F-048）。
- **根因**：案例为平台方自述、无第三方凭证，且样本量为 1。
- **影响**：任何「月入过万可复制」的读法都超出源文声明。
- **建议**：把本束当**存在性证据**使用，落地前自行完成需求验证（F-054–F-056）。

## 4. 两个可迁移模式

> 模式为**执行者提炼**；迁移前须替换场景相关项，并按洞察 5 自行验证。

### 模式 A：观察式需求发现法

- **触发条件**：想用 AI 做点东西，但不知道做什么、卖给谁。
- **核心步骤**：
  1. 选一个你**接触得到**的真实场景（本案例：常去的拼豆店，F-010、F-054）；
  2. 用现场问题清单观察：谁在日常反复花时间？哪些信息总被反复问？哪些步骤一忙就出错？（F-051、F-052）
  3. 归纳出一个「能不能把 X 和 Y 放到一起」的合并式假设（本案例：桌位+计时+订单，F-018）；
  4. **看对方实际怎么操作**，再决定要不要做一版给他试（F-055）。
- **反模式**：先定「做一门生意」再找需求；跳过找人核对直接开发全功能。
- **迁移验证**：本模式在案例中完成了「观察 → 假设 → 找人验证」的前半段（F-010–F-018、F-054–F-056）；后半段（成交）依赖试用与迭代（模式 B）。

### 模式 B：免费试用换反馈的转化法

- **触发条件**：应用已能跑，但拿不到订单。
- **核心步骤**：
  1. 主动跑多个潜在客户，预期并分类失败（本案例：5 家 → 三类失败，F-028–F-031）；
  2. 为重复的沟通动作做**可复用材料**（本案例：话术导图，F-033）；
  3. 用**免费时长 + 明确交换条件**换取真实使用（本案例：免费用一个月 + 反馈不足，F-036、F-037）；
  4. **到现场收集需求**并按真实使用迭代（本案例：驻店一周、补三项功能、数百次迭代，F-038–F-042）；
  5. 在接单时谈清报价范围与维护责任（F-057）。
- **反模式**：把免费试用做成无条件赠送；只做远程反馈不上现场；成交后不界定维护边界。
- **迁移验证**：案例中该模式完成了从「1 家愿试」到「付费成交」的闭环（F-034、F-043、F-045），但**样本量为 1**，无重复验证。
