# 事件驱动、异步交互与恢复

消息、审查评论或 CI 结果可以在任务运行期间到达。导读把事件驱动、异步交互、状态与执行环境分离以及 Watchdog 一并列入架构讨论。[F-011 至 F-013](../references/facts.md)

## 从请求到事件

Pandaily 转述的事件来源包括聊天、邮件、代码审查和 CI，并称事件先经确定性代码过滤，再由模型处理。[F-027](../references/facts.md) 确定性代码指按明确规则处理数据的程序；它与模型根据语境判断意图承担不同职责。

CI 指持续集成，例如提交后自动运行测试。线程指围绕同一主题的一串消息或评论。状态是可记录的任务进度与结果；执行环境是工具实际运行的机器或进程。外部副作用指发评论、改文件等已经改变外界的动作，不会随着会话重启自动撤销。

下表是教学分析，不是公开原型的字段定义。

| 需要区分的事 | 原因 | 设计时可追问 |
|---|---|---|
| 事件被收到 | 收到不代表允许执行 | 身份与授权是否已检查 |
| 事件被归属 | 同一用户可能有多个任务 | 是否关联正确线程和任务 |
| 事件被处理 | 处理可能失败或重复 | 是否留有结果和重试记录 |
| 结果被通知 | 成功执行不等于用户已知 | 是否只在需要判断时打断用户 |

异步交互允许新信息与长任务同时存在，但新信息何时影响正在运行的任务仍须由具体实现决定。本次没有直接证据说明原型的抢占、取消、队列或优先级规则。

## 状态与执行环境分离

来源讨论把计算、状态与执行环境分开；Pandaily 将其解释为 Agent 可在云端保持在线，同时接触用户设备。[F-012](../references/facts.md) 这属于架构描述，不能推定所有工具都会在本地运行，或所有状态都会自动持久化。

执行者分析：恢复至少要区分任务目标、已完成步骤和外部副作用。例如“提交评论已经成功，但确认消息尚未写入状态”属于需要防重复的问题。重启会话本身不会撤销已经发出的评论，也不能证明任务安全恢复。

## Watchdog 能检查什么

Watchdog 是来源中的外部进度与异常检查机制。[F-013](../references/facts.md) 从教学角度，它可以与 Worker 自述分开理解：Worker 声称在工作，并不等于外部可观察结果在推进。

但“有 Watchdog”不等于自动拥有正确恢复。下列问题需要实现证据：它依据什么判定停滞、是否误判长耗时步骤、能否取消任务、重试是否有上限、何时请人判断。本包未运行原型，不给出相关默认值。

## 主动性的授权边界

媒体提到内部系统会在讨论问题时尝试后台复现和修复。[F-020](../references/facts.md) 这不代表任何群消息都授权了 Agent 修改仓库。

建议把主动行为拆为读材料、形成建议、执行可撤销操作和发布外部结果，并分别获得授权。此为本教程的安全建议，不是已经确认的产品权限模型。继续阅读[评估与安全](03-evaluation-and-safety.md)。

授权应绑定授权人、任务、资源范围和有效期；执行、重试与恢复前重新校验。撤销授权后不得继续沿用旧许可，是否终止在途任务需有明确处理规则。

贯穿示意，非原型行为：错别字修复请求先被派工；同线程补充消息提供正确写法；完成后撤销订阅；迟到消息需重新确认是否重开任务。若发评论后中断，恢复时先查已有评论再决定是否重发。检验题：重启成功是否足以证明没有重复发布？答案是否定的，仍需外部结果证据。
