# 效果评估与安全边界

Pandaily 转述了初步合成负载实验及额外缓存 token 开销，但本次未核读原始实验。其数字仅登记于 [F-028 至 F-029](../references/facts.md)，不作为真实工作提效结论。

合成负载是人为构造的测试请求集合，未必代表实际团队工作。token 是模型处理文本的计量单元；缓存 token 涉及重复上下文复用，其费用须按具体服务计价，不能直接等同人的工时。

## 三类成本分别观察

下表是本教程提出的评估框架，未在 Super-agent 上实测。

| 观察对象 | 建议记录 | 能回答的问题 |
|---|---|---|
| 任务结果 | 验收通过、失败、重做与完成时间 | Agent 是否完成了工作 |
| 系统协调 | 派工次数、事件重复、推理费用、等待与恢复 | 并行运行的额外代价是多少 |
| 人的投入 | 补背景、追问、被打断与审查结果的时间 | 用户是否真的少做了协调工作 |

仅测任务结束时间，不能证明人的负担降低。仅测 token 费用，也不能代表结果质量或人的效率。公平比较还应固定任务、模型、工具权限和验收口径；真实团队与合成负载需分别报告。

常驻方案还应记录空闲监听、计算、存储日志、网络工具和失败重试费用，分别核算单任务与周期总成本。预算到限后由预先指定的责任人决定停止或继续，不能让后台重试无限追加开销。

## 实验数字怎样读

检查实验前先问：任务从哪一刻开始计时，什么结果算完成，失败是否计入，基线使用哪些工具，缓存成本如何计价，数据可否复验。二手报道不能替代这些条件。

F-030 中的“可跟踪会话数量”同样未核对研究依据，不作为人类注意力常数或默认并发上限。具体团队的承载量应通过真实观察判断。

## 开放问题

Global Times 报道列出扩展性、长期记忆、Agent 间通信和云端访问本地设备的安全隐私问题。[F-022](../references/facts.md)

执行者分析：Router 承载更多任务时，信息汇总与派工可能形成新瓶颈；长期记忆还需要纠错、过期和权限分区；Agent 间互通需要追踪消息来源；云端工具访问本地设备则涉及凭证和外部输入的信任边界。以上是问题展开，不是已发现的源码漏洞。

## 运行前的边界

不要按本包自行启动常驻进程、交出本地凭证或给予自动发布权限。部署前应直接核仓库、版本、LICENSE、依赖、允许用户与工具权限，并先在无敏感数据环境中验证。

凭证不得默认进入模型上下文、共享记忆或日志。工具访问应按最小权限与必要有效期配置，并准备撤销、轮换和停止通道。读取公开文档不应默认要求用户交出凭证；本次只是现有 CLI 通道未授权，不代表公开材料必须登录才能读。

导读的“非产品功能介绍”与媒体的“非生产就绪”提醒均已保留。[F-016、F-021](../references/facts.md) 即使日后确认研究原型采用开放许可证，也不代表已经完成安全评估。
