# 照做：入驻开放平台与资质认证

> 适用场景：你要以**个人**或**企业/组织**身份入驻 WorkBuddy 开放平台并完成资质认证。本文据「入驻开放平台」页（D2，`https://open.workbuddy.cn/docs/onboarding`）的七节内容（个人认证 / 管理员实名认证 / 企业认证 / 上传企业信息 / 完成企业验证 / 认证结果与规则）编成演练；概念归纳见[入驻开放平台与三档身份认证](../concepts/01-onboarding-and-qualification.md)。本篇为**原创演练**，不镜像原文。
>
> 信源为厂商（腾讯 WorkBuddy）自有开发者文档**单源**；本文**未在本机实跑**任何注册、认证、人脸核身或提交审核流程。文档未写明处一律标「**官方未给**」。

## 前置条件

- **入驻入口**：文档八步快速开始第 1 步为「注册并入驻开放平台」（F-005）；第 2 步为「完成开发者或企业资质认证」（F-006）。开放平台面向 WorkBuddy 生态业务，开发者入驻并通过相应资质审核后即可在开放平台进行业务开发管理（F-001、F-002）。
- **认证档位（三档并列）**：个人认证（F-039、F-040、F-041、F-042、F-043）、管理员实名认证（F-022）、企业认证（F-017、F-018）。三档适用主体各异，**不得互相替代**。
- **材料·个人认证**：本人中国大陆二代居民身份证；已完成实名登记的本人手机号；可以正常接收验证码的邮箱；可以正常完成人脸识别的手机（F-039）。
- **材料·管理员实名认证**：本人中国大陆二代居民身份证**号码**；已完成实名登记的本人手机号；可以正常接收验证码的邮箱；可以正常完成人脸识别的手机（F-022）。〔措辞差异照抄：个人认证写「身份证」，管理员实名认证写「身份证**号码**」〕
- **材料·企业认证**：营业执照、企业名称、统一社会信用代码、法定代表人姓名（供 OCR 识别，F-023）；选择企业法人实名认证时另需**法人身份证号码**（F-025）。
- **环境/设备**：能接收验证码的邮箱、可正常完成人脸识别的手机（F-039、F-022）；企业法人实名认证需**法定代表人本人**配合扫码人脸核身（F-019）。
- **权限门槛**：一个身份证全平台只能认证一个个人主体（F-042）；每个账号最多创建一个个人主体（F-043）；每个账号最多认证 10 个企业主体（F-028）；同一家企业最多可被 50 个账号分别认证（F-029）。

> 以上前置条件均**未在本机实跑，依据官方文档（F-001、F-002、F-005、F-006、F-017、F-018、F-019、F-022、F-023、F-025、F-028、F-029、F-039、F-040、F-041、F-042、F-043）**。

## 操作步骤

> 本段全部步骤**未在本机实跑**——本束不注册账号、不申请认证、不做人脸核身、不提交任何材料。

1. **进入入驻并选定认证档位**：注册并入驻开放平台（F-005），按自身主体类型选择资质认证档位（F-006、F-017）。〔**未在本机实跑，依据官方文档 F-005、F-006、F-017**〕
2. **个人认证**：按材料清单准备四项材料（F-039）→ 填写必填信息（F-040）→ 对照重要规则自检（F-041、F-042、F-043）。〔**未在本机实跑，依据官方文档 F-039、F-040、F-041、F-042、F-043**〕
   - **E2 口径提示（原文并列，照抄不合并）**：个人认证「必填信息」原文同时列出 **「开发者真实姓名」** 与 **「真实姓名」**，另含身份证号码、手机号码、邮箱地址（F-040）。**原文如此并列，未合并、未推断哪个是笔误；需判定请以官方页面为准。**
3. **管理员实名认证**：按材料清单准备四项材料（F-022），作为企业主体管理员的实名核验。〔**未在本机实跑，依据官方文档 F-022**〕
4. **企业认证·选择认证方式（三选一）**：企业法人实名认证（企业未在支持的第三方平台完成认证且法人可配合验证）/ 腾讯云账号快速认证 / 微信公众号·小程序账号快速认证（F-018、F-019、F-020、F-021）。〔**未在本机实跑，依据官方文档 F-018、F-019、F-020、F-021**〕
   - 三种方式**并列可选**，文档**未给**「何者优先 / 何者更快」的排序——**官方未给**。
5. **上传企业信息（5 步）**：① 上传营业执照 → ② 系统通过 OCR 识别企业名称、统一社会信用代码和法定代表人姓名 → ③ 核对系统识别结果 → ④ 填写对外展示的开发者昵称 → ⑤ 完成开发者昵称命名规范校验（F-023）。〔**未在本机实跑，依据官方文档 F-023**〕
   - 如修改企业名称、统一社会信用代码等**关键识别字段**，系统可能要求进行**二次确认**（F-024）。
   - 选择「企业法人实名认证」时，还需填写法人身份证号码，并完成**企业名称、统一社会信用代码、法人姓名、法人身份证号四要素核验**（F-025）。
6. **完成企业验证**：按所选方式收尾——企业法人实名认证由法定代表人本人扫码完成人脸核身（F-019）；腾讯云账号快速认证跳转腾讯云完成授权、校验营业执照主体与腾讯云已实名主体是否一致（F-020）；微信公众号·小程序账号快速认证跳转对应平台完成授权、校验营业执照主体与第三方已实名主体是否一致（F-021）。若第三方主体与营业执照主体**不一致**，可核对并修改信息后**重新发起认证**（F-026）。〔**未在本机实跑，依据官方文档 F-019、F-020、F-021、F-026**〕
7. **核对认证结果与规则**：认证成功后，系统生成**企业主体**，完成认证的账号成为该企业主体的**超级管理员**（F-027）；每个账号最多认证 10 个企业主体（F-028）；同一家企业最多可被 50 个账号分别认证（F-029）；不同账号认证产生的主体、开放资产和其他资产**相互独立**（F-030）。〔**未在本机实跑，依据官方文档 F-027、F-028、F-029、F-030**〕
8. **失败时按「认证失败处理」表处置（八类场景）**：下文八类场景逐一对照原文「常见提示」与「处理方法」处置。〔**未在本机实跑，依据官方文档 F-031 ~ F-038**〕

   | 场景 | 常见提示 | 处理方法 | 事实编号 |
   | --- | --- | --- | --- |
   | 三要素不一致 | 实名信息核验不通过 | 检查姓名、身份证号和手机号是否属于同一人；达到页面尝试限制后按提示稍后重试 | F-031 |
   | 手机号未实名 | 手机号未完成实名或与身份证不匹配 | 使用本人已实名且与身份证信息一致的手机号 | F-032 |
   | 人脸比对不通过 | 人脸与实名信息不匹配 | 确认由本人操作并保持光线充足；达到页面尝试限制后按提示重试 | F-033 |
   | 身份证已被占用 | 该身份证已在其他账号完成个人实名 | 使用原认证账号登录；一个身份证只能认证一个个人主体 | F-034 |
   | 营业执照识别失败 | 未能识别营业执照信息 | 上传清晰、完整、无反光的照片，或按页面要求手动补填 | F-035 |
   | 企业四要素不一致 | 企业信息核验不通过 | 检查企业名称、信用代码、法人姓名和身份证号；达到页面尝试限制后按提示稍后重试 | F-036 |
   | 第三方主体不一致 | 营业执照与第三方已实名企业不一致 | 确认使用同一企业的腾讯云或微信开放平台账号后重新授权 | F-037 |
   | 证件类型不支持 | 当前证件类型暂不支持 | 当前仅支持中国大陆二代居民身份证，港澳台及外籍证件暂不支持 | F-038 |

> 上 8 步均**未在本机实跑，依据官方文档（F-005 ~ F-038）**；条目名与门槛数字一律取自 F 表，未凭空补全。

## 结果判据

- **生成企业主体**：认证成功后系统生成**企业主体**，完成认证的账号成为该企业主体的**超级管理员**（F-027）——文档描述的判定迹象。
- **获得开发资格**：入驻并通过相应资质审核后，即可在开放平台进行业务开发管理（F-002）——文档描述的前置结果。
- **计数边界可核对**：账号名下企业主体数 ≤ 10（F-028）；同一企业被认证账号数 ≤ 50（F-029）；名下个人主体数 ≤ 1（F-043）。
- **失败可观测提示**：八类场景各有「常见提示」文案可对照，如「实名信息核验不通过」（F-031）、「未能识别营业执照信息」（F-035）、「当前证件类型暂不支持」（F-038）。
- **本机无法闭环**：认证/审核结果**由平台判定**，以上判据取自文档描述而非本机实测；本束未注册、未认证、未提交任何材料，**不得**据此写成「已完成审核 / 功能已验证可用」。

## 限制与边界

- **证照与姓名**：当前仅支持中国大陆二代居民身份证，姓名须使用证件上的中文姓名（F-041）；港澳台及外籍证件暂不支持（F-038）。
- **个人主体唯一性**：一个身份证在全平台只能认证一个个人主体（F-042）；该身份证已通过其他 WorkBuddy 账号完成个人实名认证的，不能在当前账号重复认证（F-042）。
- **计数上限**：每个账号最多创建 1 个个人主体（F-043）、最多认证 10 个企业主体（F-028）；同一家企业最多可被 50 个账号分别认证（F-029）。
- **尝试次数**：文档三处写「达到页面尝试限制后按提示稍后重试」（F-031、F-033、F-036），但**未给**尝试次数上限的具体数字——**官方未给**。
- **企业认证完整材料清单**（除已列项外，如哪些主体资质文件）——**官方未给**（[核验报告](../references/verification.md) 第五节第 7 项）。
- **审核时长**：D2 页**未给**认证/资质审核时长——**官方未给**（[核验报告](../references/verification.md) 第五节第 3 项；除 D9 分享应用给出「7 个工作日」外，其余各类审核时长均未给出）。
- **未采集页**：侧栏 `service-categories-individual`、`service-categories-enterprise`、`developer-profile`、`legal-basis-and-examples`、`contact`、`operations-data`、`api-token` **本次未采集，仅登记入口**，不得据名称推断与认证相关的字段或功能（[页级采集与覆盖台账](../references/source-manifest.md)）。
- **口径纪律**：文档未写明处一律标「**官方未给**」；本束**未在本机实跑**，不出现「已上线 / 已 GA / 已完成审核 / 功能已验证可用」类替官方宣布的表述。
