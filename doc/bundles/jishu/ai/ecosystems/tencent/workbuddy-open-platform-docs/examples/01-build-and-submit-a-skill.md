# 照做：构建并提交一个技能

> 适用场景：你已完成入驻与资质认证（见[入驻开放平台与三档身份认证](../concepts/01-onboarding-and-qualification.md)），要**从零搭建一个技能包**、走完提交到技能市场被用户安装调用的链路。本文据「技能」页（D4，`https://open.workbuddy.cn/docs/skill`）编成演练；概念归纳见[技能：开发与市场](../concepts/02-skill-development-and-marketplace.md)。本篇为**原创演练**，不镜像原文。
>
> 信源为厂商（腾讯 WorkBuddy）自有开发者文档**单源**；本文**未在本机实跑**任何创建、打包、提交或上架流程。文档未写明处一律标「**官方未给**」。

## 前置条件

- **身份门槛**：技能是开放平台支持开发的 5 类业务类型之一（技能、专家、专家团、连接器、外部应用接入）（F-003）；需先入驻并完成资质认证（F-002、F-006）——认证三档见[入驻开放平台与三档身份认证](../concepts/01-onboarding-and-qualification.md)。
- **技能包形态**：一个以技能名命名的目录 `{skill-name}/`，其中 `SKILL.md`（技能定义）**必须**，`references/`、`scripts/`、`templates/` **可选**（F-079）。
- **`SKILL.md` 形态**：**YAML frontmatter + Markdown 正文**（F-080）。
- **本地环境**：可创建目录、编辑 YAML 与 Markdown 文本的编辑器；可将技能目录打包为 **zip**（提交以 zip 包形式进行，F-078）。
- **创建入口**：技能市场右上角【添加技能】-【创建技能】（F-076）。
- **流程参照**：文档八步快速开始第 5 步为「在测试环境中进行调试和验证」（F-009）、第 6 步为「提交平台审核」（F-010）。

> 以上前置条件均**未在本机实跑，依据官方文档（F-002、F-003、F-006、F-009、F-010、F-076、F-079、F-080）**。技能页（D4）未给出技能专属的「本地调试」步骤，该环节以 D1 八步快速开始为据。

## 操作步骤

> 本段全部步骤**未在本机实跑**——本束未创建技能、未打包、未提交审核、未上架。

1. **进入创建入口**：点击技能市场右上角【添加技能】-【创建技能】（F-076）；点击创建后**跳转进入对话**，补全创建技能的提示词，开启创建（F-077）。〔**未在本机实跑，依据官方文档 F-076、F-077**〕
2. **搭建技能目录结构**：按 `{skill-name}/` 建目录，原文目录树**逐字**如下（F-079）：
   ```
   {skill-name}/
       ├── SKILL.md              # ★ 技能定义（必须）
       ├── references/           # 参考资料（可选）
       │   ├── api-spec.md       #   API 规范、字段类型等
       │   └── examples.md       #   示例数据
       ├── scripts/              # 可执行脚本（可选）
       │   ├── fetch-data.js     #   数据获取脚本
       │   └── transform.py      #   数据处理脚本
       └── templates/            # 模板文件（可选）
           ├── report.sh         #   报告生成模板
           └── workflow.sh       #   工作流模板格式
   ```
   最小可用技能包只有一个 `SKILL.md`（F-079）。〔**未在本机实跑，依据官方文档 F-079**〕
3. **编写 `SKILL.md` frontmatter**：原文示例 9 键**逐字**如下（F-081）：
   ```
   ---
   name: your-skill-name
   display_name: 展示名称
   display_name_en:
   description: 一句话描述技能能力
   description_zh: 简短中文介绍
   description_en: A Brief English Introduction
   category: writing            # 分类之一
   version: 1.0.0
   author: 合作方名称
   ---

   # 技能指令正文

   当用户需要做 XX 时，按以下步骤执行：
   1. ...
   2. ...
   3. ...
   ```
   〔**未在本机实跑，依据官方文档 F-081**〕
4. **对照字段表校核必填项**：原文「Frontmatter 字段」表共 9 条，**逐字**如下（F-082）：

   | 字段 | 必填 | 说明 |
   | --- | --- | --- |
   | name | 否 | 技能标识 |
   | description | 是 | 写清用途和触发词 |
   | description_zh | 是 | 简短中文介绍 |
   | description_en | 是 | 简短英文介绍 |
   | allowed-tools | 否 | 工具白名单（逗号分隔） |
   | version | 是 | 版本号 |
   | disable-model-invocation | 否 | true 则 AI 不会自动触发，只能用户手动调用 |
   | user-invocable | 否 | false 则隐藏菜单，仅供 AI 内部使用 |
   | author | 是 | 合作方名称 |

   **口径提示（示例 vs 字段表，两处并列不择一）**：示例中的 `display_name`、`display_name_en`、`category` 三项**未出现**在上表字段表中（F-083）；反之，字段表中的 `allowed-tools`、`disable-model-invocation`、`user-invocable` **未出现**在示例中（F-082）。文档未说明孰为准，本篇**不替官方裁决**，建包时须回源官方页面核对。〔**未在本机实跑，依据官方文档 F-082、F-083**〕
5. **组织子资源目录（均可选）**：`references/` 存放 `SKILL.md` 引用的补充知识文档，AI 执行技能时会读取作为上下文，适用 API 字段类型定义、协议规范、领域知识参考、示例数据，使用方式为在 `SKILL.md` 中通过 `@references/xxx.md` 引用（F-084、F-085）；`scripts/` 存放技能执行中需调用的脚本，AI 通过 Bash 工具执行，适用调用外部 API、数据处理、批量操作、需要特定运行时的逻辑，使用方式为在 `SKILL.md` 中声明调用命令和参数（F-086、F-087）；`templates/` 存放可复用的模板脚本或配置文件，适用标准化操作流程的模板、报告生成模板（F-088）。〔**未在本机实跑，依据官方文档 F-084、F-085、F-086、F-087、F-088**〕
6. **本地调试**：技能页（D4）**未给**技能专属的本地调试步骤——**官方未给**；文档八步快速开始第 5 步为「在测试环境中进行调试和验证」（F-009）。〔**未在本机实跑，依据官方文档 F-009；D4 未给**〕
7. **打包并提交审核**：将技能目录打包为 zip，在开放平台创建过程中提交（F-078）；流程对应八步快速开始第 6 步「提交平台审核」（F-010）。〔**未在本机实跑，依据官方文档 F-078、F-010**〕
8. **解析失败时排查（原文处置）**：先参考【技能基础结构】（第 2 步目录树，F-079）与【子资源目录说明】（第 5 步，F-084 ~ F-088）**定位问题**；定位失败则**发送邮件至 `openworkbuddy@tencent.com`**（邮件联系运营同学），或**扫描开放平台首页下方的二维码，加入社群沟通**（F-078）。〔**未在本机实跑，依据官方文档 F-078**〕
   - **跨页表述差异（并列登记）**：同一条「解析失败」口径在**专家页（D6）**的表述中，参照的小节名写作【基础结构】【配置文件】，而非技能页的【技能基础结构】【子资源目录说明】（F-078 为 D4、D6 多来源条目）；两页章节名不同属**文档自身措辞差异**，本篇并列表述、不择一。
9. **上架与用户安装调用**：技能展示在 WorkBuddy 市场上（F-073）；用户点击左侧菜单【专家·技能·连接器】出现二级菜单，选择【技能】，进入【技能市场】（F-074）；用户点击对应技能右上角加号安装对应技能，并支持在对话中调用已安装的技能（F-075）。〔**未在本机实跑，依据官方文档 F-073、F-074、F-075**〕

> 上 9 步均**未在本机实跑，依据官方文档（F-073 ~ F-088、F-003、F-009、F-010）**；目录树、frontmatter 示例与字段表逐字照抄原文，未凭空补全。

## 结果判据

- **目录结构可校核**：包内结构与 `{skill-name}/` + `SKILL.md`（必须）+ 三个可选目录一致（F-079），即符合文档描述的技能基础结构。
- **提交流程可继续**：zip 包提交后**未触发**「解析失败」异常，即视为可继续（文档把「解析失败」列为需按第 8 步排查的情形，F-078）。
- **市场可见可安装**：技能展示在 WorkBuddy 市场上（F-073）；用户在【技能市场】可见该技能、可点右上角加号安装，并在对话中调用已安装的技能（F-074、F-075）——文档描述的可见迹象。
- **本机无法闭环**：技能审核与上架结果**由平台判定**，且技能页**未给**技能审核时长（[核验报告](../references/verification.md) 第五节第 3 项）；文档第 7 步仅表述为「审核通过后发布上线」（F-011）——本束未提交、未上架，以上判据取自文档描述而非本机实测，**不得**写成「已上线 / 已完成审核 / 功能已验证可用」。

## 限制与边界

- **审核时长**：D4 页**未给**技能提交后的审核时长——**官方未给**（[核验报告](../references/verification.md) 第五节第 3 项；除 D9 分享应用给出「7 个工作日」外，其余各类审核时长均未给出）。
- **解析失败细节**：文档**未给**解析失败的具体错误码或字段级报错清单，排查只能回到「目录结构比对」这一粗粒度手段（F-078）。
- **子目录约束**：`references/`、`scripts/`、`templates/` 均为可选（F-079）；文档**未给**各子目录的数量上限、命名规范或体积约束——**官方未给**。
- **frontmatter 口径未收敛**：示例（F-081）与字段表（F-082）的字段集合不一致（F-083），文档未说明孰为准；本篇**不替官方裁决**，须回源官方页面核对。
- **安装/更新/卸载口径**：文档**未给**技能安装后的存储位置、更新机制与卸载口径——**官方未给**（F-075 仅述安装与对话调用）。
- **创建交互背后能力**：文档**未写明**创建技能对话背后使用的能力或模型——**官方未给**（F-077）。
- **未采集页**：侧栏 `api-token`、`contact`、`developer-profile`、`legal-basis-and-examples`、`operations-data`、`service-categories-individual`、`service-categories-enterprise` **本次未采集，仅登记入口**，不得据名称推断与技能相关的字段或功能（[页级采集与覆盖台账](../references/source-manifest.md)）。
- **口径纪律**：文档未写明处一律标「**官方未给**」；本束**未在本机实跑**，不出现「已上线 / 已 GA / 已完成审核 / 功能已验证可用」类替官方宣布的表述。
