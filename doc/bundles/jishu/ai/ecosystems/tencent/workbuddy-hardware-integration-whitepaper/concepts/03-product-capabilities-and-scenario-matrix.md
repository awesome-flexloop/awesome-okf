# WorkBuddy 对智能硬件开放的产品能力与场景矩阵

本篇回答一个具体问题：硬件伙伴接入 WorkBuddy 后能拿到哪些 AI 能力、又适配哪些场景。事实取自白皮书 §5 与 §6（F-082 ~ F-109）。前提是：能力都在云端提供，伙伴只需通过标准 API 调用整个引擎，无需自研任何一层（F-082）。

## 一、云端 Agent 引擎的五层结构

WorkBuddy 核心是云端 Agent 引擎，遵循「理解 → 规划 → 记忆 → 执行 → 调度」五层结构（F-082），且对伙伴完全透明：

1. **理解**：多模态输入解析（文本、语音、图像、屏幕），结合硬件上下文识别意图（F-083）。
2. **规划**：把目标拆解为多步任务，自主选择工具链与执行顺序（F-084）。
3. **记忆**：跨端长期记忆与会话短期记忆并存，Thread 在多端连续续接（F-085）。
4. **执行**：调用 Skills、Connector 与 MCP 完成实际动作，产出可交付物（F-086）。
5. **调度**：7×24 定时任务、事件触发与多智能体协同分工（F-087）。

五层构成完整闭环；接入即等于直接获得这套内核，硬件只需负责末端的传感与呈现。

## 二、云端能力包：六类能力与适配触点

硬件通过 OAuth 授权 + API 调用即可拥有以下六类能力包，白皮书为每一类标注了适配触点（F-088）：

| 能力类别 | 典型能力 | 适用触点 |
| --- | --- | --- |
| 对话与问答 | 多轮对话、复杂推理、知识问答、翻译 | 听 · 看 · 聊 |
| 任务规划执行 | 目标拆解、工具调度、多步执行、产出物生成 | 协 · 记 |
| 信息处理 | 纪要生成、摘要、结构化提取、内容改写 | 听 · 记 |
| 主动服务 | 定时任务、日程提醒、盯盘、内容监控 | 聊 · 协 |
| 跨端记忆 | 用户偏好、历史 Thread、跨设备无缝续接 | 全部 |
| 本机联动 | 调用用户 PC 桌面能力、读取文件、执行本机任务 | 协 |

## 三、端云协同机制：端、云、协同三层分工

六类能力能被硬件高效复用，靠的是三层分工（F-089 ~ F-091）：

- **端侧**：硬件负责传感（拾音、成像、位置）、唤起、播报、显示与快速反应；轻量能力可端侧完成，敏感数据可本地处理（F-089）。
- **云端**：WorkBuddy 云端负责理解、规划、记忆、复杂推理与工具调度，承担 AI 内核（F-090）。
- **协同**：遵循「端触发 → 云决策 → 端执行」的链路，并支持跨端 Thread 无缝续接——用户从眼镜切到手机能继续同一件事（F-091）。

## 四、生态扩展体系：三层可扩展生态

能力不是封闭黑盒，而通过三层可扩展生态持续进化，伙伴既可享受生态红利，也可贡献自身能力入生态（F-092）：

- **Skills**：7 万余个即插即用，覆盖办公、内容、生活、行业垂直等场景（F-092）。**口径提示**：此处数量为 `厂商自宣口径`，且与本白皮书 §0.1 关键数据表所载「2.2 万+ Skills」（F-008）不一致（勘误 E-2）；本束对两处并列登记、不裁决孰为真（F-092、F-008）。
- **专家 / 助理**：预置角色化助理与专家（写作、研究、数据、客服等），硬件可选定专家作为默认助理（F-092）。
- **Connector / MCP**：连接外部系统与设备的标准协议，硬件能力可作为 Connector 融入生态，被其他用户和场景调用（F-092）。

## 五、硬件专区：五个环节的产品承接

客户端与云端为合作硬件提供「硬件专区」承接，形成产品—用户闭环（F-093）：

1. **设备绑定**：扫码 / OAuth 一键绑定用户账号与设备，支持多设备并存。
2. **专区入口**：WorkBuddy 端内独立品牌专区，展示合作硬件、专属能力与场景玩法。
3. **官网展示**：WorkBuddy 官网设硬件生态专区，集中展示合作硬件品类与代表机型。
4. **联动能力**：专区可挂载合作方定制 Skills、场景与内容。
5. **管理后台**：合作方专属管理后台，含设备管理、用户绑定、能力配置与数据看板。

**露出口径**：官网硬件生态专区仅露出已完成接入并通过 WorkBuddy 审核的深度合作客户（认证级及以上）；展示范围、排序与更新节奏以官网公示为准（F-094）。

## 六、场景能力矩阵：六触点与推荐能力组合

按「听、看、戴、记、聊、协」六触点，可横向拆解每一触点下 WorkBuddy 能提供的 AI 能力组合（F-095 ~ F-100）：

| 触点 | 典型硬件 | 核心场景 | 推荐能力组合 |
| --- | --- | --- | --- |
| 听 | 耳机、真无线耳机（TWS） | 随身语音助理、通话实时翻译、会议摘要播报 | 对话问答 + 翻译 + 纪要摘要 + 主动提醒（F-095） |
| 看 | 眼镜、头显 | 提词、实时翻译、图像识别、临场问答、AR 提示 | 多模态理解 + 对话问答 + 翻译 + 知识调用（F-096） |
| 戴 | 手表、手环 | 抬腕速览、健康与日程提醒、消息速答、运动中语音问答 | 主动服务 + 对话问答 + 跨端记忆 + 本机联动（F-097） |
| 记 | 录音笔、智能麦克风 | 会议纪要、访谈整理、结构化沉淀、内容改写 | ASR + 纪要摘要 + 结构化提取 + 内容改写（F-098） |
| 聊 | 桌宠、桌面机器人 | 陪伴对话、语音问答、日程提醒、家庭助理 | 对话问答 + 主动服务 + 跨端记忆 + 情感化 TTS（F-099） |
| 协 | 工卡、便携终端、车机 | 差旅办公、行车助理、现场作业、任务协同 | 任务规划执行 + 本机联动 + 主动服务 + 跨端记忆（F-100） |

办公与 ToB 场景同样在接入范围内：会议空间与智能会议室（会议纪要、实时同传、待办跟进）、办公本与生产力终端（本机文档处理、日程协同）、企业工卡与服务台（任务分派、知识问答）（F-101）。此类场景通常走「双向打通」或「能力集成」；涉及企业数据的，建议同时参考第 11 章的数据安全说明（F-101）。

## 七、六个已跑通的真实场景（匿名化）

六个场景来自已完成接入或正在对接的伙伴实践，覆盖「看 / 聊 / 记 / 听」四类触点；白皮书已对品牌与产品名做匿名化处理（F-102，`匿名化场景`）。**纪律提示**：一律保持匿名，**不得反推真实品牌**、不得关联具体企业、不得用于商业尽调，仅作「品类 + 接入方式 + 能力组合」的方法论参考（F-102 ~ F-108）。

| 场景品类 | 触点 | 接入方式 | 能力组合 |
| --- | --- | --- | --- |
| 某 AI 记忆眼镜品牌 | 看 | 模式② 双向打通 | 多模态采集 + 纪要摘要 + 跨端记忆 + 任务规划执行（F-103） |
| 某光波导 AR 眼镜品牌 | 看 | 模式② 票据互换 | 多模态理解 + 云端任务管理 + 产物回显（F-104） |
| 某桌面陪伴硬件品牌 | 聊 | 模式② 官方认证硬件 | 对话问答 + 主动服务 + 任务状态回显 + 情感化语音（F-105） |
| 某智能录音卡品牌 | 记 | 模式② + 模式④（厂商官方 MCP 双向） | 语音转写 + 纪要摘要 + 结构化提取 + 内容生成 + 数据回调（F-106） |
| 某无线麦克风品牌 | 听 | 轻量接入（快捷键 / 语音映射） | 声学采集 + 语音识别 + 对话问答 + 本机联动（F-107） |
| 某翻译耳机品牌 | 听 | 模式② 双向打通 | 翻译 + 跨语言理解 + 纪要摘要 + 任务规划执行（F-108） |

同一伙伴可按能力叠加多条路径：先用最轻的快捷键 / 语音入口跑通，再按需叠加 App 植入（模式②）与数据回调（能力集成），逐步加深（F-109）。
