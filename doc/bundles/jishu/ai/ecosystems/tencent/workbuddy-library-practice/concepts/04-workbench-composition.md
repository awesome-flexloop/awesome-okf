# 工作台组合：先区分展示页面与持续使用的工具

## 读者问题

眼前的问题需要一页便于阅读和分享的展示，还是一个要持续记录、筛选和更新的工具？

S09 将工作台用途分为两类：汇报、复盘、攻略、作品集等展示场景；以及个人记录、客户跟进、任务看板等持续使用场景（F-020、F-021、F-046）。这是作者的场景分类，可用来帮助澄清需求，不意味着所有列出的场景都已在平台中验证。

## 场景选择

| 需求特征 | 优先考虑 | 设计重点 |
| --- | --- | --- |
| 信息相对稳定，主要让人浏览或分享 | 展示页面 | 内容结构、阅读顺序、来源和更新时间 |
| 信息持续变化，需要反复添加或查看记录 | 动态工作台 | 数据字段、更新责任、筛选与状态含义 |
| 同时有说明材料和持续变化记录 | 内容与数据分层 | 说明和操作约定与记录表保持可追溯关系 |

这张表是根据 S05 的载体分工和 S09 的场景分类作出的实践归纳（F-010、F-020、F-046）。关于 CSV/HTML 的平台联动细节，请参阅[官方资料库概念页](../../workbuddy-official-docs/concepts/06-knowledge-base-and-library.md)，不要仅凭案例页面推断产品能力。

## 面包店目录案例：可读结构与不可推断部分

S11 的目录列出一个主工作台和四个 HTML 看板，主题分别为营销计划、商品资料、仓配费用分析和数仓需求管理（F-028–F-030）。四个已读取看板均标注数据为虚构演示数据（F-031）。

因此，这个案例可以用于观察“一个业务工作台下组织多个主题看板”的目录构成；它不能用于证明真实面包店经营状况、指标水平或经营效果。仓配费用看板中的公式和数据表名称也是演示页面内容，不代表真实业务数据（F-032）。

**采集边界：**目录所指向的主工作台页面正文仍显示加载占位，未取得可供核对的完整正文（F-033）。本页不从目录名称或子看板反推主工作台的功能、交互或数据流。

## 从场景到工作台的实践提问

下面的问题是设计前的检查提示，不是来源页面给出的固定模板：

1. 使用者要完成什么任务，使用频率如何？
2. 哪些信息是说明，哪些是持续变化的记录？
3. 谁负责更新数据，谁确认其含义？
4. 页面上的每个指标或状态能否解释来源和更新时间？
5. 当前材料是演示数据还是实际数据，是否已明确标示？

先回答这些问题，再决定是否需要动态页面、表格或团队空间，可以减少为“看起来像系统”而引入不必要维护成本。
