# 让资料成为人与 Agent 可接续的工作成果

## 读者问题

一次任务做出的方案、报告或页面，怎样从“这次对话的结果”变成后续任务可继续使用的工作材料？

S01 将资料库描述为保存并在后续任务中调用已有成果的空间；S02 把实践组织为“保存个人成果—在后续任务继续协作—需要时转入团队共享”；S04 也讨论 Agent 接续读取、修改以及保存和分享成果（F-002、F-005、F-008、F-045）。这些是来源页面的实践描述，不是对任意资料自动可见、自动更新或持续记忆的承诺。

## 从一次产出到下一次任务

| 环节 | 实践动作 | 需要说清的上下文 |
| --- | --- | --- |
| 留存 | 把确认有复用价值的产物保存到资料库 | 这份资料是什么、适用于什么任务 |
| 指定 | 后续任务明确指出要使用的资料或空间 | 哪些内容是依据，哪些是本次新需求 |
| 接续 | 说明希望 Agent 基于已有资料完成什么修改或新产物 | 目标、受众、范围和输出形式 |
| 回存 | 检查新结果后，决定是否保存为下一轮可用材料 | 是否已校对、是否含过时或敏感信息 |
| 共享 | 需要团队共同使用时，再放入适当的共享空间 | 哪些成员需要查看或编辑 |

这张表是对 S01、S02、S04 所述做法的整理，不是 WorkBuddy 的强制流程。具体保存、添加到任务和分享入口以[官方知识库工作流](../../workbuddy-official-docs/examples/05-knowledge-base-workflow.md)为准。

## 个人材料与共享上下文

个人资料适合承接尚在整理、仅供本人使用的草稿；团队空间则可承接多人和 Agent 共同使用的项目材料。S02 将个人成果转入团队空间视作协作范围扩大的一个环节，S07 进一步描述共享空间中的资料、成员与后续复用（F-005、F-015、F-042、F-045）。

实践上，可以先问三个问题：

1. 这份材料会不会被下一项任务复用？
2. 复用者是否只有自己，还是包括团队成员？
3. 内容是否已经达到可共享状态，且访问范围合适？

这些问题帮助选择保存位置，不替代平台权限配置。WorkBuddy 的空间权限以及 Agent 所能读取的范围，参见[官方资料库与知识库说明](../../workbuddy-official-docs/concepts/06-knowledge-base-and-library.md)。

## 适用边界

- 保存资料不等于内容已核验；来源、日期、适用范围仍应随材料保留。
- “Agent 可以接着做”是来源页面描述的协作方式。实际可访问性受账号、空间和授权状态约束，不能据此推断越权访问。
- 转入团队空间前，先确认材料适合共享；不应把个人信息、未确认草稿或仅限特定对象的内容无差别扩散。
- S03 与官方快速操作内容重叠较高，因此这里只保留其入门来源映射，不复述操作步骤。
