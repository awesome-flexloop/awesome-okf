# 更新日志

## 2026-11-09（G5 模式沉淀）

- **模式**：企业微信三层接入读法——协议层（本束 SDK）/ 执行层（wecom-cli）/ 路由层（wecom-unified）分束，各自事实独立编号、束间仅相对链接。
- **触发场景**：需要在同一生态内选择「命令式摆弄」还是「长连接事件驱动」两种接入方式。
- **步骤**：①先读连接生命周期与认证帧；②再读帧结构与 `req_id` 路由；③流式回复必须按同一 `req_id` 串行确认；④媒体文件走「下载→解密」两段，密钥约定不可省略。
- **反模式**：①并发复用同一 `req_id` 发送分片；②忽略心跳判死阈值导致假在线；③把 AES 解密当作可选步骤；④以打包版本号单一口径描述运行期版本（本束 1.0.1 / 1.0.0 双写）。
- **迁移**：适用于其他基于长连接 + 流式分片的机器人协议 SDK 阅读。
