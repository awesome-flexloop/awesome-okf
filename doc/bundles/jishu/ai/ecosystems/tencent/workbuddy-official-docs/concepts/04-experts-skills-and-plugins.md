# 专家、专家团、技能与插件：四类能力扩展如何区分

> 本篇属**能力扩展层**：官方把 WorkBuddy 的适用场景归纳为七类，并说明「可通过专家、技能、连接器和资料库扩展工作能力」（F-004）。其中专家、专家团、Skill、插件四者都在回答「怎么把外部能力接进对话」，但机制与代价各不相同。事实编号见[事实登记](../references/article-source.md)，信源与口径分层见[核验报告](../references/verification.md)。

## 专家与专家团：同一批能力的两种组织方式

- **专家是「角色切换」机制**：为 WorkBuddy 配置专业角色，本质是「人设 + 方法论 + 工具链」的整体切换；**专家团是「协作执行」机制**：多位专家分工协作，由团长自动拆解任务、并行执行并整合交付（F-141）。
- **权限边界（最易误解处）**：专家本身**不主动获取系统权限**，只处理你主动提供的对话与上传文件；只有配备 Skill/MCP 时，才会在授权下间接访问文件或外部服务（F-142）。
- **召唤体验（文档可配置项）**：召唤专家后，WorkBuddy 会从引导提示词中**随机**选取一条作为开场引导，同一专家的开场提示每次可能不同；在专家团会话中切换到其他专家会提示「需要开启新对话」，即专家团内换人必须另起对话（F-143）。
- **按需连接**：专家依赖的服务未连接时，输入框上方出现连接引导卡片（显示服务名称与头像），授权后自动继续当前任务；该卡片只在任务实际用到该服务时出现（F-144）。
- **创建与代价**：创建入口为专家页面右上角「我的专家」→「创建专家」，由内置专家管理工具引导完成配置，**创建后名称无法修改**；专家团的积分消耗通常为单专家的 **3–5 倍**（F-145）。

## 技能（Skill）：把一项能力封装成可调用单元

- Skill 为 WorkBuddy 增加「特定工具能力」，封装一组可执行的脚本与工作流（如发送邮件、订外卖、查询股价、读写文件、调用第三方 API）（F-226）。
- 板块分「技能市场（推荐技能，一键安装）」与「已安装（本地技能，对话中直接调用）」；安装有**三种方式**：上传技能（导入本地技能包）、查找技能（输入任务描述自动查找）、创建技能（输入任务描述自动创建）（F-227、F-228）。
- **启用/关闭状态记录在用户全局配置中，可多端同步，且不改动技能包本身的 `SKILL.md` 文件**；关闭后仍保留在已安装列表但不参与自动调用，重新开启立即恢复；卸载则彻底删除（F-229）。
- 内置 **20+ 技能包**，覆盖文档处理、数据报表、海报设计、文件整理等场景，兼容 OpenClaw 社区技能导入，也支持通过自然语言创建自定义技能（F-236）。

## 插件：把一组能力打包分发

插件用于**打包分发一组相关能力**，一个插件可同时包含技能、外部工具连接、快捷指令、自动化规则等组件，安装后即可统一使用（F-204）。组件类型共五种：技能（Skills）、MCP 连接、快捷指令（Slash Commands，如输入 `/周报` 一键生成周报）、自动化规则（Hooks，如生成文件后自动检查格式）、智能体（Agents）（F-205）。插件市场支持关键词搜索、一键安装；已安装插件支持启用、停用、更新（F-206）。

事实源中另有一组更早的插件类型分类：插件系统支持 **Skill（技能插件）、MCP、Hook（钩子插件）、Agent（智能体插件）、Rule（规则插件）** 五种类型（F-076）；点击左侧「插件」按钮进入插件管理页，可浏览内置插件列表（名称、作者、分类）并安装，已安装插件可在中间栏管理、查看说明或卸载（F-077）；也可在插件页点「+」输入**第三方插件市场地址**后浏览安装该市场中的插件（F-078）。

> **口径提示**：F-205（组件类型）与 F-076（插件类型）是同一机制的两次表述，差异在分类维度，引用时应注明来源页面；第三方插件市场属可自行添加的分发入口（F-078），不代表平台审核背书。

## 四者对比

| 维度 | 技能 Skill | 专家 | 专家团 | 插件 |
| --- | --- | --- | --- | --- |
| 定位 | 一项「特定工具能力」（F-226） | 「角色切换」：人设 + 方法论 + 工具链（F-141） | 「协作执行」：多位专家分工 + 整合交付（F-141） | 「打包分发一组相关能力」（F-204） |
| 组成 | 脚本 + 工作流（F-226） | 单个专家配置，可挂 Skill/MCP（F-142） | 团长 + 多位专家成员（F-141） | 五种组件：Skills / MCP / 快捷指令 / Hooks / Agents（F-205） |
| 权限 | 未取得 Skill 自身的权限口径（未取得）；企业版由下发策略决定成员可用范围（F-495、F-500） | 不主动获取系统权限，仅处理主动提供的内容；配 Skill/MCP 才在授权下间接访问（F-142） | 同专家；团内切换其他专家需新开对话（F-142、F-143） | 含 MCP 连接等组件即携带对应服务的独立授权面（F-205、F-131） |
| 积分特征 | 未取得专属口径（未取得） | 事实以「单专家」为计费基准表述（F-145） | 通常为单专家的 **3–5 倍**（F-145） | 由所含组件决定；未取得插件整体口径（未取得） |

**一句话记法**：Skill 是**能力**，专家（Agent 型）是**能力 + 经验**，专家团（Team 型）是**多位专家 + 协作流程**（F-387）。另一组可参照的关系是「Skill = 能力（能做什么）、专家 = 谁能帮我做、灵感 = 成果（实际做出了什么）」（F-156）。

> **三端差异**：上述辨析出自小程序端页面，该端把专家页命名为「专家中心」并标注「专家（Agent 型）/ 专家团（Team 型）」，而 App 端页名为「专家」（F-387）。桌面端入口为侧边栏「专家·技能·连接器」（F-128）。引用时请注明端别。
