# 实战 04 · 扩展能力：技能、专家与插件

WorkBuddy 的扩展由三层组成：技能（Skill）提供执行能力、专家解决单点问题、专家团组织协作（F-142）；插件则把一组相关能力打包分发（F-204）。三者分别对应「能做什么」「谁能帮我做」「成套能力怎么装」。机制说明见 [concepts/04-experts-skills-and-plugins](../concepts/04-experts-skills-and-plugins.md)。

## 前置条件

- 已登录 WorkBuddy 客户端，且当前账号积分可用。
- 了解三个层次的分工：Skill 提供执行能力、专家解决单点问题、专家团组织协作（F-142）。
- 注意积分梯度：**专家团的积分消耗通常为单专家的 3–5 倍**（F-145，文档可配置项）。

## 操作步骤

### A. 安装与管理技能

技能为 WorkBuddy 增加「特定工具能力」，封装一组可执行的脚本与工作流（如发送邮件、订外卖、查询股价、读写文件、调用第三方 API，F-226）。技能板块分「技能市场（推荐技能，一键安装）」与「已安装（本地技能，对话中直接调用）」两块（F-227）。

安装技能三种方式（F-228）：

| 方式 | 做法 |
| --- | --- |
| 上传技能 | 导入本地技能包 |
| 查找技能 | 输入任务描述，让系统自动查找 |
| 创建技能 | 输入任务描述，让系统自动创建 |

技能市场中的推荐技能可一键安装（F-227）；此外客户端内置 20+ 技能包，覆盖文档处理、数据报表、海报设计、文件整理等场景，并兼容 OpenClaw 社区技能导入（F-236）。

启用/关闭技能（F-229）：关闭后仍保留在已安装列表，但不参与自动调用；重新开启立即恢复。开关状态记录在用户全局配置中、可多端同步，且**不改动技能包本身的 `SKILL.md` 文件**；卸载则彻底删除。

### B. 召唤专家

1. 在专家中心选择专家（F-141）。
2. 召唤后系统会从引导提示词中随机选取一条作为开场引导，**同一专家的开场提示可能每次不同**（F-143）。
3. 在专家团会话中切换其他专家，会提示「需要开启新对话」（F-143）。
4. 创建自定义专家：「我的专家 → 创建专家」，由内置专家管理工具引导完成配置，**创建后名称无法修改**（F-145）。

### C. 使用插件

1. 在插件市场按关键词搜索 → 一键安装 → 已安装插件可启用、停用、更新（F-206）。
2. 一个插件可同时包含多类组件（F-204）：技能、MCP 连接、快捷指令（Slash Commands，如输入 `/周报` 一键生成周报）、自动化规则（Hooks，如生成文件后自动检查格式）、智能体（Agents）（F-205）。
3. 输入斜杠命令时的补全行为与 CodeBuddy Code 一致（F-235）。

### D. 添加第三方插件市场

在插件页点击「+」按钮，输入插件市场地址并确认后，即可浏览和安装该市场中的插件（F-078）。

> 未在本机实跑，依据官方文档（F-078、F-141、F-142、F-143、F-145、F-204、F-205、F-206、F-226、F-227、F-228、F-229、F-235、F-236）。

## 结果判据

- 安装成功后，技能出现在「已安装」列表（F-227）。
- 召唤专家后出现该专家的开场引导（F-143）。
- 插件安装后其组件可用，含斜杠命令补全（F-205、F-235）。
- 技能启用/关闭后，开关状态可多端同步且不修改技能包本身（F-229）。

## 限制与边界

- **专家不越权**：专家本身不主动获取系统权限，仅处理主动提供的对话与上传文件；配备 Skill/MCP 时才会在授权下间接访问文件或外部服务（F-142）。
- 专家依赖的服务未连接时，输入框上方会显示连接引导卡片，授权后自动继续当前任务（F-144）。
- 创建专家后名称无法修改；专家团消耗高于单专家（F-145）。
- **企业版专属**：企业 Skill 管理用于统一下发与管理组织内 CodeBuddy / WorkBuddy 能力扩展（F-493）。管理员采用双层策略架构（Skill 下发策略 + 成员自定义 Skill 策略，F-495），策略优先级为「黑名单 > 白名单 > 默认允许」（F-496）；管理员通过下发策略控制成员「能使用哪些 Skill」，不直接干预客户端实际调用（F-500）。企业后台页披露内置 Skill 当前为 301 个（F-494）。
- 引用版本/数量以核验时点 2026-10-15 的官方页面为准，未在本机实跑。
