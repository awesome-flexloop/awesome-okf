# 五条洞察：从这一课能带走什么

> 洞察与事实分开登记：事实在 [课程事实登记](references/course-source.md)，本页只写「从事实推出什么」。每条洞察标注证据编号；凡属本包推断而非课程原文的，明确标出。

## I-1 真正的分水岭在操作链，不在聊天链

**陈述**：手机 Agent 能不能用，取决于「看屏幕 + 点按钮」这条链是否稳定；聊天能力早就不是瓶颈。

**证据**：课程把七件事归为记忆、技能、工具、闸门、运行时五类部件（F-021、F-023）；自检用两条指令分别验证聊天与操作（F-049、F-050）；「闲聊有回复、手机却不动」被单列为典型故障，排查方向是操作模型、图片支持与无障碍（F-066）；豆包手机助手的公开叙事重心也落在「操作手机」而非对话（F-083、F-084）。

**反常识**：多数人的直觉是「换个更强的模型就好了」。但这一课里，聊天链只要 Key 对就能通；真正让人卡住的是无障碍被系统关掉、操作模型没填、模型不支持看图——**这些都不是模型智力问题，而是通道与权限问题**。

**行动**：遇到故障先分链，再改配置。聊天不通查 Base URL、模型名、Key、额度；手机不动查操作模型、视觉能力、无障碍。不要在两个模型之间反复重填来「碰运气」。

## I-2 二次开发的杠杆点在规则、技能、记忆，不在核心代码

**陈述**：想把通用助理改成「你的」助理，改动应优先落在可读的文字资产（技能说明书、记忆、任务书）上，而不是核心操作代码。

**证据**：讲师自述一套规则文件、一个技能目录、一份记忆构成助手小队的全部个性化（F-018~F-020）；课程称「设闹钟」技能与提醒功能按「讲清改哪里 → 写 → 测 → 装回手机」完成（F-039）；教程把改动落点分为 app、core-memory、skills、hands 四个房间（F-091），其中 skills 是文字规则。

**反常识**：直觉是「要定制就得改源码」。但这一课的路径恰恰相反——**先改文字，再改代码**。文字资产可读、可回滚、可审计；代码改动则要真机回归（F-039）。

**行动**：拿到新需求，按「记忆 → 任务书 → skills → app → hands」的顺序找落点（见 [06 用 TRAE 读项目](concepts/06-trae-read-project.md)），只有前几层表达不了才动后面。

## I-3 长任务的成本由「截图次数」决定，任务设计即成本设计

**陈述**：手机 Agent 按步执行，每一步都要把屏幕截图发给模型判断；因此费用与失败概率主要由步数决定，而不是由回答长度决定。

**证据**：课程说明手机操作时的截图会发给配置的模型（F-068）；费用口径里明确「十几二十步的长任务大约几毛到一块钱，每一步都要发一张截图」（F-064）；任务四要素要求写明条件与停点（F-054、F-055）。

**反常识**：大家习惯用「Token 单价」比较模型贵不贵，但在手机 Agent 场景里，**同样的模型，任务书写得含糊就会多走十步**——省钱的杠杆在任务书，不在模型选型。

> 本条属本包推断：课程给出了「每步发截图」与「长任务费用更高」两个事实，但未直接把二者写成因果关系。此处把它们合成为成本模型，供任务设计使用。

**行动**：长任务拆成「侦察 → 选定 → 决策」三段；每段都写明确的停点与回报项；把预算、规格、时间写成可判定的数字。

## I-4 人类在环不是安全补丁，而是能力边界的一部分

**陈述**：产品把「该问就问」写进了主流程，而不是等到出事再弹一个免责声明；这不是能力不足的补丁，而是设计上的边界。

**证据**：付款、发送、删除前都会先问用户，密码框不能输入（F-067）；验证码必须本人过（F-053）；课程明确不让 AI 代点实名、开通与建 Key（F-072）；执行中每次操作都要用户点「允许一次」（F-052）。

**反常识**：大众叙事里「全自动」才是 Agent 的终点。但真实产品把不可逆动作全部留给人——**能被信任的自动化，恰恰是知道自己什么时候该停的自动化**。

**行动**：设计任务时显式写出停点与红线（如「不要加购、不要下单」）；把「遇到验证码先停下来告诉我」写进任务书；接受「多一次确认」是正常成本，不是失败。

## I-5 教 AI 读项目的第一课是「只讲不改」

**陈述**：让 AI 第一次接触陌生项目时，最该约束的不是它的能力，而是它的手。

**证据**：讲师习惯是第一次只让它讲、不让它改（F-038）；课程给的勘察提示词以「先只讲解，不要修改任何文件」收尾（F-041）；求助模板同样以「先只分析，不要修改任何文件」收尾（F-074）。

**反常识**：新手第一反应是「让它直接改，改坏再回滚」。但回滚需要版本控制与判断力，而这两样正是新手缺的。**先建立户型图，再动墙**，返工更少。

**行动**：首次勘察用三问模板；把「工作区无改动」列为验收项；改技能时走「讲 → 写 → 测 → 装回手机」四步，不跳步。
