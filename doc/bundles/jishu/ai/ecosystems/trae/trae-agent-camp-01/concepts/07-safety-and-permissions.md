# 安全与权限：哪些动作必须由人来按

手机 Agent 与聊天机器人最大的安全差异在于：它**真的会动手**。所以这一篇不是「注意事项」，而是一张**权限与授权地图**——你得知道自己在哪些地方把权限交了出去，以及哪些地方不该交。

## 七个必须由人处理的卡点

| # | 卡点 | 系统或产品在哪一步问你 | 你该怎么做 | 依据 |
|---|------|------------------------|------------|------|
| 1 | 安装未知来源应用 | 装 APK 时 | 只在确认来源可信时勾选「已了解风险」 | F-043、F-045 |
| 2 | 通知权限 | 首次打开 App | 允许；否则提醒不会弹 | F-046 |
| 3 | 无障碍服务 | 系统设置内 | 打开开关并允许；这是读屏与点击的前提 | F-047 |
| 4 | 单次操作授权 | 任务执行中弹确认 | 看清这一步做什么，再点「允许一次」 | F-052 |
| 5 | 付款 | 结算前 | 自己核对金额与商品后决定 | F-067 |
| 6 | 验证码 / 滑块 | 平台风控时 | 本人手动完成，再说「继续」 | F-053 |
| 7 | 密码框 | 需要输入密码时 | 它不能输入，也不该让它输入 | F-067 |

把这七个卡点记成一句话：**凡是「不可逆」或「证明你是你」的，都由人来。**

## 源码里的闸门

Sentinel 在模型之外运行，按「拒绝 → 询问 → 允许」首次匹配生效（S-024~S-027）：

| 动作 | 判定 |
|------|------|
| 受保护（FLAG_SECURE）屏幕上的设备操作 | 拒绝（返回、主页、等待除外） |
| 向密码框输入 | 拒绝 |
| 技能声明 `apps` 时操作越界包 | 拒绝（启动器与 App 自身除外） |
| 目标或节点文字命中确认词 | 询问 |
| `deeplink` 不在技能模板中 | 询问 |
| 其他动作 | 允许 |

内置确认词共 17 个：支付、付款、确认支付、立即支付、转账、发送、删除、下单、提交订单、确认呼叫、呼叫、购买、pay、send、delete、purchase、order。授权范围分「仅一次」与「本次任务」，任务结束即清除后者；每次决策写入 `audit.jsonl`。

> 课程只讲了「允许一次」；源码里还有「本次任务都允许」，界面把它收在更多选项里（S-027、S-029）。

## 不可逆动作清单

课程明确：付款、发送、删除前都会先问你，由你决定（F-067）。实际使用中，建议把这张清单扩展到下面这些动作——它们同样难以回滚：

- 付款、转账、充值、开通按量计费服务
- 发送消息、发邮件、发朋友圈、提交表单
- 删除文件、清空相册、取消订单
- 修改密码、绑定手机号、授权第三方登录
- 实名认证、人脸识别

> 这些扩展项是本包基于「不可逆性」判据给出的建议，不是课程原文。课程原文只列了付款、发送、删除三类（F-067）。

## 为什么实名、开通、建 Key 不能让 AI 代点

课程给了三条理由（F-072），每一条都对应一类风险：

| 理由 | 风险类型 | 后果 |
|------|----------|------|
| 实名要本人刷脸 | 身份核验 | 代刷脸本身不合规，且可能失败 |
| 开通模型等于同意按量计费 | 计费授权 | 你可能在没看清价格的情况下产生费用 |
| Key 一出现，替你点击的 AI 也会读到 | 凭据泄露 | Key 进入模型上下文，等于交出去了 |

第三条最容易被忽略：**屏幕上的内容对 Agent 是可见的**。所以不只是「不要发群、不要截图公开」（F-031），还要注意「不要让 Agent 在你创建 Key 的那一屏上操作」。

找不到按钮时，课程允许的做法是把控制台截图发给 TRAE 问下一步点哪里，但**截图前要确认没有露出 Key**（F-073）。

## 你的屏幕会离开手机

课程说明：手机操作时的截图会发给你配置的模型做判断（F-068）。这句话的份量比它看起来重——它意味着：

| 你手机上的内容 | 会到哪里 | 你要做的判断 |
|----------------|----------|--------------|
| 当前页面截图 | 你配置的模型服务（如方舟） | 是否接受该服务的数据条款 |
| 页面上的姓名、手机号、地址 | 同上 | 敏感页面不要让 Agent 操作，或先遮挡 |
| 聊天记录、订单、余额 | 同上 | 与钱和身份相关的页面，尽量本人操作 |
| Key、验证码 | 同上 | 绝对不要出现在 Agent 操作的屏幕上 |

这条也解释了为什么「每步都发截图」既是成本来源，也是隐私面来源（F-064、F-068）。**步数越多，离开设备的画面越多。**

## 无障碍权限该开多久

无障碍是读屏与点击的前提（F-047），它同时也是手机上权限最大的一类授权之一。课程没有讨论「用完是否关闭」，本包给出三条实践建议（属本包建议）：

1. **按需开启**：只在要跑任务时打开，任务结束回到系统设置关闭。
2. **不要在敏感 App 上使用**：银行、支付、政务、企业邮箱这类应用，尽量本人操作。
3. **定期核对**：换机、系统升级、安装新应用后，回来看一眼无障碍列表里有哪些应用还开着。

这三条不改变课程主线，只是把「权限是一直开着的」这个默认状态，改成「权限是可管理的」。

## 责任边界

| 问题 | 谁负责 | 说明 |
|------|--------|------|
| 任务目标是否合理 | 你 | Agent 只执行你写的任务书 |
| 是否允许某一步 | 你 | 弹确认时你有最终决定权 |
| 费用 | 你 | 计费按你的方舟账号走（F-064） |
| 平台规则合规 | 你 | 验证码、风控、自动化限制由平台判定（F-053） |
| 代码改动是否正确 | 你 + TRAE | 改完要在真机验证（F-039） |

一句话：**Agent 承担执行，你承担授权与后果。** 这也是「人类在环」在实践中的含义——不是产品给你留了个确认按钮，而是你必须在那个按钮上真的做判断。

## 安全检查清单

- [ ] 安装包来源可信，安装时看清了「未知来源」提示
- [ ] 通知与无障碍都已授权，且知道去哪里关闭
- [ ] 任务执行中，每次「允许一次」都看清了当前页面
- [ ] 付款、发送、删除三类动作前，确认会停下来问你
- [ ] 创建 Key 的全过程没有让 Agent 参与
- [ ] 知道截图会发给模型，敏感页面不让 Agent 操作
- [ ] 求助截图前做了打码（Key、手机号、地址）
- [ ] 记得任务结束后可以关闭无障碍权限
