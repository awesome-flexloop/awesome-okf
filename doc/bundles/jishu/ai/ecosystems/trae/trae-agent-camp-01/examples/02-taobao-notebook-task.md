# 示例二：淘宝挑一本 20 元以内的 A5 笔记本

## 这个示例解决什么

这是课程选定的第一个真实任务：它包含搜索、筛选、比对、进入详情、准备下单等多个步骤，足够长，能暴露 Agent 在真实 App 里的典型问题；同时它的停点在付款之前，风险可控。

## 前置条件

- [ ] 示例一的两条自检都通过（聊天链通、操作链通）
- [ ] 手机上的淘宝**已经登录**（F-051）
- [ ] 淘宝的滑块验证已提前手动划过去（F-053、F-077）
- [ ] 无障碍服务处于开启状态（F-047）
- [ ] 你知道当前是一个**测试任务**，不是真的要买东西

## 任务书

直接复制发送（F-051）：

```text
帮我在淘宝挑一本20元以内的A5笔记本，选好后给我确认。
```

四要素对照：

| 要素 | 文本 |
|------|------|
| 做什么 | 在淘宝挑一本笔记本 |
| 条件 | 20 元以内、A5 |
| 停在哪一步 | 选好后给我确认 |
| 回报什么 | 确认时你会看到商品与价格 |

## 执行中你只做两件事

课程明确，接下来手机会自己动起来，你只做两件事（F-052）：

1. **它弹确认时，看清楚再点「允许一次」。**
2. **它停下来以后，对照结算页核对店铺、规格、数量和金额。**

### 「允许一次」要看什么

| 看什么 | 为什么 |
|--------|--------|
| 当前页面是不是淘宝 | 防止在错误 App 里操作 |
| 这一步的动作是什么 | 是「搜索」还是「提交订单」 |
| 金额与数量 | 是否与你预期的 20 元以内一致 |

## 结算页四项核对

| 项 | 期望 | 不符时 |
|----|------|--------|
| 店铺 | 与你确认时看到的店名一致 | 说明中途换了商品，退回重选 |
| 规格 | A5、页数/内页类型与详情页一致 | 规格错就直接停止 |
| 数量 | 1 本（或你指定的数量） | 数量错先改数量 |
| 金额 | ≤ 20 元，且与详情页价格一致 | 有运费或加价时先看明细 |

## 停止条件（必须遵守）

- **不付款**：课程明确它不会自己付款，付款前会先问你（F-067）；你在核对完后就退出结算页。
- **不保存收货信息**：核对时不要顺手新增或修改地址。
- **遇验证码**：本人手动划过去，再回到对话说「继续」（F-053）。
- **任一核对项不符**：直接停止任务，不要让它在错误状态下继续。

## 不要外推

这个示例证明的是「它能停在确认前」，**不证明它能替你完成支付**，也不证明它在其他商品类目上同样稳定。把它当作一次受控演练，不要当作采购流程的替代。

## 费用量级

课程给的估算：淘宝这类十几二十步的长任务大约几毛钱到一块钱，每一步都要发一张截图给模型；实际以方舟控制台的用量和账单为准（F-064，【讲师口径】）。

想降低成本，最有效的做法不是换便宜模型，而是**减少步数**：把商品名写具体、把筛选条件写清楚、把停点提前（见 [05 任务设计](../concepts/05-task-prompt-design.md)）。

## 验收

- [ ] 任务停在确认或商品页，没有继续走到付款
- [ ] 你核对过店铺、规格、数量、金额四项
- [ ] 核对完已退出结算页
- [ ] 能说出这次任务大约走了多少步、花了多少量级的费用

## 变体练习

把条件换成你自己的，再发一次（课程建议）：例如「30 元以内」「要方格本」「3 层的抽纸」。换条件时保持四要素完整：

```text
在淘宝找一提 30 元以内、3 层的抽纸，停在商品页，把店名、规格和价格告诉我，
不要加购、不要下单。
```

这个变体把停点从「确认」提前到「商品页」，并显式写了否定式红线（F-055）。对比两次执行，你能直观看到「停点越早、步数越少、越不容易出错」。
