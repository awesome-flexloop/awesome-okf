# 示例三：写入一条偏好，再设一个两分钟的提醒

## 这个示例解决什么

前两个示例证明「它能干活」，这个示例证明「它记得你、也会主动叫你」。两件事分别对应 Agent 的记忆部件与运行时部件（见 [02 Agent 解剖](../concepts/02-agent-anatomy-react.md)）。

## 第一部分：写入偏好

### 步骤

1. 在对话里发（F-056）：

```text
记住：我买东西喜欢简单实用的款式。
```

2. 点开 App 底部的「记忆」页，确认刚才这条在列表里（F-057）。

**期望结果**：记忆页出现一条与「简单实用」相关的记录。课程说明这类记忆以 Markdown 文件形式存在手机的 App 目录里（F-058）。

### 验证「当次指令优先」

再发一句带冲突的指令，观察它是否按当次要求执行：

```text
这次要礼盒装，预算可以到 80 元。
```

课程说明：之后的任务会参考偏好，但你当次明确提的要求优先（F-060）。若它仍然只按「简单实用」执行，说明偏好被当成了硬约束——这时把当次要求写得更明确（如「忽略之前的款式偏好」）。

### 删除这条偏好

发（F-059）：

```text
忘记我喜欢简单实用的款式。
```

**期望结果**：记忆页里对应条目消失。课程说明对应的文件会被删掉。

## 第二部分：设一个两分钟的提醒

### 步骤

1. 发（F-061）：

```text
2分钟后提醒我喝水。
```

2. 立刻把 App 切到后台。
3. 等待通知弹出。

**期望结果**：约两分钟后收到通知。

### 时间边界

课程明确了两条限制（F-069）：

- **可能晚约一分钟**：建议等满 3 分钟再判断失败。
- **不支持重启后恢复**：手机重启后，这条提醒不会再触发。

## 通知不弹的四步排查

| 顺序 | 检查 | 判断 |
|------|------|------|
| 1 | 通知权限是否允许（F-046） | 没允许就不会弹 |
| 2 | App 的后台运行权限是否被限制 | 系统清理后台会导致不触发 |
| 3 | 是否等满了 3 分钟 | 可能晚约 1 分钟（F-069） |
| 4 | 期间是否重启过手机 | 重启后不恢复（F-069） |

## 验收

- [ ] 记忆页能看到刚写入的偏好
- [ ] 当次指令能覆盖偏好
- [ ] 说「忘记……」后条目消失
- [ ] 提醒在切到后台后仍能弹出
- [ ] 知道提醒可能晚约 1 分钟、重启后不恢复

## 边界与建议

- **不要写敏感信息**：记忆会进入模型上下文；课程在第二节课前的「3-2-1」准备里也明确要求不写敏感个人信息（F-077）。
- **不要依赖提醒做硬时点**：赶车、抢购、服药这类场景不适合用「尽力而为」的调度。
- **偏好要可判定**：把「便宜点」写成「单件不超过 30 元」，把「别乱买」写成「不经我同意不付款」。
- **记忆文件可以手工管理**：课程说它是 Markdown 文件，但未给出具体路径与命名规则（缺口 G-05）；在拿到源码或设备目录之前，不要凭猜测去改文件。
