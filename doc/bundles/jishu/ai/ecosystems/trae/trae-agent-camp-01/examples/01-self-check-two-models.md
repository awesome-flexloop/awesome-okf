# 示例一：两条指令自检聊天链与操作链

## 这个示例解决什么

装完 App、填完两个模型之后，你并不知道哪条链通了。这个示例用两条指令把「聊天」与「操作」分开验证，避免在错误的地方改配置。

## 前置条件

- [ ] App 已安装并能打开（`xiaoman-course.apk`，F-042）
- [ ] 通知权限已允许（F-046）
- [ ] 无障碍服务已开启并允许（F-047）
- [ ] 设置页两个模型都填了 Base URL、模型名、API Key（F-048）

## 步骤

### 第 1 条：验证聊天链

在助理的对话框里发（F-049）：

```text
你好，介绍一下你自己。
```

**期望结果**：有回复。

- 有回复 → 聊天模型通了，进入第 2 条。
- 无回复 / 报错 → 跳到下方「失败分诊 A」。

### 第 2 条：验证操作链

发（F-050）：

```text
打开设置里的 Wi-Fi 页面。
```

**期望结果**：手机自己跳到系统的 Wi-Fi 页面。

- 跳过去了 → 操作模型与无障碍都通了，本示例结束。
- 只回复不动 → 跳到「失败分诊 B」。
- 报错 → 跳到「失败分诊 C」。

## 失败分诊

### A. 聊天链不通（第一条没回复）

| 检查项 | 怎么查 | 判断 |
|--------|--------|------|
| Base URL | 设置页是否仍是 `https://ark.cn-beijing.volces.com/api/v3`（F-032、F-079） | 不一致就改回 |
| 模型名 | 是否与方舟控制台里的模型 ID 完全一致 | 大小写、连字符都要一致 |
| API Key | 是否完整粘贴、有没有多余空格 | 重新复制一次 |
| 额度与限额 | 方舟控制台看余额、推理限额、「安心体验」开关 | 报 429 时重点看这里（F-065） |

### B. 操作链不通（只回复不动）

按课程给的三个方向查（F-066）：

1. **操作模型的配置**：操作模型那一栏是不是空的，或者误填成了聊天模型。
2. **模型是否支持图片**：操作模型要看屏幕截图；不支持视觉的模型无法判断页面。官方模型列表把多模态理解与 GUI 任务处理列为 doubao-seed-2-1-pro-260915 的能力项（F-080）。
3. **无障碍服务是否被系统关掉**：部分系统会在后台清理或升级后关闭无障碍，回系统设置重新打开再试。

### C. 报 429 SetLimitExceeded

课程说明：账号额度或限额被卡住了，应到方舟检查推理限额、「安心体验」和余额；只充值不一定能恢复（F-065）。

处置顺序：

1. 看推理限额是否被设成了很低的值。
2. 看「安心体验」开关状态。
3. 看余额与免费额度是否用完。
4. 仍不行时，换一个可用的 Key 或模型，先确认链路本身没问题。

## 验收

- [ ] 第一条有回复
- [ ] 第二条手机自己跳到 Wi-Fi 页
- [ ] 知道自己刚才失败的是哪条链，以及改了哪个配置

## 边界

- 这个示例只能证明「链路通」，不能证明「任务能办好」。任务能力要在示例二里验。
- 不同品牌手机的系统页面名称略有差异；若系统里没有「Wi-Fi」字样（例如叫「WLAN」），可以把指令改成对应名称再试。
