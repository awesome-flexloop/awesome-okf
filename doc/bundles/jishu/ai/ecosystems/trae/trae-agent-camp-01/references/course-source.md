## 三、Chatbot 与 Agent

| 编号 | 事实 | 类别 |
|------|------|------|
| F-012 | 课程把日常 AI 聊天产品（例：豆包）归为 Chatbot：用户问一句、它答一句，答完之后事情仍需用户自己去办。 | 定义 |
| F-013 | 课程把 Agent 描述为：用户只说目标，它自己看屏幕、动手、检查结果，一直做到办完，或者遇到拿不准的地方停下来问。 | 定义 |
| F-014 | 课程的比喻是：Chatbot 像一个会出主意的朋友，Agent 更像一个能替用户跑腿的助理。 | 定义 |
| F-015 | 课程称从零开发一个手机 Agent 也可以，但需要不停试错、坑多，最终能否跑起来也不确定。 | 方法论 |
| F-016 | 课程推荐的路径是先装好已经开发完成的底座项目、先把它用起来，再用 TRAE 一点点改成想要的样子。 | 方法论 |
| F-017 | 课程主张这种「二次开发」的路子在 AI 时代对普通人效率最高。 | 方法论【讲师口径】 |

## 五、Agent 七件事与 ReAct

| 编号 | 事实 | 类别 |
|------|------|------|
| F-021 | 讲师把开课前收集到的问题归成 7 件事，包括怎么拆需求、怎么让它记住我、怎么接工具、怎么让它自己跑起来、跑错了怎么办。 | 结构 |
| F-022 | 课程指出模型本身只会「读进来、写出去」。 | 结构 |
| F-023 | 课程把围着模型补齐的部件列为：记忆让它记得你、技能告诉它怎么做、工具替它动手、闸门替你把关、运行时负责叫醒它、转圈和记账。 | 结构 |
| F-024 | 课程把中间这一圈循环称为 ReAct（Reason + Act）：先想这一步，再动手，看完结果接着想，直到办完。 | 结构 |
| F-025 | 课程指出记忆、技能、工具、闸门和运行时在小满 App 里已经做好，装上即可使用。 | 结构 |
| F-026 | 课程指出模型不在手机上，需要学习者自行去火山方舟开通，再把 Key 填进 App。 | 结构 |
