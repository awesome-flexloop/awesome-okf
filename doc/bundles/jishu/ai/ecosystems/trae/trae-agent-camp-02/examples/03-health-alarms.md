# 示例三：健康闹钟（health-alarms）

## 这个示例解决什么

久坐容易忘了起来活动、忘了喝水，但提醒又不能撞上课和开会。目标是让助理按你的作息挑空档，**直接在系统时钟里设好**，并且不动你原有的闹钟。

这个场景属于 `channel: gui`——需要操作真实的手机界面，验收也在系统时钟里，不在对话里。

## 前置条件

- [ ] adb 桥已搭好
- [ ] 记忆里已有作息；没有就先记一条（F-055）：

```text
记住：我工作日上午 9 点到 12 点上课，下午 2 点到 3 点开会。
```

## 第 1 步：在手机上先试一次

发（F-053）：

```text
帮我在今天下午 3 点、4 点、5 点各设一个闹钟，标签写“起来活动，喝水”。设好后打开闹钟列表给我看。
```

**观察点**：它能不能真的在系统时钟里建好这三个闹钟？标签写对了吗？最后有没有打开列表？

这句话直接给了时间，所以它不需要读记忆。记下这句话，第 3 步还要用。

## 第 2 步：在 TRAE 里改技能并推送

发（F-054）：

```text
请参考 skills/examples/set-alarm，新建技能 skills/examples/health-alarms，用 docs/skills.md 里的内置链接 xiaoman://alarm/set 打开预填好的新建闹钟页，不要拨滚轮。
我说“设健康闹钟”时，按我记忆里的作息（比如上课、开会的时间段）挑空档，
每个闹钟标签写清楚做什么（喝水、起来活动）。
设之前把时间列给我确认；设完打开闹钟列表核对每一条都在，少了就告诉我。
不删除、不修改我原有的闹钟。完成后帮我校验并推送到手机，再说明改了什么。
```

这段提示词里有三个关键设计：

| 设计 | 作用 |
|------|------|
| 用内置链接 `xiaoman://alarm/set` | 打开预填好的新建闹钟页，避免拨滚轮这种脆弱操作 |
| 设之前先列时间给你确认 | 把「设几个、设在哪」的决定权留给人 |
| 不删除、不修改原有闹钟 | 防止清理旧闹钟时误删你的关键提醒 |

## 第 3 步：回到手机复测

对助理说「设健康闹钟」。它会先列出时间，确认后再去系统时钟设。

然后到系统时钟的列表里核对（F-057）：

- [ ] 每个闹钟的时间对
- [ ] 每个标签写清了做什么
- [ ] 原有闹钟没被修改或删除
- [ ] 原有闹钟的开关状态没变

> 不同品牌的时钟界面不一样，以你手机上的列表为准。第 1 步那种直接给时间的说法，对应的是 15:00、16:00、17:00 三个闹钟。

如果今天的空档已经过了，助理会先问你改到哪天、几点（F-056）。

## 验收清单

- [ ] 内置链接能打开预填的新建闹钟页
- [ ] 时间按作息挑，不是随便定
- [ ] 设前有你确认这一步
- [ ] 系统时钟里逐条都能对上
- [ ] 原有闹钟未变

## 收尾

练完把练习闹钟删掉。删除也建议由你手动在系统时钟里完成，或明确对助理说「删除刚才设的三个练习闹钟，别的不要动」——把删除范围说死，避免它扩大范围。

## 边界

- iPhone 与鸿蒙 5 及以上无法在手机端验收，可与安卓同学结对看系统时钟（F-004）。
- 闹钟是系统能力，不是 App 内提醒；两者的可靠性不同，不要混用。
