# 示例六：资讯速览（ai-news-brief）

## 这个示例解决什么

每天的 AI、竞品、行业资讯太多。目标是只挑**和你有关**的几条，每条说清为什么相关，并附上能核对的来源。

## 前置条件

- [ ] 小满可正常对话
- [ ] 已在 App 的「服务」里打开「AI 热点」（F-070）
- [ ] adb 桥已搭好（推送需要）

## 第 1 步：记下身份与关注点

发（F-070）：

```text
记住：我是产品经理，关心 AI 助手和 Agent 的新产品，不关心芯片和融资新闻。
```

这句话同时定义了「要什么」和「不要什么」。后者同样重要——不写「不关心什么」，助理会按泛化的「热门」来挑。

## 第 2 步：先问一次

发（F-071）：

```text
今天有什么 AI 热点？只挑 3 条和我有关的，每条一句话说清楚为什么和我有关，附上来源。
```

**观察点**：有没有用当天的服务？是不是只挑了 3 条？来源是媒体名还是链接？不足 3 条时有没有直说？

记下这句原话，第 4 步复测。

## 第 3 步：在 TRAE 里改技能并推送

发（F-072）：

```text
请参考 docs/skills.md 里“聊天工作流（channel: chat）”的写法，创建或调整技能 skills/examples/ai-news-brief。
我问“今天有什么 AI 热点”时，先读记忆里的身份和关注点，再调用 AI 热点服务取当天资讯。
按偏好只挑最相关的 3 条；和偏好无关的不要，不够 3 条就如实说明。
每条写标题、一句话说明为什么和我有关、来源媒体和工具给出的链接；没链接写“来源：页面未给出链接”。
没开服务就提示我在“服务”里打开“AI 热点”，不要凭印象编新闻。最后问我要不要展开某一条。
完成后帮我校验并推送到手机，再说明改了什么。
```

三条规则值得单独记：

| 规则 | 防的是什么 |
|------|------------|
| 不够 3 条如实说明 | 用旧闻或无关新闻凑数 |
| 没链接写「来源：页面未给出链接」 | 编造链接或含糊其辞 |
| 没开服务就提示去打开，不凭印象编新闻 | 模型用训练记忆伪造「今日热点」 |

## 第 4 步：回到手机复测

把第 2 步的问题原样再问一次，核对（F-073）：

- [ ] 用的是当天的热点服务
- [ ] 按偏好最多 3 条
- [ ] 每条有一句「为什么和我有关」
- [ ] 每条有来源媒体，有链接的给链接，没链接的如实标注
- [ ] 不足 3 条时直说

> 新闻以当天为准，任何示例条目都会过期。本包不复制课程录屏里的具体新闻。

## 验收清单

- [ ] 身份与关注点已在记忆里
- [ ] AI 热点服务已打开
- [ ] 改前改后回复有可见差异
- [ ] 条数、相关性、来源三项都能对上
- [ ] 没有编造的新闻或链接

## 变体练习

换一个身份，观察筛选结果如何变化：

```text
记住：我是电商运营，关心平台规则变化和大促节奏，不关心模型技术细节。
```

如果它仍然推技术细节，说明技能里「按偏好筛」这一步写得太笼统——把「不关心」的类别也写进技能规则。

## 边界

- 本场景依赖「AI 热点」服务；服务未开时技能应提示而不是编新闻（F-072）。
- 资讯内容以当天为准，可能与你已有的认知冲突；以原始来源为准。
- 资讯里的数字若用于对外发布，需另行核验。
