# 示例二：今日开工卡（today-plan）

## 这个示例解决什么

早上要做的事散在各处，不知道该先做哪件。目标是让助理排一份**最多 3 件**的开工卡，把其余放进「可以先放放」，并在你同意后给第一件设提醒。

## 前置条件

- [ ] adb 桥已搭好（示例一第 3 步）
- [ ] 已用 TRAE 打开 xiaoman 源码
- [ ] 手机上小满可正常对话

## 第 1 步：在手机上先试一次

发（F-048）：

```text
我今天要做：交实验报告（今晚 12 点截止）、回导师邮件、买牛奶、复习英语 30 分钟。帮我排一下。
```

**观察点**：它有没有分先后？会不会一口气列出十几件？有没有问你截止时间？

把这句话**记下来**，第 3 步要原样再发一次。

## 第 2 步：在 TRAE 里改技能并推送

发（F-049）：

```text
请参考 docs/skills.md 里“聊天工作流（channel: chat）”的写法，新建技能 skills/examples/today-plan。
触发：我说出今天要做的几件事，或者说“帮我排今天”。
步骤：先按“今天不做会卡住谁”和截止时间排序，最多挑 3 件写成今日开工卡，其余放进“可以先放放”；
不确定截止时间的先问我，不要猜。
最后问我要不要给第一件设提醒，我同意才设，设好后告诉我提醒时间。
不能做：不替我发消息、不替我付款。完成后帮我校验并推送到手机，再说明改了什么。
```

**期望结果**：TRAE 先说明改哪里，写入后运行 lint 与 push，回复里出现 `0 problem(s)` 与 `pushed`（F-046）。

如果源码里已有 `today-plan` 文件夹，TRAE 会在原文件上按你的规则改，效果一样（F-045）。

## 第 3 步：回到手机原样复测

把第 1 步那句话再发一次，核对三点（F-050）：

- [ ] 开工卡最多 3 件
- [ ] 按「今天不做会卡住谁」和截止时间排序，其余进「可以先放放」
- [ ] 没写截止时间的事，它会先问你

**排序结果最终由你决定**——助理给的是建议，不是命令。

## 第 4 步：验证提醒

对助理说「给第一件设个提醒」或按它给出的问法确认。同意后把 App 切到后台，等通知弹出，核对时间（F-051）。

提醒的限制：

| 限制 | 表现 | 应对 |
|------|------|------|
| 只响一次 | 错过就没了 | 重要事项不要只靠它 |
| 不保证准点 | 可能晚一点 | 留出余量，等几分钟再判断失败 |

## 验收清单

- [ ] 改前改后回复有可见差异
- [ ] 最多 3 件，其余进「可以先放放」
- [ ] 不确定截止时间会先问
- [ ] 同意后才设提醒，且通知真的弹出
- [ ] 没有发消息、没有付款

## 变体练习

把输入换成你自己的真实清单，保持四问完整：

```text
我今天要做：写周报（周五 18 点前）、牙医预约、取快递、给客户回电话。帮我排一下，
最多 3 件，其余放“可以先放放”。
```

如果排出来的顺序不符合你的判断，不要改助理，先改技能里的排序规则——把「今天不做会卡住谁」换成你自己的判据（例如「先做有外部截止时间的」）。
