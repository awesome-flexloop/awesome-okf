# 程序层改造：让助理在手机上自己写技能

## 技能层的能力天花板

前面五个场景都是同一套动作：在电脑上把需求说给 TRAE，TRAE 写成 SKILL.md，再用数据线推到手机。技能写得再多，也离不开那台电脑和那根线（F-074、F-075）。

出门在外突然想加一个技能，就没有办法了。**课程版 App 会用技能，但不会写技能**（F-074）。想让它会写，就要动第三层：程序。

## 三条路径看清位置

课程用三条路径说明这件事（F-075）：

| 路径 | 谁写技能 | 需要什么 | 状态 |
|------|----------|----------|------|
| 上路 | 电脑上的 TRAE | 电脑 + 数据线/Wi-Fi + adb | 五个场景走的路，已存在 |
| 中路 | 手机上的小满 | 只需要手机 | 本部分要做出来的 |
| 下路 | 先改一次程序 | 电脑 + 安卓构建环境 | 慢路，但它是中路存在的前提 |

三条路径最后写进的是**同一个技能目录**，区别只在「写技能的手」换了。

## 改程序也是四件事，但最后一条变了

交给 TRAE 的仍是四件事：想要什么、举一个例子、不能做什么、怎么算完成（F-076）。区别在最后一条：

> 改程序要先有测试，测试全部通过、**能构建出新的安装包**，才算改完。

这条把「程序层」和「技能层」的验收标准彻底分开了：

| 层 | 完成判据 |
|----|----------|
| 技能 | lint 通过 + push 成功 + 手机复测行为正确 |
| 程序 | 测试全过 + 构建出新 APK + 装机后按例子跑通 |

## 课程给的需求提示词

```text
请先阅读 README.md、docs/skills.md，以及 core-agent 里的 ChatTools.kt、AgentTools.kt、Prompts.kt，告诉我你打算改哪些文件、怎么改，我同意后再动手。
我想要：在手机上跟小满说一句话，它就能新建、修改、删除技能，技能页里也能看到。
举个例子：我说“帮我加一个技能，每天晚上我说‘复盘’，就问我今天做成了哪三件事、明天最重要的一件是什么，答完记进记忆”，它写好 SKILL.md 先给我看，我回复“确认”才保存。
不能做：不经我确认，不能写入或删除技能；装在 App 里的内置技能不能删；技能里不能写密码、Key、手机号；不改 skills/examples 里的示例。
怎么算完成：新加的单元测试和原有测试全部通过，构建出新的 APK，装到手机上能按上面的例子跑通。
```

这段提示词有四层结构，值得逐层拆：

| 层 | 内容 | 作用 |
|----|------|------|
| 先读再改 | README、docs/skills.md、三个 Kotlin 文件 | 强制先建立地图，且先说明改哪些文件 |
| 我想要 | 一句话新建/修改/删除技能 | 目标单一 |
| 举个例子 | 一个完整的「说一句话 → 给看 → 确认 → 保存」 | 把验收标准具体化 |
| 不能做 | 未经确认不写、内置不能删、不写密钥、不改示例 | 四条红线 |
| 怎么算完成 | 测试全过 + 构建 APK + 装机跑通 | 可判定 |

## 程序改了哪三处

课程用一张图说明：左边是改完以后手机上的一段对话，右边三张卡片是程序里改的地方，各对应对话里的一处（F-078）。

其中最关键的是第二处：**确认关卡写在程序里**。前面写技能时，「哪一步交给你确认」写在技能里；这次写在程序里——不管助理写出什么技能，没有你回的「确认」，都存不进手机。

这形成了一道双保险：

| 层 | 闸门 |
|----|------|
| 技能层 | 技能里写「保存前先给我看、我确认才存」 |
| 程序层 | 没有「确认」这个输入，写入动作根本执行不了 |

> 技能层是「规则约束」，程序层是「能力约束」。规则可以被写歪，能力边界不会。这条对照是本包对课程设计的解读。

## 在手机上验收四点

课程给的验收清单（F-079）：

- [ ] 保存之前一定先给你看、要你确认
- [ ] 技能页里多了一个标着「我的」的技能
- [ ] 再说一次触发的那句话，它照新技能做
- [ ] 内置技能删不掉；你写的同名技能删掉以后，回到原来的版本

第三点最容易被跳过：**新技能不是「出现在列表里」就算成功，要能被触发并正确执行**。

### 回退的风险

想回到课程版，**要先卸载再装课程版 APK**；卸载会清掉 App 里的记忆与技能，先备份（F-081）。

这是整个第二课最需要提前准备的一步。备份对象至少包括：

- 记忆目录（个人档案、错题）
- 技能目录（你改过的 SKILL.md）

备份方式可以复用第二部分的 adb 思路：把文件 `adb pull` 到电脑，需要时再 `adb push` 回去。

## 环境要求

改程序、重新构建安卓 App 需要 **JDK 17 与 Android SDK 35**（F-111，课程当前环境口径）。课程的做法同样是让 TRAE 按源码说明安装，安装前先说明方案、你同意再动手（F-110）。

## 还能接着改什么

课程给了两个延伸方向（F-082）：

- 加一个语音输入按钮；
- 让它每周把你常说的话整理成新技能的草稿，交给你挑。

做法一样：说清四件事、先写测试再改、装到手机上验收。

## 什么情况下不该改程序

- 需求用技能就能表达（多会一件事、换一套做法）——先改技能，成本低一个量级。
- 你还没有跑通五个场景中的任意一个——先建立基线。
- 你没有备份记忆与技能——先备份，再动安装包。
- 你不能接受「一次构建失败要重来」——程序层的反馈周期以分钟到十分钟计，不是秒级。
