# 个人档案：把 3-2-1 变成助理的记忆

第一课教的是一条一条说「记住：……」。这一课升级为一次写入一份**结构化档案**——因为零散的偏好会互相冲突，而档案能写明「哪条是规则、哪条是例子、哪条是底线」。

## 两步法

课程把「让助理懂你」拆成两步（F-016）：

1. **在 TRAE 里把习惯整理成一份个人档案**（结构化、可读、可改）。
2. **把档案内容告诉助理，存进它的记忆**（手动逐条发，或通过 adb 整份推）。

## 第 1 步：写下你的 3-2-1

在两分钟里写下（F-017）：

- **3 条偏好**：买东西先看评价，预算宁低勿高；回复先说结论，别太长；晚上 10 点以后别给我排事。
- **2 件常做的事**：每天早上排一下今天要做的事；备考期间每天做几道题。
- **1 条底线**：付款、对外发消息之前，一定先问我。

写的时候不用正式，但尽量让每一条**可判定**：把「便宜点」换成预算区间，把「别烦我」换成时间点。

## 第 2 步：交给 TRAE 整理成档案

课程给的提示词（F-018）：

```text
下面是我的 3 条偏好、2 件常做的事和 1 条底线：
（贴上你写的内容）
请帮我整理成一份助手能用的个人档案：每条偏好写成一句清楚的规则，并给一个例子；
常做的事写成“我说什么 → 希望它怎么做”；底线单独列出。
不要加入我没提到的信息，地址和手机号先不要写进去。
```

这段提示词有三个约束值得单独记住：

| 约束 | 作用 |
|------|------|
| 每条规则配一个例子 | 让助理知道规则的边界，而不是只记住一句形容词 |
| 常做的事写成「我说什么 → 怎么做」 | 这已经是技能的雏形（下一步会用到） |
| 不加入未提到的信息、不写地址手机号 | 防止 AI 替你补全不存在的信息，也防止敏感信息进记忆 |

档案生成后先逐条读一遍，不认同的直接改，确认后再存（F-019）。

## 第 3 步：存进记忆的两种方式

### 方式一：手机上手动发（零配置）

给每条前面加「记住：」再发送，等它回复已记住后再发下一条（F-020）。适合档案条目少、或暂时不想连电脑的情况。

### 方式二：adb 一次推送（可批量、可重复）

课程把 adb 比作电脑与手机之间的一座「桥」，adb 命令由 TRAE 运行，不需要你自己敲（F-022）。

#### 先搭桥：三步

| 步骤 | 做什么 | 成功标志 |
|------|--------|----------|
| 1 | 电脑装好 adb | 能运行 `adb devices -l` |
| 2 | 手机开 USB 调试：设置 → 关于手机，连点「版本号」7 次，再进开发者选项打开「USB 调试」 | 开发者选项里开关是开的 |
| 3 | 用能传数据的线连接并在手机上点「允许」 | 手机不再弹授权窗 |

然后让 TRAE 运行 `adb devices -l`，按末尾状态判读（F-024）：

| 末尾显示 | 说明 | 怎么办 |
|----------|------|--------|
| device | 桥搭好了 | 继续下一步 |
| unauthorized | 手机上还没点「允许」 | 解锁手机，点允许 |
| offline | 连接不稳 | 换一根线重插 |
| 一台设备都没有 | 多半是 USB 调试没打开 | 回第 2 步再查 |

> **不想插线**：同一 Wi-Fi 下，开发者选项打开「无线调试」（Android 11 及以上），点「使用配对码配对设备」，把 IP、端口与配对码告诉 TRAE（F-025）。手机重启或换 Wi-Fi 后要重新告知；课堂人多时优先用数据线。

#### 再推送：一段提示词四步走

课程给的提示词（F-026）：

```text
请把刚才整理好的个人档案存进手机上小满的记忆，用 adb 来做：
1. 先运行 adb devices -l，确认手机那一行显示 device；没连通就先告诉我哪里不对。
2. 按 docs/ARCHITECTURE.md“记忆”一节的格式，把档案写成一份 Markdown 笔记，存到电脑上的 memory/profile.md：
   标题用“个人档案”，偏好、常做的事、底线每条占一行，内容和档案一致，不要增减。
3. 用 adb push 把它放到手机的 /sdcard/Android/data/dev.xiaoman.app/files/memory/profile.md。
4. 推完用 adb shell ls 看一下这个文件夹，告诉我手机上多了什么。
手机里已有的记忆不要删，也不要覆盖。
```

### 档案文件的真实格式

源码确认（S-011、S-013）：记忆目录为 `/sdcard/Android/data/dev.xiaoman.app/files/memory/`，permalink 为 `profile` 的笔记落到 `profile.md`。文件是 Basic Memory 风格的 Markdown：

```markdown
---
title: 个人档案
type: note
permalink: profile
tags: []

---

# 个人档案

## Observations
- [preference] 买东西先看评价，预算宁低勿高 (来源：3-2-1)
- [routine] 每天早上排今天要做的事
- [boundary] 付款、对外发消息前先问我

## Relations
```

三点注意：

- **permalink 决定路径**：`profile` → `memory/profile.md`；`places/家` → `memory/places/家.md`。
- **观察行的形态固定**：`- [类别] 内容 #标签 (上下文)`；普通项目符号不会被解析为观察（S-013）。
- **adb push 是整文件覆盖**：源码自身的写入是原子的（临时文件 + 重命名），但 adb push 不合并；覆盖前先备份旧文件（S-011）。

这段提示词的工程价值在于**每一步都可核对**：连没连上、文件写在哪、推到哪、手机上多了什么。它也明确写了「已有记忆不要删、不要覆盖」——这是批量写入时最容易出的事故。

#### 到手机上验一眼

打开 App 底部「记忆」，能看到「个人档案」这一条（F-027）。没看到就退出记忆页再进；仍没有，把 TRAE 的回复原样发回给它查原因。

以后档案有改动，对 TRAE 说「把改好的档案再推到手机」即可（F-028）。

## 第 4 步：验证它真的记住了

发三句话（F-029）：

```text
记住：买东西先看评价，预算宁低勿高。
帮我挑个耳机。
今天帮朋友买，预算放宽到 200。
```

| 你发 | 期望行为 | 验证的是 |
|------|----------|----------|
| 第一句 | 回复已记住，记忆页多一条 | 能存进记忆 |
| 第二句 | 你没再提要求，它也会先看评价、按偏低预算挑 | 换个说法也记得 |
| 第三句 | 这次按 200 元挑，原偏好仍在 | 当次要求优先 |

三句都对上，说明它既记住了你，也分得清长期偏好与当次要求（F-030）。哪一句没对上，就把它的回复原样贴给 TRAE，让 TRAE 改写档案里对应那条，再重新告诉助理（F-031）。

## 边界与风险

- **不写敏感信息**：地址、手机号、证件号、银行卡号不写进档案（F-018）；记忆会随任务进入模型上下文。
- **不覆盖已有记忆**：批量推送前确认目标目录已有内容，提示词里写死「不要删、不要覆盖」。
- **可分享性**：记忆是 App 目录里的 Markdown 文件，分享前去掉个人信息（F-100）。
- **格式已核验**：记忆目录、文件命名与 Basic Memory 结构由源码确认（S-011、S-013），原缺口 G-05 关闭；课程文档未展开的细节可在源码 `core-memory` 中查到。
