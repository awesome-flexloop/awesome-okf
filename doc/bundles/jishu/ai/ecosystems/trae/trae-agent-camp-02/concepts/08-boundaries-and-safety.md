# 边界与安全：改得越多，越要守住闸门

第二课教的是「改造」。改造意味着你开始给助理写规则、加能力、甚至改程序，**每多一分能力，就多一个需要守住的关口**。这一篇把课程散落在各处的边界集中起来。

## 本期的硬边界

| 边界 | 内容 | 依据 |
|------|------|------|
| 手机端支持 | 安卓与鸿蒙 4.x 及以下；iPhone 与鸿蒙 5 及以上不支持 | F-004 |
| 不能做的事 | 不读微信/QQ 群消息、不控制电脑 | F-100 |
| 比价范围 | 只比当天淘宝搜索结果里的价格；历史低价与跨平台比价为课后挑战 | F-100 |
| 提醒能力 | 只响一次，不保证准点 | F-051 |
| 体验额度 | 已随结课失效；长期使用需自己的方舟 Key | F-011、核验报告 P0-4 |

这些边界不是「暂时没做」，而是本期明确不做。把需求写在这之外，课程不会给你可验收的结果。

## 记忆与技能文件的泄露面

第二课新增了两类可被 adb 直接读写的文件：

| 文件 | 位置 | 里面可能有什么 |
|------|------|----------------|
| 记忆 | `Android/data/dev.xiaoman.app/files/memory/` | 个人档案、偏好、错题、身份与关注点 |
| 技能 | `Android/data/dev.xiaoman.app/files/skills/<技能名>/` | 你的工作流、检查点、红线 |

三条风险（F-026、F-100）：

1. **分享即泄露**：把记忆或技能文件发给别人排障时，个人信息一并出去了。
2. **截图出设备**：手机操作时的截图会发给你配置的模型做判断；记忆内容也会进入模型上下文。
3. **批量写入覆盖**：用 adb 整份推送时，若目标目录已有内容，可能覆盖旧记忆——课程提示词里明确写了「已有的记忆不要删，也不要覆盖」。

实践建议（属本包建议）：

- 分享前用编辑器打开 Markdown 删掉姓名、地址、手机号、公司名。
- 需要给别人看技能时，先复制一份、删掉与个人相关的触发语。
- 备份文件不要放在公开仓库或群共享里。

## 双闸门：规则约束与能力约束

第二课最有价值的安全设计，是把确认关卡写了两遍（F-078）：

| 层 | 闸门形态 | 能被绕过吗 |
|----|----------|------------|
| 技能层 | SKILL.md 里写「保存前先给我看、我确认才存」 | 能——技能可以被写成不遵守，或被换掉 |
| 程序层 | 没有收到「确认」这个输入，写入动作执行不了 | 不能——这是能力边界，不是规则 |

**规则约束管「应该」，能力约束管「能不能」。** 涉及不可逆动作时，优先把闸门下沉到程序层。

## 不可逆动作清单

课程明确：付款、发送、删除之前，助理一定先问；密码框它也输入不了（F-105）。把这张清单扩展到本期能碰到的动作：

| 类别 | 具体动作 | 谁来决定 |
|------|----------|----------|
| 钱 | 付款、下单、领付费券、充值 | 人 |
| 对外 | 发消息、发邮件、发帖、提交表单 | 人 |
| 数据 | 删除记忆、删除技能、删除闹钟、卸载 App | 人（卸载会清数据） |
| 身份 | 登录、滑块、验证码、实名 | 人 |
| 凭据 | 输入密码、粘贴 API Key | 人不让 Agent 碰 |

后两类不是「Agent 做不好」，而是**设计上就不该由 Agent 做**。课程在淘宝场景里明确：登录和滑块要本人完成（F-062）。

## 改程序时的特有风险

| 风险 | 说明 | 处置 |
|------|------|------|
| 卸载清数据 | 回退到课程版要先卸载，卸载会清掉记忆与技能 | 先 `adb pull` 备份记忆与技能目录 |
| 签名不一致 | 自行构建的 APK 与课程版签名不同，安装时会提示 | 先卸载旧版再装；同样先备份 |
| 测试未过就装机 | 新功能可能破坏原有流程 | 以「新增与原有测试全过 + 构建成功」为准入 |
| 技能里写密钥 | 课程明确技能里不能写密码、Key、手机号 | 凭据只放 App 设置页 |

## 改坏了怎么办

课程给的顺序是：**先退回改之前的版本，再把现象和证据交给 TRAE**（F-100）。不要在原版本上继续叠改。

## 分享与作业的脱敏

作业要求提交执行截图与开发过程截图（F-107）。提交前：

- [ ] Key、手机号、地址已打码
- [ ] 记忆页截图里没有个人档案的敏感字段
- [ ] 运行日志里的绝对路径与设备序列号已处理
- [ ] 没有把课堂体验令牌贴进帖子

## 一句话总结

改造的边界不是「能改多少」，而是「改完之后，哪些动作仍然必须由人按下确认」。守不住这一点，能力越强越危险。
