# 工作流与技能：把一件事写成 SKILL.md

先给三个词一句白话释义：

- **工作流**：一件事从开始到做完的步骤。比如比价：搜索商品、看前三家、列成表格、停在最便宜那家的商品页。
- **技能**：把一条工作流写成助理看得懂的说明书，存成一个 `SKILL.md` 文件。
- **channel**：技能的执行通道。课程文档出现 `chat` 与 `gui` 两种写法；源码枚举为 `api`、`cli`、`deeplink`、`gui`（默认）、`deeplink-then-gui`、`mixed`，没有 `chat`（见下文「channel：源码里的真实取值」）。

前两个词来自课程定义（F-032、F-033）；`channel` 的取值以源码枚举为准（S-035），课程提示词中的 `chat` 属未核验写法。

## 一次对话发生了什么

用户说一句话 → 助理先找到对应的技能 → 再照里面的步骤一步步做（F-034）。

这个顺序解释了两件事：

1. **技能是「被选中」的**。所以技能的触发描述要写得像用户的真实说法，否则匹配不上。
2. **技能是「被执行」的**。所以每一步要写清读什么、做什么、交什么，而不是只写目标。

多条工作流需要串起来时，再写一个负责调度的技能（F-035）——这就是第六部分多助理的雏形。

## 四问：写技能前的必答题

| 问题 | 要写清什么 | 课程要点 |
|------|------------|----------|
| 什么时候开始 | 你说了哪句话，或到了什么时间 | 本节课的练习都是你开口触发 |
| 一步步做什么 | 先读什么、再做什么、最后交给你什么 | 顺序可执行，不依赖助理临场发挥 |
| 怎么检查 | 做完去哪里核对：页面、闹钟列表、记忆还是通知 | 没做到的地方要如实告诉你 |
| 哪一步交给你确认 | 付款、删除、对外发消息必须等你确认 | 设提醒这类事也先问一声 |

四问的答案最后都写进同一份 `SKILL.md`（F-037）。

### 四问里最容易被省略的是第三问

「怎么检查」不是写给助理看的礼貌用语，而是**验收接口**。它决定了三件事：

- 助理知道做完后去哪里核对；
- 你知道回到手机后看哪里；
- 结果不对时，双方有共同的判断依据。

课程在五个场景里都给了具体检查点：开工卡看卡片件数与排序、健康闹钟看系统闹钟列表、比价看表格与停留页面、出题看记忆里的错题条目、资讯看来源与条数。**检查点越具体，越不需要反复调提示词。**

## 技能文件在哪

| 位置 | 路径 | 用途 |
|------|------|------|
| 课程源码（电脑） | `skills → examples → 技能名 → SKILL.md` | 查看、修改、让 TRAE 读 |
| 手机（推送后） | `Android/data/dev.xiaoman.app/files/skills/技能名/` | 被 App 加载执行 |

课程版 APK 已内置五个场景的技能：`today-plan`、`health-alarms`、`taobao-compare`、`daily-quiz`、`ai-news-brief`，装在 App 的「技能」页能看到（F-038、F-039、F-040）。

推送后同名技能会被替换为你推入的版本（F-040）。这意味着**改技能不需要重装 App**——这是技能层最大的效率优势。

### SKILL.md 的七个合法字段

源码只接受七个 frontmatter 键，出现其他键会被判为问题（S-033、S-034）：

| 字段 | 必填 | 规则 |
|------|------|------|
| `name` | 是 | 匹配 `[a-z0-9-]+`，应与文件夹同名 |
| `description` | 是 | 非空、单行；聊天模型靠它挑技能 |
| `apps` | 否 | 可操作的包名列表；设置后越界操作会被拒绝 |
| `channel` | 否 | 六种取值之一，默认 `gui` |
| `confirm_before` | 否 | 追加的确认词，不能删除内置词 |
| `memory` | 否 | 加载进操作提示词的笔记 permalink |
| `deeplinks` | 否 | `名称: "scheme://..."`，占位符由操作模型填写 |

可选的 `flow.yaml` 只有在 `SKILL.md` 本身有效后才会被校验；步骤类型为 `launch`、`deeplink`、`ai`、`confirm`、`tap`、`type`、`wait`、`assert`，`wait` 取 0..600000 毫秒（S-036）。

## channel：源码里的真实取值

02 课提示词里用的 `channel: chat` 已进入源码枚举；`docs/skills.md` 专门有一节「聊天工作流（channel: chat）」。源码 `SkillChannel` 的取值为（S-035）：

| 取值 | 含义（按源码与技能示例） | 典型场景 |
|------|--------------------------|----------|
| `api` | 通过 API 调用完成，不操作界面 | 课程未给示例 |
| `cli` | 通过命令行完成 | 课程未给示例 |
| `deeplink` | 只打开一个深链 | 课程未给示例 |
| `gui`（默认） | 需要操作手机界面 | 健康闹钟、淘宝比价、`set-alarm` |
| `deeplink-then-gui` | 先深链、再界面操作 | `taxi-home` |
| `mixed` | 混合 | 课程未给示例 |
| `chat` | 流程只在对话内完成，不操作其他 App | 今日开工卡、每日出题、资讯速览 |

> **版本提示**：2026-11-17 核验时公开分支还没有 `chat`；2026-11-18 复读时 `main` 已包含该枚举值与对应文档（S-035）。写技能时以当前仓库 `docs/skills.md` 为准：填未知 `channel` 会被 lint 判为问题（S-034、S-047）。

## 先读懂一份现成技能

课程给的读技能提示词（F-041）：

```text
请打开 skills/examples/set-alarm/SKILL.md，用大白话对照四问逐段讲给我听：
什么时候开始、一步步做什么、怎么检查、哪一步交给我确认。
再说明 channel: chat 和 channel: gui 有什么区别。
先只讲解，不要修改任何文件。
```

注意最后一句：**先只讲解，不要修改任何文件**。这与第一课「只讲不改」是同一条纪律——先建立地图，再动墙。

### 读懂的标准

不看 TRAE 讲得多长，看你能不能回答四个问题：

- [ ] 这份技能由哪句话触发
- [ ] 它按什么顺序做事，最后交给你什么
- [ ] 它做完去哪里核对
- [ ] 它会在哪一步停下来等你确认

四问都能答上来，再开始写自己的技能。

## 从档案到技能：一步之遥

第二部分的个人档案里，「常做的事写成『我说什么 → 希望它怎么做』」其实已经是技能草稿（F-018）。把它补上「怎么检查」与「哪一步确认」，就是一份可用的技能。

所以改造顺序可以是：**偏好进记忆 → 常做的事进技能 → 界面与能力进程序**。这也是本包建议的三层顺序（见 [00 课程地图](00-course-map.md)）。
