# 站点画像与学习地图

Kanzan 是以“看山AI实验室”为品牌的 AI 场景、应用和团队服务站点。官网把服务分成场景识别、系统构建、团队能力建设三条线，博客则用产品设计、企业实践、创业观察与研究解读展开这些主题。[事实 F-001、F-002、F-007](../references/facts.md)

## 对象与证据

| 对象 | 从站点可以学到什么 | 不能直接据此认定什么 |
|---|---|---|
| 公司与服务 | 服务方向、咨询准备、官网自述主体 | 工商状态、实际交付数量、SLA 与客户成效 |
| 产品 | OPC Feed、LifeFrame、BullyStop 的作者定位 | 当前全部功能、价格、合规状态和生产质量 |
| 工程文章 | 流程分层、失败边界、部署顺序 | 任意版本可照搬的完整配置 |
| 研究解读 | 用户需求、形式化验证的方法启发 | 全球人口比例、通用 Agent 成功率 |
| 创业观点 | 场景选择、地方实践和政策建议 | 政府政策、职业收益或商业成功保证 |

关于页自述运营主体是淮安看山人工智能科技有限公司，成立于 2026-04-23；相关登记信息本次没有独立工商核验。入驻文章中的门牌名称与公司简介不完全相同，使用时应区分品牌、门牌和登记主体。[F-004～F-006](../references/facts.md)

## 阅读顺序

1. 先读[场景评估与知识治理](01-use-cases-and-knowledge.md)，把业务任务、资料、责任人与验收条件接起来。
2. 再读[Agent 与事件契约](02-agent-and-event-contracts.md)，区分接入协议、任务方法和组织规则。
3. 按场景读[产品与工业边界](03-products-and-industrial-boundaries.md)，理解照片、工作 Feed 和视频场景的数据差异。
4. 进入[成本与交付](04-cost-and-delivery.md)，学习如何核算任务成本、识别部署完成。
5. 最后读[研究启发与候选模式](05-research-and-transfer.md)，区分可迁移的方法和必须重新验证的结论。

“全面学习”在这里指公开中文栏目与博客索引：6 个栏目页面及 21 篇文章正文。英文镜像、后台、登录后产品功能和关联产品站全文不在成功覆盖范围内；站点地图还有三个抓取返回 404 的独有 URL。[F-047、F-048](../references/facts.md)

## 术语入口

| 术语 | 本包用法 |
|---|---|
| 场景评估 | 在开发前明确任务、流程、资料、风险与验收 |
| MVP | 用较小产品范围验证关键假设，不等于省略安全和验收 |
| Agent | 能结合模型判断与工具执行处理任务的系统 |
| MCP | 应用与工具/数据提供方交换上下文的协议 |
| Skill | 可复用的任务说明与配套资源；不自动赋予执行权限 |
| EventType | 作者提出的工作事件类型契约；不是本包已验证 API |
| Headless CMS | 内容管理与展示解耦的内容系统 |
| FDE | 深入真实业务现场协同部署的工程角色，具体职责依组织而异 |

MCP 和 Skill 的标准定义在第二篇给出官方来源；MVP、Agent 等解释是本包教学用语，不是 Kanzan 专有定义。

## 学习与采购的分界

联系页展示 `hello@kanzan.top`，建议咨询者说明业务背景、问题、阶段与交付期待。本次没有联系公司、提交表单或试用在线接待智能体。法律页仍为隐私政策与服务条款的占位说明，不能据此认定没有其他协议，也不能当作已经完成合规披露。[F-003、F-046](../references/facts.md)

准备合作时，应另行取得具体交付范围、验收样本、数据处理协议、维护责任、计费和退出安排。公开文章适合学习方法，合同与实际验证适合判断供应商能否承担某项任务。
