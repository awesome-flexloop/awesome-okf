# 从研究解读到工作方法

Kanzan 转述的用户访谈和数学证明研究，分别提供理解使用者与设计验证器的例子。原研究能够支持限定范围的方法启发，但不能代替目标组织的用户调研或业务验收。

## 访谈的样本与解释

Anthropic 2026-03-18 发布的原研究报告访谈了 80,508 名 Claude 用户，涉及 159 个国家与 70 种语言。愿望采用单一类别，担忧采用多标签，研究方也说明活跃用户样本和提问顺序的限制。[F-041、F-042](../references/facts.md)

这些数量说明研究方报告的覆盖范围，不使样本自动成为全球人口的代表。愿望与担忧的比例也不能在分类方式不同的情况下直接相减、相加或排名比较。本包未取得全部匿名回答或重新执行编码，不独立验证研究结果。

可迁移的方法是让用户讲具体经历，区分期待、实际使用与担忧，再检查目标人群、招募方式、提问和分类规则。应用到一个组织时，还应加入尚未使用 AI 的人、拒绝者和使用失败者，避免只看到积极用户。

## 形式化证明的验证边界

AlphaProof Nexus 论文 v2 报告 full-featured Agent 在 353 个尝试的开放 Erdős 问题中解决 9 个，包括两个自 1970 年提出的问题。论文中的基本 Agent 事后比较也解决上述 9 题，这不是对全部 353 题重新测得相同成功率。[F-043、F-044](../references/facts.md)

论文描述了 Lean（形式化证明工具）编译反馈、移除 `sorry`（跳过证明的占位符），以及由专家核对形式化命题与原题的一致性。[F-045](../references/facts.md) 这提供两层验证的启发：程序检查推导是否在规定体系中成立，领域人员检查所证明的命题是否真是目标问题。证明检查器可接受一个被简化或偷换的命题，因此“通过验证器”仍需要验证对象一致。

迁移到企业任务时，格式、schema（数据结构与约束定义）或测试只覆盖它们定义的约束。若业务问题难以完整形式化，需要人类判断、真实样本和风险边界共同补足。论文每题的运行费用也不能当作完整研发与人力成本；本包未复跑任何证明。

## 三条跨主题洞察

以下为本包分析，不是研究方或 Kanzan 的普遍结论。每条均按陈述、证据、反常识、行动组织，并展开现象、机制假设与影响。

### I-1 任务定义决定验证对象

- 陈述：场景评估、知识维护和形式化验证都需要先明确“什么结果值得接受”。
- 证据：F-009 要求输入输出和验收；F-010 记录来源、版本与责任；F-045 区分 Lean 检查和专家命题核对。
- 反常识：更强模型或更严格格式，不能自动弥补问题定义偏移。
- 行动：试点前写出结果定义、适用资料、反例和裁定人，验收时同时检查对象一致与输出正确。

现象是这些主题都有额外的确认步骤；本包的机制假设是模型输出与业务用途之间存在解释距离。影响是测试看似通过仍可能解决了错误的问题。这是跨主题类比，不是对作者项目失败原因的实证归因。

### I-2 接入能力与决策权力分开管理

- 陈述：接口、任务说明与组织批准承担不同责任。
- 证据：F-017 限定 MCP 范围；F-019 说明 Skill 资源包装；F-022 将事件创建与类型治理分开；F-050 指向实现方的安全责任。
- 反常识：接入某个协议或加载某个 Skill，不代表 Agent 已获业务写入、发布或类型修改权。
- 行动：每个动作分别登记接口能力、指导文件、实际权限、审批条件和撤回途径。

现象是同一动作需要多种前置条件；本包的机制解释是“能做”与“允许做”的授权主体不同。影响是把任务说明当授权可能放大误操作范围，尤其在事件类型或公开发布中。该解释需要在目标系统权限实现中再验证。

### I-3 结果成本要计入失败和维护

- 陈述：模型账单、健康响应和研究成绩都是局部指标，需要对齐最终使用结果。
- 证据：F-027 包含集成治理培训；F-038 描述部署健康检查；F-042、F-044 说明样本与比较集合的限制。
- 反常识：调用更便宜、接口返回成功或选定题目表现更好，不足以证明整个业务更有效。
- 行动：比较相同任务的被接受结果、人工返工、维护和失败；每个指标写明对象、分母与验收范围。

现象是成本与成功指标使用不同统计单位；本包的机制假设是将局部代理指标当成业务目标会遗漏系统外成本。影响是预算与成功判断可能偏离实际用途。没有本组织记录时，不提供收益数字。

## 候选模式 对象双验

定义：先核对输出对应的目标、资料与范围，再核对其格式、推导或实际结果。模式标识 `kanzan-object-double-check`，成熟度为 L1-draft。

适用于存在形式测试、引用资料或机器检查，同时需要领域意义判断的任务。不适用于完全机械且规则已穷尽的处理，也不代替医疗、安全控制或法律专业验收。

1. 指定目标问题、责任人与不允许自动决策的范围。
2. 保留输入、来源、版本和预期结果。
3. 检查输出是否对应原问题，是否偷换单位、适用范围或命题。
4. 执行相应的格式、规则、测试或验证器。
5. 对不确定或高风险结果转交领域人员，记录接受、拒绝与修正。
6. 将失败类型回写资料或测试，下一次用同样标准复验。

检验标准：任一被接受的结果都能回到原问题与依据，具有对应验证结果和裁定记录；至少一个对象错配的反例被拒绝。

| 反模式 | 本次学习中的风险依据 |
|---|---|
| 看到大样本就推成全民比例 | 访谈招募与分类限定，F-042 |
| 检查通过就认定目标正确 | 命题一致性仍需专家核对，F-045 |
| 把局部比较换成全样本成绩 | 基本 Agent 比较集合限定，F-044 |
| 健康请求成功就宣布业务正常 | 作者部署健康覆盖范围有限，F-038 |

这些反模式来自源文口径限制与本次核验，不宣称目标产品实际犯过相应错误。

跨域迁移示例：财务汇总先确认期间、币种、主体和数据版本，再核对公式与总额；公式正确但期间错误的表应被拒绝。该示例为教学推演，未实际验证。虽然参考多个主题，它们不是两个独立业务部署案例。

升级至 L2 的证据条件：至少两个独立业务案例，各自记录环境与版本、原问题与验收标准、错配反例的拒绝证据、正常结果与回归记录，并由具名领域责任人裁定和独立审查确认。未满足全部条件时保留 L1-draft；主题不同或文章数量多不算独立部署证据。

## 开始应用

选择一个有人能判定的低风险任务，使用[场景模板](01-use-cases-and-knowledge.md)明确输入输出，再用“对象双验”检查一次结果。遇到资料不足、授权不明或高风险输出时停止扩大自动化。创业文章中的地方叙事和政策建议可以提供选题线索，不能当作政策依据、盈利证据或创业保证。[F-035](../references/facts.md)
