# 边界与风险——营销宣称、合规缺口与模式定位

> 本篇是对抗性视角的产物：AITokenBus 博文属**开发者自宣**（信源距离最短的一种），以下边界全部来自独立核验（F-028~F-036），供读者决策而非否定产品本身。

## 一、营销宣称与实测的四处差距

| # | 博文宣称 | 核验发现（2026-09-16） | 读法 |
|---|---------|----------------------|------|
| 1 | "免费**无限**用 AI"（标题，F-020） | 免费池 2 节点在线；35 个价目模型仅 qwen-3-1.7b 可用（F-028） | "有免费入口"成立，"无限"无供给与 SLA 支撑 |
| 2 | "装 **ollama** 之类启动器"贡献算力（F-017） | 客户端是自研 SUMU；全站 ollama/vllm 零命中（F-031） | 机制成立、技术形态表述失准 |
| 3 | 上游挂了"**自动切换**到下一条规则"（F-019） | 路由有内容分流与优先级；跨池 failover 无说明，仅池内 fallback_model（F-030） | 分流成立、自动容灾未证实 |
| 4 | TC 不可兑换/不可转让/永久有效（F-013） | 代码无法币出入金痕迹，行为一致；但无用户协议/隐私政策承载承诺（F-029） | 现状如此，不构成合同保障 |

另外，博文把平台描述得"注册就能顺畅使用"，但市场挂售多为 1–11 人的微型池、平台无文档站（/docs 重定向到登录页），早期产品的完成度与博文流畅叙事之间存在温差（F-026/F-027）。

## 二、合规与信任风险（读者最需要知道的部分）

### 1. 共享/转卖 API Key 与厂商服务条款的冲突

平台的供给方式是把模型厂商的 **API 地址和 Key 托管到 AITokenBus**（F-014），作者自己也把"二次分发改卖"列为用法之一（F-008）。主流国内外大模型厂商的服务条款普遍限制账号/密钥转让、转售与多人共享；将 Key 交给匿名第三方平台托管，可能面临：

- **Key 泄露与盗用**：Key 离开自己控制范围，平台一旦被入侵或内部滥用，额度可被任意消耗（首页"创建者不可见成员 Key"只解决成员侧，不解决创建者把自己的上游 Key 托管给平台这一步）；
- **账号封禁与余额损失**：厂商判定异常共享/转售时可停用 Key 或封号，套餐与余额不受保护；
- **责任连带**：若池成员经共享池从事违规生成，上游账号主体（即建池者）是追责对象。

### 2. 匿名运营 + 无协议 = 信任只凭开发者个人信用

实测页脚无运营主体、无 ICP 备案、无用户协议、无隐私政策、无联系方式（仅登录后 QQ 群），注册页也没有协议勾选（F-032）；全渠道无任何独立第三方信源（F-036）。这意味着：

- 托管上去的上游 Key、聊天请求内容如何存储/使用，**没有任何隐私文本约束**；
- TC 余额（作者宣称"永久躺在账户里"）在平台停运、更名（已有 AICodingBus → AITokenBus 更名前科，F-036）或规则变更时没有兑付保障；
- 基础设施线索（腾讯云 COS 上海存储桶、GitHub OAuth）只能说明运维位置，不能识别责任主体。

### 3. "生态虚拟币"的自我隔离设计

作者明确 TC 不与法币兑换、不可转让（F-013），产品代码中也确实没有任何充值/提现/支付通道（F-029）。这一设计客观上把平台隔离在支付与虚拟币交易监管之外，是产品能以匿名方式运行的重要前提；但反面是——TC 的"价值"完全以平台持续运营为前提，**它不是资产，只是站内积分**。读者不应为获取 TC 而投入有真实成本的资源（高级套餐额度、GPU 电力）后期待任何兑现。

### 4. 给读者的使用边界建议

- 可做：用**独立的、低额度的、可随时吊销的 Key** 试水；只走免费池/0 TC 挂售体验多协议网关；接入端做好用量监控。
- 谨慎：托管主力厂商 Key、绑定高价值套餐、把 AITokenBus 作为生产环境编程工具的唯一上游（博文设想的"AI 永不熄火"恰恰依赖它自身的可用性）。
- 不做：在无协议情况下上传敏感代码/数据经其网关；对 TC 余额形成真实价值预期。

## 三、版本号勘误与国产模型时间线（F-033~F-035）

博文结语称"glm-5.2、kimi-k3、qwen-3.8 已跻身全球最顶级行列"（"最顶级"为📝作者观点，不作事实裁决）。三个版本号经官方源逐项核验：

| 博文写法 | 发文时点（2026-07-22）是否存在 | 官方信息 |
|----------|------------------------------|---------|
| glm-5.2 | ✅ 存在（已上线 5 周） | 智谱 2026-06-15/16 上线，ID `glm-5.2`，1M 上下文；核验日最新为 GLM-5.3（08-19） |
| kimi-k3 | ✅ 存在（刚上线 5 天） | 月之暗面 2026-07-16/17 发布，2.8T 参数/1M 上下文，ID `kimi-k3`，07-27 才开源权重 |
| qwen-3.8 | ❌ **尚不存在** | Qwen3.8 于 **2026-08-03** 才发布（2.4T 参数），官方 ID 为 `qwen3.8-*`（点号）；7 月下旬最新是 Qwen3.7 系列 |

这是典型的"日期/版本表"勘误：博文把发布后 12 天才面世的模型写成了当下既成事实，且 ID 写法（连字符）与官方命名（点号）不符。正文引用时一律以正确时间线为准。一个有趣的后续注脚：核验日 AITokenBus 市场上已出现挂售 Qwen3.8-Flash 的池（2026-09-13 上架，F-027），说明平台在持续跟进新模型。

## 四、模式定位：AITokenBus 在 LLM 中转生态中的位置

| 对照对象 | 相同点 | 本质差异 |
|---------|--------|---------|
| **OpenRouter**（聚合网关） | 多厂商统一 API、按 Token 计费、一个 Key 接入 | OpenRouter 是与厂商官方结算的**持牌商业网关**（B 轮 1.13 亿美元、有公司主体与条款）；AITokenBus 是 **C2C 额度再分配**，平台不向厂商采购，Token 来自用户托管的订阅/API，TC 无法币通道 |
| **API 中转站/逆向代理** | 都提供廉价中转、OpenAI 兼容端点 | 中转站多为法币售卖、常含逆向接口；AITokenBus 主打"共享/贡献"叙事、纯站内积分、无支付链路，合规姿态不同但供给更不稳定 |
| **官方团队版/席位制**（GLM/Kimi 等的团队套餐） | 都解决"一个团队共用额度" | 官方方案有合同与 SLA、Key 体系官方托管；AITokenBus 的共享池跨厂商统一、零现金成本，但在厂商条款之外运行 |
| **ollama/lm-studio 本地模型** | 都利用本地 GPU 跑小模型 | 本地工具是纯自用；AITokenBus 把本地算力包装成可赚 TC 的捐赠节点（实际经 SUMU 客户端，非 ollama 接入） |

一句话定位：**AITokenBus = "C2C 的 LLM 额度闲鱼 + 站内积分制算力互助网络 + 多协议网关"**，在产品创意上自洽且主要功能确有实现，但它运行在厂商服务条款的灰色地带、以匿名个人信用为唯一担保，适合尝鲜与低成本非关键场景，不适合生产依赖。

## 五、时效与复核

- 平台数据均为 2026-09-16 快照；产品处于快速更名/迭代期（AICodingBus→AITokenBus、SUMU 新发布）。
- 本 bundle `stale_after: 2026-12-31`，到期前应复核：① 免费池供给与在线节点数；② 是否补齐运营主体/备案/协议；③ TC 规则是否变化；④ 自动 failover 与本地接入文档是否明确。
