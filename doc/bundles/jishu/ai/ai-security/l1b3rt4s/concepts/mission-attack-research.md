# 攻击面研究定位与档案形态

L1B3RT4S 是红队研究者 elder-plinius（Pliny the Prompter/Liberator）维护的公开仓库，可视为一份**越狱攻击面研究档案库**：以 34 个厂商/实体命名的 .mkd 文件为主体，逐厂商登记针对其模型的越狱提示词条目，并配套 glitch token 编目数据库、指令别名集与 Unicode 隐写载体文件群 (F-L1-008/009)。仓库 README 极简——标题装饰行、两个话题标签、一个社区邀请链接与一句署名，无免责声明、无伦理声明、无贡献指南 (F-L1-002)。本篇从防御研究视角回答三个问题：这份档案在公开研究资产谱系中处于什么位置、它以什么形态组织内容、它与守方档案是什么关系。

## 在公开红队研究资产谱系中的位置

AI 安全领域已有一批公开的对抗研究资产。L1B3RT4S 与它们同类——都以“让模型失守的方式”为研究对象——但在维护主体、组织形态与治理方式上差异显著：

| 资产 | 维护主体 | 形态 | 组织单位 | 治理特征 |
|---|---|---|---|---|
| JailbreakBench | 学术团队 | 行为库 + 排行榜 | 标准化行为条目 | 有伦理声明与提交审核 |
| HarmBench | 学术团队 | 攻击基准套件 | 行为 × 攻击方法矩阵 | 论文级评审与复现规范 |
| Anthropic hh-rlhf | AI 实验室 | 偏好数据集 | 对话样本对 | 数据卡与使用条款 |
| **L1B3RT4S** | 个人研究者 | 档案目录（.mkd/JSON 平铺） | 逐厂商文件 | 无伦理章节，仅 AGPL-3.0 (F-L1-002/004) |

这份差异本身就是研究信号：L1B3RT4S 的价值不在规范性而在**真实性**——它收录的是针对在役产品的实战条目，按厂商与模型版本组织（如 ANTHROPIC 14 章节、GOOGLE 15 章节、OPENAI 21 条目，覆盖 Claude/Gemini/GPT 等逐代际条目，F-L1-045/051），相当于一张持续更新的“失守方式地图”。同时它并非与学术谱系隔绝：其 glitch token 数据库的引源列表引用了 LessWrong SolidGoldMagikarp 系列、ACM 2024、arXiv 2024（GlitchMiner）、NVIDIA Garak 扫描器等学术与工业成果 (F-L1-014)——个人档案反向编目学术成果，构成洞察 5 所述“数据-工具-社区”生态的样本。

## 两大交付形态：显式模板与隐写载体

档案内容以两种截然不同的形态并存 (F-L1-053)：

| 维度 | 显式模板形态（40 个文件） | 隐写载体形态（4 个文件） |
|---|---|---|
| 代表文件 | 厂商 .mkd、`-MISCELLANEOUS-`、`1337` | `TOKEN80M8.mkd`、`TOKENADE.mkd`、`README.md`、`#MOTHERLOAD.txt` |
| 内容主体 | 可见的模板文本（含编码混淆变体） | 不可见 Unicode 字符（U+E0000–E007F Tag 区段、变体选择符）(F-L1-013/017) |
| 体量特征 | 35 字节 ~ 97KB | `TOKEN80M8` 达 23,448,666 字节；README 24,071 字节中可见字符仅约 51 个 (F-L1-003/010) |
| 人类可读性 | 可直接阅读（混淆需解码） | 近零——24MB 文件可以不含一个可读攻击词 |
| 防御含义 | 语义/关键词层检测有作用面 | 对语义过滤**结构性不可见**，需字符层检测（见[防御视角反哺](defense-perspective.md)） |

值得注意的是形态的隐喻意义：连仓库门面 README 本身都是隐写载体——访客看到的“极简文本”之下，99% 以上的字节是人眼不可见的内容 (F-L1-003)。这提示防御方：**可见内容比例本身应成为输入管道的观测指标**。

## 内容性质三分层与命名盲区

按性质，档案内容可分三层 (F-L1-052)：

1. **攻击模板条目**——34 个厂商 .mkd 的主体，收录各代际模型的越狱条目；
2. **提取成果档案**——`SYSTEMPROMPTS.mkd` 汇编各厂商产品系统提示词原文（OpenAI o1、Anthropic UserStyle 模式等），是“被提取成果”的收藏而非攻击模板 (F-L1-012)；
3. **结构化研究数据库**——`*SPECIAL_TOKENS.json` 是格式化程度最高、唯一含引文列表的文件，把 7,895 个 glitch token 按 8 类异常行为 × 5 类分词器编目 (F-L1-014/015)。

三者在命名上**未做任何区分**，全部平铺于根目录：`.mkd` 后缀既可能是攻击档案也可能是提取档案，`.json` 既可能是工具配置也可能是研究数据库。对防御方而言，这意味着消费此类公开档案时必须先做**性质甄别**——把提取成果档案误读为攻击载荷，或把研究数据库误读为工具，都会导致错误的威胁评估。

## 代际覆盖：档案作为时间切片

档案按“厂商 → 模型版本 → 条目”两级组织 (F-L1-045)，这意味着它同时是一份**时间切片集合**：每个章节锚定一个具体模型版本（ANTHROPIC 覆盖 Claude-3.5 时代至 OPUS-4.6，GOOGLE 覆盖 Gemini 1.5 至 3 代际，F-L1-020/029），而仓库近期的提交主题 (F-L1-001) 表明收录仍在持续更新。防御方消费这类档案时应注意两点：

1. **时效判定**：条目的有效性绑定于具体模型版本——对某个在役版本失守的条目未必适用于新版本，反之亦然。把档案当作“当前仍然有效的攻击清单”来读会产生系统性误判；正确用法是把 git 提交记录当作版本锚点，为每条登记标注其测试时点。
2. **代际演化信号**：同一厂商文件内部的版本序列本身就是军备竞赛记录——混淆强度随代际递增（DEEPSEEK 两代条目采用不同编码实现、GROK-MEGA 推进到多重字符体系叠加，F-L1-055）。这是评估“新版本对已知类别的抵抗力变化”的现成对照材料，也是[红队评估矩阵](../examples/redteam-workflow.md)把代际作为维度的依据。

体量分布同样携带信息 (F-L1-051)：多版本纵深档案（20~97KB）与单条目极简文件（173~302 字节）并存于同一命名体系，说明档案对“系统性研究”与“随手记录”未做任何区分。采信时应按条目而非按文件判断权重——小文件可能是精心构造的最小样本，大文件也可能只是重复模板的堆叠。

## 攻守同构：与守方档案的闭环

同一研究者同时维护着守方视角的[系统提示词透明档案 CL4R1T4S](../../cl4r1t4s/index.md)，两份档案构成同一对抗循环的两个切面（洞察 1）：

- L1B3RT4S 内部的 `SYSTEMPROMPTS.mkd` 与 CL4R1T4S 收录**同质内容**（提取出的厂商系统提示词）(F-L1-012)；
- `!SHORTCUTS.json` 中的 `!KAEL` 指令定义为要求输出系统提示词原文——攻击工具直接以守方档案的收录物为提取目标，形成“提取→归档→再提取”闭环 (F-L1-016)；
- ANTHROPIC.mkd 首条目是多轮对话实录，主题为引导模型迭代生成**攻击与防御配对样本**——攻击档案显式生产防御训练数据 (F-L1-021)。

这挑战了“攻击研究与防御研究分属对立阵营”的默认假设：同一行为者运营攻防两份档案，守方的提示词保密条款在攻方面前不构成真正的访问控制，只构成一种叙事姿态（洞察 1）。防御设计的有效性必须用攻方入口来检验，而不能只看条款是否写得很严。

配对阅读的操作含义是：防御团队评估自身提示词资产时，应同时回答两个问题——“这份资产里布置了哪些守方条款”（对照 [CL4R1T4S 束](../../cl4r1t4s/index.md)的结构学）与“攻方档案中哪个类别正以它为入口”（对照本束 [T1–T10 分类学](attack-taxonomy.md)）。只回答前者会高估条款的约束力，只回答后者则不知道该优先加固哪里。

## 防御阅读视角

本束全部内容遵循以下立场（详见[束索引](../index.md)的用途限定声明）：

- 只在**类别机制层**描述攻击技术，不收录任何可操作载荷或完整模板正文；
- 档案中的文件名、规模、结构形态按编目需要登记（见[档案编目参考](../references/catalog.md)），条目正文一律不转述；
- 技术命名采用学术分类（T1–T10），指纹要素仅用于归因分析而非复现。
