# 负责任披露与研究伦理

对一份越狱档案做二次研究，比研究普通开源项目多出一层义务：研究者必须同时回答“我能知道什么”（许可与法律边界）与“我该如何说”（披露与转述纪律）。本篇给出本束遵循的完整框架。

## 一个反常观察：档案本体没有伦理章节

L1B3RT4S 的 README 只有标题装饰、两个话题标签、社区邀请与署名——**没有免责声明、没有伦理声明、没有可接受使用条款、没有贡献指南** (F-L1-002)。这与同类学术资产形成鲜明对照：JailbreakBench 等公开基准普遍配有伦理声明与提交审核流程。

这个事实本身是研究观察点，而非模仿对象：它说明该生态的治理完全依赖上游许可（AGPL-3.0）与社区自律，**没有任何机制阻止档案被用于有害目的**（洞察 5 同时指出该生态具备准学术基础设施的形式要素——引用规范、社区渠道、许可治理——但伦理治理恰是缺口）。对二次研究者的含义是双重的：其一，不能因为“上游没写禁止”就放松自律；其二，在引用该档案做防御研究时，应显式补齐上游缺失的使用限定——本束的[用途限定声明](../index.md)正是为此而设。

## 二次研究的准入自查清单

在把此类档案纳入研究、检测建设或培训材料之前，建议逐项自查。清单按“做之前 → 做之后”排序：前两项决定要不要做，后几项决定怎么做。

- [ ] **目的审查**：产出物是否仅服务于防御研究、检测建设或治理观察，能否通过“若上游作者看到也不会异议”的检验；
- [ ] **数据最小化**：登记的元信息是否限定在结构级（文件名、规模、章节、类别归属），未复制任何条目正文；
- [ ] **隔离环境**：需要查看原始条目的核验动作是否在离线、无外联的受控环境完成（本束 R 阶段即以只读 git 命令完成全部核验，F-L1-006）；
- [ ] **溯源完整**：每条论断是否携带版本锚点（git HEAD）与读取方式记录，第三方能否独立复核；
- [ ] **输出不落地**：核验过程的中间产物（解码文本、截图、笔记）是否即用即毁、不入共享存储；
- [ ] **版本与时点注明**：所有测试结论标注被测模型版本与测试时点，避免过期结论被当作现状；
- [ ] **上报路径**：意外发现可复现脆弱性时，是否有预先确定的厂商 SRC/CERT 通道与响应时限。

## AGPL-3.0 的实际含义

档案以 GNU Affero General Public License v3 全文发布 (F-L1-004)。对本束相关的三条约束：

| 许可条款 | 内容要点 | 对二次研究的影响 |
|---|---|---|
| 强 copyleft | 衍生作品须以同许可开放源码 | 直接复制档案正文并再分发的产物需遵循同许可 |
| 第 13 条远程网络交互 | 经网络向用户提供服务的场景也须开放对应源码 | 把档案内容封装为在线服务的部署形态同样被覆盖 |
| 署名与许可传递 | 保留许可与来源声明 | 引用档案元信息（文件名、规模、结构）时应注明来源与版本 |

本束的处理方式：**只登记结构级元信息**（文件名、字节数、章节结构、类别归属）与**类别机制描述**，不复制任何条目正文，因此本束不是上游作品的衍生文本；同时所有编目均注明上游仓库、git HEAD 与读取方式 (F-L1-001/006)。读者如需引用本束结论，同样应回溯到上游档案与事实清单而非转抄本束。

另一个值得区分的概念是“事实”与“表达”：许可约束的核心是**表达**（正文文本、代码），而文件名、字节数、章节结构、类别归属这类事实性元信息的登记处于研究自由与著作权保护的交界地带。本束选择只登记事实与类别机制、完全不搬运表达，正是在该交界地带取最保守位置的实践；同类研究可以此为参照基线。

## 负责任披露的渠道惯例

防御研究发现模型脆弱性后，“告诉谁、怎么说”存在成熟惯例：

| 渠道 | 适用场景 | 实践要点 |
|---|---|---|
| 厂商安全响应渠道（SRC/漏洞赏金） | 针对特定在役产品的可复现脆弱性 | 主流 AI 实验室均设有安全报告入口或赏金计划；只描述触发条件与影响，不公开可复现载荷 |
| CERT/CC 类协调机构 | 跨厂商、涉及供应链或厂商响应缺位 | 走协调披露流程，由机构掌握披露节奏 |
| 公开基准贡献 | 方法论层面的攻击类别与度量 | 向 JailbreakBench/HarmBench 类基准贡献**行为定义与评估协议**，而非具体载荷 |
| 学术发表 | 机制研究与可泛化结论 | 会议论文普遍接受“效果统计 + 伦理声明 + 不公开载荷”的写法 |

共同纪律是**披露效果与机制，不披露弹药**：披露节奏上遵守协调期惯例，公开材料中把触发条件抽象到类别层（本束 [T1–T10 分类学](attack-taxonomy.md)即是这种抽象的产物）。

## 披露内容的抽象阶梯

公开材料对发现的呈现深度应逐级抽象——每升一级，可复现性下降而防御价值保留。本束自身的写法就是这个阶梯的实例：

| 抽象层级 | 内容形态 | 本束中的对应 |
|---|---|---|
| L3 类别机制 | 学术命名 + 机制一句话 | [T1–T10 各类的机制定义](attack-taxonomy.md) |
| L2 观测特征 | 防御方可检测的物理量 | 不可见字符占比、非常规脚本占比、输出协议痕迹 |
| L1 触发条件 | 足以理解影响的场景描述 | 仅进入有协议约束的披露渠道 |
| L0 载荷正文 | 可复现的完整模板 | **任何渠道都不公开** |

负责任披露的本质是把公开发现固定在 L2–L3 层：L1 只在协调期内向责任方提供，L0 不出隔离环境。

节奏层面的惯例同样重要：协调披露通常给厂商一个固定响应窗口（业界常引 90 天惯例，具体以渠道协议为准），窗口内同步进展、到期按约定公开；厂商无响应时升级至 CERT 类协调机构而非直接公开。对 AI 模型类发现还有一个特殊变量——模型迭代可能使发现自然失效，披露材料应注明测试时点的模型版本，避免读者把过期结论当作现状。

## 法律与合规边界

提示词层操作的法律定性在各司法辖区仍是发展中的问题，二次研究者至少应自查三条边界（本节为研究性概述，不构成法律意见）：

- **“未授权访问”类法律的类比适用**：以美国 CFAA 为代表的“超越授权访问”概念是否覆盖提示词操作，学界存在持续争议——提示词是产品预期接受的输入，越狱并未“突破”技术访问控制；但若进一步滥用输出（如获取个人信息、实施诈骗），后果行为可能独立触法。
- **平台服务条款**：厂商 ToS 普遍含自动化滥用、逆向工程与安全测试授权限制条款；即便法律上存疑，违反 ToS 仍可能导致封禁与民事追索。守方提示词中的授权边界条款（见[防御视角反哺](defense-perspective.md)对 T2 的讨论）与 ToS 构成双重约束面。
- **输出后果责任**：使用模型失守后的输出实施危害，责任归属于行为人而非研究者语境；这也是“研究样本不落地说”纪律的法律注脚。

## 本束的转述边界

综合以上，本束对上游档案的转述遵循五条可核查的边界：

1. **零载荷**：不出现任何可复制的完整提示词模板或载荷正文；结构示意仅用占位符骨架并标注为防御分析用抽象；
2. **类别级命名**：攻击技术一律采用 T1–T10 学术分类命名，描述到“类别机制”层为止；
3. **指纹最小化**：指纹要素（divider 字样、开关声明、占位符）仅以归因用途登记，不给出其构造用法；
4. **元信息可核查**：文件名、字节数、章节数等编目信息携带 F 编号，可回溯到事实清单与只读 git 读取记录 (F-L1-006)；
5. **用途限定前置**：束索引显著声明仅用于安全研究与防御评估，读者入场即知边界。

这五条边界同时也是读者检验同类材料的标尺：任何声称“研究性转述”却给出完整可复制模板的内容，无论其自我声明如何，都应按攻击载荷对待并按所在组织的安全流程处置。
