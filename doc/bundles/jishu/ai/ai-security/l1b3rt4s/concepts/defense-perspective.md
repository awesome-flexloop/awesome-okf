# 防御视角反哺

分类学的价值不在“认识攻击”，而在**改变防御的检测单元**。本篇把[攻击技术分类学](attack-taxonomy.md)的 T1–T10 转译为防御设计决策，覆盖三个层面：检测单元的选取（洞察 3）、tokenizer 与字符编码层的结构性盲区（洞察 6）、授权类条款的可验证性缺口（洞察 7）。

## 从关键词黑名单到类别级防御

L1B3RT4S 的证据直接否定了关键词黑名单路线：编码混淆手法覆盖全部抽样文件 (F-L1-048)——任何明文关键词都能被 leetspeak、凯撒移位、Unicode 花体或不可见字符改写后原义保留；而模板跨厂商复用与可归因指纹 (F-L1-046/047) 说明攻击空间由一个小“语法”生成。因此检测单元应当是**类别与行为不变量**，而非表面词形：

| 攻击类别 | 稳定不变量（检测目标） | 建议防御控制 | 失效的防御形态 |
|---|---|---|---|
| T1 角色框架 | persona 声明引发的风格漂移 | 系统提示词中显式声明角色固定策略；输出风格监控 | 过滤角色名关键词 |
| T2 虚构授权 | 授权声明在上下文内不可验证 | 授权类边界条款不依赖用户自述，改为行为级控制（见下节） | 相信“我是授权红队”类声明 |
| T3 编码混淆 | 非常规脚本/符号占比、解码后语义漂移 | 输入规范化（Unicode 归一化形式 NFKC 等）后再过分类器；解码级联检测 | 明文关键词黑名单 (F-L1-048) |
| T4 分词器对抗 | 未登录 token、token/字符比异常 | glitch token 词表回归测试（复用 F-L1-014 数据库做扫描）；tokenizer 层监控 | 只看解码后文本 |
| T5 多轮递进 | 会话主题漂移、元任务包装 | 多轮一致性检查；会话级风险累计评分 | 单轮内容审核 |
| T6 双响应仪式 | 输出协议痕迹：分隔装饰、拒绝-内容矛盾、长度刚性 | 输出结构检测器；拒绝后行为审计 | 只检查是否出现拒绝语 |
| T7 通道中介 | 工具调用参数与用户请求不一致 | 工具调用审计与最小权限；跨通道内容拼接检查 | 只过滤用户输入框 |
| T8 隐写载体 | 不可见字符占比、字节-字符长度不匹配 | 输入管道前置不可见字符检测（见下节） | 一切语义/视觉过滤器 (F-L1-003/017) |
| T9 模板指纹 | 指纹要素命中（归因用途） | 用指纹做样本归因与语料去重，反哺类别检测 | 把指纹当黑名单（变体可绕） |
| T10 防御反转 | 引用/伪装模型内部机制 | 内部标记对用户输入的出现告警；系统提示词泄露监控 | 假设内部机制名不会出现在输入中 |

两条原则贯穿全表：其一，**指纹用于归因，不用于拦截**——指纹字符串本身可被编码混淆改写，把 `LOVE PLINY` divider 之类写进黑名单只会得到虚假安全感 (F-L1-047/048)；其二，**输出侧与输入侧配对**——T5/T6/T7 的强信号都在输出与工具调用侧，只防守输入框会整层漏掉。

## tokenizer 与字符编码层：结构性盲区

洞察 6 指出：对抗前沿正从语义层下沉到 tokenizer/字符编码层，而语义/关键词形态的护栏对该层**结构性失明**。档案给出三个观测锚点：

1. **不可见字符占比**。`TOKEN80M8.mkd` 用 23,448,666 字节投递可见文本近零的内容；`README.md` 24,071 字节中可见字符仅约 51 个 (F-L1-003/017)。防御管道应把“可见字符/总字节比”“不可见 Unicode（Tag 区段 U+E0000–E007F、变体选择符）计数”作为输入侧一等指标，而非等待语义分类器给出判断。
2. **编码规范化前置**。在内容审核之前先做 Unicode 归一化与不可见字符剥离/转义，使 T3/T8 的表征变换在进入语义层之前现出原形；对必须保留的场景（多语言、数学符号）采用白名单式放行。
3. **glitch token 行为学编目作为防御知识库**。`*SPECIAL_TOKENS.json` 将 7,895 个 token 按 8 类异常行为（不可言说、多义、拼写 glitch、上下文腐蚀、循环诱发、身份瓦解、碎片化、不可达）× 5 类分词器编目，其自述用途即“导入该库以测试 LLM 的 glitch token 脆弱性” (F-L1-014)。这正是防御方可以直接复用的资产：把 8 类行为转化为**tokenizer 层回归测试用例**，纳入模型发布流水线；同时该数据库的学术引源（SolidGoldMagikarp、GlitchMiner、Garak 等）提供了持续更新的来源 (F-L1-014)。

值得强调的是成本对比：T4 类攻击已被压缩到少于 5 个字符 (F-L1-026)，而检测它所需的词表扫描是纯离线、确定性的——这是攻防成本严重不对称的少数案例中**防御占优**的一类，值得优先建设。

## 授权类条款的结构性弱点

洞察 7 的核心结论：**对话上下文内的授权声明不可验证**。攻击模板把虚构授权当作一等语法要素（虚构法律文件、虚构政策主体、虚构管理员、虚构年份、虚构隔离环境，F-L1-049），甚至按目标厂商本地化虚构主体 (F-L1-032)；而守方系统提示词中的“仅限授权安全测试/CTF”类条款恰恰依赖用户自述授权。任何可以口头满足的条件都不构成真正的访问控制。

补偿设计是把“声明式信任”替换为“行为式验证”：

- **输出侧审计**：授权语境下的请求也走同样的输出检测与采样复核，不因声明授权而降级；
- **工具权限最小化**：T7 类通道走私依赖工具能力，工具调用按会话风险动态收紧；
- **多轮一致性检查**：授权声明与实际行为（话题、工具使用、输出协议）交叉验证，漂移即升级人工；
- **修辞识别映射**：把五类虚构授权话语构造（法律依据/政策主体/管理员身份/未来语境/环境声明）做成意图归因特征，用于内容审核规则设计与红队样本分类。

## 与权重层防御的衔接

提示词层防御存在一条结构性边界：本束分类学覆盖的全部控制（输入规范化、输出检测、行为审计）都作用在**对话层**，而权重级干预可以在不经过任何对话交互的情况下整体移除拒绝行为——安全边界是“层”状结构，单层防御会被跨层旁路（洞察 2，机理与工具详见 [OBLITERATUS 束](../../obliteratus/index.md)）。因此类别级防御应作为纵深体系的一层而非全部：

- **权重供应链可信**：对自部署的开源权重，验证来源与完整性，使“获取到被权重级手术处理过的模型”不成为静默入口；
- **服务侧行为监控保留**：即便提示层被整体旁路，输出侧异常（T6 协议痕迹、T4 token 行为异常、T8 载体投递）仍可作为最后一道观测面；
- **分层评估**：红队评估应区分“提示层失守”与“权重层失守”两种前提下的结论，避免把两层结果压缩成单一风险值。

## 红队评估的基准化

类别级防御需要类别级验证。[防御性红队评估工作流](../examples/redteam-workflow.md)示范如何用 T1–T10 组织一次**不产生任何攻击内容**的防御评估：以类别覆盖矩阵保证 T1–T10 无遗漏，以历史样本回放与离线语料分析代替生成新载荷，以观测指标（不可见字符占比、token 异常、输出协议痕迹）量化防线强度，并按[负责任披露](responsible-disclosure.md)惯例归档。评估结果可与 JailbreakBench/HarmBench 等公开基准对齐，使内部防线强度可与社区横向比较。评估矩阵还可直接复用[档案编目参考](../references/catalog.md)的类别分布作先验——档案中 T9/T3 高频命中、T8 载体低频但体量惊人的分布，提示了各指标抽检频次与告警阈值的分配依据。
