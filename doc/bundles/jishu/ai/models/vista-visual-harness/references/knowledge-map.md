# 知识地图：事实层 / 机制层 / 迁移层

> 三层严格分离：事实层只放可核验断言；机制层是**执行者的解读与假设**，不是论文主张；迁移层只放中立、可逆、尊重边界的实践。
> 机制层与迁移层的每条洞察均标注其证据来源的 F 编号；无 F 支撑的推断一律标注为假设。

## 二、机制层（执行者洞察，非论文主张）

> 以下 5 项为基于上述事实的**解读与推论**，标为假设。论文未以这些措辞表述。

### M1｜"保留原始像素 + 按需重看"优于"把画面摘要得更准"

- **性质**：假设（有消融阶梯与机制描述支撑，但论文未直接对比"保留原始"与"更好的摘要"两种记忆策略）
- **证据**：F-015, F-020, F-026, F-051, F-065
- **推理**：摘要类记忆在写入时就必须决定"什么重要"，而 F-015 指出首次观察时无法预知后续哪个细节会变重要；保留原始信息是对冲这一不确定性的唯一方式。
- **反常识**：增加存储成本通常被视为劣势，但这里它换取了"未来可能需要"的期权。

### M2｜得分跃升发生在语境编排层，而非模型能力层

- **性质**：假设（论文 §3.2 明示 Harness 不训练模型，但未把分数提升归因到"语境层"这一层抽象）
- **证据**：F-034, F-035, F-054, F-063, F-079
- **推理**：消融阶梯 13.33 → 99.00 是在**同一个 GPT-5.6 Sol 模型**上逐步变更 harness 配置得到的受控对比；因此提升来自编排而非模型。
- **边界（重要）**：该结论**只对消融阶梯成立**。头部的"40.68 → 100.00"**不是**同条件对照——前者是 Opus 5.0 **high** 强度 + 官方协议（每关 5× 动作预算 / 12 小时，且由官方公布分数换算），后者是 **xhigh** + 2,000 动作 / 48 小时，差值里混入了 harness、推理强度、评测协议三项变化 [F-077][F-079]。严格同条件对照只有 Sol(max)：13.33 → 99.00。
- **反常识**：看到"满分 100"容易推断"模型变强了"。

### M3｜"满分 100"是三条限定条件共同成立的结论，缺一不可

- **性质**：假设（论文 §6 + 官方方法学的组合解读）
- **证据**：F-047, F-064, F-068, F-073, F-074
- **推理**：基线（官方实现 40.68 / 13.33）+ 数据污染不可排除 + 未见题目表现未知，三条限定共同决定该结论的可迁移范围。
- **反常识**：传播度最高的表述恰好省略了最关键的前提。

### M4｜Agent 记忆是三层结构，而非单层"记忆"

- **性质**：假设（有 GUIDE.md / WORKING.md / 视觉档案的分工描述支撑，但论文未使用"三层记忆"这一术语）
- **证据**：F-030, F-053, F-022, F-051
- **推理**：跨任务复用（GUIDE.md）/ 当前任务状态（WORKING.md）/ 原始证据（视觉档案）三者生命周期与清理策略各不相同，混用会导致上下文膨胀而有效信息不增。
- **反常识**：直觉以为"视觉经验"应以视觉形态存在，实际承担规则沉淀的是文字笔记。

### M6｜源码层的最重要增量是"工具即文件、文件即接口"

- **性质**：假设（源码可验证的构造事实，但"这是好设计"是解读）
- **证据**：F-095, F-096, F-121, F-122
- **推理**：`GUIDE.md`/`WORKING.md` 在源码里**不是文件系统旁路**，而是 `read_guide`/`write_guide`/`read_working`/`write_working` 四个与 `inspect`/`read_pixels` 同级的工具；压缩边界后 `core/dispatcher.py` 甚至强制"先存检查点再动其他工具"[F-122]。因此"记忆"对模型而言是**一组可被调度的动作**，而不是它可以绕过的环境细节。
- **反常识**：直觉上把笔记放在磁盘上、让模型"自己去读写"更灵活；但那也意味着模型可以在任何时刻绕过 harness 契约——而 harness 恰恰是这套方法的能力来源。
- **行动**：设计 Agent 记忆时，把"读/写记忆"做成**受控接口**而非旁路；工具白名单（`{save_compact_checkpoint, inspect, read_pixels, history, play}`，[F-107]）就是最小可行形态。

### M7｜"论文是机制层、源码是复现层"，两者不可互相替代

- **性质**：假设
- **证据**：F-077, F-086, F-110, F-111, F-125, F-127, F-128
- **推理**：源码默认的模型（`gpt-5.6-sol`/`max`）、强度（`opus`/`xhigh`）、回合上限（2000）与论文表 1 逐格吻合 [F-110][F-111]，说明源码是论文的忠实实现；但论文未展开的参数上限、量化方式、压缩分叉、以及上下文口径差异 [F-096][F-099][F-108][F-127] 只能从源码获得。
- **反常识**：读源码时容易误以为它是"论文的附注"；实际上**源码是唯一能回答"能不能复现"的地方**——它把每一个上游都固定到了具体 revision [F-113]。
- **行动**：引用 VISTA 类工作的结论时，**机制问论文、复现问源码**；两者结论不一致处（本束 E-10~E-14）必须显式并列，而不是取其一。

### M5'｜"满分"部分是指标聚合口径的产物，不是能力超越的证据

- **性质**：假设（基于论文公布的指标定义与三基准数字的横向比较）
- **证据**：F-073, F-081, F-084, F-056, F-058
- **推理**：把三行数字并排看——ARC-AGI-3 上 VISTA 与人类持平（100 vs 100 参照系），GameWorld 上 VISTA 高出人类新手 8.0pp（63.3% vs 55.3%），但 BabyVision 上 VISTA **落后人类 29.1pp**（63.2% vs 92.3%）。差别来自口径：ARC-AGI-3 把成绩聚合到 25 个游戏、每局按关卡序号加权、人类基线取每关动作数最少者的**上中位数** [F-073]。在缺少这种聚合与宽松基线的任务上，同一套 harness 仍显著落后人类。
- **反常识**：基准分数的绝对值高度依赖指标设计；"超越人类"与"落后人类 29 个点"可以出自同一套方法。
- **行动**：引用交互式基准的绝对分数前，先读三件事——分数如何聚合、人类基线怎么取、样本量多大 [F-081]。

### M5｜跨环境泛化证据强度是混合的，不能整体采信

- **性质**：假设（依据三基准的构成差异分析）
- **证据**：F-040, F-056, F-057, F-058
- **推理**：GameWorld 与 AI GameStore 同为浏览器游戏，共享引擎与渲染假设；BabyVision 是静态图片，与"交互式"这一核心卖点不同源。因此四个基准证明的是**稳健性 + 部分可迁移性**，而非无条件的通用性。
- **反常识**：基准数量多不等于覆盖维度多。

## 三、迁移层（中立可逆实践）

> 以下为从本案例提炼的通用做法，均**不依赖** VISTA 或 ARC-AGI-3，可在其他 Agent 场景中独立采用或拒绝。

### T1｜对不可预判重要性的信息，保留原始形式 + 提供检索工具

- **适用**：视觉输入、原始日志、多模态媒体、异常现场快照
- **不适用**：结构确定、语义稳定、压缩无损的数据（如已解析的表单）；此类信息摘要化成本更低
- **做法**：① 原始形式落盘存储；② 建立稳定索引（如回合号 + 帧号）；③ 提供按需取回与局部检视工具；④ 上下文侧只放当前必要片段
- **检验**：当某次推理需要三个月前的一张图的某个像素时，能否在有限步内取回

### T2｜把记忆按生命周期拆成三类并分别定义清理策略

- **适用**：任何跨多个任务/关卡的长时程 Agent
- **不适用**：单轮短任务
- **做法**：① 区分"跨任务可复用结论 / 当前任务状态 / 原始证据"；② 为每类指定保留期与清理触发条件；③ 状态类在任务推进时清理、结论类在会话间保留、证据类按需裁剪
- **检验**：上下文体积是否随任务时长线性增长；有效信息占比是否下降

### T3｜评测 Agent 能力时固定模型、只换 harness

- **适用**：评估编排/上下文/工具设计的增益
- **不适用**：评估模型本身能力
- **做法**：① 报出基线 harness 与目标 harness 的成对成绩；② 报告多次运行方差；③ 明确所报数字是单次最好值还是均值
- **检验**：结论能否被表述为"在同一模型上，编排带来 X 提升"

### T4｜引用基准满分类结论时强制附带"限定三件套"

- **适用**：一切交互式/生成式基准的满分或接近满分结论
- **不适用**：内部回归测试的固定用例
- **做法**：① 基线是什么；② 是否限定数据污染；③ 未见题目上的表现
- **检验**：结论能否被他人独立复述而不被误导

### T5｜区分"论文主张 / 媒体转述 / 执行者解读"三层

- **适用**：任何二手技术资讯的沉淀
- **不适用**：一手技术规范原文
- **做法**：① 转述层标注原文用词与转述用词的差异；② 论文未引用的脉络关联显式标注为作者叙述；③ 自己的推论标注为假设并挂 F 编号
- **检验**：读者能否分辨哪句话是"作者说的"、哪句话是"我说的"
