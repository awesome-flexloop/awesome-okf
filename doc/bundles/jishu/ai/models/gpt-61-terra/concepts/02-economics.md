# 价格、额度与任务成本

2026-10-27 读取的标准 API 单价如下，官网发布文和模型参考一致。[F-014 至 F-016]

| token 类别 | 每百万 token 美元价 |
|---|---:|
| 未缓存输入 | 1.00 |
| 缓存输入 | 0.05 |
| 输出 | 5.00 |

官方称标准价格比 GPT-5.6 Terra 和 GPT-6.1 Sol 低 50%。[F-010] 本束没有单独读取比较型号的完整价目表，因此不列反推价格。

## 读懂 2X

原帖写 `2X more usage than 6.1 Sol across API and subscriptions`。[F-005] 官网针对 ChatGPT Work 和 Codex 只写相同 allowance 可覆盖更多任务，没有给精确倍数或完整规则。[F-011]

| 概念 | 测量的是什么 | 是否等于原帖 2X |
|---|---|---|
| token 单价 | 按输入、缓存、输出收费 | 否，输出长度和缓存命中可能不同 |
| 订阅 allowance | 套餐内可消费用量 | 未取得精确计算、周期及套餐细则 |
| RPM / TPM | 每分钟请求 / token 限速 | 否，容量限制不是订阅次数 |
| 延迟与吞吐 | 多快完成以及每单位时间完成多少任务 | 否，需要任务级实测 |
| 每成功任务成本 | 全部尝试成本除以成功任务数 | 否，还包括失败、重试与人工返工 |

API 模型页列 Build、Launch、Grow 的 RPM 为 5,000 / 10,000 / 15,000，TPM 为 1,000,000 / 4,000,000 / 40,000,000，Free 为不支持。[F-029、F-030] 这是 API 用量层级；不能与 Plus、Pro 等订阅名称对应，也不能据此宣称订阅用户有相同 API 权益。[F-012]

## 收费修饰项

| 条件 | 模型参考口径 | 对估算的影响 |
|---|---|---|
| 缓存写入 | 30 分钟保留 $1.25/M；12 小时 $2.50/M，长上下文调整前 [F-025] | 缓存读取便宜不等于建缓存免费 |
| 超过 272K 输入 | 整个请求输入与缓存倍率 2，输出倍率 1.5 [F-026] | 不是只对超过阈值的部分加价 |
| Batch / Flex | 相比 Standard 低 50% [F-027] | 需另核对适用任务和服务条件 |
| Fast mode | Standard 的 2 倍 [F-027] | 速度偏好可能抵消单价优势 |
| 地区处理 | 可用地区加价 10% [F-027] | 部署选择会改变账单 |
| 工具费用 | 模型页提示工具特定费用，具体价格未读取 [F-028] | 不能把 token 费用当作最终总账单 |

## 一个可核对的费用模型

以下为本束推导的记账公式，**不是实测数据或官方保证**。对未触发长输入阈值、未启用其他收费修饰项的 Standard 请求：

```text
token费用（美元）
  = 未缓存输入token / 1,000,000 × 1
  + 缓存输入token / 1,000,000 × 0.05
  + 输出token / 1,000,000 × 5

成功任务平均总成本
  = 所有尝试的实际费用与可计量返工成本 / 成功任务数
```

缓存写入、工具调用、重试等要另计；没有成功任务时不能用这个比值报告优势。没有使用虚构 token 数或模拟账单作为性能证据。

总成本比较必须固定任务批次与统计周期，统一币种和人工成本折算率。人工时间没有折成费用时，应把分钟数另列，不能直接与美元相加。

将同一批任务分配给候选模型，记录实际账单、失败原因、耗时和人工修订，才有条件检验“更省”是否适合自己的场景。模型单价低与业务总成本低之间仍隔着任务成功率。
