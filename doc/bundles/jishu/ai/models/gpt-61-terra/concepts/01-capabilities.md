# 能力矩阵与 API 边界

模型名、端点、工具和宿主环境是四个不同的选择。`gpt-6.1-terra` 标识模型；Responses 与 Chat Completions 标识调用接口；Computer use 等工具提供行动通道；桌面和应用承载实际任务。[F-013、F-020 至 F-024] 模型页支持工具，并不代表每个账户已经获准使用，也不代表已有安全运行环境。

## 输入输出

token 是模型处理文本等信息的计量单位，不等于汉字或英文单词。context window 是一次请求可处理的上下文规模；Structured outputs 指按约定结构输出；Fine-tuning 指用额外训练数据调整模型。以下是模型页的声明，不是本束测试结果。

| 项目 | 模型页声明 | 不能据此推导 |
|---|---|---|
| 输入与输出 | 文本输入输出；图像仅输入 [F-018] | 原生音视频输入、原生图像输出 |
| 上下文 | 1,050,000 context window [F-017] | 可以同时塞满输入并额外获得完整输出上限 |
| 输出上限 | 128,000 max output tokens [F-017] | 每次都应生成这么长 |
| 输出约束 | Structured outputs 支持 [F-022] | 结构正确即事实正确 |
| 训练方式 | Fine-tuning 不支持 [F-022] | 可以通过该模型页直接微调 |

较大的上下文上限只说明可接受规模。检索是否可靠、截图细节是否遗漏、任务是否在中途偏离，仍需验证。长输入还有[计费阈值](02-economics.md)，不是免费的容量。

## 推理强度

`reasoning.effort` 的值为 `none`、`low`、`medium`、`high`、`xhigh`、`max`，默认 `medium`。[F-019] 这些是调用参数，不是相互独立的模型。官方评测按 effort 报告结果，比较时应把该参数记入实验记录。

先在默认设置建立基线，再在困难任务上比较更高强度。是否值得增加强度，要观察成功率、等待时间与账单，不能从命名推断 max 必然适合全部任务。此处为本束的评估建议，未执行性能实验。

## 端点与工具

浏览器复核模型页的状态图标后，确认以下区别：[F-020、F-021]

| 端点 | 文档状态 | 选择要点 |
|---|---|---|
| Responses | 支持 | 工具调用必须使用此接口 |
| Chat Completions | 支持 | 不能据端点支持推断工具调用也可使用此接口 |
| Batch | 支持 | 价格、时延与任务形式须按 Batch 文档另核对 |
| Live、Realtime、Realtime translation、Realtime transcription | 不支持 | 不从网站列出这些路径推断模型支持 |

Responses 工具区列出搜索、文件搜索、图像生成、代码解释器、托管 shell、补丁应用、Skills、电脑操作、MCP 与工具搜索支持。[F-023、F-024] “图像生成工具可用”与“模型原生图像输出”不同，也与 `v1/images/generations` 端点是否支持不同。[F-018；浏览器完整端点核对见核验记录]

本束没有读取全部工具定义，不提供猜测的 computer-use JSON schema、动作调用代码或权限配置。真正接入前，应从当前官方工具文档确认协议、执行器和允许动作。

## 电脑操作的安全责任

官方发布文称模型维持任务范围和抵抗提示注入的表现优于前代。[F-044] 这不意味着屏幕上的恶意指令没有风险。网页、文档、邮件或截图中的内容应视为任务数据，不能自动获得修改用户目标的权限。

本束建议将环境限制为测试账号或副本，给任务定义允许访问的应用与文件，对发送、支付、删除和权限变更保留人工确认，并检查实际外部状态。上述措施是工程建议，不是已读取的 Terra 系统卡具体条款。

执行器是把模型建议的动作转成实际鼠标、键盘或应用操作的程序。开展写入测试前，本束建议至少确认：它能把动作限制在允许的应用和文件、能在敏感动作前暂停、能记录结果且允许人工终止。缺任一条件时先做只读任务；满足这些条件也不等于完成生产安全认证。

官方称其网络安全能力达到 Preparedness Framework 的 Critical threshold。[F-043] 这是框架中的能力与风险分类声明，不是“安全评分 Critical 级认证”。系统卡未读取，不能进一步给出细项分数、部署豁免或风险消除结论。[F-045]
