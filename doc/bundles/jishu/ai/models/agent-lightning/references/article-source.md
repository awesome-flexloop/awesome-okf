## Rollout 执行流程（F-016 ~ F-022）

| F 编号 | 事实 | 类别 |
|--------|------|------|
| F-016 | 训练器从 SWE-smith 数据里取出任务，为 Agent 创建一次执行，称为 rollout | 机制 |
| F-017 | 控制器启动 Kubernetes Job，让 mini-SWE-agent 在代码仓库隔离环境运行 | 机制 |
| F-018 | Agent 读任务、查看代码、修改文件、运行命令 | 机制 |
| F-019 | 需要模型决定下一步时，请求发往 Agent Lightning 的 OpenAI 兼容 API 代理 | 机制 |
| F-020 | 代理把请求转给训练中的模型，记录 token ID、对数概率，并绑定到对应 rollout | 机制 |
| F-021 | 模型给出的动作由 harness 执行；反馈由 harness 整理进下一轮上下文 | 机制 |
| F-022 | 训练系统记录的是这套 Agent 实际送给模型的输入，以及模型据此生成的回答 | 机制 |

## 同步/异步训练（F-037 ~ F-041）

| F 编号 | 事实 | 类别 |
|--------|------|------|
| F-037 | 真实 Agent 任务时长很不整齐 | 背景 |
| F-038 | 同步训练等整批结束，最慢一组拖住模型更新 | 背景 |
| F-039 | Collocated Async RL 同时保持更多任务组执行；收齐足够多完整组就更新 | 机制名称 |
| F-040 | 推理和更新共用 GPU；更新前网关暂停接受请求，更新后恢复 | 机制 |
| F-041 | 相比同步 RL 带来约 2 倍端到端加速；共享 GPU 池减少资源需求 | 成效数字 |
