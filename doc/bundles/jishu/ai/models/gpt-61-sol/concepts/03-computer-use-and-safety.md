# Sol 电脑操作的执行与安全责任

Sol 能提出鼠标、键盘或浏览器操作，但你的应用负责提供环境、执行允许的动作并回传观察。[F-034、F-035] 执行器就是把模型输出转成真实动作的程序；没有它，模型的操作建议不会自动变成本机操作。

## 选择接入方式

| 路径 | 模型看见什么 | 应用负责什么 |
|---|---|---|
| `ComputerToolset` | 截图与结构化电脑动作 | 实现 driver，限制动作与环境，处理授权 [F-034] |
| `BrowserToolset` | 页面文本、控件与标签页等浏览器操作 | 通过函数工具暴露选定操作 [F-034] |
| 自管 Responses 循环 | `computer_call` 与动作数组 | 按序执行允许的动作，再返回 screenshot [F-035] |

官方指南给 Astra 的代码执行建议不能不加限定地当成 Sol 专属推荐。Sol 的模型参考确认 computer use 工具支持；具体 driver 和宿主需由应用选定。[F-011、F-034]

自管循环的基本交换为：发送任务和 `tools=[{"type":"computer"}]`；收到 `computer_call`；执行允许的 `actions`；以原 `call_id` 返回 `computer_call_output` 截图，再通过 `previous_response_id` 继续。[F-035] 只看调用对象上的 `status: completed`，无法判断界面动作是否成功。

## 两套状态

API 会话保存对话 Items，浏览器保存页面与登录状态。两者必须分别保持。[F-036] 浏览器被回收后，继续 response 不会重建登录或标签页；坐标对应的是某次截图，页面改变后不能沿用未经重新核对的坐标。

动作前取得当前观察，短组动作后重新截图或读取目标状态。写入保存后，再打开产物或目标记录检查。这是从官方循环与结果验证要求推导的验收方式。[F-035、F-039]

## 控制必须落到执行器

官方指南要求隔离环境、站点与动作白名单，视页面为不可信内容，对难以逆转的操作保留用户确认，并给运行设置步数、时间或费用边界。[F-037、F-038、F-039]

可将任务权限写成这样：

```text
允许：读取测试站点，查看指定记录，编辑草稿。
需人工确认：提交表单、向外发送内容、购买、删除或覆盖记录。
禁止：使用任务外账号、修改系统设置、改变审核与监控配置。
完成条件：保存后回读指定字段，与人工基准一致，其他记录未改动。
停止条件：达到预先设定的步数、时间或费用上限，或用户取消。
```

这是本束提供的权限设计样例，未运行。提示里的禁止条款需要 driver、权限与外部日志共同约束，不能仅依赖模型自觉遵循。

截图和页面文本可能包含密钥、个人资料与商业信息。SDK 会将观察发给 OpenAI；`store: false` 不代表所有数据处理与保留都消失。[F-040] 先用隔离测试账号和脱敏数据，不把真实业务凭据放入截图或日志。

## 如何读系统卡

2026-09-29 的 Sol 系统卡增补将网络安全能力按 `Critical`、生化能力按 `High` 管理，并声明采用与 Astra 相同的 safeguards stack。[F-041、F-042] 这表示风险管理分级，不表示面向任何场景安全、无提示注入风险或已取得业务合规认证。

系统卡明确研究环境/API 与生产 ChatGPT 的系统提示、工具和 effort 等可能不同，旧模型对照值也可能来自后续版本。[F-043、F-044] 不能将其中的基准分数直接解释成当前产品的业务成功率。

一个值得注意的局部指标：Agentic Safe Completions 中 Sensitive personal data 行，Sol 为 0.744，GPT-6 Sol 为 0.854，表述为 higher is better。[F-045] 因此，“总体更好”的官方描述不能替代敏感数据场景的单项核对；这一行也不能反推你的生产泄露率。

指令层级攻击表报告 Sol defender success rate 为 99.99%。[F-046] 它是特定评估指标，不是提示注入免疫证书。间接注入图值及后续失配、监控章节本次未完整取得，缺口见[信源台账](../references/source-inventory.md)。
