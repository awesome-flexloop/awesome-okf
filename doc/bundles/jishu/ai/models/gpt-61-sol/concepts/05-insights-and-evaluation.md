# Sol 的任务评估洞察与候选模式

## 三条四元组洞察

### I-1 按任务选择推理投入

- 陈述：effort 是待评估变量，不是质量等级标签；在满足质量门槛的配置里比较真实成本和时间。
- 证据：DeepSWE high 75.2%/0.65 美元，max 71.9%/1.57 美元；Factuality xhigh 4.1%，max 4.6%。[F-051、F-063]
- 反常识：最高档没有在两组官方点值上取得最佳结果；但缺置信区间，不能再推成 high 永远最优。
- 行动：固定任务与执行器，先以 medium 为基线，按难度比较 high/xhigh/max；记录每个任务结果，失败不剔除。

现象是曲线非单调；可检验的解释是假设推理投入与特定任务、工具行为和采样共同作用，现有点值无法拆出单一根因。影响是按 max 统一配置可能付出更多费用却没有质量收益；试验应检验这个假设而非把它当已知机制。

### I-2 拆开模型变化与工作流变化

- 陈述：降低 Agent 成本时，要分别量度模型替换、历史预算和截图/缓存策略的贡献。
- 证据：Asana 的 76 倍比较同时改变模型和工作流；B 保持型号也约降 29 倍；作者报告不同历史预算的回答情况不同，但 3/18 与 18/18 的分母单位本束未确认。[F-070–F-075]
- 反常识：更强模型不独占全部降本收益，更多上下文也不必然意味着更高成功任务成本。
- 行动：保留原模型原工作流基线，再做原模型新工作流、新模型原工作流、新模型新工作流的对照；统一验收、账单与失败统计。

现象是配置贡献交织；根因假设是观察历史同时影响输入费用、动作次数与正确性。影响是换型号后的收益无法全部归因于模型。Asana 是一个浏览器任务案例，正确性分母还待回验，不能把该假设推广成所有 Agent 的已证因果。

### I-3 将动作完成与业务正确分开

- 陈述：computer use 的工具循环、权限控制和业务验收应分别负责不同的失败面。
- 证据：driver 由应用实现，API Items 与环境状态分别维持；指南要求隔离、白名单、确认与实际结果验证。[F-034–F-039] 系统卡特定指令层级 99.99% 指标不构成生产免疫。[F-046]
- 反常识：收到 completed 或模型自称“已保存”，不代表目标记录正确，也不代表动作获授权。
- 行动：由 driver 拦截越权动作，写后回读目标字段，用独立参考验收；记录取消、超时和清理结果。

现象是协议状态与业务状态不同；根因是模型输出、执行器动作、页面状态分属不同责任主体。影响是只看 API 正常返回会漏掉无效写入或错误目标；最终验收必须落到真实产物。

## 候选模式 任务账单对拍

定义：把任务验收与全批次账单绑定，再用单变量和组合对照定位配置收益。

### 适用边界

适用于可重复的编码、资料采集、文档处理和工具工作流；任务有参考结果，环境可隔离，模型、effort 或观察策略正在变更。不适用于没有验收标准的开放创作排名，也不能用一次试验直接确定医疗、法律或高风险交易部署。

支撑案例是官方多 effort 评测与 Asana 同任务多配置实验。二者不是两次跨域生产复测；模式保持 L1-draft，未独立入方法论库。

### 核心步骤

1. 定义一批脱敏任务与逐项通过条件，冻结参考答案、源数据和版本。
2. 记录原模型、原 effort、原工作流的费用、耗时与失败，作为基线。
3. 先改变一个变量，保留执行器、提示与任务一致；再测必要的组合配置。
4. 每次记录型号、时间、输入/输出/缓存 usage、工具调用、重试、环境费与人工返工；保留所有尝试。
5. 用参考答案、测试或写后回读判断通过；按通过数统计成功任务总成本，零成功单列。
6. 在满足预先约定的正确性与风险门槛后比较费用和延迟，换任务集复验，再决定扩大试用。

浮动别名无法锁定服务版本时，交错运行新旧配置并在批次结束复跑基线；若服务返回型号、行为或配置发生变化，暂停归因并拆成新的时点批次。记录请求、提示、工具定义、SDK、执行器与环境版本；结果只称“时点复现”，不宣称严格版本复现。

### 检验标准

- 所有配置对应同一批任务、固定验收与可追踪版本。
- 每项改善可追溯到记录，不用模型自述作唯一验收。
- 失败、重试、回退和返工没有被剔除；币种与人工折算口径一致。
- 单变量贡献与组合贡献分别报告，无法分解时明确限制。
- 计费和参数来自同一时点账户；缓存文档冲突解决前不将条件公式视为真实账单。

### 反模式

1. 把 Asana 的 76 倍全归于模型，忽略 B 自身工作流优化。[F-073]
2. 强制裁短历史只看输入费，不验收完整结果，或把分母未确认的 3/18 写成字段准确率。[F-075]
3. 用更低每调用费用推定更低每任务费用，忽略次数与失败。[F-078]
4. 把部分奖励当完整成功率，或把 completed 当真实保存。[F-058、F-035]
5. 将官方参数快照与旧通用缓存说明拼成已验证代码。[F-022、F-083]

### 跨域迁移

可将这一模式迁移到 OCR 文档入库：冻结一组文档与人工字段参考，分别改变识别引擎、图像预处理与人工复核策略，再比较通过字段验收的文档成本。识别字符准确率、调用费和整份文档可用性分开记录。此为迁移设计，未执行 OCR 实验，不构成第二个实测案例。

升级到 L2 的条件是至少两类异质任务独立复验，留下任务参考、版本、完整失败日志与真实费用，并通过复核；当前不满足。

## 最小试用路径

开始前应有可用的 OpenAI API 组织/项目、Sol 模型权限、开发环境中已配置的 `OPENAI_API_KEY`、当前 SDK 版本与依赖清单，以及账户费用上限。ChatGPT 订阅不能替代 API 账户权限。认证、权限或限速失败时停止并核对账户，不自动重复收费请求；不打印密钥。

下面是 SDK 请求草案，未运行，不是已经跑通的 Hello World。采用现有依赖管理方式安装并记录 `openai` 版本；测试任务只有确定算术答案，没有工具、个人信息或有争议的缓存参数。[F-001、F-030]

```python
from openai import OpenAI

client = OpenAI()
response = client.responses.create(
    model="gpt-6.1-sol",
    input="只输出 17 加 25 的十进制整数结果。",
)
print(response.output_text)
print(response.usage)
```

预期文本为 `42`。仅该题回答正确不代表业务质量合格；同时检查 typed `output`、请求标识、`usage` 和账单，确认没有工具调用或未预期的副作用。

| 阶段 | 返回与回传类型 | 通过条件 |
|---|---|---|
| 纯文本 | `message` / `output_text`，无需工具回传 | 固定答案与 usage 可读取 |
| 无副作用函数 | `function_call` → `function_call_output` | 原 `call_id` 对应，参数与结果正确 |
| 隔离浏览器只读 | BrowserToolset 函数路径，或 computer_call → computer_call_output | 选择一种路径，记录当前观察，读取测试记录正确 |
| 测试草稿写入 | 按所选工具协议回传 | 限定权限、写后回读、取消与清理都通过 |

`function_call_output` 与 `computer_call_output` 不可互换。每阶段未通过就不进入下一阶段；难逆操作仍须确认。浏览器函数路径和原生截图/电脑动作路径是不同接入选择。[F-031、F-034、F-035]

### 术语与观察位置

| 词 | 含义 | 如何观察与常见误解 |
|---|---|---|
| Item | Responses 中带类型的输入/输出对象 | 查看 `output` 的 type，不能沿用 choices 格式 |
| usage | 服务返回的 token 使用信息 | 与账单核对，不以最终文字长度代替 |
| KV / 前缀 | 注意力中间状态 / 请求开头的相同内容 | 看缓存 token 计量；不是保存最终答案 |
| TTL | 缓存保留时间设置 | 当前 Sol 参数冲突未解决，不能照搬旧请求 |
| 服务模式 | Standard/Fast/Batch/Flex 等处理方式 | 价格、资格和延迟分别核对，倍率非速度承诺 |
| SLA / SLO | 供应商服务承诺 / 应用自身目标 | 合同与实际端到端测量分开，平均延迟不能代替尾部延迟 |

### 扩大试用与采购门

负责人应在测试前设定质量、费用和端到端 P95/P99 延迟阈值、截止时间内成功率，以及限流/故障回退规则。供应商合同 SLA 与应用实测 SLO 分别记录；没有服务承诺不能用“Fast”名称代替。

账号准入逐项核对企业主体、调用所在地、产品入口、组织限额、数据驻留/处理地区和服务模式。US/EU 驻留声明不证明企业或调用地区具备资格；未知项记为未通过准入。[F-082]

使用真实账号前，数据负责人需批准允许上传的类别、截图脱敏、保留/删除要求和第三方工具数据流；账号操作授权不等于数据外发授权。未审批时仅使用人工构造的无敏感测试输入，不把业务数据发往模型或工具服务。[F-037–F-040]

代表任务质量、SLO、服务准入、数据审批、TCO 和回退路径分别通过预定标准，才批准采购或生产扩大。资料阅读、一次请求成功和官方跑分均不构成此门通过。

| 待验证项 | 负责人角色 | 验收证据与时间节点 |
|---|---|---|
| 缓存 TTL 与写入费 | API 集成人员 | 接入前，以当前文档、测试请求、usage 和账单解决冲突 |
| Sol 代表任务对照 | 业务负责人 | 扩大试用前，提供固定任务集、逐项正确性与全尝试费用 |
| Computer use 权限 | 应用负责人 | 使用真实账号前，隔离测试越权拦截、取消与写后回读 |
| 数据流与地域准入 | 数据与合规负责人 | 使用真实数据前，审批上传类别、驻留、处理与工具数据流 |
| 服务与采购验收 | 采购及应用负责人 | 扩大部署前，SLO、回退、合同与 TCO 分别通过预设标准 |
| 价格、权益、型号变化 | 文档维护者 | 2026-11-27 前或官方变更时，更新台账而非覆盖历史记录 |
