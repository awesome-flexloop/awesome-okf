# Sol 的 token 价格与缓存成本

2026-10-27 模型参考的 Standard 文本 token 价格为每百万输入 2 美元、缓存输入 0.10 美元、输出 10 美元。[F-015] 缓存读取价格是未缓存输入的 5%，这个折扣只针对符合命中条件的输入部分，不是整任务降低 95%。[F-016]

## 计费类别

**缓存细则有来源冲突。** 模型参考两次都列写入费；恢复后通用缓存页却称无额外写入费，保留参数也返回旧 `in_memory`/`24h` 说明。下表保留前轮 TTL 说明和模型价格，不能当作今天账户已验收的报价单。[F-017、F-022、F-023、F-083]

| 类别 | 每百万 token 的 Standard 费率 |
|---|---:|
| 普通未缓存输入 | 2 美元 [F-015] |
| 缓存读取 | 0.10 美元 [F-015] |
| 缓存写入 | 模型参考为 2.50 美元；前轮指南对应 30m [F-017、F-022] |
| 12 小时缓存写入 | 前轮指南倍率推得 5 美元；TTL 与恢复后页面冲突 [F-022] |
| 输出 | 10 美元 [F-015] |

前轮缓存指南将输入按未缓存、缓存读取或缓存写入类别计费，写入费率不再叠加普通输入费率；恢复后页面却称写入无额外费。[F-023] 在模型参考写入费采用“替代类别”的条件下，对同一输入 token 再计完整普通输入费率会重复计算。最终以当前接口计量和账单裁定。

以下公式是本束条件推导，采用前轮写入替代类别与 TTL 倍率，适用于 Standard、输入不超过 272K、未叠加地区或速度修饰项的文本请求；变量均为实际计费类别数量。若真实账单不采用这些类别，公式不适用：

```text
文本 token 费用（美元）
  = 普通输入数 / 1,000,000 * 2
  + 缓存读取数 / 1,000,000 * 0.10
  + 30分钟写入数 / 1,000,000 * 2.50
  + 12小时写入数 / 1,000,000 * 5
  + 计费输出数 / 1,000,000 * 10
```

从服务账单或 usage 取得计费输出数量，不以最终可见回答字数估算推理输出。工具、图像及环境费用以实际账单单列，公式不是完整 Agent 账单。

## 长上下文与服务模式

输入超过 272K 时，完整请求的输入及缓存费率乘 2，输出乘 1.5；并非只给超出的 token 加价。[F-018] 1,050,000 上下文容量与 272K 价格阈值是不同边界。

Fast 为 Standard 的 2 倍；Batch 与 Flex 比 Standard 低 50%；部分地区 processing 加价 10%。Ultrafast 的原价格来源位置未保留，本束不提供其报价倍率。[F-019、F-020、F-021] 这些是价格规则，不能把倍率解释成保证提速。模式组合、地区资格、工具计费和适用 SLA 在上线前仍应核对，不在未取得细则时盲目连乘全部倍率。

## 缓存如何命中

提示缓存保留可复用前缀的 KV 状态，后续请求需要渲染后的完整前缀匹配。[F-024] 两次说明都给最低 1,024 个输入 token；“GPT-5.6 以后按可见输入计、隐藏系统内容不计”只在前轮取得，细则待复核。[F-025] 前缀足够长只是必要条件之一，路由、生命周期和设置变化也会影响命中。

稳定的业务说明、工具定义放在前部，任务变化内容放在后部，是基于前缀机制的组织建议。缓存不跨组织共享；地域处理与保留位置约束另行核对，不能由保留位置推定缓存共享隔离规则。保持会话不能保证命中。[F-026]

不要为了凑最低长度给短请求填充无关文字。应先比较不缓存、实际写入与重复读取的费用，而不是追求命中率本身。

### 缓存写入的盈亏读法

仅比较同一前缀的输入费用，假设一次写入、后续全部命中、未触发其他价格项：

```text
30分钟缓存方案：2.50 + 0.10 * 后续读取次数
全用普通输入：2.00 * (1 + 后续读取次数)
```

两式均按每百万前缀 token 计。一次后续命中时前者为 2.60、后者为 4.00；没有复用时写入反而更贵。这是代数示例，不是实测节省率。12 小时写入的成本更高，应依据真实重复次数和命中窗口判断。

## 成功任务成本

```text
成功任务平均总成本
  = 固定批次内所有尝试的模型、工具、环境和返工费用之和
    / 通过预定验收条件的任务数
```

失败请求、重试、超时和人工修正均进入分子。通过数为零时比值不可定义，应报告零成功与已发生费用。统一币种、统计周期和人工折算率；没有折成美元的人工分钟数单列，不能相加。

分母为去重后通过验收的任务数；同一任务重试成功只计一次。需要截止时间的业务，超时交付应按预定规则计失败。

上述公式是批次运行成本。采购 TCO 还应单列接入开发、迁移测试、持续监控、固定订阅和维护投入，按明确周期与预期任务量分摊。回本分析保留“不换模型、仅优化旧工作流”的对照；没有固定投入与任务量数据时不输出 ROI 数字。

这套口径用于设计自己的评估，不能直接替换官方图表里的 cost per task。模型 token 单价、ChatGPT 套餐权益和端到端成本分别核对。
