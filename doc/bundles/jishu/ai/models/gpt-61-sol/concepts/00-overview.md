# Sol 的定位与学习路径

GPT-6.1 Sol 的官方定位是以更低成本处理复杂编码、电脑操作与专业工作，达到 near-Astra 表现。[F-002] “near”是厂商定位，不是所有任务上的质量等价；官方也要求使用自己的任务比较两者。它适合作为复杂工作候选模型，而不是未经测试的统一替代品。

## 四个层次分别核对

| 层次 | 需要核对的对象 | 不应混同 |
|---|---|---|
| 模型 | `gpt-6.1-sol`，模态、effort、上下文 [F-001、F-004–F-008] | 原生输出与工具生成 |
| API | Responses、无工具的 Chat Completions、Batch [F-012、F-028、F-047] | 端点支持与业务验收 |
| 工具与宿主 | computer use 等工具、应用 driver、截图与权限 [F-011、F-034–F-039] | 模型建议与真实动作 |
| 产品入口 | 发布时 ChatGPT 工作、Codex 及套餐开放描述 [F-048] | API 限速、聊天权益与账号当前可用性 |

effort 是模型的推理投入档位；driver 是执行模型动作的程序；缓存是对相同输入前缀中间状态的复用；cost per task 是特定评测对单任务费用的统计，不等于成功交付任务的总成本。先理解这四个词，再读价格与评测会更容易。

## 从任务选择入口

| 任务 | 初始评估方向 | 必须另验收的条件 |
|---|---|---|
| 修改仓库、跨文件编码 | 比较 Sol medium/high 与原模型，固定测试与执行器 | 测试通过、接口兼容、未改无关文件 |
| 浏览器采集与业务软件操作 | 比较观察历史、截图策略与 Sol 档位 | 采集正确性、真实保存结果、授权范围 |
| 长 PDF 与专业分析 | 使用人工参考核对关键事实与页内证据 | 领域判断、遗漏、引用忠实度 |
| 最困难科研任务 | 保留 Astra 作为对照，官方也建议该路径 [F-061] | 数据、推导与程序独立复核 |
| 语音、视频或直接图像输出 | 先选专门模型/端点 | Sol 本体只输出文本 [F-006、F-047] |

这些是评估设计建议，不是本束实测推荐。“默认 medium”只表示接口默认值；是否采用 high，应由任务成功标准和真实费用决定。

## 产品时间边界

模型参考的 2026-04-30 是知识截止日。[F-003] 系统卡增补标注 2026-09-29，Asana 案例页标注 2026-10-09；Sol 发布文日期本次没有取得。[F-041、F-068] 三种日期不能互相替代。

发布文称 Sol 开放到 ChatGPT 工作和 Codex，暂未进入“聊天”，并预告 Ultrafast 在未来几天推出。[F-048、F-049] 这些是发布时状态；本次没有进入真实账户验证今日权益，不把预告写成当前已全面开放。
