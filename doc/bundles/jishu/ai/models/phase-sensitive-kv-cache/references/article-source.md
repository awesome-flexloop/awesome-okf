## KV Cache 压缩背景（F-021 ~ F-027）

| F 编号 | 事实 | 类别 |
|--------|------|------|
| F-021 | 长上下文推理需保存大量历史 Token 的 Key/Value 供注意力使用，上下文越长缓存内存与计算开销越大 | 背景 |
| F-022 | DeepSeek-V4 采用分块 KV Cache 压缩：把连续 token 分成窗口，将窗口信息压缩成更少缓存条目 | 机制 |
| F-023 | token 相对窗口边界的位置称为 Phase（相位） | 术语 |
| F-024 | 模型对不同相位的信息存在系统性检索能力差异，命名为相位敏感性 | 术语 |
| F-025 | 该问题不能简单归为"信息恰好被切在窗口之间"——即使 Key 和 Value 都在同一窗口，不同位置检索准确率也可相差很大 | 结论 |
| F-026 | 压缩的目的是节省内存、降低长上下文注意力计算成本 | 背景 |
| F-027 | 即便存在位置偏差，长上下文推理的内存/计算成本仍在，压缩仍有现实价值 | 结论 |

## 从头预训练模型家族（F-028 ~ F-034）

| F 编号 | 事实 | 类别 |
|--------|------|------|
| F-028 | 以 Qwen3-0.6B 架构为基础，构造多种 KV Cache 压缩方案，并设无压缩的全注意力模型作对照 | 实验事实 |
| F-029 | 所有受测分块压缩模型都出现与压缩步长对应的周期性变化 | 实验结论 |
| F-030 | 全注意力基线模型没有出现同等程度的周期性 | 实验结论 |
| F-031 | 分别调整窗口大小与压缩步长，发现周期主要跟着压缩步长变化（步长 4/6/8 → 周期 4/6/8） | 实验结论 |
| F-032 | 不使用 RoPE 位置编码、或把可学习压缩权重换成简单平均，相位敏感性依然存在 | 实验结论 |
| F-033 | 结论：问题并非某位置编码或特殊模块单独造成 | 结论 |
| F-034 | 结论：分块压缩这种设计本身就可能引入周期性检索弱点 | 结论 |
