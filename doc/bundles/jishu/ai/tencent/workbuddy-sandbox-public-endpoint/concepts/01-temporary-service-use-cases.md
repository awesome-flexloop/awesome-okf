# 临时服务的适用场景与边界

博文列出六类用途（F-012）。这些用途的可行性并不相同：公网 HTTPS 页面已经被实证，但回调、支付、长期托管还涉及鉴权、限流、SLA 和数据生命周期。

## 1. 场景适配矩阵

| 场景 | 建议等级 | 适配理由 | 必要约束 |
|------|----------|----------|----------|
| 临时演示 / Demo | ✅ 适合 | 可快速把本地页面或原型通过 HTTPS 链接发给观看者；历史案例包含个人技术站、学习台和业务小工具（F-034） | 演示前确认服务在线；准备回收后链接失效的说明 |
| 快速托管静态页 | ✅ 适合 | 静态页无后端状态，和实时案例最接近（F-012、F-034） | 仍应避免放入私密数据、内部文档和未公开素材 |
| 小程序/公众号后端联调 | ⚠️ 有条件适合 | HTTPS 是必要条件之一，平台域名能降低本地联调成本（F-012） | 还需满足对应平台的域名校验、业务鉴权、接口格式与账号权限；不能只凭 HTTPS 判断可行 |
| 给 Agent 当临时接口 | ⚠️ 原型适合 | 可让外部工作流临时访问沙箱中的 HTTP 服务（F-012） | 必须加访问控制、请求校验和速率限制；不要把无鉴权工具执行接口暴露到公网 |
| Webhook 接收端 | ⚠️ 仅短时间测试 | 沙箱域名可作为临时回调地址（F-012） | GitHub/支付等回调要求地址稳定、可重试、可验签；博文也承认会话结束服务会消失（F-019、F-021） |
| frp/ngrok 内网穿透替代 | ⚠️ 仅轻量替代 | 对“临时给别人看页面”足够方便（F-012） | 不等同完整隧道产品：自定义域名未获证实（F-022）；保留地址、TCP/UDP 转发、观测和 SLA 差异为编者基于产品边界的推导 |

## 2. 为什么临时演示最适合

临时演示的核心需求是：

1. 快速获得一个外网可打开的 HTTPS 地址；
2. 不需要长期保留；
3. 数据和环境可以随演示结束而回收；
4. 访问者主要查看页面或试用原型。

这与博文所说“会话在、服务在”和“沙箱回收、链接失效”相匹配（F-014）。实时案例中的个人主页、学习闯关台和保质期计算器也都属于可公开展示的轻量 Web 应用，而非依赖强事务和私密数据的核心业务系统（F-034、F-035）。

## 3. Webhook 场景为什么要降级处理

Webhook 与普通网页访问不同。外部平台通常会：

- 在事件发生时主动向 URL 发送 POST；
- 在超时或 5xx 时重试；
- 要求签名或密钥验证；
- 对响应时间、载荷大小和 TLS 配置有要求；
- 在订单、支付、代码仓库事件等场景留下审计链路。

博文只说明可把沙箱域名填入 GitHub 或支付回调（F-012），同时又提示端口、限流以平台实际为准、沙箱不应作为生产环境（F-019、F-021）。因此本知识包将该用途限定为**短时间联调**，不把它写成可直接承接生产回调的方案。

## 4. 安全边界

### 4.1 不要放置的内容

博文明确提示不要放机密和长期数据（F-020）。具体包括：

- 云厂商 AccessKey、API Token、OAuth Secret、私钥；
- 客户数据、员工数据、财务数据和未公开业务数据；
- 只依赖“别人猜不到 URL”的内部文件；
- 需要长期持久化的数据库和上传文件；
- 可执行高权限操作但没有鉴权的 Agent 工具接口。

### 4.2 最小防护清单

即使是临时服务，也建议满足：

1. 页面或接口区分公开内容和管理能力；
2. 写入类接口使用临时令牌、签名或一次性请求头；
3. 日志中不记录密钥、Cookie 或完整敏感载荷；
4. 限制请求体大小与调用频率；
5. 演示结束后停止服务，而不是依赖沙箱自动回收；
6. 对第三方回调做签名校验与重放保护。

这些要求不是博文逐条给出的命令，而是根据其“无机密、非生产、限流以平台为准”边界推导出的读者防护措施（F-019~F-021）。

## 5. 与传统部署的取舍

博文用“轻量云、nginx、证书”对比传统路径（F-013、F-027），但两者不是替代关系：

| 决策项 | 临时沙箱公网端点 | 云服务器/容器/托管平台 |
|--------|------------------|------------------------|
| 启动速度 | 快，适合即时分享（F-013） | 需要实例、部署、网络和证书配置 |
| 生命周期 | 随环境/会话变化，需现场确认（F-014、F-019） | 可按服务目标配置保活、弹性和备份 |
| 域名 | 平台分配，自定义能力未证实（F-022） | 可绑定自有域名 |
| 运维责任 | 平台隐藏代理和证书细节 | 用户掌握网关、证书、观测和升级 |
| 适用负载 | Demo、静态页、短期联调 | 生产 API、支付/代码回调、长期 Agent 服务 |

## 6. 本篇结论

这条能力的正确定位是“**临时公网展示与联调通道**”，而不是“零成本生产服务器”。如果目标是几分钟内展示一个页面，它的投入产出比很高；如果目标是稳定接收外部回调或运行长期 Agent，应选择有明确生命周期和 SLA 的云服务器、容器或 WMA 托管 Runtime（F-018、F-030、F-031）。
