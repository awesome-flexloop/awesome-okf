# 会话保活、生产边界与提示词改写

## 1. 生命周期：先判断自己使用的是哪种环境

博文用一句话概括临时链路：“会话在、服务在”（F-014）。这适用于短生命周期预览沙箱，但不能覆盖 WorkBuddy 生态中的全部运行形态。

| 环境 | 生命周期特征 | 适合任务 |
|------|--------------|----------|
| 临时预览/沙箱环境 | 会话或环境回收后链接可能失效；博文明确提示“沙箱活着服务才活着”（F-019） | 临时 Demo、静态页、短时联调 |
| CloudStudio 已部署环境 | CodeBuddy IDE 4.12 已提供部署记录查看与删除入口（F-033） | 已生成 Web 应用的部署与清理，具体保留策略以产品界面为准 |
| CodeBuddy Remote Control | 本地 Gateway 通过 Cloudflare Tunnel 或局域网暴露远程 Web UI，Beta 功能（F-032） | 远程操作本机会话，不用于托管后端服务 |
| WorkBuddy Managed Agents | 云端沙箱，官方描述支持 7×24、自动休眠、毫秒级恢复、数据持久化与跨节点恢复（F-030、F-031） | 企业托管 Agent、长程任务、在线客服、自动触发任务 |

因此，遇到链接失效时，第一步不是盲目执行心跳，而是确认当前服务到底跑在哪个产品形态中。

## 2. 博文给出的三种保活办法

### 2.1 周期性心跳

博文建议运行：

```bash
while sleep 60; do date; done
```

这是通用 shell 循环，可让终端保持周期性输出（F-015）。但它是否能阻止特定平台的空闲回收，博文没有提供官方策略或实验数据；不能把它视为保活承诺。

### 2.2 后台运行与终端解绑

博文建议：

```bash
nohup node server.js > app.log 2>&1 &
disown
```

该命令的作用是让 Node 进程在后台运行、输出写入日志，并从当前终端任务列表解绑（F-016）。它解决的是“关闭终端导致 SIGHUP”的问题，不解决“环境休眠、机器回收、部署过期、平台限流”等问题。

### 2.3 让 Agent 自行监控

博文建议让 WorkBuddy 挂心跳并检查域名是否可通（F-017）。这适合作为临时演示前的巡检，但应要求 Agent 报告：

- 本地服务进程是否存在；
- 本地端口是否有 HTTP 响应；
- 平台面板显示的实际域名是什么；
- 外部 HTTPS URL 返回状态码是多少；
- 若失败，失败发生在本地服务、平台网关还是外部网络。

## 3. 生产边界

博文已经给出关键底线：真正需要 7×24 时，应使用正经云服务器或容器；保活只是拖时间，不是买保险（F-018）。本知识包将该判断细化为四条红线：

1. **不要承诺可用性**：临时域名没有在博文中给出 SLA、RTO/RPO 或故障支持承诺。
2. **不要保存唯一数据**：博文明确提示不要放长期数据（F-020）。
3. **不要依赖未证实端口和限流规则**：平台策略以实际配置为准（F-021）。
4. **不要假定品牌域名能力**：博文称不能自定义品牌域名，但该点未获官方文档复核（F-022）。

若服务需要稳定承接外部回调、长期运行数据库或处理敏感数据，应改用：

- WorkBuddy Managed Agents 等托管 Runtime（适合企业 Agent，F-030、F-031）；
- 云服务器、容器服务或长期应用托管平台（博文也给出这一方向，F-018）；
- 具备自定义域名、证书管理、日志监控、弹性伸缩和备份策略的正式部署环境。

## 4. 安全版提示词（非官方改写）

> **非官方提示词**：以下内容由本知识包根据博文改写，目的是避免 Agent 硬编码过期域名或擅自安装 nginx。它不是腾讯官方文档原文（改写自 F-023，限制见 F-037~F-039）。

```text
我需要把一个临时 Web 服务通过当前平台提供的公网 HTTPS 入口暴露出去，用于短时间演示。

请按以下步骤执行：
1. 先在沙箱内启动一个只提供公开演示内容的 HTTP 服务，避免写入任何密钥、客户数据或长期数据。
2. 不要自行安装 nginx、申请证书或猜测公网域名；先查看当前沙箱信息、任务面板或部署环境中平台实际分配的 HTTPS 域名。
3. 如果平台明确提供端口转发/公开访问能力，按面板提示使用实际域名验证服务。
4. 如果平台没有显示公网域名、端口不支持转发，或需要额外配置，请停止并把缺少的条件告诉我，不要虚构域名。
5. 验证本地 HTTP 响应和外部 HTTPS 响应，分别记录状态码与失败环节。
6. 明确标注这是临时演示环境，不承诺 7×24；不要在服务中暴露无鉴权的写入接口或可执行高权限操作的 Agent 工具。
```

与博文原提示词相比，改写版删除了固定 `sh1.agentos-app.net`、CLB 和 sandbox-proxy 断言（F-007~F-009），改为从平台读取当前域名；同时加入数据、鉴权和失败停止条件。

## 5. 演示前检查清单

- [ ] 服务只包含可公开演示的数据与页面。
- [ ] 本地 HTTP 路径返回预期状态码和内容。
- [ ] 平台面板显示的公网域名已复制，未手工拼接后缀。
- [ ] 外部浏览器通过 HTTPS 打开成功。
- [ ] 写入型接口具备临时鉴权或已禁用。
- [ ] 已确认环境休眠/回收的处理方式。
- [ ] 演示结束后停止服务或删除部署记录。
- [ ] 若需要长期运行，已迁移到 WMA、云服务器或容器平台。

## 6. 本篇结论

`nohup`、`disown` 和心跳只能改变进程与终端的关系，不能改变平台的资源生命周期（F-015、F-016、F-019）。临时公网端点的价值在于快速、低运维、可回收；一旦需求转为持续服务、稳定回调或敏感数据处理，就应切换到具有明确生命周期管理的运行环境。
