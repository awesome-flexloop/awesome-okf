# 桌面 Agent 能力判读：从榜单到软文的证据分层

> 本篇对应知识地图第三层（So-what）：博文作者提出的「托付命题」是否站得住、该用什么框架评判一个桌面 Agent、以及如何从一篇厂商正面实测软文中提取可靠信息。本篇是方法论与判读指南，不是对 WorkBuddy 的独立评测。

## 1. 把作者的托付命题翻译成可检验的能力项

博文的核心论点（F-021，作者观点）是：用户愿意把多少工作交给 Agent，取决于它能否**理解目标、调度能力、接住变化、持续推进到结果**。这四个动作恰好可以与沙利文报告的技术指数维度（F-025）对齐：

| 作者命题（博文话语） | 可检验的能力项（报告话语，F-025） | 博文给出的观察证据 |
|---------------------|--------------------------------|------------------|
| 理解目标 | 任务规划、需求澄清 | 三问澄清（痛点/MVP 范围/使用规模）F-008 |
| 调度能力 | 工具调用、多 Agent 协作、Skills/MCP 扩展 | 四角色介入、变更派活、连接器 F-007/F-012/F-016 |
| 接住变化 | 记忆管理、错误恢复、权限控制 | 长程上下文、自述调研局限 F-013/F-015 |
| 推进到结果 | Harness 工程、交付与发布链路 | PRD→开发→14 天试用版小程序 F-009/F-017/F-018 |

这一对齐的意义在于：作者的感性结论并非自说自话，它与第三方评价框架使用的维度基本同构。但**维度同构不等于水平被证明**——博文是单一任务、有利视角下的演示，报告才是跨产品比较的结果，两者证据等级不同。

## 2. 为什么「Harness 是胜负手」

沙利文报告经媒体转述提出：**Harness 是桌面 AI 智能体的真正胜负手**（F-025）。Harness（驾驭层/工程衔接层）指模型与外部世界之间的工程化体系——任务规划、工具调用、环境隔离、权限控制、错误恢复、状态记忆等。

这与「模型能力决定论」形成对比：

```mermaid
flowchart LR
    M["基础模型能力<br/>推理/生成"] --> H["Harness 驾驭层<br/>规划·工具·记忆·权限·恢复·发布"]
    H --> R["可交付的工作成果<br/>文档/应用/数据/可访问产物"]
    style H fill:#e8f0fe,stroke:#4285f4
```

对办公场景，用户感知的不是模型参数，而是「说一句话后，有没有东西被真正做出来、做错了能不能被发现和修正、产物能不能直接用」。博文实测展示的三件套产出（F-009）、变更联动（F-012）、不确定性披露（F-013）和一键发布试用版（F-018），都属于 Harness 层能力的展示。报告把**自定义模型零成本接入**称为「独有护城河」（F-025，媒体转述报告用语），同样指向工程与生态层而非模型层。

读者可据此调整评测重心：比较桌面 Agent 时，与其比较「谁写得好」，不如设计一组需要**多步规划 + 工具调用 + 中途变更 + 最终交付**的真实任务，观察全链路完成率。

## 3. 读这篇文章的证据分层

本束在事实登记时采用三层分类（见[信源清单](../references/article-source.md)），这也是读者复用时应持有的取用规则：

| 层级 | 内容举例 | 可怎么用 | 不可怎么用 |
|------|---------|---------|-----------|
| ✅ 已外部核验的事实 | 双榜第一（F-024）、小程序发布能力与 5.6.1/14 天试用版（F-029）、腾讯身份（F-023）、月活（F-028） | 可作为行业事实引用，标注来源与口径 | 不可把转述级报告（Omdia/IDC）说成报告原文 |
| 🟡 博文过程叙述（产品口径） | 五阶段流程、多角色协作、PRD/画像/问卷生成 | 可作为「产品宣称的能力与体验路径」引用 | 不可当作独立复现过的普遍能力；无版本/输入输出记录 |
| ⚠️ 单源信息 | 「腾讯问卷」连接器（F-031）、微信原文账号与发布时间（F-032） | 可作为待核实线索 | 不可断言其存在/精确时间，更不可据此推断商业赞助关系 |
| 💬 作者观点/体验 | F-003、F-010、F-015、F-020、F-021 | 可作为产品经理视角的**一种解读**参考 | 不可包装成客观结论或腾讯官方表态 |

特别说明：本篇博文与典型「成效数字型」软文不同——**全文没有提效倍数、节省工时、成本下降类数字**（核验清单②，见[核验报告](../references/verification.md)）。它的营销载荷在两处：榜单背书（已核验属实）与定性能力展示（单次案例）。识别软文时，没有造假数字不代表没有立场——选题（新产品上线当天）、叙事结构（全程顺滑无失败）、结尾 CTA（F-022）共同构成了有利框架。

## 4. 批判性提问清单：复用「一句话需求」实测时该追问什么

把博文方法迁移为自己的评测时，建议补齐作者有意或无意省略的对照项：

1. **输入对照**：一句话需求之外，澄清轮补充了多少信息？如果不补充，产出降级到什么程度？（博文 F-008 显示澄清是产出三件套的前提）
2. **失败与回退**：五阶段全程无返工失败记录。真实使用中 Agent 误判影响面、工具调用失败时如何恢复？（对应报告的「错误恢复」维度，博文未覆盖）
3. **权限与数据**：连接器读写、本地文件访问、发布小程序分别需要什么授权？数据流向哪里？（报告「权限控制」维度，博文未覆盖）
4. **产物所有权**：14 天试用版不可转正式版（F-029）——到期后用户与数据如何处置？绑定自有账号发布的审核主体是谁？
5. **可复现性**：同一需求在不同会话、不同时间（产品快速迭代，50+ 版本/6 个月，F-027）能否得到同等结果？
6. **对照基准**：与人工 PM+开发者团队、或与同类桌面 Agent 相比，时间/质量差异是多少？博文无对照组。

这六问不否定博文的信息价值，而是把「演示证据」还原为它应处的位置：**产品能力的存在性线索**，而非「产品已可托付复杂工作」的充分证明。

## 5. 市场地位叙事的口径边界

- **沙利文双榜**（F-024）：中国、桌面 AI 智能体、个人端/企业级、2026-09 报告——竞争力评估证据，三家媒体转述同一报告；
- **AICPB 月活**（F-028）：桌面端、国内、2026-08 时点、1115.23 万——用户规模证据，单一调研机构经科技日报报道；
- **官方生态数字**（F-027、F-030）：100+ 专家、7 万+ Skills、50+ 行业、超百家伙伴——官方自述口径；
- **时间窗口**：上述叙事集中在 2026-08~09 的六周内，且与产品自身的密集发布节奏（企业版→开放平台→网页应用→小程序）同步。高增速与强宣发期重叠时，引用任何单点数字都应带上时间戳，并在 `stale_after: 2026-12-31` 后重新核验。
