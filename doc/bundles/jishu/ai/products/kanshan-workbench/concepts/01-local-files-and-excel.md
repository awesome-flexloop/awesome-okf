# 本地文件与 Excel：授权目录内的读、改、写回

## 1. 支持哪些文件

官方列举的常见格式包括 Excel、CSV、PDF、Word、PPT、Markdown、TXT、JSON、HTML、PNG 等图片，以及其他结构化或半结构化文档（F-010）。能力分三层：

1. **单文件读取与分析**：读取一个 Excel/PDF/Word 等文件，按指令分析、总结或修改。
2. **Excel 读、改、写回**：直接读取工作表数据，完成分析或修改后写回工作簿（F-011）。
3. **多文件综合处理**：同时读取 Word、PDF、Excel 等多个文件，做批量总结、内容对比与报告生成（F-013）。

> ⚠️ **格式边界**：读取格式列「PPT」，导出格式列「PPTX」（F-010、F-073），原文未说明旧版 PPT 的读取兼容范围与写回能力（F-120）。处理旧版 PPT 前建议先另存为 PPTX 或 PDF 再试。

## 2. 权限模型：不是「全盘可读」

官方把权限模型写成三条（F-015、F-108）：

- 不默认访问电脑中的全部文件；
- 用户需要主动授权可访问的目录范围；
- 应用仅在授权范围内读取、修改和保存文件。

初次配置时，系统会提示授予权限并选择允许访问的本地目录；官方建议把需要 AI 处理的文件统一放入指定工作目录，便于管理权限（F-065）。

**实践建议**：为看山工作台单独建一个工作目录（如 `~/KanshanWorkspace/`），只把当次任务需要的文件放进去；任务结束后移出敏感文件。这样既缩小授权面，也让「AI 能看见什么」保持可解释。

## 3. Excel 读改写回：一条完整链路

### 3.1 四步流程

官方把本地文件处理写成四步（F-069）：

1. **添加文件**：把文件放入已授权目录，或在对话中选择本地文件。
2. **发起任务**：用自然语言说明要分析或修改什么（F-070）。
3. **修改并写回 Excel**：明确工作表、数据范围、写入位置与保存方式（F-071）。
4. **保存或导出结果**：写回 Excel，或导出为其他格式（F-073）。

### 3.2 Excel 指令的五项要素

官方建议写回指令时明确五件事（F-071）：

| 要素 | 要写清楚什么 | 示例 |
|---|---|---|
| 数据范围 | 读取哪个工作表、哪些列/行 | 「读取『客户反馈』工作表的 A1:C200」 |
| 分析或修改 | 要做什么分类、计算或清洗 | 「把 B 列反馈分为功能、价格、服务和其他四类」 |
| 写入位置 | 原表、新列还是新工作表 | 「分类结果写入 C 列，不覆盖 B 列」 |
| 原始数据 | 是否保留 | 「保留原始内容，另存为新文件」 |
| 输出文件 | 文件名与保存位置 | 「另存为『客户反馈_已分类.xlsx』到同一目录」 |

官方给出的完整示例是：读取「客户反馈」工作表，将 B 列反馈分为功能、价格、服务和其他四类，把分类结果写入 C 列，保留原始内容并另存为「客户反馈 _ 已分类.xlsx」（F-072）。

### 3.3 为什么要「另存为新文件」

看山工作台没有内建的文件历史面板，也不提供操作级回滚或自动快照（F-093、F-098）。这意味着：

- 如果直接覆盖原文件，写错了只能靠你自己事先做的备份或 Git 提交恢复；
- 如果另存为新文件，原文件天然成为回退点；
- 如果目录是 Git 仓库，可以用只读 Git 命令查看改动，但恢复仍需用户确认（F-056、F-057、F-096）。

**默认策略**：先另存为新文件；确认结果无误后，再由用户手动替换原文件。

## 4. 多文件综合处理

官方示例有两类（F-014）：

- **批量总结**：读取一个文件夹内所有 PDF，总结每份文档的核心内容，整理成对比表；
- **材料汇总**：根据一个目录下的全部材料，整理项目背景说明，包括核心数据、关键结论和待解决问题。

多文件任务的关键是把「范围」和「输出结构」说清楚：

```text
读取 ~/KanshanWorkspace/项目资料/ 下的全部 PDF（共 N 份），逐份提炼：
1. 文档主题与时间范围
2. 三个核心结论
3. 关键数字（带出处页码）
最后汇总成一张对比表，输出为 Markdown 文件，保存到同一目录。
```

> **注意**：多文件读取会消耗更多上下文与时间；文件数量大时，建议先做一轮「目录清单 + 每份一句话摘要」，再挑重点深入，而不是一次性要求全量精读。

## 5. 结果输出与导出

官方列出的出口包括（F-073）：

- 写回 Excel；
- 生成或导出 Word、Excel、PDF、PPTX、CSV、JSON、Markdown、HTML、PNG 等文件；
- 导出到飞书文档；
- 复制到剪贴板；
- 保存到本地目录。

两项限制需要记住（F-074）：

1. PPTX 通过演示文稿 Skill 的标准流程生成；
2. Excel 公式重算等依赖 LibreOffice 的任务在当前环境中可能受限。

**如果你的表格含复杂公式**：写回后不要只看单元格显示值，要在 Excel 中打开并确认公式是否重算、引用是否错位；必要时让看山只写入值、不写入公式，或把公式列单独保留。

## 6. 文件安全与数据流向

官方在功能一、技术说明、FAQ、安全权限四处重复同一承诺：本地文件不会上传到云端，读取、修改与保存在用户电脑和授权范围内完成（F-016、F-051、F-102、F-109）。

但原文同时说云端能力用于模型推理、复杂任务规划、多模态理解和内容生成（F-049），并未说明本地文件内容如何参与云端推理（F-116）。因此：

- **可以引用**：「文件本体不会上传」是官方承诺；
- **不要扩写**：「任何数据都不离开本机」不是原文口径；
- **敏感材料**：先做脱敏副本（去掉姓名、手机号、客户 ID、金额等），再交给看山处理；处理完删除临时副本。

## 7. 一页检查表

- [ ] 文件已放入单独的工作目录，目录已授权（F-065）。
- [ ] 指令写清了工作表、范围、修改内容、写入位置、是否保留原数据、输出文件名（F-071）。
- [ ] 默认另存为新文件，不直接覆盖原文件（F-093、F-098）。
- [ ] 含公式的表格，写回后在 Excel 中人工复核公式与关键数字（F-074、F-101）。
- [ ] 多文件任务先列清单再深入，避免一次性全量精读（F-014）。
- [ ] 敏感材料先脱敏，不把「文件不上云」扩写为「数据不离机」（F-116）。
