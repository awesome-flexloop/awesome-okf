# 本地记忆与定时任务：让重复工作持续执行

## 1. 本地记忆：把「每次都要交代的背景」存下来

看山工作台支持本地记忆，可以记住用户主动提供的职业背景、行业语境、常用术语、文档偏好和工作习惯，让后续任务的输出更贴近个人需求（F-041）。

### 1.1 记忆放在哪里、怎么管

- 在「记忆中心」查看和编辑记忆（F-042、F-081）；
- 可以在对话中明确要求「记住某项信息」（F-081）；
- 可以从其他平台导入已有记忆（F-042、F-081）。

### 1.2 可以记什么

官方列出七类内容（F-043）：

| 类型 | 示例 |
|---|---|
| 职业角色和所属行业 | 产品经理、SaaS 行业 |
| 常用文档格式和表达方式 | 正式、清楚、不营销 |
| 常见任务类型 | 周报、竞品分析、需求评审 |
| 常用术语与团队内部口径 | DAU、留存率、LTV 的团队定义 |
| 数据分析指标 | 新增、留存、转化率、复用率 |
| 输出结构和风格偏好 | 结论—原因—建议 |
| 项目背景信息 | 项目目标、里程碑、关键干系人 |

### 1.3 记忆的结构与操作

官方把记忆分为**核心记忆**和**项目上下文**，可按主题保存偏好、项目、反馈及一般信息，并支持读取、关键词检索、写入、追加和覆盖（F-082）。

| 层 | 适合放什么 | 生命周期建议 |
|---|---|---|
| 核心记忆 | 长期稳定的偏好：职业、行业、表达风格、常用指标 | 长期保留，定期清理过时偏好 |
| 项目上下文 | 某个项目的目标、术语、干系人、阶段结论 | 项目结束后归档或删除 |

> **为什么区分两层**：如果把项目临时信息写进核心记忆，下一次无关任务也会被旧项目语境污染；如果把长期偏好只放在项目上下文，换个项目就要重新交代。分层是为了让「稳定的归稳定，临时的归临时」。

### 1.4 记忆示例

官方给出两组示例（F-044、F-068、F-083）：

- 「记住：以后帮我写产品更新说明时，语气保持正式，但不要太营销，重点讲清楚功能价值和使用场景。」
- 「记住：以后分析运营数据时，优先查看新增、留存、转化率和复用率。」
- 「记住：我常用的分析结构是现状、问题、原因和建议。」

### 1.5 记忆的边界

原文没有说明记忆的存储位置、加密方式、是否跨设备同步、如何彻底删除（仅有「删除记忆」的操作入口）。涉及个人隐私或商业秘密的信息，建议只写「口径」不写「原始数据」，例如写「客户 A 属于重点客户」，而不是写客户联系人与合同金额。

## 2. 定时任务：按时间自动执行

### 2.1 能做什么

定时任务支持按固定时间或固定周期执行，例如每日、每周或每月自动进行数据分析、资料汇总和报告生成（F-045）。

官方示例（F-047）：

- 每天上午 9 点读取指定目录中的销售数据，生成昨日销售简报；
- 每周五下午 5 点汇总本周业务数据，生成周报并导出为飞书文档；
- 每周一查看指定竞品官网的产品和价格变化，生成竞品动态简报。

### 2.2 创建任务的六个字段

进入「定时任务」页面创建任务，需要设置（F-084）：

| 字段 | 说明 | 示例 |
|---|---|---|
| 任务名称 | 可识别的短名 | 「每日销售简报」 |
| 执行时间 | 具体时间点 | 每天 09:00 |
| 任务指令 | 要做什么 | 读取昨日销售数据，生成简报 |
| 数据来源 | 本地文件或飞书文档等 | `~/KanshanWorkspace/sales/` |
| 输出方式 | 保存到知识库、导出文档、推送飞书 | 导出 Markdown 并推送飞书 |
| 重复周期 | 一次性/每天/每周/工作日/Cron | 每天 |

系统会打开预填好的创建窗口，任务需要由用户最终确认并保存（F-085）。**这一步不能省**：预填只是草稿，执行时间、数据源和输出目标都要人工核对。

### 2.3 五类周期

定时任务支持一次性定时执行，以及每天、每周、工作日或自定义 Cron 周期（F-086）。

- **一次性**：适合单次延迟任务，例如「今晚 22:00 汇总今天的资料」；
- **每天/每周/工作日**：适合日报、周报、工作日晨报；
- **自定义 Cron**：适合「每月最后一个工作日」「每两周一次」等非标准周期。

### 2.4 并发上限

当前最多支持 3 个并发任务；具体任务数量上限可根据产品版本和企业配置调整（F-046、F-089、F-118）。

这意味着：

- 同时运行的定时任务不要超过 3 个；
- 如果你的任务耗时较长，建议错开执行时间，避免排队；
- 「3 个」是采集时页面口径，没有版本锚点，升级后需重新确认。

### 2.5 触发机制：按时间，不按文件变化

原文明确：定时任务按时间触发，不会在文件发生变化时立即自动运行；如需接近「变更触发」的效果，只能通过定期检查文件并对比变化来实现（F-088）。

这是一个重要的设计约束。如果你需要「文件一改就处理」，只能：

1. 设置一个较短的检查周期（如每 10 分钟）；
2. 让任务先对比文件修改时间或哈希；
3. 只有发现变化时才执行正式处理。

> 这本质上是用「轮询」模拟「事件触发」，会带来延迟与空跑成本；对实时性要求高的场景，应使用专门的监听工具，而不是定时任务。

### 2.6 数据源、输出与执行记录

- 数据源可以使用本地文件、飞书文档等（F-087）；
- 结果可以保存到知识库、导出为文档或推送到飞书（F-087）；
- 任务完成后，可以查看执行记录和生成结果（F-087、F-110）。

**建议**：每次执行都保留记录，尤其是推送到飞书或覆盖文件的任务；一旦结果异常，可以从执行记录回溯输入、输出与时间点。

## 3. 记忆 + 定时任务的组合模式

| 模式 | 记忆提供 | 定时任务执行 | 适用场景 |
|---|---|---|---|
| 日报/周报 | 输出结构、指标口径、语气偏好 | 每天/每周读取数据并生成报告 | 运营、销售、项目管理 |
| 竞品监控 | 关注维度、竞品清单 | 每周读取竞品官网并对比 | 市场、产品 |
| 资料归档 | 分类规则、命名规范 | 每天整理指定目录并归档 | 研究、知识管理 |
| 个人复盘 | 复盘框架、关注问题 | 每周汇总本周记录并生成复盘草稿 | 个人成长、团队管理 |

组合使用的关键：**记忆负责「怎么想」，定时任务负责「什么时候做」**。把稳定的口径写进记忆，把易变的输入输出写进任务指令。

## 4. 一页检查表

- [ ] 长期偏好写入核心记忆，项目信息写入项目上下文（F-082）。
- [ ] 记忆只写口径与规则，不写原始敏感数据（原文未披露存储加密与同步边界）。
- [ ] 定时任务的六个字段逐项核对，尤其是执行时间、数据源、输出目标（F-084）。
- [ ] 预填窗口中的任务由人工确认后再保存（F-085）。
- [ ] 同时运行的定时任务不超过 3 个，长任务错峰（F-046、F-089）。
- [ ] 需要「文件一变就处理」时，用轮询 + 变化对比模拟，不期待事件触发（F-088）。
- [ ] 推送飞书或覆盖文件的任务，保留执行记录并定期抽查（F-087、F-110）。
