# 飞书连接、定时任务与 Coding 任务：三条进阶链路

> **说明**：步骤来自官方手册（F-040、F-067、F-079、F-084~F-090），本包未真机执行。企业平台的授权入口与权限名称可能随管理员配置变化，以你所在组织的当前界面为准。

## 链路 1：连接飞书

### 步骤

1. 进入「第三方数据」页面；
2. 选择「飞书」；
3. 选择连接方式：
   - 「自动创建/授权」：由系统引导创建应用并授权；
   - 「手动配置」：提供已有应用凭证与权限配置；
4. 按页面提示完成授权；
5. 回到主界面，确认飞书状态为已连接。

依据：F-040、F-067、F-079。

### 验收

- [ ] 状态显示已连接；
- [ ] 能读取一个你有权限的飞书文档；
- [ ] 不能读取你无权限的文档（返回空或无权限，而不是报错崩溃）；
- [ ] 发送消息/创建文档前有确认步骤。

### 读不到内容时的排查顺序

| 顺序 | 检查 | 依据 |
|---|---|---|
| 1 | 连接是否有效（是否过期、是否被管理员撤销） | F-039 |
| 2 | 组织是否开放了对应应用/接口权限 | F-039 |
| 3 | 当前用户是否有该文档/知识库的数据权限 | F-039 |
| 4 | 文档是否在个人空间而非组织空间 | 原文未展开，按飞书权限模型判断 |

## 链路 2：创建一个每日定时任务

### 场景

每天上午 9 点读取指定目录中的销售数据，生成昨日销售简报（官方示例，F-047）。

### 步骤

1. 进入「定时任务」页面；
2. 点击创建任务；
3. 在预填窗口中填写六个字段：

| 字段 | 填写示例 |
|---|---|
| 任务名称 | 每日销售简报 |
| 执行时间 | 每天 09:00 |
| 任务指令 | 读取昨日销售数据，生成简报：核心指标 / 异常变化 / 建议动作 |
| 数据来源 | `~/KanshanWorkspace/sales/`（本地文件） |
| 输出方式 | 导出 Markdown 并推送飞书文档 |
| 重复周期 | 每天 |

4. 人工核对执行时间、数据源、输出目标；
5. 保存任务。

依据：F-084、F-085、F-086、F-087。

### 先手动试跑

在启用周期前，先用同一条指令手动执行一次，确认：

- [ ] 能读到最新文件；
- [ ] 输出结构符合预期；
- [ ] 推送飞书成功，且没有覆盖同名文档；
- [ ] 执行记录里能看到本次运行。

### 并发与触发边界

- 同时运行的定时任务不超过 3 个（F-046、F-089）；
- 定时任务按时间触发，不会因文件变化立即运行（F-088）；
- 需要「文件一变就处理」时，设置短周期检查 + 对比文件修改时间/哈希，接受延迟与空跑成本。

### 一个更稳的任务指令模板

```text
每天 09:00 执行以下任务：
1. 读取 ~/KanshanWorkspace/sales/ 下修改时间最新的一个 Excel。
2. 计算昨日销售额、订单数、转化率，并与前 7 日均值对比。
3. 输出结构：核心指标表 → 异常变化（超过 ±20%）→ 三条建议动作。
4. 导出 Markdown 到 ~/KanshanWorkspace/reports/，文件名含日期。
5. 推送到飞书文档「销售日报」；如已存在同日文档，追加到末尾而不是覆盖。
6. 执行记录中保留：读取文件名、行数、计算口径、输出路径。
```

## 链路 3：Coding 任务与 Git 恢复

### 步骤

1. 在设置中授权项目目录（只授权该项目，不授权整个主目录）；
2. 确认目录是 Git 仓库；
3. 发起任务，先只读探查：

```text
在 ~/projects/demo 中执行：
1. 运行 git status、git log --oneline -5，报告仓库状态。
2. 阅读 src/ 下的代码，列出模块结构与入口。
3. 不要修改任何文件。
```

依据：F-090、F-095。

4. 确认结构后，再发起最小修改任务：

```text
修改 src/utils.py 中的 parse_date 函数，使其支持 YYYY/MM/DD 格式。
要求：
- 只改这一个函数，不改其他文件；
- 修改后展示 git diff；
- 运行项目已有测试，报告通过/失败项；
- 不执行 git push、不强推、不删分支、不重写历史。
```

依据：F-090、F-100。

5. 修改后复核 `git diff` 与测试结果；
6. 如需恢复某个文件：

```text
把 src/utils.py 恢复到上一次提交的版本。
执行前先运行 git status，确认是否有未提交改动；
如有未提交改动，先告诉我并等待确认，再决定是否备份或暂存。
恢复后展示 git diff，确认工作区状态。
```

依据：F-057、F-058、F-096。

### 三条硬边界

| 边界 | 含义 | 依据 |
|---|---|---|
| 本地服务会被回收 | 当前会话结束后，本地开发服务停止 | F-091 |
| Python 依赖装受管环境 | 直接装宿主环境可能无法在沙箱使用 | F-092、F-119 |
| 无操作级回滚/快照 | 只能靠 Git 或事先备份 | F-093、F-098 |

### 验收

- [ ] 只读探查没有产生文件改动；
- [ ] 最小修改只触及指定函数；
- [ ] `git diff` 内容与任务要求一致；
- [ ] 项目测试通过，或有明确的失败清单；
- [ ] 没有自动 push、强推、删远端分支或重写历史；
- [ ] 本地服务只在会话内使用，未作为长期公开服务。

## 三条链路的组合

```text
本地数据 → 定时任务生成日报 → 推送飞书文档
                ↓
         Coding 任务维护生成脚本
                ↓
         Git 提交保存脚本版本
```

- 定时任务负责「按时跑」；
- 飞书负责「给团队看」；
- Coding 任务负责「改脚本」；
- Git 负责「可回退」。

四者各司其职，不要指望单一功能覆盖全部环节。

## 失败排查表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 飞书连接失败 | 组织未开放应用、回调被拦截 | 检查组织权限；换默认浏览器重试（F-039） |
| 定时任务未执行 | 任务未保存、时间设置错误、并发已满 | 检查任务状态与执行记录；错峰（F-085、F-089） |
| 推送覆盖了文档 | 任务指令未限制同名处理 | 指令中写明「同名则追加，不覆盖」（F-080） |
| Coding 任务装依赖失败 | 装到了宿主环境而非受管环境 | 先确认解释器路径（F-092、F-119） |
| 代码改动无法回退 | 目录不是 Git 仓库或没有备份 | 开工前 `git init` 或整目录备份（F-094、F-098） |
