# Excel 写回的五套任务模板与验收方法

> **使用方式**：把模板中的 `[方括号]` 替换为实际文件名、工作表名与列名。所有模板都遵循官方建议的五项要素：数据范围、分析或修改、写入位置、是否保留原始数据、输出文件名与位置（F-071）。

## 模板 1：分类列写回（保留原列）

**适用**：客户反馈分类、工单归类、评论情感分类。

```text
读取 [文件路径] 的「[工作表名]」工作表，范围 [A1:C200]。
把 [B] 列的文本按以下规则分类：[功能 / 价格 / 服务 / 其他]。
分类结果写入 [C] 列，表头为「反馈类型」，不覆盖 [B] 列原始内容。
保留原始数据，另存为 [原文件名_已分类.xlsx]，保存到同一目录。
完成后报告：分类总数、各类别数量、无法归类的行号。
```

**官方同款**：读取「客户反馈」工作表，将 B 列反馈分为功能、价格、服务和其他四类，把分类结果写入 C 列，保留原始内容并另存为「客户反馈 _ 已分类.xlsx」（F-072）。

**验收**：

- [ ] 原列未被覆盖；
- [ ] 新列有表头；
- [ ] 类别数量之和等于总行数；
- [ ] 无法归类的行被明确列出，而不是强行归类。

## 模板 2：异常值检查与批注

**适用**：金额、库存、转化率、时长等数值列的异常检查。

```text
读取 [文件路径] 的「[工作表名]」，检查 [D] 列（[指标名]）的异常值。
判定规则：低于 [P1] 或高于 [P99]，或偏离中位数超过 [3] 倍四分位距。
不要删除或修改任何数值；在异常单元格添加批注，说明异常类型与判定依据。
另存为 [原文件名_异常检查.xlsx]。
完成后列出所有异常单元格的坐标、原值、判定原因。
```

**官方同款**：检查表中的异常值，用批注说明异常原因并保存修改（F-012）。

**验收**：

- [ ] 数值未被修改；
- [ ] 批注挂在正确单元格；
- [ ] 异常清单与批注一一对应；
- [ ] 判定规则在报告中复述，便于复核。

## 模板 3：多文件汇总对比

**适用**：同目录多份周报、月报、PDF 摘要的横向对比。

```text
读取 [目录路径] 下的全部 [PDF/Word/Excel] 文件（共 [N] 份）。
逐份提取：[文档主题、时间范围、三个核心结论、关键数字及出处页码]。
汇总成一张对比表，列包括：[文件名 / 主题 / 时间范围 / 结论1 / 结论2 / 结论3 / 关键数字]。
输出为 Markdown 与 Excel 两份，保存到 [输出目录]。
无法提取的单元格写「未披露」，不要猜测。
```

**官方同款**：读取文件夹中的所有 PDF，总结每份文档的核心内容，并整理成一个对比表（F-014）。

**验收**：

- [ ] 文件数量与目录清单一致；
- [ ] 每份文件的结论都有出处（页码/工作表）；
- [ ] 缺失项写「未披露」而不是空白或猜测；
- [ ] 输出两份格式内容一致。

## 模板 4：清洗与去重

**适用**：名单、订单、线索表的规范化。

```text
读取 [文件路径] 的「[工作表名]」，执行以下清洗：
1. 去除 [A] 列首尾空格；
2. 将 [B] 列日期统一为 YYYY-MM-DD；
3. 按 [C] 列（[唯一键]）去重，保留最新一条；
4. 不删除任何行，把清洗结果写入新工作表「清洗结果」。
另存为 [原文件名_清洗.xlsx]。
完成后报告：原始行数、去重后行数、日期格式修正数量、仍无法解析的行号。
```

**验收**：

- [ ] 原工作表保留；
- [ ] 去重键选择合理（如订单号，而不是姓名）；
- [ ] 行数变化有解释；
- [ ] 无法解析的行被列出，而不是静默丢弃。

## 模板 5：分析结论写入新工作表

**适用**：销售分析、运营分析、财务分析。

```text
读取 [文件路径] 的「[工作表名]」，分析 [指标1]、[指标2]、[指标3]。
输出结构固定为：结论（3 条以内）→ 原因（每条结论对应）→ 建议（可执行动作）。
把分析写入新工作表「分析结论」，原工作表保持不变。
另存为 [原文件名_分析.xlsx]。
完成后报告：读取行数、使用列、计算口径、结论写入位置。
```

**官方同款**：分析 Excel 文件中的销售数据，找出增长最快和下滑最明显的品类，并将分析结论写入一个新的工作表（F-012）。

**验收**：

- [ ] 结论、原因、建议三层齐全；
- [ ] 每条结论都能对应到数据列或计算；
- [ ] 原工作表不变；
- [ ] 计算口径被写明（如「增长率 =（本期-上期）/上期」）。

## 写回后的统一验收清单

| 检查项 | 方法 | 依据 |
|---|---|---|
| 原文件是否被覆盖 | 对比修改时间与文件名；确认是否另存 | F-071、F-101 |
| 关键数字是否正确 | 抽查 5~10 个单元格，手工复算 | F-101、F-104 |
| 公式是否重算 | 在 Excel 中打开，检查公式列与引用 | F-074 |
| 行列是否错位 | 检查表头、空行、合并单元格 | F-101 |
| 批注是否挂对 | 打开批注，核对单元格坐标 | F-012 |
| 输出是否完整 | 对比任务要求的结构与实际输出 | F-070 |

> ⚠️ **公式限制**：Excel 公式重算等依赖 LibreOffice 的任务在当前环境中可能受限（F-074）。如果表格含复杂公式，优先让 AI 只写「值」，公式列由你在 Excel 中维护。

## 失败时的回退路径

1. **立即停止继续写回**；
2. 如果目录是 Git 仓库，用 `git diff` 查看改动（F-095）；
3. 如果原文件仍在，直接放弃新文件；
4. 如果原文件已被覆盖且没有备份，检查是否有系统级文件历史/云盘版本（原文未提供产品内建恢复，F-093）；
5. 下次执行前，先落实「另存新文件 + 开工前备份」两条纪律（F-098、F-101）。
