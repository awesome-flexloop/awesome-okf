# 01 · 本地优先只读架构与两个 Skill

## 1. 两层心智模型

博文给出的核心逻辑（F-026）可以画成一条很清晰的分层：

```
上层：情报产品层
  日报 / 待回复 / 承诺 / 商机 / 复联线索 / 任意时间范围报告   （F-044）
        ↑ 读取后转换
底层：只读 Reader
  只读本机已有聊天记录；不获取密钥、不重签名、不注入、不 Hook  （F-027）
```

官方中文定位把上层产物列得更完整：「联系人历史、群聊主题、待回复、承诺、商机、复联线索，以及任意指定时间范围的情报报告」（F-044）。所以这个项目的价值不在「搜聊天记录」，而在**把消息流翻译成状态与行动项**——详见 [03-search-contacts-and-actions.md](03-search-contacts-and-actions.md)。

## 2. 仓库四层结构与「一个产品，两个 Skill」

官方 README 给出的目录结构（F-047）：

| 路径 | 角色 |
|------|------|
| `projects/rion-wechat-reader/` | 底层只读 Reader（数据获取边界所在） |
| `skills/wechat-cli/` | Skill 一：命令行/检索能力 |
| `skills/wechat-intelligence-hub/` | Skill 二：情报日报与报告能力 |
| `projects/wechat-intelligence-hub/` | 上层情报产品实现 |

官方将其概括为「**一个产品，两个 Skill**」（F-046）：`wechat-cli` 偏向底层可检索的 CLI 能力，`wechat-intelligence-hub` 偏向上层面向 Codex 的情报工作流。这也解释了为什么博文强调「在 Codex 里直接说人话，不用记命令行参数」（F-030）——自然语言入口由 Skill 承载，官方 README 给了三条 `$wechat-intelligence-hub ...` 示例（F-051）。

## 3. 本地优先的三条硬约束

| 约束 | 博文口径 | 官方口径 |
|------|---------|---------|
| 数据不出本机 | 「真实聊天、联系人、Profile、报告都不进 Git，也不发服务器」（F-028） | 逐字一致，且样例数据必须为虚构（F-053）✅ |
| 授权在本人 | 「接入时由你本人完成登录和系统授权，密码和密钥不交给任何人」（F-031） | 逐字一致（F-053）✅ |
| 敏感材料不外发 | 「聊天记录、密钥、数据库，别往 Issue 和社群里发」（F-036） | 官方同等纪律（F-053）✅ |

**个性化排序**是本地优先的另一面：Profile 把「你在做的事、个人背景、关系标签」变成日报排序依据（F-029）；官方 `profile-init` 的四个参数 `--owner-alias` / `--personal-doc` / `--plan-doc` / `--priority-label` 与之对应（F-050）。也就是说，日报不是按时间倒序，而是按**与当前目标的相关度**排序。

## 4. ⚠️ 最重要的口径勘误：「不重签名」只约束 Reader 核心

博文写道：底层只读 Reader「不获取密钥、不重签名、不注入、不 Hook 微信」（F-027）。这句话在 **Reader 核心范围内与官方逐字一致**，但**不能泛化到整个项目的所有路径**：

> 官方 README 同时说明：macOS 上的**候选接入工具**可能重启微信、对副本做重签名，并有独立的授权与副作用边界；Windows 首次获取路径尚未合入；真实首次接入需要单独验收（F-056）。

因此正确表述是：

| 范围 | 边界 |
|------|------|
| Reader 核心（读已同步的本机数据） | 只读；不获取密钥、不重签名、不注入、不 Hook |
| 实验性首次数据接入助手（macOS 候选路径等） | **可能有重启微信 / 重签名副本等副作用**，有独立授权边界，官方标注未实测/未合入 |

这也与「macOS 新机器的获取路径官方还没实测，不保证所有微信版本都通」（F-035）互相印证。**把「不重签名」当成全项目承诺，是本博文最容易被误读的一处。**（勘误③、引文逐字核对表）

## 5. 只读 ≠ 零风险 / 全量历史

官方另有两条免责，博文只做了弱化转述（F-054）：

- **不保证零封控**，也不保证任意微信版本长期兼容——只读降低的是行为侵入性，不等于平台侧风险为零。
- **实时读取只包含「本机已同步且当前可读」的数据**；完整历史需要本人授权的本地数据库，且只覆盖已同步到本机的部分（F-034）。换句话说，它不等于「云端全量聊天记录」。

## 6. 小结

| 维度 | 结论 |
|------|------|
| 架构 | 底层只读 Reader + 上层情报产品；四层目录（F-047） |
| 交付形态 | 一个产品、两个 Codex Skill（F-046） |
| 数据边界 | 本机、不进 Git、不上服务器、样例虚构（F-028/F-053） |
| 排序依据 | Profile 四参数驱动的相关度排序（F-029/F-050） |
| 关键勘误 | 「不重签名」仅限 Reader 核心（F-027 vs F-056） |
