# 02 · 旗舰交互式日报、双格式报告与四种视图

> **口径声明**：本篇大量内容来自博文中的官方效果截图与图注（信源距离第 ② 层）。首轮凡标「图注单源」者，官方 README 只提供语义对应、**未逐字给出 UI 名称**，引用时不可写成「官方验收过的功能名」。
>
> **🔬 源码轮修订（2026-11-06，commit `fb6a42c`）**：本篇首轮的 5 项「图注单源」判定已被源码与官方文档**大部分坐实**，其中「四种视图风格」一项需**修正**。修订结论见 [07-flagship-renderer-and-view-model.md](07-flagship-renderer-and-view-model.md)，本篇保留首轮原文并加注修订标记。

## 1. 旗舰交互式日报：四个入口

博文称旗舰日报左侧有四个入口（F-011，图注单源）：

| 入口 | 博文描述的作用 | 官方语义对应（F-044） |
|------|---------------|---------------------|
| 综合行动 | 全局待办与行动项总览 | 「可行动的个人情报」 |
| 群聊日报 | 群聊主题与话题汇总 | 「群聊主题」 |
| 重点联系人 | 关键人物状态面板 | 「联系人历史 / 待回复 / 承诺」 |
| 商单信号雷达 | 把可能值得跟的商机、合作、资源信号单独拎出来排队（F-012） | 「商机 / 复联线索」 |

图注还说明「四个入口一键切换，全局搜索加分区导航」（F-013，图注单源）。四个入口不是四份数据，而是**同一份情报的四种切法**——这一点与「同一份聊天数据渲染成四种视图风格」（F-016）是同一设计思路的延伸。

**商单信号雷达**是博主最强调的能力：从散落的对话里识别值得跟进的商业信号（F-012）。但要注意，官方中文定位只写到「商机、复联线索」，**没有定义判定规则、阈值或准确率**，因此本束不对其有效性作任何断言。

## 2. 双格式报告：Markdown + HTML

| 格式 | 博文描述（F-015） | 官方可核验事实 |
|------|------------------|---------------|
| Markdown | 适合复制归档、接着交给 AI 加工 | 输出 `wechat_daily_full.md`（F-052）；安装带 `--with-html`（F-048） |
| HTML | 浏览器内搜索、筛选、切主题，可打印和导出当前分区 | 输出 `wechat_daily_report.html` 与 `wechat-report/` 目录（F-052） |

「完整报告同时出 Markdown 和 HTML 两种」（F-014）在官方产物文件名与安装参数上得到印证（✅，核验项 #15）。但 F-015 中「适合交给 AI 加工」「可打印导出当前分区」属于**博主体验描述**，官方 README 未逐字确认，标 P1 ⚠️。

这个双格式设计有一条可迁移的意味：**Markdown 面向机器与归档，HTML 面向人读与交互**——同一份结构化情报给出两种消费面，而不是让人去适配单一界面。

## 3. 四种视图风格与移动端

博文称同一份聊天数据可渲染成四种视图风格，且支持明暗主题与分区切换（F-016，图注单源）；四张图注分别为（F-017，图注单源）：

- 视图风格 A：综合行动总览
- 视图风格 B：群聊与话题日报
- 视图风格 C：重点联系人面板
- 视图风格 D：商单信号雷达

另有「手机端有对应视图，等车间隙把今天的待办和重点群消息扫一遍」（F-018，图注单源）。

注意 A~D 与第 1 节的四个入口**名称高度重合**——博文未说明二者是同一套配置的两个说法，还是「入口导航」与「渲染主题」两层不同机制。本束按原文并列登记，**不做合并推断**（避免超出 F 集的编造）。

> **🔬 源码轮结论（F-087~F-090）**：上述并列已在源码中解开——
> - **四个入口名坐实**：`report_bundle_flagship.py` 的 `PAGE_SPECS` 常量逐字给出「综合行动 / 群聊日报 / 重点联系人 / 信号雷达」，代码内嵌字符串与 `docs/USAGE.md` 三源一致（F-080、F-090）；
> - **「四种视图风格」修正为设计期候选**：A~D 出自 `report-redesign-research-2026-08-28.md` 的「四套**待选**视觉风格」，原文结论为「采用 **A 作为主框架**」；`style-previews/` 10 个文件**无任何运行时代码引用**，故运行时不存在四套可切换主题（F-087~F-089）；
> - **四个顶层入口 ≠ 四种视图风格**：源码层级为「4 个顶层路由入口 + 群聊页内 3 个视图（话题 / 重点群聊 / 群聊筛选）」（F-086）；
> - **明暗主题与移动端坐实**：`theme-button` → `dataset.theme` → `localStorage` → `html[data-theme="dark"]` 完整可运行；移动端为同一份 HTML 的 `@media` 响应式分支，非另立渲染产物（F-083~F-085）。

## 4. 三种证据强度不要混用

阅读这一层时最容易犯的错，是把截图里的漂亮界面当成「功能已验收」。请按下面分层理解：

| 证据 | 能证明什么 | 不能证明什么 |
|------|-----------|-------------|
| 官方 README 的产物文件名（F-052） | 存在 md / html / report 目录三类产物 | 具体页面交互、筛选能力 |
| 官方中文定位（F-044） | 上层情报语义（群聊主题/待回复/承诺/商机/复联） | 四个 UI 标签的准确名称 |
| 博文截图图注（F-011~F-018） | 博主看到的界面长这样 | 官方已逐字定义、所有版本都有、真实数据下同样呈现 |

尤其要记住：本项目的演示数据为**全虚构 Demo**（F-032、F-049），截图呈现的是虚构数据下的链路效果，**不构成真实聊天数据可用性的证据**（勘误③）。
