# 05 · 洞察、可迁移模式与采用边界

> 本篇是七概念链路中 **I（洞察）→ E（模式萃取）** 的产物。所有判断都建立在前四篇与 [../references/article-source.md](../references/article-source.md) 的 F 集之上；标注「洞察」者属本束的分析，不是项目官方结论。

## 1. I 阶段：三条本质洞察

### 洞察一：它卖的不是检索，是「状态」

搜索工具的价值函数是「找得到」；这个项目的价值函数是「**知道还欠什么**」。官方中文定位把产物写成待回复、承诺、商机、复联线索（F-044），全都是**带时态的对象**，而不是命中片段。博主那句「把你早该整理、却一直没空整理的东西，安静地替你理成了能用的情报」（F-037，作者观点）之所以有共鸣，正是因为痛点在「状态维护」而非「信息查找」。

### 洞察二：克制是可采用性的前提

博主写「本地优先、只读不碰，这种克制反而让人敢用」（F-038，作者观点）。把这个判断拆开看：聊天记录是**最高敏感度**的个人数据，任何"上云 / 代发消息 / Hook 客户端"的设计都会让采用成本陡增。项目把边界钉在「只读本机已有数据、不发消息、不操作 UI」（F-009、F-033、F-053），换来的是用户敢在自己的真实数据上试。

但这条洞察有一个必须同时说清的反面：**只读不等于零风险**（F-054 不保证零封控/任意版本兼容），且实验性首次接入助手可能有重签名等副作用（F-056）。「克制」是对 Reader 核心的准确描述，不是对全部路径的免责承诺。

### 洞察三：先验证链路，再验证数据

全虚构 Demo（F-032、F-049）在本项目里承担了一个很关键的认识论角色：它把「**链路是否成立**」与「**真实数据是否可用**」拆成两个独立问题。前者可以零成本、零隐私风险地验完；后者才需要本人授权、本地数据库与平台兼容验证。博文的建议顺序「先用虚构 Demo 跑一遍，再决定要不要接自己的微信」（F-040）实际上是一套**风险递增的验收策略**。

## 2. E 阶段：三条可迁移模式

| 模式 | 抽象 | 迁移到别处 |
|------|------|-----------|
| **M1 状态化情报层** | 消息 → 事件 → 状态 → 行动项；输出带时态对象而非命中列表 | 邮件/工单/会议纪要的个人工作台；把「检索」升级为「待办与承诺台账」 |
| **M2 双消费面产物** | 同一份结构化情报同时产出机器可读（Markdown）与人读交互（HTML） | 任何 Agent 报告系统：一份归档喂给下一个模型，一份给人浏览筛选（F-014、F-052） |
| **M3 演示数据先验链** | 用全虚构数据把索引/判断/报告链路跑通，再单独验收真实接入 | 涉及敏感数据或外部平台授权的工具，先做零风险链路验证，隔离「产品逻辑」与「数据接入」两类缺陷 |

> M1~M3 是本束从 F 集萃取的**分析性模式**，非项目官方提出的概念；引用时请标注为「OKF 教程归纳」。

## 3. 采用边界（V 阶段对抗审查后必须有的清单）

### 3.1 许可证与商业化 🔴

README 精确写 **`GNU Affero General Public License v3.0 only（AGPL-3.0-only）`**，并明确**闭源 / OEM / 白标需商业授权**，第三方依赖各自适用其许可证（F-055）；GitHub API 只给 `AGPL-3.0`（F-041）。采用含义：

- 个人本机使用与阅读源码无负担；
- 修改后以网络服务形式对外提供会触发 AGPL 的网络开源义务；
- 闭源集成、贴牌、OEM 前**须取得商业授权**，不能按「AGPL 通用理解」自行推断。

### 3.2 版本与成熟度 🟠

当前是 `v0.9.2-preview.2`（F-045，博文完全未提版本）。preview 意味着命令、参数与目录结构仍可能变动；本束 [04-official-workflow-and-demo-gap.md](04-official-workflow-and-demo-gap.md) 的命令只是 2026-11-06 文档快照。生产依赖前应锁版本并复核 README。

### 3.3 平台与数据可达性 🔵

| 风险 | 官方口径 |
|------|---------|
| 首次数据获取 | macOS 候选工具可能有重启/重签名副作用；Windows 首次获取路径**未合入**；真实首次接入需单独验收（F-056） |
| 版本兼容 | 不保证任意微信版本长期兼容，也不保证零封控（F-054） |
| 历史完整性 | 只覆盖本机已同步且当前可读的数据（F-034、F-054） |
| 安全边界范围 | 「不重签名」仅约束 Reader 核心（F-027 vs F-056） |

### 3.4 证据强度 🟣

- 标题 hook「5 天攒 2000 星」为**未独立核验**的成效数字（F-006~F-008）；引用请带时点与「博文口径」。
- 四个入口名、四种视图、移动端、回复草稿、检索五维度均为**截图图注/博文单源**（F-011~F-024 中的 ⚠️ 项）。
- 演示数据全虚构，界面截图**不构成真实数据可用性证据**（F-032、F-049）。

> **🔬 源码轮修订指向（2026-11-06，commit `fb6a42c`）**：上面第 2 条是**首轮「图注单源」口径**，已在源码轮逐项复核——四个入口名、移动端、定向检索五维度、重点联系人与回复草稿**坐实**（回复草稿为官方文档 + 代码双源）；**「四种视图风格」改判为设计期候选方案**，运行时不存在四套可切换主题。逐项状态见 [../references/verification.md](../references/verification.md)「🔬 源码轮追记」，实现依据见 [07-flagship-renderer-and-view-model.md](07-flagship-renderer-and-view-model.md) 与 [09-safety-and-adoption-boundaries-from-source.md](09-safety-and-adoption-boundaries-from-source.md)。本节首轮原文按「不改写已验证结论」原则保留。

## 4. 什么情况下不该采用

- 需要**云端全量历史**或跨设备同步——官方只覆盖本机已同步数据（F-054）。
- 需要**保证平台侧零风险**——官方明确不保证（F-054）。
- 需要**闭源商业集成**而无商业授权——README 要求单独授权（F-055）。
- 需要**已验收的 Windows 首次接入**——该路径官方标注尚未合入（F-056）。
