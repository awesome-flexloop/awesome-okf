# 03 · 定向检索、重点联系人与行动项

## 1. 本质：把「消息流」翻译成「状态机」

博文反复描述的其实不是搜索，而是一条转换链（F-010、F-026、F-044）：

```
原始消息流  →  定位与去重  →  事件/状态  →  行动项
(十几个群)     (会话/时间/事件)  (承诺/待回复/商机)  (该找谁、该回谁、该跟什么)
```

官方中文定位把这三层产物写全了：「联系人历史、群聊主题、**待回复、承诺、商机、复联线索**，以及任意指定时间范围的情报报告」（F-044）。所以本项目的差异点是**输出状态而非输出命中片段**。

## 2. 第一段：定向检索与去重总结

博文给出的检索维度（F-019，P1 ⚠️ 博文单源）：

| 维度 | 人 | 群 | 产品 | 标签 | 日期区间 |
|------|----|----|------|------|---------|
| 用途 | 锁定某人的上下文 | 锁定某群 | 锁定某话题对象 | 按关系标签过滤 | 指定时间窗 |

处理顺序为「先定位相关消息和上下文 → 再按会话、时间、事件去重总结」（F-019）。另有一条边界：「关键词检索始终覆盖全部记录，不受标签限制」（F-021，博文单源）——即标签是加速器，不是过滤器。

**官方同源示例**（F-020 ↔ F-051）：博文的「搜过去 7 天所有关于 AI 培训的讨论」，在 README 中对应 `$wechat-intelligence-hub 搜索过去 7 天所有微信聊天里关于「AI 培训」的讨论`。博主进一步描述效果为「把散在十几个群里的对话并成一条脉络，标出谁在牵头、聊到哪了、下一步该找谁」（F-020）——后半句属于**博主对输出的描述**，官方未逐字承诺该结构化字段。

## 3. 第二段：重点联系人与承诺状态

博文描述（F-022、F-023）：总结与某人最近聊到哪、谁还欠着承诺、该回没回；示例问题「我和张总最近聊到哪，还有什么承诺没完成」会输出一份状态清单。

官方 README 有同义示例（F-051）：`总结我和「联系人名字」最近聊到哪里，还有什么承诺没有完成`。因此「承诺 / 待回复」这类状态对象**有官方语义支撑**（✅，F-044），而「输出成一份状态清单」的具体呈现形式来自博文。

关于「还能照着你的语气，给某人草拟一条回复草稿」（F-024）：这条在官方 README 中**未逐字确认**，标 P1 ⚠️ 博文单源。若它是你最关心的能力，采用前应先自行验证。

## 4. 第三段：行动项与信号雷达

| 产物 | 博文口径 | 官方语义 |
|------|---------|---------|
| 该回没回 / 待回复 | F-022 | F-044「待回复」✅ |
| 谁欠着承诺 | F-022、F-023 | F-044「承诺」✅ |
| 商机 / 合作 / 资源信号排队 | F-012（图注单源） | F-044「商机、复联线索」✅ 语义对应 |
| 复联线索 | F-026 | F-044 ✅ |
| 综合行动总览 | F-017（图注单源） | 未逐字核验 ⚠️ |

注意「信号」这个词的分量：它意味着系统要**做判断**（什么算值得跟），而不是只做检索。但官方 README 与博文都**没有给出判定规则、阈值或准确率**，本束因此不对信号质量作评估，也不建议把商业决策直接建立在未经验证的信号上。

## 5. 自然语言是入口，不是能力本身

三条官方 Codex 示例（F-051）覆盖了本项目的三个主场景：

| 场景 | 官方示例（节选） |
|------|-----------------|
| 日报 | `生成过去 24 小时的完整微信情报日报，分析群聊、重点联系人、待回复事项和商业机会` |
| 关系状态 | `总结我和「联系人名字」最近聊到哪里，还有什么承诺没有完成` |
| 定向检索 | `搜索过去 7 天所有微信聊天里关于「AI 培训」的讨论` |

博文把这一点归纳为「在 Codex 里直接说人话，不用记命令行参数」（F-030，✅ 核验项 #14）。但要分清：**自然语言降低的是调用门槛，真正决定结果质量的是底层索引、去重与状态抽取**。同一句提问，在全虚构 Demo 与真实数据下的表现差异，见 [04-official-workflow-and-demo-gap.md](04-official-workflow-and-demo-gap.md)。
