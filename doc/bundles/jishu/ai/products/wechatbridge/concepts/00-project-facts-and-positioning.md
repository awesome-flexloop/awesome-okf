## 1. 一句话定位

**WeChatBridge（微信流）** 是一个把微信「合并转发」产生的聊天归档，直接送进 AI Agent 与本地知识库的工具
（F-010、F-012、F-064）。

官方的一句话定位是：「群里几百条消息没空翻？多选、转发，一步交给 AI 总结，或存进你的知识库。」（F-065）
源文的说法是「让微信的『合并转发』直接抵达 AI Agent 和你的知识库」（F-012）——两者语义一致，
但**前者是项目方逐字表述，后者是推介文转述**，引用时应优先用官方措辞。

源文把产品能力归纳为三条（F-017），官方「核心能力」表以八项覆盖并扩展了它们（F-075）：

| 源文三大能力 | 源文描述 | 官方对应项 | F 编号 |
|-------------|---------|-----------|--------|
| **一键转发** | 微信转发菜单里直接选目标，不用打开主窗口 | 「十二个原生入口」+「自定义目标」 | F-018 / F-067 / F-074 |
| **AI 处理** | 自动激活目标 App、附加场景指令、粘贴聊天归档 | 「AI Agent 转发」+「场景与技能」 | F-019 / F-075 / F-087 |
| **本地沉淀** | 生成 Markdown 存 Obsidian，保留原始 ZIP，按聊天名自动组织 | 「Obsidian 沉淀」+「本地记录」+「失败兜底」 | F-020 / F-070 / F-075 |

源文另用六行「原来…现在…」对照表描述功能模块（F-041~F-047）；官方则是八项核心能力表，
多出「自定义目标」与「双语界面」（F-075、F-076）。这是**结构粒度差异**，不是能力冲突。

## 5. 一个值得注意的「没有」

源文**没有任何成效数字**——没有提效倍数、节省工时、用户量、Star 数或下载量（F-063）；
官方 README 同样没有（F-107）。因此本 bundle 的「成效数字溯源表」为空风险表：
不存在需要降级处理的营销数据。这与同分组内多数「微信博文转化」束不同，
后者常需拦截「省下 X 小时」「Star 从 3 千到 5 千」这类时点数字。

真正需要处理的是**功能计数与时点**：九个→十二个入口、macOS-only→多端。
这类漂移的处理方式见 [02 篇](02-entry-matrix.md) 与 [verification.md ③ 口径对照表](../references/verification.md)。
