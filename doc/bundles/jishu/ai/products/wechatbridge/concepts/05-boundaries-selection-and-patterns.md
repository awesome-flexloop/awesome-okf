# 边界、选型对照与三条可迁移模式

> 本篇分两层：**§1~§4 是事实与边界**（带 F 编号）；
> **§5 是编者洞察**（G2 洞察四元组、G3 可迁移模式），与事实严格分层，全部显式标注「非官方结论」。

## 1. 源文的方案对比（及其证据等级）

源文把「整理微信聊天记录」的传统办法列为三类（F-049）：

| 传统办法 | 源文描述 | 证据等级 |
|---------|---------|---------|
| 截图 | 「一张张截图」 | 常识性描述，无需核验 |
| 手动复制粘贴 | 「一段段复制粘贴，整理一次能劝退一次」 | 作者修辞（V，F-004） |
| 第三方工具读取微信数据库 | 称「有封号和数据泄露风险」 | ⚠️ **作者断言，无独立出处**（F-049） |

源文结论「微信流选了一条更省事也更安全的路」（F-050）是**作者观点**，不是核验结论。
本 bundle 能确认的事实只有：微信流「只接管微信官方『合并转发』生成的归档」，
且官方隐私六条明确不读数据库、不解密、不注入、不修改微信进程、归档只来自主动导出文件（F-051、F-082）。

> 因此「更安全」只能作为作者判断引用，**不得**写成「官方证明不会封号」。
> 官方 README 里不存在「不怕封号」类承诺（F-107）。

## 2. 四条前提（源文给出，官方机制佐证）

| # | 前提 | F 编号 | 官方佐证 |
|---|------|--------|---------|
| 1 | 只支持 macOS 14 及以上 | F-052 | 下载表 macOS 14+；构建前置 macOS 14+（F-078、F-088） |
| 2 | 需要 macOS 微信 4.1.13 以上版本 | F-053 | 「需要 macOS 微信 4.1.13 或更高版本」（F-077） |
| 3 | 核心场景是主动转发选中的聊天，**不是全量自动归档** | F-054 | 每批手动选取（F-086）、只来自主动导出文件（F-082）、100 条上限来自微信侧（F-085） |
| 4 | 目标为 AI Agent 时，Agent 本身要装好并完成授权 | F-055 | 入口行为为「激活目标应用并粘贴」（F-069）；失败兜底为留在剪贴板（F-075） |

**选型含义**：这是一套「人在环内、按需导出」的工具，不是聊天备份/同步系统。
若需求是「全量、无人值守地把微信消息同步进知识库」，这四条前提直接排除该方案。

## 5. 三条可迁移模式（⚠️ 编者洞察，非官方结论）

> 以下三条是**本知识包编者的萃取**，不是项目方声明，也不是源文作者观点。
> 判据：脱离 WeChatBridge 这个具体产品，模式仍能被复述、被搬到别的场景、被证伪。

### 模式 A：官方导出通道 + 补一层入口

- **观察**：微信 4.1.13 提供了「合并转发给第三方应用」的官方通道，但系统列表只收 Share Extension 应用，
  多数 AI 工具缺席（F-013、F-080）；微信流用十二个 Share Extension 把这层入口补齐（F-096）。
- **可迁移表述**：当平台已经开放一条「用户主动导出」的合规通道，却因生态位限制覆盖不到目标应用时，
  最小改动不是去碰平台内部数据，而是**做一个只接该通道输出的适配层**。
- **适用边界**：平台必须真的提供导出通道；且导出物格式稳定（此处是含 TXT/图片/视频的 ZIP，F-081）。
- **证伪条件**：若平台关闭/改变导出通道，或导出格式不再可解析，该模式立即失效。

### 模式 B：把上下文前置到转发动作里

- **观察**：场景提示词按群聊保存，转发时自动带上（F-032、F-087）；`SKILL.md` 让 Agent 按统一规范处理（F-033、F-075）。
- **可迁移表述**：与其在每次对话里重复解释背景，不如把「上下文 + 处理规范」绑定到**数据进入管道的入口**，
  让入口负责注入，消费端只负责执行。
- **适用边界**：上下文要能按来源稳定分组（此处按群聊）；否则维护成本会超过收益。
- **证伪条件**：来源分组频繁变动、或同一来源需要多种互斥处理规范时，入口注入反而成为负担。

### 模式 C：本地优先 + 显式降级落点

- **观察**：归档、场景、记录都保存在本机，Share Extension 无网络权限（F-082）；
  目标未装或权限不足时文件仍留在剪贴板（F-035、F-075）；未完成批次可在记录页继续、失败可重试（F-086）。
- **可迁移表述**：一个「转发/投递」型工具应同时设计**正常落点**与**降级落点**，
  且降级落点必须是用户能立刻接手操作的地方（剪贴板），而不是只写一条错误日志。
- **适用边界**：投递物本身是可独立使用的文件（此处是 ZIP / Markdown 附件）。
- **证伪条件**：若投递物离开本工具就不可读，降级到剪贴板就没有意义。

> 三条模式都满足 G3「可迁移」：不依赖本项目名、不依赖 macOS 专用术语之外的实现细节、
> 且各自给出了适用边界与证伪条件。它们**不是**官方 README 的结论，引用时请保留这层标注。
