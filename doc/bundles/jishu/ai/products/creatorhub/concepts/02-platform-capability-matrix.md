## 一、视频号：最容易被误读的平台

官方明文：**视频号只支持创作者助手中的本账号数据，不支持监控或下载他人作品**（F-045）。具体缺口：

- 无关键词批量采集（F-036、F-037）。
- 不能监控对标账号、不能下载他人作品（F-041、F-045）。
- 无自动评论/回复（F-043、F-045）。
- 有发布能力，但走对应创作平台流程（F-042）。

所以源文标题“把抖音小红书快手视频号全管了”只在**本账号管理**意义上成立；作为“四平台竞品监控”理解会直接落空（F-064）。这是本包标记 flagged 的两项核心勘误之一。

## 二、监控：作品、评论、弹幕

### 作品监控

添加创作者主页、作品链接、短链或平台 ID，发现新作品自动入库（F-038）。三个细节值得注意：

1. **多账号监控同一主页**：抖音、小红书、快手支持不同执行账号分别订阅同一主页，各任务独立维护扫描进度、采集策略与作品记录；同账号同主页仍只允许一条任务，暂停任务也参与去重（F-038）。
2. **历史回填**：新增目标默认只监控订阅后的作品；可配置回填最近若干条，`monitor_initial_backfill_count=0` 表示只监控新作品，`-1` 表示尽可能回填（F-058）。
3. **频率**：作品/评论/弹幕监控支持秒级预设或自定义 1–86400 秒，分钟可填小数但换算后须为整秒（F-069；参数区间见 README）。

### 评论监控

可订阅单条作品，也可监控账号近期作品的评论（F-039）。评论与作品是两条独立订阅线：只监控作品不会自动聚合其全部评论，需要另建评论监控（F-039）。

### 弹幕监控（仅抖音）

独立于评论区，按视频内时间轴渐进探测并排序；支持时间范围、关键词、文本长度、点赞数、容量上限过滤，持久化到 SQLite（F-040）。自己的视频走创作中心，公开视频走播放器拦截（F-040）。

> 弹幕是“时间轴数据”，不是“评论数据”。做直播/短视频内容复盘时，它能回答“第几秒观众在讨论什么”，评论只能回答“总体在说什么”。

## 三、关键词批量采集：一次性批处理

抖音、小红书支持关键词采集作品/笔记、评论、媒体（F-037）。关键参数与边界：

- 一次最多 **20 个关键词**；可设每词作品数、采集深度、排序、发布时间、作品类型、互动门槛、每作品评论数、二级评论与媒体下载（F-037）。
- 已结束任务支持编辑配置、保留结果去重续跑和 Excel 导出（F-037）。
- 与持续轮询的作品监控**相互独立**：关键词采集是一次性批处理，不产生持续订阅（F-037）。
- **结果是采集上限，不是平台全量**：受平台排序、账号登录态与当前可见范围影响（F-037）。

> 做竞品研究时，不要用“采集到 500 条”推导“平台共 500 条”。正确表述是“在指定关键词、排序与可见范围内采集到 500 条”。

## 四、下载

- 支持断点续传与失败重试；抖音可选画质，小红书支持图集和视频，快手支持视频（F-041）。
- 多任务下载同一媒体至同一路径时串行写入并复用已有文件；需要分别保存时为任务设置不同下载目录（F-041）。
- 链接下载：粘贴完整分享文案或链接，自动提取地址并下载（F-041）；命令行入口见 [examples/03](../examples/03-download-publish-and-transfer.md)（F-057）。
- 平台音频/视频流合并依赖 ffmpeg；未安装系统 ffmpeg 时使用 Python 依赖附带的 ffmpeg（F-031、F-055）。

## 五、发布与跨平台转发

官方流程（F-042）：

1. **小红书**：支持图集、视频和定时发布，面板内完成。
2. **抖音 / 快手 / 视频号**：通过对应创作平台发布（浏览器流程）。
3. **跨平台转发**：已下载的抖音作品可转发到小红书或视频号；小红书作品可转发到抖音；发布前可修改标题、正文和话题。
4. **发布预览**：发布编辑器提供素材与文案实时预览（README 界面说明）。

需要收窄源文口径：官方**没有**声明“一次提交、自动分发全平台”。实际是各平台分别发布 + 下载后转发；批量分发需要自己按平台逐个建任务（F-066）。

## 六、自动评论 / 回复

- 支持关键词、排除词、多模板、回复冷却、最大消息年龄（F-043）。
- **默认生成待审核草稿**；选择免审核后仍经过活跃时段、统一写间隔、小时/每日上限及风险冷却（F-043）。
- 自动回复只使用账号自己的可见 Chrome 会话与页面输入框，不拼装签名请求；提交结果不确定时不自动重试（F-043）。
- 自动评论、回复、私信及关注操作受平台风控影响，官方建议低频使用（F-043）。

> “自动”在这里是**半自动**：默认人工审核，免审核也有硬上限。把它当“无人值守客服”会同时踩平台规则与账号安全两条线。

## 七、本账号与私信

- 抖音：作品、关注、粉丝、私信；支持 API/浏览器/混合通道（资料、粉丝、私信、弹幕），发布仍走浏览器（F-044）。
- 小红书：作品、关注、粉丝、私信；普通账号可通过新版 Web `/chat` 同步会话与消息，首次启用只建立游标，不处理历史积压（F-044）。
- 快手：作品、关注、粉丝（无 im 能力）（F-044）。
- 视频号：作品、数据、评论（仅本账号）（F-044、F-045）。

## 八、通知

通知渠道为 Bark、钉钉、Telegram（F-046）；可启用作品健康监控，对零播放、违规或下架状态发送提醒（F-046）。v0.2.4 另增 Webhook 事件出站与 HMAC-SHA256 签名（F-071）。

## 已知边界（使用前必读）

1. **未实机复跑**：能力表来自 README；平台页面结构随时变化，实际可用性以你当前版本与账号状态为准。
2. **登录态决定一切**：小红书扫码只获取主站读取态，发布需另用“创作者登录”；链接需含 `xsec_token` 才能稳定解析（F-072）。
3. **采集上限≠全量**：见第三节。
4. **视频号缺口**：不要为视频号规划竞品监控或他人作品下载（F-045）。
5. **合规**：自动操作与批量采集须遵守平台规则；项目 README 明确用于技术学习与个人内容管理（F-059）。
