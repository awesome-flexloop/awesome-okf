## 老项目改造："先分清，再体检"

面对已有的老界面，oil-ui 主张（F-017 / F-009✅）：

1. **先分清**：判断这是"内容页"还是"说服页"，决定首屏策略；在存量项目里，先分清用户要的是"优化 UI、改流程还是加新功能"——三者视觉处理方式不同（改流程/加新功能沿用现有视觉，不走新方向探索）。
2. **再体检**：用八步法逐项检查当前实现的品类、调性、差异化、记忆点是否到位。
3. **只推进一处**：一次只改一处"最该改"的地方，避免大改伤及可用性。

> 开源版"老项目"能力是**基础体检**；完整版提供更深的问题定位与改造建议（F-028）。

## 版本检查与自动更新机制细节（F-020 / F-034~F-036）

- **频率**：约每 10 分钟联网检查一次是否有更新。
- **超时**：网络请求超时 2 秒即跳过，不阻塞工作；失败后稍后重试。
- **隐私**：**只读 `ui.oiloil.org` 公开版本列表，不上传对话内容**。
- **自动更新**：发现新版本且具备 Python 3 + Node.js 18+ 时尝试自动更新。
- **静默**：本机无 Python（`python3`/`python`/Windows `py -3`）时只提醒一次；离线时不提示新版本。
- **环境变量**：`OIL_NO_AUTO_UPDATE=1` 只提醒不自动更新；`OIL_NO_UPDATE_CHECK=1` 完全关闭检查（F-035）。
- **恢复命令**：缺依赖时给出 `npx github:oil-oil/oil-cli update oil-ui --path "<安装路径>"`（F-036）。

> 完整机制见 [05 自动更新、独立评审与能力边界](05-auto-update-and-capacity.md)。

## 相邻工具

官方推荐的搭配（F-029）：

- [draw-ui](https://github.com/oil-oil/draw-ui)：生图产出设计稿。
- [oil-motion](https://github.com/oil-oil/oil-motion)：滚动 / 拖动类网页动画。

两者与 oil-ui 各司其职：oil-ui 定方向，draw-ui 出图，oil-motion 做动效。
