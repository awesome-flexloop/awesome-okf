# 自动更新、独立评审与能力边界

本篇覆盖 oil-ui 的**运行期行为**：它如何自我更新、如何做质量护栏（独立评审）、以及它**明确不做什么**（能力边界）。这些决定了你在真实项目里能否放心使用。

## 自动更新机制（v2，比博文所述更完整）

博文只讲了"版本检查"；官方 README 实际描述的是更完整的**检查 + 自动更新**两级机制（F-034）：

- **触发**：使用本 Skill 时触发；最多每 10 分钟联网一次。
- **检查目标**：只读取 `ui.oiloil.org` 公开的版本列表，**不上传项目内容**。
- **时效与降级**：超过 2 秒无响应即跳过，不拖慢任务；网络失败稍后重试；**离线时不提示新版本**。
- **自动更新**：发现新版本且本机具备 Python 3 + Node.js 18 以上时，尝试自动更新。
- **缺依赖**：无 Python 3 时检查不运行、只提醒一次（底层以 `OIL_UPDATE_CHECK_SKIPPED: missing_python` 返回标记记录是否已提醒），设计任务照常继续。

### 三个环境变量（F-035）

| 变量 | 效果 |
|------|------|
| `OIL_NO_UPDATE_CHECK=1` | **完全关闭**版本检查 |
| `OIL_NO_AUTO_UPDATE=1` | **只提醒**有新版本，不自动更新 |
| （默认） | 检查并尝试自动更新 |

### 恢复提示命令（F-036）

自动更新缺依赖时，Agent 会在回复末尾给出带当前安装绝对路径的恢复命令，原文保持原样：

```bash
npx github:oil-oil/oil-cli update oil-ui --path "<安装路径>"
```

> **隐私与合规**：检查只读公开版本列表、不上传对话内容（博文与官方一致，F-020）；更新命令涉及本机安装路径，属正常 CLI 操作，无远程代码注入面。

## 独立评审：oil-ui 的质量护栏

评审是方法论的一部分而非可选点缀（F-039 / F-040）：

- **触发**：新页面、整体改版或影响主要构图/任务流程的变更，初版稳定后独立评审。
- **评审者**：隔离上下文的视觉评审子 Agent，**不看制作历史、代码或旧评分**。
- **参照标准**：以"这一体裁里顶尖设计团队会怎么做"为参照，按 **10 分制**指出当前画面差多远（F-040）。
- **免费/Pro 差异**（F-039）：开源版每阶段一轮；Pro 以 **9 分为目标，最多评审三轮**。
- **修正闭环**：主 Agent 按反馈修正并用实际画面重新取证，**不把评审偏好自动当成用户要求**。
- **方向探索阶段**：对比页先交用户，评审作为推荐流程（用户同意时每个小样都评一轮，目的不是追分而是打破模板骨架）。

## 能力边界：明确"不做什么"（F-041）

- **无看图能力**：可产出设计说明 / 实现代码 / 源码级检查，但必须明确"**未验证实际视觉**"，不生成虚假的视觉评分。
- **无可运行环境**：不能声称交互通过；请求要可运行界面却只能交付方案时，明确标为未完成部分。
- **职责范围**：只负责设计判断；组件归属、数据流、状态正确性、测试等**代码实现质量不在范围内**（SKILL.md description）。
- **不乱接外部**：不管理密钥、不安装工具、不发布网站；网络不可用时用已有参考并说明来源范围。已安装 oil-ui-pro 时转交 oil-ui-pro。

> **一句话**：oil-ui 把"能自动升级 + 有独立评审 + 明确能力边界"三者内置为纪律，让 AI 产出的视觉结论可审计、不越界、可持续维护。
