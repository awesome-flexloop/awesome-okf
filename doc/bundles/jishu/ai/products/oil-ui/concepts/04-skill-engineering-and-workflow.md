# SKILL.md 工程结构与五步工作流

八步设计法是讲师面（给设计师看的方法论）；本篇进入**机制层**：oil-ui 作为 Agent Skill 在宿主里到底怎么跑——它不是一个黑箱，而是**宿主中立的文本流程** + **范围分流表** + **五步工作流** + **references 参考文件体系**（F-031 / F-032 / F-038）。

## 核心定位：宿主中立的文本流程

SKILL.md 的核心是**纯文本流程**，不绑定特定宿主、不依赖其他 Skill、也不绑定模型（F-037）。这意味着 Claude Code、Cursor、Codex 等任何支持读取文本流程并调用宿主能力（文件/浏览/看图/生成/隔离执行）的 Agent 都能执行。

- **配对的能力边界**：对比页生成器需要 Python 3.10+ 标准库；实际视觉验收需要看图能力；交互验收需要可运行环境（F-037）。

## 范围分流：先问"这是什么活"，再决定走多深

oil-ui 不会对所有请求都跑完整流程，而是先按**范围分表**分流（F-032）：

| 当前范围 | 执行方式 |
|---------|---------|
| 单个元素、一处间距、文案/颜色等小改动 | 直接改，在目标视口看改动处，一两句话说明；不盘点、不开方向、不评审 |
| 新界面或重新探索 | 走步骤 1–5；只交付设计说明时止于相应方案 |
| 单个组件打磨到极致 | 走步骤 1–5，范围仅限该组件：先定视觉主角，从它取色 |
| 已有方向深化/局部优化 | 保留方向，从步骤 2 进入，只检查受影响区域 |
| 存量项目优化 UI/改流程/加新功能 | 先分清三种需求分别处理；沿用/重定视觉，盘点现有页面与共享组件 |
| 截图还原 | 以参考图为视觉基线，确定视口约束后进入步骤 2，不发散新风格 |
| UI/UX 评审 | 只执行步骤 4 的诊断，交付证据与建议；不要求重新设计 |

> **提问策略**：只在**缺失信息会改变核心方向**时才提问，可逆的细节自行决定并简述假设——不把设计探索变成强制问卷或逐步审批（F-033）。

## 五步工作流（F-031）

```
1. 探索并收敛方向     先认品类、拆标杆，再定调性、起方向；方向卡写记忆点；多方向进对比页交用户挑
2. 建立视觉与交互结构 按需读 visual-language/media/imagery/motion 参考；交代视觉层级与关键操作链
3. 制作并取得实际证据 先做代表性页面，动效录屏/三帧留证；在目标视口运行查看，不能只看首屏
4. 独立评审与修正     派隔离执行的视觉评审子 Agent，按 10 分制对标顶尖团队；主 Agent 修正再取证
5. 验证与交付         做减法（一页一个主角）；双尺寸/200% 缩放下检查；交付说明+评审记录
```

## references 参考文件体系（F-038）

SKILL.md 把方法拆成独立参考文档，按需读取而非预先全部加载：

| 参考文件 | 解决的问题 |
|---------|-----------|
| design-direction | 探索并收敛方向（认品类/拆标杆/定调性/方向卡/差异检验） |
| visual-language | 视觉层级、字体、色彩、空间、图标、风格统一与减法 |
| media | 素材选择、视频与 3D |
| imagery | 生成配图：让图承担意思、写提示词 |
| motion | 三处基本动效与呼应、动效手感、首屏动画、滚动叙事 |
| style-explorer | 自带的风格对比页模板与生成器 |
| layout-and-viewport | 布局与视口（含截图还原的"精准还原"） |
| visual-review | 视觉评审协议（含"给已有界面评审"） |

## 与八步设计法的关系

- **八步法** = 方向探索阶段的细粒度方法（步骤 1 的核心）。
- **五步工作流** = 一条任务从探索到交付的完整执行链。
- **范围分流** = 决定这条链要走多深。

三者共同构成"可执行的设计方法论"——这正是博文所说"从教 AI 设计，到给 AI 施工图纸"的机制落点（F-003）。
