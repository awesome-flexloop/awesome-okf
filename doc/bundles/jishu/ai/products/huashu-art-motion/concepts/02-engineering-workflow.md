# 动画工程工作流与可迁移实践

> **迁移层**：本页讲"这套 skill 把动画当成一个可测量、可验收的工程"，并从中提炼对任何"人工产物（动画/设计/文稿）验收"场景都可复用的实践。

## 一、拆解脚本：把参考动画变成"能写代码的地图"

想复刻别人的动画？先跑 `breakdown.py`，它会输出（F-028/F-044/F-052）：

1. **转场标记**——哪里切了、切了什么类型的转场
2. **节拍网格**——整体节奏是 24fps 还是 30fps、每几秒一个节拍
3. **运动热图**——每一段画面里哪里在动、动的幅度多大

先把参考拆成可量化地图，再按机制用代码复刻（F-041/F-050）。

## 二、QA 脚本：数字验收 + 旁观者审查

花叔很在意"动画做完怎么验收"，`qa.py` 从五维度自动测量（F-029/F-044/F-052）：

| 维度 | 测量内容 |
|------|---------|
| 稳定性 | 同一个 spec 渲两次，帧之间的差异多大 |
| 效率 | 每帧的成本（渲染时间 + CPU 使用率） |
| 动感 | 画面里的运动元素有多少、幅度多大 |
| 流畅度 | 帧与帧之间的过渡是否自然 |
| 文字框景 | 文字是否正确放在画面里合适的位置 |

数字过了之后，再派一个**"没参与制作"的 agent** 只看成片挑问题（F-030/F-044）——"这就像代码 review，但对象是动画"（F-030）。

## 三、纯代码绘制 + 生图模型合成的分工

- **代码完成**：场景、转场、运动（F-031）
- **生图模型出帧**：只有"人"很难用代码画得像（F-031/F-049）
- **代码负责**：帧间过渡、换帧节奏、材质合成——用多个生图帧 + 代码合成，在不同画风里保持形象一致（F-049/F-031）

## 四、配乐：纯代码合成

`scripts/audio/` 模板（F-032/F-050）支持：

- **BPM 网格对齐**——音乐节拍和动画节拍对齐
- **动机换乐器**——同一旋律不同乐器，匹配不同画风情绪
- **结尾音效序列**——穿越到下一个画风时配水墨"唰"声或像素"boop"声

## 五、快速上手（操作可复现性两问皆"是"，故给 examples 式实操）

**前置**：`uv`、`ffmpeg`、Playwright Chromium（`uv run --with playwright playwright install chromium`）（F-033/F-050）。

**安装**：
```bash
npx skills add alchaincyf/huashu-art-motion
```

**试渲一帧梵高风格**：
```bash
git clone https://github.com/alchaincyf/huashu-art-motion.git
cd huashu-art-motion
uv run --with playwright python scripts/engine/render.py --solo 09_postimp --stills 0.3 --out 试渲
```
`--solo 09_postimp`=梵高后期印象派；`--stills 0.3`=只渲前 0.3 秒省时间；`--out`=输出目录（F-036/F-050）。

**渲完整财经图表动画**：
```bash
uv run --with playwright python scripts/engine/render.py \
  --spec scripts/engine/examples/t3_finance_chart.json \
  --out 财经图表.mp4
```
读 JSON spec 里的时间轴/数据/标签，输出一段完整 MP4（F-051）。

**常见用法（官方"能做什么"矩阵，F-050）**：

| 你说 | 它做 |
|------|------|
| 「复刻这个动画」「拆一下这段」 | 先跑拆解脚本量出转场/节拍网格/运动热图，再按机制用代码复刻 |
| 「做个梵高／莫奈／包豪斯那种的动画」 | 先设计一帧，再让它动起来；35 张风格配方卡当起点 |
| 「用我的口播做一段艺术动画」 | 镜头表 → 定风格 → 世界画布加镜头 → 输出一条画面轨 |
| 「做一个人穿过一幅幅名画的片子」 | 长卷骨架：每个世界一个段文件，主角一路往右走，跨边界换画风 |
| 「做解说视频的动画段」 | 按口播选语法，喂一份 JSON，出一段时长精确到帧的片段 |

不需要按钮、不需要面板、不需要打开 Figma 或 After Effects（文章结语）。

## 六、安装陷阱（重要）

skill 不只是一个 `SKILL.md` 单文件——`references/`、`assets/`、`scripts/` 等多子目录有被引用的配方、脚本和素材（F-035/F-042/F-052）。

- 若你的 `skills` CLI 版本过旧，可能**只同步 SKILL.md 单文件**，导致缺依赖（F-035）。
- 检查：安装目录若只有 SKILL.md 没有那几个子目录，说明 CLI 版本旧：
  ```bash
  npm i -g skills@latest
  # 或 git clone 兜底
  git clone https://github.com/alchaincyf/huashu-art-motion.git ~/.claude/skills/huashu-art-motion
  ```

## 七、迁移层洞察（四元组，G2-3 检查通过）

> ⚠️ **单案例边界**：以下洞察均源自本文单项目（huashu-art-motion）的观察，属**单案例待验证假设（L1）**，未跨多个独立项目交叉验证；迁移到其他领域前建议先小范围试测。

### 洞察 A：从"经验"沉淀到"工程验收"，才是 Skill 复用的前提
- **陈述**：一个 AI Skill 要可复用，不能只存"怎么做"的代码，还要存"怎么判断做对了"的验收标准。
- **证据**：qa.py 五维度数字验收 + 旁观者 agent 审查，是本项目区别于一般 skill 的关键（F-029/F-030/F-044）。
- **反常识**：大多数人做 skill 只写 prompt/代码，花叔把"验收"也做成 skill 的一部分——把隐性的人类审美判断显式化为可测维度。
- **行动**：做任何"生产型 AI Skill"时，配套一个可量化的 QA 层级（稳定性/效率/质量维度）+ 一个非制作者的审查者角色。

### 洞察 B：可复现的风格 = 参数 + 运动 + 转场 + 短板 四元组配方
- **陈述**：想让 AI 稳定复现一种艺术风格，要的不是更长的 prompt，而是一份写清参数、母题动作、签名转场、当前短板的**可执行配方卡**。
- **证据**：35 张配方卡每张都是可运行场景 + 渲染器 + 签名转场，且写"当前短板"（F-008/F-009/F-040）。
- **反常识**：配方卡主动写"当前短板"（"这里做不好"），反而是让它更可信——它把 AI 的边界透明化，agent 知道什么时候该手动补帧或交给生成模型。
- **行动**：沉淀人工作业/设计规范时，用"参数 + 动作 + 转场 + 短板"四要素替代"风格描述"这种模糊说法。

### 洞察 C：让 AI 去拿 AI 最不擅长的补位，而不是全包
- **陈述**：纯代码负责确定性高的几何/运动/转场，生图模型只补"人"这种代码画不像的东西。
- **证据**：场景/转场/运动用代码，人物交生图模型出帧+代码合成（F-031/F-049）。
- **反常识**：近年直觉是"全部交给生成模型更简单"；本方案反其道——**确定性优先、生成模型补位**，换来跨画风一致性（同一角色形象稳定）。
- **行动**：设计"生成模型 + 确定性代码"混合管线时，先问"哪部分是确定性高的"，把生成模型只留给真正需要它的部分。
