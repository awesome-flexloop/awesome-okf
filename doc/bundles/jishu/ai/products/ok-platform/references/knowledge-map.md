# 知识地图（事实层 / 机制层 / 迁移层）

## 一、事实层（F 映射）

文章可核验事实构成一张「AI 端到端研发」的最小骨架：

- **对象**：OK 平台——AI 驱动的端到端研发平台，「需求即交付」[F-024][F-025]
- **规模**：安全中心项目空间 2026.04~06，254 条需求 / 172 条(68%) 端到端完成 / 51%·2h 内完成 / 传统中位 3~5 工作日 [F-027][F-028][F-030][F-031]
- **链路**：九阶段全链路，各阶段 AI 角色+输入+输出+质量门（表格以配图呈现）[F-033][F-034]
- **两道质量门**：需求评审（访谈式深挖 + 可落地性 7 维打分）[F-038][F-041]；技术方案（依赖图排序/垂直切片/粒度/检查点四条硬纪律 + 找茬自审）[F-044][F-045]
- **编码三条纪律**：简单优先 / 范围纪律 / 关键路径先测 [F-049]
- **审查标准**：改善即批准（关键问题才阻塞）+ 六项安全强制核对 [F-052][F-053]
- **人的角色**：决策者与知识供给者，四个不可替代节点 [F-055][F-056]

## 二、机制层（执行者洞察；单源标记为假设）

> 以下为执行者基于「文章 + 领域共识」的归纳。凡仅由单篇支撑者标 `（假设）`，不作为事实引用。

### 洞察 I-1：质量门前置化 —— 「在方向还便宜时修正」
- **现象**：OK 把需求（可行性≥60 分）和技术方案（找茬自审 + 待确认问题早暴露）做成**上游卡口** [F-042][F-045][F-046][F-047]。
- **机制（假设）**：AI 端到端的成本结构与传统研发不同——返工是纯时间成本且随阶段指数放大，故把「不确定性」消灭在上游比在下游擦屁股 ROI 更高。
- **影响**：整个链路以「需求质量」和「方案质量」为总闸门，编码反而只是执行。
- **建议**：任何引入 Agent 端到端的团队，第一优先级是设计需求/方案的前置质量门，而非堆编码 prompt。

### 洞察 I-2：确定性工程纪律，而非 prompt 玄学
- **现象**：编码三条纪律（简单优先/范围/先测）、审查「改善即批准」本质是把人的工程约束**硬编码**进 Agent 的执行与审查策略 [F-049][F-052]。
- **机制（假设）**：AI 输出质量直接受**约束与反馈回路**支配；把工程纪律变成可执行 gate，比反复调试 prompt 更有效。
- **影响**：作者称「上下文质量 > 反复调 Prompt」[F-057]——同向印证：约束与上下文是杠杆，不是模型替换。
- **建议**：将团队既有编码/审查规范翻译为 Agent 可执行的标准与 gate。

### 洞察 I-3：人机重定位 —— 从执行者到决策者
- **现象**：AI 接管需求/方案/编码/审查后，人进入四个决策节点（选型/隐性上下文/异常干预/价值判断）[F-056]。
- **机制（假设）**：AI 端到端不减少人的重要性，而是**上移人的价值**——常识、全局视角、历史包袱这些「写不进文档」的知识成为稀缺输入 [F-058]。
- **影响**：「上下文质量决定输出质量」要求人成为知识供给者，而非监督打字员。
- **建议**：团队应围绕「如何高效供给背景上下文 + 在决策节点拍板」重建人的工作流。

### 洞察 I-4：审查意图化 —— 从样式到意图
- **现象**：人审从行级（命名/风格）上升到意图级（跨模块交互/边界/安全面）[F-059]。
- **机制（假设）**：机械性检查被 Agent 自动消化后，人的审查唯一不可替代价值在于「这个改动对不对」的意图判断。
- **影响**：「改善即批准」是防「风格偏好阻塞变更」的纠偏 [F-054]。
- **建议**：人工 Review 清单应聚焦意图、边界、安全影响面，放行非关键风格差异。

## 三、迁移层（中立、可逆实践）

> 这些实践与具体 OK 平台解耦，可在任何引入 AI 研发流程的团队先行验证，且可逆（不破坏既有流程）。

1. **零基追问**：对其余每个研发环节，问「它因人的局限而存在，还是因问题需要它」[F-018]——先判断题干再谈落地，避免在旧流程上「插 AI」而非「重建」[F-020][F-023]。
2. **上游质量门**：把「需求可执行性」和「方案正确性」做成进入开发的前置闸门（打分/找茬/待确认项早暴露）[F-041][F-045][F-046]。
3. **方案依赖图排序**：实现步骤按依赖自底向上，垂直切片保证每步可编译可验证 [F-044]。
4. **范围纪律 + 关键路径先测**：Agent 只碰明确文件并记录「发现但不碰」；核心逻辑先写失败测试再实现 [F-049]。
5. **审查两档 + 安全硬底线**：关键问题才阻塞、改进建议不阻塞；安全六项无条件强制核对 [F-052][F-053]。
