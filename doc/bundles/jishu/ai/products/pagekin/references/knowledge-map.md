# Pagekin 知识地图与迁移模式

## 范围与骨架

主线是小说创作桌面工具，因此归入 `jishu/ai/products/pagekin/`。文学经典分组不承担软件使用任务，工程实践分组不承担该产品的集中说明。本次不新增分组，不复制已有 InkOS 包的 Agent 架构。

| 层次 | 材料 | 读者任务与落点 |
|---|---|---|
| 事实层 | F-001 至 F-044，文章、维护者说明、模型官方协议 | 认识产品、区分网页声明与实测：概览和 references |
| 机制层 | F-005 至 F-010、F-029 至 F-030 | 理解章节材料组织与人工审校：上下文、审稿教程 |

## I-01 材料筛选需要遗漏检查

- 现象：文章把相关角色、蓝图和摘要作为章节上下文，官网描述相同主要材料（F-007、F-029）。
- 工作原因假说：按章节取材能减少无关材料进入本次生成，但筛选也可能遗漏早期线索。本轮未查检索实现，不能断言具体算法。
- 影响：可控输入和完整记忆是两项不同目标；“材料更少”不能推出“不会忘”。
- 建议：把线索起点、当前状态和应回收章节另列台账；写前核对，写后对照原文。
- 陈述/证据/反常识/行动：检验上下文时先找缺项；F-007、F-009、F-029；短上下文不自动更准确；用[手工蓝图练习](../examples/02-blueprint-and-continuity.md)检查遗漏。

## I-02 确认入口不等同有效监督

- 现象：维护者演示意见选择与差异合并，也演示全部采用（F-039、F-040）。
- 工作原因假说：系统把修改交给作者决策，但作者仍可能因省事跳过检查。
- 影响：拥有确认按钮不保证每处差异都经过理解；默认全部接受会弱化监督。
- 建议：先核对作者不允许改变的事实，再判断修改建议；合并与定稿分开。
- 陈述/证据/反常识/行动：监督取决于核对内容；F-010、F-039、F-040；按钮不是质量保证；从一段修稿开始记录采用理由。

## I-03 本地与云端需按动作划边界

- 现象：作品存于本机，同时云模型收到相关文本，Key 存于本机配置（F-031、F-032）。
- 工作原因假说：文件保存位置、模型计算位置和凭证保存位置是独立选择，界面中“本地作品”标签不能覆盖所有动作。
- 影响：未授权稿件或商业设定仍可能随着一次生成发往外部服务。
- 建议：在调用前分别判断稿件权利、模型去向、费用和密钥保护；先用独立虚构测试材料。
- 陈述/证据/反常识/行动：按调用判断隐私；F-028、F-031、F-032；本地存储不等于离线推理；建立一次不含真实稿件的连通验收。

## PAT-01 分段确认候选模式

这是文档推导的候选模式，不是 Pagekin 的官方术语。支撑产品数为 1，实际实践验证数为 0，跨领域复用数为 0；不能标为已验证模式或正式模式库条目。

适用于有明确原稿、修改意见和差异结果的创作或编辑；不适用于没有原稿基准的自动发布、不可回滚操作，或无人负责审校的场景。

1. 写明不可改变的事实和本次修改范围。
2. 生成建议，并把建议与已确认问题分开。
3. 只把选定意见送入修改。
4. 比对原稿、修稿及事实台账，逐段决定取舍。
5. 保存采用理由，合并后再审校和定稿。

反模式是：把待核实意见当事实、全部接受却称已人工检查、修稿顺带改变未授权设定。它们分别对应 F-039、F-040 及官网的人工判断边界，是防护场景，不是本轮观察到的用户事故。

检验标准：未选意见没有被偷偷处理；拒绝的修改不进入正文；关键事实保持一致；合并后状态与定稿分开。迁移到技术文档审校时，可把人物事实换成 API 契约、蓝图换成章节目标，沿用差异取舍；此迁移只是设计例，不是验证完成记录。
