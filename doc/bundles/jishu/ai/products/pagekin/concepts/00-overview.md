# 认识书童 Pagekin 与创作流程

长篇写作中，角色在前章知道了什么、某条线索是否已揭开、下一章要完成什么，都需要持续保存和检查。Pagekin 把人物、世界观、章节蓝图与稿件放进同一个创作项目，让模型提供草稿和建议，由作者决定内容。维护者将它定位为 Windows/macOS 桌面软件，原名 AI Novel Writer（F-003、F-005、F-019、F-027）。

事实编号统一查[台账](../references/article-source.md)，可信度查[核验表](../references/verification.md)。官网声明 GPL-3.0 与软件免费；本轮未读取 LICENSE 原文或下载二进制，云模型费用另计（F-004、F-028）。

## 先区分六种材料

| 材料 | 回答的问题 | 作者要确认的内容 |
|---|---|---|
| 故事前提 | 谁在什么处境中遇到什么矛盾 | 故事方向与不能随意改变的设定 |
| 人物与世界观 | 人物是谁，世界按什么规则运行 | 人物动机、关系、时间和规则 |
| 故事大纲 | 整本书的事件如何推进 | 主支线走向与关键转折 |
| 章节蓝图 | 本章具体发生什么 | 本章目标、阻碍、结果、结尾问题 |
| 草稿与修稿 | 情节怎样落成文字 | 内容是否实现蓝图，修改是否越界 |
| 定稿与后续资料 | 哪些内容成为下一章的依据 | 采用的正文、后续连续性材料 |

这张表是依据官网流程整理的学习框架，不是数据库字段表或内部状态机。官网描述从前提、人物世界观、大纲蓝图，到生成或导入草稿、审稿修稿及确认定稿的过程（F-005、F-029、F-030、F-041）。

## 一章如何推进

先保存作品方向，再确认人物与世界规则。整体大纲分解到章节蓝图后，生成草稿才有具体目标。审稿意见仍是待核实建议，作者选择需要处理的意见，比较修稿与原稿，再决定合并和定稿（F-005、F-006、F-010、F-039、F-040）。

“合并完成”与“定稿完成”不是一回事。维护者历史演示只到修稿合并，章节仍待定稿；当前官网的另一组截图只到第一章蓝图，正文仍待写（F-037、F-040）。把这些画面拼成“完整小说已写完”的证据会误读演示范围。

## 适合谁

适合愿意自己规划、校对和修改长篇作品的人。已有原稿的人可以考虑导入后继续写，局部句段也可续写或改写，但支持格式和具体入口需按所用版本核对（F-012、F-014）。

它不提供在线发布、阅读社区或模型账号，不能据此推导自动投稿或商业收益。DSH 插件是另一项冻结的开发预览，不应和桌面程序混装（F-035、F-036）。作者仍需承担创意、事实与版权判断，AI 审稿不是质量认证。

## 学习顺序

1. 阅读[章节上下文](01-chapter-context.md)，理解资料筛选与记忆保证的区别。
2. 阅读[审稿与写作规则](02-review-and-skills.md)，学会检查建议与差异。
3. 阅读[模型与数据](03-models-and-data.md)，选择模型协议和数据去向。
4. 先做[手工蓝图练习](../examples/02-blueprint-and-continuity.md)，有需要再走[桌面初次使用](../examples/01-first-session.md)。
