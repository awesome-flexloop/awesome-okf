# 审稿修稿、写作 Skill 与参考资料

审稿报告指出的问题仍需核实。维护者的历史样例包含“复验：未验证”的意见；作者对照设定和原文后，才决定是否将某条意见送去修稿（F-039）。模型提出问题、作者确认问题、作者接受修改，是不同动作。

## 审稿到定稿的分工

| 动作 | 输入 | 观察结果 | 作者责任 |
|---|---|---|---|
| 审稿 | 当前正文与有关设定 | 分条建议 | 对照出处判断是否真有矛盾 |
| 选择意见 | 建议及作者自己的要求 | 本轮要处理的意见 | 不把未核实意见一并默认接受 |
| 修稿 | 原稿与选定意见 | 修订文本 | 检查是否超出本次范围 |
| 差异确认 | 原稿与修稿 | 逐段选用或编辑 | 保持不允许改变的设定 |
| 合并与定稿 | 选用的段落 | 合并结果及后续状态 | 再读正文，确认后才定稿 |

维护者历史演示的差异页提供“用原稿”“用修稿”“手动编辑”，也有“全部用修稿”。所以文章的“不会一键覆盖”适宜理解为有差异查看与确认过程，不能理解为软件完全没有批量采用入口（F-010、F-011、F-039、F-040）。该演示是 v1.3.0，不能直接代替当前版的全部界面验收。

## 怎样判断一条修改意见

先定位问题对应的原文，再问：它与哪个已确认设定冲突；会影响哪些后续章节；所提修法是否改变人物动机。若意见只说“节奏不好”而没有位置和理由，可先补充说明，不必立即重写整章。

修改前写下不可改变的事实，修改后只看差异还不够，还需把相关段落连起来读。局部修法可能让相邻段落的时间或人称不一致。这里是执行者的审校建议，不是声称软件已经自动执行这些检查。

## 写作 Skill 的含义

按文章描述，写作 Skill 是自包含 `SKILL.md` 提示词规则，可从本机或 GitHub 导入并绑定规划、写稿、审稿、修稿等阶段；文章称不运行脚本或 hook（自动触发的扩展动作）。本轮没有读取装载源码，不能据此证明实现只处理文本或不能执行工具，安全结论保留单源（F-015、F-016）。

普通文本规则仍会影响模型行为。导入前读完整规则，拒绝要求忽视作者意图、隐藏改动、泄露稿件或复制受保护内容的指令。规则之间若冲突，先简化；“去 AI 味”也不是文学质量、原创性或平台审核保证。

下面是独立编写的提示词练习，**不是官方 Skill 模板，也未验证可直接导入 Pagekin**：

```markdown
# 审稿规则练习

对每条问题给出原文位置、相关设定和修改理由。
把待核实问题与已确认矛盾分开。
只处理作者选中的意见。
不得新增人物经历、改变已确认时间或改写结局。
修订后列出仍需作者判断的事项。
```

## 参考小说与原稿导入

维护者支持参考文本、全文检索与风格提取；文章进一步列出 `.txt`、`.md`、`.epub` 与仿写约束，精确格式支持本轮未核查（F-012、F-044）。导入自己的原稿续写和对正文选段操作已有维护者说明（F-014）。

把参考文本放进知识库不等于获得改编或上传权限。“不会混进正文”也不是防复制保证（F-013）。优先用自己的作品或明确获授权的材料，提取通用的节奏、叙述距离、句式变化；不要要求模型复制原作人物、情节或独特段落。云模型参与时还要判断是否获准把参考文本发给服务商。

文章还提到版本历史、向量检索和 WebDAV 备份，本轮只有全文检索得到官网对应，其余暂不作为已验证功能教程（F-018）。备份是否成功应靠真实恢复验证，不能只看按钮或宣传描述。

向量检索按内容相似程度找材料；WebDAV 是远程文件访问协议，可能把备份送到外部服务器。这些用途解释不证明 Pagekin 的具体实现。初次学习可跳过相关选项，先完成一章的人工审校。
