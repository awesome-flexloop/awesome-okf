# 桌面版初次使用与小范围验收

**本流程来自官方公开操作记录，未在当前机器安装或运行。** 当前官网图文标注 v1.3.2，审稿视频和图文标注 v1.3.0；实际入口和状态以安装版本为准（F-027、F-037、F-038）。没有在文中预填任何“运行成功”结果。

## 准备与安装

准备一份独立虚构创作方向，以及可使用的模型。云服务需自行开通并检查费用；本地模型需已安装且能运行，教程不自动安装软件、下载模型或调用服务（F-023、F-028）。

从维护者指向的 [Release 入口](https://github.com/EthanYoQ/AI-Novel-Writer/releases/latest)选择对应包（F-019、F-033）：

| 平台 | 官网文件名模式 |
|---|---|
| Windows x64 | `ai-novel-writer-setup-<version>.exe` |
| macOS Apple Silicon | `ai-novel-writer-mac-arm64-<version>-installer.dmg` |
| macOS Intel | `ai-novel-writer-mac-x64-<version>-installer.dmg` |

这是官网公布的命名模式，不是本轮获取的实际 Release 清单。安装前核对来源、架构和版本；遇到安全警告时先检查，不关闭全局保护。已有作品升级前应独立备份，文章的“升级不删数据”未实测（F-020）。

本包不提供已验证源码构建教程：Node.js 22.14+、指定 pnpm 与构建脚本尚未核查（F-021、F-022）。不要凭文章中缺省的 pnpm 版本自行补写依赖契约。

## 配置模型并试一次短请求

1. 按当前版设置页选择模型服务及匹配协议。云服务填写真实账号授权的端点、Key 和模型名；不要把 Key 写进作品正文。
2. 本地 Ollama 先在其模型管理入口确认已有模型，再按当前官方客户端说明启动服务，独立做一次短对话确认模型可运行；记录实际模型名。没有已安装模型或服务未运行时，停在准备阶段，不为本教程自动下载。随后按[模型配置](../concepts/03-models-and-data.md)填 `/v1` 兼容端点。
3. 用无隐私、无第三方版权内容的短创作请求检查返回结果。若当前版提供测试入口可用它；没有则用一次小范围生成，不假设固定按钮存在。
4. 检查错误提示、输出是否完整、是否发生重复或中断，并记录实际版本和模型。一次返回不等于兼容所有功能。

若无结果，先检查服务是否启动、地址与协议是否一致、模型名是否存在、云账号权限与余额是否足够。不要通过连续整章重试验证连通，避免不必要费用。

## 从设定到第一章

先在文章所述的书房“新建作品”入口填写自己的创作方向，保存后进入创作流程；入口名称以当前版本为准（F-017）。根据维护者 v1.3.2 公开记录，生成后分别检查故事前提、角色名单、世界观和情节大纲，再逐节确认。样例四节均标“已确认”后，下一步蓝图按钮启用；它只展示第一章蓝图，正文待写（F-037）。

故事前提限定核心矛盾，角色名单核对身份关系，世界观检查规则，情节大纲检查事件推进。“故事大纲”在本包是教学总称，不要求软件额外生成一份名为“核心大纲”的第五节。若内容有矛盾先修改再确认，不为开启下一步而直接全选。

用自己的内容完成同类步骤，记录：

| 阶段 | 应留下的材料 | 验收方式 |
|---|---|---|
| 设定与架构 | 确认后的故事方向和人物规则 | 名字、关系、动机互相一致 |
| 第一章蓝图 | 目标、事件、转折与悬念 | 能指出本章结束时发生的变化 |
| 正文草稿 | 生成或导入的章稿 | 对照蓝图和连续性记录，不直接定稿 |

表中的验收方式是执行者建议，不是软件自动测试。无需复制官网的样例小说或计划字数。

## 小范围审稿与差异验收

参照 v1.3.0 历史记录，先出审稿报告，对照原文核实后只选一条意见送修，再检查修稿差异。保留原稿、采用修稿或手动编辑，由作者决定；合并后重新检查再定稿（F-039、F-040）。

若当前版入口不同，停在能核实的阶段，查当前说明。不要把历史“全部用修稿”当必须步骤，更不要用它证明每一段都已人工审查。

成功标准是：选定问题被处理、无关设定未改变、拒绝的差异未进入正文、合并后的状态与定稿分开。失败时保留原稿，不反复覆盖后再寻找错误。

在非正式测试稿中，实际选择一处“用原稿”并记录位置，合并后确认它未被修稿替换，才算覆盖拒绝分支。若本次没有可拒绝的差异，标记该项“未覆盖”，不要当作通过。

## 实际执行时的记录

记录安装版本、操作系统与架构、协议与模型名、测试材料范围、费用或资源观察、实际完成阶段及失败信息。密钥和私有稿件不进公开记录。没有完成正文、审稿或定稿时，分别标记未执行，不能统称“流程通过”。
