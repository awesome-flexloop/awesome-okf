# Octop 多 Agent 专家与长期记忆

> 能力层（How to use the platform's core ideas）。本文聚焦 Octop 区别于单聊天机器人的两个核心能力：多 Agent 专家体系与长期记忆/知识库。

## 从单聊天机器人到 AI 专家团队

Octop 最核心的特点，是把传统「一个通用助手干所有事」扩展为「多个专业 Agent（专家）」（F-012）。

不同任务所需的知识、工具和使用习惯并不相同：写代码、整理会议纪要、制定学习计划，虽然同一大模型都能处理，但各自偏好的工具与上下文不同。Octop 的思路是为不同任务建立专门专家（F-013，作者转述）。

博文举例（F-013，产品用法示例）：

- **写作内容助手**：熟悉文章风格与选题方向；
- **编程助手**：专职代码开发与调试；
- **资料整理助手**：管理文档、检索知识、生成总结。

每个专家（Agent）都可以独立配置：**模型、工作空间、技能（Skills）、消息渠道**（F-014）。

## 专家库与共享

- **专家库**：可复用已有专家配置，减少重复搭建（F-015）。
- **专家共享**：可将配置好的专家分享给同一部署环境中的其他用户（F-015）。
- **AgentTeams（Beta）**：官方提供协调 Agent，可调度多个专家完成多步骤任务（F-038，官方能力，博文未展开）。

## 长期记忆：Octop Memory

Octop 内置长期记忆存储与检索（F-007），由 `harness-memory` 提供：

- **层级召回（hierarchical recall）+ 全文检索（full-text search）**（F-037，官方 PyPI 口径）；
- 智能体的记忆随其**工作空间（workspace）**移动（F-037）。

意义：AI 不再「每次新对话都失忆」，而是能在工作空间内保留过去交互、项目进度与偏好（F-001 概述所述问题 1 的解法）。

## 知识库 / RAG

Octop 内置基于 **RAG（检索增强生成）** 的知识库能力（F-017）：

- AI 可结合**用户自己的资料**回答问题，而非只依赖训练阶段的通用知识（F-018）；
- 适合频繁查阅技术文档、项目规范与内部知识的团队，减少人工翻找（F-018，作者转述）。
- **同一部署环境内可共享知识库**：多个用户或专家按配置复用资料（F-019）。

## 多用户隔离与权限

- 管理员可创建与管理用户；每位用户拥有自己的专家、工作空间与会话数据（F-025）。
- 身份认证使用 **JWT**，提供**管理员角色**与**用户隔离**机制（F-026）。
- 官方口径：一个管理员账号服务于家庭或团队；每位用户的专家、工作空间、模型提供商与定时任务相互隔离（F-038）。

## 反模式与边界

- **孤立专家 ≠ 复用专家**：若每个新任务都从零建专家、不利用专家库与共享，就失去了平台的核心价值（F-015）。
- **长期记忆 ≠ 跨实例通用**：记忆随工作空间，迁移环境需同步工作空间数据（F-037，推断）。
- **知识库共享 ≠ 无权限共享**：共享按配置进行，用户隔离仍由 JWT 权限边界约束（F-019/F-026/F-038）。
