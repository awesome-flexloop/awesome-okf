# 选型矩阵与三个可迁移模式（萃取层）

> 本文是 **E 阶段萃取产物**（G3）：每个模式都给出触发场景、核心步骤、反模式与迁移验证，可脱离 Univer 复用。博文的对比段（F-052~F-055）属**作者观点**，本文把它拆成"可核验事实"与"观点"两层。

## 选型对照（观点与事实分层）

| 方案 | 博文判断（V） | 官方可核验事实 |
|------|--------------|---------------|
| Handsontable / AG Grid 类数据表格 | 缺完整公式引擎与文档模型（F-052） | 官方 SDK 对比页对象为 SpreadJS / Handsontable / ONLYOFFICE / Syncfusion，**未含 AG Grid**（F-072）；对比对象系作者自选 |
| OnlyOffice 集成 | 不用另起文档服务器（F-053） | 仅对**开源子集**成立；启用协同/文件转换仍需 Server SDK（F-060/F-062） |
| Univer 开源核心 | 像把 Office 内核嵌进产品（F-052） | 纯前端可跑、无需商业许可即可编辑与算公式（F-064）；但**不含服务端组件、公式引擎性能低于商业版**（F-072） |
| Univer 完整 SDK | 文件导入导出要付费（F-054） | Exchange / 协同 / 历史属 Server SDK，商业插件与 Freemium 水印另计（F-062/F-072） |

**结论口径**：如果需求是「产品里放一个能算公式的表格、数据自己存」，开源核心可闭环；如果需求是「让用户上传下载 Excel / 多人协同 / 复杂图表透视表」，就进入商业授权范围。选型时把这两句话写进立项文档，比记任一产品名称都重要。

## 模式 P-1：授权边界前置三问

**触发场景**：把开源 SDK 引入商业产品，尤其当**官方 demo 同时展示开源与商业能力**时。

**核心步骤**
1. 立项前逐项列出"必须交付能力"，而不是"演示里看到的能力"。
2. 按产品分层（Web/Server/AI 或等价划分）把每项能力映射到授权档位。
3. 找出**会跨档的那一项**（通常是文件互通、协同、版本历史），先确认授权与预算再写 PoC。
4. 明确标注 demo 的性质（官方是否声明"含商业能力"）。

**反模式**：❌ 看到 "Apache-2.0 商用没问题" 就推定全功能免费；❌ 用在线演示当开源功能清单；❌ PoC 跑通后才评估授权。

**迁移验证**：换任一"开源核心 + 商业扩展"型 SDK（如文档/图表/地图组件）时，若三问仍能定位到跨档能力，则模式成立。Univer 上的验证结果：第 1 问"要不要上传下载 Excel"直接决定是否需要 Server SDK（F-046/F-062）。

## 模式 P-2：把 AI 治理下沉到命令层

**触发场景**：让 AI agent 与人类用户操作**同一个可编辑对象**（表格、文档、设计画布、配置台）。

**核心步骤**
1. 确认人和 agent 是否共用同一套写入 API；若是，则治理点应放在该 API 之下，而非 UI 之上。
2. 在"执行前"事件做权限判定并支持取消，在"执行后"事件做审计留痕。
3. 让 agent 在**隔离草稿**中作业，读回自检后再交人显式合并。
4. 把"命令成功"与"结果正确"分开——用读回断言验证后者。

**反模式**：❌ 只在 UI 层禁按钮，agent 从旁路绕过；❌ 让 agent 直接写生产对象、靠提示词约束行为；❌ 以工具返回码成功当作任务完成。

**迁移验证**：Univer 对应 `BeforeCommandExecute` / `CommandExecuted` + Worktree + readback（F-068/F-071/F-072）；官方文档逐字 "Command success is not correctness evidence"（F-071）。换到任何具备命令/事件总线的编辑型系统，若仍存在"执行前可取消 + 执行后可审计 + 隔离草稿 + 读回自检"四件套，模式即可迁移。

## 模式 P-3：快照优先、文件互通后置

**触发场景**：产品需要持久化用户编辑内容，且同时被要求"支持导出 Excel/Word"。

**核心步骤**
1. 先用系统**内部快照格式**完成持久化闭环（可序列化、可恢复、自带插件数据）。
2. 把"文件格式互通"识别为**独立能力**，单独评估授权与服务端依赖。
3. 恢复路径要显式"用快照创建"，而非"创建空白对象再灌数据"。
4. 在需求文档中写清「能保存」≠「能导出 Excel」。

**反模式**：❌ 把内部快照当成文件导出交付；❌ 先建空对象再逐格回填（易丢插件数据）；❌ 把文件转换当成本地前端小事。

**迁移验证**：Univer 上 `workbook.save()` 为含插件数据的 JSON 快照，恢复须 `createWorkbook(JSON.parse(saved))`，XLSX 走 Server SDK Exchange（F-067/F-072）。任何"内部模型 + 外部格式"双轨系统均可套用。
