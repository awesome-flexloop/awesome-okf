# Token 共享与交换机制——共享池、Token 市场与 TC 经济模型

> 机制描述以博文口径为线索（F-010~F-019），每项均对照 2026-09-16 站点实测（F-026~F-031、F-037）。

## 一、出发点：套餐额度的"重置浪费"

作者的机制设计基于一个观察：订阅制套餐过 0 点重置，没用完的额度"白送给模型厂商"，而为了不浪费刻意用 AI 又是"时间换空间"（F-007，📝 作者观点）。他归纳出四条处置路径（F-008）：

1. 团队共享、AA 平分账单；
2. 无偿分享给他人（"做慈善"）；
3. 二次分发改售；
4. **像存银行一样把 Token 存起来**——AITokenBus 选择的方向。

另一类闲置资源是自购算力：自有服务没有请求时 GPU 空转（F-009）。平台因此同时做"额度流转"和"算力流转"两个市场。

## 二、Token 共享池：把套餐"分包"（F-014，✅ 实测确认）

套餐持有者把模型厂商的 **API 地址和一个专有 API Key 托管**到平台，创建一个"Token 共享池"，再生成邀请链接发给成员；成员通过共享池分配的专有 API 地址与 Key 接入，消耗的是创建者套餐的额度。作者称之为"分包器"——一个套餐分成多个包，一人一包，用不完还可以继续发邀请（F-014）。

实测要点（F-026/F-037）：

- 池上游配置字段：`source_type / api_url / api_key / auth_type / models / fallback_model / max_members / lifecycle_days`——即池有成员上限和生命周期；
- 邀请码可重新生成（`/pools/:id/regenerate-invite`），加入链接 `https://aitokenbus.24x7.to/join/<邀请码>`，无效码公开访问即返回"链接无效"；
- 首页特性称成员 API Key 自管、**创建者不可见**，并支持 Token 限制、周期配额、并发与 RPM 限流。

## 三、Token 市场与 TC：glm → Token Coin → K3（F-015/F-010，✅ 实测确认）

共享池可以"分包挂售"到 Token 市场：其他用户使用你池里的 Token 时，向你支付 **Token Coin（TC）**；你再用 TC 去消费别人挂出的其他模型。作者强调这不是直接互换，而是 **glm → TC → K3** 的媒介路径（F-015）。

实测（F-027）：市场免登录可见，核验日 8 个挂售，全部以"**TC/千 Token**"计价，从 0 TC（OpenRouter 免费模型）到 1 TC（AIHubMix 混合池）不等，挂售方自定成员上限与可用模型清单。TC Wallet 记录余额、累计赚取/消耗与收支明细。

**TC 的三重设计意图**（F-010/F-011/F-016/F-013，⚠️ 部分实测）：

| 设计点 | 博文口径 | 实测对照 |
|--------|---------|---------|
| 交换媒介 | 不同厂商 Token 之间经 TC 互转 | ✅ 市场挂售/消费均以 TC 结算 |
| 跨期存储 | 不用就永久躺在账户里，把今天的 Token 挪到未来用（📝 作者阐释） | ✅ 钱包有累计余额；但"永久"是产品承诺，无条款文本 |
| 激励供给 | 提供免费模型/挂售/捐 GPU 都能赚 TC，再去消费高级模型 | ✅ 赚 TC 三途径（官方活动/挂售分成/GPU 节点奖励） |
| 合规隔离 | **不与法币兑换、不可转让、仅站内产生与使用**，定位"生态虚拟币"以规避非法交易 | ⚠️ 全站确无充值/提现/法币代码痕迹（F-029），但无任何协议公示该属性 |

## 四、两个"矿池"：免费 LLM 池与 GPU 贡献（F-012/F-017/F-018，⚠️ 部分确认）

平台把"贡献"也设计成赚 TC 的途径，存在两类池：

- **官方免费 Token 池**（F-018）：博文口径"注册账号即可立即使用、不花钱不扣 TC"，代价是控制请求频率；池内 Token 全部由其他用户贡献，"人越多效率越高"。实测免费池 `official-mine-pool-free-llm` 真实存在（0 TC、131K 上下文、登录后免审批加入），但核验日仅 **2 个在线节点、35 个价目模型中只 1 个可用**（F-028）。
- **GPU 算力池**（F-017）：博文设想用户在自己电脑装"**ollama 之类**"的大模型启动器，空闲时运行小模型接入平台供 Token、赚 TC，作者自比"挖矿"但强调 Token 真的帮到人、产生实际价值。实测 GPU 贡献机制确实存在（注册节点填 GPU 型号/显存/模型，密钥前缀 `skml_`），但承载形态是**自研桌面客户端 SUMU v0.1.2**，全站"ollama""vllm""lm-studio"零命中、无本地接入文档（F-031）——"用 ollama"是作者的设想性说法，产品实现并非如此。

## 五、请求路由：按任务智商分流 + 故障切换（F-019，⚠️ 部分确认）

博文的路由构想有两个目的：

1. **成本分流**：高智商任务走高单价模型，简单任务（文字处理/翻译/检查）走免费或低价池——"不同任务交给水平不同的模型"（与 F-018 的免费池定位呼应）；
2. **故障容灾**：同一任务配多条规则，一个上游挂了自动切下一条，避免编程工具中途报错（速度换连续性）。

实测 Request Routing 模块（F-030）：

- ✅ 支持按**内容类型**分派：Default / Thinking / Long Context / Image Understanding / Model Mapping；
- ✅ 支持请求模型改写、目标模型改写、优先级 Priority（高值优先）、规则启停、独立路由 API Key 与 Base URL；
- ⚠️ 但前端代码 "failover" 零命中，"自动切换到其他上游池"**没有公开说明**；仅每个池的上游配置有 `fallback_model`（同池备用模型）字段。优先级规则是否隐式构成降级链，公开页面无法确认。

## 六、机制总评

把五块拼起来，AITokenBus 本质是一个**带积分层的多租户 LLM 网关**：共享池解决"额度分包与邀请管理"，市场+TC 解决"跨厂商、跨期的额度再分配"，矿池解决"零成本供给与闲置算力变现"，路由解决"按任务选池"。博文描述的机制在产品中**大部分有对应实现**（共享池、市场、TC、免费池、GPU 节点、路由分流均经实测确认）；偏差集中在三处：ollama 的具体技术形态、跨池自动故障切换、以及 TC 属性/永久存储的**条款化承诺缺失**——这些偏差的合规含义见 [02-risks-and-boundaries.md](02-risks-and-boundaries.md)。
