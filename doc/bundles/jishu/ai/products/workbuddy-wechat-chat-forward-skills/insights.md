# 洞察

> 下列内容是编者从事实登记和核验结果中抽取的洞察，不是 WorkBuddy、微信或文章作者的官方承诺。事实依据分别回指 `F` 编号；状态与缺口见 [references/verification.md](references/verification.md)。

## 1. 入口稳定性先于自动化能力

- **陈述**：工作流能否长期运行，首先取决于入口是否稳定、授权边界是否清楚，而不只是 Skill 的处理能力。
- **证据**：原生入口与四步路径见 F-013~F-016；旧方案的下架与风险叙述见 F-024~F-030；DMCA 事件的权威核验见 F-107~F-110。
- **反常识**：标题把入口描述为“不怕封号”，但核验未发现相应官方承诺；该表述属于因果跳跃，不能作为平台保证（F-030、F-111）。
- **行动**：在设计聊天自动化前，单独记录入口来源、用户主动操作环节、失效替代路径与账号风险，不把“能转发”写成“不会受限”。

## 2. Skill 的复用性来自流程分层

- **陈述**：将确定性处理、模型判断和最终呈现分层，比单纯增加提示词长度更有利于复用。
- **证据**：日报 Skill 的时间线拼接、去重和脚本/模型/版式分工见 F-042~F-059；配置沉淀与风格切换见 F-080~F-081。
- **反常识**：Skill 并不等于一段更强的自然语言指令；如果结构、计算和呈现没有分层，换场景时仍会重复人工整理。
- **行动**：先列出可计算、可判断、可呈现三类步骤；把可计算部分固定化，把风格变化限制在呈现层，并为每层保留可核查输入输出。

## 3. 辟谣输出的可信度取决于引文可核对性

- **陈述**：辟谣卡的说服力不仅来自结论，还来自每条结论是否能回到准确的权威出处。
- **证据**：三条测试消息及其权威依据见 F-060~F-069；淡盐水引文逐字对应见 F-115；ETC 与微信收费两条存在出处或措辞差异见 F-117~F-118。
- **反常识**：结论方向正确，并不意味着引文可以概略转述；媒体名、栏目名和原句错配会削弱可复核性。
- **行动**：每张卡为每条结论保留来源链接和原文摘录；发布前逐条核对主体、标题、时间和措辞，不能用“某官方媒体说过”替代出处。

## 4. 输出载体应服从受众和转发场景

- **陈述**：给自己复盘和给群成员转发是不同任务，应使用不同的信息密度与版式。
- **证据**：长图、单条卡及面向家族群的输出分层见 F-070~F-072；具体图片结构因正文未返回而登记为缺口见 F-073~F-074、F-082、F-095。
- **反常识**：把所有依据塞入一张“更完整”的长图，不一定提高传播效果，反而可能降低读者抓住结论和行动建议的概率。
- **行动**：先确定受众、阅读时长和转发场景，再决定长图、单条卡或文字摘要；对图片中未返回的规则不自行补写。

## 5. 原生入口不等于官方免责

- **陈述**：产品能通过微信提供的入口接收聊天记录，只能证明存在一条可操作路径，不能推出账号安全或平台责任承诺。
- **证据**：入口路径与 WorkBuddy 选择项见 F-013~F-016；文章的“不怕封号”表述及其无官方依据的核验见 F-030、F-108、F-111。
- **反常识**：用户主动点击、无需扫码或脚本等操作特征，并不能替代平台对账号风险的明示说明（F-015、F-026）。
- **行动**：涉及封号、合规或安全的文案必须引用官方原文；没有官方依据时，标为作者观点或不可验证声明，并在交付中显式保留风险。

## 6. 自动化末端应保留人的语气判断

- **陈述**：面向家人或群聊的自动化输出，最后一步仍需要人判断语气、关系和是否适合发送。
- **证据**：作者关于“建议这样回”“改两个字再发”的设计描述见 F-091~F-093；输出分层与人工改写位置见 F-070~F-072。
- **反常识**：自动生成越完整，不代表越适合直接发送；关系语境往往不在结构化事实中。
- **行动**：把“人工审阅、改写、确认后发送”作为流程中的显式闸门，不把图片生成或结论生成视为发送授权。

## 采用边界

- 这些洞察可迁移到“聊天记录 → 结构化处理 → 面向不同受众输出”的设计，但不能据此证明两个 Skill 已开源、可安装或可复现（F-037、F-096~F-100、F-120）。
- 文章图片中的规则、版式和入口生态未在正文返回，不能根据图片标题补足实现细节（F-073、F-082、F-095）。
