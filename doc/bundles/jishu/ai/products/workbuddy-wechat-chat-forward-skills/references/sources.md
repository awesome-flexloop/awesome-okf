# 信源地图

本文件是信源导航，不替代 [article-source.md](article-source.md) 的 F 编号事实清单，也不替代 [verification.md](verification.md) 的逐项核验。具体声明以 F 编号为准。

## 信源分层

| 层级 | 信源 | 可支持的内容 | 使用边界 |
|---|---|---|---|
| L1 原文 | 微信公众号《微信聊天记录终于能正经交给 AI 了，官方开的口子不怕封号》 | 文章元信息、作者叙述的入口、两个 Skill、提示词和作者自述（F-001~F-100） | 文章是作者实践与推广混合文本；作者观点、自述和图片缺口不得升级为官方事实（F-037、F-095~F-100） |
| L2 产品信源 | WorkBuddy 官网 | 产品定性与官网可见的产品入口信息（F-119） | 不据此补写两个 Skill 的源码、版本、许可证或下载方式 |
| L3 平台帮助 | 企业微信官方帮助中心《如何合并转发会话消息》 | 合并转发的条数与消息体积口径（F-101） | 不能把企业微信口径直接等同于个人微信全平台口径 |
| L4 权威转述 | 微信派、钛媒体、腾讯回应及 GitHub 受影响项目 README | 入口的第三方旁证、100 条端差异、DMCA 事件（F-102~F-110） | 同一时间窗的多篇实测可能存在转载关系，不能替代正式官方公告（F-103~F-106） |
| L5 辟谣来源 | 四川省人民政府、新华网、中国互联网联合辟谣平台、无锡公安、澎湃新闻、光明网转载健康上海 12320、央视网等 | 三条测试消息的权威核验依据（F-112~F-118） | 引用时必须按 verification.md 的逐字核对结果写明实际来源 |

## 事实登记关系

- `references/article-source.md` 是 F-001~F-120 的 bundle 侧登记；主仓库 spec 的 `facts.md` 是对应正本，编号集合必须相等且连续。
- `references/verification.md` 记录 20 项 P0/P1 核验、E-1~E-6 勘误以及 `status: flagged` 的判定依据。
- `insights.md` 只抽取可从上述登记支持的模式；其中“行动”是编者建议，不是新增事实。

## 关键使用规则

1. 看到入口路径时，优先引用 F-013~F-016，并同时保留“无官方公告”的限制（F-103~F-106）。
2. 看到“100 条”时，必须同时检查企业微信 2MB、iOS 100 和安卓 99 的口径差异（F-101~F-102）。
3. 看到“不怕封号”或“两个 Skill 都开源”时，分别回到 E-1、E-2；前者无官方依据，后者不可验证，不得改写成承诺或已证伪事实（F-030、F-037、F-111、F-120）。
4. 看到辟谣卡中的媒体名或引文时，回到 F-115、F-117、F-118 与 verification.md，不凭记忆替换出处。
