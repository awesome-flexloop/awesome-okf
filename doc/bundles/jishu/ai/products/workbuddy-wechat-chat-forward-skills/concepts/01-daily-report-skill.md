# 工作群日报 Skill：时间线拼接、三层分工与选题雷达

> 本篇是**机制层 A**。作者对这个 skill 的全部描述均为**自述（S）与设计观点（V）**：正文没有源码、脚本、配置样例或运行日志（F-098），输出为图片且图片文字未转录（F-095）。因此本篇讲的是「作者声称怎么设计」，不是「已验证的产品实现」。

## 1. 从旧方案到重做

| 阶段 | 博文表述 | 依据 | 类型 |
|------|---------|------|------|
| 旧方案 | 作者自引「去年 6 月」的《微信群聊一键整理！n8n+AI自动生成日报》；称「能跑通，但门槛不低。要装工具、配环境、串工作流」，且那篇文章开头「还得专门花一节回答『会不会封号』」 | F-042 / F-043 | S（旧文日期未独立核验） |
| 新方案 | 换成官方入口后「前面这些全省了」，作者「把日报从头重做了一遍」 | F-044 | S |
| 两处改进 | 「一是日报里能直接捞出选题，二是长相要普通人也愿意看」 | F-044 | S |

这条演进线是本束最有迁移价值的部分：**省掉的不是「整理」这一步，而是「把聊天记录弄出来」这一步**（F-013~F-016、F-024）。功能复杂度没降，降的是入口成本与合规顾虑（见 [00 篇](00-official-entry-and-path.md) §5）。

| 消息数 | 216 条 | F-045 | 📝 作者自述 |
| 发言人数 | 36 人 | F-045 | 📝 作者自述 |
| 图片数 | 27 张 | F-045 | 📝 作者自述 |
| 切出话题 | 6 个 | F-046 | 📝 作者自述 |

## 3. 三层分工：为什么是 skill 而不是一句「总结一下」

作者的自问自答（F-021，**V**）：直接说「总结一下」，「每次出来的东西都不一样，今天给你五段话，明天给你一张表」。于是他把流程「钉死」（F-022，**S**）：

| 层 | 承担者 | 博文依据 | 设计意图 |
|----|--------|---------|---------|
| 确定性计算 | 脚本算数字 | F-022 | 消息数、人数、时段热度等可计算结果不交给模型 |
| 语义判断 | 模型判断 | F-022 | 话题切分、头条提炼、选题角度交给模型 |
| 呈现 | 版式固定成长图 | F-022 / F-035 | 输出形态稳定，读者形成阅读预期 |

作者进一步称「换风格只要说一句『换成手账风』，它**只重新出图，不重新分析**」（F-059，**S**）——把「分析」与「渲染」解耦，风格切换不触发重算。这条与 F-080「首次配置写进配置，以后就不用再说」共同构成复用设计：**一次性配置 + 稳定流程 + 可替换渲染**。

> 上述分工是作者的设计自述，正文未给出脚本、数据结构或渲染实现（F-098）。把它当模式读（见 [03 篇](03-transferable-patterns-and-boundaries.md) §2 模式 2），不要当 API 读。

## 4. 选题雷达：把零散发言合成为需求信号

作者称日报里能「直接捞出选题」（F-044），具体是找五类信号（F-051，**S**）：

| 信号 | 原文识别特征 | 合成逻辑 |
|------|-------------|---------|
| 反复追问 | 好几个人问了同一个问题却没人答上来 | 同一问题在不同时间被多人提起 |
| 争议未决 | 吵了半天没结论 | 讨论热度高但无收敛 |
| 空白需求 | 有人说「要是有个工具能……就好了」 | 显式表达未被满足的愿望 |
| 踩坑记录 | 有人分享报错和隐藏规则 | 可复用的经验与边界条件 |
| 新工具新玩法 | 新功能上线大家跟着试 | 早期采用者行为 |

配套两项：

- **证据绑定**（F-052，**S**）：每个信号写「谁、几点、几个人参与」，使结论可回溯到原消息；
- **个人配置**（F-053/F-078/F-080，**S**）：以「你是谁、擅长什么、不做什么」为过滤条件，输出「切入角度、该写文章还是做工具、大概要多久、第一步干什么」；不填也能跑，但方向会泛。

作者的观点是「单看哪一条都不起眼，几个人在不同时间问了同一件事，合在一起就是一个真需求」（F-054，**V**）。这是**聚合优于单条**的判断，也是「数字由脚本算、判断交给模型」的具体落点：计数与时间点由脚本给出，是否为需求由模型结合配置判断。

## 5. 五种风格：从「我好看」到「群里愿不愿翻」

| 风格 | 作者给的适用场景 | 依据 |
|------|----------------|------|
| 苹果扁平（默认） | 大多数群都合适 | F-058 |
| 便当盒拼贴 | 截首屏发朋友圈、小红书最出效果 | F-058 |
| 杂志白 | 偏正式的群和周报 | F-058 |
| 手账便签 | 家长群、读书群这类非技术群 | F-058 |
| 深蓝琥珀 | 作者自己的品牌色（第一版） | F-055 / F-058 |

形成过程（F-055~F-057，**S**）：第一版用与封面同色系的深蓝配琥珀金，作者自己满意；但「我觉得好看不算数」（F-056，**V**），真正的问题是「这张图最后是要发到群里的，群里的人愿不愿意往下翻」。于是摆出四个方向并排比，结果「哪个都舍不得删，干脆全留下」，连第一版共 5 种。

**可迁移的判据**：输出物的审美标准由**受众与分发场景**决定，不由制作者偏好决定；当无法判断时，用并排对比代替猜测（F-056/F-057）。这一点与 [02 篇](02-factcheck-card-skill.md) 的「长图 / 单条卡」分层是同一个思路。

## 6. 结构缺口：日报里到底有什么，正文没说

「日报里有什么」小节在「从上往下读，依次是：」之后即为图片（F-050），正文没有给出条目文字；热度图、日报长图、五风格对比同样是图片（F-095）。因此本束**不列出日报的完整字段清单**——只能确认文中零散提到的组件：头条一句话（F-048）、热度图（F-049）、选题雷达（F-051~F-053）、五种版式（F-058）、以及「从上往下读」的顺序性（F-050）。

同样地，分批拼接、自动去重（F-019/F-020）与「几秒钟就好」（F-059）都没有算法说明或计时证据。若日后取得图片 OCR，应以新增 F 编号补齐，不回改现有编号（见 [核验报告](../references/verification.md) §5）。

## 7. 本篇结论

- **值得学**：入口成本优先于功能复杂度；确定性/判断/呈现三层分离；分析渲染解耦；信号聚合并绑定证据；按受众定版式。
- **不可照搬为事实**：全部实测数字、五种风格的实际效果、拼接去重算法、「几秒钟」体感——都是作者自述，缺少可复核材料（F-095~F-098）。
- **不能复现**：两个 skill 的 zip 无正文链接、无版本、无源码（F-040/F-099/F-120），因此本束不设 `examples/`，也不提供演练步骤。
