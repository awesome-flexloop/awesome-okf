# 可迁移模式、操作路径登记与可复现性边界

> 本篇是**模式与边界层**。§2 的五个模式按「触发场景 / 核心步骤 / 反模式 / 迁移验证」四段组织（七概念 G3）；§5 是原子化行动清单（G4）。所有模式是**从博文萃取的可迁移思路**，不是 WorkBuddy 官方 API 或已验证实现。

## 1. 洞察四元组落地（承接 spec I 阶段）

| # | 陈述 | 证据 | 反常识 | 行动 |
|---|------|------|--------|------|
| 1 | 决定长期可用性的常是**入口**而非功能 | F-024~F-030 / F-089 / F-107~F-110 | 作者反而认为「门小、一次 100 条、亲手推」是优点（F-033/F-088） | 方案评审先盘点数据入口授权来源 |
| 2 | skill 化的本质是**钉死流程** | F-021 / F-022 / F-059 / F-080 | 模型越强不代表越不需要固定流程，输出不稳定才是复用障碍 | 拆「可计算 / 可判断 / 可呈现」三层 |
| 3 | 辟谣说服力来自**可点名的权威依据** | F-068 / F-069 / F-115 / F-117 / F-118 | 引文出处写错，比结论不够详尽更伤说服力 | 每条结论附可核验链接并做逐字核对 |

## 2. 五个可迁移模式

### 模式 1　入口合法性优先（Entry-first）

- **触发场景**：要把某个平台内的私有/半私有数据（聊天记录、工单、邮件、文档库）交给 AI 处理。
- **核心步骤**：
  1. 列出候选数据获取方式，标注是否依赖模拟登录、读取本地数据库、逆向协议或自动化脚本（F-025）；
  2. 查平台对该类行为的公开表态与历史事件（如 2026-01-22 DMCA 投诉下架，F-107~F-110）；
  3. 优先选择平台内原生、由用户主动触发的入口（F-013/F-016/F-103）；
  4. 把「入口断了怎么办」写进方案，而不是只优化下游功能（F-089/F-090）。
- **反模式**：先用第三方导出工具把链路跑通，再回头担心合规；把「官方提供入口」直接写成「官方保证无风险」（F-030，E-1）。
- **迁移验证**：能否用一句话说清「数据是怎么从平台到 AI 的」，且这句话里没有「模拟」「破解」「绕过」；能否指出该入口依赖的客户端版本（本文缺，F-096）。

### 模式 2　确定性 / 判断 / 呈现三层分离

- **触发场景**：同一个任务需要反复执行，而直接一句提示词每次输出形态都不同（F-021）。
- **核心步骤**：
  1. 把可精确计算的部分交给脚本（计数、时间分布、去重、排序，F-020/F-022/F-049）；
  2. 把语义判断交给模型（话题切分、头条、选题角度，F-022/F-048/F-051）；
  3. 固定呈现层（长图版式、字段顺序，F-022/F-050）；
  4. **分析与渲染解耦**：换风格只重渲染、不重分析（F-059）；一次性配置写进配置而非每次重说（F-078/F-080）。
- **反模式**：让模型既算数又排版；把风格切换实现成整链路重跑；把「数字由脚本算」当口号却不落实（本束无源码可验证，F-098）。
- **迁移验证**：同一份输入连续跑两次，确定性字段是否完全一致；只改风格参数时，分析结果是否保持不变、耗时是否显著下降。

### 模式 3　证据可点名且逐字核对

- **触发场景**：输出会影响他人判断或行动（辟谣、合规结论、医疗/财务提示）。
- **核心步骤**：
  1. 每条结论绑定一条可访问、可点名的权威来源（F-068/F-070/F-071）；
  2. 结论方向与**引文出处**分开核验：本文三条结论方向全对，但两条媒体名/栏目名记错（E-4/E-5，F-117/F-118）；
  3. 对官方定位、机构名、栏目名做逐字核对，意译不加引号；
  4. 高风险项固定置顶、原话中的链接打码（F-070）。
- **反模式**：只写「据权威媒体」「网上查到」；把「AI 判断」当依据；在结论里夹带与权威口径相反的隐含承诺（如淡盐水「降血压」，F-064 vs F-116）。
- **迁移验证**：随机抽 3 条结论，逐条打开链接确认机构名、日期与表述一致；任一链接失效即视为该条不可发布。

### 模式 4　按受众分层输出

- **触发场景**：同一份分析结果要同时给「自己复盘」和「转发给别人」两类读者。
- **核心步骤**：
  1. 先定受众与分发场景，再定信息密度（F-056/F-058/F-070/F-071）；
  2. 完整版给自己：结构化、含证据、含热度与选题（F-048/F-049/F-051）；
  3. 轻量版给群里：一条一卡、原话划掉、一句大字结论、底部带依据（F-071）；
  4. 无法判断受众偏好时，用并排对比代替主观猜测（F-057）。
- **反模式**：把所有信息塞进一张更全的长图；用制作者自己的品牌色当默认审美（F-055/F-056）。
- **迁移验证**：把两类输出给目标受众各看一次，能否在 5 秒内说出核心结论；轻量版是否仍然保留依据。

### 模式 5　末端保留人类语气

- **触发场景**：AI 生成的内容会以「我」的名义发给熟人、长辈或客户（F-091/F-092）。
- **核心步骤**：
  1. 生成可复制的话术而非自动发送（F-070「建议这样回」）；
  2. 明确提示使用者改成自己平时说话的样子（F-092）；
  3. 把「判错比不判更伤」作为保守倾向的原则（F-073 引导句）——注意三条具体规则正文缺失，不可补写。
- **反模式**：生成即代发；把礼貌话术完全外包给模型；在辟谣场景为追求覆盖率而给出绝对化结论。
- **迁移验证**：发送前是否存在一个无法被自动跳过的人工确认点；话术里是否留有可改写的余地。

## 3. 操作路径登记（原文照录，未实机复现）

> ⚠️ 以下为**信源原文登记**，用于理解文章在讲什么，**不是本束提供的操作教程**。两个 skill 的 zip 无正文链接、无版本、无源码（F-040/F-099/F-120），本次未安装、未运行、未产生任何输入输出。按「操作可复现性两问」第二问为否，本束不设 `examples/`。

**四步路径**（F-016）：长按多选 → 合并转发 → 转发到其他应用 → 选 WorkBuddy → 说 `整理日报` 或 `帮我辟谣`。

**提示词原文**（F-075~F-078，逐字）：

> 紧邻提示：以下四组文本是**原文照录的事实登记**，依赖两个未公开、未实跑的 zip；复制粘贴并不会得到文中效果。本束不提供演练步骤，也不保证这些提示词在当前版本可用。

```
整理日报
```

```
整理日报，用手账风
整理日报，五种风格各出一张
整理日报，用杂志风，昵称打码，我要发回群里
```

```
帮我辟谣
```

```
整理日报。这个群叫「AI 超级个体交流群」，我是写自动化工具分享的公众号作者，不做课程带货。
```

作者称最后一例用于首次配置，「它会顺手写进配置，以后就不用再说」（F-079，**S**），且「你是谁、擅长什么、不做什么」决定选题雷达的方向，不填也能跑但会比较泛（F-080，**S**）。

**导入说明**（F-038/F-039，**S**）：两个 skill 都是 zip 包，在 WorkBuddy 里导入即可用；因「公众号正文里不让放外链」，获取方式放在评论区置顶。本束无法核验该链接是否存在、是否仍有效（F-041/F-120）。

## 4. 同一入口的延展规划（现状与规划须分开）

作者观点：「这两个 skill 用的是同一个入口。入口不变，接上不同的 skill，就是不同的工具」（F-081，**V**），并列出三个**尚未实现**的方向（F-082~F-086，**S**）：

| 规划 skill | 设想 | 状态 |
|-----------|------|------|
| 需求确认单 | 把对接群转过去，理清交付物、截止时间、每轮修改意见 | 规划（F-083） |
| 群聊播客 | 日报写成两人对聊稿子，配 TTS，通勤听 | 规划（F-084） |
| 新人入群手册 | 每天攒「有问有答」，一个月后出一份 | 规划（F-085） |

「绿色的两个已经开源」是配图标注（F-082），但开源本身无法验证（E-2）。读者不应把这三个方向当作已有工具。

- [ ] 每条对外结论都附一条可打开的权威链接，并核对机构名与栏目名（E-4/E-5）。
- [ ] 已为不同受众准备不同信息密度的输出（F-070/F-071）。
- [ ] 高风险项置顶、原话链接打码（F-070）。
