# 发布单、灰度与回滚实操

微信云托管的部署发布采用**发布单**形式，流程包含新建版本、测试、灰度上线 3 个子流程（F-053）。它不是控制台里的一个可选页面，而是这个平台唯一的发布语义载体——版本、灰度、回滚、流水线、CLI 部署都挂在它上面。本文档按发布单的实际操作顺序展开。

## 目标与前置条件

**目标**：完成一次可控的发布——新版本先在小范围验证，再按 10% 粒度放量，出问题时能按既定路径向前回退。

**前置条件**：

| 前置条件 | 说明 | 依据 |
|---|---|---|
| 发布单唯一 | 一个服务同一时间点只能存在 1 张发布单，如需发布其他版本需先取消发布或者结单 | F-023 |
| 有可发布代码 | 首发需从 5 种代码方式中选定一种 | F-054 |
| 端口已确认 | 端口号由业务项目自行设定，必须在新建版本时于控制台填写 | F-026 |
| 流量位充足 | 一个服务下最多 2 个版本有流量（服务灰度过程中） | F-024 |

## 步骤

### 步骤 1：新建发布单并确认唯一性

**操作**：在服务下发起一次部署发布，先确认当前没有其它未结单的发布单；若上一张发布单还在流程中，先取消发布或者结单，再新建。

**关键配置**：部署发布采用发布单形式，流程包含新建版本、测试、灰度上线 3 个子流程（F-053）；一个服务同一时间点只能存在 1 张发布单，如需发布其他版本需先取消发布或者结单（F-023）。

**依据**：F-053、F-023

### 步骤 2：选择代码方式并新建版本

**操作**：首次发布时从 5 种代码方式中选定一种；若走手动上传，注意代码包体积。

| 代码方式 | 说明 | 依据 |
|---|---|---|
| 绑定 Github 仓库 | 首发可选方式之一 | F-054 |
| 绑定 Gitlab 仓库 | 首发可选方式之一 | F-054 |
| 绑定 Gitee 仓库 | 首发可选方式之一 | F-054 |
| 手动上传代码包 | 支持代码文件夹、代码 zip 压缩包两种方式，大小不能超过 2 MiB | F-055 |
| 拉取镜像 | 首发可选方式之一 | F-054 |

**关键配置**：新建版本时同步确认监听端口——必须为 1~61000 之间的整数且不能为 9100；微信云托管默认为 80 端口，如果没有找到则部署失败（F-025）。端口号由业务项目自行设定，系统无法自动获取（F-026）。

**依据**：F-054、F-055、F-025、F-026

### 步骤 3：配置测试条件

**操作**：从两种测试方式中选一种；选 URL 参数方式时至少配置 1 个 key 和 value 条件。

| 测试方式 | 约束 | 依据 |
|---|---|---|
| OpenID 白名单 | 与 URL 参数并列的两种测试方式之一 | F-056 |
| URL 参数 | 至少配置 1 个 key 和 value 条件，value 支持 Glob 表达式 | F-056 |

**关键配置**：URL 参数方式用请求特征而非用户身份圈定测试人群，value 支持 Glob 表达式（F-056）。

**依据**：F-056

### 步骤 4：进入灰度并按粒度放量

**操作**：测试通过后进入灰度上线，按 10% 一档逐步调整流量比例。

**关键配置**：

- 灰度上线时按 10% 粒度加减流量比例，只支持最多 2 个版本有流量，支持将灰度流量比例回调（F-057）；一个服务下最多 2 个版本有流量（服务灰度过程中），超过 2 个的其他版本可以存在但没有流量接入（F-024）。
- 流量路由规则为用户首次进入时按照流量比例随机进入某一个有流量的版本，非首次进入时该用户将一直进入到首次进入的版本中（F-058）。
- 进入灰度上线步骤后测试阶段的测试配置失效且不可再回到上一步骤；一旦更新测试配置，当前流程不可返回上一步再重新选择版本（F-059）。

**依据**：F-057、F-024、F-058、F-059

### 步骤 5：结束灰度并留出观察窗

**操作**：按官方推荐节奏结束灰度——先 50%，然后隔 3-5 分钟结束灰度；结束后不要立刻判定健康，留出观察窗。

**关键配置**：版本切换空窗期流量切换出现空白一般持续 1 分钟自动恢复，推荐灰度发布做法为先 50%，然后隔 3-5 分钟结束灰度（F-066）。

**依据**：F-066

### 步骤 6：观察新旧版本交替期

**操作**：发布完成后立刻去控制台看实例分布——新旧版本同时有实例是正常状态，不是配置错误。

**关键配置**：新版本发布成功后旧版本还会缓存 2 分钟时间，这段时间内控制台会看到新旧版本同时都有实例，且部分请求还会走到旧版本（F-061）。版本分线上、线下两种状态；线下版本会无视配置信息，在下线半小时内缩容到 0，并一直保持直到再次被推到线上（F-060）。服务部署发布时都会先产生 1 个容器实例，部署成功后等待半小时再缩容至 0（F-065）。

> **勘误说明（E-003）**：官方文档不同页面口径不一致——`guide/service/online.html` 正文称版本下线后「半小时内缩容到 0」，同页举例又称「缓存 2 分钟后缩容为 0」。本处采信「2 分钟缓存期 + 半小时缩容」的并列口径：二者分别对应缓存与缩容两个阶段（F-060、F-061）。

**依据**：F-061、F-060、F-065

### 步骤 7：出问题时向前回退

**操作**：需要回退时，选定一个更低的版本执行回退，先恢复其最小副本数再接入现网。

**关键配置**：回退操作只能向前回退，即高版本回退到低版本，不可反向回退；回退时先把目标版本的实例数保持到版本创建时的最小副本数，再接入现网（F-062）。除线上版本不可删除外，其余版本均可删除（F-063）。

**依据**：F-062、F-063

### 步骤 8：接受版本内的配置锁定

**操作**：把规格、副本数、扩缩容条件、环境变量的变更需求前置到「服务设置」，不要期望改完设置就作用到已存在的版本上。

**关键配置**：版本创建时「服务设置 - 基础信息」里的规格、副本数、扩缩容条件、环境变量信息会锁定在版本中，不可以再次更改（F-063）。因此回退到一个低版本时，它携带的是该版本创建时的配置快照。

**依据**：F-063

### 步骤 9：配置流水线（可选的自动化路径）

**操作**：需要 CI 触发时配置流水线代码源与分支策略。

| 维度 | 事实 | 依据 |
|---|---|---|
| 代码源 | 目前支持 GitHub、GitLab、码云 Gitee 三种代码源 | F-064 |
| 端口 | 端口目前仅支持配置一个端口 | F-064 |
| 推送触发 | 推送触发只能全量发布现网 | F-064 |
| 私人仓库 | 业务自己搭建的私人仓库因涉及需要填写账密暂不支持 | F-064 |
| 分支策略 | 开发/测试环境建议绑定 dev 或 test 分支并可开启推送触发；预发/生产环境绑定 master/main 分支且一般不建议开启推送触发，建议采用手动触发流水线 + 灰度发布 | F-091 |

**依据**：F-064、F-091

### 步骤 10：用 CLI 部署（可选的脚本路径）

**操作**：本地安装 CLI、登录后执行部署命令。

> 以下为非官方示例代码，基于官方文档描述自行编写。
```bash
# 安装 CLI（F-069）
npm install -g @wxcloud/cli

# 登录：CLI 密钥需在「微信云托管控制台-设置-CLI 密钥」生成，生成时需要账号管理员扫码（F-069）
wxcloud login -a <你的小程序 AppID> -k <CLI 私钥>

# 部署命令为 wxcloud run:deploy [OPTIONS] [PATH]（F-068）
# 支持的参数：--releaseType=FULL|GRAY、--containerPort、--dockerfile、--targetDir、
#             --libraryImage、--envParams、--override、--noConfirm、--detach
wxcloud run:deploy --releaseType=FULL --containerPort=80 --dockerfile=Dockerfile --targetDir=./ .
```

**关键配置**：CLI 发布版本后直接 100% 接入现网（F-068）——即使传入 `--releaseType=GRAY`，精细的灰度比例调节仍然依赖控制台的发布单界面。

**依据**：F-068、F-069

## 发布前检查清单

| # | 检查项 | 通过标准 | 依据 |
|---|---|---|---|
| 1 | 发布单 | 当前服务没有其它未结单的发布单 | F-023 |
| 2 | 代码来源 | 已从 5 种首发方式中选定一种 | F-054 |
| 3 | 代码体积 | 手动上传的代码包不超过 2 MiB | F-055 |
| 4 | 监听端口 | 1~61000 的整数且不是 9100，与项目实际监听一致 | F-025、F-026 |
| 5 | 测试配置 | 已选定 OpenID 白名单或 URL 参数；后者至少 1 组 key/value | F-056 |
| 6 | 灰度粒度 | 按 10% 一档调整，不跳档 | F-057 |
| 7 | 有流量版本数 | 同时有流量的版本不超过 2 个 | F-024、F-057 |
| 8 | 结束节奏 | 先 50%，隔 3-5 分钟结束灰度 | F-066 |
| 9 | 观察窗 | 发布后留出至少 2 分钟再判定新版本健康 | F-061 |
| 10 | 回退路径 | 已明确指定一个可向前回退的低版本 | F-062 |
| 11 | 配置变更 | 规格/副本数/扩缩容/环境变量的改动已前置到服务设置 | F-063 |
| 12 | 流水线策略 | 生产环境用手动触发 + 灰度，未依赖推送触发 | F-064、F-091 |
| 13 | CLI 用法 | 已知 CLI 发布后直接 100% 接入现网 | F-068 |

## 已知边界

- **流程是单向的**：进入灰度上线后不可返回上一步，更新测试配置后也不可回退重选版本（F-059）。
- **回退只能向前**：高版本回退到低版本可行，反向不可（F-062）。
- **版本配置是快照**：规格、副本数、扩缩容条件、环境变量在版本创建时即锁定（F-063）。
- **自动链路没有灰度档位**：推送触发只能全量发布现网，CLI 发布后也直接 100% 接入现网（F-064、F-068）。
- **私人仓库不支持**：业务自建私人仓库因涉及填写账密暂不支持（F-064）。
- **副本数上限**：每个版本的实例数上限为 50 个，超过上限不会再继续扩容（F-149）。

> **勘误说明（E-001）**：官方文档不同页面口径不一致——`basic/noun.html` 称实例副本数上限最大 5，`guide/service/pipeline.html` 与 `Billing/faq.html` 称最大 50。本处采信 **50**（更具体且被计费文档复述，noun 页为旧值，F-149）。

> **勘误说明（E-002）**：官方文档不同页面口径不一致——`basic/noun.html` 与 `guide/service/pipeline.html` 称缩容到 0 的判定时长为 30min，`basic/scene.html` 称 1 小时。本处采信 **30min**（两处文档一致，且与计费文档 F-151 互相印证，F-065）。
