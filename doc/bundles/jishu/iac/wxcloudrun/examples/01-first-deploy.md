# 第一次部署：从零到可用服务

本文档是一条从零开始的部署动线：先把账号与环境准备好，再按「代码来源 → 环境变量 → 端口 → 规格 → Dockerfile → 构建 → 验证」的顺序把一个服务真正跑起来。每一步都标注了对应的编号事实，可回溯到官方文档原文。

## 目标与前置条件

**目标**：完成一次可用的云托管服务部署——服务可被调用、监听端口正确、容器规格足以承载业务、数据库等外部依赖的环境变量齐备。

**账号与平台侧前置条件**：

| 前置条件 | 说明 | 依据 |
|---|---|---|
| 已有微信小程序或公众号 | 必须先有微信小程序/公众号才可以开通微信云托管 | F-010 |
| 公众号须已认证 | 未认证的公众号不支持开通微信云托管 | F-047 |
| 账号类型在支持列表内 | 已支持的开发账号类型为微信小程序、微信小游戏、微信公众号、微信小商店、微信开放平台第三方服务商 | F-047 |
| 环境数量 | 一个「小程序/公众号」账号最多支持创建 3 个环境，仅第 1 个环境带有 3 个月免费额度 | F-022 |
| 协议前提 | 云托管调用仅支持 HTTP 协议，不支持 tcp/udp/mqtt 等其他协议 | F-070 |

## 步骤

### 步骤 1：确认账号资格并选定环境

**操作**：用目标小程序/公众号登录微信云托管控制台，确认账号类型在支持列表内；若使用公众号，确保账号已完成微信认证；创建环境时优先使用第 1 个环境，以保留 3 个月免费额度。

**关键配置**：环境是微信云托管的最大单位，包含一整套资源（包括容器、数据库等），各个环境相互独立、资源隔离，不同环境的计费和资源包结算完全独立（F-011）。

**依据**：F-010、F-047、F-022、F-011

### 步骤 2：选择入门路径（无门槛部署 / 自定义部署）

**操作**：目标是「尽快看到服务跑起来」就选无门槛部署；要自行控制代码、镜像与依赖组织方式，就选自定义部署。

**关键配置**：微信云托管提供「无门槛部署」和「自定义部署」两种快速入门方式；无门槛部署整个步骤会在 3-5 分钟完成（F-190）。

**依据**：F-190

### 步骤 3：取用代码来源与官方模板

**操作**：走自定义部署时，到官方模板仓库按语言与框架取模板；仓库位于 `https://github.com/WeixinCloud/` 命名空间，包含 springboot、express、django、thinkphp-nginx、thinkphp-apache、laravel、flask、koa、dotnet、golang 等框架与语言模板（F-188）。构建方案文档另收录 6 类模板：Nginx+HTML 分发模板、Nginx+Node 分发模板、PHP 中 SG11 扩展安装模板、jetty 应用模板、Nginx+java-openjdk 分发模板、Nginx+Node 简易 WebSocket（F-186）。

**关键配置**：手动上传代码包支持代码文件夹、代码 zip 压缩包两种方式，大小不能超过 2 MiB（F-055）。

**依据**：F-188、F-186、F-055

### 步骤 4：手动新建服务时补全数据库环境变量

**操作**：在「服务设置」中补全环境变量 `MYSQL_ADDRESS`、`MYSQL_PASSWORD`、`MYSQL_USERNAME`；如果此前用过控制台模板部署，再次部署前必须先确认这三个变量是否还在。

**关键配置**：手动新建服务并部署时若不补全这三个环境变量，会引发无法连接数据库并导致部署失败；控制台部署模板成功后这三个环境变量会消失，二次部署前需先补全（F-189）。这三个变量仅在模板部署自动开通数据库时产生（F-089）。

**依据**：F-189、F-089

### 步骤 5：在控制台填写监听端口

**操作**：新建版本时在控制台填写端口号，端口值需与项目实际监听的端口保持一致。

**关键配置**：监听端口必须为 1~61000 之间的整数且不能为 9100；微信云托管默认为 80 端口，如果没有找到则部署失败（F-025）。端口号由业务项目自行设定，系统无法自动获取，必须通过新建版本时在控制台填写来告知云托管（F-026）。一个服务只能设置一个端口，该端口不暴露给调用方，公网域名收到请求后由云托管统一网关转发到对应端口（F-027）。

**依据**：F-025、F-026、F-027

### 步骤 6：选择容器规格

**操作**：按固定的 CPU 与内存搭配表选择档位，不要随意组合；Java 服务不要压到最低档。

**关键配置**：微信云托管的容器最小规格为 0.25 核 0.5G（F-013）。内存与 CPU 搭配规则为 0.25 核配 0.5GB、0.5 核配 1GB、1 核配 2GB、2 核配 4GB、4 核配 8GB、8 核配 16GB、16 核配 32GB（F-029）。规格设置过低可能导致部署成功但频繁出现 500 错误；Java 服务相对较重，建议使用 1 核 2G 及以上规格（F-030）。

**依据**：F-013、F-029、F-030

### 步骤 7：处理 Dockerfile 的三个关键项（时区 / 依赖层 / 加速源）

**操作**：在 Dockerfile 中显式设置时区；把依赖清单与源码分层 COPY；必要时指定加速源。

**关键配置**：容器默认时区为 UTC，如需使用上海时间需在 Dockerfile 中启用时区设置命令；使用无 Dockerfile 模式部署暂不支持修改时区（F-038）。容器系统时间默认为 UTC 协调世界时间，与本地所属时区 CST（上海时间）相差 8 个小时（F-039）。时区修正需在 Dockerfile 中按基础镜像系统类型选择命令（F-040）。依赖层写法上，先 `COPY ./package*.json` 再执行 `npm install` 最后 `COPY . .`，在不变更 package*.json 时打包时间基本都在 1 秒左右（F-184）。

> 以下为非官方示例代码，基于官方文档描述自行编写。
```dockerfile
# 基础镜像为 Alpine 时的时区写法（F-040）
ENV TZ Asia/Shanghai
RUN apk add tzdata && cp /usr/share/zoneinfo/${TZ} /etc/localtime

# 基础镜像为 Debian/Ubuntu/CentOS 时的时区写法（F-040）
ENV TZ Asia/Shanghai
RUN ln -fs /usr/share/zoneinfo/${TZ} /etc/localtime && echo ${TZ} > /etc/timezone

# 依赖层与源码分层 COPY（F-184）
COPY ./package*.json ./
RUN npm install
COPY . .
```

加速源方面，微信云托管线上构建的 Docker 镜像源已经是腾讯加速源，所以不需要自己设置 registry-mirrors；Dockerfile 内可自行指定 alpine（mirrors.tencent.com）、NPM（mirrors.tencent.com/npm/）、Python（mirrors.cloud.tencent.com/pypi/simple）加速源（F-185）。

**依据**：F-038、F-039、F-040、F-184、F-185

### 步骤 8：触发构建并排查构建失败

**操作**：提交代码包等待构建完成；构建日志出现「无报错、空白」时，先查本次构建耗时。

**关键配置**：构建阶段无报错日志、空白，大概率是构建超时（> 10 分钟）；微信云托管不支持 Docker Compose（F-034）。

**依据**：F-034

### 步骤 9：确认部署结果并做首次可用性验证

**操作**：在控制台确认版本已进入线上状态、实例已拉起，再发起一次真实请求验证端口、路径与响应。

**关键配置**：云托管服务创建完成后，后台会分配给该服务一个公网域名和一个镜像仓库，每个服务一个镜像仓库，互相隔离（F-035）。服务部署发布时都会先产生 1 个容器实例，部署成功后等待半小时再缩容至 0（F-065）。

**依据**：F-035、F-065

## 部署前检查清单

| # | 检查项 | 通过标准 | 依据 |
|---|---|---|---|
| 1 | 账号资格 | 已有小程序/公众号；公众号已认证 | F-010、F-047 |
| 2 | 入门路径 | 已确定走无门槛部署还是自定义部署 | F-190 |
| 3 | 代码体积 | 手动上传的代码文件夹或 zip 不超过 2 MiB | F-055 |
| 4 | 数据库环境变量 | `MYSQL_ADDRESS`、`MYSQL_PASSWORD`、`MYSQL_USERNAME` 三项齐备 | F-189 |
| 5 | 监听端口 | 在控制台填写，落在 1~61000 且不是 9100，与项目实际端口一致 | F-025、F-026 |
| 6 | 容器规格 | 按固定搭配表选择；Java 服务不低于 1 核 2G | F-029、F-030 |
| 7 | 时区 | Dockerfile 中已按基础镜像类型写入时区设置命令 | F-038、F-040 |
| 8 | 依赖层顺序 | 依赖清单先 COPY，源码后 COPY | F-184 |
| 9 | 构建耗时 | 构建未超过 10 分钟；未使用 Docker Compose | F-034 |
| 10 | 部署后状态 | 版本为线上状态且实例已拉起 | F-065 |

## 已知边界

- **端口是单数的**：一个服务只能设置一个端口（F-027）；平台不支持一个服务开启多个监听端口，也不支持部署 Docker Compose（F-163）。
- **容器内不是存储**：微信云托管服务是计算型的，扩缩过程中数据无法持久化保存；服务挂载硬盘目前还不支持，Redis 暂未支持，可以在腾讯云或其他云厂商购买（F-164、F-181）。
- **状态型依赖要外置**：不支持用来部署数据库/Redis 等有状态服务（F-163）。
- **时区修改有前提**：使用无 Dockerfile 模式部署暂不支持修改时区（F-038）。
- **默认公网域名只能做测试**：默认公网域名性能有限制，仅能支持接口测试使用，小程序后台无法配置使用默认公网域名（F-007）。
- **构建期有静默失败面**：构建无报错日志、空白大概率是构建超时（> 10 分钟）（F-034）。
