# 计费模型与成本核算

微信云托管的账单不是「云服务器账单」的翻版：它以**环境**为维度拆分，容器、MySQL、对象存储、CDN 各有独立的计费项与独立的免费额度，而「用量是否产生」由一组与直觉不完全一致的条件决定。多数成本失控不是因为单价算错，而是因为**用错了触发条件**——例如以为「没访问就不产生流量费」，实际只要调用了对象存储就会产生 CDN 流量。

## 计费维度与结算节奏

微信云托管以环境为维度，只提供「按量计费」计费方式，按量计费方式下还可通过购买资源包进一步降低成本（F-128）。同一个账号下所有微信云托管环境共享账户余额、独立计费；资源包以环境为维度，一个资源包只能给一个环境使用，不可给多个环境使用（F-129）。

| 维度 | 规则 | 事实 |
|---|---|---|
| 计费方式 | 只提供「按量计费」，可叠加购买资源包降低成本 | F-128 |
| 结算单元 | 以环境为维度；同一账号共享账户余额、独立计费 | F-129 |
| 资源包归属 | 一个资源包只能给一个环境使用，不可给多个环境使用 | F-129 |
| 低消补齐 | 当日有资源使用且产生的计费金额不足 0.01 元时，补齐按 0.01 元收取 | F-130 |
| 结算节奏 | 系统每日进行资源消耗和结算，并在次日扣费（特殊情况可能延迟几天，但不会超过当月最后一天） | F-131 |
| 免费额度 | 首个环境赠送免费额度，有效期 3 个月，使用 80% 时推送消息通知；免费体验仅限首个环境，额外多建的环境会立刻计费 | F-132 |

## 产生用量条件：什么时候才真的计费

单价只是乘法的一半，另一半是**触发条件**。把下表逐条对照业务实际行为，才能得到接近真实的账单。

| 计费项 | 产生用量条件 | 事实 |
|---|---|---|
| CPU（核×小时）、内存（GiB×小时） | 环境中任意服务下任意版本，**实例数量不为 0**；1（核×小时）= 60（核×分钟）= 3600（核×秒） | F-138 |
| 流量（GB） | 环境中任意服务通过公网域名访问，或任意服务访问过公网；**只通过 callcontainer 访问服务不产生用量** | F-139 |
| 构建（分钟） | 发布服务时采用了「本地代码/代码库拉取」方式；使用「镜像拉取」方式无构建用量 | F-140 |
| MySQL 数据库算力 | 对数据库进行了任意读写/运算操作，或通过任意管理界面登录访问过数据库；1 CCU 等价于 1 核 2GB 的计算能力 | F-141 |
| MySQL 数据库存储（GB*小时） | 「开通了 MySQL 未注销」时**持续产生**用量；无论是否存有业务数据，系统表都至少消耗 28M 存储空间 | F-142 |
| 对象存储下载/上传操作次数 | 无论请求成功或失败均计算次数，不足一万次按一万次计算 | F-143 |
| CDN 流量 | 对象存储默认开启 CDN 加速，**只要调用即会产生 CDN 流量** | F-143 |
| 容器（无版本） | 只创建服务没有创建版本不会产生费用 | F-151 |
| 容器缩容到 0 | 最小副本数为 0 且连续半小时无访问触发缩容到 0，不产生任何容器相关用量和费用 | F-151 |

一个易被忽略的换算是：实例消耗的资源量为**规格乘以运行时间**（精确到秒）——0.25 核 0.5GB 实例运行 4 小时消耗 CPU 1（核*小时）、内存 2（GB*小时）；1 核 2GB 实例运行 1 小时与两个 0.5 核 1GB 实例运行 1 小时消耗的资源量完全相同（F-148）。也就是说，**拆分实例不省算力，但也不额外加价**，加价的是实例总数与运行时间。

## 抵扣顺序与资源包

按量计费结算时的抵扣顺序为「先抵扣免费资源，再进行资源包的用量抵扣，抵扣完成后再计算按量计费费用」；当有多个资源包时可叠加使用，一个资源包中某个指标用量耗尽后其他指标仍可继续抵扣（F-145）。

```mermaid
flowchart LR
    A[当期用量] --> B[免费额度<br/>仅首个环境·3个月]
    B -->|有余额| C[资源包抵扣<br/>一包一环境·不可转移]
    B -->|耗尽| C
    C -->|有余额| D[按量计费<br/>刊例价]
    C -->|耗尽| D
    D --> E[次日扣费<br/>不足 0.01 元补齐]
```

| 规则 | 内容 | 事实 |
|---|---|---|
| 抵扣顺序 | 免费资源 → 资源包用量抵扣 → 按量计费费用 | F-145 |
| 多包叠加 | 多个资源包可叠加使用；某指标用量耗尽后其他指标仍可继续抵扣 | F-145 |
| 资源包性质 | 均为一次性购买，不可续费，可反复购买 | F-146 |
| 转移限制 | 为环境级别购买，不支持转移到其他环境；到期后不可再用于抵扣按量计费用量 | F-146 |
| 服务资源包内容 | 容器（服务）CPU 使用量 360（核*小时）、内存使用量 720（GB*小时）、构建时长 60 分钟、公网流量 10GB | F-147 |
| 服务资源包价格 | 有效时长 3 个月，原价 53.84 元，售价 36 元 | F-147 |

> **勘误采信（E-009 · 资源包场景剩余量）**：官方文档资源包抵扣示例章节的正文与同页举例算术不一致——正文称「CPU 12 核*小时由 B 抵扣后剩余 702 核*小时」，而同页举例写出的算式是 `720 − 12 = 708`（源文档未说明该 720 对应哪一个资源包额度）。本处采信源文档正文原值 **702 核*小时**，并标注**源文档算术存疑**：引用该场景剩余量时按源文档原值表述并保留此标注，不以推算值 708 替代原文。

## 数据库的开关效应与固定成本

| 行为 | 计费后果 | 事实 |
|---|---|---|
| 开通数据库 | 立即创建 3 个系统数据库用于创建系统表，预计占用数据库 28M 内存，每天都会产生微量的数据库存储费用；如无需使用数据库请及时销毁 | F-152 |
| 自动暂停 | 开启数据库自动暂停后，连续 10 分钟内没有任何读写和运算操作即进入暂停状态 | F-150 |
| 暂停中的存储 | 暂停状态不会产生数据库算力资源用量，但**还会有数据库存储用量** | F-150 |
| 实例上限 | 每个版本的实例数上限为 50 个，超过上限不会再继续扩容 | F-149 |
| 环境实例上限 | 单个环境下总实例数量最大支持 28 个，不可特殊申请 | F-020 |
| 有状态服务 | 不支持用来部署数据库/Redis 等有状态服务（Redis 可在腾讯云或其他云厂商购买） | F-163 |

换言之，数据库的「算力」可以靠自动暂停压到接近零，但「存储」一旦开通就持续计费——这是典型的**沉没型固定成本**。

## 欠费分级处置

欠费并非「立刻停机」，而是分三级逐步加码，且每一级的成本行为不同：

| 欠费时长 | 平台处置 | 事实 |
|---|---|---|
| ≤ 12 小时 | 正常使用且继续扣费 | F-153 |
| > 12 小时且 < 7 天 | 所有环境停服；数据库存储、对象存储容量、静态资源存储容量继续扣费，数据保留 | F-153 |
| > 7 天 | 资源销毁无法找回，账号下所有环境被删除 | F-153 |

与之并行的是两条「非欠费但同样致命」的规则：账号欠费时所有环境都将被冻结，欠费超过 7 天所有环境都将被删除且无法恢复，环境删除后环境内所有资源将被释放、不可恢复（F-045）；环境在 30 天内未产生任何请求调用即被冻结，冻结后云服务资源无法使用、线上业务停服，冻结时间超过 180 天系统自动销毁并删除环境且不支持恢复（F-044）。另需注意，有免费额度的环境删除后再次创建的环境不会再有免费额度（F-045）。

## 成本核算示例

官方文档给出的三个算例可作为量级校验：工具类小程序每日 8:00～24:00 维持 1 个 0.25 核 0.5GB 实例，每月 CPU 120（核*小时）、内存 240（GB*小时），每月费用总计 14.28 元（F-154）；活动类小程序每月费用总计 28.3545 元（F-155）；社区论坛类小程序每日费用总计 4.7264 元、每月费用总计 141.792 元（F-155）。

需要特别标注的是口径：这些费用预估均基于刊例价，**不考虑折扣、特惠活动、资源包、优惠券等**，文档称可理解为理论上的最高价（F-156）。因此算例适合做量级对标，不适合做预算承诺。

## 洞察

### 洞察 A：计费的第一性原理是「声明量」而非「使用量」

- **陈述**：容器费用完全由声明的规格与实例数量决定，与实际 CPU 利用率无关；弹性伸缩只改变实例数量，改变的是账单而不是单价。
- **证据**：F-138（CPU 与内存的产生用量条件是「环境中任意服务下任意版本，实例数量不为 0」）、F-148（实例消耗的资源量为规格乘以运行时间，1 核 2GB 运行 1 小时与两个 0.5 核 1GB 运行 1 小时消耗的资源量完全相同）、F-149（每个版本实例数上限 50 个，超过不再扩容）、F-020（单环境总实例上限 28 个，不可特殊申请）。
- **反常识**：直觉上「用得少就少付钱」——但计费口径是「声明的规格 × 实例数 × 时间」，空闲但未缩容的实例照样全额计费；只有触发缩容到 0 才归零（F-151）。
- **行动**：把「最小副本数」当作成本开关而不是性能开关来管理：低频服务设 0 并接受半小时内缩容的冷启动代价；高负载服务按峰值规格选型而不是按均值；建立「服务 × 最小副本数」的清单并定期复核，避免测试环境常驻实例长期计费。

### 洞察 B：免费额度与资源包都被环境切碎，跨环境无法调剂

- **陈述**：免费额度只赠首环境且有 3 个月期限，资源包一包一环境且不可转移，因此「账号下共享余额」这个共享度并不能给成本带来弹性。
- **证据**：F-129（同一账号下所有环境共享账户余额、独立计费；一个资源包只能给一个环境使用）、F-132（免费额度仅限首个环境，有效期 3 个月，使用 80% 时推送通知，额外多建的环境会立刻计费）、F-146（资源包为环境级别购买，不支持转移到其他环境，到期后不可再抵扣）、F-147（服务资源包 360（核*小时）/720（GB*小时）/60 分钟/10GB，3 个月有效，原价 53.84 元，售价 36 元）。
- **反常识**：直觉上「资源包是预付折扣，买了就等于账户余额」——实际它锁死在单个环境，环境销毁或换环境时钱就沉了；而免费额度虽然只给首环境，却是所有额度中唯一会主动提醒的（80% 推送通知）。
- **行动**：采购资源包前先确认目标环境的存续期（结合 F-044 的 30 天冻结、180 天销毁规则）与规格预估，把包买在长期存续的环境上；对首环境的 3 个月免费额度设置 80% 阈值的监控响应，把它当成一次性启动预算而不是长期折扣。

### 洞察 C：真实成本大头在「沉默的固定成本」和「计次与流量叠加」

- **陈述**：数据库开通即产生每日微量存储费、对象存储一调用即产生 CDN 流量，这些在业务看板上几乎不可见的成本，累加起来常常超过容器算力本身。
- **证据**：F-142（MySQL 存储在「开通了 MySQL 未注销」时持续产生用量，系统表至少消耗 28M）、F-152（开通数据库即创建 3 个系统数据库、占用 28M 内存、每天产生微量数据库存储费用，如无需使用请及时销毁）、F-150（自动暂停只停算力不停存储）、F-143（下载/上传操作次数无论成功失败均计数，不足一万次按一万次计算；对象存储默认开启 CDN 加速，只要调用即产生 CDN 流量）、F-136（CDN 流量 0.18 元/GB、CDN 回源流量 0.15 元/GB，静态资源存储与流量的免费额度为「无」）。
- **反常识**：直觉上「存储便宜、不访问就几乎不花钱」——但存储按开通时间连续计费、流量按「只要调用」触发，且静态资源流量一项完全没有免费额度兜底。
- **行动**：把「数据库不用就销毁」写进资源台账，而不是依赖自动暂停；对象存储调用前评估是否会触发 CDN 流量；对静态资源流量单独做预算科目（它既无免费额度，又叠加在 CDN 流量之上）。

### 洞察 D：欠费与闲置是两条独立的「静默死亡」通道

- **陈述**：成本失控的极端形态不是账单变高，而是环境在无人察觉的情况下停服或被删除，而其中相当一部分仍继续扣费。
- **证据**：F-153（欠费 > 12 小时 < 7 天：所有环境停服，但数据库存储、对象存储容量、静态资源存储容量继续扣费，数据保留；> 7 天资源销毁无法找回，账号下所有环境被删除）、F-045（欠费超过 7 天所有环境删除且无法恢复，环境内资源释放不可恢复）、F-044（30 天无任何请求调用即被冻结，冻结后线上业务停服，冻结超过 180 天自动销毁且不支持恢复）。
- **反常识**：直觉上「停了就不花钱了」——实际停服阶段存储类资源照扣，而冻结和销毁的时间窗完全由平台单方设定，业务方没有「主动保活」以外的干预手段。
- **行动**：把环境清单（每个环境是否有业务、最近一次请求时间）纳入常态化巡检；对有业务价值的环境配置资源到期与欠费告警，在腾讯云侧设置余额告警，并按 F-153 的三级时点（12 小时 / 7 天）提前触发处置动作；停用环境时走「销毁」而不是「闲置」，因为闲置既可能触发冻结，也仍占存储。
