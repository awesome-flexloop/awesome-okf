# CSS 生成流水线

`generate_css.py` 是双桥架构中第一座桥的核心——它在构建时将 Python 端的 `JupyterStyle` 类"编译"为静态 CSS 文件。本文档深入解析这条流水线的每个环节。

## 流水线总览

```
JupyterStyle 类（Python 字典）
    │
    ▼
HtmlFormatter(style=JupyterStyle)
    │  Pygments 内部将 styles 字典转换为 CSS 规则
    ▼
formatter.get_style_defs('.highlight')
    │  生成完整 CSS 字符串（含 .highlight 前缀选择器）
    ▼
filter(line.startswith('.highlight'))
    │  过滤非 .highlight 开头的行
    ▼
prefix + highlight_css
    │  添加版权注释头部
    ▼
style/base.css（写入文件）
```

## 第一步：创建 HtmlFormatter

```python
from pygments.formatters import HtmlFormatter
from jupyterlab_pygments import JupyterStyle

formatter = HtmlFormatter(style=JupyterStyle)
```

`HtmlFormatter` 是 Pygments 内置的 HTML 输出格式化器。当传入 `style=JupyterStyle` 时：

1. HtmlFormatter 内部实例化 JupyterStyle
2. 遍历 Style 类的 `styles` 字典
3. 将每个 token→CSS 映射记录到内部状态
4. 准备好根据这些样式生成 CSS 和 HTML

HtmlFormatter 支持多种选项（通过构造函数参数），generate_css.py 使用默认选项：
- CSS class 前缀：`'.highlight'`（通过 `get_style_defs()` 参数指定）
- 不添加行号样式
- 不使用自定义 CSS class

## 第二步：生成 CSS 定义

```python
css = formatter.get_style_defs('.highlight')
```

`get_style_defs(selector)` 是 HtmlFormatter 的关键方法，它：

1. 遍历 Style 类的 `styles` 字典
2. 为每个非空的 token 映射生成一条 CSS 规则
3. 选择器格式为 `{selector} .{css_class}`
4. 生成 `background-color`（来自 `background_color`）和 `highlight` 样式
5. 返回完整的 CSS 字符串

### get_style_defs 输出示例

对于 JupyterStyle，`get_style_defs('.highlight')` 的输出大致如下（示意）：

```css
pre { line-height: 125%; }
td.linenos .normal { color: inherit; background-color: transparent; padding-left: 5px; padding-right: 5px; }
span.linenos { color: inherit; background-color: transparent; padding-left: 5px; padding-right: 5px; }
/* ... 更多行号和预格式化样式 ... */
.highlight { background: var(--jp-cell-editor-background); }
.highlight .c { color: var(--jp-mirror-editor-comment-color); font-style: italic }
.highlight .k { color: var(--jp-mirror-editor-keyword-color); font-weight: bold }
.highlight .o { color: var(--jp-mirror-editor-operator-color); font-weight: bold }
.highlight .m { color: var(--jp-mirror-editor-number-color) }
.highlight .s { color: var(--jp-mirror-editor-string-color) }
.highlight .p { color: var(--jp-mirror-editor-punctuation-color) }
.highlight .err { color: var(--jp-mirror-editor-error-color) }
/* ... 其他 token 类型 ... */
```

**注意**：输出包含很多非 `.highlight` 开头的规则，如 `pre`、`td.linenos`、`span.linenos` 等——这些是 HtmlFormatter 为了完整的 HTML 代码块渲染而生成的默认样式。

## 第三步：过滤 .highlight 规则

```python
highlight_css = '\n'.join(filter(
    lambda line: line.startswith('.highlight'), css.splitlines()
))
```

这一步将 CSS 字符串按行分割，只保留以 `.highlight` 开头的行。为什么需要这一步？

1. **关注点分离**：jupyterlab_pygments 只负责语法高亮颜色，不控制 `pre`、行号等布局样式
2. **避免样式冲突**：JupyterLab 有自己的 `pre`、代码单元格样式，如果 Pygments 也设置这些样式可能导致冲突
3. **精简输出**：只保留实际需要的 CSS 规则，减少 bundle 体积

过滤后的 CSS 只包含：

```css
.highlight { background: var(--jp-cell-editor-background); }
.highlight .c { color: var(--jp-mirror-editor-comment-color); font-style: italic }
.highlight .k { color: var(--jp-mirror-editor-keyword-color); font-weight: bold }
.highlight .o { color: var(--jp-mirror-editor-operator-color); font-weight: bold }
/* ... 仅 .highlight 开头的规则 ... */
```

### 过滤逻辑的局限性

简单的 `startswith('.highlight')` 过滤有一个潜在问题：如果 CSS 规则跨行（如多行选择器或多行声明），可能误过滤。但 Pygments 的 HtmlFormatter 生成的 CSS 是单行规则（每条规则一行），所以这个简单过滤是安全的。

## 第四步：添加版权前缀

```python
prefix = """
/*-----------------------------------------------------------------------------
| Copyright (c) Jupyter Development Team.
| Distributed under the terms of the Modified BSD License.
|----------------------------------------------------------------------------*/
/* This file was auto-generated by generate_css.py in jupyterlab_pygments */
"""
```

版权头部有两个作用：
1. **法律声明**：标明代码的 BSD 许可证
2. **自动生成标记**：明确告知开发者此文件是自动生成的，不应手动编辑——修改应在 `style.py` 中进行

## 第五步：写入文件

```python
here = Path(__file__).parent
style_file = here / "style" / "base.css"
style_file.write_text("\n".join((prefix, highlight_css)))
```

- 使用 `pathlib.Path` 进行跨平台路径操作
- 输出路径相对于脚本位置：`style/base.css`
- 将版权前缀和过滤后的 CSS 拼接写入
- 使用 `"\n".join()` 确保前缀和 CSS 之间有换行符分隔

## base.css 在构建链中的位置

生成的 `base.css` 不是最终产物，它在构建链中被进一步处理：

```
generate_css.py → style/base.css
                      │
                      ▼
               style/index.css: @import url('base.css')
                      │
                      ▼
               style/index.js: import './base.css'
                      │
                      ▼  (webpack 打包)
               labextension/static/style.js
                      │
                      ▼  (wheel 打包)
               share/jupyter/labextensions/jupyterlab_pygments/static/style.js
                      │
                      ▼  (JupyterLab 加载)
               浏览器中 CSS 注入生效
```

### 为什么使用间接引入（index.css → base.css）？

`style/index.css` 只包含 `@import url('base.css')` 一行。这种间接层级看起来多余，但有其设计理由：

1. **生成文件与稳定入口分离**：`base.css` 是自动生成的（可能被覆盖），`index.css` 是稳定的入口点，不会被生成脚本修改
2. **构建工具约定**：JupyterLab 扩展系统期望 CSS 入口是 `style/index.css`，而实际内容可能由多个 CSS 文件组成
3. **扩展性**：未来如果需要添加非生成的自定义 CSS，可以在 `index.css` 中添加更多 `@import`，不影响生成流程

### 为什么还需要 style/index.js？

`style/index.js` 只包含 `import './base.css'`。这是 webpack 等现代 JS 打包工具的要求：CSS 必须通过 JS 模块的 `import` 语句引入才能被打包工具处理。JupyterLab 构建系统使用 webpack，通过 `package.json` 的 `styleModule` 字段识别 JS 样式入口。

## 重新生成 CSS 的场景

在以下情况下需要重新运行 `python generate_css.py`：

1. **修改了 style.py 中的样式映射**：修改了 `styles` 字典中任何 token 的 CSS 值
2. **修改了 background_color 或 highlight_color**：改变了背景色
3. **升级了 Pygments 版本**：新版本可能生成不同格式的 CSS
4. **添加了新的 token 映射**：启用了之前注释掉的子 token 类型

修改后，需要完整重建 labextension：

```bash
python generate_css.py      # 重新生成 base.css
jlpm build:lib              # 重新编译 TypeScript
jlpm build:labextension:dev # 重新构建 labextension
```
