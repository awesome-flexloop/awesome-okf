# 02 · 工作模型：三种时间尺度

> 博文的核心洞察之一：**任务、周期、模块是三种不同的时间尺度**，Plane 把它们固化成三个对象，而不是靠约定和标签去凑（F-015 ~ F-021）。

## 1. 三层对照

| 层 | 对象 | 时间尺度 | 回答的问题 | 关键机制 |
|----|------|---------|-----------|---------|
| 微观 | **Work Item** | 单件事 | 这件事现在什么状态？ | 富文本、附件、子任务、关联、负责人、标签、优先级（F-015） |
| 中观 | **Cycle** | 这两周 | 这个迭代完成得怎么样？ | 燃尽图、完成率自动计算，未完项可结转（F-018、F-019） |
| 宏观 | **Module** | 整条线 | 这个大版本走到哪了？ | 跨周期聚合，进度条与状态分布（F-020、F-021） |

```text
Module（一次大版本重构，横跨 3–4 个周期）
  ├── Cycle #1（两周）── Work Item × N
  ├── Cycle #2（两周）── Work Item × N
  └── Cycle #3（两周）── Work Item × N（含上期结转）
```

## 2. Work Item：最小工作单位

博文列出的属性（F-015、F-016、F-017）：

- 富文本编辑器，**认 Markdown**，代码块与图片可直接粘贴
- 附件、子任务、任务间关联（blocking / blocked by / duplicate / relates-to）
- 负责人、标签、优先级
- 评论区可 **@ 同事**
- **状态列可自定义**：默认 Todo / In Progress / Done 三档不够用时可自建（如测试的「待验证」）

> 官方侧补充：Work Item 支持**多负责人**、故事点与工时估算、开始/截止日期区间、父子层级（Sub-work items）。

## 3. Cycle：这两周

- 对应 Scrum 的 Sprint（F-018）
- 建一个两周周期，把要做的事拖进去
- **燃尽图与完成率自动算**，不需要手工统计
- 收尾未完成的，直接转到下一期（F-019）
- 官方补充：周期时长**可逐周期修改**（这一期两周、下一期四周），可多项目并行多个活跃周期

## 4. Module：整条线

- 管**跨周期**的工作：一次大版本重构往往横跨三四个周期（F-020）
- 相关任务收进同一个模块，**进度条与状态分布自动生成**（F-021）
- 想知道整体走到哪，看模块即可，不必逐个周期翻

## 5. 为什么值得单独讲这三层

博文的判断（**作者观点**）是：三层分工清楚后，「一层管单件事，一层管这两周，一层管整条线走到哪」，**固化成三个对象，就不必靠约定和标签去凑**（F-020 语境）。

这个判断在工程上成立的原因：标签与约定是**软约束**（可被遗忘、可被绕过），而对象层级是**硬结构**（进度必须由子项汇总）。代价是团队需要接受这套模型，而不是沿用自己原有的标签体系。

## 6. 已知边界

- 「状态默认三档」与「可自建状态」来自博文（F-017），官方 README 未逐项列状态模型 → 属**官方功能面的一部分但未一手逐字核到**，采信前可查产品文档
