# 05 · 选型矩阵与适用边界

> 本节含**作者观点**与**本包独立推导的选型维度**两类内容，已分别标注，请勿把前者当作官方结论。

## 1. 谁适合 / 谁不适合（博文口径）

博文给出的适配团队（**作者观点**，F-055）：

| 团队类型 | 判断 | 理由（博文口径） |
|---------|------|----------------|
| 中小研发团队 | ✅ 推荐 | 想跑完整敏捷流程，又不愿耗在 Jira 配置上；开源项目里它最贴近商业产品 |
| 在意数据归属的团队 | ✅ 推荐 | 整套装在自己服务器，数据攥在自己手里 |
| 预算紧张的初创团队 | ✅ 推荐 | 社区版免费、人数不限、功能够用 |
| 市场/运营等非技术团队 | ✅ 可用 | 看板与日历排期，界面对非技术同事友好 |
| 需要 SSO / 审计日志的团队 | 💰 付费 | 这些能力在商用版付费档，按座席收费（F-050 / V23） |
| 打算二开再商用的团队 | ⚠️ 受限 | AGPL 3.0 传染条款（F-051 / V21） |

## 2. 与同类工具的取舍维度

博文的对照是**作者观点**（F-053、F-054），下表把主观评价拆成可自行验证的客观维度：

| 维度 | Plane | Jira | Linear | Redmine / OpenProject |
|------|-------|------|--------|----------------------|
| 开源可自审 | ✅ AGPL v3.0 | ❌（DC 版可自托管但非开源） | ❌ 闭源 | ✅ 开源 |
| 数据留在自有服务器 | ✅ | ⚠️ 仅 Data Center | ❌ | ✅ |
| 配置成本（博文判断） | 低 | **高**（F-054） | 低 | 中高 |
| 交互代际（博文判断） | 现代 | 现代 | 现代 | **停留在上一时代**（F-053） |
| 计费模式 | 社区版免费 / 商用按座席 | 按座席 | 按人头（F-054） | 社区版免费 |

> 三个「判断」行均为**作者观点**，非官方对比数据。做正式选型时，官方对比文（plane.so/blog）属**厂商自宣信源**，同样需要按自己的真实流程跑一遍验证。

## 3. 本包推导的六步自检

1. **数据主权是不是硬约束？**（金融/医疗/政府/合规）→ 是，自托管几乎是唯一解
2. **能不能接受 AGPL？**（是否二开再商用）→ 不能，走 Commercial 授权或换栈
3. **人数与付费能力需求？** → ≤12 且只要免费档能力：Community；否则 Commercial
4. **是否需要完全离线？** → 是：Airgapped（注意企业档与商务渠道）
5. **有没有人运维？** → 自托管要自己承担备份、升级、监控、证书、容量、灾备
6. **迁移成本评估？** → 官方提供 Jira / Asana / Linear / Notion / ClickUp / CSV 导入器，但工作流重建与团队再培训是主要成本

## 4. 六条可信边界

1. **无一手实测**：博文作者未部署（F-052），本包亦未实测 → 资源占用、升级平滑度、故障率无数据
2. **版本与集成是时点快照**：Star、组件版本、集成清单均为 2026-10-13 值，上游发版即变化
3. **Intake 机制未核到官方一手页**（V26）
4. **Kubernetes 三条参数仅博文单源**（V27）
5. **座席与最低购买门槛可能变动**：2026-04 曾拟设门槛后延期，采购前须确认当期条款
6. **组件版本已漂移**：Postgres 15.5→15.7、Redis→Valkey 7.2、MinIO 镜像切换；博文数字不可直接照用
