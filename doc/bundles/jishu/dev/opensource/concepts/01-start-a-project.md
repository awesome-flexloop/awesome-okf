# 开启一个开源项目

> **时点说明**：本文基于 2020 年前后教程（简书连载《开源的世界》第 1.2 篇《1.2 开启一个开源项目》）整理，内容源自 GitHub 开源指南（opensource.guide）。开源的项目准备方法论（许可证/README/贡献指南/行为规范）长期稳定。

## 开源的含义（F-248）

当一个项目被开源，意味着**任何人都可以出于任何目的查看、使用、修改和分发你的项目**。这些权限通过[开源许可](https://opensource.org/licenses)强制实施。开源降低了事物被采纳的障碍，允许想法迅速传播。

## 为什么开源一个项目（F-249）

- **协作**：开源项目可以接受世界各地人们的修改。例如 Exercism 是一个拥有 350 多个贡献者的练习平台
- **采用和重组**：任何人几乎可以出于任何目的使用开源项目，甚至用它构建其他东西。例如 WordPress 派生自一个名为 b2 的现有项目
- **透明度**：任何人都可以检查开源项目是否有错误或不一致。透明度对保加利亚/美国政府、银行或医疗保健等受监管行业以及 Let's Encrypt 等安全软件都很重要

开源并不仅限于软件，可以开源任何事物，从数据集到书本。

## 开源不是"免费"的同义词（F-250）

"免费"只是开源的总体价值的一个副产品。开源许可证要求任何人可以几乎出于任何目的使用、修改和共享项目，因此大多数开源项目是免费的；但**"免费"不是开源定义的一部分**。有些方法可以通过**双重许可或有限功能**间接地为开源项目收费，同时仍然遵守开源的官方定义。

## 每个项目应包括的文档（F-251）

一般来说，如果乐意他人对你工作进行查看和反馈，便可以选择开源项目。每个项目都应包括以下文档：

- Open source license（开源许可证）
- README（自述文件）
- Contributing guidelines（贡献指南）
- Code of conduct（行为规范）

如果项目在 GitHub 上，将这些文件放在根目录并使用推荐的文件名，有助于 GitHub 识别并自动将其显示给读者。

## 选择一个许可证（F-252）

开源许可证保证其他人可以使用、复制、修改和贡献项目而不会产生不良后果，同时保护作者免受繁琐的法律影响。**启动开源项目时，请务必包含许可证。**

- MIT、Apache 2.0 和 GPLv3 都是非常流行的开源许可证
- 可以通过 choosealicense.com 选择其他选项
- 在 GitHub 上创建新项目时可以选择许可证，包含开源许可证将使项目成为开源

## 撰写 README（F-253）

README（`README.md`）不仅仅用于说明如何使用项目，还可以解释项目为什么重要。在自述文件中尝试回答以下问题：

- **What**：这个项目做什么？
- **Why**：为什么这个项目有用？
- **How**：如何开始？
- **Help**：如果需要，我可以在哪里获得更多的帮助？
- **Who**：谁维护和参与项目？

灵感来源：@18F 的"让 README 可读"与 @PurpleBooth 的 README 模板（需要梯子）。当在根目录中包含 README 文件时，GitHub 会自动将其显示在存储库的主页上；也可放在仓库根目录、`docs` 或隐藏的 `.github` 目录中。

## 编写贡献者指南（F-254）

CONTRIBUTING 文件告诉受众如何参与项目，可以包括：如何提交错误报告（尝试使用 issue 和 pull request 模板）、如何建议新功能、如何配置环境和运行测试。除了技术细节，还可传达对贡献的期待：寻求的贡献类型、项目路线图或版本、贡献者应如何与你联系、创建良好议题或拉取请求的步骤、指向外部文档或行为准则的链接、社区和行为预期。

使用热情友好的语气并提供具体的贡献建议（例如编写文档或搭建网站）可以大大提高新人的参与度。项目初期贡献文件可以很简单，随时间推移再添加常见问题。

模板参考：@nayafia 的贡献指南模板、@mozilla 的"如何构建 CONTRIBUTION.md"。在 README 中链接 CONTRIBUTING，贡献者创建 issue 或开启 pull request 时 GitHub 会自动链接该文件。

行为规范（Code of conduct）有助于为项目参与者的行为设定基本规则，促进健康、有建设性的社区行为。《贡献者公约》（contributor-covenant.org）是行之有效的行为规范，已被超过 4000 个开源项目使用（包括 Kubernetes、Rails、Swift）。将文本粘贴到根目录的 CODE_OF_CONDUCT 文件中，并从 README 链接它。

## 项目命名与品牌（F-255）

品牌不仅是 logo 或易记的项目名，还关于如何谈论项目以及想传递的信息。

- 选择容易记住、有创意、能表达项目用意的名字。例如：Sentry 监控应用程序的崩溃报告；Thin 是一个简单快速的 Ruby web 服务器；node-fetch 将 `window.fetch` 添加到了 Node.js
- 避免名字冲突：查看是否有同名的开源项目，尤其是相同语言或生态；确保项目名没有侵权（可查阅 WIPO 全球品牌数据库），如有侵权可能被要求下架或采取法律措施
- 写作风格与编码风格也是品牌的一部分：使用热情、通俗易懂的语言，使用简单语言（读者可能英语不是很好）；项目早期是建立先例的机会

## Pre-launch 检查清单（F-255）

发布前检查清单涵盖三个方面：

- **文档**：指定开源协议；有基础文档（README、CONTRIBUTING、CODE_OF_CONDUCT）；易记且不冲突、不侵权的项目名；最新的 issue 队列，组织和标记清除的 issues
- **代码**：一致的代码风格和明确的名字；注释清晰的代码，记录意图和边缘案例；在修改历史、issues 或 pull requests 中没有敏感信息（如密码等）
- **人**：个人需告知法律部门/理解公司开源政策与 IP；公司或组织需告知法律部门、有营销计划、有人管理社区互动（回复 issues、检查和合并 pull requests）、至少有两人有管理访问权限
