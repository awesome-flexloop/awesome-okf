# 06 · 安全默认

> 核心判断：dws 的安全不是「加一个 `--confirm` 参数」，而是把**副作用声明前置到命令契约**，再用预览、确认、审计三段式把它落到执行链上。

## 1. 三段式流程

```text
① 预览（--dry-run）        ② 确认（confirmation）        ③ 审计（audit）
   发出什么请求？             这一步是否被允许？             谁在何时做了什么？
   改哪些字段？               风险等级是否超阈值？           记录是否可验未被篡改？
```

对应到契约字段（F-021）：

| 字段 | 回答 | 消费者 |
|------|------|--------|
| effect | 这是读、写、删除还是发送？ | dry-run 说明、风险提示 |
| risk | 风险多高？ | 确认门阈值 |
| confirmation | 是否必须人工确认？ | 交互层 |
| idempotency | 重试会不会重复副作用？ | 重试策略 |

> **洞察**：把安全判断从「业务代码里的 if」搬到「命令元数据」，最大的变化是**可预演**。dry-run 不需要真的执行，就能根据 effect 拼出请求；这在 Agent 场景里尤其重要——人类可以在副作用发生前看到意图。

## 2. 预览：看得见才敢放行

```bash
dws <命令> ... --dry-run
```

（F-047）

dry-run 应展示：

- 最终请求方法、路径与关键字段（敏感值脱敏）；
- 将被修改的资源标识；
- 因约束推导而自动补全的参数；
- 若执行，预计的 effect 与 risk。

**纪律**：dry-run 不等于「无网络」。它可能仍需要读取身份与元数据来确定账号归属，因此不要在没有登录态的环境里指望它完全离线。

## 3. 确认门：默认拦，显式放

| 场景 | 默认行为 | 跳过方式 |
|------|---------|---------|
| 读操作 | 直接执行 | — |
| 写操作 | 要求确认 | `--yes` |
| 高风险/删除类 | 要求确认并展示风险摘要 | `--yes`（不建议脚本化） |

（F-048）

确认提示由安全元数据生成（F-021），不是各命令手写。这带来的直接后果是：**新增命令无法「忘记」加确认**，因为 risk 字段必填。

## 4. 审计：JSONL 哈希链

审计记录以 JSONL 落盘，并以哈希链串联（F-049）。

它能回答三个问题：

1. **谁**：账号/组织/Agent 标识（F-059）；
2. **做了什么**：规范命令路径 + 关键参数摘要；
3. **能否验证**：相邻记录哈希相连，单条篡改会导致后续校验失败。

它不能回答的：业务数据的最终正确性。审计证明「发生过这个调用」，不证明「调用结果符合预期」。不要把审计当业务对账。

## 5. 出站边界

| 控制 | 默认 | 可调 |
|------|------|------|
| 域名白名单 | `*.dingtalk.com` | `DWS_TRUSTED_DOMAINS` 扩展 |
| 传输协议 | 仅 HTTPS | `DWS_ALLOW_HTTP_ENDPOINTS=1` 且仅回环 |
| raw API | 受同一白名单约束 | 不因「逃生舱」而放宽 |

（F-050、F-051）

这三条共同限制了「凭据被诱导外发」的风险：即使参数被注入一个恶意 URL，请求也会在域名校验处失败。

## 6. 输入防御

| 类别 | 攻击形态 | 防御 |
|------|---------|------|
| 路径穿越 | `../../etc/passwd` | 规范化后校验根目录 |
| 头部注入 | 参数中含 CRLF | 拒绝换行与控制字符 |
| Unicode 伪装 | 同形字符伪造命令/域名 | 规范化与白名单比对 |
| 文件注入歧义 | `@` 前缀误判 | 严格前缀规则（F-045） |

（F-052、F-045）

## 7. 给 Agent 的三条硬规则

1. **写操作先 dry-run**，把预览结果作为确认依据，而不是直接 `--yes`。
2. **不要给 Agent 开放 raw api**：它不在 Agent Schema 中（F-060），也不参与安全元数据校验。
3. **用退出码而不是文本判断失败**：4 需要人类介入，5 需要补权限，二者都不应自动重试（F-043）。

## 8. 边界声明

本束只陈述机制，**不构成任何合规认证结论**。审计日志的留存周期、加密方式、访问控制策略需由使用方按自身合规要求另行设计。
