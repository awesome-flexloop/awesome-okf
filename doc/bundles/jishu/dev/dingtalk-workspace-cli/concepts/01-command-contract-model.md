# 01 · 声明式命令契约

> 核心判断：dws 的可维护性不来自「代码写得整齐」，而来自**每条命令都必须交出一份完整契约**，缺一项就编译不过或测试不过（F-023）。

## 1. 一条命令由什么构成

`corecmd.Spec` 把命令拆成七个面，每个面都有明确的消费者：

| 面 | 内容 | 谁消费 |
|----|------|--------|
| 身份 | 规范路径、产品、资源、动词、别名 | CLI 路由、Schema 索引 |
| Cobra 元数据 | 短描述、长描述、示例 | `--help` |
| 参数 | `FlagSpec` 列表（名称、类型、必填、默认、枚举） | 参数解析、Schema |
| 约束 | 互斥、依赖、至少一个、只能一个 | 执行前校验 |
| 安全 | effect、risk、confirmation、idempotency | dry-run、确认门、审计 |
| 契约 | 产品级声明与最终契约 | 生成校验、发布 |
| 执行体 | 静态管线 / raw 分发 / 手写 Go | 实际发请求 |

（F-017、F-021、F-022、F-032）

## 2. 参数回退链：一个值从哪里来

`FlagSpec` 的取值优先级是固定的五级：

```text
CLI flag  >  InputSchema 属性  >  Cobra flag  >  别名  >  默认值
```

（F-019）

这条链解决了一个具体问题：同一个参数在「模型生成」「用户手敲」「脚本拼装」三种场景下名字可能不同，回退链让它们落到同一字段，而不是各写一套解析。代价是**排错时必须知道当前值来自哪一级**——因此 `--dry-run` 的预览会回显最终请求体（F-047）。

## 3. 约束系统：把「不能同时给」写进契约

| 约束 | 语义 | 例子 |
|------|------|------|
| `one_of` | 多选一 | 按 openId 或按手机号查人 |
| `require_one_of` | 至少给一个 | 发消息必须给会话或用户 |
| `mutex` | 互斥 | `--text` 与 `--markdown` 不同时出现 |
| `linked` | 联动 | 给了 A 必须给 B |

（F-020）

约束由框架统一校验，**不靠每个命令手写 if**。这让错误信息一致，也让 Schema 能提前告诉 Agent 哪些组合非法（F-032）。

## 4. 三类执行体：为什么不是所有命令都生成

| 执行体 | 适用 | 特征 |
|--------|------|------|
| 静态管线生成 | 绝大多数 CRUD 型接口 | 完全由端点数据驱动，改数据即改命令 |
| raw 分发器 | `dws api` | 直连开放平台，绕过命令层，但受域名白名单约束（F-058） |
| 手写 Go 命令 | 需要状态机或复杂交互（事件订阅、登录、升级、`dev connect`） | 有独立测试，仍须实现 `Spec` |

（F-018）

> **洞察**：三种执行体并存不是妥协，而是**按「接口是否可被声明」分层**。可声明的走生成，不可声明的走手写，但两者都必须交出同一份契约——这才是五条不变量里最关键的一条。

## 5. 五条不变量

1. 每个叶命令必须有 `Spec`，不允许「裸 Cobra 命令」。
2. 参数名一律 kebab-case。
3. flag 是唯一输入面：除选择器类位置参数外不接受自由位置参数（F-024）。
4. 安全元数据必填：没有 effect/risk 的命令不能注册。
5. Schema 必须派生，禁止手写第二份（F-023、F-025）。

这五条把「文档腐化」变成「构建失败」。反过来看，如果团队只想快速糊一个脚本，这套约束会显得过重——它适合的是**长期对外提供接口**的场景。

## 6. 三层契约声明

```text
ContractDecl（单命令声明）
      ↓ 汇总
ProductDecl（产品级声明）
      ↓ 定稿
ContractFinal（发布契约 / Catalog 输出）
```

（F-022）

注意方向：Catalog 是**产物**，不是输入。很多团队反过来先维护一份大 Catalog 再拆命令，结果两边漂移；dws 让声明自下而上汇总，Catalog 每次重新生成。

## 7. 反模式对照

| 反模式 | 后果 | dws 的替代 |
|--------|------|-----------|
| 每个命令各写一套参数解析 | 错误信息不一致、Schema 无法生成 | 统一 `FlagSpec` + 回退链 |
| 用位置参数传业务数据 | 无法稳定生成 Schema | flag 唯一输入面 |
| 安全判断写在业务代码里 | 无法在 dry-run 阶段预演 | 安全元数据前置到 `Spec` |
| 手写 help 文本 | 与实现漂移 | 从 registry 派生 |
