# 配置流程：三步走 + 四个源文未覆盖的官方能力

## 一、前置条件

| 条件 | 说明 | 来源 |
|---|---|---|
| 一块**可用的无线网卡** | 没有无线网卡就没有接入点可言 | F-002（`article_claim`） |
| 一个**能上网的上行链路** | 网线、上游 Wi-Fi 或蜂窝数据，三选一 | F-025（`official_doc`，L1） |
| Windows 11 | Windows 10 的支持已于 2025-10-14 结束 | F-031（`official_doc`，L1） |

源文限定场景是「一根网线 + 一台 Windows 电脑 + 若干只能走 Wi-Fi 的设备」（F-001）。这个场景下**最稳的硬件组合是「有线网卡负责上行、无线网卡负责发热点」**——两块网卡的职责完全分离，不存在同一块网卡既要连上游又要当 AP 的并发压力（F-012）。

## 二、官方路径：五步

微软官方支持文档给出的步骤（F-024 ~ F-027）：

1. **进入设置**：开始菜单 → 「设置」→「网络和 Internet」→「移动热点」。官方还提供了快捷 URI：`ms-settings:network-mobilehotspot`。
2. **选共享来源**：「共享我的 Internet 连接来源」下拉中选择要共享的那条连接（F-025）。
3. **选共享方式**：「共享方式」下拉中选择 **Wi-Fi** 或 **蓝牙**；**Wi-Fi 通常更快且是默认项**（F-026）。
4. **（可选）改属性**：展开「属性」→ 点「编辑」→ 设置**网络名称、密码、网络频段** → 「保存」（F-027）。
5. **打开开关**：页面顶部的「移动热点」开关。

> **与源文的对应关系**：源文的三步（进入移动热点页 / 选共享来源 / 编辑属性并开开关）与官方路径完全对应，只是源文把「选共享方式」这一项略去了（C1 ✅）。

## 三、四个源文未覆盖、但官方明确写出的能力

这几项在源文中完全没出现，但都来自官方支持文档原文（F-025、F-026、F-028、F-029、F-030），是本包相对源文的增量。

### 3.1 共享方式：Wi-Fi 还是蓝牙

「共享方式」决定**用哪种无线技术承载**：

| 选项 | 适用 | 代价 |
|---|---|---|
| **Wi-Fi**（默认） | 绝大多数场景；速率高、兼容性广 | 占用无线网卡 |
| **蓝牙** | 目标设备只支持蓝牙 PAN，或需要极低功耗的近场接入 | 速率远低于 Wi-Fi，兼容性面窄 |

官方原文只写「Wi-Fi 通常更快且是默认值」（F-026）——**没有**给出两者的定量差异，具体速率取决于网卡与对端设备。

### 3.2 QR 码连接

其他设备可以**用密码，也可以扫 QR 码**连接（F-028）。这解决的是「密码输错」和「密码含有易混淆字符」两个实际痛点。源文只提了密码。

操作位置：移动热点页面的「属性」区提供二维码入口；客户端在 Wi-Fi 设置里找到该网络后扫描即可。

### 3.3 快速设置面板

任务栏的**快速设置**里有「移动热点」快捷操作（F-029）：

- 可能需要点「下一页」箭头翻到快速操作第二页才能看到；
- 点它即开关热点，**使用默认属性或上次在「设置」中用过的属性**；
- 开启时，**该快捷操作会显示已连接的设备数量**；
- 右键（或长按）→「转到设置」可管理网络密码等。

**实用价值**：这是最快的开关方式，也让「当前有几台设备连着」一眼可见——排障时非常有用，因为 ICS 侧不提供连接数面板。

### 3.4 远程开启（蓝牙 + 蜂窝数据）

如果设备有**蜂窝数据**，可以**远程开启**移动热点：需要 Windows 电脑与控制端设备**都具备蓝牙且已完成配对**（F-030）。

这条能力的意义是：热点主机可以是一台放在角落、无人值守的带蜂窝数据的电脑，由另一台已配对设备远程拉起热点。

## 四、共享来源选择矩阵

「共享我的 Internet 连接来源」的三种取值（F-025）及其后果，是本包认为**最值得单独成节**的部分——因为它同时决定了成败率和排障顺序。

| 共享来源 | 上行链路 | 无线网卡的角色 | 稳定性 | 典型场景 |
|---|---|---|---|---|
| **以太网** | 网线 | 专职当 AP | **最高**——职责分离，无并发压力 | 源文场景（F-004）：只有一根网线 |
| **Wi-Fi** | 上游路由器 | 既连上游（STA）又发热点（AP） | **依赖驱动并发能力**；失败率最高 | 没有网线、只有无线 |
| **蜂窝数据** | 运营商网络 | 专职当 AP | 高，但**消耗流量套餐** | 主机本身是带 5G/4G 的设备 |

**选择 Wi-Fi 作共享来源时的三个已知风险**：

1. **角色耦合**：同一块无线适配器要同时承担 STA 与 AP 两种角色。是否可行取决于驱动对并发模式的支持，与用户操作无关。
2. **切换影响**：上游 Wi-Fi 断开时，热点往往随之失效；反之亦然。
3. **信号竞争**：上下行共享同一频段，吞吐会被折损。

**官方社区答复佐证**：「已连接但无网络」的一类常见成因，正是**共享来源选错**或**客户端未取得正确 IP**；官方给出的处置顺序是「先改选另一条共享接口 → 再考虑重置网络」（F-032）。

> **因此第一条排障动作是换共享来源**，而不是重置网络、更不是重装驱动。

## 五、属性设置的三项细节

### 5.1 网络名称（SSID）

- 官方支持在「编辑」里自定义网络名称（F-027）。
- 源文经验：**网络名称最好用英文字符，避免部分设备识别乱码**（F-006，`article_claim`）。这是**经验口径**，无官方文档背书；但与「WPA2-PSK passphrase 必须是 ASCII」这类硬约束同属编码问题域，值得采纳。

### 5.2 密码

- 官方规范：**WPA2-PSK passphrase 为 8 至 63 个 ASCII 字符（码位 32–126）**（F-020，L2）。
- 源文只说「至少 8 个字符」（F-007）——**正确但不完整**：上限是 63，且必须是 ASCII 可打印字符。
- 常见踩坑：输入中文或 emoji 的密码，会因无法映射到 ASCII 而被拒绝。

### 5.3 网络频段

「编辑」里可选**网络频段**（F-027）。源文给出三个取值与取舍：**5GHz / 2.4GHz / 任何可用频率**（F-008）。详细的频段取舍与兼容性分析见 [频段与兼容性](frequency-and-compatibility.md)。

## 六、关闭与恢复

- **关闭**：直接关掉「移动热点」开关即可。源文指出**下次再开无需重新设置**（F-011）——属性会被记住。
- **关闭前提醒**：源文注意事项②③指出——电脑关机则热点消失（F-013）；若 Windows 进入休眠，热点可能无法继续使用，需关闭自动休眠（F-014）。
- **查看已连接设备**：源文称终端接入后可在 Windows 属性中看到设备名称、IP 与 MAC 地址（F-010）。**注**：本包未在官方文档中找到对应的界面说明，此项属源文经验口径；更可靠的等价信息是快速设置面板显示的已连接设备数（F-029）。

## 七、照做前的三条自检

| 自检项 | 判定标准 | 不通过怎么办 |
|---|---|---|
| 上行链路本身是通的吗？ | 主机在**不开热点**的情况下能正常上网 | 先解决主机上网问题，别碰热点设置 |
| 无线网卡有没有被别的程序独占？ | 没有 VPN/抓包/其他虚拟网卡工具在占用 | 关闭冲突程序后重试 |
| 硬件角色分离了吗？ | 上行是网线时，无线网卡只做 AP | 已是最佳；上行是 Wi-Fi 时见 4.2 的风险说明 |
