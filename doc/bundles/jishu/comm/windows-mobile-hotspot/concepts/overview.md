# 总览：信源性质、结论地图与勘误索引

## 一、本包要解决的两个问题

源文（`s1-wx-article`）是一篇**场景导向**的公众号图文：它从「手里只有一根能上网的网线，还有一台 Windows 电脑，旁边设备只能走 Wi-Fi」这个具体困境出发，给出三步开启流程和四条注意事项。

它的价值在于**路径清晰、结论可执行**——经核验，核心操作路径与微软官方支持文档完全一致（C1 ✅）。但它也有两个明显的短板：

1. **有一处实质性错误**（注意事项④，见下文第三节），且这个错误恰好落在最容易被读者直接照搬的结论句上；
2. **覆盖面窄**——只覆盖了官方能力面的一部分，漏掉了共享方式下拉、QR 码连接、快速设置面板、远程开启、蜂窝数据作为共享来源等官方明确写出的能力（F-025、F-026、F-028、F-029、F-030）。

因此本包的工作不是「摘要一篇文章」，而是**以文章为线索、以官方文档为判据**，把一个能用的操作教程补成一份带证据分层的完整教程。

**证据层级**（这条话有多可信）

| 层级 | 含义 | 可否作为操作依据 |
|---|---|---|
| **L1** | 官方支持/产品文档 | 可 |
| **L2** | 官方技术学习文档 | 可 |

## 三、勘误索引（本包最重要的一条）

<a id="errata-index"></a>

源文注意事项④原文大意是：真正的路由器可以长期运行，支持**防火墙、DHCP、端口转发**等功能；而 Windows 11 的移动热点更适合临时应急共享网络，不建议作为长期方案替代路由器。

这句话把**三项能力**打包成了一个对比，实际需要拆开看：

| 能力 | 源文归因 | 核验结论 | 官方依据 |
|---|---|---|---|
| **DHCP** | 路由器有，Windows 热点没有 | **❌ 错**。ICS 为私网提供地址分配 | F-016（L2，`s3-ms-learn-sr2003-network`）；F-018（L2，`s4-ms-learn-embedded-ics`）；F-019（L4，`s5-ms-hw-compat`） |
| **防火墙** | 路由器有，Windows 热点没有 | **❌ 错**。Windows 防火墙是**状态防火墙**，且是 ICS 的依赖组件 | F-016、F-019（L2/L4） |
| **端口转发** | 路由器有 | **✅ 对**。ICS 提供的是 NAT 共享，不含静态端口映射 | F-018（L2，`s4-ms-learn-embedded-ics` 描述的是源地址改写而非端口映射） |

**修正后的正确表述**（本包正文一律采用此口径）：

> Windows 11 移动热点**自带** DHCP 地址分配、DNS 代理与状态防火墙——这些不是「专业路由器才有的东西」。它与家用路由器的真实差距在于：① 它依赖这台电脑保持开机且不休眠；② 它提供的是 **NAT 共享出口**，不是端口转发/内网穿透/策略路由；③ 它缺少家用路由器的管理面——访客网络、设备分组、家长控制、QoS 优先级等。

这个勘误不是「抬杠」：它**直接改变排障动作**。如果读者相信「热点没有 DHCP」，遇到「手机连上了但 IP 是 169.254.x.x（未拿到地址）」时会去检查防火墙开关或重装驱动；而真实路径是检查 DHCP 服务与第三方安全软件对 UDP 67/68 的拦截（F-019）。

## 四、三条结论的推导链

<a id="three-conclusions-derivation"></a>

### I1 · 移动热点的网络能力由 ICS 提供

**陈述**：Windows 11 移动热点的网络能力由 Internet Connection Sharing（ICS）提供，包括 DHCP 地址分配、DNS 代理、NAT 改写，并依赖 Windows 防火墙。
**证据**：F-016（F-017、F-018、F-019），分别来自官方学习文档三处独立表述与官方硬件兼容性规范。
**反常识**：多数教程（含源文）把 DHCP 与防火墙当作路由器专属能力；实际上它们是 ICS 的组成部分，且 ICS 会自动完成防火墙配置。
**行动**：排障第一步查上游链路与 ICS 服务状态，不查防火墙开关。

### I2 · 官方开启路径是设置界面，命令探测属于另一代技术

**陈述**：微软官方给出的开启路径是「设置 > 网络和 Internet > 移动热点」与任务栏快速设置（F-024、F-029）；`netsh wlan show drivers` 输出的 `Hosted network supported` 探测的是 **Hosted Network**（Windows 7 时代的承载网络），与当前移动热点的可用性不是同一判据（F-037，L5 社区口径）。
**证据**：官方支持文档全文不含 `netsh wlan`、不含 Hosted Network；官方社区答复给出的处置建议也是改选共享来源/重置网络，而非启用 Hosted Network（F-032）。
**反常识**：大量中文教程把「`netsh wlan show drivers` 里 Hosted network supported 显示为 No」当作「本机开不了热点」的结论依据，而这两件事判据不同。
**行动**：判断热点能否开启，看**移动热点开关是否可用**与**驱动是否支持 SoftAP**；不要拿 Hosted Network 的探测行当判据。

### I3 · 失败多来自共享来源与上行链路的耦合

**陈述**：移动热点的上游选择与承载方式存在耦合：共享来源为 Wi-Fi 时，同一块无线适配器既要作为 STA 连接上游、又要作为接入点承载热点，受驱动并发能力约束；共享来源为以太网时无此耦合（F-004、F-012、F-032）。
**证据**：源文场景限定为「网线 + 无线」（F-004、F-012）；官方社区答复把「共享来源选错」「客户端未取得正确 IP」列为「已连接但无网络」的常见原因（F-032）。
**反常识**：源文把「电脑最好用有线网卡共享」列为注意事项，但**真正决定成功率的是驱动对并发模式的支持，而不是用户有没有按步骤操作**；因此第一排障动作应是换共享来源，而不是重置网络。
**行动**：排障时优先改选「共享来源」，其次才升级到网络重置。
