# 边界与风险：它到底不能做什么

## 一、勘误后的能力边界

先给一张**准确**的对照表。左列是源文正确的地方，右列是源文归因错误的地方。

| 能力 | 家用路由器 | Windows 11 移动热点 | 结论 |
|---|---|---|---|
| **DHCP 地址分配** | 有 | **有**（ICS 内建，F-016/F-018/F-019） | 源文 ❌ 误述 |
| **DNS 代理** | 有 | **有**（F-019） | 源文未提及 |
| **状态防火墙** | 有 | **有**，且是 ICS 的**依赖**（F-016） | 源文 ❌ 误述 |
| **NAT 出口** | 有 | **有**（F-018） | 源文未提及 |
| **端口转发 / 内网穿透** | 有 | **无** | 源文 ✅ 正确 |
| **长期无人值守运行** | 有 | **无**（依赖主机常开且不休眠，F-013/F-014） | 源文 ✅ 正确 |
| **访客网络 / 设备分组 / 家长控制 / QoS** | 有 | **无** | 源文未提及 |
| **多 WAN / 策略路由 / 链路聚合** | 部分有 | **无** | 源文未提及 |

**一句话**：移动热点的差距**不在网络基础能力**，而在**可用性形态与管理面**。

## 二、它不能做的事（逐条）

### 2.1 不能提供「入口」

ICS 是 NAT 共享出口（F-018）。出网可以，被动入站不行。**端口映射、内网穿透、把内网服务暴露到公网——ICS 一概不做**。需要这些能力，用专门的方案（见 [互链：贝锐内网穿透](../../iot/oray/index.md)）。

### 2.2 不能在主机休眠/关机时工作

源文注意事项②③说对了（F-013、F-014）。**「关掉自动休眠」是让热点持续工作的必要前置**，不是可选项。

> **补充一条未闭环项**：源文只覆盖了「休眠」这一种失效源。Windows 11 移动热点另有一个「节能：无设备连接时自动关闭」相关的节能行为，本包**未在官方文档中核实**其存在与触发条件（U-5）。若遇到「热点自己关了」，先查这一项。

### 2.3 不能当长期主力网络

理由不是技术弱，而是**形态不对**：它绑在一台需要被照看的个人电脑上。这台电脑合盖、关机、断电、被系统更新重启，热点就没了。

**适用定位**：临时应急、演示环境、给一两台设备临时联网、路由器故障时的替代方案。**不适用**：家庭长期主力、公司正式网络、把服务器暴露到外网。

### 2.4 不能同时共享多个上行

一次只能共享一个来源（F-025 官方文档即只列一个下拉）。需要多路共享是路由器/软路由的活。

## 三、安全模型

### 3.1 访问控制只有一层：密码

热点启用后，**唯一的访问控制手段就是 WPA2-PSK 密码**（F-020）。没有设备白名单、没有 MAC 过滤的官方入口、没有隔离访客与主网的机制。

官方在讨论 8 台上限时给出的建议是：**设置复杂密码，并轻易不要向他人共享密码**（F-021）。

### 3.2 客户端对公网不可见

这是 ICS 的一个**安全优势**，常被忽略：

> 启用 ICS 时，只有 ICS 主机对 Internet 可见；ICS 客户端的地址对 Internet 隐藏（F-017）。

官方还直接建议**在 ICS 主机上始终启用 Windows 防火墙**，因为这会让 ICS 客户端一并获得保护（F-016）。

### 3.3 威胁面

| 风险 | 说明 | 缓解 |
|---|---|---|
| **弱密码被蹭网** | 唯一门禁是密码；改密码可踢掉已自动重连的旧设备 | 用 ≥12 位随机密码；不共享给不信任的人 |
| **第三方安全软件夺走防火墙** | 官方规范要求主机防火墙放行 DHCP(67/68) 与 DNS(53)（F-019）；若被接管，这两条放行可能失效 | 排障时把安全软件列为嫌疑项 |
| **共享主机被他人接入** | 办公室/公共场所的电脑开热点，可能被不认识的设备连入 | 不用时关闭；或用完立即改密码 |
| **绕过企业网络策略** | 把办公网通过个人设备再分发，可能违反网络使用规范 | 见下一节 |

### 3.4 企业与公共场所

**这属于合规问题，不是技术问题**：

- 很多组织的网络使用规范禁止在办公设备上私自开启接入点、禁止把受管网络二次分发；
- 公共 Wi-Fi 环境下，**自建热点通常比连公共热点更可控**（密码是自己设的、不经过第三方）；
- 但**把公司网络通过个人电脑再分发出去**，通常踩的是「二次分发/旁路」这条线。

**建议**：办公场景先确认组织的网络使用规范；不确定就不开。

## 四、能耗与热

热点开启后，无线网卡从「只收」变成「既收又发」，且要持续做 NAT 与 DHCP——这会明显抬高功耗与发热。源文虽未提及，但这是「电脑别关机」「关自动休眠」的同源代价：**长期当路由器用，与「省电」的默认取向直接冲突**。
