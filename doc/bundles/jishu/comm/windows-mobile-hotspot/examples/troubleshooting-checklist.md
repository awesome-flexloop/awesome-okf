# 排障清单：按症状定位

> **核心原则：按机制分层，不按界面分层。** 每一步先判定「卡在哪一层」，再动手。凭界面症状瞎试（反复开关、重置网络、重装驱动）会把简单故障拖成复杂故障。

## 分层判定表（先做这一步）

| 客户端观察 | 卡在哪层 | 直接跳到 |
|---|---|---|
| 扫不到热点网络 | Wi-Fi 层 / 驱动 | S1 |
| 关联成功但 IP 是 `169.254.x.x` | DHCP 层 | S2 |
| IP 正常，域名解析不了 | DNS 层 | S3 |
| 域名能解析，网页打不开 | NAT / 上游层 | S4 |
| 连上又断、时好时坏 | 驱动并发 / 频段 | S5 |
| 第 N 台连不上（N≤8） | 连接数 / 驱动上限 | S6 |

---

## S1 · 扫不到热点网络

| # | 动作 | 判定标准 |
|---|---|---|
| 1.1 | 确认主机侧开关已打开 | 主机「移动热点」开关为开启态 |
| 1.2 | 确认无线网卡驱动为最新 | 设备管理器 → 无线网卡 → 有可用更新 |
| 1.3 | 确认没有其他程序占用无线网卡 | 关闭 VPN / 抓包 / 虚拟网卡工具后重试 |
| 1.4 | 检查「共享方式」是否为 Wi-Fi | 若为蓝牙，改回 Wi-Fi（F-026） |
| 1.5 | 确认其他设备未开启 Wi-Fi 过滤 | 部分手机有「扫描结果排序」「隐藏」选项 |

> **不要做**：`netsh wlan set hostednetwork mode=allow`。它配置的是 Hosted Network，与当前移动热点不是同一条技术路径（F-037，见 [辨析](../concepts/frequency-and-compatibility.md#hosted-network)）。

---

## S2 · 连上了但拿不到 IP

<a id="s2-connected-no-ip"></a>

**症状**：Wi-Fi 已连接，地址是 `169.254.x.x`（APIPA），或客户端显示「正在获取 IP 地址」。

**对应机制**：DHCP 服务器（ICS 内建，F-016/F-018）未正常应答。

| # | 动作 | 判定标准 |
|---|---|---|
| 2.1 | 在主机上确认上行链路正常 | 主机自己能上网 |
| 2.2 | 确认防火墙未被第三方安全软件接管 | 安全软件的「网络防护/防火墙」处于不接管状态 |
| 2.3 | 放行 DHCP 端口 | 官方规范要求放行入向 UDP 68→67、出向 UDP 67→68（F-019） |
| 2.4 | 检查是否处在「已连满 8 台」状态 | 快速设置面板显示的已连接设备数（F-029） |
| 2.5 | 检查网段冲突 | 客户端拿到的地址是否与上游局域网同段（U-2 社区口径） |
| 2.6 | 最后才考虑网络重置 | 「高级网络设置 > 网络重置」（F-032 官方社区建议的**后置**手段） |

---

## S3 · 拿到 IP 但解析不了域名

<a id="s3-ip-no-dns"></a>

**症状**：能 ping 通 `192.168.137.x` 网关，能 ping 通具体 IP，但 ping 域名失败。

**对应机制**：DNS 代理（ICS 内建，F-019）未正常应答。

| # | 动作 | 判定标准 |
|---|---|---|
| 3.1 | 放行 DNS 端口 | 官方规范要求放行 UDP 53 的入向与出向（F-019） |
| 3.2 | 确认安全软件未劫持 DNS | 关闭安全软件的 DNS/流量防护后重试 |
| 3.3 | 确认客户端没有残留的 VPN DNS 配置 | 客户端关闭 VPN 后重试 |
| 3.4 | 临时手动指定 DNS 做对照测试 | 在客户端手动填 DNS 后能解析 → 定位到 DHCP 下发的 DNS 有问题 |

---

## S4 · 域名能解析但打不开网页

<a id="s4-dns-no-web"></a>

**症状**：域名解析成功，浏览器打不开页面或极慢。

**对应机制**：NAT 出口或上行链路（ICS 的源地址改写，F-018）。

| # | 动作 | 判定标准 |
|---|---|---|
| 4.1 | 在主机上用同一网络访问同一站点 | 主机也打不开 → 是上行问题，不是热点问题 |
| 4.2 | 改选共享来源 | 官方社区答复把「共享来源选错」列为常见成因（F-032） |
| 4.3 | 上行是 Wi-Fi 时，改用网线上行试一次 | 若改用网线即恢复 → 定位到无线网卡的并发模式限制 |
| 4.4 | 检查上游是否对客户端做了设备级限制 | 企业网可能限制经 NAT 后的流量 |

---

## S5 · 连上又断 / 时好时坏

| # | 动作 | 判定标准 |
|---|---|---|
| 5.1 | 换频段 | 2.4 GHz ↔ 5 GHz 各试一次（F-008） |
| 5.2 | 上行是 Wi-Fi 时，改为网线上行 | 分离 STA/AP 角色 |
| 5.3 | 检查距离与遮挡 | 5 GHz 穿墙衰减明显 |
| 5.4 | 检查主机是否有省电策略介入 | 关闭无线网卡的「允许计算机关闭此设备以节约电源」 |
| 5.5 | 检查主机是否进入了休眠或被节能策略关闭 | 关闭自动休眠与「无设备连接时自动关闭」类节能项（后者属 U-5，未闭环） |

---

## S6 · 第 N 台连不上（N ≤ 8）

**症状**：新设备连不上，或昨天能连的设备今天连不上，Windows 不给任何提示。

| # | 动作 | 判定标准 |
|---|---|---|
| 6.1 | 看快速设置面板的已连接设备数 | 显示已满 → 就是名额问题（F-029） |
| 6.2 | 改密码 | 已自动重连的旧设备会被踢出（F-021 官方建议） |
| 6.3 | 关闭不用的设备的 Wi-Fi | 它们可能仍占着名额 |
| 6.4 | 确认是否已达驱动自身的并发上限 | 该上限不受 ICS 侧参数影响（F-037） |
| 6.5 | 注册表调整（**不建议常规使用**） | `icssvc\Settings\WifiMaxPeers`（F-023，L3；效果未获官方确认，U-3） |

## 升级路径：什么情况下该放弃自建

以下情形说明问题**不在**「怎么配热点」，应换方案：

| 情形 | 更好的方案 |
|---|---|
| 需要**长期**稳定运行 | 买一个路由器，或用软路由 |
| 需要**对外暴露**内网服务（端口映射/穿透） | 内网穿透方案（本包不提供，见 [互链：贝锐](../../../iot/oray/index.md)） |
| 需要**大量设备**接入（远超 8 台） | 企业级 AP |
| 需要**访客网络 / 家长控制 / QoS** | 家用路由器的管理面 |
| 办公设备且组织有明确网络规范 | **先问 IT**（合规优先） |

## 一条不该忘的纪律

> **不要为了「让热点能用」去关闭 Windows 防火墙。** 防火墙是 ICS 的依赖（F-016），且官方明确建议在 ICS 主机上始终启用它。正确做法是**放行需要的那两条端口规则**（DHCP 与 DNS，F-019），而不是关掉整个防火墙。
