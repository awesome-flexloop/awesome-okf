## F-001 ~ F-025：doltlite-android

F-001 | `Doltlite.kt` 中类 `Doltlite` 实现 `AutoCloseable`，封装 SQLite + Dolt 版本控制操作
F-002 | `Doltlite` 构造函数签名：`constructor(path: String, create: Boolean = true)`，持有 `private val db: CDoltlite = Native.load("doltlite", CDoltlite::class.java)`
F-003 | `Doltlite.execute(sql: String, vararg binds: Any?): Int` — 执行无返回行的 SQL，返回影响行数或错误码
F-004 | `Doltlite.query(sql: String, vararg binds: Any?): List<Map<String, Any?>>` — 执行查询，返回列名→值的映射列表
F-005 | `Doltlite.doltCommit(message: String, all: Boolean = false): Int` — 封装 `dolt_commit()` C 函数
F-006 | `Doltlite.doltVersion(): String` — 返回 Dolt 版本字符串
F-007 | `Doltlite.doltBranch(command: String, args: Array<String>): Int` — 封装分支操作命令
F-008 | `Doltlite.close()` — 调用 `sqlite3_close_v2(handle)` 关闭连接
F-009 | 参数绑定类型支持：`null`、`Int`、`Long`、`Double`、`Float`、`String`
F-010 | 所有公共方法失败时抛出 `DoltliteException(sql, message)`
F-011 | `CDoltlite` 是内部 interface 继承 JNA `Library`，暴露 SQLite C API
F-012 | `CDoltlite` 暴露的 SQLite 函数：`sqlite3_open_v2`、`sqlite3_close_v2`、`sqlite3_exec`、`sqlite3_prepare_v2`、`sqlite3_step`、`sqlite3_finalize`、`sqlite3_column_*`、`sqlite3_bind_*`
F-013 | `sqlite3_column_type()` 常量：`INTEGER=1`、`FLOAT=2`、`TEXT=3`、`BLOB=4`、`NULL=5`
F-014 | `query()` 内部流程：`sqlite3_prepare_v2` → `sqlite3_step` 循环 → `sqlite3_finalize`
F-015 | `query()` 结果列值类型映射：`INTEGER→Int`、`FLOAT→Double`、`TEXT→String`、`BLOB→null`、`NULL→null`
F-016 | JNA 加载常量：`val OK = 0`、`val ROW = 100`、`val DONE = 101`
F-017 | `build.gradle.kts` 使用 Android Library Plugin 8.5.2，Kotlin 2.0.20
F-018 | Maven Central 坐标：`com.dolthub:doltlite-android:0.11.20`（README 中标注的版本）
F-019 | `minSdk 21`，`compileSdk 34`
F-020 | 核心 native 依赖：`net.java.dev.jna:jna:5.14.0@aar`
F-021 | 发布配置：`publishToMavenCentral()` + `signAllPublications()`
F-022 | `dolt_*` SQL 函数通过标准 SQL 调用，不通过 JNA 直接调用（README 明确说明）
F-023 | `execute()` 调用路径：`sqlite3_exec(handle, sql, NULL, NULL, nullPtr())`
F-024 | `Doltlite` 类标注 `@OptIn(ExperimentalStdlibApi::class)`，使用 `unsafeCast<>()` 进行指针转换
F-025 | `CDoltlite` 接口中 `sqlite3_bind_*` 方法签名含 `Long` 参数（stmt pointer 类型）

## F-026 ~ F-045：vitess (DoltHub fork)

F-026 | Go 模块名 `github.com/dolthub/vitess`，`go.mod` 声明 `tool golang.org/x/tools/cmd/goyacc`
F-027 | SQL parser 入口：`go/vt/sqlparser/sql.go`（由 goyacc 从 `sql.y` 自动生成，文件头含 `// Code generated by goyacc -o sql.go sql.y. DO NOT EDIT.`）
F-028 | `yyParsePooled(yylex yyLexer) (ret int)` 使用 `sync.Pool` 复用 parser 对象，避免 GC 压力
F-029 | Parser 嵌套深度限制：`nesting == 200` 时返回错误（`incNesting` 函数）
F-030 | `ParserOptions` 结构体包含 `AnsiQuotes bool`、`SQLMode sqlmode.SQLMode` 等解析选项
F-031 | AST 核心接口：`Statement`（所有 SQL 语句类型的公共接口）
F-032 | `Statement` 接口实现类型包括：`*Select`、`*Insert`、`*Update`、`*Delete`、`*DDL`、`*Show`、`*Set`、`*Call`、`*Begin`、`*Commit`、`*Rollback`、`*Replace`、`*Grant`、`*Revoke`、`*Alter`、`*Create`、`*Drop`、`*TruncateTable`
F-033 | `ast.go` 包含 `Expr` 接口（表达式基类）及实现：`*Literal`、`*NullValue`、`*Boolean`、`*ColName`、`*CompoundExpr`、`*Parentheses`、`*BinaryExpr`、`*UnaryExpr`、`*ExistsExpr`、`*Subquery`、`*RangeExpr`、`*CollateExpr`、`*CaseExpr`、`*When`、`*FuncExpr`、`*ConvertExpr`、`*CastExpr`、`*SubstringExpr`、`*TrimExpr`、`*ExtractExpr`、`*PositionExpr`、`*UserVarExpr`、`*VarExpr`、`*MatchExpr`、`*ExistsExpr`
F-034 | `token.go` 包含词法分析器 `Tokenizer` 结构体及 `Next() (int, []byte)` 方法
F-035 | `keywords.go` 中 `keywords` 变量为 `map[string]int`，映射 MySQL 兼容的所有关键字到 token 值
F-036 | `sql.go` 中 token 常量起始值：`STRING_TYPE_PREFIX_NON_KEYWORD = 57346`，`LEX_ERROR = 57347`
F-037 | `normalizer.go` 提供查询标准化功能（`Normalize` 函数），用于安全比较和缓存
F-038 | `parsed_query.go` 包含 `ParsedQuery` 结构体，用于参数化查询预处理
F-039 | `comments.go` 支持 SQL 注释解析（`/* */` 块注释和 `--` 行注释）
F-040 | `auth.go` 包含 MySQL 认证相关 AST 节点（`*Grant`、`*Revoke`、`*CreateUser` 等）
F-041 | DoltHub fork 与上游 Vitess 的差异：添加了 DDL 语句支持、存储过程支持、触发器支持，剪枝了 90% 非核心代码
F-042 | `go/mysql/` 目录包含 MySQL 协议实现（连接握手、数据包序列化/反序列化）
F-043 | `go/sqltypes/` 目录包含 SQL 值类型系统（`Value` 结构体、类型常量、类型转换函数）
F-044 | `go/vt/proto/query/` 包含 protobuf 定义的查询协议消息类型
F-045 | `README.md` 明确说明：Vitess 自 2011 年起作为 YouTube 数据库基础设施核心组件

## F-046 ~ F-075：go-mysql-server

F-046 | Go 模块名 `github.com/dolthub/go-mysql-server`，关键依赖 `github.com/dolthub/vitess v0.0.0-20260904221543-1d51d1321878`
F-047 | 其他关键依赖：`go-sql-driver/mysql v1.9.3`、`cockroachdb/apd/v3 v3.2.3`（高精度十进制运算）、`sirupsen/logrus v1.8.3`（日志）
F-048 | `sql/core.go` 定义核心接口 `Expression`：`Type(ctx) Type`、`IsNullable(ctx) bool`、`Eval(ctx, row) (interface{}, error)`、`Children() []Expression`、`WithChildren(ctx, ...Expression) (Expression, error)`
F-049 | `sql/core.go` 定义核心接口 `Node`：`Schema(ctx) Schema`、`Children() []Node`、`WithChildren(ctx, ...Node) (Node, error)`、`IsReadOnly() bool`、`Resolved() bool`
F-050 | `NodeExecBuilder` 接口：`Build(ctx, n Node, r Row) (RowIter, error)` 将计划节点转换为行迭代器
F-051 | `ExecSourceRel` 接口：无子节点的执行源，直接实现 `RowIter(ctx, r) (RowIter, error)`
F-052 | `ExecBuilderNode` 接口：控制自身迭代器生成但有子节点的节点
F-053 | `Catalog` 接口聚合：`DatabaseProvider` + `FunctionProvider` + `TableFunctionProvider` + `ExternalStoredProcedureProvider` + `StatsProvider`
F-054 | `Catalog.Table(ctx, dbName, tableName) (Table, Database, error)` — 获取表引用
F-055 | `Catalog.TableAsOf(ctx, dbName, tableName, asOf) (Table, Database, error)` — 时间旅行查询（Dolt 版本控制核心能力）
F-056 | `Catalog.CreateDatabase(ctx, dbName, collation) error` 和 `RemoveDatabase(ctx, dbName) error`
F-057 | `Catalog.LockTable(ctx, table string)` 和 `UnlockTables(ctx, id uint32) error` — 表级锁机制
F-058 | `sql/analyzer/` 包含约 72 个规则文件，核心文件：`analyzer.go`、`rules.go`、`process.go`、`catalog.go`
F-059 | DoltHub 特有分析规则：`triggers.go`（触发器）、`stored_procedures.go`（存储过程）、`resolve_ctes.go`（CTE 解析）、`functional_index_expr.go`（函数式索引）
F-060 | `sql/plan/` 包含 130+ 计划节点文件，核心类型：`project.go`、`filter.go`、`join.go`、`group_by.go`、`sort.go`、`limit.go`、`insert.go`、`update.go`、`delete.go`、`ddl.go`、`procedure.go`、`trigger.go`
F-061 | `sql/expression/` 包含约 55 个表达式文件，`sql/expression/function/` 包含约 90 个内置函数
F-062 | `sql/types/` 定义 SQL 类型系统，支持类型：`Int8`~`Int64`、`Float32`、`Float64`、`Text`、`Blob`、`Date`、`Time`、`Timestamp`、`Datetime`、`JSON`、`Geometry`、`Vector`、`Enum`、`Set`
F-063 | `server/` 目录提供 MySQL 协议兼容的网络服务器，处理连接握手和协议包
F-064 | `auth/` 目录包含 `AuthorizationHandler` 接口，将认证授权逻辑委托给外部实现
F-065 | `memory/` 目录提供内存表后端，文档明确标注：非线程安全、无事务支持、索引性能较差
F-066 | `enginetest/` 目录包含 SQL 引擎测试框架与集成测试用例
F-067 | ICU 正则依赖为可选：`-tags=gms_pure_go` 可切换为 Go 标准库 regex
F-068 | `ValueExpression` 接口是实验性优化路径：`EvalValue(ctx, row) (Value, error)` 避免 `interface{}` 装箱开销
F-069 | `NonDeterministicExpression` 接口标记不可缓存表达式（如 `NOW()`、`RAND()`）
F-070 | `SchemaTarget` 接口用于 DDL 操作的 target schema 设置（`WithTargetSchema(Schema) (Node, error)`）
F-071 | `Projector` 接口返回投影表达式列表，用于 GroupBy/Window/Project 节点
F-072 | `Expressioner` 接口返回节点内含的表达式列表（`Expressions() []Expression`）
F-073 | `OpaqueNode` 接口禁止对其子节点进行变换（`Opaque() bool`）
F-074 | `ConvertToBool(ctx, v interface{}) (bool, error)` 支持多种类型到布尔值的转换
F-075 | `DecodeVector` / `EncodeVector` 函数用于向量类型（`[]float32`）与 `[]byte` 之间的编解码，支持距离计算函数

F-081 | `ast.go` 中 `Statement` 接口实现类型：`*Select`、`*Insert`、`*Update`、`*Delete`、`*DDL`、`*Show`、`*Set`、`*Call`、`*Begin`、`*Commit`、`*Rollback`
