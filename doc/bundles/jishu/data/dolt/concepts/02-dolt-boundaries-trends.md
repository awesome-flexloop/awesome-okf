## 性能数据与限制

### TPC-C 性能

根据官方 Sysbench 测试结果（F-042），Dolt 在 TPC-C 测试中 TPS 约为 MySQL 的 54%（F-043，✅ 官方确认：MySQL 97.52 TPS vs Dolt 53.03 TPS = 54.4%）。

作者认为 54% 对于大部分应用来说是够用的（F-044，作者观点）。对于读多写少或写入频率较低的场景，这一性能差距是可以接受的——毕竟你获得的是完整的版本控制能力。

> **⚠️ 口径细化**：官方 latency 文档（2026-05-14）同时显示，在 Sysbench 读写基准测试中，Dolt 的 read mean multiplier 为 0.83、write mean multiplier 为 0.91（<1 表示 Dolt 更快）。这意味着 Dolt 在简单读写场景下实际已超越 MySQL，博文"接近 MySQL"的措辞偏保守。

### 复杂查询性能

Dolt 对复杂查询比 MySQL 慢（F-046）。这是因为版本控制在查询执行层面引入了额外开销——每一次查询都需要考虑当前分支和历史版本的上下文。对于 OLTP 场景中的简单查询影响较小，但对于复杂 JOIN、子查询、聚合分析等场景，性能差距会比较明显。

### "1G 数据阈值"勘误 ⚠️

博文称"按照社区评价，Dolt 在处理超过 1G 数据时会变慢"（F-045）。**这是一处误读，已在 F-060 更正。**

| 维度 | 博文表述 | 官方正确口径 |
|------|---------|------------|
| 来源 | "社区评价" | 2021-05-26 DoltHub 官方博客 |
| 原文 | "Dolt 在处理超过 1G 数据时会变慢" | "About 1GB or smaller databases web queries will typically complete in a few seconds... Above that the query usually times out" |
| 适用范围 | 泛化为 Dolt 数据库本身 | 明确限定于 DoltHub Web UI 浏览器端查询 |
| 现状 | 仍被引用 | 2021 年过时信息，与当前 Dolt 生产性能无关 |

**结论**：Dolt 生产环境可处理 TB 级数据，官方声称支持百万级分支/版本。博文的"1G 阈值"说法是对 DoltHub Web UI 限制的不当泛化，不应作为 Dolt 本身的性能边界引用。

## 迁移成本与适用场景

### 不能"叠加"到现有数据库

Dolt 不能"叠加"到现有数据库上（F-047），需将数据迁移过来。若业务系统不能修改（F-048），Dolt 难以直接接管数据库。

更常见的做法是把数据定期同步到 Dolt，由 Dolt 负责记录和追踪数据变化（F-049）。这类似于把 Dolt 作为操作层/分析层的"镜像数据库"，而非替换生产库。

### 安装便捷性

Dolt 提供 Mac、Windows、Linux 三平台安装包（F-034），从 GitHub Releases 下载安装包（F-035）。安装后需设置用户名、邮箱等信息（与 Git 类似，F-036）。

### 适用场景

作者认为对于数据分析/数据科学团队，分支功能非常管用（F-058）。具体适用场景包括：

| 场景 | 适用性 | 说明 |
|------|--------|------|
| 数据分析/数据科学实验 | ⭐⭐⭐⭐⭐ | 分支隔离不同实验，互不干扰 |
| 数据库结构变更测试 | ⭐⭐⭐⭐⭐ | 在分支上测试 DDL，确认后再合并 |
| 多人协作的数据工作流 | ⭐⭐⭐⭐ | 分支 + 合并替代手动锁定 |
| 数据版本回溯与审计 | ⭐⭐⭐⭐⭐ | 行级历史记录，精确追溯 |
| AI Agent 数据操作沙箱 | ⭐⭐⭐⭐⭐ | MCP Server + 分支隔离，安全可控 |
| 高并发 OLTP 生产库 | ⭐⭐ | 性能开销较大，需谨慎评估 |
| 复杂分析查询密集型 | ⭐⭐ | 复杂查询性能明显低于 MySQL |

## 选型启示

### Git 理念向数据领域的延伸

Dolt 本质上是把 Git 的核心思想（分支隔离、提交快照、合并协同、历史追溯）移植到数据库层。这一移植的价值在于：

1. **开发体验一致性**：熟悉 Git 的团队可以快速上手
2. **数据实验的安全沙箱**：分支机制让数据实验不再有风险
3. **AI Agent 友好**：MCP Server + 分支隔离为 AI 数据操作提供了前所未有的安全边界

### 行业趋势观察

Dolt 的产品矩阵（Dolt/DoltHub/DoltLab/Hosted Dolt/MCP Server/Workbench）显示其正在从单一数据库产品向"数据版本控制平台"演进。MCP Server 的发布尤其值得关注——这标志着 Dolt 正在主动拥抱 AI Agent 生态，将自身定位为 AI 时代数据安全操作的基础设施。

经本地源码核验（①），这一趋势已进一步深化为 **"多协议版本化数据库生态"**（F-073）：同一套 Prolly Tree 存储引擎支撑 4 种数据库协议——MySQL（Dolt）、PostgreSQL（Doltgres，F-074）、SQLite（DoltLite，F-075）、MongoDB（DumboDB，F-076）——并通过 MCP Server（40+ 工具）与 Workbench（Agent Mode）统一接入 AI Agent。这种"一套存储引擎 + 多协议前端 + AI 统一接入"的架构，是 Dolt 区别于传统单一协议数据库的核心战略，也是"Git 理念向数据领域蔓延"的技术载体。
