## 关键事实登记

### F-001~F-003：GraphQL 的定义与边界

**信源**：Section 1 -- Overview.md

GraphQL 是一种查询语言，通过提供直观且灵活的语法与系统来描述客户端的数据需求与交互，以构建客户端应用。它有三个关键边界：

1. **不是通用编程语言**：GraphQL 不能进行任意计算，它专注于数据查询与交互描述。
2. **不绑定实现语言**：不强制要求实现它的应用服务使用特定的编程语言或存储系统。
3. **是应用层查询语言**：它位于客户端与后端服务之间，描述数据需求而非数据如何获取。

### F-004~F-009：五大设计原则

GraphQL 的设计围绕五个核心原则：

#### 1. Product-centric（产品中心）

GraphQL 由视图和编写视图的前端工程师的需求驱动，从他们的思维方式和需求出发构建语言和运行时。它不是由存储层或后端架构约束塑造的，而是由产品消费数据的方式塑造的。

#### 2. Hierarchical（分层）

GraphQL 请求本身是分层结构的，请求的形状与其响应中的数据形状一致。嵌套选择集对应嵌套响应对象，形成自然的树状同构关系。

#### 3. Strong-typing（强类型）

每个 GraphQL 服务定义一个应用特定的类型系统：
- 请求在该类型系统的上下文中执行
- 工具可以在执行前（开发时）确保操作在语法上正确且在该类型系统中有效
- 类型系统是契约，而非辅助文档

#### 4. Client-specified response（客户端指定响应）

- GraphQL 服务通过类型系统发布客户端允许消费的能力
- 由客户端负责指定如何消费这些能力
- 请求以字段级粒度指定
- 响应恰好包含客户端所请求的内容，不多不少

#### 5. Self-describing（自描述）

GraphQL 服务的类型系统可通过 GraphQL 语言本身查询，其中包含可读的文档。这一特性支撑了 GraphiQL、代码生成、IDE 支持等整个工具生态，也是 AI agent 自动发现 API 能力的基础。
