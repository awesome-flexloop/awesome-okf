# 任务优先评估与三条洞察

统一内存容量、低精度峰值、软件兼容与用户任务价值需要分别验收。下面的结论是基于事实台账的**本包分析**，不是 NVIDIA 官方结论或购机推荐。

## I-001 容量与速度分开验收

- **现象与证据**：官方宣传同时突出 128 GB 和 1 Petaflop，但 OEM 脚注分别限定共享可用空间与稀疏 FP4 理论峰值（F-007、F-013~F-014）。
- **根因解释**：容量决定工作集能否容纳；运算精度、内核、内存访问和负载决定任务速度。两种约束作用不同。
- **影响与反常识**：“模型装得下”不能直接证明“交互足够快”，即使二者出现在同一张宣传图。
- **建议**：先记录目标模型、量化、上下文、并发与可用内存，再测首 token 延迟、输出吞吐和正确性；不要先用峰值给出响应承诺。

## I-002 原生支持按依赖链判断

- **现象与证据**：新闻稿给整体包覆盖率，微软区分 CPU/CUDA 构建，并将新 Windows ML 路径标为 experimental（F-043~F-050）。
- **根因解释**：应用依赖锁、ABI、驱动、插件与 GPU 内核都可能有各自支持条件；全生态比例没有代替这些条件。
- **影响与反常识**：大部分包“兼容”仍不能证明自己的完整应用兼容。
- **建议**：列出关键依赖及锁定版本，按安装、正确性、GPU 执行、部署目标四层验收；实验 API 另设版本冻结与回退路径。

## I-003 本地执行与数据治理分开

- **现象与证据**：官方同时介绍本地智能体、OpenShell/MXC、PAIR 和本地/云端混合路由（F-019、F-024、F-026~F-028）。
- **根因解释**：推理位置、工具权限与数据传输是三个不同控制对象。
- **影响与反常识**：模型在本机不会自动令任务离线；家庭网络推理也不是同机保存。
- **建议**：画出模型、检索、工具、遥测和云回退的数据流，逐项确认授权；敏感任务用测试数据检验拒绝越界与关闭云回退的行为。

## 任务优先评估

“任务优先评估”是**候选方法 L1**：由本次发布资料解读形成，未经过两台设备或独立跨领域实测。它适用于硬件/软件平台购前技术可行性筛选与迁移试验，不适用于替代设备安全认证、投资回报评估或泛化预测性能。

### 无需购机的第一步

先填一张任务卡：目标任务、现有做法、成功条件、禁止外传的数据、必须使用的应用/插件、未知配置。比如“用本地助手整理测试目录；输出可人工核对；不得联网发送文件；模型与插件版本待查”。这是教学例子，不是已执行任务。

完成判据是能区分“资料已经说明”“需要厂商补证”“必须实机测量”三类信息。自测：有128 GB和本地模型，能否保证快速且完全离线？不能，分别缺任务性能与完整数据流证据。

1. **定任务**：用一个已有真实工作流界定成功条件，如模型任务完成率、项目可正确导出、游戏达到所需响应水平。
2. **定范围**：记录国家/地区、具体 SKU、内存、驱动、应用版本与插电条件。
3. **定口径**：区分权重与运行内存、峰值与持续吞吐、渲染帧与生成帧、支持声明与正式版本。
4. **测完整链**：运行实际输入，记录正确性、失败、延迟、峰值内存、持续功耗与网络流向。
5. **算成本并留退路**：汇总硬件、电力、软件、迁移、人工复核、失败返工及维护支出；关键依赖失败时保留原环境或转获批环境。禁止出云的任务必须停止或改用获批本地环境，不能为完成任务恢复云回退。

采购还需在同一评估周期和任务频次下，与现有设备及获批云方案比较增量成本和可兑现收益；节约机器时间不自动等于节省人工费用，没有收益证据不能宣称回本。商用准入另核具体版本的应用许可证、自动化调用、模型使用/再分发及素材权利；付费或本地运行不能代替授权。以上是本包建议，尚未完成许可审计。

### 反模式

| 反模式 | 本次资料中的风险入口 | 防护 |
|---|---|---|
| 峰值替代任务指标 | 稀疏 FP4、1440p 超过 100 FPS，F-013、F-053 | 固定负载，分别测算力相关任务与游戏响应 |
| 发布列表替代完整兼容性 | beta、后续支持、97% 包覆盖率，F-031、F-047 | 回读锁定版本，完成依赖链与插件测试 |
| 本地推理替代权限审计 | PAIR 与混合路由，F-026~F-028 | 确认数据流及拒绝越界行为 |
| 起价绑定最高配置 | 地区起价与最高 128 GB，F-004~F-009 | 获取目标 SKU 报价及配置单 |

这些是从资料暴露的误读风险，不是已经观察到的设备失败案例。

### 迁移与检验

**假设性跨领域迁移，未实测**：选工业视觉边缘盒子时，先用目标相机、真实分辨率与现场光照确认检测质量，再测端到端延迟、热稳定性、网络上送与断网恢复；不能只看芯片 TOPS。方法从个人 AI PC 转移到了工业设备，仍以真实任务、完整链和同口径测量为中心。

方法执行后应能拿出同一任务的输入、配置、日志与成功判定；“高配”“AI-ready”“支持”都不能单独作为验收结果。没有实机证据时，结论只能是资料充分性判断，而非性能通过。

## 待补证据

| 对象 | 要补的材料 | 判定用途 |
|---|---|---|
| 中国起价与具体配置 | 当地 OEM SKU 页面或采购报价 | 不将新闻起价当最终交易价 |
| 模型体验 | 固定模型/上下文的独立实测 | 容量、吞吐与质量 |
| 应用迁移 | 版本说明、依赖锁与自己的项目测试 | beta 与正式版本、插件与 CUDA |
| 游戏 | 固定设置的实测及兼容数据库 | 原生/生成帧、延迟与反作弊 |
| 本地治理 | 数据流、认证策略、权限拒绝日志 | 多设备与云回退边界 |

本包不替用户购买设备、不配置账户、不下载大模型、不运行付费云服务。2026-10-31及2026-11-30计划窗口结束时应复核对应支持；GA发布、延期、撤回或目标SKU/版本变化也应触发复核。2026-12-31为兜底到期日，并非已安排自动检查。
