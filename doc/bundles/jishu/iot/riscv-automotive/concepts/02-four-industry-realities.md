# 四个产业现实与边界

> 对应事实：F-018~F-028（核验状态见 [P0 核验报告](../references/verification.md)，V3/V6/V7/V8/V9/V10）

博文在给出"活路"之后并未止于乐观，而是列出**四个产业现实**作为边界条件。这一节是全文最"冷静"的部分，也是本包读法上最需要注意的地方。

## 现实一："换供应商不用重写软件"是理想上限，不是现状

这是作者对前文（[00 篇 §2 商业层主张](00-supply-chain-autonomy.md)）的**自我修正**（F-018）。原因在于（F-019 / F-020）：

- **指令集兼容 ≠ 外设、中断控制器、底层 HAL 全兼容**；
- 各家 RISC-V 车规 IP 的**自定义扩展仍有很大差异**。

核验以两个实证加强了这一判断（V6 ✅）：

- **中断控制器不一致**：RISC-V 的 PLIC 是事实标准，但实现差异关键——SiFive PLIC 支持 1024 个外部中断源，Andes PLIC 仅支持 256，且中断优先级编码方式不同（F-037）。
- **自定义指令不可移植**：RISC-V 自定义指令无法被标准工具链与第三方库直接识别，使用自定义指令的代码无法在其他 RISC-V 处理器上运行（F-038）。

真正平滑的迁移还需 **AUTOSAR 等上层抽象配合**（F-021）——核验佐证：经纬恒润完成 AUTOSAR 与 RISC-V 的全面适配（F-033，V7 ✅）。

> 结论：**"不重写软件"是目标上限，不是当下现状**（核验 V3 ⚠️）。

## 现实二：高安全等级的难点在认证，不在内核

作者判断，高安全等级真正的门槛不是能不能造出内核，而是认证（F-022）。具体来说是两个量级的叠加（F-023）：

- **单个内核拿 ASIL 认证并不难**；
- 难的是**整套 MCU 加工具链、编译器、调试器全链路通过 ISO 26262 认证**——周期长、成本高，这才是量产门槛。

核验给出可量化的产业锚点（V8 ✅）：

- ISO 26262 **ASIL-D** 从定级到安全机制设计全链路约需 **2 年**（F-039）；
- 编译器/代码生成器属 **TCL1（高影响）工具**，必须通过严格鉴定（FMEDA、失效模式分析、独立测试报告）（F-039）；
- RISC-V 工具链可走"**基于构造的鉴定**（Qualification by Construction）"路径，以 LLVM/GCC 的公开可分析编译流程证明优化通道的确定性与安全性（F-040）。

> 结论：**内核之外的工具链与认证链路，才是真正的量产门槛**（核验 V8 ✅）。

## 现实三：短期高安全核心仍以 ARM 为主流（双轨并行）

作者判断，短期看，动力、底盘、主域控等**高安全核心仍以 ARM 为主流**（F-024）；RISC-V 更多充当**第二供应链与自主可控备选**，**双轨并行**才是主流策略（F-025）。

核验状态为 ⚠️ **single-source（定性判断）**：目前**无量化权威源**可证"仍以 ARM 为主流"，且 DF30 已实现 ASIL-D 量产，格局处于变化之中（V9 ⚠️）。

> 结论：这是**趋势判断而非量化事实**——正文按作者判断标注，读者引用时应保留"定性"限定。

## 现实四：开源不等于无风险

作者提醒：指令集标准开源，但**商用车规 IP 多为厂商私有实现**（F-026）；开源代码本身**不附带安全资质**，仍需投入巨大的车规验证与软件成分分析成本（F-027）。

核验 ✅（V10）：RISC-V 指令集开源而商用 IP 多私有；功能安全工具链鉴定成本高，专有编译器动辄数百万美元且不可跨项目复用，开源工具链则需走前述"基于构造的鉴定"（F-040 / F-041）。

> 结论：**"开源"解决的是规范锁定问题，不解决认证与验证成本问题**（核验 V10 ✅）。

## 结语

博文以一句话收束：RISC-V 给汽车行业提供了摆脱**单一架构供应商绑定**的可能性，而**量产元年只是起点**（F-028）。

把它放回四个现实来看：RISC-V 的价值是**打开了第二条路**，而不是立刻替代 ARM；能否真正上位，取决于**生态能否被"冻住"**（[01 篇 §2](01-adoption-path-and-ecosystem.md)，F-017）以及**认证链路的成本能否被摊薄**（现实二）。
