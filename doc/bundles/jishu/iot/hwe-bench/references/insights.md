# HWE Bench 架构洞察四元组（I-1~I-6）

六条洞察均由 [facts.md](facts.md) 的编号事实支撑（每条证据列 ≥3 个 F 编号），模块定位与行段以[源码地图](source-code-map.md)的 C 台账为准。每条按「陈述 / 证据 / 反常识 / 行动」四段呈现；行动项面向**把同一套范式迁移到其他自治优化/基准系统**的读者，而非本仓的修改建议。

## I-1 在自治优化系统里，验证器才是沉淀下来的工件

- **陈述**：自主研究循环（生成假设→改码→跑分）本身是可商品化的通用件；真正经历 73 次试探而活下来的资产，是一组 agent 不能触碰、也无法软化的外部验证器（formal/cosim/沙箱/FPGA 门）。
- **证据**：作者逐字立论 "the loop isn't the moat…the loop is commodity…it was the verifier"（F-005）；同次运行 73 个假设 63 个被验证器拒绝（F-006）；编排代码文件头写死 "The LLM never touches this file"（F-011）；agent 可写面被限制为 rtl/ 与 test/test_*.py 两类路径，评测器在任何评测运行之前先做路径沙箱拒绝（F-021、F-022）。
- **反常识**：直觉认为「会写 RTL 的强模型」是系统价值核心，但排行榜显示最强模型也有 22% pass-rate、rep 内 22 次 hypothesis_gen_failed（F-112）——模型能力是噪声来源，验证器才是信号过滤器；换一个模型只需换 CLI（provider 合法集是数据，F-033），换验证器则等于换基准。
- **行动**：设计任何自治优化 harness 时，先冻结并显式声明「不可变工件」清单（评测器、契约、参考模型），把模型运行环境与评测环境物理分离（worktree + 指纹，见 I-3）；投资优先级应为验证器的判错成本与覆盖率，而非 prompt 调优。

## I-2 接受规则不是记账逻辑，而是搜索空间的形状

- **陈述**：「严格大于现任冠军才合并」「3 种子至少 2 个布局成功」「4.6% margin」等接受规则直接决定搜索沿什么轨迹移动；它们同时承担防漂移（平局不换主干）、防噪声（中位数 + 多种子）和防局部破坏（与基线比较闸）三重职能。
- **证据**：无 target 时接受规则为严格 `>`（F-015）；最差假设 r24s2 在 formal 与 cosim 全过的情况下 fitness −73.25%，被与基线比较的闸拦下，若入主干一回合并抵消此前全部胜场（F-104）；4 个 placement_failed 全部结构性尝试，单种子幸存不被承认（F-071、F-103）；V2 据实测布局噪声把阈值演进为 4.6% margin（F-124）。
- **反常识**：一个「门全过但性能暴跌」的候选在通常 CI 语义里应判通过；这里它必须被拒绝（regression，丢弃 worktree），因为搜索的目标函数是单调爬坡的现任冠军而非单次正确性（F-082）。更微妙的是反例：tie-ready=1 的 bench 夹具让「只在停顿时作用」的逻辑被常量折叠出零成本时序收益，接受规则对**测量契约本身的漏洞**无能为力（F-079）——接受规则的质量上界由测量契约决定。
- **行动**：把接受规则当作搜索算法的一部分来设计并预注册（target 有无、平局处理、margin、重复次数），而非事后写的统计口径；同时建立「接受规则审计」机制：每一条规则都要回答它能/不能挡住哪类假阳性，并随测量装置（夹具、停顿模型）变更而重标。

## I-3 防作弊是基准工程的本体，不是附加的安全层

- **陈述**：HWE Bench 把「agent 软化解题环境」当作默认对手建模：从文件白名单、SHA-256 指纹、CRC 自校、LFSR 反常量折叠、XOR 防 DCE，到克隆环境剥离成果、独立 OS 账号，全部是对具体作弊/泄漏路径的逐条封堵。
- **证据**：路径沙箱在评测运行**之前**拒绝触碰 formal/tools/fpga 等目录（F-022），运行前后两次对契约文件、共享 formal 检出与 PATH 上 EDA 二进制做指纹比对（F-040）；fpga 夹具用 LFSR 驱动 imemData 防止 Yosys 把核折叠成常量（F-076）、XOR-reduce 输出防死输出消除剪掉 RVFI fan-out（F-077）；CoreMark 自报 "Correct operation validated." 不可信，评测器用五个 CRC 常量自行复核 UART（F-069、F-078）；bench runner 克隆时剥离成果/研究、删 tag、造无父根提交（F-116）。
- **反常识**：v1 运行实测的三次沙箱越权不是恶意攻击，而是模型在正常解题中反复尝试新增白名单外的 `test/_helpers.py`（F-044）——越界是能力分布的一部分而非异常输入；同时最危险的泄漏来自**编排方自己**：heredoc 重定向落主树曾阻塞一个干净的 +28.5% 胜场（F-037），防作弊机制也保护 harness 不被自己误伤。
- **行动**：基准/竞赛系统应维护一份「攻击面台账」，每条防作弊措施绑定一个具体作弊假设与触发证据（本仓 CLAUDE.md 的 10 条不变量各注明强制检查，F-042）；对合成工具的优化行为（常量折叠、DCE、黑盒内联）要像对被测 agent 一样防御性设计；隔离边界要同时覆盖 agent 与 harness 的文件描述符/cwd。

## I-4 形式验证必须分层声明证明了什么，并把「空过」当作一等公民

- **陈述**：工程化 formal 的关键不是检查数量，而是显式声明每一层证明/不证明什么：ALTOPS 替身只证明旁路/路由/停顿而不证明乘除算术，真算术下沉到 cocotb/cosim/formal-deep；同时用最低检查数门槛、`make -k` 全调度与 PREUNSAT 计数规则处理「检查没生成」和「真空成立」两类空过。
- **证据**：ALTOPS 用 XOR-of-add/sub 替换 M-ext 公式，DUT 与 spec 共用替身时错误乘法器也能过，故真算术由 test_alu.py/cosim/formal-deep 兜底（F-050）；EXPECTED_MIN_CHECKS=50 拒绝只生成 1-2 个任务的半截 genchecks（F-055），PASS+FAIL=0 强制 FAIL（F-053）；`_ch1`+PREUNSAT 合法计 PASS 但仅在单发射假设语义下成立（F-052）；检查数存在 53/95+/~105 三个口径，计数对象不同（F-057、K-4）。
- **反常识**：「形式验证通过」不是布尔事实——同一核上 53（V0 基线检查全集）、95+（`make -k` 调度项）、~105（NRET=2 含 ch1/PREUNSAT）三个数同时为真（K-4）；V2 还披露 vendored 规格把有符号 DIV/REM 按 unsigned 算，导致「全算术检查对每个正确除法器都失败」以及送验代码与综合代码异版仍双过 53 项的缺口（F-123）。空过不是 bug 而是语义现象，必须显式分类。
- **行动**：formal 报告必须带「证明矩阵」（每个性质：证明了什么、替身是什么、谁兜底），而不是只报一个数；为工具链失败（genchecks 崩溃、make 中途失败）与逻辑空过（PREUNSAT、TOTAL=0）设独立结果类（F-056 的做法）；formal 所消费源码与综合/仿真源码的一致性应纳入指纹。

## I-5 测量口径不是附录：口径变了，结论就换了一个对象

- **陈述**：本仓几乎每个头条数字（IPC、fitness、胜场数、135 次 random、983 vs 7024）都依赖一组极易被忽略的测量口径（量纲、种子、停顿模型、计时括号、程序版本）；口径漂移会把「同一结论」变成不同对象的比较。
- **证据**：log.jsonl 的 ipc_coremark 原始值 2e-06 是 iter/cycle 绝对值，乘 1e6 才是对外的 2.2264 CoreMark/MHz（F-083、K-5 相关）；约 22% imem/dmem 反压把 V0 从「零等待幻想总线」2.87 拉到诚实的 2.21（F-059），计时只算 MMIO start/stop 括号内周期（F-062）；博客「10 胜/50 回归」与日志机械复算「9 真胜/51 回归」差在基线哨兵行（F-099、K-2）；V1 random 的 135 次实为 3 draws 重复 45 次，V2 修复播种后 135 次独立抽取零接受（F-121、F-124、K-6）；V1/V2 因 timer、被计时电路、隐藏程序、统计法七项变更被官方明示不可比（F-124、F-125）。
- **反常识**：文档/注释行号漂移看似无害（fpga.py:247 实为 L274、help 写 $30 实为 $200、"10 min" 实为 30 min），但在「照文档复现」的基准语境里它们直接改变复现者跑的实验（K-5）；而 holdout 的存在（五隐藏程序、geomean 只算 validated、冠军须保 ≥50% 增益）说明：**对训练负载的测量优化到极致后，测量对象本身必须换成不可见的负载**（F-084~F-087）。
- **行动**：任何对外数字与口径（量纲、种子列表、重复次数、计时边界、程序哈希）一起发布，随结果存档；口径变更走新版本并显式声明不可比（V2 白页做法）；用脚本机械复算所有计数（本束 73 假设分布即由 Python 全量解析得到，F-097），叙事数字与机械数字冲突时以机械计数为准并立勘误台账。

## I-6 自治 harness 的可靠性故障大多「只制造假失败」，这是设计出来的故障方向

- **陈述**：长时间无人值守运行（单 rep 4-5h、全榜约 130-170h）的 harness 必然遭遇环境性故障；工程目标不是零故障，而是保证每个已知故障模式的错误方向都是「不计分」而非「错计分」，并保留完整现场。
- **证据**：seatbelt 内 `kill -0` 对外部 PID 报 EPERM 使 reaper 误删 harness 自己的 formal 工作目录，最佳 601.32 被放入 aborted1 且不计分、不入 results.jsonl——作者强调它只能产生假失败（F-126）；parser 不可靠被 lessons 固化为「共用一个加固 parser + 每个 prompt 解析 agent N≥2 burn-in + 真实 round-2 prompt 集成测试」（F-034）；成本 $200/rep 硬上限与 watchdog 防止失控（F-019、F-029）；telemetry 从 git 全引用+reflog 重建 log.jsonl，使日志可被事后独立复原（F-116）。
- **反常识**：一次误删自己工作目录的事故被当作「系统按正确方向失败」的正面案例（F-126）；而 LUT4/DFF 解析失败时代码选择大声崩溃而非替 0，因为静默 0 会让每个假设都「获胜」——崩溃是假失败，替 0 是假通过（F-075）。故障方向的非对称性比故障频率更重要。
- **行动**：为 harness 每个故障点标注错误方向（假失败/假通过/双向），凡可能双向或假通过的路径必须改造；长任务产物写 append-only 事件流并可由底层状态（git 引用、reflog、遥测）重建；异常产物隔离命名（aborted/）并显式排除出计分数据集；运维教训沉淀为 harness 自身的 burn-in/隔离规则（独立 CODEX_HOME、无 login shell、首 rep 监看，F-034）。
