# Docker 镜像构建

本例演示如何使用 constructor 生成 Docker 镜像，用于容器化部署 Python/conda 环境到服务器或 Kubernetes 集群。

## 前提条件

- 构建机器运行 Linux（或 Linux VM/WSL2）
- 安装 Docker 和 buildx：
  ```bash
  docker buildx version
  ```
- 安装 constructor 和 conda-standalone

## 场景 1：生成 Dockerfile（手动构建）

适用于 CI/CD 流水线中单独控制 Docker 构建步骤。

### construct.yaml

```yaml
name: mypython
version: "1.0"

installer_type: docker
docker_base_image: debian:bookworm-slim

channels:
  - conda-forge
specs:
  - python=3.14
  - pip
  - conda

# Docker 特定配置
default_prefix: /opt/conda          # 容器内安装路径
initialize_conda: true
keep_pkgs: false                    # 减小镜像体积
docker_labels:
  org.opencontainers.image.description: "My Python 3.14 runtime"
  maintainer: "dev@example.com"
```

### 构建

```bash
constructor . -o ./dist
```

### 输出

```
dist/
├── mypython-1.0-Linux-x86_64.sh     # SH 安装程序（Docker构建的输入）
└── Dockerfile                        # 生成的 Dockerfile
```

### 查看 Dockerfile

生成的 Dockerfile 大致内容：

```dockerfile
# Generated by constructor 4.x
FROM debian:bookworm-slim

LABEL org.opencontainers.image.title="mypython"
LABEL org.opencontainers.image.version="1.0"
LABEL org.opencontainers.image.description="My Python 3.14 runtime"
LABEL maintainer="dev@example.com"

ARG PREFIX=/opt/conda
ENV PATH="${PREFIX}/bin:${PATH}"

COPY mypython-1.0-Linux-x86_64.sh /tmp/installer.sh
RUN apt-get update && apt-get install -y --no-install-recommends \
        bash bzip2 ca-certificates curl && \
    rm -rf /var/lib/apt/lists/* && \
    bash /tmp/installer.sh -b -p "${PREFIX}" && \
    rm /tmp/installer.sh && \
    "${PREFIX}/bin/conda" clean -afy && \
    "${PREFIX}/bin/conda" init --all

CMD ["/bin/bash"]
```

### 手动构建镜像

```bash
cd dist
docker build -t mypython:1.0 .
docker run --rm mypython:1.0 python --version
```

## 场景 2：一键构建并导出镜像 tar

constructor 可直接调用 docker buildx 构建镜像并导出为 tar 文件，方便离线分发。

### construct.yaml

```yaml
name: myservice
version: "2.0"

installer_type: docker
docker_base_image: debian:bookworm-slim
docker_image_format: tar           # 导出镜像为 tar
docker_tag: "myservice:2.0"

channels:
  - conda-forge
specs:
  - python=3.14
  - conda
  - pip
  - fastapi
  - uvicorn
  - pydantic
  - sqlalchemy
  - psycopg2
  - redis-py
  - gunicorn
  - python-multipart

default_prefix: /opt/conda
initialize_conda: false            # 容器中不需要 conda init
keep_pkgs: false
register_envs: false

docker_labels:
  org.opencontainers.image.description: "MyService API backend"
  org.opencontainers.image.source: "https://github.com/example/myservice"
```

### 构建

```bash
constructor . -o ./dist
```

### 输出

```
dist/
├── myservice-2.0-Linux-x86_64.sh
├── Dockerfile
└── myservice-2.0-Linux-x86_64-docker.tar   # Docker 镜像 tar
```

### 加载和运行

```bash
# 加载镜像
docker load -i dist/myservice-2.0-Linux-x86_64-docker.tar

# 运行
docker run -d -p 8000:8000 myservice:2.0 \
  gunicorn myservice.main:app -w 4 -k uvicorn.workers.UvicornWorker -b 0.0.0.0:8000
```

### 推送到镜像仓库

```bash
docker tag myservice:2.0 registry.example.com/myservice:2.0
docker push registry.example.com/myservice:2.0
```

## 场景 3：多阶段构建优化镜像

对于生产环境，可手动修改生成的 Dockerfile 使用多阶段构建来减小镜像体积：

```dockerfile
# 构建阶段
FROM debian:bookworm-slim AS builder
COPY myservice-2.0-Linux-x86_64.sh /tmp/installer.sh
RUN bash /tmp/installer.sh -b -p /opt/conda && \
    /opt/conda/bin/conda clean -afy

# 运行阶段（仅复制安装结果）
FROM debian:bookworm-slim
COPY --from=builder /opt/conda /opt/conda
ENV PATH="/opt/conda/bin:$PATH"
RUN apt-get update && apt-get install -y --no-install-recommends ca-certificates && \
    rm -rf /var/lib/apt/lists/*
CMD ["/bin/bash"]
```

## 场景 4：Kubernetes Deployment 示例

构建完成后，在 K8s 中使用：

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myservice
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myservice
  template:
    metadata:
      labels:
        app: myservice
    spec:
      containers:
      - name: myservice
        image: registry.example.com/myservice:2.0
        ports:
        - containerPort: 8000
        command: ["gunicorn"]
        args: ["myservice.main:app", "-w", "4", "-k", "uvicorn.workers.UvicornWorker", "-b", "0.0.0.0:8000"]
        env:
        - name: DATABASE_URL
          valueFrom:
            secretKeyRef:
              name: myservice-secrets
              key: database-url
        resources:
          requests:
            memory: "512Mi"
            cpu: "500m"
          limits:
            memory: "2Gi"
            cpu: "2000m"
```

## 基础镜像选择建议

| 基础镜像 | 大小 | 兼容性 | 适用场景 |
|---------|------|--------|---------|
| `debian:bookworm-slim` | ~80MB | ✅ glibc | 推荐：平衡大小和兼容性 |
| `ubuntu:24.04` | ~180MB | ✅ glibc | 需要 Ubuntu 特定包 |
| `debian:bookworm` | ~120MB | ✅ glibc | 需要更多系统工具 |
| `alpine:latest` | ~5MB | ❌ musl | **不兼容** conda 包 |
| `registry.access.redhat.com/ubi9/ubi-minimal` | ~100MB | ✅ glibc | RHEL/OpenShift 环境 |

> ⚠️ **不要使用 Alpine**：conda 包编译时链接 glibc，Alpine 使用 musl libc，二进制无法运行。

## 减小镜像体积的技巧

1. **`keep_pkgs: false`**（默认）：安装后删除包缓存
2. **`initialize_conda: false`**：容器中不需要 conda init shell hook
3. **不安装 conda**：如果容器只运行 Python 应用，可以使用 `base_needs_python` 相关逻辑或只装最小依赖
4. **conda clean**：Dockerfile 中 RUN 命令末尾添加 `conda clean -afy`
5. **多阶段构建**：分离构建和运行阶段，仅复制 `/opt/conda`
6. **--no-install-recommends**：apt-get 安装系统依赖时使用
7. **合并 RUN 层**：减少 Docker 镜像层数

## CI/CD 集成（GitHub Actions 示例）

```yaml
name: Build Docker Image
on:
  push:
    tags: ["v*"]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Conda
        uses: conda-incubator/setup-miniconda@v3
        with:
          environment-file: environment.yml
          activate-environment: build

      - name: Install constructor
        run: conda install -y constructor conda-standalone

      - name: Build installer and Dockerfile
        run: constructor . -o dist/

      - name: Build and push Docker image
        uses: docker/build-push-action@v5
        with:
          context: dist/
          push: true
          tags: |
            ghcr.io/${{ github.repository }}:${{ github.ref_name }}
            ghcr.io/${{ github.repository }}:latest
```

## 多架构构建（amd64 + arm64）

constructor 支持交叉构建，但 Docker 多架构需要 QEMU：

```bash
# 注册 QEMU 模拟器
docker run --privileged --rm tonistiigi/binfmt --install all

# 创建 buildx builder
docker buildx create --name multiarch --use

# 构建两个架构
constructor . --platform linux-64 --conda-exe /path/to/linux-64/conda.exe -o dist-amd64/
constructor . --platform linux-aarch64 --conda-exe /path/to/linux-aarch64/conda.exe -o dist-arm64/

# 用 buildx 构建并推送多架构镜像
docker buildx build --platform linux/amd64,linux/arm64 \
  -t mypython:1.0 --push dist-amd64/
```
