# 03 · 投稿表单与合规条款

> 本篇是**最容易直接出局**的一章。细则正文只写「提交以下信息：社媒发布链接、作品介绍、UserID、联系方式**等**」（F-022）——那个「等」字后面的全部内容，在 `openForm()` 定义的 8 项字段与前端校验逻辑里。读规则只读到细则，会漏掉本篇大半内容。

## 1. 有效投稿：一份排除项清单，不是「做完就有效」

把分散在细则四处与表单提示语里的门槛合并，得到一张**必须全部避开**的清单（方案层 B-1~B-5 据此设立阻塞决策点）：

| # | 排除项 | 出处 |
|---|---|---|
| 1 | 未使用混元 Hy4 完成真实创作/任务 | F-015、F-055 |
| 2 | 社媒未发布 / 未同时带 `#WorkBuddy` `#Hy4` | F-019、F-021、F-032 |
| 3 | 帖子非公开可见 / 链接活动期内不可正常打开 | F-032 |
| 4 | 创作过程截图或录屏中看不到模型已选择为 Hy4 | F-020、F-042 |
| 5 | 无有效 WorkBuddy 账号 / 未通过活动入口投稿 | F-054、F-059 |
| 6 | 只提交创意说明或未公开发布的内容 | F-055 |
| 7 | 作品非活动期（11-04—11-15）新创作，或已投过其他活动/评奖 | F-056 |
| 8 | 8 项表单字段任一缺失或校验未过 | F-041、F-050、F-051 |

> **状态语义（本包推导）**：「有效投稿」在本活动里是一个**合取条件**——任一排除项命中即无效，且无效投稿「不进入评审」（F-032）。这与「先做作品、再补齐形式」的直觉相反：形式项不是加分项，是资格项。见 [04 · I-02](04-mechanism-insights.md)。

## 2. 8 项字段逐条拆解

表单标题「提交我的真实体验」，8 项 `<label>` **均带必填星号 `*`**（F-041）。下表按 `openForm()` 中的 01—08 顺序：

| # | 字段 | 控件与限制 | 提示语要点 | 事实 |
|---:|---|---|---|---|
| 01 | 您的作品链接 | `input[type=url]` | 公开可见、可正常打开、带两个话题标签；**过程截图/录屏需能看到模型已选择为 Hy4**；社媒数据将用于核验与评分（占 70 分） | F-042 |
| 02 | 您上传作品的平台（单选） | 6 个单选项 | `FORM_OPTIONS.platforms`：B站 / 小红书 / 公众号 / 视频号 / 抖音 / 其他 | F-043 |
| 03 | 使用场景标签（单选） | 7 个单选项 | `FORM_OPTIONS.types`：视觉理解 / 长程任务 / 办公文档 / 电脑操作 / 硬核推理 / 日常工作 / 其他 | F-044 |
| 04 | 内容介绍 | `textarea`，`maxlength=2000`，计数器 `0/2000` | **不少于 30 字**；简述使用 WorkBuddy × 混元 Hy4 的具体场景 | F-045 |
| 05 | WorkBuddy 创作对话记录 | `input[type=url]` | 用于核验作品确由本人在 WorkBuddy 创作；**分享前确认对话不含个人隐私、商业机密**；附获取分享链接指引图与三步操作（右上角「分享」→ 选择对话 → 底部「链接」复制）；**提交前建议重新打开链接确认评审可正常访问** | F-046 |
| 06 | 您的 UserID | `input[type=text]`，`maxlength=64` | 「不是邮箱/微信/手机号」，在 WorkBuddy 客户端左下角头像处可查看复制；附指引图 | F-047 |
| 07 | 联系方式 | `input[type=tel]`，`maxlength=11` | 大陆手机号；「仅用于获奖后的通知及联系发放奖品」；**联系方式不公开展示**、活动结束后按细则处理 | F-048 |
| 08 | 参赛授权 | `checkbox` | 「我已阅读并同意《…活动细则》，并授权主办方在本次活动及相关宣传中使用我提交的内容」；**未满 18 周岁应事先取得监护人的同意和指导** | F-049 |

表单顶部三条引导语（F-041）：用 Hy4 完成一次真实任务并分享出来；社媒需带 `#WorkBuddy #Hy4`；投稿征集期 11-04—11-15 23:59「如有调整，以活动页公告为准」。另有一条醒目提示：「请确保分享内容合法合规，使用脱敏材料，不要上传敏感、保密或未经授权的信息」。

**平台与场景标签的纪律**：细则正文列举的社媒平台是「小红书/抖音/视频号/公众号/B站等」（F-019），表单选项是含「其他」的 6 项（F-043）——两者不同源、不同粒度，本包不把任一方写成另一方的官方解释。场景标签 7 项与「建议任务方向」6 类（F-018）也不是同一套枚举，**不可混用**；选标签是表单必填动作，不是命题约束。

## 3. 前端硬校验链：提交按钮按下后发生什么

`submitWork()` 的校验顺序（F-050）：

1. `submitClosedNow()` → 超过 `SUBMIT_END` 直接 toast「投稿已截止，暂不能再提交」，注释写明**含缓存旧页面打开的表单也硬拦截**；
2. `canSubmit()` → 必须处于公开视图或内测视图**且** `phaseNow().k === "submit"`；否则拒绝；
3. 平台、场景标签必选；内容介绍 `raw.length >= 30`；`url` 与 `conversation` 必须匹配 `^https?://`；
4. `uid` 非空；手机号匹配 `^1[3-9]\d{9}$`；授权勾选框必须勾选；
5. `auditSubmission()` 内容安全检查（命中则返回字段名与分类，提示修改后再提交）；
6. 公开视图下需已登录 WorkBuddy；`getCurrentUid()` 返回的当前登录账号**必须与填写的 UserID 一致**，否则报「填写的 UserID 与当前登录账号不一致，请检查」（F-051）。

提交成功后：生成 `SHY4-<时间戳>-<随机码>` 提交编号与提交时间，写入**独立投稿池**（`buildSubmissionProperties()` 落库 11 项），联系方式经 `saveContact()` 单独保存，随后清空本地草稿（F-053）。落库字段中「投稿归属账号ID」「提交编号」「提交时间」为系统生成，表单 8 项里的「联系方式」不落在主投稿池（C-07 ✅）。

**三处不可逆 / 不可回退（F-053）**：代码注释两处明确「本活动仅收集投稿，不提供审核驳回或重新上墙的修改模式」「本活动不提供审核后修改投稿」；`FORM_EDIT=null` 恒为空。因此**提交即定稿**，没有「先交一版再补」的余地。草稿只存在浏览器 `localStorage`（键 `wb_hy4_tmLICh_draft_copy_v2`），换设备或清缓存即丢，不能当备份。

## 4. 参与条件与资格取消

**三项有效参与条件（F-054~F-056）**：① 拥有有效 WorkBuddy 账号并通过活动入口完成投稿；② 使用 Hy4 完成**本人真实创作/任务**并按要求发布社媒、提供**可核验的发布链接**，仅提交创意说明或未公开发布的内容不视为有效投稿；③ 作品须在本活动期间（2026-11-04—11-15）用 Hy4 **新创作完成**，此前已参加过其他活动征集或评奖的作品不参与本活动评奖。

**8 类资格取消（F-057）**：细则写「若有下列任何一种行为或情况的，主办方有权单方面取消你的参与资格、获奖资格等，已经发放的奖品有权追回」——

| # | 情形（原文压缩转录） |
|---:|---|
| (1) | 不符合参与资格的 |
| (2) | 同一用户、同一手机号、同一设备、同一账号或经合理判断为同一实际参与主体**重复提交**的（主办方有权仅认定首次有效投稿或取消相关资格） |
| (3) | 提供虚假信息的 |
| (4) | 虚假交易或恶意破坏活动的（含刷赞、刷收藏、使用第三方刷量工具或服务） |
| (5) | 以机器人/蜘蛛/爬虫/刷奖软件或其他自动方式、不正当手段参与的 |
| (6) | 违反诚实信用、公序良俗、公平、公正原则的 |
| (7) | 提交违法违规或侵权内容的 |
| (8) | 其他违反相关法规、本规则行为的 |

第 (2) 项与「撤回后不可重复提交」（F-062）共同构成一账号一次投稿的实际约束；F-059 另写「**每个账号仅可参与本活动一次**」。第 (4)(5) 项与评分章 F-031 的刷量剔除条款从行为侧与数据侧双向覆盖（C-08 ✅）。

**有效发放三要件与异常发放（F-058）**：奖励发放须同时满足——① 发放对象具备参与资格且未违反本规则；② 奖励种类/数量/面值与活动载明一致；③ 发放过程未受异常情形影响；任一不满足不构成有效发放。因系统漏洞、程序缺陷、配置错误、数据同步异常、库存超卖、网络攻击、第三方服务中断、不可抗力等非主办方真实意思表示的原因导致少发/多发/错发/重复发放的，该发放**自始不发生给付效力**；主办方可冻结或收回，无法原状返还的应返还等值价款，通知后 **15 日**内未返还的可从其他奖励/收益/应付款中抵扣并保留追偿权；确属应发未发的应在合理期限内补发或经同意以等值替代礼品履行。

**活动资格（F-059）**：面向所有已注册 WorkBuddy 账号的用户，须使用有效账号参与；每账号仅可参与一次；活动中获得的积分奖励在同一账号下的 WorkBuddy 与 CodeBuddy 等产品端之间**互通共享、统一计算**；未满 18 周岁用户应事先取得监护人同意和指导，主办方有权依法律法规对未成年参与行为合理限制。

## 5. 内容要求：脱敏是硬要求，不是建议

- **F-060**：保证投稿内容为本人独立制作、不侵犯第三方合法权益（著作权、商标权、形象权、名誉权等）；**应避免展示、上传或披露任何保密信息、商业秘密、客户信息、个人信息或第三方受保护内容；如需展示工作流，请使用脱敏、示例化或公开资料**。表单顶部「使用脱敏材料」提示与此同向。
- **F-061**：不得含有违法违规、危害国家安全统一、破坏社会稳定、违反公序良俗、侮辱诽谤淫秽或性暗示、暴力；侵害名誉权/肖像权/知识产权/商业秘密；涉及他人隐私、个人信息；骚扰、广告、垃圾信息；恶意虚构事实、隐瞒真相等内容。与参与方式处的 F-016 红线（命理预测、金融理财建议、政治时政敏感议题）合并构成完整内容禁区。
- **F-063**：一旦发现含前述内容，主办方有权取消参与或获奖资格并要求删除、修改；因违反投稿规则或第三方平台规则导致国家机关诉讼/罚款/行政制裁或第三方受损的，投稿者承担全部责任并赔偿主办方或第三方损失。

> **与 05 篇的关系**：本库的 `guoxue/`、`yixue/`、`sheke/minsu/` 等束含命理、术数、民俗类正文，展示工作流时若直接截这些页面，会同时碰到 F-016 与 F-060 两条。方案层把「选题绕开敏感正文 + 全程脱敏」列为阻塞决策点 B-2，并在 §7 合规四层自查中逐层核。

## 6. 撤回、投诉与知识产权

**撤回（F-062）**：可在**投稿截止前**发邮件至 `workbuddy@tencent.com` 提交撤回申请；撤回成功后**不再参与评审且不可重复提交**；截止后不再接受撤回申请；撤回**仅影响活动评审资格，不当然导致第三方平台已发布内容自动删除**，需自行按平台规则操作。撤回处理时限与确认方式官方未给（G-10）。

**投诉举报（F-064）**：发现展示投稿侵犯合法权益或违反法律法规的，可发同一邮箱投诉举报，主办方「将在审核后及时处置并告知您结果」。

**知识产权三条（F-065~F-067）**：

| # | 条款要点 |
|---|---|
| (1) | 用户**保留**投稿内容的知识产权；授予主办方及关联公司一项**免费、非独占、可转授权给活动合作方**的使用许可，范围限于活动组织、评审、公示、奖品发放、活动宣传及案例展示、官方案例库模板复用所**必要**的复制、展示、传播、编辑排版及合理改编；**不改变权利归属** |
| (2) | 投稿含主办方知识产权（含 WorkBuddy 商标）时，未经授权**仅限用于本次活动**；可在活动指定或认可的平台发布含 WorkBuddy 名称/商标/界面的内容，但仅限参与本活动及非商业展示目的，**不得**用于无关的商业盈利、误导性宣传或损害品牌权益，**不得擅自转发至其他平台**，不得用于出版、商业盈利或二次创作；违反可被取消资格并追责 |
| (3) | 授权主办方以自己名义或委托第三方**代维权**（监测、维权函、诉讼/仲裁、调解、和解），主办方独立决策实施，用户有配合义务 |

> **F-066(2) 是一处容易忽略的边界**：它限制了「同一份投稿内容再转发到其他平台做二次传播」的自由度。方案层据此把「一稿多平台分发」标为需确认项（G-13），默认按单一平台单帖发布执行，避免与「不得擅自转发至其他平台」相抵。

**其余条款（F-068~F-072）**：第三方平台发布内容同时受该平台用户协议及规则约束（权利声明）；不可抗力/第三方平台/网络安全事件/系统故障等可调整、暂停或终止活动，用户自身网络设备原因不担责，用户自行确保参与行为合法合规；主办方有权在**提前通知**前提下合理调整规则，调整后规则在活动页面公示；适用中华人民共和国大陆地区法律（不含冲突法），争议提交**规则签订地深圳市南山区**有管辖权的人民法院；本规则与《WorkBuddy 软件许可及服务协议》《WorkBuddy 隐私保护指引》共同构成完整协议，任一条款无效不影响其余效力。

> **复核触发（M-08、T-1）**：F-070「调整后的规则将在活动页面公示」+ F-005/F-006「如有调整，以活动页公告为准」共同说明——本包所有规则的复核触发条件是**活动页公告变更**，而不是 `stale_after` 日历到期。检测表见 [核验报告 §6](../references/verification.md)。
