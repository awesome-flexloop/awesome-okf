# 01 · 活动事实与采集链路

> 本篇每条规则陈述挂 F 编号。事实原文见 [事实底账](../references/facts.md)；口径张力与核验结论见 [核验报告](../references/verification.md)。

## 1. 活动是什么

活动全称为「WorkBuddy × 混元 Hy4「体验官」征集活动」（F-001）。细则写「本次活动**拟由**腾讯云计算（北京）有限责任公司举办」，主办方自称「主办方」（F-002）——「拟由」是细则原文措辞，本包不改写为既成事实。

活动邀请用户在 WorkBuddy 中使用混元 Hy4 模型完成一次**真实的创作或办公任务**，并将创作过程、成果与真实使用感受发布至社交媒体平台（F-003）。这句话里有三个不可拆的约束：**真实任务**、**Hy4 模型**、**公开发布**。少任何一个，后续评分公式都无从谈起。

流程为五步：使用 Hy4 完成任务并发布社媒 → 提交投稿信息 → 投稿截止后统一核验社媒数据并评审 → 公布结果及发奖（F-004）。

> **注意时序反直觉处**：投稿提交发生在社媒发布**之后**，而社媒数据核验发生在**投稿窗口关闭之后**。这两点共同决定了本活动不是「先报名再开发」的结构，判型结论见 [05 §1](05-participation-plan.md)。

## 3. 有效参与的三个动作

**动作一 · 用 Hy4 完成真实任务**（F-015）。细则同时给出六个「建议任务方向（灵感参考，场景不限）」（F-018）：读图能力实测、一口气提一堆要求（长程任务）、办公场景实测、让它替你操作电脑、拿硬核难题考它、用真实工作来测。

> 「场景不限」是原文。六方向只是灵感参考，**不构成命题约束**——这是本活动判为「自选型」而非「命题型」的依据（方案层 [05 §3](05-participation-plan.md)）。

内容红线在参与方式处即出现：不得提供违反社会公序良俗或法律法规要求的内容，细则点名禁止算命、占卜、塔罗牌占卜、八字排盘、星盘占星等命理预测功能或内容，涉及股票、基金、期货等金融理财建议的内容，涉及政治、时政等敏感议题的内容（F-016）；主办方结合内容实际情况及展示文案审核，不符合要求的内容不予展示或参与评奖（F-017）。

**动作二 · 社媒发布三部分内容**（F-019、F-020）。整理为图文或视频，发布至任一社交媒体平台（小红书 / 抖音 / 视频号 / 公众号 / B站等），并**同时**带上话题标签 `#WorkBuddy` `#Hy4`。三部分为：

| # | 内容 | 细则明确的可举证要求 |
|---|---|---|
| ① | 创作过程 | 操作 / Prompt / 生成过程展示，**截图或录屏画面中需能看到模型已选择为 Hy4** |
| ② | 结果展示 | 最终产出效果 |
| ③ | 真实使用感受 | 真实反馈文字（效率提升、体验亮点、与以往体验对比等） |

细则用加粗写明：参与者**必须**完成社媒发布方视为有效投稿；未发布社媒或未带活动话题标签的投稿不计入评选（F-021）。这一条在评分章节以「参与门槛」再次出现（F-032），两处口径一致。

**动作三 · 提交投稿信息**（F-022）：通过活动页投稿收集表提交社媒发布链接、作品介绍、UserID、联系方式等。表单实际 8 项字段见 [03 §2](03-submission-and-compliance.md)。

## 4. 授权与信息处理

提交投稿即视为同意授权主办方为本活动及相关宣传推广、产品官方案例库模板等目的使用该内容，包括展示、复制、改编及通过各类渠道传播（F-023）。同时细则给出两条限定：涉及肖像、语音、城市等非必要信息的公开展示或推广宣传使用，将**另行取得单独同意**；用户拒绝非必要信息公开授权的，**不视为放弃奖项**（F-024）。收集到的用户信息将在活动结束后予以删除；但拒绝提供奖品发放所必需信息的，主办方有权视为放弃奖项（F-025）。

> **对参赛者的实际含义（方案）**：授权是提交动作的附随效果，不是可选项；但「非必要信息」的单独同意与「拒绝不视为放弃奖项」是明确写进细则的用户权利。展示工作流时应使用脱敏、示例化或公开资料（F-060），这既是内容要求，也降低授权范围争议。

## 5. 采集链路：为什么不能只读页面首屏

活动页 `www.workbuddy.link/p/<nodeId>` 是客户端渲染的单页应用。直接请求只得到 5,844 字节外壳，正文为空，`<title>` 之外几乎无文本（M-02）。这正是参赛作战手册采集阶梯里 L1「静态直读」会误判为「已采集」的空壳页面。

本包实际走的是 **L1 → L3 SPA 引导数据逆向**：

| 级 | 动作 | 结果 |
|---|---|---|
| L1 | 静态 HTML 直读 | 仅得标题与 `window.__PUBLISH_BOOTSTRAP__` 引导数据（nodeId `tmLIChKEjyBNv8UQXxD29c`、`publishVersion: 12`、artifact 清单 2 项） |
| L3-a | 从引导数据取静态托管目录 | `https://workbuddy-space-static.codebuddy.work/page/tmLIChKEjyBNv8UQXxD29c/axS-bAKLmFby/` |
| L3-b | 下载两个 artifact | 正文 HTML 186,585 字节；`janus.data.json` 状态树 235,566 字节（M-03） |
| L3-c | 从状态树文本节点取正文 | 首屏文案 897 字符；细则全文在 JS 的 `ruleHTML()` 返回字符串里；投稿表单在 `openForm()`；时间轴在 `SUBMIT_END` / `PHASES` 常量（M-04） |

未使用 L4 浏览器渲染——L3 已取得完整规则文本（M-05）。页面带 `noindex, nofollow`，`userinfo` 接口对未登录返回 `code: 11607 / not login`，说明活动页公开内容无需登录即可读取（M-06）。

> **为什么这节值得单独写**：如果止步于首屏，会漏掉 8 类资格取消情形、8 项表单字段、撤回与投诉邮箱、知识产权条款、刷量异常剔除规则——也就是参赛方案里全部「可能直接出局」的部分。**规则页能打开 ≠ 规则能读到**。
