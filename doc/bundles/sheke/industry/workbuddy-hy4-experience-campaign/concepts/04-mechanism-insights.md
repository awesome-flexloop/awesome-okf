# 04 · 机制洞察

> **整篇都是「洞察/推断」，不是主办方口径。** 每条按七概念 G2 门给出**陈述 / 证据 / 反直觉推断 / 行动**四元组；证据只挂 F 编号，推断不写进事实层。G3 门的跨场景迁移判定见 §5 与 [核验报告 §3](../references/verification.md)。

## I-01 · 70 分是相对量，30 分才是绝对量

| 四元组 | 内容 |
|---|---|
| **陈述（洞察/推断）** | 100 分里，只有 20+10 = 30 分的取值不显式依赖其他投稿；70 分的取值由「本投稿 ÷ 全场最高」定义，分母在参赛者控制之外。努力能**直接**改善的是分子与那 30 分，不是分母。 |
| **证据** | F-026（70/20/10 三分）、F-027（归一化公式逐字）、F-028、F-029（两项均为评委打分，标准里不含他人数据的量）、F-030（数据以核验时平台公开显示为准） |
| **反直觉推断（洞察/推断）** | 「社媒占 70 分」最容易被读成「这是一场传播比赛，应该把力气花在涨粉和投放上」。但公式是**归一化**的：把全场最高者同时抬高一倍，所有人的 70 分都不变。也就是说，提高自己数据的边际收益取决于一个自己看不到的量——这正是相对量的特征。而 20 分那句「Hy4 能力体现是否清晰可信」是可以在内容里直接做实的。 |
| **行动（方案）** | 投入顺序：先把 20+10 分对应的**内容完整性与过程可举证性**做到无短板，再在窗口内让帖子自然获得真实互动；不买量、不刷量（F-031、F-057(4)(5) 会直接取消资格），不把分母当可控变量，不据此推算任何分数或名次。落点见 [05 §4](05-participation-plan.md)。 |

> **边界**：本条不声称 30 分「更重要」（权重明摆着是 70 更大），只声称 30 分是**唯一不依赖他人的量**。官方未给分数分布与评委机制（G-01、G-02），故不评估两部分对最终排序的实际影响。

## I-02 · 有效投稿是「排除项清单」，不是「做完就有效」

| 四元组 | 内容 |
|---|---|
| **陈述（洞察/推断）** | 本活动的有效资格是一个**合取式排除清单**：真实任务、模型为 Hy4、本人创作、活动期新作、社媒公开、双标签、链接可打开、过程可见模型选择、账号与 UserID 一致、8 项表单齐全、授权勾选——任一命中即「不进入评审」。没有「作品足够好可补正形式」的通道。 |
| **证据** | F-015、F-019~F-021、F-032、F-041、F-050、F-051、F-054~F-056；细则两处用「必须」「不进入评审」而非「建议」 |
| **反直觉推断（洞察/推断）** | 按「先报名→再开发→最后提交作品」的经验，形式材料常被视为可后补的手续。本活动的时序恰好相反：**社媒发布在投稿提交之前**（F-004、F-022），而「模型已选择为 Hy4」必须在创作过程截图/录屏里当场留证（F-020）。证据是**过程中产生的**，事后无法补造；补造就落到 F-057(3) 提供虚假信息。 |
| **行动（方案）** | 把取证前置到任务开始之前：开工先确认模型选择器可见、录屏/截图即刻留存、隐私同步脱敏；把 8 项排除项做成**提交前逐项打钩表**（[05 §7](05-participation-plan.md)），并把 B-1~B-5 设为不通过则不执行的硬阻塞点。 |

## I-03 · 核验在窗口之后且是一次快照：截止即定稿

| 四元组 | 内容 |
|---|---|
| **陈述（洞察/推断）** | 影响 70 分分子的有效时间区间是「社媒发布 → 2026-11-15 23:59 投稿截止」；截止后主办方统一核验并冻结数据，核验之后的数据变化不再调整名次。同一时点还并行关掉另外两扇门：投稿入口硬禁用（F-013、F-050）、撤回不再受理（F-062）、投稿不可再修改（F-053）。 |
| **证据** | F-007、F-011（截止常量）、F-013、F-030（截止后统一核验 + 核验后不调整）、F-050（submitClosedNow 硬拦截，含缓存旧页面）、F-053（不提供审核后修改）、F-062（截止后不受理撤回） |
| **反直觉推断（洞察/推断）** | 「截止」通常被理解为「交材料的最后时刻」。在这里它同时是**数据冻结的基准时点**与**三个不可逆动作的合流点**：交完就不能改、不能撤、数据不再涨。于是一个常见的排期直觉——「先交上占个坑，剩下几天再慢慢把帖子推起来」——在本活动里会让后续所有传播投入不计入评分。 |
| **行动（方案）** | 采用**双轨倒排**：内容/证据轨在截止前至少 24 小时冻结，发布/传播轨从发布日一直排到截止前；提交动作放在两条轨都收口之后，不抢在最后时刻草率提交（[05 §8](05-participation-plan.md)）。把「截止前 24h 冻结」写成日历项而非建议。 |

## I-04 · 创作对话记录同时是过程证据与隐私成本

| 四元组 | 内容 |
|---|---|
| **陈述（洞察/推断）** | 表单 05 项要求提交 WorkBuddy 创作对话记录分享链接（F-046），这是「作品确由本人在 WorkBuddy 创作」的核验凭据；但同一份链接也会把对话里的全部上下文暴露给评审者。而 F-060 要求避免披露保密信息、商业秘密、客户信息、个人信息或第三方受保护内容，F-023 的授权又是提交即生效、范围含展示/复制/改编/传播。**取证与脱敏必须成对完成，不能先取证后补脱敏**——因为 F-053 使提交后不可修改，F-062 的撤回又不可重复提交。 |
| **证据** | F-023、F-024、F-046、F-053、F-060、F-062、F-065；表单提示「分享前请务必确认对话中不含个人隐私、商业机密等敏感信息」「提交前建议重新打开链接，确认评审人员可以正常访问」 |
| **反直觉推断（洞察/推断）** | 「把过程摊开给评审看」与「少暴露信息」通常被当作两个方向，取舍发生在提交前。这里二者被绑成**同一个必填字段**：不交这条链接表单校验直接不通过（F-050），交了又必须保证链接可访问且内容干净。于是「用真实工作来测」（F-018 第 6 类建议方向）这条最贴近真实体验的路径，恰恰是隐私成本最高的一条。 |
| **行动（方案）** | 选题阶段就用**可公开的资料**构造真实任务（本库自身即公开资产），对话中不粘贴客户信息、密钥、本机绝对路径、真实 UserID/手机号；分享前按 F-060 逐条脱敏，用另一账号/无痕窗口重新打开链接验证可访问性；把这条列为 B-2 并在合规四层的 L-C 层复核（[05 §7](05-participation-plan.md)）。 |

## 5. G3 门：哪些判定可以带出本活动

| 判定 | 可否迁移 | 迁移到哪 / 限制 |
|---|---|---|
| 「评分拆相对项 / 绝对项，只投可控侧」 | ✅ | 任何含归一化或排名制评分的活动（如 [workbuddy-1024-contest](../../workbuddy-1024-contest/index.md) 的社媒人气分）；**限制**：不同赛事权重不同，必须重新从公式拆，不得套用 70/30 |
| 「有效投稿 = 合取排除清单」 | ✅ | 任何「有效作品/有效参与」由多条款定义的征集活动；**限制**：须逐条重读该活动原文，不复用本包 8 条 |
| 「核验快照时点决定投入窗口」 | ✅ | 有统一核验/截止后取数的活动与投稿系统；**限制**：有的赛事核验在截止前或滚动进行，时点须重查 |
| 「过程证据字段 = 取证 + 脱敏成对」 | ✅ | 要求提交对话记录、源文件、日志、屏幕录制的评审场景；属通用发布纪律，与 [ai-project-submission-and-content-publishing-guide](../../ai-project-submission-and-content-publishing-guide/index.md) 的版权时序条目同向 |
| 「提交即定稿，不可先交后补」 | ⚠️ | 只在**明确写「不提供审核后修改」**的系统成立；允许修改补件的赛事不适用，不可当通则 |
| 「本活动 521 名算术」 | ❌ | 纯本源数字，无迁移价值 |
