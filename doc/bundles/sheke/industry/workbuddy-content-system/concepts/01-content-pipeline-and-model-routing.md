# 内容流水线与模型路由

## 从“写一篇文章”到工序集合

作者把写作拆成 17 个工序，涵盖选题诊断、概念、立意、案例、钩子、结构、内容生成、标题、升华、精修、排版、封面和分发等环节（F-010～F-011）。这个动作的价值在于把模糊的创作任务变成可检查的阶段契约：

1. 每个阶段有输入和输出；
2. 每个阶段可以单独复盘；
3. 不同阶段可以采用不同质量和成本策略。

## 关键路径优先

作者把案例、钩子、结构、生成、标题、升华、精修视为决定上限的七步（F-012），并提出高价模型用在关键路径、默认模型用于铺量（F-013～F-014）。

这可以抽象成一个非官方的路由函数：

```text
非官方示意：
if step in ["案例", "钩子", "结构", "生成", "标题", "升华", "精修"]:
    route = "高质量模型"
else:
    route = "低成本模型"
```

> 上述代码不是 WorkBuddy 或任何模型厂商的官方 API，只是对文章观点的结构化表达。

## 成本观点的正确读法

“贵的用在决定生死的地方，便宜的用来铺量”是资源分配原则，不是成本定律。文章没有提供 token 用量、模型价格、质量评分、对照组或收益数据，因此不能据此计算真实 ROI（F-015、F-035）。

## 迁移检查

迁移到其他业务前，需要先列出：

- 哪些步骤决定最终质量；
- 哪些步骤只承担格式转换或重复劳动；
- 每一步的验收标准；
- 高质量模型和低成本模型的切换条件。
