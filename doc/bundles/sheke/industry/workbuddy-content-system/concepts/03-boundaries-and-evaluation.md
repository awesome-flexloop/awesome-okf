# 边界、评价与反模式

## 三层可信度

| 层级 | 本文内容 | 使用方式 |
|---|---|---|
| 文章事实 | 三层系统、17 道工序、11 个模块、8 个分身 | 可作为案例结构阅读 |
| 作者观点 | 关键路径优先、少写多复用、AI 放大判断力 | 可作为待验证假设 |
| 作者成效自述 | 日更数量、经营年限、成本、胜率、变现 | 不作为基准或承诺 |

## 最小评估框架

不要先问“系统能不能让我躺赢”，先问：

1. **质量**：关键路径的输出是否比基线更好？
2. **吞吐**：同等质量下，交付周期是否缩短？
3. **学习**：数据是否真正改变下一轮选题或结构？
4. **经济性**：模型、人工、审核和平台成本是否被完整计入？
5. **合规性**：多端再创作是否保持事实、版权和平台规则一致？

## 反模式

- 把个人截图或自述数字当成普遍收益；
- 只增加工序数量，不定义阶段输入输出；
- 用便宜模型处理真正决定质量的步骤；
- 把跨平台复制当成内容适配；
- 有了自动触发器，却没有人工质量门；
- 只看曝光量，不记录转化、留存和时间成本。

## 结论

文章最稳健的学习价值，是“把内容业务当作可分层、可复盘、可回流的系统”这一抽象（F-005～F-008、F-023）。它不等同于 WorkBuddy 的官方产品能力，也不证明作者的收益主张（F-034～F-035）。
