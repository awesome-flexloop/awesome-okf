# 投稿表单字段全解

> 本篇逐条拆解活动页投稿表单的 13 项字段。事实取自页面内嵌的表单定义代码（`openForm()` / `FORM_OPTIONS` / `auditSubmission()` / `canSubmit()` / `renderLinkGuide()`），逐条挂 F 编号。
>
> **总览**：13 项中 **11 项必填**（星号：01—07、10—13）；**第 08 项社媒分享链接与第 09 项上传作品的平台均无星号，为选填**（F-035）。
>
> ⚠️ **投稿入口在 WorkBuddy 资料库的「活动」页**，不在活动页首屏的「发布作品」按钮上——细则原文为「通过**资料库活动入口**完成投稿」（F-081）。

## 01 · 作品宣言（必填，≤200 字）

- 占位示例：「这个 1024，我做了一个待办整理助手，让每天的任务更清楚。」
- 官方给出的模板句式：**「这个 1024，我做了一个______，让______。用一句话介绍你的作品与价值。」**
- 事实：F-036。

> **洞察/推断**：字段 01 与字段 05 存在分工——01 是**一句话的价值陈述**（≤200 字），05 是**完整介绍**（≤2000 字）。两处都涉及"介绍作品"，若 01 写成 05 的缩写，评委会在两处读到同一内容。字段 01 更适合承担**价值主张**，字段 05 承担**事实说明**。

## 05 · 作品介绍（必填，≤2000 字，提示不少于 30 字）

- 表单提示原文：「介绍谁会使用你的作品、如何体验，以及可以得到什么结果。」
- 页面提供 `0/2000` 实时字数计数（F-040）。
- 事实：F-040。

> **四个必答要素**（依提示原文拆解）：① 谁会用 ② 如何体验 ③ 得到什么结果 ④ 核心玩法或功能。**使用说明的清晰度**同时对应「使用体验 25 分」的评分标准（F-066）——这一栏不是填表义务，是**评分表的答题区**。

## 06 · 作品体验链接（必填，url）

表单提示原文：「请填写可以直接打开并体验作品的链接」（F-041）。

### 两种形态的获取路径

| 形态 | 路径 | 事实 |
|---|---|---|
| 网页应用 | 在 WorkBuddy 将作品「发布为网站」→ 点击右上角分享按钮 → 复制公开访问链接 | F-057 |
| 小程序应用 | 小程序无法分享链接 → 改走小红书小工具：进入小红书创作服务平台 → 左侧「小工具」→ 按指引上传小工具文件并填写信息 → 发布后复制挂载该小工具的公开笔记链接 | F-058 |

- 表单明示：「**上传未能正常体验的链接不作为有效体验链接**」（F-059）。
- 缺口 G-13：小红书小工具的审核时长、上传文件格式约束与是否收费均未给出。

## 07 · WorkBuddy 创作对话记录（必填，url）

- **用途（原文）**：「用于辅助核验作品是否使用 WorkBuddy 创作。」
- **获取路径（原文四步）**：打开相关 WorkBuddy 对话 → 点击页面右上角「分享」按钮 → 选择要分享的对话 → 在底部选择「链接」后复制地址。
- **隐私要求（原文）**：分享前确认对话中不包含个人隐私、商业机密、客户信息、账号信息或其他敏感内容；**提交前建议重新打开链接，确认评审人员可以正常访问**。
- 事实：F-042、F-043。

> 这条链接是**过程证据**，与第 06 项的**成果证据**性质不同。详见[机制洞察 I-03](03-mechanism-insights.md)。

## 08 · 社媒分享链接（选填，url，标注「最高加 30 分」）

表单页四段说明原文要点：

1. 「如果你已将参赛作品公开分享至社交媒体，请填写分享内容的链接。」
2. 「**通过小红书小工具参赛的**，如果第 06 项填写的链接本身就是可公开访问、可体验小工具的笔记链接，**两处可以填写同一链接**。」
3. 基础 10 分 + 人气 5—20 分的分档与 11-02 统一核验说明。
4. 有效分享四条件（含话题 `#WorkBuddy` `#1024程序员节`）。

事实：F-044。

`小红书` / `抖音` / `视频号` / `公众号` / `B站` / `其他`（内部 id `ZC40Vb9FHpi4`、`QrozkToFCdTt`、`TCOk1uTegsLU`、`OBCrEAqnG07C`、`jtd1a1zyPFyS`、`n0LBjipdgMwu`）。事实：F-045。

## 10 · 应用界面截图或展示视频（必填，二选一）

| 通道 | 约束 | 事实 |
|---|---|---|
| 截图 | JPG / PNG，最多 **9 张**；多选；上传时前端压缩 | F-046 |
| 视频 | **仅 MP4（`.mp4`）**；前端拒绝非 `.mp4` 文件并提示「目前仅支持 MP4（.mp4）格式视频」 | F-046 |

- 提示原文：「建议展示整体布局和核心功能，请勿包含未经授权的第三方信息、个人信息或重要数据。」——**「展示整体布局和核心功能」与「使用体验 25 分」的标准（操作顺畅、界面与使用说明清晰）直接对应**（F-047、F-066）。
- 事实：F-046、F-047。

### 截图的前端处理链（事实登记）

| 环节 | 参数 | 事实 |
|---|---|---|
| 压缩目标 | 最长边上限 1600 px、初始 JPEG 质量 0.82 | F-055 |
| 单张上限 | base64 **字符数** ≤ 520×1024 | F-055 |
| 总量预算 | 全部截图 base64 **字符数**合计 ≤ 1900×1024 | F-055 |
| 降质策略 | 6 档逐级降级：1600/0.82 → 1280/0.78 → 1024/0.72 → 820/0.66 → 640/0.60 → 480/0.55 | F-055 |
| 透明处理 | JPEG 无透明通道，先铺白底避免透明区变黑 | F-055 |
| 上传 | 提交前逐张串行上传 CDN，失败后最多尝试 3 次（首次 + 2 次重试），退避 700ms×attempt | F-056 |
| 失败行为 | 任一张失败即中止投稿；代码注释明确「绝不把 base64 写进数据表」 | F-056 |

> 推论（洞察/推断）：单张 520 KB + 总量 1900 KB 的预算意味着**最多约 3—9 张有效截图**（取决于画面复杂度），且低信息密度的纯色界面截图更容易通过压缩、复杂界面更容易触顶降质。

## 表单之外的三条机制

### 一、违规内容扫描（F-051、F-052）

- 扫描字段：`作品名称`、`作品链接`、`创作者昵称`、`作品宣言`、`详细说明` —— **五个字段**，逐字段扫描，命中即返回**第一个**问题（字段名 + 分类 + 命中词）。
- 匹配方式：同时按原串与**归一化串**匹配。归一化 = 全角转半角 + 繁体转简体 + 去除空格/标点/符号/emoji。
- 代码注释写明归一化目的：「去掉夹字符：空格/标点/符号/emoji 等常被用来拆词（赌*博、赌 博）」。

> **落点**：归一化扫描意味着**用符号拆开敏感词同样会被命中**。需规避争议词与谐音拆分写法的字段是 **01（作品宣言）、02（作品名称）、03（作者昵称）、05（作品介绍）、06（作品体验链接）**——**作品形态（04）与社媒分享链接（08）不在扫描范围内**（F-056b）。词库本身在页面内但未公开枚举（G 表未列，因其为前端词库而非规则缺口）。

### 二、提交条件与阶段门（F-053）

- 提交按钮可用的充要条件：处于公开活动视图或内部测试视图 **且** 当前阶段为投稿期。
- 非投稿期按钮禁用并显示「即将开启」类状态。

### 三、草稿缓存（F-054）

- 写入 `localStorage` 草稿的是：字段 **01—07、09、11**（**不含第 12 项联系方式 `fPhone`**）、已选截图、平台、形态、视频附件；因容量超限时逐张丢弃截图直至写入成功。
- **实践后果**：刷新页面后**联系方式需重填**（其余已填字段与截图可恢复）。
- 视频附件仅在本地路径引用，**刷新后需重新选择本地视频**。

### 附：作品墙的场景标签机制（F-060、F-061）

作品墙按七个场景标签分类（`效率工具`/`生活助手`/`内容创作`/`学习教育`/`娱乐游戏`/`开发工具`/`其他`），由前端按关键词自动判定，判定顺序为 开发工具 → 学习教育 → 内容创作 → 娱乐游戏 → 生活助手 → 效率工具，命中即返回，否则归「其他」。该标签**仅用于前端展示，不改写投稿池与作品墙的原始作品形态字段**。

> **参赛落点（洞察/推断）**：判定顺序中「效率工具」排在最后，意味着**当作品同时含效率与开发类关键词时，先被归入「开发工具」**。想被归到「效率工具」类目，作品的名称、宣言、介绍中需避免出现代码/编程/开发/调试/接口/API/数据库/Git/测试/程序员/开发者等词。
