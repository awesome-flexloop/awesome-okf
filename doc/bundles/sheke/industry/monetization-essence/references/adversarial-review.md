# 对抗审查记录

> 阶段：V（强制在 F 之后）｜ 目标：≥5 条具体意见、至少采纳 2 条修正；产出合规红绿区边界。

## 1. 四视角攻击

### 1.1 魔鬼代言人（攻击公理体系本身）
1. **V-01（攻击 A1）**："价值源于需求方效用判断"会陷入完全主观——但食品安全、结构安全等存在客观标准。若价值全主观，则 A1 无法解释强制性交换（税收、罚款）。
2. **V-02（攻击 A7）**："可持续正循环"是否否认了一次性合法变现（如咨询项目、一次性作品授权）？公理把"可持续"当成必要条件，可能过度拔高。
3. **V-03（攻击公理性质）**：公理体系混用了"描述性"（经济事实是什么）与"规范性"（变现应该如何）——A1-A3 偏描述，A4-A7 已带"应当"意味。不区分会导致论证循环。

### 1.2 新人视角（可理解性与冗余性）
4. **V-04（冗余质疑）**：A4（交易成本）与 A5（信任）高度重叠——信任成本本就是交易成本的子类。为何拆两条？
5. **V-05（道家映射牵强）**："无为而无不为→搭建低摩擦通道"是创造性转译；若读者不懂道家原意，会误以为在"为道家贴金"。映射的依据需要更明确。

### 1.3 老板视角（收益与责任）
6. **V-06（可量化收益）**：平台 demo 用虚拟货币，未证明真实赚钱路径；100+ 方案中"真正有付费意愿、可落地"的比例未量化，存在"纸上方案"风险。
7. **V-07（合规责任）**：方案涉及金融（荐股风险）、医疗（诊断风险）、灵性（迷信风险）；一旦出问题，责任归属未定义。

### 1.4 未来视角（趋势与可持续）
8. **V-08（监管收紧）**：agent 大规模自主变现必然引发监管（反 spam、反欺诈、agent 责任）；当前架构的治理层是否能跟上未来监管？
9. **V-09（技术过度工程）**：tvm-ffi 集成对机会打分是否必要？未来是否有更合适的替代（如纯 Python + 向量化）？

## 2. 采纳修正（采纳 ≥2 条，记录修正对照）

| 意见 | 是否采纳 | 修正内容 |
|---|---|---|
| V-01 | 采纳 | A1 补充限定：价值判断的主体可以是个人，也可以是**集体/制度化的需求方**（社会契约、标准机构）；强制性交换（税/罚）属于"集体效用判断"的再分配，不否定 A1。 |
| V-02 | 采纳 | 公理体系增加"适用边界"声明：A7 描述的是**可持续变现**的理想形态（本束平台的目标），不否定一次性合法交易；一次性交易是"变现事件"，可持续变现是"变现系统"。 |
| V-03 | 采纳 | 增加"公理性质"声明：A1-A3 为**描述性公理**（经济事实），A4-A7 为**工程性公理**（实现约束）；两者关系是"事实 → 约束"，不循环论证。 |
| V-04 | 采纳（部分） | 明确 A5 独立理由：信任成本虽是交易成本子类，但其**非线性放大效应**（信任崩塌呈指数性）使其值得单列；在关系图中标注"信任是交易成本的独立放大器"。 |
| V-05 | 采纳 | 道家映射增加"类比启发"声明：映射是**设计启发**（借道家思想校准 agent 行为），不作经典教义主张；每个映射保留经典出处（已在 00-axioms.md 完成）。 |
| V-06 | 部分采纳 | 方案目录按"落地等级"标注（即时可落地/需集成/需牌照），并在本束显式说明"真实变现需用户自接适配器，平台只提供沙箱与框架"。 |
| V-07 | 采纳 | 合规红绿区清单升级为**平台硬约束**（compliance/policies.py 已实现红区禁行）；金融/医疗/灵性类方案一律标注"红区边界声明"。 |
| V-08 | 采纳（原则） | 架构治理层设计为**可插拔策略**：未来监管规则以策略形式加入 compliance/，无需改核心循环。 |
| V-09 | 采纳（设计） | tvm-ffi 定位为"高性能计算加速"而非"必须依赖"：双路径设计（native + 纯 Python 参考实现），编译不可用时优雅降级。 |

## 4. 合规红绿区边界清单

### 🔴 红区（禁行，agent 不得执行）

| 类别 | 禁行行为 | 依据 |
|---|---|---|
| 反欺诈 | 虚假宣传、伪造数据、诱导点击、暗藏扣费 | A5 信任公理 / 平台 ToS |
| 反垃圾 | 群发 spam、SEO 垃圾、刷量刷评 | A4 交易成本（污染生态） |
| 金融 | 荐股、代客理财、无牌照证券建议 | 监管红线 |
| 医疗 | 疾病诊断、疗效承诺、替代就医 | 监管红线 / yixue 束自证边界 |
| 灵性迷信 | 算卦/改名/开运/通灵收费 | 反迷信与产品定位 |
| 隐私 | 未授权采集/出售个人数据 | A5 / 数据合规 |
| 版权 | 抄袭、未授权转售受版权保护内容 | A5 / 平台 ToS |

### 🟢 绿区（可行，agent 可自主执行）

| 类别 | 可行行为 |
|---|---|
| 内容服务 | 原创内容生成、知识解读、文档/代码/报告（有交付物、可退订） |
| 数据服务 | 公开数据聚合分析、可视化、按量计价（授权数据） |
| 工具服务 | API 封装、自动化脚本、MCP 服务器托管、自托管方案 |
| 教育咨询 | 课程、方法论训练、合规边界内的咨询（不含荐股/诊断） |
| 沙箱演示 | 虚拟货币闭环（平台 demo 模式） |

### ⚖️ 灰区（需显式用户确认后启用）

真实资金通道适配器：须用户显式 `enable_real=true` + 合规确认，且平台不含真实资金流转。
