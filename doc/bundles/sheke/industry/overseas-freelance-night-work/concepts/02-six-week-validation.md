# 六周验证框架

文章建议“只选一条线，先跑六周”（F-026）。把它改写成一个最小实验：

| 周期 | 目标 | 证据 |
|---|---|---|
| 第 1 周 | 完成资格、支付和一个样品 | 账户状态、支付验证、作品链接 |
| 第 2 周 | 提交少量高匹配申请 | 投递数、回复数、拒绝原因 |
| 第 3 周 | 完成一次小交付或测试 | 交付时长、返工次数、客户反馈 |
| 第 4 周 | 固化交付模板 | 输入清单、输出格式、报价假设 |
| 第 5 周 | 复核净收入 | 平台费、支付费、实际工时 |
| 第 6 周 | 决定继续、换平台或停止 | 一页复盘与下一步行动 |

## 停止条件

- 地区资格长期不满足；
- 支付账户无法验证或费用吞噬小额收入；
- 连续多个样品无法在两小时内完成；
- 真实净收入与机会成本不匹配；
- 平台要求违反当地法律、平台规则或个人雇佣约束。

六周不是“坚持就会成功”的承诺，而是给尝试设置时间盒。首单等待 1–4 周只是博文作者经验（F-027），不能当作平台 SLA。
