# 从身边动作到十人验证循环

## 三步循环

原文给出三步：寻找高频烦人动作、做只解决一件事的小工具、先给 10 个真实用户使用（F-014 至 F-016）。将它转成可审计循环：

```text
观察动作
  -> 访谈并记录原流程
  -> 交付一个最小结果
  -> 观察真实使用
  -> 记录主动反馈、复用和付费信号
  -> 保留、改写或放弃该切口
```

## 10 人不是统计样本

“10 人中 3 人主动说不错”应理解为早期筛选信号，而不是统计显著性或收费阈值。至少还要观察：

- 用户是否第二次使用；
- 是否把结果用于真实工作；
- 是否愿意提供输入数据或推荐给同事；
- 是否愿意为节省的步骤付费；
- 失败时是否能说出具体原因。

因此，验证结果最好记录为“行为证据”，而不是“喜欢/不喜欢”的口头评价。

## 可迁移检查表

| 检查项 | 通过标准 |
|---|---|
| 动作 | 有明确的人群、频率和触发场景 |
| 输入 | 用户能在几秒内提供所需输入 |
| 输出 | 结果可直接用于下一步工作 |
| 价值 | 节省时间、减少错误或降低替代成本 |
| 反馈 | 能获得真实使用而非只看展示 |
| 边界 | 失败、隐私、版权和合规责任已写明 |

## 反模式

- 看到 Photo AI、Coconote、Cal AI 的收入数字就复制功能，不复制需求证据。
- 把“AI 能做”当成“用户愿意付费”。
- 用免费用户的赞美替代真实使用和付费信号。
- 以“1000 人 × 30 元”的算术示例（F-017）伪装成市场预测。

## 结论

文章最可复用的不是某个产品点子，而是一种观察路径：先从具体动作发现摩擦，再用最小结果验证价值，最后根据行为证据决定继续、收费或换题。
