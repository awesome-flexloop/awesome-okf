# AI Works 一键代部署：从 ZIP 源码包到正式公网链接

> **本篇为 2026-10-19 官方公告的增补页**（F-084~F-108）。内容来自知乎产品情报局发布的《🚀 Vibe coding作品能直接上线？AI Works 一键代部署来了！》，**不是工坊活动规则的修订**，也**不是本包的真机实测记录**。部署流程中的按钮名、构建行为与审核结果以你操作时的平台界面为准。
>
> **与活动的关系（洞察/推断）**：工坊要求「通过『上传源码』发布至 AI Works『科学季』项目类型」（F-048）。本篇公告描述的是同一「源码发布」环节的自动化部署能力（F-087~F-092），但公告全文**未提及「科学季」项目类型**（F-108），因此它是否适用于本届工坊投稿，**需要以 AI Works 创建页当前可选项为准**——这是本篇的待核点，不是既成事实。

## 一、这条更新补上了哪一环

在公告之前，参赛路径的第三步只写到「上传源码至 AI Works『科学季』类型」（F-048），没有说明上传之后平台会做什么。公告补上了这一段（F-087、F-089）：

| 环节 | 公告前（活动规则口径） | 公告后（部署公告口径） |
|---|---|---|
| 代码在哪运行 | 未说明 | 用户本地 Agent 开发并确保本地可运行（F-090） |
| 上传什么 | 「上传源码」（F-048） | 打包上传一个 ZIP 源码包（F-089） |
| 平台做什么 | 未说明 | 自动完成代码检测、构建并拉起云端服务（F-089） |
| 如何看到结果 | 未说明 | 先生成带 `preview` 的预览地址，作者本人登录可访问（F-101~F-103） |
| 如何公开 | 未说明 | 审核通过后生成不带 `preview` 的正式公网链接（F-105） |

一句话：**公告把「上传源码」从一句规则变成了「本地开发 → 打包 → 上传 → 自动构建 → 预览 → 审核 → 发布」的可操作链路。**

## 二、部署前准备

### 2.1 用本地 Agent 完成并跑通项目

第一步要求使用 Agent（如 Codex、ClaudeCode、WorkBuddy 等）完成 WebApp 开发，并**确保项目在本地可以正常运行**（F-090）。「等」表示非穷尽列举——公告没有限定只能用这三个工具。

**自检**：

- [ ] 项目能在本地启动，主页面可访问；
- [ ] 核心交互可用，不是静态截图或空壳；
- [ ] 没有依赖本地绝对路径、私人密钥或未打包的资源；
- [ ] 如果用到数据库，已按 2.2 处理。

### 2.2 先处理数据库与秘钥

这两条是公告里唯一的「关键注意事项」，也是最容易导致构建失败的地方。

| 限制 | 公告口径 | 处理方式 | 依据 |
|---|---|---|---|
| 数据库 | 当前代部署**暂不支持独立数据库托管** | 把数据库文件改成 JSON 格式数据文件 | F-095、F-096 |
| 秘钥 | 使用知乎 CLI 若提示注入环境变量秘钥 | 告诉 Agent：秘钥写入文件直接构建 | F-097 |
| 仓库 | 按上述方式处理时 | 代码不会上传到仓库 | F-098 |

> ⚠️ **边界**：JSON 文件是「数据文件」替代，不是数据库托管——并发写入、事务、复杂查询都不具备。秘钥写入文件是公告给出的变通路径，但「代码不会上传到仓库」是平台承诺，**未独立验证**（F-098）。涉及真实密钥时，建议使用测试密钥或最小权限密钥，部署完成后轮换。

### 2.3 确认部署额度

每位用户最多支持部署 **10 个应用**（F-106）。公告未说明是按账号还是按组织计算、是否可调整、是否包含已下线应用（G12）。如果你已经接近上限，先清理不再使用的应用或换用其他账号。

## 三、四步部署流程

### 第一步：准备项目

使用 Agent 完成开发并确保本地可运行（F-090）。这一步的产物是一个**能跑起来的 WebApp 项目目录**。

### 第二步：在项目广场创建作品

登录知乎「项目广场主页」，点击进入创建流程，填写作品的基础信息（F-091）。

**建议**：基础信息里的作品名、简介、标签要与实际功能一致；后续介绍文章与评审都会引用这些信息。

### 第三步：源码发布、打包与上传

这是公告的核心环节，分为四个动作：

1. **选择「源码发布」**：把平台给出的提示词复制给本地 Agent，协助打包代码（F-092）。
2. **在项目根目录操作**：确保 Agent 处于当前项目根目录下，打包成功率更高（F-093）。这是一条经验性建议，不是硬性要求（F-093 备注）。
3. **执行页面命令**：复制页面提供的命令并执行，确认构建方法（F-094）。公告未给出命令文本，实际命令以页面为准（G10）。
4. **上传 ZIP**：上传打包好的 ZIP 源码包；如果找不到生成的文件，可以命令 Agent 把它拷贝到电脑桌面（F-099）。
5. **观察构建状态**：构建成功即可进入下一步；遇到报错，把错误提示复制给 Agent 协助修复（F-100）。

一个可复制的打包提示词骨架（**非官方文案**，依据 F-092~F-094 重组）：

```text
请在当前项目根目录下完成 AI Works 源码发布打包：
1. 先确认当前目录是项目根目录（列出 package.json / index.html 等入口文件）。
2. 按平台提示词要求的目录结构与忽略规则打包，排除 node_modules、.git、.env、本地缓存与私人密钥。
3. 如果项目使用数据库，把数据库导出为 JSON 数据文件，并在代码中改为读取该 JSON。
4. 如果需要注入秘钥，写入构建所需文件，不要提交到仓库。
5. 生成 ZIP 后，告诉我文件路径与大小；如果我找不到，请复制到桌面。
```

### 第四步：预览测试与正式发布

部署成功后的流程有两道门（F-101~F-105）：

| 阶段 | 地址形态 | 访问范围 | 依据 |
|---|---|---|---|
| 预览 | URL 带 `preview` 关键词 | 仅作者本人登录状态可访问调试 | F-101~F-103 |
| 审核前 | 下方按钮获取到的均为预览链接 | 未公开 | F-104 |
| 正式发布 | 不带 `preview` 的公网链接 | 审核通过后可分享给所有知友 | F-105 |

**操作顺序**：

1. 在预览地址中逐项测试核心功能；
2. 确认无误后点击「确认发布」；
3. 等待平台审核；
4. 审核通过后，复制不带 `preview` 的正式链接，用于介绍文章与作品展示。

> ⚠️ **审核边界**：公告只写「平台审核通过后」，没有给出审核维度、时限、驳回后的重试规则（G11）。不要把「预览可访问」当作「已通过审核」，也不要在审核前把 `preview` 链接当作正式作品链接对外分享（F-104）。

## 四、与工坊参赛流程的衔接

### 4.1 在四步流程中的位置

工坊的四步流程是「选工具 → 选题 → 上传源码至 AI Works → 发布介绍文章」（F-030~F-045）。公告补的是**第三步的内部细节**：

```text
选题 → 本地开发（Agent）→ 源码发布打包 → ZIP 上传 → 自动构建 → 预览测试 → 确认发布 → 审核 → 正式链接 → 写介绍文章
```

### 4.2 三个必须确认的点

| 确认点 | 为什么必须确认 | 依据 |
|---|---|---|
| 项目类型是否可选「科学季」 | 公告未提及该类型；工坊规则要求「科学季」 | F-048、F-108（G7） |
| 介绍文章是否已嵌入正式链接 | 工坊要求把 AI Works 作品链接嵌入文章 | F-043 |
| 文章是否标注赛道 | 工坊要求正文标注「此项目投稿至豆包专属赛道」或「看山工作台专属赛道」 | F-044 |

> 这三项里，第一项是**新增的待核点**：如果创建页没有「科学季」选项，应按活动页当前说明处理，或向平台确认；不要仅凭本篇公告推断「一键代部署自动适用于工坊」。

### 4.3 与「有效作品」门槛的关系

工坊要求作品具备「实际可体验、可交互或可使用的功能」（F-047）。一键代部署只解决「怎么上线」，不解决「作品是否有效」——空壳、套壳、批量生成仍然不计为有效作品（F-047）。公告里的「本地可正常运行」（F-090）可以作为最低自检标准。

## 五、失败排查表

| 现象 | 可能原因 | 处理 | 依据 |
|---|---|---|---|
| 打包失败 | 不在项目根目录、入口文件缺失、忽略规则错误 | 让 Agent 先确认根目录与入口文件，再按平台提示词重打包 | F-092、F-093 |
| 构建报错 | 依赖未安装、构建命令不对、运行时版本不匹配 | 复制错误提示给 Agent 修复；确认页面命令已执行 | F-094、F-100 |
| 数据库相关报错 | 使用了独立数据库 | 改为 JSON 数据文件 | F-095、F-096 |
| 秘钥注入失败 | 环境变量未注入 | 按公告把秘钥写入文件直接构建 | F-097 |
| 预览打不开 | 未登录、链接被当成正式链接、审核未过 | 确认作者本人登录；确认 URL 带 `preview`；等待审核 | F-102~F-104 |
| 无法再部署 | 达到 10 个应用上限 | 清理不再使用的应用或换账号 | F-106 |
| 找不到 ZIP | 生成路径不直观 | 让 Agent 拷贝到桌面 | F-099 |
