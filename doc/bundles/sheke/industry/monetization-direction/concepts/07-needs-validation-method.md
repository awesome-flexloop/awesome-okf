# 步骤 3 需求验证：JTBD 三问、Mom Test 与最小实验

> **非决定论声明**：本步的验证信号用于「是否继续投入」的启发式判断，不构成对方向成立与否的判定。
> **非承诺声明**：本步不承载任何收益、规模或成功概率的承诺；信号阈值均为方法自定义参数，非实证结论。

## 1. 本步在四步法中的定位

本步承接步骤 2 的**候选方向卡**（见 [候选方向生成](06-candidate-generation-method.md)），对每张卡的「当前最大不确定性」设计验证。本步**不生成候选**（见步骤 2），**不做 go / no-go 决策**（决策阈值见 [决策与启动](08-decision-and-launch-method.md)）。

## 2. 输入项

- 步骤 2 产出的 3~5 张候选方向卡，每张卡均带「当前最大不确定性」字段。
- 可访谈对象清单（须标注与本人的关系：熟人 / 半熟人 / 陌生人）。

## 3. JTBD 三问（功能 / 社会 / 情感）

**事实依据**：Clayton Christensen、Scott Cook 与 Taddy Hall 于 2005 年在《哈佛商业评论》首次系统表述「待办任务（Jobs to be Done, JTBD）」思想（F-074；亦有 2006-01-16 HBS 版）。作者主张：顾客不是「购买产品」，而是「雇佣」方案来完成生活中的某项进展（job），含**功能、社会、情感**三个维度（F-075〔主张〕）。

**操作步骤**：对每张候选卡，就三个维度各写一句「顾客雇佣该方案，是为了完成 ___」：

1. **功能维度**：他要推进的具体事情是什么？
2. **社会维度**：他希望在他人的眼中成为什么？
3. **情感维度**：他希望摆脱 / 获得什么感受？

**判定标准**：三问均有具体表述，且不出现产品功能名词（功能名词属于解决方案，不属于 job）。

## 4. Mom Test 提问脚本（问过去行为）

**事实依据**：Rob Fitzpatrick 于 2013 年自出版《The Mom Test》（F-076）。方法指出三类误导性反馈——compliments（恭维）、fluff（空话 / 泛化断言）、ideas（对方的点子）（F-077）。作者主张应问**过去的具体行为**而非未来承诺与假设（「你会不会买」→「你上次是怎么做的」）（F-078〔主张〕）。

**操作步骤**
1. 按脚本对每个受访者提 10 个问过去行为的问题（完整脚本见 [验证实验模板](../examples/03-validation-experiment-template.md)）。
2. 访谈中识别并丢弃三类回答：恭维、空话、对方的点子（F-077）。
3. 访谈后立即转录，只保留「已发生的行为」记录。

**判定标准**：每条访谈记录均含**具体过去行为 + 时间 + 当时所用替代方案**；仅含意愿或评价的记录视为无效样本。

## 5. 最小验证实验设计（落地页 / MVP / 预售）

**事实依据**：Eric Ries 于 2011 年出版《The Lean Startup》，提出 build-measure-learn（构建-测量-学习）循环、最小可行产品（MVP）与转型（pivot）（F-071）。MVP 定义为开发中的产品版本，能「以最少努力与最短开发时间完成一次完整 Build-Measure-Learn 循环」（F-072）。作者建议优先测试计划中风险最高的要素（F-073）。价值主张画布（VPC）由 Osterwalder 等 2014 年提出（F-079），结构为 Customer Profile（jobs / pains / gains）与 Value Map（products & services / pain relievers / gain creators），追求两者「fit」（F-080）。

**操作步骤**
1. 从候选卡的「最大不确定性」出发，写出**一条可被证伪的假设**（优先测试风险最高要素，F-073）。
2. 选择实验形态（三种任选）：
   - **落地页型**：写出价值主张（对齐 VPC 的 jobs / pains / gains，F-080），观察访客的实际行为（留资、点击、预约）。
   - **MVP 型**：以最小成本交付一次完整「构建-测量-学习」循环所需的最小版本（F-072），观察真实使用行为。
   - **预售型**：在交付前开放付费承诺，观察真实付费行为。
3. 预先登记**信号阈值**（本方法自定义参数）：如「至少 N 位陌生受访者已为现方案付费」「落地页留资转化达到 X%」等，阈值须在实验前写定，禁止事后调整。
4. 记录实际信号，与阈值比对。

**判定标准**：每个实验均含「假设 / 对象 / 动作 / 信号阈值」四要素，且阈值在实验前登记。

## 6. 反模式清单

| 反模式 | 问题 | 纠正 |
|---|---|---|
| 问朋友「会不会买」 | 得到未来承诺而非过去行为（F-078） | 改问「你上次遇到这个问题时是怎么做的」 |
| 样本全是熟人 | 熟人倾向给出恭维（F-077） | 混入半熟人与陌生人样本 |
| 把点赞 / 好评当付费意愿 | 社交信号 ≠ 付费行为 | 以真实付费或真实使用行为为准 |
| 事后调整信号阈值 | 阈值失去判据作用 | 阈值实验前登记 |
| 把 MVP 做成「功能简陋的半成品」 | 偏离 MVP 的验证目的（F-072） | MVP 目的是完成一次学习循环 |
| 只验证最容易的假设 | 未测最高风险要素（F-073） | 优先测风险最高要素 |
| 用功能性名词替代 job | 混淆 job 与解决方案（F-075） | JTBD 三问须用「进展」表述 |

## 7. 产出物

本步产出：**验证实验卡、Mom Test 访谈记录、信号记录表**。

- 可填写模板：[需求验证实验模板](../examples/03-validation-experiment-template.md)

## 8. 完成本步的达标条件

- [ ] 每张候选卡至少有一条可被证伪的假设。
- [ ] 每个实验含「假设 / 对象 / 动作 / 信号阈值」四要素，阈值实验前登记。
- [ ] Mom Test 访谈记录均含具体过去行为。
- [ ] 已按反模式清单自查，无「样本全是熟人」「把点赞当付费意愿」等项。

## 9. 边界

- 〔洞察〕单次实验信号反映的是**该实验设定下**的观察结果，不能外推为整体市场需求；样本偏差、时机偏差与自选择偏差共同限制其外推范围，详见 [边界与风险](10-boundaries-and-risks.md)。
- 本步仅产出验证记录，判定归步骤 4。
