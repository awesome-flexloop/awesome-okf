# 具身部署场景与系统边界

文章用机器人把剪刀放入抽屉的连续画面说明，任务不是一次性识别，而是每一步都要重新读取环境状态并决定动作（F-015）。科研自动化场景强调同时调用 Python 仿真和跟踪试管状态；智能制造场景则把自然语言工单转换为取件、搬运和放置步骤。

这些演示适合说明模型承担“高层规划大脑”的位置：它理解指令、识别环境、拆解任务，并输出供下游系统执行的计划（F-016）。它不等于端到端控制器，不能替代运动控制、碰撞检测、权限校验、急停和设备安全逻辑。

因此，评估此类模型不能只看 VLM 基准。至少还应观察：

| 评估层 | 要回答的问题 |
|---|---|
| 感知层 | 多视角、遮挡和状态变化下，空间关系是否稳定 |
| 规划层 | 长任务是否能在新画面到来后及时修正 |
| 工具层 | Python、机器人 API 或设备接口调用是否符合约束 |
| 安全层 | 错误计划是否被外围控制系统拦截 |
| 工程层 | 推理延迟、显存、吞吐和故障恢复是否满足现场要求 |

作者认为小型模型可能在部署成本和响应速度上更有优势（F-017）。这是可检验的选型假设，不是本文已经证明的普遍结论。
