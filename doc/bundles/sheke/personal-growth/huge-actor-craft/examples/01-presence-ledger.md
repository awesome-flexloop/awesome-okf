# 01 · 持续在场账本

> **依据**：见 [../concepts/02-influence-methods.md](../concepts/02-influence-methods.md) 路径二。这是本包判定为**最可迁移**的一条路径——理由是**它受外部变量影响最小**。
>
> **核心原则**：**「持续在场」不是「做很多事」，是「同一件小事做很久」。**

## 一、四栏账本

### 栏 1：承诺栏（一次填写，长期不变）

```
我承诺持续在场的事：
  ______

承诺的频率：□ 每天 □ 每周 □ 每月 □ 每季 □ 每年
承诺的期限：______（建议写一个具体日期，不是「长期」）

**检验**：这个频率你已经在做了吗？
  □ 已经在做 → 承诺期从今天算
  □ 没在做 → 先做 3 个月，再写承诺期
```

> **为什么建议先做 3 个月再写承诺**（推断）：因为**没做过的事不知道自己能不能坚持**。先做三个月是最低成本的验证。

### 栏 2：在场栏（每次记录）

| 日期 | 做了什么 | 耗时 | 是否被看见 |
|---|---|---|---|
| | | | □ 是 □ 否 |
| | | | □ 是 □ 否 |

> **「是否被看见」这一列是本表的核心**（推断）：
>
> **持续在场的最大敌人是「需要被看见才能继续」。**
>
> 如果你的在场**必须被看见**才能维持，那么它不是「持续在场」，而是「持续表演」——**表演有疲劳期，在场没有。**
>
> **对照**：胡歌每月给张冕父母打生活费（F-HG-038，A/C 级）——这件事**没有人会知道**。游本昌在史家小学每周上一次课（A/C F-YB-081）——**媒体报道极少**。**它们能持续十九年/八年，正是因为不需要被看见。**

### 栏 3：中断栏（关键——记录断在哪）

| 中断时间 | 持续了多久 | 中断原因 | 恢复用了多久 |
|---|---|---|---|
| | | | |

> **为什么必须记中断（推断）**：
>
> **中断不是失败，中断不记录才是失败。** 因为：
>
> ```
> 不记录中断 → 中断是模糊的「有一阵子没做」
>             → 下次更容易中断（因为感觉「已经断了，算了」）
> 记录中断   → 中断是具体的「第 47 天到第 63 天，原因是出差」
>             → 下次可以针对性预防
> ```
>
> **游本昌的例证**（C 级 F-YB-022）：1991 年后他沉寂了近 30 年——**但这不是「放弃」，而是他自述的真实原因（妻子患癌推掉全部邀约）**。**记录原因使他后来能准确地说出「长期积累」而不是「我运气不好」**（A 级 F-YB-053）。

### 栏 4：无人在场时栏（进阶）

```
我做的这件事，在我不在场时会怎样？
  □ 完全停止 → 这是「在场」，不是「机制」
  □ 降低但继续 → 这是半机制
  □ 完全继续 → 这是机制

如果完全停止，我留下的东西是什么？
  ______
```

> **这一栏直接对应本包的核心判据**（推断）：**「我走了之后，这件事还在吗」**（见 `../../youbenchang-jigong/examples/01-90day-pilot.md`）。
>
> **注意这一栏不必填「完全继续」**——**大部分长期在场的最后结果都是「降低但继续」，这已经比完全停止好得多。**
>
> **本包的诚实提示**：游本昌的史家小学八年课程，**在他不去之后就停了**（A/C F-YB-081）；他真正建成机制的是后来的「种子计划」（A 级 F-YB-087，培养乡村教师）。**这说明他从「在场」进化到了「机制」，花了很多年。**

## 二、规模陷阱的四种识别信号（本包核心）

**最重要的警告**：不要把「做 30 多所学校」当成目标。

| # | 陷阱信号 | 表现 | 为什么危险 |
|---|---|---|---|
| 1 | **目标规模化** | 「我要做 30 所」 | 规模需要组织能力，远超个人在场；**照着规模规划必然放弃** |
| 2 | **一次性思维** | 计划「今年做 10 件」 | 每年重新开始 = 没有积累 |
| 3 | **以「影响人数」自我评价** | 「我影响了 165 万人次」 | 人数是结果指标，不是行为指标；**且此数未获官方独立印证**（见 `../youbenchang-jigong/references/index.md` 规模数据警示） |
| 4 | **把规模当作可持续性证明** | 「看，我做了这么多」 | 规模大恰恰意味着**不可复制**（需要团队、需要资金） |

> **正确的目标写法（推断）**：
>
> ```
> ❌ 目标：做 30 所学校
> ✅ 目标：连续 60 个月，每月给 X 某件事
> ```
>
> **区别**：前者需要组织能力才能达成；后者只需要你在场。**后者才可能持续。**

> **与游本昌的对照（A 级 F-YB-086）**：
>
> 他成立基金会时的表述：「我成立的基金会不叫『游本昌』公益基金会。**游本昌只是一瞬间的事**，我希望基金会可以一直把『济世为公』的事情长久地做下去。」
>
> **注意他排除的是自己的名字，不是规模。** 他要的是**长久**，不是**大**。
>
> **这与本表的判断一致**：**目标是「长久」，不是「规模」。**

## 三、退出成本计算（本包公式，推断层）

「持续在场」的护城河来自**退出成本**。这是一个可以估算的量：

```
退出成本 = 已经持续的时间 × 中断时的愧疚感 × 对象的依赖度
```

**逐项打分（0–3 分）**：

| 项 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| **已持续时长** | < 1 个月 | 1–6 个月 | 6 个月–2 年 | > 2 年 |
| **愧疚感** | 无所谓 | 有点可惜 | 会内疚 | **会持续自责** |
| **对象依赖度** | 没人知道 | 有人知道 | 有人受益 | **有人因此改变** |

**你的分数**：______ / 9

> **判读（推断）**：
>
> | 分数 | 状态 | 风险 |
> |---|---|---|
> | 0–3 | 随时可退出 | 还没有形成护城河 |
> | 4–6 | 有一定承诺 | 关键在最初 6 个月 |
> | 7–9 | 已成护城河 | **中断成本极高，这正是它可持续的原因** |
>
> **本包的判断**：**退出成本高不是好事，是「已经做对了」的证明。** 一个人如果做任何事都能轻松退出，说明他还没有找到值得长期在场的事。

## 四、三个真实场景的改写

### 场景 A：技术人

| 栏 | 填写 |
|---|---|
| 承诺 | 每月去一次本地的开源/技术社区，做一次分享或答疑 |
| 频率 | 每月一次 |
| 期限 | 先做 6 个月，再评估 |
| 规模陷阱 | ❌ 「我要做 100 场分享」→ ✅ 「我今年要 12 场」 |
| 退出成本 | 已持续 N 月 = ___ 分 |

**注意**：分享会当场有反馈（L4 级延迟），且**规模小、频率高**。

### 场景 B：管理者

| 栏 | 填写 |
|---|---|
| 承诺 | 每周固定一次「不解决问题的一对一」——只听，不给建议 |
| 频率 | 每周一次 × ___ 人 = 每周 ___ 小时 |
| 期限 | 12 周 |
| 中断记录 | 若中断，记录原因与恢复时间 |
| 无人在场时 | 团队失去的是什么？如果答案是「只是我的时间」，那这不是机制，只是习惯 |

> **场景 B 的特殊价值**（推断）：**一对一是最难被外包的「在场」**，因为它不可规模化——**这正是它的护城河**。
>
> **注意「不解决问题」这个限定**（推断）：如果一对一变成了解决问题，它就退化成「任务分配」，会场的性质变了。**限制「不给建议」是为了保护「听」这个动作的纯粹性。**

### 场景 C：任何行业的人

| 栏 | 填写 |
|---|---|
| 承诺 | ______ |
| 频率 | ______ |
| 期限 | ______ |
| 今天的第一个动作 | **今天/本周内可以做完的第一件事：______** |

> **第三个场景是本表的核心用途**（推断）：**这张表最重要的不是填满，是填出「今天能做的第一件事」。**
>
> **因为持续在场的启动成本几乎为零，难的只是开始。** 而「今天能做的一件事」是唯一能跨过启动障碍的东西。

## 五、十二周检查

```markdown
## 第 12 周检查

### 1. 在场记录统计
- 承诺频率：每 ___ 一次
- 实际完成次数：___ 次
- 完成率：___ %
  （低于 60% → 承诺频率定高了，降频而不是硬撑）

### 2. 中断记录
- 中断次数：___ 次
- 最长一次中断：___ 天
- 中断主因：______

### 3. 在场栏「被看见」的比例
- 被看见 ___ 次 / 共 ___ 次 = ___ %
  （**如果比例 > 70%，你在做的是表演不是在场** → 需要重新设计，让它可以不被看见地持续）

### 4. 无人在场时
- 我不在场时会：□ 完全停止 □ 降低但继续 □ 完全继续
- 结论：这是「在场」还是「机制」？

### 5. 下一阶段
- 继续 □ / 降频 □ / 终止 □ / 转化为机制 □
```
