# SOP 的要素与文档层级

## 一、SOP 的常见组成字段

行业实务资料归纳一份完整 SOP 的通用元素（F-026，引用 S10）：

1. **编号与版本号**：唯一标识 + 版本序列，便于追溯。
2. **生效日期**：SOP 正式实施的日历日期。
3. **编制 / 审核 / 批准人**：三签制度——编制者记录实际操作，审核者确认技术正确性，批准者（通常是质量部门或主管）授权生效。
4. **目的**：SOP 旨在解决什么问题（为什么写这份文件）。
5. **适用范围**：适用于哪些岗位、设备、流程、场所。
6. **职责说明**：谁负责执行、谁负责监督、谁负责审核。
7. **操作步骤**：按时间顺序排列的具体动作。
8. **注意事项 / 安全要求**：风险提示、个人防护、紧急情况处置。
9. **相关附件**：表单、检查单、流程图等支撑材料。
10. **修订记录**：每次变更的内容、日期与原因。

中文作业标准书实践另要求在页眉标注单位全称、编码、页码与关键词检索项（F-026，引用 S10）。

## 二、四种呈现格式

同一 SOP 可用不同视觉格式表达，选择取决于受众和场景（F-025，引用 S10）：

| 格式 | 形态 | 适用场景 |
|------|------|---------|
| 步骤式（Step-by-step） | 编号列表，每个步骤一个动作 | 线性操作、常规任务 |
| 流程图式（Flowchart） | 带分支判断的图形流程 | 决策节点多、路径分叉的流程 |
| 核查单式（Checklist） | 打勾项，无描述性文字 | 高风险场景的关键步骤确认（如手术、起飞前检查） |
| 层级式（Hierarchical） | 按组织层级展开，体现报告关系 | 跨部门协调流程、应急响应 |

> **WHO 的例子（F-010）**：手术安全核查表刻意仅保留 19 项关键步骤，用口头逐项确认 + 表单记录的方式呈现——不是流程图的精细度，而是核查单的简洁度。

## 三、文件层级体系

### 合规行业通行的四层体系（F-017）

| 层级 | 英文 | 功能 | 示例 |
|------|------|------|------|
| 一阶 | Policy（政策） | 确立组织合规立场的高层指令 | 《数据保护政策》《质量管理体系方针》 |
| 二阶 | Procedure / SOP（程序） | 实施政策所需过程详细描述 | 《供应商审批程序》《偏差处理程序》 |
| 三阶 | Work Instruction（作业指导书） | 具体任务的分步指导 | 《离心机操作指导书》《pH 计校准步骤》 |
| 四阶 | Record（记录） | 执行证据 | 批记录、校准记录、偏差报告 |

### ISO 体系中的三阶 / 四阶说法（F-028）

中文管理百科与 ISO 咨询圈常以四阶概括 ISO 9000 体系：

- 一阶：质量手册（Quality Manual）
- 二阶：程序文件（Procedure）
- 三阶：作业指导书 / SOP
- 四阶：表单记录（Record）

"三阶文件"说法侧重把 **SOP 本身**归入第三层——即它是"作业性文件"，既非政策也非单纯表单。两种说法并不矛盾，只是分层粒度不同。

### 关键区分

- **SOP ≠ 制度**：制度是"做什么 / 不可以做什么"的规范性文件（一级）；SOP 是"怎么做"的程序文件（二/三级）。
- **SOP ≠ 表单**：SOP 描述过程，表单是记录载体（四阶）；两者常一起发布，但性质不同（F-029、F-028）。

## 四、编写流程

行业实务资料归纳 SOP 编写的典型流程（F-027，引用 S10）：

1. 确定需要文档化的流程
2. 让实际执行工作的人参与编写
3. 选择合适格式
4. 撰写清晰简单的指令
5. 添加可视化辅助（流程图 / 照片）
6. 评审、测试与验证
7. 培训团队
8. 安排定期复审更新

> **要点**：第 2 条"让实际执行人参与"是避免文档脱离现场的关键一步。很多组织以文档部门或管理层代笔，结果写成后一线人员读不懂。
