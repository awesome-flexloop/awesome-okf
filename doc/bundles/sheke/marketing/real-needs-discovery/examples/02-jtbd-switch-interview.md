# JTBD Switch 访谈提纲：还原一次真实切换

> 目的：通过还原用户从旧方案切换到新方案的完整过程，提取任务说明书与四力结构。方法依据见 [../concepts/04-jtbd-framework.md](../concepts/04-jtbd-framework.md)；事实溯源至 [../facts.md](../facts.md)（F-016~F-019）。
>
> 时长与样本量为【P2】经验区间，非权威标准。

## 1. 找对人：谁算"切换者"

switch 访谈的对象必须**真实发生过切换**——不是"打算换"，是已经换了。三类合格对象：

| 类型 | 例子 | 能采到什么 |
|---|---|---|
| 切换到你的人 | 从竞品/土办法换用你的产品的用户 | 拉力与推力的现场证据 |
| 从你这切走的人 | 流失用户 | 焦虑与惯性如何输掉 |
| 内部切换者 | 从 Excel 土办法换用内部系统的员工 | 替换成本的具体构成 |

每场 45~60 分钟；**先攒 5~8 场再归纳模式**，单场结论不可外推（本包【P2】经验区间）。

## 2. 主线：时间线还原六站

访谈不按主题问，按**时间线**走——让对方讲故事，你负责钉细节：

```
① 最初念头   ② 被动寻找   ③ 主动寻找   ④ 决策   ⑤ 上手   ⑥ 现在
```

各站的核心问题：

| 站 | 核心问题 | 在挖什么 |
|---|---|---|
| ① 最初念头 | "第一次觉得旧办法不行，是什么时候、发生了什么事？" | **推力**：现状造成真实损失的具体事件 |
| ② 被动寻找 | "那之后你注意到过什么替代方案吗？在哪看到的？" | 认知渠道；拉力的第一触点 |
| ③ 主动寻找 | "你开始认真找是什么时候？找了哪些？怎么比的？" | 评估标准（= 任务的验收条件） |
| ④ 决策 | "最后下决心那刻，是什么让你定的？差点让你不选它的是什么？" | **拉力峰值**与**焦虑峰值** |
| ⑤ 上手 | "第一次用的时候顺不顺？哪里卡住了？" | **惯性**与迁移成本 |
| ⑥ 现在 | "现在回得去吗？为什么？" | 旧习惯是否瓦解；留存的力场 |

钉细节的三件武器（沿用 Mom Test 纪律，F-014）：问具体时间、问具体事件、问"然后呢"。

## 3. 四力提取问题清单

时间线走完后，用下表把散落回答归位到四力（F-018）：

| 力 | 追问问题 | 记录格式 |
|---|---|---|
| 推力 push | "旧方案最差的一次体验是什么？造成了什么实际损失？" | 事件 + 损失（时间/金钱/情绪） |
| 拉力 pull | "新方案第一次让你觉得'值了'的瞬间是什么？" | 场景 + 被满足的任务维度（功能/情感/社会，F-019） |
| 焦虑 anxiety | "决定之前，你最大的顾虑是什么？后来怎么打消的？" | 顾虑 + 打消机制（试用/口碑/可逆承诺） |
| 惯性 habit | "旧方案里有什么你至今还在用/还想念的？" | 残留依赖 + 原因（沉没投入/习惯路径） |

切换判定式（见 [../concepts/04-jtbd-framework.md](../concepts/04-jtbd-framework.md) 第 4 节）：**(推力 + 拉力) > (焦虑 + 惯性)**——记录时给四力各打一个 1~5 粗分，用于多场横向比较（本包【P2】实践共识，分数是组织信息的工具，不是精密测量）。

## 4. 访谈记录模板

```
【基本信息】对象角色 / 行业 / 切换发生时间 / 访谈日期
【切换路径】旧方案：______ → 新方案：______
【时间线】
  ① 最初念头（日期 + 触发事件）：
  ② 被动寻找：
  ③ 主动寻找（评估了哪些方案 + 标准）：
  ④ 决策（临门一脚 + 最大顾虑）：
  ⑤ 上手（卡点 + 解决）：
  ⑥ 现在（回不回去 + 原因）：
【四力】推力 /5：｜拉力 /5：｜焦虑 /5：｜惯性 /5：
【任务维度】功能：｜情感：｜社会：
【金句】（原话摘录，标注分钟数）：
【证据等级】本场最有价值的一条行为证据，按 L1~L6 定级：
```

## 5. 产出：任务说明书

5~8 场访谈后，把反复出现的任务写成任务说明书（句式见 [../concepts/04-jtbd-framework.md](../concepts/04-jtbd-framework.md) 第 6 节）：

> **当**〔情景〕**时，我想要**〔进展〕**，以便**〔结果〕。

写作检查单：

- [ ] 无产品名、无具体技术词（"导出 Excel"❌ → "完成周报"✅）
- [ ] 情景具体到时间、地点、前置事件
- [ ] 功能/情感/社会三个维度各至少一条证据支撑（F-019）
- [ ] 至少两场访谈中出现同构任务才立案

## 6. 汇总：模式提取

多场访谈的横向对比看三个模式（本包【P2】实践共识）：

1. **推力事件是否同源**：如果 8 场里 6 场的"最初念头"都是同一类事件——你找到了产品的核心场景；
2. **焦虑的集中点**：焦虑集中在哪个环节，那个环节就是 onboarding 与营销要优先拆除的障碍；
3. **惯性残留物**：旧方案里被想念的东西，是新产品必须兼容或主动替代的清单。

最后把模式翻译回俞军公式验算（F-005）：**新体验 − 旧体验 − 替换成本**——三场以上出现"新体验好但替换成本更高"的记录，就意味着迁移工具与可逆承诺比功能迭代更优先。
