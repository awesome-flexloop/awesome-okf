# 一周验证计划模板：一条假设的生死周

> 目的：用一周时间给当前最危险的一条需求假设一个明确判决——验证、证伪或带预案的灰区。方法依据见 [../concepts/05-validation-loop.md](../concepts/05-validation-loop.md)；事实溯源至 [../facts.md](../facts.md)（F-036~F-045）。
>
> 阈值与节奏均为【P2】经验区间，须按行业基线自行校准。

## 1. 周一：假设卡（本周唯一主角）

一周只验一条假设。选出"最危险"的那条——**证据等级最低 × 赌注最大**的交叉点。

```
【假设卡】
一句话假设：我们认为〔人群〕会为〔价值〕付出〔代价〕，
            因为〔已有的最好证据，标注证据等级 L?〕。
当前证据等级：L__（参照 concepts/00 第 4 节）
验证线：〔什么结果算假设成立，含数值与期限〕
证伪线：〔什么结果算假设失败〕
灰区预案：〔介于两线之间时，补什么证据、问谁、看哪里〕
信任预算：本实验可接受的用户误解/善后成本上限
```

写不出验证线与证伪线的假设不许进入实验——"跑完看感觉"是 F-045 明令禁止的自欺结构。

## 2. 周一：MVP 形态选择决策表

按证据缺口选最便宜的形态（F-038 谱系）：

| 你要测的缺口 | 推荐形态 | 原因 | 一周内成本量级 |
|---|---|---|---|
| 价值主张说不说得动陌生人 | 落地页 | 纯文案实验，无需产品 | 半天~1 天 |
| 有没有人想要（点击/留资） | 假门 fake door | 测 L2→L4 转化 | 1 天 + 善后话术 |
| 愿不愿以"自动化形态"交互 | 绿野仙踪 | 前台真实、后台人工（IBM 语音实验，F-040） | 2~3 天 |
| 服务流程哪步最痛 | 礼宾 concierge | 全人工贴身服务（F-052） | 3~5 天 |
| 愿不愿付钱 | 预售/众筹 | 唯一直达 L5~L6 的形态（F-044） | 视交付承诺 |
| 核心价值能否独立成立 | 单功能 MVP | 砍到任务链最痛一环 | 3~5 天 |

三条红线（F-041、F-068）：假门必须配善后（解释 + 感谢，不留 404）；涉及钱必须能退款兜底；实验流量控制在全体用户的小比例。

## 3. 周二~周五：任务卡

| 日 | 任务 | 产出物 |
|---|---|---|
| 周二 | 搭建实验载体（落地页/假门/礼宾流程）；写死埋点 | 可访问的实验入口 + 数据回收表 |
| 周三 | 投放/邀约：够到目标人群（社群、广告小额、朋友圈、上门） | 触达记录（渠道、成本、量） |
| 周四 | 继续跑量；对**留资者**追加 15 分钟访谈（行为刚发生，动机最新鲜） | 行为数据 + 3~5 条即时访谈记录 |
| 周五 | 停量收数；整理数据按假设卡两线判定 | 数据汇总表 |

注意：周四的即时访谈是本周的隐藏金矿——用户刚完成一个真实行为（点击/留资/预付），此时问"刚才是什么让你决定留这个邮箱"，得到的动机证据质量远高于事后回忆（衔接 [02-jtbd-switch-interview.md](02-jtbd-switch-interview.md) 的还原法）。

## 4. 周六：复盘表

```
【数据对照】
  触达人数：____  → 关键行为人数：____  → 转化率：____%
  验证线：____｜证伪线：____｜实测：____
【判定】□ 验证（≥验证线） □ 证伪（≤证伪线） □ 灰区（执行预案）
【证据升级】本周把假设的证据等级从 L__ 推到 L__
【即时访谈发现】三个最高频动机：① ② ③
【意外发现】（计划外但可能更重要的信号）：
```

## 5. 周日：决策记录（pivot / persevere）

判定结果必须落到书面决策（F-045），三种出口：

| 判定 | 决策动作 | 下周计划 |
|---|---|---|
| 验证 | persevere：进入下一条最危险假设 | 新假设卡（证据等级已整体抬高一层） |
| 证伪 | pivot：改人群 / 改任务 / 改价值主张，三选一并写明依据 | 转型后的新假设卡 |
| 灰区 | 执行预案：补指定证据（通常是回"问"路径定位断点） | 定向访谈或观察计划 |

**禁止的第四种出口**："再跑一周看看"——灰区预案已经规定了补什么证据，无限续命是验证闭环最常见的死法。

## 6. 完整示例（浓缩版）

> 假设：我们认为 20~35 岁合租青年会为"公共区域的定期保洁协调"付每月 29 元，因为 6 场访谈中 4 人描述过因卫生分工翻脸的经历（L2）。
>
> 形态：落地页 + 假门（"加入本楼保洁排班"按钮 → 留微信）。
>
> 验证线：200 个目标访客中留资 ≥ 8%（16 人）且其中 ≥ 3 人接受 29 元/月预付意向；证伪线：留资 ≤ 2%。
>
> 结果：触达 240 人，留资 9 人（3.8%，灰区）；即时访谈发现动机真实但"付钱给工具"意愿弱——他们更想要"保洁阿姨直订"。
>
> 决策：pivot（改价值主张：从"协调工具"转"阿姨撮合"），新假设卡进入下周。
