# 验证闭环：从假设到付费级证据

> 问、看、算三条路径的产出终究停留在 L2~L3 证据层；要把证据推到 L4~L6（留资、预付、付款），必须走"试"路径。本篇给出实验路径的完整闭环：循环主轴 → MVP 谱系 → pretotyping → 组织化机制 → 决策出口。事实溯源至 [../facts.md](../facts.md)（五区 F-036~F-045，关联 F-061、F-068），解释性判断见 [../insights.md](../insights.md) 第 1、6 条。

## 1. 为什么必须"试"

按 [00-what-is-real-need.md](00-what-is-real-need.md) 第 4 节的行为证据等级，需求判别的分水岭在 L3 与 L4 之间——用户是否**为尚未到手的东西付出真实代价**。访谈里的"我会买"（L2）、观察里的高频使用（L3）都不能替代一次真实的留资、预付或下单。

实验路径的全部方法论都在回答一个问题：**如何用最低成本，设计一个让用户付出真实代价的情境**。

## 2. 主轴：build-measure-learn

莱斯《精益创业》（2011）给出的循环主轴（F-036）：

```
      假设                认知
       │                  ▲
       ▼                  │
     build ──► 产品/实验 ──► measure ──► 数据 ──► learn
```

- 创业的核心活动是把想法以最小成本转化为可学习的实验，**循环转速是创业公司的核心速率**。
- 循环的产出物不是产品，而是"经证实的认知"（validated learning）——它直接喂给终点决策：转型（pivot）还是坚持（persevere）（F-045）。
- 常见误用：把循环跑成 build-build-build——每个迭代必须事先声明"这次要学什么、什么结果算学到"，否则只是在快速生产废品（本包【P2】实践共识）。

## 3. MVP 正名与五大谱系

**MVP 的定义**：能让团队用最少努力收集最大量经证实的认知的那个产品版本——MVP 的目标是**学习**，不是"缩小版产品"（F-037）。把 MVP 理解成"功能阉割版 V1"是最常见的误读：缩小版产品追求的是交付价值，MVP 追求的是证据产出。

社区实践归纳的 MVP 谱系（F-038），按"人工含量"从高到低：

| 形态 | 做法 | 测什么 | 经典案例 |
|---|---|---|---|
| 礼宾（concierge） | 全人工服务少数用户 | 服务本身是否被需要、流程哪个环节最痛 | Food on the Table 创始人上门定制菜谱（F-052） |
| 绿野仙踪（Wizard of Oz） | 前台像产品，后台人工 | 用户是否愿意用"自动化"形态交互 | IBM 语音转文字实验（F-040）；Zappos 拍照卖鞋（F-047） |
| 假门（fake door） | 做一个入口测点击/留资 | 兴趣强度（L2→L4） | Buffer 两页落地页 + 定价页留邮箱（F-048） |
| 落地页（landing page） | 描述价值主张收集意向 | 价值主张是否说得动陌生人 | Dropbox 演示视频等候名单 5 千→7.5 万（F-046） |
| 单功能 MVP | 只做任务链上最痛的一环 | 核心价值能否独立成立 | —— |

谱系的选择原则（本包【P2】实践共识）：**证据缺口在哪一层，就选能把那一层测出来的最便宜的形态**——测"有没有兴趣"用假门，测"愿不愿付钱"必须上预售或真实交付，假门测不到付费。

## 4. pretotyping：先证"对的产品"

阿尔贝托·萨沃亚（谷歌首位工程总监）把实验再向前推了一步（F-039）：**"确保你在把产品做对之前，先确保你做的是对的产品"**——pretotyping 用极端低成本的伪装实验测"有没有人真的想要"，发生在写任何正式代码之前。

经典案例是 IBM 语音转文字实验（F-040）：让客户对着"能听懂语音并自动打字的电脑"说话，幕后由真人打字员实时转录——先验证人们是否真愿意用语音输入，再决定是否投入语音识别研发。这个实验同时演示了绿野仙踪形态的两个要点：**前台体验必须真实**（用户以为在用产品），**后台成本必须廉价**（真人而非研发）。

**假门的信任成本（F-041）**：伪装实验是有代价的——被识破的用户会有被欺骗感。管理纪律：

1. 控制实验流量比例（小流量试探，不全体推送）；
2. 准备善后话术与补偿（点进假门的用户应得到解释与感谢，而非 404）；
3. 评估品牌信任预算——误导性实验的长期成本由品牌承担（F-068）。

## 5. 组织化机制

三条把"试"嵌入组织的机制：

- **PR/FAQ 逆向工作法（F-042）**：亚马逊新品立项须先写新闻稿与常见问题，以客户视角倒推产品定义——写不出让客户兴奋的新闻稿，立项即止步。这是把"需求语言检查"制度化为立项闸门。
- **做不可规模化的事（F-043）**：Paul Graham 2013 年博文主张早期主动做不可规模化的事——手动招募用户、亲自服务——以换取对需求的贴身理解。Airbnb 创始人逐户为房东拍照、Food on the Table 上门代买食材都是注脚（F-049、F-052）。
- **预售与众筹（F-044）**：付钱比口头承诺高一个证据等级，是 L5~L6 级证据的标准采集法。同组 bundle [sell-before-build-validation](../../sell-before-build-validation/index.md) 已专述"先卖后做"方法论，本包引用不重复展开。

## 6. 决策出口：pivot 还是 persevere

验证的终点是决策（F-045）：经证实的认知唯一去向是**转型（pivot）或坚持（persevere）**。把决策纪律写死在实验之前（本包【P2】实践共识）：

| 实验设计要素 | 说明 | 反例 |
|---|---|---|
| 假设一句话 | "我们认为〔某人群〕会为〔某价值〕付出〔某代价〕" | "试试水再说" |
| 验证线 | 什么结果算假设成立（如：落地页访客→留资 ≥ 8%） | 跑完再看数据"感觉不错" |
| 证伪线 | 什么结果算假设失败（如：≤ 2%） | 不达标时改口径找补 |
| 灰区预案 | 介于两线之间时补什么证据（问？看？换人群重试？） | 灰区里无限续命 |

灰区的标准解法来自双路径交叉（见 [02-discovery-method-map.md](02-discovery-method-map.md) 第 8 节）：行为信号不达标时回到"问"定位断点——是价值主张没说清（改文案重试），还是需求本身不成立（pivot）。

## 7. 闭环节奏：一周一轮

```
周一   列出当前最危险的一条假设（证据等级最低、赌注最大）
周二   选 MVP 形态，写死假设/验证线/证伪线
周三~五 跑实验，采行为数据
周六   复盘：证据到 L 几？对照两线判定
周日   决策：persevere（进入下一假设）/ pivot（改人群、改任务、改价值主张）
```

可直接套用的一周计划模板见 [../examples/03-one-week-validation-plan.md](../examples/03-one-week-validation-plan.md)。

## 8. 边界

- **早期信号不可线性外推（F-061）**：MVP 在尝鲜者中成立，不代表鸿沟另一侧的早期大众成立——跨越鸿沟需要重新验证，详见 [07-cases-and-boundaries.md](07-cases-and-boundaries.md)。
- **伦理底线（F-068）**：假门与绿野仙踪不得给用户造成实际损失；涉及金钱的实验（预售）必须能退款兜底。
- **验证不是一次性事件（F-065）**：需求随供给普及漂移（Kano 退化 F-029），PMF 需要持续再验证——闭环没有"毕业"一说。
