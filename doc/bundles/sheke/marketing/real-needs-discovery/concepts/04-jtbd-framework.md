# JTBD 框架：用户不是买产品，而是雇用产品完成任务

> JTBD（Jobs to be Done）是"问"路径里体系最完整的一支：它给出需求的最小描述单位（任务）、还原需求的访谈方法（switch）、以及预判切换成败的分析模型（四力）。本篇事实溯源至 [../facts.md](../facts.md)（F-016~F-019，关联 F-005、F-061~F-062），解释性判断见 [../insights.md](../insights.md) 第 2、8 条。

## 1. 核心隐喻：雇用

克里斯坦森等在《与运气竞争》（2016）中提出：**顾客不是购买产品，而是"雇用"产品来完成生活中的一项任务（job）**（F-016）。

这个隐喻做了两件事：

1. **转换主语**。供给方语言问"用户要买什么产品"，需求方语言问"用户要完成什么任务"。它是莱维特"要的是洞不是钻头"（F-003，见 [00-what-is-real-need.md](00-what-is-real-need.md) 第 2 节）的操作化版本——"洞"就是任务，"钻头"只是当前被雇用的工具。
2. **重画竞争边界**。产品的竞争对手不是同品类产品，而是**一切能被雇用来完成同一任务的方案**——包括"什么都不做"。

由此得到 JTBD 式的需求定义：真需求存在于"某人在某情景下想把事情变得更好，却苦于没有好办法"的时刻。需求描述的最小单位不是用户画像，而是**任务**。

## 2. 奶昔案例：框架的完整演示

克里斯坦森广泛讲述的奶昔案例（F-017）是 JTBD 方法的一次完整演示：

> 一家快餐连锁想提升奶昔销量，先按人口统计口径调研（性别、年龄、收入分层的顾客想要更浓还是更甜的奶昔），改进了产品，销量无变化。
>
> 改用任务视角观察后发现：大量奶昔在**清晨**被独自开车的人买走。它被"雇用"来完成的任务不是"解馋"，而是——**打发漫长的通勤车程，同时提供一上午的饱腹感**：单手能拿、不脏方向盘、能吸上二十分钟。
>
> 按任务重看竞品：奶昔真正的对手不是别家奶昔，而是**香蕉**（几口就没了，不顶时间）、**贝果**（掉渣、要抹酱、双手操作）、**无聊**本身。

案例的三层启示：

- **人口统计不解释购买**。同一个通勤者下午给孩子买奶昔时，雇用它的任务完全变了——用户没变，任务变了，产品选择标准跟着变。
- **竞品由任务定义**。找错竞品（盯着同品类）是需求错判的常见形态；按任务列竞品才能看到真实替代方案。
- **改进方向由任务导出**。清晨任务的改进是"更耐吸、更快取餐、单手友好"，而不是"更浓更甜"——任务决定产品标准。

## 3. 任务三分：功能、情感、社会

JTBD 对"任务"的完整定义包含三个维度（F-019）：

| 维度 | 含义 | 手表例子 |
|---|---|---|
| 功能 | 把什么事办成 | 看时间 |
| 情感 | 让自己感觉如何 | 掌控感、安心感 |
| 社会 | 让别人如何看待自己 | 职业形象、身份信号 |

操作含义：**只写了功能维度的需求描述是不完整的**。同样是"看时间"，手机早已免费满足功能维度，机械表市场却存活——因为被雇用的任务主要在情感与社会维度。判伪时也一样：一个"功能上成立"的需求若触碰了负面的社会维度（例如 Google Glass 的"Glasshole"污名，F-053），任务整体不成立——详见 [01-fake-need-taxonomy.md](01-fake-need-taxonomy.md)。

## 4. switch 访谈与四力模型

JTBD 的配套访谈方法叫 switch 访谈：不聊假设中的产品，而是还原一次**真实发生过的切换**——用户从旧方案换到新方案的那次决策。切换时刻的受力分析用四力模型（F-018）：

```
            推动切换                        阻碍切换
   ┌─────────────────────┐      ┌─────────────────────┐
   │ 推力 push            │      │ 焦虑 anxiety         │
   │ 现状有多难受          │      │ 新方案会不会更糟      │
   ├─────────────────────┤      ├─────────────────────┤
   │ 拉力 pull            │      │ 惯性 habit           │
   │ 新方案有多诱人        │      │ 旧习惯与沉没投入      │
   └─────────────────────┘      └─────────────────────┘
        切换发生 ⟺ (推力 + 拉力) > (焦虑 + 惯性)
```

四力模型的三个直接推论：

- **加大拉力不是唯一杠杆**。新产品营销习惯性堆拉力（功能、补贴），但削减焦虑（免费试用、迁移工具、可逆承诺）与瓦解惯性（导入旧数据、兼容旧流程）常常更便宜。
- **没有推力的需求是软需求**。用户对现状满意时，再好的新方案也只是"不错"——访谈时要优先找推力的证据（现状造成的真实损失）。
- **惯性是真实成本**。即使新方案客观更优，习惯与沉没投入也足以维持现状——"更好"不自动等于"被采用"。

## 5. 与俞军公式的同构

四力模型在中文谱系有一个数学化的对应物——俞军用户价值公式（F-005，见 [00-what-is-real-need.md](00-what-is-real-need.md) 第 3 节）：

```
俞军：  用户价值 = 新体验 − 旧体验 − 替换成本
JTBD：  切换动力 = (推力 + 拉力) − (焦虑 + 惯性)
```

两者结构同构（详见 [../insights.md](../insights.md) 第 2 条）：**新体验/拉力、旧体验被推翻的程度/推力、替换成本/焦虑与惯性**。合并表述即——用户是否切换，不取决于新产品有多好，而取决于新体验相对旧体验的**净增益是否覆盖替换成本**。这也是评估"真需求"的商业化判据：任务真实存在（JTBD），且净收益足以驱动切换（俞军），需求才算成立。

## 6. 操作：写一份任务说明书

JTBD 的产出物不是用户画像，而是任务说明书。通行句式（本包【P2】实践共识）：

> **当**〔情景〕**时，我想要**〔动机/进展〕**，以便**〔期望结果〕。

奶昔例：当我独自开车通勤一小时时，我想要一件能单手消磨时间又顶饱的东西，以便到上午十点都不觉得无聊和饿。

写作纪律：

- 主语是任务，禁止出现产品名与具体技术——"导出 Excel"不是任务，"完成周报"才是（衔接 [03-interview-playbook.md](03-interview-playbook.md) 第 5 节 5 Whys 的追问终点）。
- 情景（when）必填——任务高度依赖情景，同一用户清晨与下午雇用的是不同任务。
- 三个维度（功能/情感/社会）各问一遍，缺维度就回访谈补料。

可直接套用的访谈提纲见 [../examples/02-jtbd-switch-interview.md](../examples/02-jtbd-switch-interview.md)。

## 7. 边界

- **非消费（F-062）**：颠覆式创新常从服务"原本不消费的人群"起步——这类人群没有"旧方案"可切换，switch 访谈与四力模型部分失效，需改用"首次雇用"视角分析。
- **鸿沟（F-061）**：早期采用者雇用的任务与早期大众不同，同一产品在不同人群那里完成不同任务——早期验证信号不能线性外推，详见 [07-cases-and-boundaries.md](07-cases-and-boundaries.md)。
- **JTBD 回答"需求是什么"，不回答"先做哪个"**：任务的重要性与未被满足程度需要量化排序，接 [06-need-prioritization.md](06-need-prioritization.md) 的 ODI（F-030）。
- **JTBD 不替代验证**：任务说明书仍是假设，是否有人愿意付出代价要交给试路径（[05-validation-loop.md](05-validation-loop.md)）。
