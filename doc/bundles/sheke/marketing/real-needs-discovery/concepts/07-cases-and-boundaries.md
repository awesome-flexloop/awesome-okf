# 案例与边界：验证时刻、名言勘误与方法论的适用条件

> 末篇做三件事：把正面案例按证据等级排成谱系，勘误两则被用作"跳过验证许可证"的名言，然后划定全部方法论的适用边界。事实溯源至 [../facts.md](../facts.md)（六区 F-046~F-052、八区 F-061~F-068），反面案例见 [01-fake-need-taxonomy.md](01-fake-need-taxonomy.md)，解释性判断见 [../insights.md](../insights.md) 第 5~7 条。

## 1. 正面案例：验证时刻谱系

七个正面案例按"采集到的最高证据等级"排列（对应 [00-what-is-real-need.md](00-what-is-real-need.md) 第 4 节 L1~L6）：

| 案例 | 验证动作 | 证据等级 | 关键事实（编号） |
|---|---|---|---|
| Dropbox | 3 分 41 秒演示视频，等候名单 5 千→7.5 万 | L4 留资 | F-046；勘误：视频前已有可运行早期原型，并非"没写一行代码" |
| Buffer | 两页落地页，点"查看定价"即留邮箱，约 7 周获首批付费用户 | L4→L6 | F-048 |
| Food on the Table | 创始人上门为单个家庭定制菜谱并代买食材 | L6（真实付费服务） | F-052 |
| Zappos | 不建仓库，拍照挂网，有人下单再去店里原价买 | L6 | F-047 |
| Airbnb | 卖政治主题麦片盒筹约 3 万美元；逐户为房东拍照 | L6 + 不可规模化 | F-049 |
| 小米 | 论坛共创 + 每周五更新（"橙色星期五"），反馈直入需求池 | L3 持续使用 | F-051 |
| 拼多多 | 三年上市；黄峥："让安庆的人有厨房纸用、有好水果吃" | 被服务人群的真实需求 | F-050【P0，语录措辞待复核】 |

谱系的三点读法：

1. **没有一个案例靠"问"完成验证**。Dropbox 与 Buffer 用落地页把证据推到 L4，Zappos、Airbnb、Food on the Table 直接用真实交易推到 L6——验证时刻全是行为，不是陈述。
2. **越早期，人工含量越高**（F-043）。礼宾式服务（Food on the Table）看似"不像互联网公司"，却是证据等级最高、成本最低的早期验证形态。
3. **被验证的是需求，不是产品形态**。Zappos 验证的是"人们愿意网上买鞋"，不是"需要建仓库"；先证需求，再投基础设施。

## 2. 反面案例的位置

反面案例已在 [01-fake-need-taxonomy.md](01-fake-need-taxonomy.md) 按三大温床解剖（Google Glass/Juicero/Segway、O2O/ofo、脸萌，F-053~F-060）。此处只补一条未展开的案例：

- **Quibi（F-055）**：融资约 17.5 亿美元的短剧流媒体，2020 年 4 月上线、12 月关停，存活约 8 个月。"移动端限定 + 付费短剧"的需求假设从未接受低成本验证——对照 Buffer 的两页落地页，Quibi 把验证预算花成了制作预算。这是"跳过试路径直接大规模建设"的极端样本。

## 3. 名言勘误：两则"跳过验证许可证"

两句名言常被引来论证"不必研究用户需求"，考证后均不成立：

**「更快的马」（F-063）**。"如果我问顾客想要什么，他们会说一匹更快的马"——未见亨利·福特本人原始出处；Quote Investigator 考证显示该话为后人转述与层累附加（S28）。

**「乔布斯不做市场调研」（F-064）**。准确语境是 1998 年《商业周刊》采访：乔布斯说按焦点小组设计产品很难、很多时候人们直到看到产品才知道自己想要什么——语境是**具体产品定义之难**，并非否定一切需求研究（S29）。苹果的实践本身也从未跳过对用户的观察。

勘误的方法论意义（详见 [../insights.md](../insights.md) 第 5 条）：这两句名言的共同功能是**给供给方自恋发许可证**——"用户不知道自己要什么，所以听我的"。但本包全部方法论从未主张"问用户要什么产品"；Mom Test 问过去行为（F-014）、JTBD 还原切换（F-018）、民族志看现场（F-021）、实验测代价（F-036~F-044）——**研究的是任务与行为，不是让用户当产品经理**。名言的对立（研究 vs 不研究）是伪对立。

## 4. 需求的时点属性：漂移与鸿沟

需求不是静态实体，方法论结论都有保质期：

- **Kano 退化（F-029）**：昨天的兴奋点变成今天的门槛——需求清单必须周期重跑（见 [06-need-prioritization.md](06-need-prioritization.md) 第 3 节）。
- **持续再验证（F-065）**：供给普及会改变需求本身，PMF 不是一次性达成而是持续校准，pivot 概念的内核即在于此。
- **鸿沟（F-061）**：早期采用者与早期大众之间存在鸿沟——MVP 在尝鲜者中验证成立，不能线性外推到主流市场；跨越鸿沟时任务、四力、证据等级全部要重新评估。
- **非消费（F-062）**：颠覆式创新常从"原本不消费的人群"起步——在存量市场里测不到的需求，可能在非消费者那里成立；反之亦然，对非消费者成立的低价方案，不要指望直接打动高端存量用户。

## 5. 时代变量：AI 把天平推向"找需求"

F-066（本包【P2】行业观点，非定量结论）：2023 年以来，AI 编码与内容生成工具使原型与内容的生产成本显著下降，**"能做出来"的门槛降低，"找到真需求"相对"把东西做出来"的稀缺性上升**。

对本包方法的两个推论：

- **试路径更便宜了**：MVP 谱系（F-038）里绿野仙踪、单功能 MVP 的构建成本继续下降，"先证对的产品"（F-039）的借口更少；
- **伪供给更多了**：生产门槛降低意味着"能做出来但没人要"的产品供给膨胀——F-060 的伪需求结构会以更高频率重演，判别通货（行为证据等级）的价值反而上升。

## 6. 伦理边界

方法论的全部技巧都有伦理约束（F-068，关联 F-041）：

- **假门与绿野仙踪**：不得给用户造成实际损失；被识破的欺骗感是品牌负债，须控制实验比例、准备善后话术与补偿；
- **涉及金钱的实验**：预售必须能退款兜底；
- **访谈**：遵循知情同意，不伪装身份套取信息；
- **数据**：算路径使用行为数据须守住用户隐私底线。

原则一句话：**验证成本应该由供给方承担，不应转嫁给被试用户**。

## 7. 全包回顾：真需求判别流程

```
发现一个"需求陈述"
   │
   ├─ ① 本体检查（00篇）：说的是需要、欲望还是有购买力支撑的需求？
   │      翻译成用户要的结果（要洞不要钻头）
   │
   ├─ ② 伪需求排雷（01篇）：技术自恋？补贴伪高频？痒点错觉？
   │      笨问题：撤掉补贴、停掉 PR、放三个月，还剩什么？
   │
   ├─ ③ 四路径发现（02篇）：问（03篇）→ 看 → 算 → 试
   │      任务层锚定：JTBD 任务说明书 + 四力（04篇）
   │
   ├─ ④ 验证闭环（05篇）：选最危险假设 → 定验证/证伪线
   │      → 选 MVP 形态 → 跑 → pivot / persevere
   │
   ├─ ⑤ 排序（06篇）：Kano 定类型 → ODI/RICE 定先后 → 留存复核
   │
   └─ ⑥ 边界检查（本篇）：鸿沟外推？需求漂移？伦理成本？时代变量？
```

走完六道检查仍站得住的需求陈述，才配叫"真需求"——并且它只在此刻、此人群、此供给格局下为真。
