# 访谈 Playbook：让客户说出真话

> 访谈是四条路径里成本最低、也最容易自欺的一条。本篇回答三个问题：访谈为什么会骗人、怎样问才能逼近行为证据、访谈的能力边界在哪里。事实溯源至 [../facts.md](../facts.md)（二区 F-011~F-015、F-020，三区 F-026），解释性判断见 [../insights.md](../insights.md) 第 1、3 条。

## 1. 为什么访谈会骗人

访谈的默认产出是不可靠的，原因有三层：

1. **恭维机制**。当你向别人描述自己的想法，对方的最优社交策略是夸你。《The Mom Test》把恭维（compliment）列为最危险的信号——对方夸你的想法，不代表会付钱；"你会买吗"这类诱导将来承诺的问题，得到的答案不可靠（F-015）。
2. **言行差距**。用户自述行为与实际行为系统性不一致（F-026）——不是用户故意撒谎，而是人对"自己平时怎么做"的记忆本身就不可靠。
3. **将来时陷阱**。"如果有一个 XX，你会用吗"把对方放进假想情境，假想情境里的决策不承担任何代价——按 [00-what-is-real-need.md](00-what-is-real-need.md) 第 4 节的证据等级，这连 L2 口头陈述都不如，是 L1 恭维的近亲。

由此得出访谈的总纲：**访谈能采到的最有价值的东西不是观点，而是对过去具体行为的回忆**——过去的行为真实发生过，不受你的诱导污染。

## 2. 方法论地基：Blank 的客户开发

史蒂夫·布兰克把"找客户谈话"从随机动作升级为制度（F-011~F-013）：

- **客户开发四步**：客户探索 → 客户验证 → 客户创造 → 公司构建，与产品开发流程并行（F-011）。前两步是"搜索"：验证问题与方案假设；后两步才是"执行"。
- **走出办公楼**："没有一份商业计划能在第一次接触客户后幸存"，关于需求的全部事实都在办公楼之外（F-012）。
- **临时组织**：初创公司不是大公司的微缩版，而是"寻找可重复、可扩展商业模式的临时组织"（F-013）——访谈是这个搜索组织的侦察动作，不是市场调研部门的问卷外包。

对访谈操作的直接推论：**在客户探索阶段，访谈的目的是证伪自己的假设，不是收集赞美**。带着"证明我是对的"的目的去访谈，几乎一定能采回恭维（F-015）。

## 3. Mom Test 三规则

罗布·菲茨帕特里克的三条规则（F-014）是访谈提问的语法核心：

| 规则 | 操作要点 | 针对的失真 |
|---|---|---|
| ① 谈论对方的具体生活，而非你的想法 | 全程不出现"我在做一个……" | 恭维机制（F-015） |
| ② 问过去发生的具体行为，不问泛泛观点与将来承诺 | "上一次"是最好用的开场词 | 将来时陷阱、言行差距（F-026） |
| ③ 少说多听 | 沉默让对方展开；忍不住要介绍产品时记账到访谈后 | 诱导污染 |

两条辅助纪律（本包【P2】实践共识）：

- **追问细节而不是接受概括**。"我经常为这事头疼"→"上一次是什么时候？那天你具体做了什么？花了多长时间？"——概括是观点，细节才是行为。
- **把"想"翻译成"做过"**。对方说"我很需要这个"→"你之前为解决这个问题尝试过什么？花过钱吗？"——尝试史是最便宜的替代性支付证据。

## 4. 坏问题 → 好问题对照表

| 坏问题 | 为什么坏 | 好问题改写 |
|---|---|---|
| "你会用这样的 App 吗？" | 将来承诺不可靠（F-015） | "上一次遇到这个问题是什么时候？你当时怎么解决的？" |
| "你觉得这个功能怎么样？" | 求观点≈求恭维 | "你最近一次为这类事情花钱是什么时候？花在哪？" |
| "如果价格便宜你会买吗？" | 假想情境零代价 | "你现在为解决它每年花多少钱/多少时间？" |
| "你常为此烦恼吗？" | 诱导肯定 + 频率失真 | "这个问题过去一个月出现过几次？最严重那次怎样？" |
| "你需要 X 功能还是 Y 功能？" | 替用户设计，采回的是礼貌 | "你现在的完整流程是什么？哪一步最难受？" |

对照表的使用方式：访谈前列出想问的问题清单，逐条过一遍——**凡是主语是"我的产品/我的想法"的问题全部删掉，凡是时态是将来的问题全部改成过去式**。完整改写练习见 [../examples/01-interview-script-workshop.md](../examples/01-interview-script-workshop.md)。

## 5. 5 Whys：穿透表面答案

5 Whys 源自丰田生产方式（大野耐一）：对问题连问五个"为什么"，穿透表面症状到达根因（F-020）。在访谈中它的用法是：

```
用户："我需要一个导出 Excel 的功能。"
  → 为什么需要导出？        "要给领导看数据。"
  → 为什么领导要看这个？    "他每周要向上汇报进度。"
  → 为什么用 Excel？        "公司汇报模板就是 Excel。"
  → 根因浮现：任务不是"导出 Excel"，而是"完成周报"——
    真正的解决方案空间立刻变大（自动生成周报？直接对接汇报系统？）
```

两条使用注意（本包【P2】实践共识）：

- **"五个"是约数不是指标**——问到根因浮现即可，机械地凑满五次会让访谈变成审讯。
- **追问对象是行为链，不是价值判断**——"你为什么这么想"容易激起防御，"你为什么会这样做"保持在对事实的追溯上。

5 Whys 挖到的"任务"层，正是 JTBD"雇用"隐喻的入口（F-016），完整框架见 [04-jtbd-framework.md](04-jtbd-framework.md)。

## 6. 访谈能做什么、不能做什么

| 能做 | 不能做 |
|---|---|
| 挖动机：用户为什么这样做（指向 JTBD 四力 F-018） | 预测未来行为："你会买吗"永远不可靠（F-015） |
| 采行为史：过去的尝试、花费、变通办法 | 验证支付意愿：付钱与否只能交给试路径（F-044，见 [05-validation-loop.md](05-validation-loop.md)） |
| 定位痛点环节：现有流程哪一步最难受 | 发现用户未意识到的行为：这是看路径的地盘（F-021~F-026，见 [02-discovery-method-map.md](02-discovery-method-map.md) 第 4 节） |
| 测替换成本：旧方案的沉没投入与切换阻力（F-005、F-018） | 规模化：几十场访谈的结论不能直接外推主流市场（F-061） |

边界条款只有一句：**访谈是四条路径的起点，不是终点**——采回来的假设必须交给看（现场验证）或试（行为验证）接力，否则全部证据停在 L2 口头陈述层（F-067）。

## 7. 收尾：把访谈记录变成证据

访谈结束后的整理动作决定证据质量（本包【P2】实践共识）：

1. **分离事实与结论**：记录栏写"用户上周手动对账 3 次、每次约 40 分钟"，不写"用户对对账很苦恼"——前者是可复核的行为事实，后者是你的解读。
2. **证据等级对号入座**：按 [00-what-is-real-need.md](00-what-is-real-need.md) 第 4 节的 L1~L6 给每条关键信息定级——恭维（L1）不计入，口头陈述（L2）仅作线索，过去真实花费（L3 及以上）才可写入决策依据。
3. **保留反例**：主动记录与自己假设相矛盾的回答——访谈的价值在证伪，不在攒支持票（F-045 的 pivot 决策需要反例作输入）。
