## 一、需求本体：什么是真需求

| 编号 | 事实内容 | 信源 |
|---|---|---|
| F-001 | 需要、欲望、需求三分（科特勒体系）：需要（needs）是人类基本匮乏状态（衣食住行、归属、尊重）；欲望（wants）是文化与个性塑造下对具体满足物的向往；需求（demands）是有购买力支撑的欲望。营销不创造需要，而是影响欲望、把欲望转化为对特定产品的需求。【P1】 | S18 |
| F-002 | 马斯洛 1943 年论文《人类动机理论》（A Theory of Human Motivation）提出需求层次：生理→安全→归属→尊重→自我实现。【P1】 | S16 |
| F-003 | 西奥多·莱维特《营销想象力》（The Marketing Imagination，1983）：「人们不想买四分之一英寸的钻头，他们想要的是四分之一英寸的洞。」【P1】 | S17 |
| F-004 | 莱维特 1960 年《哈佛商业评论》发表《营销短视症》：衰退行业的企业把自己定义为「生产某种产品」而非「满足某种顾客需求」——铁路公司以为自己做铁路生意而非运输生意。【P1】 | S17 |
| F-005 | 俞军《俞军产品方法论》（2020）：用户不是自然人，而是需求的集合；用户价值 = 新体验 − 旧体验 − 替换成本。【P1】 | S24 |
| F-006 | 俞军：企业以产品为媒介与用户进行价值交换；产品经理是在约束条件下设计效用组合的人。【P1】 | S24 |
| F-007 | 梁宁《真需求》（中信出版社，2024）提出真需求三角：价值（这件事创造了被需要的价值）、共识（相关方对价值达成一致）、模式（交付价值的方式可持续运转）——三者缺一，需求不成立或生意不成立。【P1，出版月份 P0 待复核】 | S23 |
| F-008 | 梁宁《产品思维30讲》（得到，2018）：痛点是恐惧，爽点是即时满足，痒点是满足虚拟自我（对理想自我的投射）。【P1】 | S22 |
| F-009 | 梁宁《产品思维30讲》：点线面体——个体与产品（点）的收益取决于其附着的线（行业）、面（平台）、体（经济体）的周期位置，需求判断须看时势。【P1】 | S22 |
| F-010 | 「刚需、痛点、高频」六字判断法在中文创投圈广泛流传，常被归于周鸿祎公开分享；原始出处未见权威文本。【P1，归属待复核】 | S27 |

## 二、问：访谈路径

| 编号 | 事实内容 | 信源 |
|---|---|---|
| F-011 | 史蒂夫·布兰克（Steve Blank）《顿悟的四个步骤》（2005）提出客户开发（Customer Development）四步：客户探索→客户验证→客户创造→公司构建，与产品开发流程并行。【P1】 | S1 |
| F-012 | 布兰克：「没有一份商业计划能在第一次接触客户后幸存」（No business plan survives first contact with customers）；主张创业者「走出办公楼」（get out of the building）直接面对潜在客户。【P1】 | S1、S2 |
| F-013 | 布兰克：初创公司不是大公司的微缩版，而是「寻找可重复、可扩展商业模式的临时组织」。【P1】 | S1、S2 |
| F-014 | 罗布·菲茨帕特里克（Rob Fitzpatrick）《The Mom Test》（2013）访谈三规则：① 谈论对方的具体生活而非你的想法；② 问过去发生的具体行为，不问泛泛观点与将来承诺；③ 少说多听。【P1】 | S6 |
| F-015 | 《The Mom Test》：恭维（compliment）是最危险的信号——对方夸你的想法不代表会付钱；「你会买吗」类诱导承诺的问题得到的答案不可靠。【P1】 | S6 |
| F-016 | 克莱顿·克里斯坦森等《与运气竞争》（Competing Against Luck，2016）提出 JTBD（Jobs to be Done）：顾客不是购买产品，而是「雇用」产品来完成生活中的一项任务（job）。【P1】 | S4 |
| F-017 | 奶昔案例（克里斯坦森广泛讲述）：一家快餐连锁想提升奶昔销量，按人口统计调研无果；观察发现大量奶昔在清晨被通勤者买走——它被「雇用」来打发漫长车程并提供一上午的饱腹感，真正的竞品是香蕉、贝果与无聊。【P1】 | S4 |
| F-018 | switch 访谈与四力模型（JTBD 实务）：促使切换的两力是现状推力（push）与新方案拉力（pull），阻碍切换的两力是对新方案的焦虑（anxiety）与旧习惯的惯性（habit）；只有前两力之和压过后两力，切换才会发生。【P1】 | S4 |
| F-019 | JTBD 的任务三分：一项任务包含功能维度、情感维度与社会维度（例如戴某品牌手表既是看时间，也是自我感受与他人观感的管理）。【P1】 | S4 |
| F-020 | 5 Whys 源自丰田生产方式（大野耐一）：对问题连问五个「为什么」以穿透表面症状到达根因。【P1】 | S31 |

## 三、看：观察路径

| 编号 | 事实内容 | 信源 |
|---|---|---|
| F-021 | 民族志（ethnography）方法 1980 年代进入商业设计：施乐帕洛阿尔托研究中心（Xerox PARC）的人类学家（露西·萨奇曼 Lucy Suchman 等）通过观察真实办公场景改进复印机设计，开创了工作场所研究（workplace studies）传统。【P1】 | S10 及学术史 |
| F-022 | 情境访谈（Contextual Inquiry，Beyer 与 Holtzblatt《Contextual Design》，1998）四原则：情境（在用户做事的现场）、伙伴（与用户结成师徒式合作）、解读（与用户共同解释所见）、焦点（研究者保持明确观察焦点）——核心动作是「在用户工作的现场边看边问」。【P1】 | S10 |
| F-023 | 设计思维五阶段：同理（Empathize）→定义（Define）→构思（Ideate）→原型（Prototype）→测试（Test）——该表述通行于斯坦福 d.school 教学；蒂姆·布朗（Tim Brown）《Change by Design》（2009）将设计思维体系化为商业创新方法。【P1】 | S9 |
| F-024 | 同理心地图（Empathy Map）由戴夫·格雷（Dave Gray，XPLANE）创建：用「说（Say）/想（Think）/做（Do）/感（Feel）」四象限整理对单一用户的观察，暴露言行不一之处。【P1】 | S11 |
| F-025 | 埃里克·冯·希佩尔（Eric von Hippel）《Democratizing Innovation》（2005）提出领先用户（lead user）理论：多个行业（科学仪器、半导体工艺、外科手术器械、运动装备等）中，许多重要创新最早由领先用户做出，制造商事后才将其产品化；3M 等公司据此建立领先用户方法。【P1】 | S12 |
| F-026 | 言行差距（say-do gap）：用户自述行为与实际行为系统性不一致，观察路径可捕获用户自己都未意识到的变通行为（workaround），而变通行为往往指向未被满足的需求。【P2，方法论文献共识】 | S10、S11 |
| F-027 | 极限用户（extreme users）访谈：设计研究实务主张访谈重度用户与完全不用者，比访谈「平均用户」更能暴露需求的两极。【P2，方法论文献共识】 | S9、S11 |

## 四、算：数据路径

| 编号 | 事实内容 | 信源 |
|---|---|---|
| F-028 | 狩野纪昭（Noriaki Kano）与同事 1984 年发表魅力质量研究，提出 Kano 模型：需求分五类——基本型（必须具备，缺了不满、有了不夸）、期望型（做得越多越满意）、兴奋型（超预期惊喜）、无差异型、反向型；核心洞见是「满意」与「不满意」不是同一根轴的两端。【P1】 | S7 |
| F-029 | Kano 退化规律：兴奋型需求随时间退化为期望型、再退化为基本型（手机摄像头、汽车倒车影像均为实例）——昨天的惊喜是今天的门槛。【P1】 | S7 及后续阐释 |
| F-030 | 托尼·乌尔维克（Tony Ulwick）《Jobs to be Done: Theory to Practice》（2016）提出成果驱动创新（ODI）：把任务拆解为可度量的期望成果（desired outcomes），用「重要性 × 未被满足程度」定位机会；机会算法为 机会分 = 重要性 + (重要性 − 满意度)。【P1】 | S5 |
| F-031 | RICE 优先级模型由 Intercom 公开：分数 = Reach（触达人数）× Impact（影响程度）× Confidence（信心）÷ Effort（投入人月），用于需求/功能排期。【P1】 | S8 |
| F-032 | 马克·安德森 2007 年博文《The Only Thing That Matters》推广 PMF（产品—市场契合）概念：在好的市场中拥有能满足该市场的产品。【P1】 | S20 |
| F-033 | 肖恩·埃利斯（Sean Ellis）提出 PMF 检验：问用户「若明天不能再使用该产品，你会有多失望」，回答「非常失望」者占比约 40% 时视为达到 PMF 的信号。【P1】 | S21 |
| F-034 | 增长实务共识（RARRA 顺序修正）：同期群留存曲线是否走平是需求真实性的先行信号——留存不止跌，获客投入只是给漏水的桶加水。【P2】 | S21 及增长文献 |
| F-035 | 数据路径的适用前提：已有产品与流量才有可分析的行为数据；零到一冷启动阶段无数据可算，须依赖问、看、试三条路径。【P2，方法论判断】 | 本包综合 |

## 五、试：实验路径

| 编号 | 事实内容 | 信源 |
|---|---|---|
| F-036 | 埃里克·莱斯（Eric Ries）《精益创业》（2011）提出 build-measure-learn 循环：创业的核心活动是把想法以最小成本转化为可学习的实验，循环转速是创业公司的核心速率。【P1】 | S3 |
| F-037 | 莱斯对 MVP 的定义：能让团队用最少努力收集最大量「经证实的认知」（validated learning）的那个产品版本——MVP 的目标是学习，不是缩小版产品。【P1】 | S3 |
| F-038 | MVP 谱系（社区实践归纳）：落地页（landing page）、假门（fake door，做一个入口测点击）、绿野仙踪（Wizard of Oz，前台像产品、后台人工）、礼宾（concierge，全人工服务少数用户）、单功能 MVP。【P1】 | S3、S13 |
| F-039 | 阿尔贝托·萨沃亚（Alberto Savoia，谷歌首位工程总监）提出 pretotyping（《The Right It》，2019）：「确保你在把产品做对之前，先确保你做的是对的产品」——用极端低成本的伪装实验测「有没有人真的想要」。【P1】 | S13 |
| F-040 | IBM 语音转文字假门实验（萨沃亚在 IBM 时期的经典案例）：让客户对着「能听懂语音并自动打字的电脑」说话，幕后由真人打字员实时转录——先验证人们是否真愿意用语音输入，再决定是否投入语音识别研发。【P1】 | S13 |
| F-041 | 假门与伪装实验有信任成本：被识破的用户有被欺骗感，须控制实验比例、准备善后话术与补偿，避免透支品牌信任。【P2，实践共识】 | 本包综合 |
| F-042 | 逆向工作法（Working Backwards）：亚马逊新品立项须先写新闻稿与常见问题（PR/FAQ），以客户视角倒推产品定义；布里亚与卡尔《Working Backwards》（2020）系统记录了该机制。【P1】 | S14 |
| F-043 | 保罗·格雷厄姆 2013 年博文《Do Things that Don't Scale》：早期应主动做不可规模化的事——手动招募用户、亲自服务，以换取对需求的贴身理解。【P1】 | S19 |
| F-044 | 预售与众筹是付费级需求信号：付钱比口头承诺高一个证据等级（同组 bundle sell-before-build-validation 已专述「先卖后做」方法论，本包引用不重复展开）。【P1】 | S3、S19 |
| F-045 | 验证的目标是「经证实的认知」而非「证明自己是对的」——莱斯强调 validated learning 的产出是是否转型（pivot）或坚持（persevere）的决策依据。【P1】 | S3 |

## 六、正面案例：需求被验证的时刻

| 编号 | 事实内容 | 信源 |
|---|---|---|
| F-046 | Dropbox：2008 年在 Hacker News 与 Digg 发布约 3 分 41 秒演示视频，等候名单一夜从约 5,000 涨至约 75,000（团队原期望约 15,000）；勘误口径——视频前已有可运行的早期原型，并非「没写一行代码」。【P1】 | S30 |
| F-047 | Zappos：1999 年尼克·斯威姆（Nick Swinmurn）不建仓库、不进货，把当地鞋店的鞋拍照挂到网站，有人下单再去店里原价买下寄给顾客，以此验证「人们是否愿意在网上买鞋」。【P1】 | S30 |
| F-048 | Buffer：2010 年乔尔·加斯科因（Joel Gascoigne）先上线两页落地页（产品介绍页 + 定价页），点击「查看定价」即留邮箱；确认有人愿意付费后才开始写代码，约 7 周内获得首批付费用户。【P1】 | S30 |
| F-049 | Airbnb：2008 年资金枯竭时靠设计并售卖政治主题麦片盒（Obama O's、Cap'n McCain's，约 40 美元/盒）筹得约 3 万美元维持运营；早期创始人在纽约逐户为房东拍照——PG「做不可规模化的事」的经典注脚。【P1】 | S19、S30 |
| F-050 | 拼多多：2015 年成立，2018 年在纳斯达克上市（约三年）；黄峥接受《财经》专访时表述大意：消费升级不是让上海人去过巴黎人的生活，而是让安徽安庆的人有厨房纸用、有好水果吃。【P0，语录原始出处与措辞待复核】 | S26 |
| F-051 | 小米：MIUI 早期坚持每周五更新（「橙色星期五」），论坛用户反馈直接进入需求池；黎万强《参与感》（2014）将这套用户共创打法总结为「和用户做朋友」。【P1】 | S25 |
| F-052 | Food on the Table（莱斯书中礼宾 MVP 案例）：创始人曼努埃尔·罗索亲自上门为单个家庭定制菜谱并代买食材，服务到把每个环节都摸透后才逐步自动化。【P1】 | S3 |

## 七、反面案例与伪需求图谱

| 编号 | 事实内容 | 信源 |
|---|---|---|
| F-053 | Google Glass：2013 年 Explorer 版以约 1,500 美元面向开发者与尝鲜者销售，2015 年停售消费者版本；隐私争议（「Glasshole」污名）与使用场景不清是事后分析的两大焦点——技术可行先于需求成立。【P1】 | S30 |
| F-054 | Juicero：智能榨汁机公司融资约 1.2 亿美元，机器售价从 699 美元降至 399 美元；2017 年 Bloomberg 报道其专用果蔬包可以直接用手挤出近似效果，公司于 2017 年 9 月宣布关停——用昂贵硬件解决一个不存在的问题。【P1】 | S30 |
| F-055 | Quibi：短剧流媒体平台融资约 17.5 亿美元，2020 年 4 月上线，2020 年 12 月宣布关停（存活约 8 个月）；「移动端限定 + 付费短剧」的需求假设未获验证。【P1】 | S30 |
| F-056 | Segway：2001 年发布前被寄望颠覆城市交通（发布前保密代号与高调造势广为人知），实际销量远低于预期，成为「技术自恋 + 场景错配」的常用案例。【P1，具体销量数字不写死】 | S30 |
| F-057 | O2O 补贴潮（约 2014–2016）：上门洗车、上门按摩、上门做饭等大量项目靠补贴制造订单；补贴停止后订单消失，绝大多数项目死亡——补贴买来的是交易，不是需求。【P1】 | S30 |
| F-058 | 共享单车：ofo 小黄车 2018 年底爆发押金难退，线上排队退押人数超过千万；行业以资本与补贴维持的骑行「需求」未能覆盖车辆损耗与运营成本。【P1】 | S30 |
| F-059 | 脸萌等「现象级」应用：2014 年拼脸应用脸萌爆红登顶 App Store 后数月内热度骤降——痒点型新鲜感需求可引爆但难留存。【P1】 | S30 |
| F-060 | 伪需求的供给方共同结构（本包分析）：Google Glass、Juicero、Segway 的失败呈同一结构——把「能做出来的技术」当作「被需要的产品」，需求假设从未接受低成本验证。【P2，分析性陈述】 | 本包综合 |

## 八、边界与时代变量

| 编号 | 事实内容 | 信源 |
|---|---|---|
| F-061 | 杰弗里·摩尔《跨越鸿沟》（Crossing the Chasm，1991）：早期采用者与早期大众之间存在鸿沟——早期验证信号不能线性外推到主流市场。【P1】 | S15 |
| F-062 | 非消费（nonconsumption，克里斯坦森颠覆式创新理论）：颠覆式创新常从服务「原本不消费的人群」起步，与既有产品争夺的不是同一批用户。【P1】 | S4 |
| F-063 | 「更快的马」名言考证：广泛流传的「如果我问顾客想要什么，他们会说一匹更快的马」未见亨利·福特本人的原始出处；Quote Investigator 考证显示该话为后人转述与层累附加。【P1】 | S28 |
| F-064 | 乔布斯表述的准确语境：1998 年《商业周刊》（BusinessWeek）采访中，乔布斯表示按焦点小组设计产品很难、很多时候人们直到看到产品才知道自己想要什么——语境是具体产品定义之难，并非否定一切需求研究；中文语境常将其剪裁为「乔布斯从来不做市场调研」。【P1】 | S29 |
| F-065 | 需求随供给普及而漂移：Kano 退化（F-029）使昨天的兴奋点变成今天的门槛；莱斯以 pivot（转型）概念强调 PMF 需要持续再验证。【P1】 | S3、S7 |
| F-066 | AI 时代变量（2023 年以来）：AI 编码与内容生成工具使原型与内容的生产成本显著下降，「能做出来」的门槛降低，行业公开讨论中「找到真需求」相对「把东西做出来」的稀缺性上升。【P2，行业观点非定量结论】 | 本包综合 |
| F-067 | 四条发现路径的互补盲区（本包方法论判断）：访谈捕获不到用户未意识到的行为，观察难以规模化，数据需要存量产品，实验有信任成本——实务上须组合使用。【P2】 | 本包综合 |
| F-068 | 伦理边界：假门与绿野仙踪实验须避免给真实用户造成实际损失，访谈须遵循知情同意；误导性实验的长期成本由品牌承担。【P2，设计研究伦理共识】 | S10、S13 |
