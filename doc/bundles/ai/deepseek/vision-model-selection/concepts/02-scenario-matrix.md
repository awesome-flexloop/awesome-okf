# 按场景选型矩阵

选型不是比参数，而是匹配场景。博文把视觉任务归纳为五类场景，每类给出推荐模型与理由。本页将其矩阵化，并附价格与注意事项。

## 场景一：零成本跑起来

| 项目 | 内容 |
|------|------|
| 推荐模型 | GLM-4.6V-Flash（F-010） |
| 价格 | 目前官方价格为免费（F-010） |
| 适用条件 | 中文截图、UI 页面、商品图片信息提取和普通 OCR（F-011） |
| 注意事项 | 免费额度或并发不能满足需求时，再换 FlashX（F-012）；FlashX 价格为输入 $0.04、输出 $0.40/百万 tokens（F-013） |

先用免费模型把链路跑通，量上来再升级付费档（F-010、F-012），这是成本最低的验证路径。

> 事实溯源：F-010 ~ F-013

## 场景二：面向国内用户

| 项目 | 内容 |
|------|------|
| 推荐模型 | Doubao-Seed-2.0-mini（豆包）（F-014） |
| 价格 | 输入 ¥0.2、输出 ¥2/百万 tokens 起（F-015）；¥0.2 输入价仅适用于非音频输入且输入长度 ≤32K 档，音频输入 3.0 元/百万 tokens 起（F-036） |
| 适用条件 | 需要图像、视频、音频和文本四模态统一处理（F-014）；国内接入和人民币结算比较方便（F-016） |
| 注意事项 | 正式上线前要根据业务量实测并发、限流和 SLA（F-017） |

豆包的"起"字定价是阶梯口径的起点，音频与文本/视觉输入价格差异显著（F-036），测算时务必分开计算。

> 事实溯源：F-014 ~ F-017、F-036

## 场景三：多图、长视频或海外业务

| 项目 | 内容 |
|------|------|
| 推荐模型 | Gemini 2.5 Flash-Lite（F-018） |
| 价格 | 输入 $0.10、输出 $0.40/百万 tokens（F-019） |
| 适用条件 | 支持图像、视频和文本输入（F-018）；多图、长视频或海外业务（F-018） |
| 注意事项 | 只是给 DeepSeek 提供视觉事实的话，通常没必要硬上 Gemini Pro（F-020） |

> 事实溯源：F-018 ~ F-020

## 场景四：图片分类、简单截图识别和结构化抽取

云端低价档：

| 项目 | 内容 |
|------|------|
| 推荐模型 | GPT-5 nano（F-021） |
| 价格 | 便宜（F-021） |
| 适用条件 | 图片分类、简单截图识别和结构化抽取（F-021） |
| 注意事项 | 分工模式同双模型协作架构：视觉侧只做提取，判断交给 DeepSeek（F-024、F-028） |

本地隐私档：

| 项目 | 内容 |
|------|------|
| 推荐模型 | MiniCPM-V 4.6 本地部署（F-022） |
| 价格 | 本地部署，无 API 计费；约 1.3B 参数，也能通过 Ollama 运行（F-023） |
| 适用条件 | 图片不能上传云端（F-022） |
| 注意事项 | 分工模式：MiniCPM-V 负责提取图片信息，DeepSeek 负责后续分析（F-024） |

> 事实溯源：F-021 ~ F-024

## 场景五：PDF、扫描件、票据和表格

| 项目 | 内容 |
|------|------|
| 推荐模型 | DeepSeek-OCR-2 或 GLM-OCR（F-025） |
| 价格 | 对于几十页文档，OCR 专用模型通常更便于控制成本（F-026） |
| 适用条件 | PDF、扫描件、票据和表格（F-025）；几十页文档（F-026） |
| 注意事项 | OCR 专用模型通常更便于保留布局和生成 Markdown（F-026）；遇到复杂表格、小字以及模糊扫描件，仍要做抽样验收（F-027） |

DeepSeek-OCR-2 的架构与用法可参考既有知识包：[DeepSeek-OCR-2](../../deepseek-ocr2/index.md)（Visual Causal Flow 视觉因果流 OCR 模型）与前代 [DeepSeek-OCR](../../deepseek-ocr/index.md)。

> 事实溯源：F-025 ~ F-027
