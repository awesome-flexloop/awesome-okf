# 自验证机制详解

本文详细阐述 DeepSeekMath-V2 的自验证（Self-Verification）机制，这是模型实现严谨数学推理的核心能力。

## 为什么需要自验证

传统数学推理模型的问题：

```
问题 → 模型生成答案 → 输出
                    ↑
              只奖励最终答案正确
```

这种范式下，模型可能通过"巧合"得到正确答案但推理错误（幻觉推理），或者对需要证明的任务完全无法适用。自验证范式则形成闭环：

```
问题 → 生成证明 → 验证证明 → 发现问题？
                         ↓ 是
                    精炼证明 ← ← ← ←
                         ↓ 否（或达到轮次上限）
                      输出最终证明
```

## 三层验证架构

### 第一层：证明生成器（Generator）

**目标**：生成尽量正确、严谨的数学证明。

生成器使用 `proof_generation` prompt 模板，要求模型：
1. 先生成完整解答（`## Solution` 部分）
2. 再进行自评（`## Self Evaluation` 部分）
3. 自评必须逐步骤分析正确性
4. 发现问题必须如实报告，禁止"撒谎说正确"

关键设计：prompt 中明确告知模型"如果你作弊声称正确但实际错误，我们会发现并惩罚你"，引导模型忠实自评。

### 第二层：证明验证器（Verifier）

**目标**：独立评估证明质量，给出 0/0.5/1 评分。

验证器使用 `proof_verification` prompt，与生成器的自评不同——验证器是独立角色，不关心是谁写的证明，只按标准评判：

| 评分 | 含义 |
|---|---|
| **1** | 完全正确，所有步骤执行恰当且清晰展示 |
| **0.5** | 大体正确，但有细节遗漏或小错误 |
| **0** | 未解决问题、致命错误、严重遗漏 |

**多次采样投票**：单次验证可能有随机性，因此对每个证明独立采样 64 次（`n_verification_per_proof=64`），取多数投票结果。

### 第三层：元验证器（Meta-Verifier）

**目标**：评估验证器本身的判定是否合理。

元验证器使用 `meta_verification` prompt，从三个维度审查验证器的输出：

1. **步骤重述检查**：验证器对解决方案的重述是否忠实于原文
2. **缺陷分析**（最重要）：验证器指出的错误是否真的存在？分析是否准确？
   - 验证器认为正确的部分，无论实际是否正确，都不在审查范围
   - 验证器指出的缺陷，必须逐一核实
3. **表达分析**：验证器的表述是否准确（如：不能因为某步错误就断言后续结论也错，只能说"未被严格证明"）
4. **评分分析**：最终评分与发现的缺陷是否匹配

元验证器本身也给出 0/0.5/1 评分。可通过 `--skip_meta_verification` 跳过以加速推理。

## 评分体系

### 三级评分标准

| 分数 | 条件 |
|---|---|
| **1 分** | 完全正确——每一步都执行恰当、清晰展示；引用的结论必须附带证明 |
| **0.5 分** | 大体正确——整体思路正确，但有细节遗漏或小错误（不影响最终结论） |
| **0 分** | 致命错误——未解决问题、根本性错误、严重遗漏 |

### 引用规则

关键规则：**引用论文结论不能替代证明**。如果解决方案引用了某个定理但没有给出证明，则不能得 1 分。这要求模型不仅会用定理，还要理解并能证明所用结论。

## 迭代精炼流程

### 初始阶段（Round 1）

1. 对每个问题采样 `n_best_proofs_to_sample=32` 份候选证明
2. 每份证明用验证器评估 `n_verification_per_proof=64` 次
3. （可选）用元验证器审查验证结果
4. 选择最优证明进入精炼

### 精炼阶段（Rounds 2~16）

1. 从证明池中选择 `n_proofs_to_refine=1` 个最有潜力但可能有瑕疵的证明
2. 使用 `proof_refinement` 模板，提供：
   - 原始问题
   - 候选证明及其评估意见
   - 精炼指令（修复评估中指出的问题、复用有价值的思路）
3. 生成精炼后的证明
4. 对精炼证明重新进行验证
5. 将新证明加入证明池
6. 重复直到 `max_rounds=16`

### 聚合阶段

最后采样 `n_agg_trials=32` 次，从证明池中聚合出最终答案。

## 生成-验证差距的维持

随着训练迭代，生成器变强，能生成更优的证明。但这带来一个问题：如果验证器无法判断更优证明的质量，就无法提供有效的奖励信号。

解决方案：
1. **扩展验证计算**：对难验证的证明，增加验证采样次数或使用更强的验证配置
2. **自动标注**：通过扩展计算得到可靠标签，用于训练更强的验证器
3. **共进化**：生成器和验证器在迭代中共同进步

## test-time compute 扩展

DeepSeekMath-V2 支持通过增加推理时间来提升准确率：
- 更多采样 → 更多候选证明
- 更多验证 → 更可靠的质量评估
- 更多精炼轮次 → 更充分的错误修复
- 更多聚合采样 → 更稳定的最终答案

Putnam 2024 的 118/120 成绩就是通过**扩展 test-time compute**（增加采样和精炼轮次）取得的。
