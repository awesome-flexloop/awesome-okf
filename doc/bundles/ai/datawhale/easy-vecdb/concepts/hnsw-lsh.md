# HNSW 与 LSH

HNSW（图索引类）和 LSH（哈希类）代表了 ANN 算法中两种截然不同的思路：HNSW 通过构建近邻图实现高精度导航搜索，LSH 通过哈希映射实现极速粗筛。二者在性能特征和适用场景上形成鲜明对比。

## HNSW：分层可导航小世界图

### 核心思想

HNSW（Hierarchical Navigable Small World）通过构建多层次的邻近关系图，让向量之间形成高效的导航路径。搜索时从最高层（稀疏、长距离连接）开始快速定位大致方向，然后逐层向下（密集、短距离连接）进行精细搜索。

类比为在多层迷宫城市中找目标：
- **最上层**：少量建筑和粗略主干道，快速确定大致方向
- **中间层**：更多建筑和道路，缩小搜索范围
- **最下层**：所有建筑和密集道路，精确找到目标

这种"先粗后精、逐层细化"的机制使 HNSW 同时兼顾搜索速度和精度。

### 小世界网络理论

HNSW 的理论基础是"小世界网络"（Small World Network）：

- 任意两个节点之间通过少量长距离连接即可到达（六度分隔）
- 图中同时存在短距离的局部连接和长距离的"捷径"连接
- 搜索时沿长连接快速跳跃到目标区域，再沿短连接精细查找

HNSW 在不同层级实现不同密度的连接：上层稀疏（长距离跳跃），下层密集（局部精细搜索）。

### 图结构

HNSW 的图结构特点：

- 每个节点（向量）在其出现的每一层维护一个邻居列表
- 节点被随机分配到某一层（类似跳表的层级分配），约 1/M 的概率进入上一层
- 上层节点数量少、连接距离长；下层包含所有节点、连接密集
- 每层的边数由参数 M 控制

### 搜索算法

HNSW 的搜索过程：

1. **从最高层入口节点开始**
2. **在当前层贪心搜索**：从入口节点出发，遍历邻居，找到距离查询向量最近的节点作为新的入口；重复直到无法找到更近的节点（局部最优）
3. **将当前层找到的最近节点作为下一层的入口**
4. **在更下层继续搜索**（搜索范围更宽，使用 efSearch 参数控制候选集大小）
5. **在最底层（第 0 层）返回 efSearch 个候选中最近的 K 个**

### 关键参数

| 参数 | 含义 | 影响 | 典型值 |
|------|------|------|--------|
| **M** | 每层每个节点的最大连接数 | M 越大→图越密→召回越高→内存越大、构建越慢 | 16~48 |
| **efConstruction** | 构建索引时的搜索宽度 | 越大→构建质量越高→构建时间越长 | 100~500 |
| **efSearch** | 查询时的搜索宽度（动态参数） | 越大→召回越高→延迟越高 | 50~200 |

- M 决定了图的"度数"，直接影响内存占用（每个节点需存储 M 个邻居 ID）
- efConstruction 在构建时固定，影响图的质量
- efSearch 可在查询时动态调节，是运行时精度-速度权衡的主要旋钮

### 插入算法

新向量插入时：

1. 从最高层开始贪心搜索找到最近节点
2. 逐层向下，在每一层找到最近的 efConstruction 个邻居
3. 随机选择新节点的最高插入层
4. 在该层及以下各层，从候选邻居中选择 M 个建立双向连接
5. 如果已有节点的连接数超过 M，按距离裁剪保留最近的 M 个

### HNSW 的优势与局限

**优势**：
- 召回率高，在大多数基准测试中表现最优
- 查询延迟低，图导航搜索效率极高
- 支持动态插入（无需重建索引）
- 参数调节简单（主要调节 efSearch）

**局限**：
- 内存占用大（需存储完整向量 + 图结构）
- 索引构建时间较长
- 删除操作较复杂（需标记删除后定期重建）
- 不适合超大规模内存受限场景（需配合 PQ 压缩）

### HNSW + PQ 组合

为解决 HNSW 内存占用大的问题，可组合 HNSW + PQ：

- 使用 HNSW 构建图结构保证导航精度
- 使用 PQ 压缩向量降低内存
- 查询时先用 PQ 近似距离快速筛选候选，再用原始向量精确重排

Milvus 中支持 `HNSW` 和 `HNSW_PQ` 索引类型。

## LSH：局部敏感哈希

### 核心思想

LSH（Locality Sensitive Hashing，局部敏感哈希）通过特殊设计的哈希函数，使相似向量以高概率被映射到相同的哈希桶（Bucket），不相似向量映射到不同桶。查询时只需计算查询向量的哈希码，在相同桶中查找候选。

类比为给每个向量生成"指纹"：相似图片的指纹也相似，只需比对指纹（哈希码的汉明距离）即可快速筛选。

### 哈希函数性质

LSH 的哈希函数族需满足：

- 如果两个向量距离近（d(v₁,v₂) < d₁），则哈希冲突概率高（P > p₁）
- 如果两个向量距离远（d(v₁,v₂) > d₂），则哈希冲突概率低（P < p₂）

不同距离度量有不同的 LSH 函数族：

| 距离度量 | LSH 方法 |
|---------|---------|
| 汉明距离 | Bit Sampling |
| 余弦相似度 | 随机超平面（Sign-Random Projection） |
| 欧氏距离 | p-Stable Distribution（基于高斯/柯西分布） |
| Jaccard 相似度 | MinHash |

### 随机超平面 LSH（余弦相似度）

最常用的 LSH 实现之一：

1. 生成 k 个随机超平面（每个超平面是一个随机向量）
2. 对每个向量 v，计算它与每个随机超平面法向量的内积
3. 内积 > 0 记为 1，< 0 记为 0，生成 k 位二进制哈希码
4. 两个向量的哈希码汉明距离越小，余弦相似度越高

### 多哈希表增强召回率

单个哈希函数可能漏检相似向量（近似就意味着有误差）。实际使用时：

- 构建 L 个独立的哈希表（每个使用不同的随机哈希函数）
- 查询时在每个哈希表中查找对应桶
- 合并所有桶中的候选向量
- 对候选计算精确距离并返回 Top-K

L 越大召回率越高，但内存和查询时间也线性增加。

### LSH 的优势与局限

**优势**：
- 查询速度极快（哈希码比较可在硬件级实现）
- 存储极省（每个向量只需几十位哈希码）
- 易于并行化
- 适合超大规模数据的快速粗筛

**局限**：
- 召回率相对较低（哈希存在信息损失）
- 传统随机 LSH 无法适应数据分布
- 需要多哈希表来平衡召回率，增加内存
- 高维数据中需要很长的哈希码才能保持区分度
- 通常作为粗筛阶段，需配合精确重排

## HNSW 与 LSH 对比

| 维度 | HNSW | LSH |
|------|------|-----|
| **索引类型** | 图索引 | 哈希索引 |
| **召回率** | 高（通常 >95%） | 中低（需多表增强） |
| **查询速度** | 快（图导航） | 极快（哈希查找） |
| **内存占用** | 高（向量+图结构） | 低（仅哈希码） |
| **构建速度** | 慢（需构建多层图） | 快（哈希计算） |
| **动态更新** | 支持插入 | 支持插入 |
| **参数调节** | M, efConstruction, efSearch | k（哈希码长度）, L（表数） |
| **适用场景** | 高召回低延迟 | 超大规模粗筛 |
| **典型应用** | Milvus/Faiss 主力索引 | 去重、初筛阶段 |

## 在工程中的选择

- **首选 HNSW**：大多数在线服务场景（推荐、搜索、RAG），内存充足且要求高召回低延迟
- **选择 LSH**：数据量极大（十亿级以上）、内存受限、可接受较低召回作为粗筛
- **HNSW + PQ**：需要 HNSW 的高精度但内存不足时
- **IVF + HNSW**：Milvus 支持的组合，IVF 做粗分区，分区内用 HNSW 精细搜索
