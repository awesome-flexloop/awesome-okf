# 3个内部流程实测

> ⚠️ **来源声明**：以下3个流程为微信公众号"人间彷徨"（作者 wyzw）团队的**自述实测体验**（F-038），非官方 benchmark，无独立第三方验证。具体耗时和成功率为该团队环境下的数据，不同场景、不同模型版本结果可能差异很大。文中使用的具体模型版本（MAI-UI 旧权重还是 Qwen-UI-Agent 新权重）博文未明确说明，考虑到 Qwen-UI-Agent 权重截至 2026-08-28 尚未发布（F-032），实际测试可能基于 MAI-UI 旧权重。

博文作者团队用 Qwen-UI-Agent 测试了三个内部流程，分别代表不同类型的 GUI 自动化场景。

## 流程一：财务对账导出

**场景描述**（F-019）：每月底从 3 个后台系统分别导出 Excel，再手动比对差异。熟练同事也要 40 分钟。

**使用方式**：让 Qwen-UI-Agent 自动登录 3 个后台系统，点菜单、导出文件，然后把三张表并排打开比对，有差异的行标红。

**结果**：跑顺后整套流程压到 **5 分钟以内**。

**场景特征**：
- 多系统切换（3个后台）
- 结构化数据操作（导出Excel→比对→标红）
- 步骤较多但路径固定
- 属于"短平快重复活儿"的典型

## 流程二：运营日报搬运

**场景描述**（F-020）：把各平台后台的数据搬到汇总表里。

**结果**：成功率约 **85%**。

**遇到的问题**：某些后台会弹出"版本更新"弹窗，Qwen-UI-Agent 不认识这个弹窗就卡住了。

**解决办法**：事先在指令里加"看到弹窗先点稍后"——这对应了概念文档中提到的"关键步骤加人工确认闸"和"指令需考虑异常情况"（F-022）。

**场景特征**：
- 单一系统内重复操作
- 非预期弹窗是主要失败原因
- 成功率受UI稳定性影响
- 需要预先考虑异常处理指令

## 流程三：老 CRM 查单回复

**场景描述**（F-021）：客服团队用的十年前的 CRM 系统，没有 API 接口，过去只能人手查订单状态再回复客户。

**结果**：这个流程"比前两个还稳"。

**为什么最稳**：
- 老系统界面简单、变化少（不会频繁改版）
- 操作路径固定：查单号→看状态→复制回复
- 没有弹窗干扰
- GUI 智能体在"无 API 的老系统"场景优势最彻底——它像新人客服一样自己点进去查，不需要系统提供接口

**场景特征**：
- 无 API 的遗留系统
- 界面稳定不变
- 操作路径固定
- 是 GUI 智能体相比 RPA/API 集成优势最大的场景

## 三个流程对比总结

| 维度 | 财务对账 | 运营日报 | 老CRM查单 |
|------|---------|---------|----------|
| 系统数量 | 3个后台 | 各平台后台 | 1个老CRM |
| 结果 | 40分→5分内 | 成功率约85% | 最稳 |
| 主要问题 | 无（跑顺后稳定） | 弹窗卡住 | 无 |
| 步骤复杂度 | 高（多系统） | 中 | 低 |
| UI稳定性 | 较稳定 | 有弹窗干扰 | 极稳定（十年老系统） |
| 适合度 | ✅ 高 | ⚠️ 中（需异常处理） | ✅ 最高 |

### 可迁移的经验

1. **UI 越稳定，成功率越高**：老 CRM 之所以最稳，是因为界面十年不变；运营日报因弹窗干扰成功率降到 85%。
2. **异常处理要预先写进指令**：弹窗、加载等待、确认对话框等非预期情况需要在任务指令中显式说明。
3. **多系统切换可行但需跑顺**：财务对账涉及3个系统，初期可能需要调试，但跑顺后效率提升最大（40分→5分）。
4. **无 API 的遗留系统是最佳场景**：这是 GUI 智能体相比传统 RPA 和 API 集成优势最彻底的领域。

> 以上经验来自单一团队的自述实测，仅供参考。实际部署前应在自身环境中充分测试。
